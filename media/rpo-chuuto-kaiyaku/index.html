採用代行を途中解約したいときの進め方

採用代行がうまく回っていないとき、解約という選択が浮かびます。ただ、すぐに条項を確認するより先にやることがあります。何が起きているのかを工程で特定することです。原因が代行会社側にない場合、依頼先を替えても同じ状態が繰り返されます。この記事では、特定から申し入れ、引き継ぎまでの順番を整理します。

まず不満の中身を工程で特定する

「成果が出ていない」という言い方のままでは、次の判断ができません。採用の工程に当てはめて、どこで止まっているかを見ます。

止まっている場所見えている症状原因がある側
母集団形成候補者が集まらない要件が厳しい／媒体が合っていない／運用の質
書類選考集まるが通らない要件のずれ／検索条件のずれ
面談設定通っても会えない文面／連絡の速さ／日程の出し方
選考会うが進まない面接の内容／訴求／条件
内定進むが決まらない条件／競合／意思決定の速さ
運用そのもの連絡が遅い、報告がない代行側の体制

このうち代行会社の交代で改善するのは、運用の質と体制の部分です。要件のずれや条件の問題は、依頼先を替えても残ります。書類が通らない状態が続いているなら、まず自社の要件と、落とした理由を見直すほうが早く直ります。

工程で特定すると、解約すべきかどうかの判断も変わります。運用の質が原因なら交代に意味がありますし、要件が原因なら、いま契約している相手と要件を作り直すほうが立ち上げが速い。

解約の前に検討できること

解約は手間もコストもかかります。次の選択肢で解決するかを先に見ます。

担当者の交代を申し入れる。連絡が遅い、提案が出てこない、指示したことが反映されない。こうした症状は担当者に紐づいていることが多く、会社を替えなくても交代で変わることがあります。契約に交代の条項がなくても、申し入れ自体はできます。

業務範囲を変える。広く任せすぎて機能していないなら、狭めます。定型業務だけを残し、判断が要る工程は社内に戻す。逆に、狭すぎて手戻りが多いなら、前後の工程を含めて任せる形に変えます。

稼働量を変える。採用の状況が変わっているなら、稼働を下げて期間を延ばす、あるいは一時停止して再開時期を決める。この調整に応じる会社は少なくありません。

指標と報告の形を変える。何が起きているか見えないことが不満の正体である場合、稼働報告の粒度を上げるだけで解消することがあります。工程ごとの内訳と、成果物の量を並記してもらう形にします。

いまの体制で何が足りないのか、一緒に洗い出します

エラベルの見解

解約の相談で多いのは、不満が溜まりきってから初めて代行会社に伝えるというパターンです。伝えた時点ですでに信頼関係が切れているので、改善提案が出てきても受け取れず、結局は解約になります。

代行側から見ると、指摘は早いほど直しやすい。スカウトの返信が鈍い、書類が通らない、報告が読みにくい。こうした点は、月次の定例会で出してもらえれば手を打てます。ところが定例会は進捗報告で終わりがちで、うまくいっていないことを言い出す場になっていない。ここに構造的な問題があります。

対処は簡単で、定例会の議題に「今月うまくいっていないこと」を固定で入れるだけです。発注側から一つ、代行側から一つ出す。これを最初の月から続けると、不満が溜まる前に会話になります。解約の判断をするときも、それまでの記録があれば、原因がどちらにあったかを冷静に見られます。

解約を進める順番

解約すると決めたら、次の順で進めます。

  1. 契約書の該当条項を確認する。解約の予告期間、最低契約期間の残り、違約金や残存期間の支払い、成果物とデータの扱い
  2. 社内で解約後の体制を決める。次の依頼先を探すのか、内製に戻すのか。決めてから動くほうが空白が短くなります
  3. 口頭で意向を伝える。書面より先に会話の場を持つと、引き継ぎの協力が得られやすくなります
  4. 書面で申し入れる。予告期間の起算日を明確にするため、日付の残る形で送ります
  5. 引き継ぎの範囲と期日を合意する。何を、どの形式で、いつまでに受け取るか
  6. 進行中の候補者の扱いを決める。選考中の候補者への連絡を誰が引き継ぐか
  7. アカウントと権限を整理する。媒体・採用管理システム・メールの権限を戻す

三番と四番の順番は入れ替えないほうが実務は円滑になります。書面が先に届くと、相手は事務手続きとして処理します。会話が先にあると、引き継ぎに手が入ります。

回収するもの

契約が終わるときに受け取っておくものを、リストにしておきます。

  • 求人原稿・スカウト文面（編集できる形式で）
  • 候補者の検索条件と、その設計意図
  • 選考中・接触中の候補者の一覧と、それぞれの状況
  • 応募者データ、選考履歴、評価コメント
  • 稼働報告の履歴と、集計した数値
  • 連絡テンプレート、面接案内の文面
  • 採用管理システムの設定内容
  • 媒体アカウントの権限

個人情報を含むデータの受け渡しは、扱いに注意が要ります。委託契約の中で個人データの取り扱いを定めている場合、返却か削除かを契約に沿って処理します。削除を求めるなら、削除証明の形式も決めておきます。個別の判断は、社内の管理体制や専門家の助言にあわせてご確認ください。

もめやすい点

予告期間の起算日。申し入れた日なのか、書面が到達した日なのか、月末なのか。ここがずれると請求月が一つ変わります。

残存期間の支払い。最低契約期間が残っている場合の扱いは契約によります。全額なのか、一部なのか、稼働を止めても発生するのか。条項を読んだうえで、実際の運用について確認します。

引き継ぎ作業の費用。引き継ぎを代行側の稼働に含めるか、別途費用とするかは決まっていないことが多い項目です。契約時に決めておくのが本来ですが、決めていない場合はこの段階で合意します。

進行中の候補者。選考の途中で担当が替わると、候補者の側から見ると連絡が途切れます。誰がいつ連絡するかを決め、空白を作らないようにします。

媒体の契約が代行会社名義。名義が代行側だと、解約と同時にデータへアクセスできなくなることがあります。名義の切り替えか、データの書き出しを先に行います。

相談だけでも構いません。発注前提ではありません

無料で相談する

エラベルの見解

解約が決まった後にやっておくと、次が変わることがあります。うまくいかなかった理由を、自社の言葉で一枚に書き残すことです。

書くのは三つだけで足ります。どの工程で止まっていたか。その原因は要件・運用・体制のどれだったか。次の依頼先に何を求めるか。これを書いておくと、次の商談で伝える内容が具体的になり、提案の精度が上がります。

もう一つ、次に選ぶときの基準も一つ増えます。前回うまくいかなかった工程を、誰が担当するのかです。同じ工程で同じことが起きないよう、その工程の経験を持つ担当者かどうかを確認する。会社の実績ではなく、担当者の実績で見る、という基準です。

解約は失敗ではなく、判断材料が増えた状態です。一枚に残しておけば、次の契約はそのぶん短い時間で決められます。

まとめ

  • 解約を考える前に、どの工程で止まっているかを特定する。要件が原因なら替えても直らない
  • 解約以外に、担当者交代・範囲の変更・稼働量の調整・報告の粒度という選択肢がある
  • 不満は溜める前に出す。定例会に「うまくいっていないこと」を固定議題で入れる
  • 進める順番は、条項確認 → 社内で次を決める → 口頭 → 書面 → 引き継ぎ合意
  • 回収するのは文面・検索条件・候補者データ・稼働報告・アカウント権限
  • もめやすいのは予告期間の起算日・残存期間の支払い・引き継ぎ費用・進行中の候補者
  • 終わったら、止まった工程と原因を一枚に書き残す

よくある質問

解約の予告はどのくらい前に伝えるものですか

契約書に定めがあればそれに従います。定めがない場合でも、引き継ぎの実務を考えると、ある程度の余裕を持って伝えるほうが円滑です。進行中の候補者がいる場合は、その選考が一段落する時期も考慮に入れます。予告期間の解釈で判断に迷うときは、締結した契約書を持って専門家にご確認ください。

解約後に同じ候補者へ自社からアプローチできますか

契約の中で、候補者データの取り扱いや、接触した候補者の帰属について定めていることがあります。まず条項を確認してください。定めがない場合でも、個人情報の取得経路と利用目的の観点から整理が要ります。自社の個人情報の取り扱い方針とあわせて確認するところです。

代行会社を替えると採用は止まりますか

引き継ぎの準備次第です。文面・検索条件・候補者の状況が手元にあれば、次の依頼先は立ち上げを短くできます。逆に、これらが前の代行会社の環境にしか残っていないと、ゼロから作り直しになります。解約を決めた時点で回収の準備を始めると、空白は短く済みます。

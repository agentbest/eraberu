副業の稼働の時間になって、「今日は何をするんだったか」と思い出すところから始まる。依頼側の連絡を読み返し、前回どこまでやったかを探し、気づけば稼働の時間が半分過ぎている。副業のタスクは、どう管理すればよいのか。結論を先に書くと、**副業のタスク管理は、「やることを全部書く」のではなく、「依頼側ごとに『次の一手』と『判断待ち』と『締め切り』の三つだけを一枚に持ち、稼働の始めに見て、終わりに更新する」形で足ります。副業は稼働が細切れで、稼働と稼働の間に本業と生活が挟まるので、前回の続きを思い出す時間が最も無駄になります。一枚を見れば前回の続きから始められる形にし、道具より、更新する時刻を固定することが効きます。**稼働時間の記録は[稼働時間の管理と申告](/media/fukugyo-kadou-kanri/)に、複数案件の回し方は[複数案件のスケジュール管理](/media/fukugyo-fukusuu-kanri/)に、時間配分は[時間配分の決め方](/media/fukugyo-jikan-haibun/)にまとめています。

## 副業のタスク管理が本業と違う点

本業のタスク管理の方法を副業に持ち込むと、合わないことがあります。違いを見ます。

| 点 | 本業 | 副業 |
|---|---|---|
| 稼働の連続性 | 毎日続く。前日の続きを覚えている | 細切れ。稼働と稼働の間に数日空く。前回の続きを忘れる |
| タスクの量 | 多い。全部を書かないと漏れる | 少ない。全部を書くと管理の時間が稼働を圧迫する |
| 判断の所在 | 自分で判断できることが多い | 依頼側の判断待ちで止まることが多い |
| 締め切りの種類 | 社内の締め切り | 依頼側の採用の日程に紐づく締め切り。落とすと依頼側の採用が止まる |
| 情報の扱い | 社内の道具に社内の情報を書ける | 依頼側の情報を、自分の道具に書く線に注意が要る |
| 道具 | 会社が決めた道具 | 自分で選ぶ。依頼側の道具と自分の道具の二つを持つことがある |

違いの要点は、「前回の続きを忘れる」ことと、「判断待ちで止まる」ことの二つが、副業のタスク管理の中心だということです。全部を書く管理は、副業では管理の時間が稼働を圧迫します。前回の続きが一目で分かり、判断待ちが何かが一目で分かる。この二つに絞った一枚が、副業のタスク管理です。稼働の細切れへの対処は[本業と両立する時間の作り方](/media/fukugyo-jikan-kakuho/)に、判断待ちの扱いは[分からないことの聞き方](/media/fukugyo-shitsumon-shikata/)に書いています。

## 一枚で持つ三つの項目

副業のタスク管理は、依頼側ごとに三つの項目を一枚に持ちます。

| 項目 | 内容 | 書き方の例 |
|---|---|---|
| 一、次の一手 | 次の稼働で最初にやること。一つか二つ。「何を」「どこまで」 | 「求人票の構成を直す。仕事の中身を先頭に。今回で仕上げて送る」 |
| 二、判断待ち | 依頼側の判断を待っていること。「何を」「いつ聞いたか」「期限」 | 「面接官の人選、〇日に依頼。期限△日。来なければ△日に催促」 |
| 三、締め切り | 依頼側の採用の日程に紐づく締め切り。「何を」「いつまでに」「落とすと何が止まるか」 | 「スカウト文面、〇日まで。落とすと今週の送信が止まる」 |

三つの要点は、「一」の次の一手を、「何をどこまで」まで書くことです。「求人票」とだけ書くと、次の稼働で「求人票の何をするんだったか」と思い出すところから始まります。「求人票の構成を直す。仕事の中身を先頭に。今回で仕上げて送る」と書けば、稼働の始めに読んで、すぐに手が動きます。次の一手は、前回の自分から今回の自分への引き継ぎです。判断待ちの書き方は[分からないことの聞き方](/media/fukugyo-shitsumon-shikata/)に、締め切りの余裕は[遅れそうなときの連絡](/media/fukugyo-okure-renraku/)に整理しています。

### エラベルの見解

担当する側から見ると、細切れの稼働で成果を出している担当者と、稼働の時間が「思い出す時間」で消えている担当者の差は、道具の良し悪しではなく、「稼働の終わりに、次の一手を書いてから閉じているか」です。書いている人は、次の稼働の始めに一枚を読んで、すぐに手が動きます。書いていない人は、依頼側の連絡を読み返し、前回の作業を探し、何をするかを決めるところから始まり、稼働の三分の一が消えています。

見ていて差がつくのは、判断待ちに「期限」と「来なければどうするか」を書いているかです。判断待ちを「面接官の人選、依頼済み」とだけ書いていると、依頼側から返らないまま何週間も止まります。「期限△日。来なければ△日に催促」と書いている人は、期限が来たら催促し、止まる期間が短くなっています。依頼側は、担当者が催促してくれることで、判断が遅れていることに気づきます。エラベルでは、依頼側が担当者を選ぶ仕組みなので、判断待ちを放置せず、期限を決めて動かす担当者が、依頼側から「進めてくれる人」として評価されています。タスク管理は、書くことではなく、前回の自分から今回の自分へ引き継ぐことです。

## 稼働の始めと終わりの更新の型

一枚は、稼働の始めと終わりに、決まった型で更新します。

| 時点 | やること | かかる時間 |
|---|---|---|
| 稼働の始め | 一枚を読む。次の一手を確認する。判断待ちの期限を見て、期限が来ていれば催促を最初にやる。締め切りを見て、今日やる順番を決める | 五分 |
| 稼働の中 | 一枚は見ない。次の一手を進める | |
| 稼働の終わり | 一枚を更新する。次の一手を「何をどこまで」で書き直す。判断待ちに、今日依頼したものを足し、返ってきたものを消す。締め切りを確認し、変わったものを直す。依頼側への返信を送る | 十分 |

型の要点は、「稼働の終わりの更新を、依頼側への返信の前にやる」ことです。返信を先にやると、返信で疲れて一枚の更新を忘れ、次の稼働で思い出すところから始まります。一枚を更新してから返信すれば、一枚の内容（次の一手、判断待ち、締め切り）が返信の材料になり、「次は〇〇を△日までに出します」「□□のご判断を〇日までにお願いします」と書けます。返信の型は[稼働報告の書き方](/media/fukugyo-kadou-houkoku/)に、連絡の時刻は[連絡の速さをどう担保するか](/media/fukugyo-renraku-sokudo/)に書いています。

## 依頼側ごとの分け方

複数の依頼側を持つなら、一枚を依頼側ごとに分けます。混ぜると、情報が混ざり、判断待ちを取り違えます。

| 分け方 | 内容 |
|---|---|
| 依頼側ごとに一枚 | 依頼側Aの一枚、依頼側Bの一枚。一つの画面に並べてよいが、欄は分ける |
| 依頼側の名前は記号で | 「A」「B」など、自分だけが分かる記号。会社名を書かない |
| 候補者の名前を書かない | 「候補者の一人目」「〇日応募の方」など。名前と経歴を書かない |
| 一枚の外に、依頼側の情報を置かない | 一枚には次の一手と判断待ちと締め切りだけ。資料や記録は依頼側ごとの別の場所に |
| 全体の締め切りを、一つのカレンダーに集める | 依頼側ごとの締め切りを、一つのカレンダーに記号で入れ、重なりを見る |
| 稼働の日を、依頼側ごとに割り当てる | 「火曜はA、木曜はB」のように、稼働の日で依頼側を分ける |

分け方の要点は、「依頼側の名前と候補者の名前を、一枚に書かない」ことです。一枚は、通勤で見たり、家族のいる場所で開いたりするもので、依頼側の情報が入っていると、見られたときに漏れます。記号と「〇日応募の方」で書けば、自分だけが分かり、他人が見ても分かりません。情報の分け方は[案件ごとの情報の分け方](/media/fukugyo-jouhou-bunri/)に、稼働の日の割り当ては[複数案件のスケジュール管理](/media/fukugyo-fukusuu-kanri/)に整理しています。

## 道具の選び方と情報の線

タスク管理の道具は、何でも構いません。選び方と、依頼側の情報を入れない線です。

| 道具 | 向く場合 | 注意 |
|---|---|---|
| 紙のノート一冊 | 稼働の場所が自宅だけ。道具に時間をかけたくない | 持ち歩かない。依頼側の情報を書かない |
| 文書の一枚（メモ帳など） | 副業用の端末で完結させたい | 副業用の端末にだけ置く。同期先に注意 |
| 表計算の一枚 | 依頼側が複数で、締め切りを並べたい | 依頼側の名前は記号で |
| タスク管理の道具（アプリ） | 通知や期限の管理を道具に任せたい | 依頼側の情報を入れない。通知が本業の端末に来ない設定に |
| 依頼側の道具（依頼側の管理表やチャット） | 依頼側の情報を扱うタスクは、依頼側の道具の中で | 自分の一枚には、依頼側の道具のどこを見るかだけを書く |

線の要点は、「自分の道具には、依頼側の情報を入れない。依頼側の情報を扱うタスクは、依頼側の道具の中でやる」ことです。候補者の名前や選考の状況は、依頼側の道具（採用管理の仕組み、依頼側のチャット）の中にあり、自分の一枚には「依頼側の道具の〇〇を見て、△△する」とだけ書きます。自分の道具は、自分の動きの管理で、依頼側の情報の保管場所ではありません。道具の合わせ方は[クライアントのツールに合わせる](/media/fukugyo-kokyaku-tool/)に、統一の考え方は[ツールを統一するか合わせるか](/media/fukugyo-tool-toitsu/)に書いています。

## タスクが溢れたときの直し方

一枚が溢れる、次の一手が増えすぎる、判断待ちが溜まる。溢れたときの直し方です。

| 溢れ方 | 原因 | 直し方 |
|---|---|---|
| 次の一手が五つ以上ある | 範囲が広がっている。一稼働でできる量を超えている | 次の一手を一つか二つに絞る。残りは「その後」に分けて書く。範囲を見直す |
| 判断待ちが溜まっている | 依頼側の判断が遅い。催促していない | 期限を決めて催促する。定例で一度にまとめて聞く。判断待ちが多い依頼側は、判断の型を渡す |
| 締め切りが重なっている | 複数の依頼側の日程を見ていない | 一つのカレンダーに集める。重なる前に、依頼側に締め切りの相談をする |
| 一枚を更新していない | 稼働の終わりの型が崩れている | 更新を返信の前に戻す。更新する時刻を固定する |
| 一枚に依頼側の情報が混ざっている | 線が崩れている | 依頼側の情報を消し、記号と「〇日応募の方」に戻す |
| 稼働の始めに一枚を見ずに、連絡を読み始める | 型が崩れている | 一枚を見てから連絡を読む、に戻す |

直し方の要点は、「次の一手が五つ以上あるなら、タスクの問題ではなく範囲の問題」だということです。一稼働でできる量を超える次の一手があるなら、受けている範囲が稼働の枠を超えています。タスク管理を工夫しても解決せず、範囲を絞るか、稼働の枠を広げるかの判断が要ります。範囲の見直しは[業務範囲を書面で固める](/media/fukugyo-scope/)に、稼働の枠は[週何時間から受けられるか](/media/fukugyo-kadou-jikan/)に、判断待ちの動かし方は[定例会の進め方](/media/fukugyo-teirei-shinkou/)に整理しています。

## 管理を作る順番

副業のタスク管理を作る順番です。

| 順番 | 内容 |
|---|---|
| 一、道具を一つ決める | 紙でも文書でも。副業用の端末か、持ち歩かないノート |
| 二、依頼側ごとに、三つの項目の欄を作る | 次の一手、判断待ち、締め切り |
| 三、依頼側と候補者の名前を、記号と「〇日応募の方」にする | 一枚に依頼側の情報を書かない |
| 四、稼働の始めに一枚を見る型を決める | 五分。次の一手、判断待ちの期限、締め切りの順 |
| 五、稼働の終わりに一枚を更新する型を決める | 十分。返信の前に |
| 六、締め切りを一つのカレンダーに集める | 依頼側が複数なら |
| 七、週に一度、一枚が溢れていないかを見る | 次の一手が五つ以上なら範囲の問題 |
| 八、月に一度、一枚と稼働の記録を並べて見る | 見積もりと実態の差 |

順番の要点は、「五」の、稼働の終わりの更新の型を、最初に固めることです。始めに見る型は、終わりに更新されていれば自然にできます。終わりの更新が崩れると、始めに見ても古い情報で、思い出すところから始まります。終わりに更新する時刻を固定し、返信の前にやる。この一つが、副業のタスク管理の中心です。稼働の記録との突き合わせは[稼働時間の管理と申告](/media/fukugyo-kadou-kanri/)に、時間配分は[時間配分の決め方](/media/fukugyo-jikan-haibun/)に書いています。

### エラベルの見解

相談で最も多い思い込みは、「タスク管理は、良い道具を使えばうまくいく」というものです。実際には、道具を変えても、稼働の終わりに次の一手を書いていなければ、次の稼働は思い出すところから始まります。副業のタスク管理で効くのは、道具ではなく、更新する時刻を固定することです。紙のノート一冊でも、終わりに次の一手を書いていれば回り、高機能な道具でも、書いていなければ回りません。

順番として、道具を一つ決め、依頼側ごとに次の一手と判断待ちと締め切りの欄を作り、依頼側と候補者の名前を記号にし、稼働の始めに見る型と終わりに更新する型を決め、締め切りを一つのカレンダーに集め、週に一度溢れていないかを見て、月に一度稼働の記録と並べて見る。この順番で、タスク管理は「やることを書くもの」から「前回の自分から今回の自分へ引き継ぐもの」になります。エラベルでは、依頼側が担当者を選ぶ仕組みなので、判断待ちを期限で動かし、締め切りを落とさない担当者が、依頼側から「進めてくれる人」として選ばれ続けています。タスク管理の中心は、道具ではなく、更新の時刻です。

## まとめ

- 副業のタスク管理は**依頼側ごとに「次の一手」「判断待ち」「締め切り」の三つだけを一枚に**持つ。全部を書かない
- 副業は稼働が細切れで**前回の続きを忘れる**。次の一手は「何をどこまで」まで書き、前回の自分から今回の自分へ引き継ぐ
- 判断待ちには**期限と「来なければどうするか」**を書く。放置すると何週間も止まる
- **稼働の始めに五分で見て、終わりに十分で更新する**。更新は依頼側への返信の前に
- 一枚に**依頼側と候補者の名前を書かない**。記号と「〇日応募の方」で。依頼側の情報は依頼側の道具の中で
- 次の一手が五つ以上なら**タスクではなく範囲の問題**。道具より、更新する時刻の固定が効く

## よくある質問

### 本業で使っているタスク管理の道具を、副業でも使ってよいですか

本業の会社が用意した道具（会社のアカウントで使うもの）は、副業に使いません。本業の記録に副業の情報が残り、本業の会社が見られる状態になります。自分で契約している個人の道具なら使えますが、本業の情報と副業の情報を同じ場所に置かず、副業用の領域を分けます。通知が本業の端末に来ない設定にし、依頼側の情報は入れません。端末と道具の分け方は[私物端末で作業してよいか](/media/fukugyo-tanmatsu/)に整理しています。

### 依頼側から「進捗を管理表で共有してほしい」と言われました。自分の一枚を見せてよいですか

自分の一枚は、自分の動きの管理で、依頼側に見せるものではありません。依頼側と共有する進捗は、依頼側の道具（依頼側の管理表や共有の文書）の中に、依頼側向けの形で作ります。「進行中の項目、判断待ちの項目、次に出すもの」を依頼側の言葉で書き、自分の一枚とは別に持ちます。二つを持つのは手間に見えますが、自分の一枚には自分だけが分かる書き方ができ、依頼側の共有には依頼側が分かる書き方ができ、両方が速くなります。共有の作り方は[稼働ログの付け方](/media/fukugyo-log/)に書いています。

### 稼働の終わりに更新する時間が取れず、次の稼働で思い出すことが続いています

稼働の終わりの十分を、稼働の中に最初から入れておきます。「稼働は二十時から二十二時」なら、「作業は二十一時四十五分まで。残りは更新と返信」と、稼働の中で区切ります。更新の時間を稼働の外に置くと、疲れて飛ばします。稼働の中に置けば、作業を早めに切り上げてでも更新する形になります。更新を飛ばした稼働は、次の稼働の始めが遅れるので、結果として稼働の時間が減ります。稼働の区切り方は[本業と両立する時間の作り方](/media/fukugyo-jikan-kakuho/)に整理しています。

検索しても、候補者が数十人しか出ない。一巡して送り終えたら、送る相手がいない。条件を緩めれば数は増えるが、合わない人が増えるだけの気もする。どこから広げればよいか、広げた後に何を見ればよいかが分からず、送信が止まっている。結論を先に書くと、**母集団を広げるときは、「条件を緩める」から始めません。「検索の言葉」「経歴の読み替え」「隣の職種」「媒体」「条件」「時間軸」の順に広げます。手前の四つは、採りたい人の像を変えずに数を増やす方法で、条件を緩めるのは五番目です。広げた分は「別の層」として記録し、元の層と返信と面談の結果を分けて見ます**。ターゲットの像の作り方は[スカウトのターゲットペルソナの作り方](/media/scout-persona-sakusei/)に、送信枠の優先順位は[送信枠が足りないときの優先順位](/media/scout-waku-tarinai/)にまとめています。

## 母集団が小さい構造

母集団が小さすぎるのは、次の構造で起きます。

| 構造 | 起きていること |
|---|---|
| 検索の言葉が、社内の言葉 | 社内の職種名や製品名で検索し、候補者が経歴に書く言葉と一致しない |
| 経歴を「同じ役割の経験」でしか読まない | 別の名前で同じ仕事をしてきた人が、検索と選別から落ちている |
| 職種を一つに固定している | 隣の職種で、要件の大半を満たす人を見ていない |
| 媒体が一つ | その媒体に登録している層だけが母集団 |
| 条件が最初から狭い | 勤務地、年収の幅、雇用の形、経験の年数が、要件以上に狭い |
| 一度の検索で見ている | 今日いる候補者だけを見て、来月登録する人、活動を再開する人を見ていない |
| 「条件を緩める」しか手が無いと思っている | 数を増やす方法が一つしか無く、緩めると像が崩れるので止まる |

構造の大半は、「採りたい人の像を変えずに数を増やす方法」を知らないことです。方法は、条件を緩める以外に四つあります。

## 広げる六つの順番

母集団を広げる順番です。手前ほど、像を変えずに増やせます。

| 順 | 広げ方 | 像への影響 |
|---|---|---|
| 一 | 検索の言葉 | 変わらない。同じ人を、別の言葉で見つける |
| 二 | 経歴の読み替え | 変わらない。同じ仕事を別の名前でしてきた人を拾う |
| 三 | 隣の職種 | 少し変わる。要件の大半を満たす隣の職種を足す |
| 四 | 媒体 | 変わらない。同じ像の人を、別の媒体で見つける |
| 五 | 条件 | 変わる。勤務地、年収、雇用の形、経験の年数を、要件の範囲で緩める |
| 六 | 時間軸 | 変わらない。今日いない人を、今後の登録と活動の再開で拾う |

順番の要点は、「一〜四で像を変えずに増やしてから、五で条件を見直す」ことです。五から始めると、像が崩れ、返信は増えても面談以降で落ちます。一〜四で足りれば、五は要りません。

## 順番ごとの広げ方

六つの順番それぞれで、具体的に何をするかです。

| 順 | やること | 例の形 |
|---|---|---|
| 一 検索の言葉 | 社内の職種名を、候補者が経歴に書く言葉に置き換える。同じ仕事の別の呼び方、略称、英語と日本語、製品や技術の名前、業務の動詞を集める。返信が来た人の経歴から、実際に使われている言葉を拾う | 「〇〇担当」→「〇〇企画」「〇〇推進」「〇〇マネージャー」「〇〇の立ち上げ」など。返信者の経歴の言葉を検索に戻す |
| 二 経歴の読み替え | 役割の要件を「経験の中身」に分解し、別の職種名でも中身を満たす経歴を選別で拾う。「同じ職種名」でなく「同じ中身」で見る | 要件が「顧客との調整と社内の進行」なら、営業、PM、カスタマーサクセス、企画のどれにもいる |
| 三 隣の職種 | 要件を並べ、大半を満たす隣の職種を足す。足りない部分が入社後に補えるかを社内で確認 | 要件の八割を満たす隣の職種を一つか二つ |
| 四 媒体 | 同じ像の人が、別の媒体に登録している。媒体ごとの候補者の層の違いを見て、足す。仕様と費用は公式の案内で確認 | [媒体の組み合わせ方](/media/scout-baitai-kumiawase/) |
| 五 条件 | 勤務地（リモートや出社の頻度）、年収の幅、雇用の形、経験の年数を、要件の範囲で見直す。「なぜその条件か」を一つずつ問う | 「経験五年以上」は「三年で足りる中身」かもしれない |
| 六 時間軸 | 今日の検索で出ない人を、定期的な再検索、活動の再開の通知（媒体の機能がある場合）、過去の送信先への時間を空けた再送で拾う | [時間を空けて再送するときの書き方](/media/scout-kikan-aketa/) |

広げ方の要点は、「一」の「返信者の経歴の言葉を検索に戻す」ことです。返信が来た人が、経歴にどんな言葉で書いているかを見ると、社内の言葉とのずれが分かります。それを検索に戻すと、同じ像の人が増えます。

## 広げてはいけない方向

数は増えるが、像が崩れるか、別の問題になる広げ方です。

| 広げ方 | 問題 |
|---|---|
| 属性で広げる・絞る | 年齢や性別や国籍で対象を操作する。[差別的表現になっていないかの確認](/media/scout-sabetsu-hyougen/) |
| 要件を落として広げる | 「経験不問」にして数を増やす。返信は増えても、面談以降で落ち、担当者の時間が消える |
| 役割を変えて広げる | 「この人なら別の役割で」と役割を後から作る。役割の設計の問題であって、母集団の問題ではない |
| 活動していない人に広げる | 媒体上で活動を止めている人に送る。届かないか、返信が来ない |
| 送ってはいけない相手に広げる | 取引先、競合の「送らない」の区分、連絡不要の人。[送ってはいけない候補者の管理](/media/scout-blacklist/) |
| 同じ人に何度も送って「数」にする | 送信の数は増えるが、母集団は増えていない |

方向の要点は、「要件を落とす」と「役割を変える」の区別です。「経験三年で足りる中身か」を問い直すのは要件の見直しで、五番目に入ります。「経験不問」にするのは要件を落とすことで、像が崩れます。線は、「入社後に補えるか」を社内で判断できるかどうかです。

## 広げた分の扱い

広げた分は、元の母集団と分けて記録し、結果を比べます。

| 項目 | 内容 |
|---|---|
| 層の区分 | 送信ログの「層」に、「元の層」「検索の言葉で広げた層」「隣の職種の層」「媒体で広げた層」「条件を緩めた層」を持つ |
| 文面の型 | 広げた層には、一段落目の型を変える。隣の職種なら「〇〇のご経験は、この役割の△△に近い」と、読み替えの理由を書く |
| 結果の比較 | 層ごとに、返信率、面談率、面談以降の結果を見る。広げた層が面談以降で落ちるなら、広げ方を戻す |
| 判断の期限 | 広げた層を、一〜二か月送って判断する。返信だけでなく面談以降まで見る |
| 型にした結論 | 「この役割は、隣の職種の△△からの返信が面談に至りやすい」など、次の役割に活かす一文 |

扱いの要点は、「広げた層を別に記録する」ことです。混ぜると、全体の返信率が動いても、元の層が効いたのか広げた層が効いたのか分かりません。層ごとに見て、面談以降まで追えば、「広げてよかった方向」と「戻すべき方向」が分かります。検証の単位の考え方は[どの単位で効果を検証するか](/media/scout-kensho-tan-i/)に書いています。

### エラベルの見解

相談で最も多い失敗は、「候補者が三十人しか出ないので『経験不問』に緩めたら三百人になり、返信も増えたが、面談に来る人の大半が要件を満たさず、面談の担当者が疲弊して『もう面談したくない』と言い出した」というものです。条件を緩める前に、検索の言葉と読み替えを見直していませんでした。役割の要件を「経験の中身」に分解し、社内の職種名を候補者の言葉に置き換え、隣の職種を二つ足したら、条件を変えずに百人を超え、面談以降の落ちも小さくなりました。数を増やす手は、緩める以外にありました。

見ていて差がつくのは、担当者が「返信者の経歴の言葉」を検索に戻しているかです。最初の検索の言葉を使い続ける担当者と、返信が来るたびに「この人は経歴にこう書いている」と拾い、検索の言葉を更新する担当者がいます。後者の母集団は、月ごとに広がります。

発注側にできるのは、役割の要件を「職種名」でなく「経験の中身」で担当者に渡すことです。中身で渡せば、担当者は読み替えられます。

## 広げても足りないとき

六つの順番で広げても、母集団が足りない場合の考え方です。

| 状況 | 考えること |
|---|---|
| 一〜四で増えず、五を緩めても要件を満たす人がいない | 役割の要件が市場に無い組み合わせ。要件そのものを社内で見直す（分けて二つの役割にする、一部を入社後に補う） |
| 条件（年収、勤務地）が市場と根本からずれている | 条件の見直しは社内の判断。[年収の希望と合わない](/media/rpo-nenshu-awanai/)、[地方で採用できない](/media/rpo-chihou-saiyo/) |
| 母集団は小さいが、一人採れれば足りる | 数を増やすより、小さい母集団に丁寧に送る。個別化を深くし、時間軸で拾う |
| スカウト以外の経路が要る | 紹介、リファラル、コミュニティ、ダイレクトの検索の外。スカウトだけで埋めない判断 |
| 役割を分ける | 一人に求めている要件を、二人に分けられないか |

足りないときの要点は、「母集団の問題ではなく、役割と条件の問題」と切り替えることです。六つの順番を尽くしてなお足りないなら、スカウトの運用ではなく、採用の設計に戻ります。

## 外注する場合の範囲

母集団の広げ方を、スカウト代行に出す場合の範囲です。

**出せる工程。** 役割の要件の「経験の中身」への分解の下書き、検索の言葉の収集と更新（返信者の経歴からの拾い上げ）、経歴の読み替えの基準の作成と選別、隣の職種の候補の提示、媒体ごとの候補者の層の比較と追加の提案、条件を緩める場合の案（要件の範囲で）、定期的な再検索と時間軸での拾い上げ、広げた層の記録と文面の型の分け方、層ごとの結果の比較と報告、型にした結論。

**社内に残す判断。** 役割の要件の定義と、入社後に補える部分の判断、隣の職種を足すことの承認、媒体の追加の承認と費用、条件の見直し（年収、勤務地、雇用の形）の決定、要件そのものの見直しと役割の分割、スカウト以外の経路の判断。

**外注の効きどころ。** 母集団の広げ方は、「言葉を集め、読み替え、隣を足し、媒体を足し、層を分けて記録し、比べる」運用で、社内では「条件を緩める」しか手が無くなりやすい工程です。担当者が六つの順番を持ち、返信者の言葉を検索に戻し、読み替えの基準で選別し、層を分けて結果を見れば、像を崩さずに母集団が広がります。担当者は複数の会社で同じ役割の母集団を見ているので、「この役割はこの言葉で見つかる」「隣のこの職種から採れている」を持ち込めます。ただし、要件の定義と、補える部分の判断と、条件の見直しは、社内でしか決められません。

**外注しても動かない場合。** 役割の要件を職種名でしか伝えない、隣の職種を「違う」と一律に断る、媒体の追加を検討しない、条件を「変えられない」と固定したまま数だけ求める、要件そのものの見直しに進まない。社内の判断で、代行を替えても直りません。

母集団は、条件を緩める前に、言葉と読み替えと隣の職種と媒体で広げ、広げた分を別の層として見れば、像を崩さずに増やせます。外注は、言葉の収集と読み替えと層の記録と比較を担う手段です。

### エラベルの見解

担当する側から見ると、母集団の相談で最も多いのは、「役割の要件が、職種名で来る」ことです。「〇〇マネージャーの経験者」と言われると、検索も選別も職種名になり、母集団は職種名を持つ人だけになります。「〇〇マネージャーとして、何をしてきた人が欲しいのか」を聞くと、「顧客との調整」「社内の進行」「数字の管理」と中身が出てきて、それを満たす人は職種名の外に何倍もいます。

母集団を広げる最初の一歩は、検索の技術ではなく、要件を中身で言葉にすることです。それができれば、一〜三は担当者が回せます。

発注側にできるのは、「この役割の人は、入社後の最初の三か月に、何をしますか」を担当者に話すことです。そこから中身が出ます。

## まとめ

- 小さいのは**社内の言葉で検索・同じ役割名でしか読まない・職種を固定・媒体が一つ・条件が最初から狭い・一度の検索・緩めるしか手が無い**構造
- 順番は**検索の言葉→経歴の読み替え→隣の職種→媒体→条件→時間軸**。一〜四は像を変えずに増やす、五は要件の範囲で見直す
- 広げ方は**返信者の言葉を検索に戻す・要件を中身に分解・八割を満たす隣の職種・媒体ごとの層・なぜその条件かを問う・再検索と再送**
- 広げてはいけないのは**属性・要件を落とす・役割を変える・活動していない人・送ってはいけない相手・同じ人に何度も**
- 広げた分は**別の層として記録・一段落目の型を分ける・層ごとに面談以降まで比べる・一〜二か月で判断・型にする**
- 足りなければ**要件の見直し・条件の見直し・小さい母集団に丁寧に・スカウト以外の経路・役割の分割**。母集団でなく設計の問題
- 外注できるのは**中身への分解・言葉の収集・読み替えの基準・隣の職種の提示・媒体の比較・条件の案・再検索・層の記録・比較・型化**。社内に残るのは**要件の定義・補える部分・隣の職種の承認・媒体と費用・条件の決定・要件と役割の見直し・経路の判断**

## よくある質問

### 検索の言葉は、どうやって集めればよいですか

三つの元から集めます。一つ目は、返信が来た人と、社内でその役割にいる人の経歴に書かれている言葉。二つ目は、同じ役割の他社の求人票で使われている職種名と業務の表現。三つ目は、業務の動詞（「立ち上げ」「推進」「改善」「運用」）と、製品や技術や手法の名前。集めた言葉を一覧にし、検索のたびに一つずつ試して、出てくる候補者の経歴が要件に合うかを見ます。合う言葉を残し、合わない言葉を外します。

### 隣の職種を足すと、面談の担当者が「違う」と言います

面談の前に、「なぜ隣の職種を足したか」と「要件のどこを満たし、どこが足りないか」を面談の担当者に渡します。渡さずに面談に出すと、職種名だけで「違う」と判断されます。加えて、隣の職種から採った人が入社後にどうだったかの記録を残し、実績で示します。それでも「違う」なら、足りない部分が入社後に補えないと社内が判断したことになるので、その隣の職種は外します。

### 媒体を足せば増えますか

同じ像の人が別の媒体にいるなら増えます。ただし、媒体ごとに登録している層が違うので、「今の媒体で見つからない像が、別の媒体にいるか」を先に見ます。媒体の追加には費用がかかり、運用の手間も増えるので、一〜三で増やしてから、四で足すのが順番です。媒体の仕様と費用は公式の案内で確認してください。媒体の組み合わせは[媒体の組み合わせ方](/media/scout-baitai-kumiawase/)に書いています。

ATSを入れるほどの規模ではない、または入れる前に回る形を作りたい。そのとき、スプレッドシートで採用管理を作ることになります。ところが、依頼側の既存のシートを開くと、一人が複数行にわたり、段階が「一次済」「二次済」と列で並び、セルにメモが混ざり、誰が最新かが分からない。スプレッドシートが崩れるのは、道具の限界ではなく、構造が無いからです。結論を先に書くと、**スプレッドシートの採用管理は、一人一行・段階は一列で選択式・記録は別シートで紐づけの三つを基本に、一覧の項目を絞り、更新の担当とタイミングをATSと同じルールで決め、個人情報の列を分けて共有の範囲を設計し、関数と自動化は最小に留め、ATSに移行しても困らない形で作ります。**ATSの選定は[ATSの選定と初期設定](/media/fukugyo-skill-ats-sekkei/)に、運用ルールは[ATSの運用ルールを作る](/media/fukugyo-skill-ats-unyou/)に書いています。ここでは、スプレッドシートの型に絞ります。

## 崩れる典型

| 崩れ方 | 何が起きるか |
|---|---|
| 一人が複数行（応募のたび、面接のたびに行が増える） | 「いま誰がどの段階か」が数えられない |
| 段階が複数列（「一次済」「二次済」に○） | 段階を進めるたびに列を探す。一覧で並べられない |
| セルにメモが混ざる | 検索できない。誰が書いたか分からない |
| 個人情報と評価が同じ行 | 面接官に見せると連絡先も見える |
| 誰が最新の行を持っているか分からない | コピーが増え、正が分からない |

崩れたシートを直すより、構造を決めて作り直すほうが早いことが多い。ただし、選考中の候補者の情報は正確に移します。

## 基本の三つ

| 基本 | 中身 | なぜ |
|---|---|---|
| 一人一行 | 候補者一人につき一行。応募や面接で行を増やさない | 「段階ごとに何人」が数えられる |
| 段階は一列で選択式 | 「段階」の列を一つ作り、プルダウンで選ぶ（応募／書類／一次／二次／最終／内定／入社／見送り／辞退） | 並べ替えと絞り込みができる。表記の揺れが出ない |
| 記録は別シートで紐づけ | 評価シートの記録は別のシートに、候補者の番号で紐づける | 一覧が重くならない。面接官に一覧を見せずに記録だけ書ける |

三つが守られていれば、スプレッドシートはATSと同じ構造になります。ATSは、この三つを画面にしたものです。

### エラベルの見解

担当する側から見ると、スプレッドシートで最も差がつくのは、「段階を一列で選択式にする」を最初に決められるかどうかです。受ける側は、依頼側の既存のシートの「一次済」「二次済」の列を尊重して、そのまま足していきます。ただ、段階が列だと、「いま一次で止まっている人は何人か」が数えられず、[採用ファネルを可視化する](/media/fukugyo-skill-funnel/)ができません。段階を一列にして、選択肢を依頼側の選考の段階と一致させる。それだけで、一覧の並べ替えと段階ごとの数が出ます。エラベルで担当者を選ぶ企業には、「採用管理のシートで、段階は一列ですか、複数列ですか」を、私たちから先に聞いています。受ける側がその場で使える判断としては、既存のシートを見たら、段階が一列かを最初に確かめ、複数列なら作り直しを提案すること。作り直しの負担より、数えられないことの損失が大きい、と伝えます。

## 一覧に置く項目

| 列 | 中身 | 注意 |
|---|---|---|
| 番号 | 候補者ごとの通し番号。記録のシートとの紐づけの鍵 | 氏名ではなく番号で紐づける |
| 段階 | 一列、選択式 | 依頼側の選考の段階と一致 |
| 経路 | どこから来たか（媒体名、紹介、リファラル、自己応募） | 選択式 |
| 応募日 | 最初の接点の日 | 日付の形式を揃える |
| 最終更新日 | 段階が動いた日 | 週次の確認で「古い順」に並べる鍵 |
| 担当 | いま誰が動かすか | 一人。選択式 |
| 次にやること | 一行 | 日程調整中、評価シート待ち、結果連絡、など |
| 次の日程 | 面接や面談の日時 | 日付と時刻 |
| 見送り・辞退の理由 | 段階が見送りか辞退のときだけ。分類（速さ・迷い・接点・条件・要件・その他） | 選択式。自由記述は記録のシートに |

氏名と連絡先は、一覧とは別の「個人情報」のシートに置き、番号で紐づけます。一覧を面接官に見せても、連絡先が見えない形にします。項目は上の範囲で足り、増やすと更新が止まります。

## 記録のシート

| 列 | 中身 |
|---|---|
| 番号 | 一覧の番号と同じ |
| 段 | 一次・二次・最終のどれか |
| 面接官 | 誰が書いたか |
| 観点一〜三の事実 | 候補者が語った場面。一行ずつ |
| 観点一〜三の判断 | 通す・迷う・通さない。選択式 |
| 候補者の質問と迷い | 一行 |
| 次の段への引き継ぎ | 一行 |
| 記入日 | 面接の直後 |

評価シートの型をそのまま列にします。面接官には、このシートの自分の段の行だけを渡す（別のシートに分けるか、フィルタで見せる）形にします。評価シートの型は[評価シートを作る](/media/fukugyo-skill-hyouka-sheet/)に書いています。

## 更新のルールはATSと同じ

| 決めること | 中身 |
|---|---|
| 更新の担当 | 段階ごとに一人 |
| 更新のタイミング | 「面接の直後」「日程が決まった直後」など、既にある行動の直後 |
| 段階を進める条件 | 記録のシートの判断が埋まり、決める人が通したら、人事が段階を進める |
| 正はどれか | 共有の場所にある一つのシートが正。コピーを作らない。ダウンロードしない |
| 週次の確認 | 最終更新日の古い順に並べ、止まっている候補者を担当に知らせる |

道具が変わってもルールは同じです。ルールの作り方は[ATSの運用ルールを作る](/media/fukugyo-skill-ats-unyou/)に書いています。

### エラベルの見解

相談で最も多い思い込みは、受ける側の「スプレッドシートなら、関数と自動化で便利にできる」というものです。実際には、関数と自動化が増えるほど、作った担当者にしか直せなくなり、担当者が替わった瞬間に壊れます。段階ごとの数を出す関数と、最終更新日の並べ替え。それ以上は足しません。「見た目が良い集計」より「誰でも直せる素の表」のほうが、長く使われます。受ける側がその場で使える判断としては、関数を一つ足すたびに、「依頼側の人事が、この関数を自分で直せるか」を問うこと。直せないなら足しません。集計が要るなら、別のシートに手で転記する形のほうが、壊れません。

## 共有の範囲と個人情報

| シート | 誰が見られるか | 中身 |
|---|---|---|
| 一覧 | 人事、決める人、副業の担当者（契約の範囲で） | 番号・段階・経路・日程・担当・次にやること |
| 個人情報 | 人事と、日程調整を担う人だけ | 番号・氏名・連絡先・履歴書の置き場所 |
| 記録 | 各段の面接官は自分の段の行だけ。決める人は全部 | 観点ごとの事実と判断 |
| 集計 | 人事、決める人 | 段階ごとの数、経路ごとの数（手で転記か最小の関数） |

シートを分けて、共有の設定をシートごとに変えます。一つのブックに全部を入れて全員に共有すると、面接官に連絡先が見えます。共有の設定は依頼側の管理者が行い、担当者は設計を渡すまでです。個人情報の扱いに法令が関わる場合は、依頼側の決まりと専門家の確認に従います。個別の判断は専門家にご確認ください。扱いは[個人情報の扱い](/media/fukugyo-kojin-jouhou/)と[情報の取り扱いと端末の分離](/media/fukugyo-security/)に書いています。

## ATSに移行しても困らない形

| 形 | なぜ |
|---|---|
| 一人一行 | ATSの候補者の一覧と同じ構造。そのまま移せる |
| 段階が一列で選択式 | ATSの段階に対応させられる |
| 番号で紐づけ | 記録と個人情報を、番号で一緒に移せる |
| 日付の形式が揃っている | 取り込みで崩れない |
| セルにメモが無い | 移すものが明確 |

スプレッドシートを「ATSの前段」として作っておけば、候補者が増えてATSに移るときに、作り直しが要りません。移行の順番は[ATSの選定と初期設定](/media/fukugyo-skill-ats-sekkei/)に書いています。

## よく起きる詰まりと直し方

| 詰まり | 直し方 |
|---|---|
| 既存のシートが崩れていて直せない | 選考中の候補者だけを新しい構造に移し、旧シートは読み取り専用で残す |
| 依頼側が「氏名を一覧に出したい」と言う | 一覧に番号と、個人情報のシートへの参照だけ。連絡先は出さない。氏名を出すかは依頼側の決まり |
| 面接官が一覧を見て他の候補者の記録を読む | 記録のシートを段ごとに分け、共有を段ごとに |
| 関数が壊れた | 壊れた関数を消し、手で転記する形に戻す。足すときは人事が直せるものだけ |
| コピーが増えて正が分からない | 共有の場所の一つを正と決め、コピーとダウンロードを禁止する一行をルールに |
| 段階の選択肢が増え続ける | 依頼側の選考の段階だけ。「保留」「要相談」を増やさず、「次にやること」の列に書く |

## まとめ

- 崩れるのは道具のせいではなく**構造が無い**から
- 基本は**一人一行・段階は一列で選択式・記録は別シートで番号で紐づけ**
- 一覧の項目は**番号・段階・経路・日付・担当・次にやること・次の日程・理由の分類**。氏名と連絡先は別シート
- 記録のシートは**評価シートの型をそのまま列に**。面接官には自分の段だけ
- 更新のルールは**ATSと同じ**。担当・タイミング・進める条件・正はどれか・週次の確認
- **関数と自動化は最小に**。依頼側の人事が直せないものは足さない
- シートを分けて**共有の範囲を変える**。個別の判断は専門家にご確認ください
- **ATSの前段**として作れば、移行で作り直しが要らない

## よくある質問

### 依頼側が「Excelのファイルをメールで回している」状態です

正が分からなくなる構造なので、共有の場所にある一つのシートに変える提案をします。メールで回す形は、個人情報が添付で流れることにもなり、依頼側の決まりに照らして問題になることがあります。変えられない事情があるなら、少なくとも「一人一行・段階は一列」の構造にし、最新版の管理を一人に決めます。共有の形の判断は依頼側です。

### 複数の求人を一つのシートで管理してよいですか

一覧に「求人」の列を足し、選択式にすれば、一つのシートで複数の求人を管理できます。段階の選択肢が求人で違う（新卒と中途で段階が違う）なら、シートを分けます。記録のシートの観点は求人ごとに違うので、記録は求人ごとに分けるほうが扱いやすい。一覧は一つ、記録は求人ごと、が基本の形です。

### スプレッドシートの作成を「副業の成果物」として、単価に含めてよいですか

構造の設計（三つの基本と項目とルール）は成果物です。ただし、作ったシートは依頼側のもので、担当者が持ち出したり、他の依頼側で使い回したりしません。使い回せるのは「型」（項目の並び、ルールの一枚の形）だけです。成果物の範囲と、案件の終了後の扱いは契約に書きます。範囲の決め方は[業務範囲を書面で固める](/media/fukugyo-scope/)に書いています。

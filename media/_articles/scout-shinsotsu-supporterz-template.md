サポーターズの文面は、一般的な新卒スカウトの型をそのまま持ち込むと弱くなります。読むのがエンジニア志望の学生で、しかも**技術で評価されたい**という前提があるからです。結論を先に書くと、**サポーターズの文面は「絞り込んだ技術条件を、そのまま一行目に書く」「技術的な実績や自主的なアウトプットに触れる」「用途（インターン集客・説明会・面談）ごとに差し出すものを一つに絞る」の三つで設計します**。仕様は変わるので、契約する前に公式の案内で確認してください。以下は、2026年9月23日時点で公式サイトに記載されている内容に基づいて整理しています。運用の組み方は[サポーターズの運用スケジュールと送信計画](/media/scout-shinsotsu-supporterz-unyou/)に、選定は[サポーターズのプロフィール選定基準の作り方](/media/scout-shinsotsu-supporterz-screening/)にまとめています。

## 前提が二つ違う

**一、学生が受け取るスカウト数が限られています。**公式サイトのスカウト・メディアのページは、特徴の二つ目として「エンジニア特化型だからこそ実現する、質の高いマッチング」を挙げ、次のように説明しています。

「エンジニア領域特化型サービスであるため、**プログラミング経験などの細かい絞り込み条件でターゲット学生をピンポイントでスカウトできます**。また、特化型サービスのため、**大手ナビ媒体と比べ学生の受け取るスカウト数が限られており、他企業に埋もれてしまう心配もありません**」

**一通が読まれる可能性が高い環境です。**だからこそ、雑な一斉送信は損になります。受け取る通数が少ない環境で、明らかなテンプレートが届くと、その会社の印象がそのまま下がります。

**二、絞り込みの軸が技術です。**同ページのよくある質問には「スカウト時に学生をどこまで絞り込み可能でしょうか？」という問いに対し、「**プログラミング経験の有無（授業での経験からリリース経験）や使用言語、志向性等**で検索いただく事が可能です」との記載があります。

**絞り込んだ条件が、そのまま文面の材料になります。**「Goで書いた経験がある」「リリース経験がある」という条件で抽出したなら、その語を一行目に置けます。**抽出条件と文面を同じ設計図から作る**のが、この媒体での基本です。

**学生の性質。**公式サイトは、登録学生について「IT・デジタル関連の職種（エンジニア・データサイエンティスト・ITコンサルタントなど）を志望する学生の中でも、**意欲的な学生や、プログラミング経験のある学生が多く登録**しています」としています。また、選ばれる理由の二つ目として「ハイスキルなエンジニア学生が多数」を挙げ、「単なる母集団形成ではなく、**技術的な実績や自主的なアウトプットを重視したマッチング**を行います。**コーディングスキルがあり、問題解決能力に長けた**ハイスキルなエンジニア学生に直接アプローチできます」と説明しています（※対象：2026年卒のサポーターズ登録学生、との注記が付されています）。

**技育プロジェクトの存在。**同サイトは「テックカンファレンス・ハッカソン・技術勉強会などを**年間150回以上開催**し、『エンジニア学生の育成』に注力しています」とし、「技育プロジェクト」に大学1〜2年生も多く参加していること、テックカンファレンス「技育祭」には毎回2,000名以上の学生が参加していることを挙げています。

**つまり、技術の話が通じる相手です。**「成長できる環境」「風通しのいい社風」のような抽象語ではなく、**何を作っているか、どう作っているか**を書いたほうが届きます。

## 冒頭三行の型

| 行 | 置くもの | 書き方 |
|---|---|---|
| 一行目 | **抽出条件に使った技術**を名指しする | 「◯◯で個人開発をされていると拝見して、ご連絡しました」 |
| 二行目 | **自社の技術と接続する** | 「弊社の△△も◯◯で書いていて、□□の部分を作り直しているところです」 |
| 三行目 | **差し出すものを一つ置く** | 「その話ができるエンジニアと、一度30分話しませんか」 |

**一行目で技術に触れる理由。**プログラミング経験の有無や使用言語で絞れる媒体なので、**何を見て声をかけたのかを技術の言葉で書ける**はずです。ここが「あなたのプロフィールを拝見し」で始まると、絞り込んだ意味がなくなります。

**二行目は、自社の技術を具体に書きます。**使っている言語、直近で作り直した部分、詰まっている課題。**学生から見て「話を聞いてみたい」と思えるのは、きれいな紹介文ではなく、いま現場で起きていること**です。技術的な実績や自主的なアウトプットを重視する学生が多い媒体なので、ここが効きます。

**三行目は一つに絞ります。**用途によって差し出すものが変わります。

| 用途 | 差し出すもの | 向く時期・相手 |
|---|---|---|
| **インターンシップの集客** | 短期・長期インターン、就業体験 | 学年が低い、技術を試す場を探している |
| **会社説明会の案内** | 説明会、座談会、技術イベント | まだ企業を絞っていない |
| **面談の案内** | 現場エンジニアとの1on1 | 技術条件が強く合致、早く会いたい |

**「エンジニアと話せる」を書きます。**エンジニア志望の学生は、人事ではなく現場のエンジニアと話したがります。誰が出るのか（役割、使っている技術、何年目か）を三行目に書けると、返信率が変わります。

**会社紹介は四行目以降です。**事業の説明や社風の話は、技術に触れたあとに置きます。

### エラベルの見解

依頼側から見ると、エンジニア向けの文面で最も多い失敗は、**人事が一人で書こうとすること**です。技術の話を書こうとして、社内のドキュメントから用語を拾ってくる。学生はそれを読んで、書いた人が中身を分かっていないと気づきます。

実務でやるのは、**現場のエンジニアに素材を出してもらうこと**です。いま何を作っているか、直近で作り直した部分はどこか、詰まっている課題は何か、この技術を選んだ理由は何か。三十分のヒアリングを二人か三人にやれば、文面に使える素材が二十個は出ます。人事はそれを組み立てる役に回ります。

そして、この素材は**説明会の内容にも、募集要項にも使えます**。公式サイトは「公開募集機能」があることを挙げているので、スカウト文面と募集ページを同じ素材から作ると、一貫します。

もう一つ、**現場のエンジニアの名前で送れるかを確かめます**。誰から届いたかは、エンジニア志望の学生にとって大きな情報です。送信者の設定がどうなっているかは運営に確認したうえで、可能なら現場の名前を使う設計にします。エラベルでは、依頼側が担当者の経歴を見て選ぶ仕組みなので、現場のエンジニアを巻き込む設計まで提案できる担当者かどうかを、面談で確かめてみてください。

## 用途別の書き分けと点検

**通数が無制限であることの意味。**公式サイトは、スカウト・メディアについて「スカウト送信の通数制限無しで、年間を通じてご利用いただけます。**インターンシップの集客、会社説明会の案内、面談の案内など時期に応じて様々な用途**でご利用いただけます。年間を通じて学生と接触する機会を作り出すことで、**細かくPDCAを回して改善**を行うことが可能です」としています。

**同じ学生に、時期を変えて別の用途で送れる設計です。**夏にインターンの案内、秋に説明会の案内、冬に面談の案内。三通とも同じ文面だと効きませんが、**前に送ったことに触れながら用途を変える**と、一貫した接触になります。

| 回数 | 書き方 |
|---|---|
| 一通目 | 技術条件を名指し。用途に合わせた差し出し |
| 二通目（時期をずらす） | 「◯月にインターンのご案内をした△△です」と前回に触れる。別の用途を出す |
| 三通目 | 接点の実績があれば、それに触れる（イベント参加、募集ページの閲覧など） |

**検証を組み込みます。**「細かくPDCAを回して改善を行うことが可能」とされている媒体なので、**文面を二種類用意して、同じ条件の母集団を分けて送る**ことができます。一行目を技術で始めた版と、事業の話で始めた版。返信率を比べれば、自社にどちらが合うかが分かります。通数の制約がないからこそ、この検証が成立します。

**文面の点検表。**

| 点検する項目 | 見るところ |
|---|---|
| 一行目 | **抽出条件に使った技術**が現れているか。「プロフィールを拝見し」で始まっていないか |
| 二行目 | 自社の技術が**具体に**書かれているか。事業の抽象的な説明になっていないか |
| 三行目 | 差し出すものが**一つ**か。用途と合っているか |
| 出てくる人 | **現場のエンジニア**が出ることが書かれているか。役割と使っている技術 |
| 用語の正確さ | 技術用語の使い方が正しいか。現場のエンジニアに一度読んでもらったか |
| 学年 | 学年に合った用途か。低学年に本選考を送っていないか |
| 長さ | 冒頭三行で用件が分かるか。会社説明が先に来ていないか |
| 前回の接触 | 二通目以降は、前に送ったことや接点に触れているか |
| 検証の設計 | 比べる版を用意しているか。用途別に数字を分けているか |
| 公開募集との一貫性 | 募集ページと同じ素材から作られているか |

**技術用語を間違えないこと。**この媒体の読み手は、プログラミング経験のある学生が多いとされています。用語の使い方が雑だと、そこで判断されます。**送る前に現場のエンジニアに一度読んでもらう**工程を、運用の中に入れます。

**知名度は前提にしません。**公式サイトのよくある質問には「知名度が低い会社でも採用できますか？」という問いに対して「採用できます」との記載があり、短期的には成果報酬型の人材紹介サービスや合同説明会、中長期的には技育プロジェクトを通じた認知度向上の支援について触れられています。**文面でも、知名度ではなく技術の中身で勝負する**設計にします。

### エラベルの見解

依頼側から見ると、文面を外に出すときの心配は「技術が分かっていない人が書くのではないか」です。これは正当な心配で、エンジニア向けの文面は、技術の中身が薄いとすぐ見抜かれます。

ただ、外注先に技術力を求めるのは筋が違います。**技術の中身は現場のエンジニアから出し、外注先はそれを学生に届く形に組み立てる**。この分担にすれば、両方が回ります。外注先に求めるのは、技術の知識ではなく、**現場から素材を引き出す力**です。

見分け方は簡単で、最初の面談で「現場のエンジニアに話を聞かせてもらえますか」と言うかどうかです。会社案内と求人票だけで書こうとする担当者は、この媒体では当たりません。

そして、素材は一度集めれば一年使えます。募集が変わっても、作っているものと技術選定の理由は大きく変わらないからです。**最初にヒアリングを依頼範囲に入れるか**で、その後の質が決まります。エラベルは依頼側が担当者を選べる仕組みなので、この提案を自分からする担当者かどうかを、面談で確かめてみてください。

## まとめ

- 「特化型サービスのため、**大手ナビ媒体と比べ学生の受け取るスカウト数が限られており**、他企業に埋もれてしまう心配もありません」とされている。**一通の重みが大きい**
- 絞り込みは「**プログラミング経験の有無（授業での経験からリリース経験）や使用言語、志向性等**」。**絞った条件をそのまま一行目に書く**
- 登録学生は「意欲的な学生や、**プログラミング経験のある学生**が多く登録」とされ、「**技術的な実績や自主的なアウトプットを重視したマッチング**」が挙げられている
- 冒頭三行は、**技術の名指し／自社の技術の具体／差し出すもの一つ**。会社紹介は四行目以降
- 通数無制限のため、**インターン集客・説明会案内・面談案内**と用途を変えて時期をずらした接触ができる。**文面を二種類比べる検証**も組める
- 技術用語の使い方は**現場のエンジニアに読んでもらう**工程を入れる。仕様は変わるので、公式の案内でご確認ください

## よくある質問

### 文面に技術の話をどこまで書くべきですか

サポーターズの公式サイトは、スカウト・メディアについて「エンジニア領域特化型サービスであるため、プログラミング経験などの細かい絞り込み条件でターゲット学生をピンポイントでスカウトできます」としています。また、登録学生について「技術的な実績や自主的なアウトプットを重視したマッチングを行います」「コーディングスキルがあり、問題解決能力に長けたハイスキルなエンジニア学生に直接アプローチできます」と説明しています。絞り込みに使った技術条件を一行目に置き、自社が使っている技術と接続する形が、媒体の性質に沿います。用語の正確さが判断されるため、送る前に現場のエンジニアに読んでもらう工程を入れるのが実務です。

### 同じ学生に何度も送ってよいですか

公式サイトは、スカウト・メディアについて「スカウト送信の通数制限無しで、年間を通じてご利用いただけます。インターンシップの集客、会社説明会の案内、面談の案内など時期に応じて様々な用途でご利用いただけます」としています。同じ内容を繰り返すのではなく、時期と用途を変えて接触する設計が想定された書き方です。実務では、二通目以降に前回の案内に触れ、別の用途を差し出します。再送の具体的な条件は運営にご確認ください。

### 知名度がない会社でも書けることはありますか

公式サイトのよくある質問には「知名度が低い会社でも採用できますか？」という問いに対し「採用できます」との記載があり、デジタル・IT人材に特化した採用支援を行っているため採用ノウハウを伝えながらプランニングを支援できること、中長期的には「技育プロジェクト」を通じた認知度向上の支援を行っており、学生からの知名度は高くないBtoB企業などで認知度や就職意向度が向上した事例が多数あることが挙げられています。文面としては、知名度ではなく、いま何を作っていて、どう作っているかを具体に書くほうが、この媒体の読み手には届きます。

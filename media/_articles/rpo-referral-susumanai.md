社員の紹介による採用（リファラル）を始めた。制度を作り、謝礼を決め、全社に周知した。半年経って、紹介はゼロ。「知り合いを紹介してください」と言っても、社員は動かない。たまに紹介があっても、不採用にしたら、紹介した社員との関係が気まずくなった。結論を先に書くと、**リファラルが広がらないのは、「制度を作れば動く」と思っているからです。社員が紹介しないのは、制度が無いからではなく、「誰を紹介すればよいか分からない」「紹介して不採用だったら気まずい」「紹介の手間が重い」「紹介しても何も戻ってこない」からです。頼み方、戻し方、負担、不採用時の扱いの四つを設計すれば、制度が無くても動きます**。社員の紹介を急ぎで使う場面は[急な増員要請に対応できない](/media/rpo-kyuu-zouin/)に、知名度が無い会社の経路としては[知名度がなくて応募が集まらない](/media/rpo-chimeido-nai/)にまとめています。謝礼に関する扱いは、法令上の定めがあるので専門家に確認します。

## リファラルが広がらない構造

社員の紹介が広がらないのは、次の構造で起きます。

| 構造 | 起きていること |
|---|---|
| 「制度を作れば動く」と思っている | 謝礼と手続きを決めて周知しただけ。頼み方も戻し方も無い |
| 頼み方が曖昧 | 「知り合いを紹介してください」。誰を、どの役割で、が無い。社員は思い浮かべられない |
| 結果が戻らない | 紹介しても、選考の進み具合も結果も戻ってこない。「紹介して終わり」 |
| 紹介の手間が重い | 紹介の書式が長い、知り合いに履歴書を頼まないといけない、社内の手続きが多い |
| 不採用時の扱いが無い | 紹介した人が不採用になると、社員と知り合いの関係が気まずくなる。二度と紹介しない |
| 紹介する側の心理の壁 | 「自分の評価に響くのでは」「知り合いに悪い」「押しつけがましい」 |
| 会社の実態に自信が無い | 社員自身が「この会社を勧めてよいか」と迷っている。勧められない会社の紹介は来ない |
| 謝礼だけが目的に見える | 謝礼を前に出しすぎると、「金のために紹介する」と社員が感じ、動かない |

構造の大半は、「制度」ではなく「運用と関係」の問題です。

## 社員が紹介しない理由

社員に、なぜ紹介しないかを聞くと、理由は分かれます。

| 理由 | 中身 | 対処 |
|---|---|---|
| 誰を紹介すればよいか分からない | 「知り合い」では広すぎる。役割と要件が具体的でない | 頼み方を具体的に。「〇〇ができる人」「こういう経験の人」 |
| 不採用だったら気まずい | 知り合いを紹介して落とされると、関係が壊れる | 不採用時の扱いを先に決めて伝える |
| 紹介の手間が重い | 書式、履歴書、手続き | 手間を最小に。「名前と連絡先だけ」から |
| 自分の評価に響くのでは | 紹介した人が合わなかったら、自分の責任になるのでは | 「紹介した人の結果は、紹介した社員の評価に関係ない」を明言 |
| 会社を勧めてよいか迷う | 社員自身が、会社の実態に自信が無い | 会社の実態を良くする。または、「合う人」を絞って頼む |
| 知り合いに転職の意向があるか分からない | 「転職を考えているか」を聞きにくい | 「転職を考えていなくても、話を聞くだけの場（カジュアル面談）がある」と伝える |
| 何も戻ってこないので、やる気にならない | 過去に紹介して、結果が戻らなかった | 戻し方の運用を作り、過去の紹介にも結果を戻す |
| 謝礼が目的に見えて嫌 | 「金のために知り合いを売る」ように感じる | 謝礼を前に出さず、「一緒に働きたい人」を前に出す |

理由を聞くと、「制度」に関する理由は少なく、「頼み方」「戻し方」「気まずさ」「手間」に関する理由が多いです。

## 頼み方の型

「知り合いを紹介してください」ではなく、具体的に頼みます。

| 項目 | 頼み方 |
|---|---|
| 誰を | 「〇〇ができる人」「〇〇の経験がある人」「こういう動きをしていた人」。役割の記述から。「知り合い」ではなく像で |
| どの役割で | 「この役割で、一緒に働く人」。役割の一行と、一緒に働く人 |
| なぜ | 「〇〇の事業が広がって、この役割が要る」。理由があれば、社員は「自分の会社の話」として頼める |
| いつまでに | 「今月中に心当たりがあれば」。期限が無いと、後回しになる |
| どう紹介するか | 「名前と連絡先を、担当者に伝えてください。あとはこちらで」。手間を最小に |
| 転職の意向が無くても | 「転職を考えていなくても、話を聞くだけの場があります。まず紹介だけ」 |
| 不採用の場合 | 「合わなかった場合の連絡は、こちらが丁寧に行います。紹介した方の関係には影響しないよう配慮します」 |
| 誰が頼むか | 責任者から、部署の会議で。人事からの一斉メールより、責任者の口から |
| 頻度 | 求人が出るたびに。一度周知して終わりにしない |
| 個別に頼む | 「〇〇さんの前の会社に、こういう人はいませんでしたか」。全体への周知より、個別の声かけ |

頼み方の要点は、「像を具体的に、責任者から、個別に、繰り返し」です。全社への一斉メールで「知り合いを紹介してください」は、頼んでいないのと同じです。

社員が「この人かも」と思い浮かべられる像を渡すことが、紹介の出発点です。

## 結果を戻す運用

紹介があったら、結果を戻します。戻さなければ、次の紹介は来ません。

**紹介を受けたら、当日に社員に「受け取りました」と伝える。** 「〇〇さんをご紹介いただき、ありがとうございます。担当者から〇日までに連絡します」。

**紹介された人に、担当者から連絡する。** 社員を通さず、担当者が直接。「〇〇さんからご紹介いただきました。まず話を聞く場をご案内します」。カジュアル面談から。

**選考の進み具合を、社員に戻す。** 「面談を行いました」「選考に進みました」「内定を出しました」。節目ごとに、一行で。詳細（評価の内容）は戻さない。

**結果を、社員に戻す。** 「入社が決まりました」「今回はご縁がありませんでした」。不採用の場合の戻し方は、次の章。

**紹介した社員に、感謝を伝える。** 入社が決まったら、責任者から。「〇〇さんのご紹介で、△△さんが入社しました。ありがとうございました」。全社に共有する場合は、紹介した社員と入社した人の同意のうえで。

**入社した人の、その後を戻す。** 「〇〇さんが、こういう場面で活躍しています」。紹介した社員は、「紹介してよかった」と感じます。

**過去の紹介で、戻していないものがあれば、今から戻す。** 遅れたことを詫びて。

戻す運用の要点は、「節目ごとに一行」と「入社後も戻す」ことです。戻し方が無いリファラルは、「紹介して終わり」になり、社員は動かなくなります。

### エラベルの見解

相談で最も多い失敗は、「リファラルの制度を作り、謝礼を決め、全社にメールで周知して、半年待ったが紹介ゼロ」というものです。頼み方が「知り合いを紹介してください」の一斉メールで、社員は誰を紹介すればよいか分からず、不採用時の扱いも分からず、動きませんでした。責任者が部署の会議で「〇〇ができる人、心当たりはありませんか。名前と連絡先だけで、あとはこちらで。合わなかった場合の連絡は丁寧に行います」と個別に頼み、紹介があれば節目ごとに戻す形にしたら、制度は同じまま、紹介が動き始めました。制度ではなく、頼み方と戻し方でした。

見ていて差がつくのは、担当者が「制度」ではなく「運用」を設計するかどうかです。「リファラルの制度を整えましょう」と言う担当者と、「制度は最小でよいです。頼み方を役割の像で具体的にし、責任者から個別に頼み、紹介があれば節目ごとに戻し、不採用時の扱いを先に決めましょう」と、運用を設計する担当者がいます。後者のリファラルは、動きます。

発注側にできるのは、「制度を作ったのに動かない」を「頼み方と戻し方が無い」と読み替えることです。

## 紹介する側の負担の減らし方

紹介の手間と心理の負担を減らします。

**紹介は「名前と連絡先」だけから。** 書式、履歴書、推薦文を社員に求めない。名前と連絡先を担当者に伝えれば、あとは担当者が動く。

**紹介された人への最初の連絡は、担当者が。** 社員が知り合いに「応募して」と頼む形にしない。担当者が「まず話を聞く場」を案内する。

**カジュアル面談を、入口に。** 「転職を考えていなくても、話を聞くだけ」の場があれば、社員は「まず話を聞いてみない？」と軽く声をかけられる。面談は選考にしない（[カジュアル面談が選考になってしまう](/media/rpo-casual-mendan-kadai/)）。

**社員が知り合いに渡せる材料を、用意する。** 会社の説明の一枚、役割の一行、採用ページのリンク。社員が自分で説明しなくて済む。

**「紹介した人の結果は、社員の評価に関係ない」を明言する。** 責任者から。心理の壁を下げる。

**「紹介の義務」にしない。** 「一人以上紹介」のような目標や圧は、紹介の質を下げ、社員の不満になる。頼むのは具体的に、圧はかけない。

**社員の時間を、使わせない。** 紹介のために社員が面談に同席する、知り合いと会社の間で調整する、といった負担を求めない。

負担の要点は、「社員は名前と連絡先を渡すだけ、あとは会社が動く」ことです。社員に手間と責任を負わせる形は、広がりません。

## 不採用時の扱い

紹介された人を不採用にする場合の扱いです。ここが雑だと、次の紹介は来ません。

**先に、扱いを決めて社員に伝える。** 「合わなかった場合、こちらから丁寧に連絡します。紹介した方の関係に影響しないよう配慮します」。頼むときに伝える。

**紹介された人への不採用の連絡は、担当者から、丁寧に。** 通常の不合格の連絡（[不合格連絡が遅い・出していない](/media/rpo-fugouhi-renraku/)）以上に丁寧に。「〇〇さんからのご紹介で、お話しできてよかったです。今回はご縁がありませんでしたが」。理由は、要件に対する事実の範囲で。

**紹介した社員には、結果だけを戻す。** 「今回はご縁がありませんでした」。評価の内容や理由の詳細は、社員に戻さない。社員から知り合いに伝わる形を避ける。

**社員に、感謝を伝える。** 「ご紹介いただき、ありがとうございました。今回は合いませんでしたが、また心当たりがあれば」。不採用でも、紹介は感謝の対象。

**「合わなかった」の言い方に、配慮する。** 「能力が足りない」ではなく、「今回の役割との合い」。紹介した社員が、知り合いに説明しやすい言い方。

**社員と知り合いの関係を、壊さない。** 紹介された人に「〇〇さんが紹介してくれたから会えた」と伝え、紹介した社員に感謝が向く形に。

**紹介した社員に、「紹介の結果は評価に関係ない」を再度伝える。** 不採用の後こそ。

不採用時の要点は、「先に伝える」ことと「担当者が丁寧に連絡する」ことです。社員に「知り合いに断りを伝えて」と頼む形は、最も気まずさを生みます。

## 謝礼と法令上の扱い

謝礼は、リファラルの中心ではありませんが、設ける場合の考え方です。

**謝礼は、前に出さない。** 「一緒に働きたい人を」が前で、謝礼は後。謝礼を前に出すと、「金のために」と社員が感じます。

**謝礼の有無と額は、社内の規程と法令上の扱いを専門家に確認する。** 社員への紹介の謝礼には、法令上の扱いに関する論点があります。設ける場合の形、額の考え方、支給の時期と条件は、専門家（社労士、弁護士）に確認します。

**謝礼の条件を、明確にする。** 「入社後〇か月の在籍で支給」など。条件は社内の規程に沿い、専門家に確認。

**謝礼より、感謝と戻し方が効く。** 責任者からの感謝、入社後の様子の共有、全社での紹介（同意のうえで）。謝礼が無くても、これらがあれば動きます。

**謝礼だけを増やしても、紹介は増えない。** 頼み方と戻し方と負担と不採用時の扱いが無ければ、謝礼を上げても動きません。

謝礼の要点は、「中心にしない」ことと「法令上の扱いを専門家に確認する」ことです。

## 外注する場合の範囲

リファラルが広がらない問題を、採用代行に出す場合の範囲です。

**出せる工程。** 社員が紹介しない理由の聞き取り、頼み方の型（役割の像、責任者向けの頼み方の文面、個別の声かけの設計）、社員が知り合いに渡せる材料（会社の一枚、役割の一行、採用ページ）、紹介の受付の窓口（名前と連絡先を受け取り、担当者が動く）、紹介された人への最初の連絡とカジュアル面談の設定、選考の進み具合と結果を社員に戻す運用、不採用時の連絡（紹介された人へ丁寧に、社員へ結果だけ）、感謝の伝え方の型、入社後の様子の共有、謝礼の設計の整理（専門家への橋渡し）、紹介の数と入社の数と定着の記録。

**社内に残す判断。** リファラルを進める方針、責任者が頼むこと、「評価に関係ない」の明言、謝礼の有無と額と条件（専門家との連携）、判定、内定、全社への共有の可否。

**外注の効きどころ。** リファラルは、「紹介があってからの運用」（連絡、面談、戻し、不採用時の扱い）が、社内では手が回らず雑になりやすい工程です。担当者が受付の窓口になり、紹介された人への連絡と面談と戻しを丁寧に回せば、社員は「紹介すると、ちゃんと動いてくれる」と感じ、次の紹介につながります。頼み方の型も、担当者が責任者向けに用意できます。

**外注しても動かない場合。** 責任者が個別に頼まない、「評価に関係ない」を明言しない、社員が会社を勧められないほど実態が悪い。社内の判断で、代行を替えても直りません。

リファラルは、制度ではなく運用で動きます。外注は、運用を回す手段です。

### エラベルの見解

担当する側から見ると、リファラルの相談で最も多いのは、「社員が会社を勧めてよいか迷っている」ことです。制度も頼み方も整えたが、紹介が来ない。社員に聞くと、「知り合いに勧められるほど、うちは良い会社か分からない」。

これは、リファラルの問題ではなく、会社の実態の問題です。社員が勧められない会社に、紹介は来ません。逆に、社員が「一緒に働いてほしい」と思える会社は、制度が無くても紹介が来ます。リファラルの動き方は、会社の実態の指標でもあります。

発注側にできるのは、紹介が来ない理由を社員に聞き、「勧められない」が理由なら、リファラルの設計ではなく、会社の実態を直すことです。

## よくある質問

### 制度と謝礼を作ったのに、紹介が来ません

制度と謝礼は、リファラルの中心ではありません。社員が紹介しない理由（誰を紹介すればよいか分からない、不採用だと気まずい、手間が重い、何も戻らない）を聞き、頼み方（役割の像を具体的に、責任者から個別に）、戻し方（節目ごとに一行）、負担（名前と連絡先だけ）、不採用時の扱い（先に伝え、担当者が丁寧に）を設計します。制度は同じままでも、運用が変われば動きます。「勧められない」が理由なら、会社の実態の問題です。

### 紹介された人を不採用にしたら、社員が気まずそうです

先に扱いを決めて伝えていなかったことが原因です。今からでも、社員に「ご紹介ありがとうございました。今回は役割との合いで、ご縁がありませんでした。紹介の結果は、あなたの評価に関係ありません」と、責任者から感謝と明言を伝えます。紹介された人には、担当者から丁寧に連絡し、「〇〇さんからのご紹介で、お話しできてよかった」と、紹介した社員に感謝が向く形に。次からは、頼むときに「合わなかった場合はこちらが丁寧に連絡します」と先に伝えます。

### 謝礼を上げれば、紹介は増えますか

増えません。謝礼を上げても、頼み方と戻し方と負担と不採用時の扱いが無ければ、動きません。謝礼を前に出しすぎると、「金のために知り合いを売る」と社員が感じ、かえって動かなくなります。謝礼より、責任者からの感謝、入社後の様子の共有、丁寧な運用のほうが効きます。謝礼を設ける場合の形と額と条件は、法令上の扱いに関する論点があるので、専門家（社労士、弁護士）に確認します。

依頼側の担当者から「採用がうまくいっていない」「応募は来るが決まらない」と聞いた。困っていることは分かるが、何が原因で、どこから手を付ければよいかが、その言葉からは見えない。自分の範囲で何をすれば効くのかも分からない。結論を先に書くと、**依頼側の漠然とした課題は、「採用を工程で分ける」「止まっている場所を記録で特定する」「原因を依頼側の範囲と自分の範囲に分ける」「取り組む課題を一つに絞る」の四段で構造にします。構造にすれば、依頼側の担当者は社内で「ここで止まっている」と説明でき、自分は自分の範囲で動けます。**「採用がうまくいかない」のまま動くと、思いついた施策を順に試すことになり、効かず、稼働だけが使われます。課題の言語化は[課題の言語化](/media/fukugyo-kadai-teigi/)に、現状の把握は[現状把握のしかた](/media/fukugyo-genjou-haaku/)に、ヒアリングの項目は[ヒアリングで押さえる項目](/media/fukugyo-hearing/)にまとめています。

## 構造化が要る理由

依頼側の課題は、依頼側の担当者の中でも、構造になっていないことが多いです。構造にしないまま動くと、何が起きるかを見ます。

| 構造にしないまま動くと | 何が起きるか |
|---|---|
| 「うまくいかない」に対して、思いついた施策を試す | 媒体を増やす、文面を変える、要件を緩める、と順に試し、どれも効かず、稼働と依頼側の予算が消える |
| 原因を一つに決めつける | 「文面が悪い」と決めて文面を直すが、実際は面接の日程で止まっていた |
| 依頼側の範囲の問題を、自分の範囲で解こうとする | 面接官の判断で止まっているのに、スカウトの送信を増やす |
| 依頼側の担当者が社内で説明できない | 「外部に頼んだが、うまくいっていない」としか言えず、上長は外部の価値を疑う |
| 成果の定義ができない | 何が課題かが決まっていないので、何が成果かも決まらない |
| 課題が全部に見え、手が出ない | 「全部悪い」と感じ、どこから手を付ければよいか分からず、動けない |

理由の要点は、「構造が無いと、原因ではなく思いつきで動く」ことです。思いつきで動いた施策は、効いても偶然で、効かなくても理由が分かりません。構造にして、止まっている場所と原因を特定してから動けば、施策は「その場所に効くもの」になり、効かなかったときも「原因の見立てが違った」と分かります。思いつきの提案が通らない理由は[提案が通らなかったとき](/media/fukugyo-hantai-sareta/)にも書いています。

## 四段の手順

課題を構造にする四段です。順番を守ると、依頼側の課題は動ける形になります。

| 段 | 内容 | 出てくるもの |
|---|---|---|
| 一、工程で分ける | 採用を、母集団→反応→書類→日程→面接→内定→承諾の工程に分ける。依頼側の実際の流れに合わせる | 工程の一覧 |
| 二、止まっている場所を記録で特定する | 各工程の出口の数字を、依頼側の記録から見て、どの工程で数字が落ちているかを見つける | 止まっている工程（一つか二つ） |
| 三、原因を範囲で分ける | 止まっている工程の原因の候補を挙げ、それぞれが依頼側の範囲か自分の範囲かを分ける | 原因の候補と、誰の範囲か |
| 四、一つに絞る | 自分の範囲で動かせて、記録で結果が見え、数週間で試せる原因を一つ選ぶ | 取り組む課題（一つ） |

四段の要点は、「二」で記録を使うことです。依頼側の担当者の「応募は来るが決まらない」は感覚で、記録を見ると、応募から書類の通過で落ちているのか、書類の通過から面接の日程で落ちているのか、面接から内定で落ちているのかが、数字で分かります。感覚で止まっている場所を決めると、外れます。記録から工程ごとの出口を取る方法は[KPIを設計する](/media/fukugyo-kpi-sekkei-skill/)に、数字の語り方は[数字で語る](/media/fukugyo-suuji/)に整理しています。

### エラベルの見解

相談で最も多い思い込みは、「課題を構造化するには、分析の専門的な手法が要る」というものです。実際には、副業の担当者に要る構造化は、採用の工程を分けて、記録で数字が落ちている工程を見つけ、原因を範囲で分けて、一つに絞る、という四段で、専門的な手法は要りません。要るのは、依頼側の記録を工程ごとに見る習慣と、原因を「誰の範囲か」で分ける癖です。

見ていて差がつくのは、「三」の原因を範囲で分けているかです。止まっている工程が面接から内定で、原因が面接官の判断や条件なら、それは依頼側の範囲で、自分がスカウトを増やしても効きません。原因を範囲で分けずに動く人は、依頼側の範囲の問題を自分の範囲の施策で解こうとして、稼働を使い、成果が出ず、「成果が見えない」と言われています。分けている人は、「ここは御社の範囲で、ここは私の範囲。私の範囲ではこれをやります」と言え、依頼側の担当者も社内で説明できています。エラベルでは、担当者が依頼側の課題を扱うとき、工程と範囲で構造にする形をお願いしています。構造化は、分析の技術ではなく、動ける形にする整理です。

## 工程で分ける型

「一」の工程の分け方の型です。依頼側の実際の流れに合わせて、足したり減らしたりします。

| 工程 | 入口 | 出口 | よく止まる原因の候補 |
|---|---|---|---|
| 母集団の形成 | 募集の開始 | 応募、スカウトの送信 | 媒体の選定、求人票の内容、送る相手の絞り方 |
| 反応 | 送信 | 返信 | 文面、送る相手、送信の時間帯、求人の魅力 |
| 書類の選考 | 応募・返信 | 通過 | 要件の設定、選考の基準、選考の速さ |
| 日程の調整 | 通過 | 面接の確定 | 面接官の予定、候補者への提示の速さ、候補日の数 |
| 面接 | 面接の実施 | 通過 | 面接官の評価の基準、面接の内容、候補者の印象 |
| 内定 | 面接の通過 | 内定の提示 | 社内の承認の速さ、条件の決定 |
| 承諾 | 内定の提示 | 承諾 | 条件、他社との比較、内定後の連絡 |

型の要点は、「各工程の出口を、次の工程の入口として並べる」ことです。並べると、どの出口で数字が落ちているかが、一目で分かります。出口の数字が落ちている工程が、止まっている場所です。工程の分け方は、依頼側に無い工程（二次面接が無いなど）は置かず、依頼側にある工程（適性検査など）は足します。依頼側の流れの聞き方は[ヒアリングで押さえる項目](/media/fukugyo-hearing/)に書いています。

## 記録で止まっている場所を特定する

「二」の、記録から止まっている場所を見つける方法です。感覚ではなく、数字で見ます。

| 手順 | 内容 |
|---|---|
| 一、各工程の出口の数を、記録から取る | 依頼側のATSと媒体の管理画面から、直近数か月の、工程ごとの出口の数を取る |
| 二、工程の間の落ち幅を見る | 「送信〇通→返信〇件」「通過〇件→面接の確定〇件」のように、前の工程の出口から次の工程の出口への落ち幅を見る |
| 三、落ち幅が最も大きい工程を見つける | 落ち幅が大きい工程が、止まっている場所の候補。一つか二つに絞る |
| 四、その工程の中身を見る | 落ちている理由を、記録の中身（辞退の理由、選考の結果の理由）から見る |
| 五、依頼側の担当者の感覚と比べる | 担当者の「ここで困っている」と、記録の落ち幅が合っているか。合っていなければ、記録を担当者に見せる |

特定の要点は、「五」で担当者の感覚と記録を比べることです。担当者は「応募が少ない」と感じていても、記録では応募は足りていて、書類の通過から面接の日程で落ちている、ということがあります。記録を見せれば、担当者は「そこだったのか」と気づき、課題の認識が揃います。記録が無い工程は、記録を始めることが最初の課題になります。記録の整え方は[議事録の残し方](/media/fukugyo-gijiroku/)と[稼働ログの付け方](/media/fukugyo-log/)に整理しています。

## 原因を範囲で分ける

「三」の、原因を依頼側の範囲と自分の範囲に分ける考え方です。分けないと、動けない原因に稼働を使います。

| 止まっている工程 | 原因の候補 | 誰の範囲か | 自分の範囲でできること |
|---|---|---|---|
| 反応（返信が少ない） | 文面、送る相手の絞り方 | 自分（スカウトを担当していれば） | 文面の構造を変える、相手の条件を変える |
| 反応（返信が少ない） | 求人の条件が市場と合わない | 依頼側 | 事実として示す。条件の判断は依頼側 |
| 日程の調整（確定が遅い） | 候補者への提示の速さ、候補日の数 | 自分（日程調整を担当していれば） | 複数の候補日を最初から提示する |
| 日程の調整（確定が遅い） | 面接官の予定が取れない | 依頼側 | 枠の固定を提案する。確保は依頼側 |
| 面接（通過が少ない） | 面接官の評価の基準が曖昧、面接の内容 | 依頼側 | 準備の資料を整える。評価は依頼側 |
| 面接（通過が少ない） | 送っている候補者が要件と合っていない | 自分 | 送る相手の絞り方を要件に寄せる |
| 承諾（辞退が多い） | 条件、他社との比較 | 依頼側 | 事実として示す。条件は依頼側 |
| 承諾（辞退が多い） | 内定後の連絡が無い | 自分（内定者の連絡を担当していれば） | 連絡の型を作る |

分ける要点は、「同じ工程でも、原因によって範囲が違う」ことです。返信が少ない原因が文面なら自分の範囲で、求人の条件なら依頼側の範囲です。自分の範囲の原因は自分で動き、依頼側の範囲の原因は事実として示して判断を依頼側に返す。この分け方で、動ける原因と動けない原因が分かれ、稼働を動ける原因に集中できます。範囲の線は[権限がないと動けない場面](/media/fukugyo-kengen-nai/)に、依頼側の範囲の示し方は[成果が見えない](/media/fukugyo-shippai-4/)に書いています。

## 一つに絞る基準

「四」の、取り組む課題を一つに絞る基準です。複数に取り組むと、どれも薄くなります。

| 基準 | 内容 | なぜ |
|---|---|---|
| 自分の範囲で動かせる | 依頼側の判断を待たずに、自分の稼働で試せる | 依頼側の範囲は、自分では動かせない |
| 記録で結果が見える | 変えた後、依頼側の記録の数字で結果が分かる | 見えない結果は、効いたかどうか分からない |
| 数週間で試せる | 一か月から二か月で、変えた結果が出る | 長すぎると、依頼側の期待が持たない。[短期成果と中長期施策のバランス](/media/fukugyo-tanki-choki/) |
| 落ち幅が大きい工程に関わる | 最も落ちている工程の原因 | 小さい落ち幅を直しても、全体は変わらない |
| 失敗しても損が小さい | 効かなかったときに、依頼側の採用が悪化しない | 文面や相手の絞り方は戻せる。要件の変更は戻しにくい |
| 依頼側の担当者が納得している | 記録を見せて、担当者が「そこだ」と思っている | 納得していない課題に取り組んでも、依頼側は協力しない |

絞る要点は、「自分の範囲で動かせて、記録で見えて、数週間で試せる」の三つが揃う課題を選ぶことです。三つが揃わない課題（依頼側の範囲、結果が見えない、時間がかかる）は、一つ目の課題で結果を出した後に、提案として出します。課題を一つに絞る考え方は[課題の言語化](/media/fukugyo-kadai-teigi/)に、最初の数週間で出す成果は[早い段階で成果を出す](/media/fukugyo-quick-win/)に整理しています。

## 構造を依頼側と共有する一枚

構造にした課題は、一枚にして依頼側と共有します。担当者が社内で使える形にします。

| 項目 | 内容 |
|---|---|
| 工程の一覧と出口の数字 | 直近数か月の、工程ごとの出口の数。記録の出どころを添える |
| 止まっている工程 | 落ち幅が大きい工程を、一つか二つ |
| 原因の候補と範囲 | その工程の原因の候補と、それぞれが依頼側の範囲か自分の範囲か |
| 取り組む課題（一つ） | 自分の範囲で、最初に取り組む原因と、その理由 |
| 依頼側に判断してほしいこと | 依頼側の範囲の原因について、依頼側に決めてほしいこと |
| 結果を見る数字と時期 | 何の数字を、いつ見るか |

一枚の要点は、「依頼側に判断してほしいこと」を分けて書くことです。依頼側の範囲の原因は、自分の課題ではなく、依頼側の判断の対象です。「面接官の枠の固定は御社でご判断ください。私は候補日の提示の速さを直します」と、分けて書けば、担当者は社内に「外部はここをやり、社内はここを決める」と伝えられます。一枚の作り方は[提案のまとめ方](/media/fukugyo-teian/)に、伝え方は[改善提案の伝え方](/media/fukugyo-kaizen-teian/)に書いています。

## 構造化でやりがちな失敗

構造化の途中で、やりがちな失敗があります。

| 失敗 | 何が起きるか | 防ぎ方 |
|---|---|---|
| 記録を見ずに、担当者の感覚で止まっている場所を決める | 実際の落ち幅と違う場所に取り組み、効かない | 記録を先に見る。感覚は記録と比べる |
| 原因を一つに決めつける | 「文面が悪い」と決めて、他の候補を見ない | 原因の候補を複数挙げてから、範囲と基準で絞る |
| 依頼側の範囲の原因に、自分の範囲で取り組む | 稼働を使って効かない | 範囲で分け、依頼側の範囲は判断を返す |
| 全部の課題に一度に取り組む | どれも薄くなり、結果が見えない | 一つに絞る。二つ目は一つ目の結果の後 |
| 構造を自分の中だけに持つ | 依頼側の担当者と認識が揃わず、協力が得られない | 一枚にして共有し、担当者に「そこだ」と言ってもらう |
| 構造化に時間をかけすぎる | 分析が長引き、動き出すのが遅れる | 最初の数週間で四段を済ませ、動きながら直す |
| 依頼側の担当者を責める形になる | 「御社の面接官が遅い」と言い、担当者の立場を悪くする | 人ではなく工程で書く。「面接の評価の段階で止まっている」 |

失敗の要点は、「構造化に時間をかけすぎる」ことです。構造は、動くための整理で、完璧な分析ではありません。最初の数週間で四段を済ませ、一つに絞って動き、結果を見て構造を直す。動きながら構造を精度よくしていくほうが、最初に完璧な構造を作ろうとするより、依頼側の期待に合います。

### エラベルの見解

担当する側から見ると、依頼側の課題に対して効く施策を出せている人は、施策の引き出しが多い人ではなく、課題を構造にしてから施策を選んでいる人です。工程で分け、記録で止まっている場所を見つけ、原因を範囲で分け、一つに絞る。この四段を踏んでから施策を選ぶので、施策は止まっている場所に効き、効かなかったときも原因の見立てを直せます。思いつきで施策を出す人は、引き出しが多くても、効く施策に当たるまで稼働を使い、依頼側の予算を消しています。

順番として、案件の最初の数週間で、依頼側の流れを工程に分け、記録から工程ごとの出口を取り、落ち幅が大きい工程を見つけ、原因の候補を範囲で分け、自分の範囲で動かせる一つに絞り、一枚にして担当者と認識を揃え、動き、結果を見て構造を直す。この順番で、「採用がうまくいかない」は、動ける課題になります。エラベルでは、担当者が依頼側の課題を扱うとき、工程と記録と範囲で構造にする形をお願いしています。構造化は、依頼側の担当者が社内で説明できる形を作ることであり、自分が自分の範囲で動ける形を作ることです。

## まとめ

- 漠然とした課題は**工程で分ける→止まっている場所を記録で特定する→原因を範囲で分ける→一つに絞る**の四段で構造にする
- 構造にしないと**思いつきの施策を順に試し、効かず、稼働と予算が消える**
- 工程は**各工程の出口を次の入口として並べ**、出口の数字が落ちている工程を見つける
- 止まっている場所は**記録の落ち幅**で特定し、担当者の感覚と比べて認識を揃える
- 原因は**同じ工程でも範囲が違う**。自分の範囲は動き、依頼側の範囲は判断を返す
- 一つに絞る基準は**自分の範囲で動かせる・記録で見える・数週間で試せる・落ち幅が大きい・失敗の損が小さい・担当者が納得している**
- **一枚にして共有し**、依頼側に判断してほしいことを分けて書く。構造化に時間をかけすぎず、動きながら直す

## よくある質問

### 依頼側の担当者が「全部が課題だ」と言い、一つに絞ることを嫌がります

記録の工程ごとの出口を一枚にして見せ、「全部の工程で落ちているように見えますが、落ち幅が最も大きいのはここです。ここを直すと、全体の数字が最も動きます」と、記録で示します。「全部」は感覚で、記録を見れば、落ち幅には差があります。担当者が記録で「そこだ」と納得すれば、一つに絞れます。それでも「全部」と言うなら、「まず一つを数週間で試し、結果を見て次に進む」と、順番の形で提案します。提案の形は[改善提案の伝え方](/media/fukugyo-kaizen-teian/)に整理しています。

### 止まっている場所が、全部依頼側の範囲でした

自分の範囲で動かせる原因が無い場合、自分の範囲の工程は動いていて、その先で止まっていることになります。それは、自分の範囲の成果としては良い状態で、止まっている場所を事実として依頼側に示し、判断を返します。「私の範囲の工程は動いています。止まっているのは〇〇の工程で、原因は△△と見ています。ここは御社のご判断で、私の範囲でできることは□□です」の形です。依頼側が動かなければ、その案件では成果が出ない構造で、更新の節目で範囲か案件を見直します。依頼側の範囲で止まる場面は[成果が見えない](/media/fukugyo-shippai-4/)に書いています。

### 構造化した結果、自分の範囲の外に課題があり、範囲を広げるべきか迷います

範囲を広げるなら、更新の節目で、稼働と条件と一緒に広げます。構造化の結果は、範囲を広げる根拠になります。「止まっている工程は〇〇で、私の今の範囲の外です。次の期に、この工程を範囲に入れる形をご相談したいです」と、構造の一枚を根拠に提案します。なし崩しに範囲の外に取り組むと、範囲の膨張になります。広げ方は[範囲の膨張](/media/fukugyo-shippai-2/)と[次の案件へ広げる](/media/fukugyo-tsugi-e/)に整理しています。

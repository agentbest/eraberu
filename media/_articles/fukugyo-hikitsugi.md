副業の案件は、いつか終わります。区切りで終える、依頼側の採用が終わる、自分の時間が取れなくなる。終わり方は色々ですが、終えるときに何を残すかで、その後の関係が決まります。引き継ぎが無いと、直した仕組みは自分がいなくなった週から止まり、依頼側は「いなくなったら元に戻った」と感じます。結論を先に書くと、**引き継ぎ資料は「型（仕組みの手順と文面）」「いまの状態（進行中の応募者と数）」「未完了の一覧（残った課題と判断待ち）」「連絡と権限の整理（返したもの・止めたもの）」の四つを残す**と、依頼側は自分がいなくても回せ、次の依頼や紹介につながります。型の書き方は[資料の作り方](/media/fukugyo-shiryou/)に、終えたあとに続けてもらう考え方は[継続してもらうために](/media/fukugyo-keizoku/)にまとめています。

## 引き継ぎで残す四つ

残すものを四つに分け、それぞれの中身を示します。

| 残すもの | 中身 | 誰が使うか |
|---|---|---|
| 一 型 | 直した仕組みの手順、文面の雛形、見る数、崩れたときの見方。役割名で | 担当、次の担当 |
| 二 いまの状態 | 進行中の応募者の段階と次の対応（依頼側の環境の中の表で）、直近の数 | 担当 |
| 三 未完了の一覧 | 残った課題、判断待ち、途中の作業。どこまでやって、次に何をすればよいか | 担当、判断する人 |
| 四 連絡と権限の整理 | 返した権限、止めたアカウント、自分の側に残っていないことの確認、以後の連絡先（あれば） | 担当 |

四つの要点は、「一の型は、副業の途中から作っておく」ことです。終わりが決まってから型を作ると、時間が足りません。三か月目に型にして渡す設計にしておけば、引き継ぎの型はすでにある状態で終われます。[稼働開始から九十日の設計](/media/fukugyo-shoki-90nichi/)を参照してください。

## 終わりが決まってからの手順

終わりが決まってから、最後の稼働までの手順を番号付きで整理します。二〜四週間の目安です。

1. **終わりの日を、依頼側と書面で決める。** 最後の稼働日と、引き継ぎを渡す日。[契約期間の決め方](/media/fukugyo-keiyaku-kikan/)
2. **型を確定する。** 途中で作っていた型を、最新の手順と文面に直す。自分の名前と判断を、役割名と基準に置き換える。
3. **いまの状態を、依頼側の環境の中の表で整える。** 進行中の応募者の段階と次の対応を、担当が見て分かる形に。自分の側には作らない。
4. **未完了の一覧を作る。** 残った課題（優先順位付き）、判断待ち（期限付き）、途中の作業（どこまでやったか）。
5. **担当に、型で一度回してもらう。** 自分が見ている間に、担当が型どおりに一週間回す。迷った箇所を型に足す。
6. **引き継ぎの打ち合わせを持つ。** 四つを渡し、担当の質問に答える。判断する人にも四つを送る。
7. **権限を返す。** 依頼側の環境の自分専用のアカウントを止めてもらう。媒体の権限、共有フォルダの権限。
8. **自分の側に残っていないことを確認する。** 端末、メール、メモ。応募者の情報と依頼側の内情が無いこと。契約と請求の控えは残す。
9. **最後の請求と、区切りの数を送る。** 開始時点から終了時点までの数の変化。[請求書の書き方](/media/fukugyo-seikyuusho/)
10. **以後の連絡について、一言添える。** 「型で迷った点があれば、〇〇までご連絡ください」。範囲と時間を決めた形で。

手順の要点は、「五で、担当に型で回してもらう」ことです。型を渡しただけでは、担当が使えるかどうか分かりません。自分が見ている間に一度回してもらうと、型の抜けが見つかり、担当は自信を持って引き継げます。

### エラベルの見解

登録の相談で多いのは、「案件を終えたあとに、依頼側から『あの仕組みが止まった』と連絡が来た」という話です。型は渡していたが、担当が使い方を分からず、元のやり方に戻っていた。渡すだけでは、引き継ぎになっていません。担当が回せるところまで見届けて、初めて引き継ぎです。

見ていて差がつくのは、「終わる前に、担当に一週間回してもらっているか」です。自分がいる間に担当が回すと、型のどこで迷うかが分かり、そこを足せます。担当は「自分でも回せる」と分かり、副業の人がいなくなっても仕組みが残ります。エラベルの登録でも、案件を終えたあとに依頼側から次の相談や紹介が来る人は、この見届けをしています。終わり方が、次の始まりを決めます。

## 未完了の一覧の書き方

四つのうち、未完了の一覧は、書き方で依頼側の受け取り方が変わります。型を示します。

| 項目 | 書くこと | 例 |
|---|---|---|
| 残った課題 | 優先順位、課題の形（何が・どこで・なぜ）、範囲の中か外か、次にやるなら何から | 「一 書類確認の日数。判断の返事の目安が未決。判断する人が目安を決めるところから」 |
| 判断待ち | 項目、選択肢、期限、誰の判断か | 「応募者二件の一次絞りの判断。AかB。今週中。担当」 |
| 途中の作業 | どこまでやったか、残りは何か、置き場所 | 「スカウト文面の型三つ目。冒頭まで作成。共有フォルダの〇〇」 |
| 手を付けなかったこと | 気づいていたが範囲外か時間が無かったこと | 「面接の辞退率。設定から実施までの連絡が無い。範囲外として記録」 |

一覧の要点は、「手を付けなかったことも書く」ことです。書かないと、依頼側は気づかないまま、あとで「知っていたなら言ってほしかった」となります。書いておけば、次の担当や次の副業の人が、そこから始められます。

## 情報を残さない線

引き継ぎは、依頼側に残すものと、自分の側に残さないものを、はっきり分けます。

| 依頼側に残す | 自分の側に残さない | 自分の側に残す |
|---|---|---|
| 型（役割名、手順、文面の雛形） | 応募者の情報（名前、連絡先、経歴、評価） | 契約の控え |
| いまの状態の表（依頼側の環境の中） | 依頼側の内情（予算、社内の事情、採用計画） | 請求の控え |
| 未完了の一覧 | 依頼側の環境の権限 | 稼働の記録（業務の種類と数だけ） |
| 区切りの数（開始時点と終了時点） | 依頼側とのチャットの内容 | 一般化した型（社名・名前・数値・時期を消したもの） |

線の要点は、「自分の側に残す一般化した型は、依頼側に渡した型とは別物」ということです。依頼側に渡す型には依頼側の文面と手順がそのまま入りますが、自分の側に残すのは、それを一般化して、どの依頼側にも使える形にしたものです。依頼側の文面をそのまま自分の側に残さないでください。[情報の取り扱いと端末の分離](/media/fukugyo-security/)を参照してください。

## 引き継ぎで起きる失敗

引き継ぎで起きやすい失敗を整理します。

| 失敗 | 起きる構造 | 直し方 |
|---|---|---|
| 終わりが決まってから型を作り始める | 途中で作っていない | 三か月目に型にする設計。終わりが決まる前から |
| 型を渡すだけで見届けない | 時間が無い | 最後の一週間は担当に回してもらう |
| 型に自分の名前と判断が残っている | 自分がやっていた前提 | 役割名と基準に置き換える |
| いまの状態を自分の側で作る | 手元のほうが作りやすい | 依頼側の環境の中の表で |
| 未完了を書かない | 終わるので関係ないと思う | 書く。手を付けなかったことも |
| 権限を返さない | 忘れる。「念のため」 | 書面に。止めてもらったことを確認 |
| 自分の側に応募者の情報が残る | 消し忘れ | 端末、メール、メモを確認。契約と請求の控えだけ |
| 依頼側の文面をそのまま自分の型にする | 次に使いたい | 一般化する。社名・名前・数値・時期を消す |
| 最後の稼働で急に終わる | 引き継ぎの時間を取っていない | 終わりの二〜四週間前から手順に沿う |
| 以後の連絡を曖昧にする | 言いにくい | 「型で迷った点は〇〇まで」と範囲を決めて一言 |

失敗の要点は、「終わりが決まってから慌てる」ことで起きています。副業の途中から、終わることを前提に型を作り、記録を残していれば、引き継ぎは整えるだけで済みます。

### エラベルの見解

担当する側として登録した人の話を聞くと、案件を終えたあとに次の依頼や紹介が来る人は、引き継ぎに時間をかけています。終わりの一か月を引き継ぎに使い、担当に回してもらい、四つを渡し、権限を返す。依頼側から見ると、「最後まで丁寧だった人」で、仕組みが残っているので、次の採用のときに「また頼みたい」となります。慌てて終えた人は、仕組みが止まり、「いなくなったら戻った」と記憶されます。

エラベルは、範囲と時間を書いた登録に、条件が合う案件のときだけご連絡する窓口ですが、案件の終わり方は、担当者ご自身の動き方で決まります。依頼側から「前の担当者が残した型で回っている」と聞く案件は、次の採用のときにも同じ担当者の名前が出ます。引き継ぎは、案件の後始末ではなく、次の案件の入口です。四つを残す型を持っていただくことをお勧めしています。

## まとめ

- 引き継ぎで残すのは**型・いまの状態・未完了の一覧・連絡と権限の整理**の四つ
- 型は**副業の途中から作っておく**。終わりが決まってから作ると間に合わない
- 手順は**終わりの日を書面で→型を確定→状態を依頼側の環境で→未完了の一覧→担当に一週間回してもらう→打ち合わせ→権限を返す→自分の側の確認→最後の請求と数→以後の連絡を一言**
- 未完了の一覧は**残った課題・判断待ち・途中の作業・手を付けなかったこと**。書かないと後で困る
- 依頼側に残すものと自分の側に残さないものを分ける。**自分の側に残す型は一般化したもの**
- **担当に回してもらって見届ける**ことが、渡すだけとの違い。終わり方が次の始まりを決める

## よくある質問

### 依頼側の都合で、急に終わることになりました。引き継ぎの時間がありません

最低限、型と未完了の一覧と権限の返却の三つを、最後の稼働で渡します。型は途中から作っていればそれを整えるだけ、無ければ手順の箇条書きと文面の雛形だけでも残す。いまの状態は、依頼側の環境の表がそのまま残っているので、最新にするだけ。権限の返却は、担当に止めてもらうことを書面で確認する。急な終わりでも、この三つがあれば、依頼側は回せます。急な終わりを避けるためには、契約の区切りと、終える場合の引き継ぎ期間を、最初の書面に入れておきます。

### 引き継ぎのあとも、依頼側から質問が来ます。どこまで応じればよいですか

終えるときに、以後の連絡の範囲と時間を一言決めておきます。「型で迷った点があれば、一か月間は書面で答えます。それ以降は、必要なら別途ご相談ください」。範囲を決めずに応じ続けると、無償の稼働が続きます。質問が型の範囲内なら、決めた期間は答える。型の範囲外（新しい課題、判断）なら、「それは新しいご依頼になります」と伝え、受けるなら条件を決め直します。引き継ぎのあとの連絡は、関係を保つためのものであって、稼働の延長ではありません。

### 自分の側に、型を残してよいですか

依頼側に渡した型そのもの（依頼側の文面、手順、数値）は、自分の側に残しません。残すのは、それを一般化したもので、社名・名前・数値・時期を消し、どの依頼側にも使える手順と考え方だけにしたものです。「スカウトの文面は四つに分けて冒頭だけ変える」は一般化した型で、残せます。「〇〇社向けの文面Aは、この書き出し」は依頼側の情報で、残しません。一般化した型は、次の案件と、発信や登録先のプロフィールで使えます。[noteで実績を見せる](/media/fukugyo-note/)を参照してください。

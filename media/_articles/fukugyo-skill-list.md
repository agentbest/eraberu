検索条件を組んで結果が出ると、次は「誰に送るか」です。ここで検索結果をそのまま表に貼って「候補者リスト」と呼ぶと、依頼側は上から順に見て、途中で読むのをやめ、担当者は「なぜこの人を選んだか」を聞かれて答えられません。候補者リストは、検索結果の写しではなく、「送る順番と、送る理由・送らない理由」が残る一枚です。結論を先に書くと、**候補者リストは、媒体のIDと要件との照合結果と優先度と理由と送信日と返信の有無だけを載せ、氏名や経歴の全文は載せず、優先度を三段階で付け、依頼側と共有する場所に置き、送った後に返信の結果で更新して、次回の検索条件に戻します。**検索条件の組み方は[検索条件を組む](/media/fukugyo-skill-kensaku/)に、個人情報の扱いは[スカウトで得た個人情報の扱い](/media/scout-kojin-jouhou-toriatsukai/)に書いています。ここでは、リストの型に絞ります。

## 検索結果をそのままリストにしてはいけない理由

| そのまま貼ると | 何が起きるか |
|---|---|
| 経歴の全文が並ぶ | 個人情報が媒体の外に出る。共有先が広がると管理できない |
| 送る順番が無い | 上から送ることになり、合う人が後ろに埋もれる |
| 送らない理由が無い | 次回、同じ人をまた見て、また悩む |
| 返信の記録が無い | どの条件・どの文面が効いたか分からない |
| 依頼側が全部読もうとする | 読み切れず、確認が止まる |

リストの役割は、「誰に送るか」を決めることと、「なぜそう決めたか」を残すことの二つです。両方が無いリストは、作る時間の割に、次につながりません。

## 載せる項目

| 項目 | 中身 | 載せない理由・注意 |
|---|---|---|
| 媒体のID（または媒体内のリンク） | 媒体に戻れる目印 | 氏名は載せない。IDで足りる |
| 要件との照合 | 必須の三〜五つそれぞれに○△× | 経歴の全文は載せない。照合の結果だけ |
| 優先度 | 上・中・下の三段階 | 下の基準 |
| 送る理由／送らない理由 | 一言。「〇〇の経験が必須と一致」「会社の型が違う」 | 主観の評価（「良さそう」）は書かない |
| 送信日 | 送った日 | 未送信は空欄 |
| 返信の有無と結果 | 返信あり／なし、面談に進んだか | 返信の本文は載せない |
| 使った条件の名前 | どの検索条件で出た人か | [検索条件を組む](/media/fukugyo-skill-kensaku/)の記録と対応 |

載せるのは、判断と記録に要る項目だけです。経歴の詳細は媒体の画面で見ます。リストは「媒体に戻るための索引」であって、経歴の写しではありません。

### エラベルの見解

担当する側から見ると、候補者リストで最も差がつくのは、「送らない理由」を残しているかどうかです。送る理由は誰でも書きますが、送らない理由を書いていないと、次回の検索で同じ人がまた出てきて、また同じ時間を使います。「会社の型が違う」「直近で転職したばかり」「必須の〇〇が無い」と一言残しておけば、次回は飛ばせますし、送らない理由に同じものが多ければ、それを検索の除外条件に足せます。エラベルで担当者を選ぶ企業には、「送らなかった人の理由を、リストに残していますか」を、私たちから先に聞いています。受ける側がその場で使える判断としては、リストの「理由」の欄を、送る人も送らない人も空欄にしないこと。一言で足ります。空欄が多いリストは、次回の材料になりません。

## 優先度を三段階で付ける

| 優先度 | 基準 | 扱い |
|---|---|---|
| 上 | 必須が全部○。ターゲット像の「いまどこで何をしているか」に近い | 個別に文面を書いて先に送る |
| 中 | 必須に△が一つか二つ。会社の型は近い | 型の文面に一段落足して送る |
| 下 | 必須に×がある。または会社の型が遠い | 送らない。理由を残す。要件が変わったら見直す |

優先度は、担当者の印象ではなく、要件との照合結果で決めます。「良さそう」「雰囲気が合いそう」は理由になりません。照合の基準は要件の一枚で、作り方は[採用要件を引き出すヒアリングの型](/media/fukugyo-skill-youken-hearing/)に書いています。見極めの型は[プロフィールの見極め方](/media/fukugyo-skill-screening/)に書いています。

上を先に送るのは、稼働時間が限られているからです。上に個別の文面を書く時間を確保し、中は型で回し、下には時間を使いません。

## 氏名や経歴の全文を載せない線

| 載せないもの | 理由 |
|---|---|
| 氏名 | 媒体のIDで足りる。リストの共有先が広がっても、個人が特定されにくい |
| 経歴の全文・自己PRの写し | 媒体の外に個人情報を出さない。媒体の規約にも関わる |
| 現職の会社名 | 会社の型（規模・業態）で足りる |
| 返信の本文 | 返信の有無と結果だけ。本文は媒体の中で見る |
| 担当者の主観の評価 | 「印象が良い」などは書かない。照合の結果だけ |

リストを媒体の外（表計算や共有ドキュメント）に置くこと自体が、媒体の規約と依頼側の決まりに関わります。何をどこまで媒体の外に出してよいかは、依頼側の決まりに従い、不明なら依頼側に確認します。個人情報の扱いに法令が関わる場合は、個別の判断は専門家にご確認ください。線の詳細は[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に書いています。

## 依頼側と共有する場所と形

| 決めること | 選び方 |
|---|---|
| 置く場所 | 依頼側が管理する共有の場所。担当者の個人の環境に置かない |
| 見せる範囲 | 依頼側の採用担当と面接官まで。それ以上に広げない |
| 確認してもらうこと | 優先度「上」の人を送ってよいか。「下」に落とした理由に異論が無いか |
| 更新の頻度 | 送信のたびに送信日、返信のたびに結果。まとめて更新しない |

依頼側に確認してもらうのは、リストの全部ではなく、「上」の人と、「下」に落とした理由です。上を送ってよいかの確認は、依頼側が候補者を知っている（過去に応募があった、知人である）ことがあるためです。下の理由の確認は、要件の解釈がずれていないかを見るためです。

### エラベルの見解

相談で最も多い思い込みは、受ける側の「リストは送る前に作るもの」というものです。実際には、リストの価値の半分は、送った後にあります。返信が来た人の優先度と会社の型を見ると、「中」から返信が多い、「上」からは来ない、ということが起きます。それは要件の必須が実態とずれているか、上の人に送った文面が合っていないかのどちらかで、リストが無いと気づけません。送った後に返信の結果を戻し、優先度の基準と検索条件を書き換える。この往復ができて、リストは仕事の道具になります。受ける側がその場で使える判断としては、送信から一定の期間が過ぎたら、リストの「返信」の欄を埋めて、優先度ごとの返信の割合を一行で依頼側に伝えること。数字は自分のリストの範囲の数で、市場の数字として断定しません。数字の扱いは[成果の数字の扱い](/media/fukugyo-suuji/)に書いています。

## 送った後に更新して次回に戻す

| 段階 | リストに書くこと | 次に戻す先 |
|---|---|---|
| 送信 | 送信日、使った文面の名前 | 文面の検証に |
| 返信あり | 返信あり、面談に進んだか | 優先度の基準の見直し |
| 返信なし | 返信なし | 文面と件名の見直し。[返信ゼロが続くときに疑う順番](/media/scout-henshin-nashi-genin/) |
| 送らなかった | 理由 | 除外条件に足す。要件の見直し |

返信の結果を戻す先が決まっていると、リストの更新が「作業」ではなく「次の判断の材料」になります。返信が来た後の対応の分担は[返信が来たあとの対応分担](/media/scout-daikou-henshin-taiou/)に書いています。

## リストが長くなったとき

| 状態 | 扱い |
|---|---|
| 「下」が大半 | 検索条件が広すぎる。除外条件を足して、検索の段階で減らす |
| 「上」が稼働で送り切れない | 上の中でさらに順番を付けず、送れる数だけ送り、残りは次回に。送信日の空欄で管理 |
| 過去の分が溜まる | 送信済みと未送信を分ける。送信済みは返信の結果が入ったら畳む |
| 依頼側が全部見たがる | 上だけを見せる形にする。全部は共有の場所にあり、いつでも見られると伝える |

リストは短いほど使われます。長くなったら、リストを整理するのではなく、検索条件に戻って減らします。

## よく起きる詰まりと直し方

| 詰まり | 直し方 |
|---|---|
| 経歴を写してしまい、リストが重い | 照合の○△×と一言の理由に置き換える。経歴は媒体で見る |
| 優先度が全部「中」になる | 必須の照合を厳密に。○が全部なら上、×があれば下。中は△だけ |
| 依頼側の確認が返ってこない | 確認を「上の人を送ってよいか」だけに絞る。期限を添える |
| 返信の欄が埋まらない | 送信のたびに送信日を書く癖を先に付ける。返信は媒体の通知で拾う |
| 担当者の手元にしかリストが無い | 依頼側の共有の場所に移す。案件の終了時に手元の分を消す。[引き継ぎ資料の残し方](/media/fukugyo-hikitsugi/) |

## まとめ

- 検索結果の写しではなく、**送る順番と、送る理由・送らない理由が残る一枚**
- 載せるのは**媒体のID・照合結果・優先度・理由・送信日・返信・使った条件**。氏名と経歴の全文は載せない
- 優先度は**上・中・下**。要件との照合で決め、印象で決めない。上に個別の文面、中は型、下は送らない
- **送らない理由**を空欄にしない。除外条件と要件の見直しの材料になる
- **依頼側が管理する共有の場所**に置き、確認は「上を送ってよいか」「下の理由」だけ
- 送った後に**返信の結果を戻し**、優先度の基準と検索条件を書き換える
- 個人情報を媒体の外に出す範囲は依頼側の決まりに従う。**個別の判断は専門家にご確認ください**

## よくある質問

### 依頼側から「候補者の経歴をまとめて見たい」と言われました

媒体の画面で見てもらう形にします。経歴をリストに写すと、個人情報が媒体の外に出て、共有先の管理ができなくなります。「リストには照合の結果と優先度だけを置き、経歴は媒体のIDから開いてください」と伝え、依頼側が媒体にログインできる形を確認します。依頼側が媒体を触れない場合は、優先度「上」の人だけ、要件との照合の結果を口頭か画面共有で説明します。写しは作りません。

### 一つのリストを複数の求人で使い回せますか

要件が違うなら、リストも分けます。同じ人が二つの求人に出てくることはありますが、照合の結果と優先度は求人ごとに違うので、同じ行に混ぜると判断がずれます。「媒体のID」を共通の目印にして、求人ごとのリストを持ち、同じ人には同時に二つの文面を送らない、という決まりを依頼側と作ります。同じ人に別の求人で重ねて送ると、受け取る側の印象を落とします。

### 案件が終わったとき、リストはどうしますか

依頼側の共有の場所にあるものは依頼側のものなので、そのまま残し、担当者の手元にある写しや下書きは消します。消したことを依頼側に伝えます。次の案件で「前のリストを参考にしたい」と思っても、別の依頼側のリストは使いません。使えるのは、自分の型（項目の作り方、優先度の基準の付け方）だけです。引き継ぎの形は[引き継ぎ資料の残し方](/media/fukugyo-hikitsugi/)に書いています。

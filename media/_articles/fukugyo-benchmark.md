依頼側の担当者から「他社はスカウトの返信率をどうやって上げているのか」「同じ業界の会社はどんな要件にしているのか」と聞かれる。自分は他の案件で見てきたことがあり、答えれば喜ばれそうだが、それは他の依頼側の情報だ。結論を先に書くと、**他社の事例として依頼側に出してよいのは、「公開されている情報」と「自分の判断の仕方」までです。自分が担当した他の依頼側の事例は、会社名を伏せても出しません。加えて、他社の事例を依頼側の判断の代わりにしないことも要ります。他社で効いた形が今の依頼側で効くとは限らず、他社の真似は依頼側の状況を見ない判断になります。**他社事例は、依頼側の判断の材料の一つで、答えではありません。自分の案件の事例を流用しない理由は[事例を流用しない](/media/fukugyo-jirei-ryuuyou/)に、守秘の線は[守秘の線を越える](/media/fukugyo-shippai-8/)に、外部の視点の使い方は[外部視点の価値](/media/fukugyo-shiten/)にまとめています。

## 依頼側が他社事例を求める理由

依頼側が「他社では」と聞くとき、頭の中にあるものは一つではありません。理由が分かると、答え方が決まります。

| 理由 | 依頼側の頭の中 | 求めているもの |
|---|---|---|
| 自社の位置を知りたい | 「うちの返信率は普通なのか、悪いのか」 | 比べる基準 |
| 社内を説得したい | 「他社もやっていると言えれば、上長が納得する」 | 社内で使える根拠 |
| 自分で考えたくない | 「他社がうまくいっている形をそのまま真似すれば早い」 | 答え |
| 外部の担当者を試している | 「この人はどれだけ知っているか」 | 担当者の経験の幅 |
| 不安を減らしたい | 「この進め方で本当によいのか、他社も同じなら安心」 | 安心 |
| 具体の参考がほしい | 「文面の例、要件の例を見たい」 | 具体の型 |

理由の要点は、「自分で考えたくない」と「社内を説得したい」の二つが、他社事例を答えの代わりにしてしまう入口だということです。「他社もやっている」を根拠に進めると、依頼側の状況を見ずに施策が決まり、効かなかったときに「他社では効いたのに」で終わります。他社事例を出すときは、材料として出し、判断は依頼側の状況で行う形を保ちます。提案の形は[改善提案の伝え方](/media/fukugyo-kaizen-teian/)に書いています。

## 出してよい事例と出せない事例の線

他社の事例を、出してよいものと出せないものに分けます。線は「どこで知ったか」です。

| 出してよい | 出せない |
|---|---|
| 公開されている情報。企業が自ら公開している採用の取り組み、媒体が公開している一般的な傾向、公的な統計 | 自分が担当した他の依頼側の事例。会社名を伏せても、業界・規模・状況の組み合わせで特定される |
| 自分の判断の仕方。「返信が来ないときは、文面より相手の絞り方を疑う」 | 他の依頼側で得た結果。「〇〇の訴求で返信が上がった」 |
| 一般化した教訓。複数の経験から取り出した、依頼側に依らない型 | 他の依頼側の社内の運用の工夫、体制、判断の経緯 |
| 業界の一般的な傾向として、広く知られていること | 本業の会社の採用の内情 |
| 依頼側自身の過去の事例（依頼側の記録にあるもの） | 副業の仲間から聞いた、その人の依頼側の事例 |

線の要点は、「会社名を伏せれば出してよい、ではない」ことです。「以前担当した〇〇業界の数十名の会社では」と言えば、その業界の人には会社が絞れ、依頼側は「うちのことも、次の案件で同じように話される」と感じます。自分が担当した他の依頼側の事例は、伏せても出さない。出すのは、公開情報と自分の判断の仕方だけです。公開情報を使うときも、数値や仕様は出典を確認し、確認できないものは出しません。

### エラベルの見解

相談で最も多い思い込みは、「他社の事例をたくさん知っているほうが、依頼側に価値がある」というものです。実際には、依頼側の担当者が求めているのは、他社の事例そのものより、「うちの状況で、何をすればよいか」です。他社の事例を並べられても、担当者は「で、うちはどうすれば」となります。他社の事例を出さずに、依頼側の記録を見て「御社の場合は、ここが止まっているので、こうしましょう」と言える担当者のほうが、依頼側からは価値があると見られています。

見ていて差がつくのは、「他社では」と聞かれたときに、他社の話で答えるか、依頼側の話で答えるかです。「他社ではこうしています」と答える人は、その場では喜ばれますが、次に「他社の情報を話す人」と見られます。「他社の具体はお伝えできませんが、御社の記録を見ると〇〇なので、こう考えます」と答える人は、その場では物足りなく見えても、依頼側から「うちを見て判断してくれる人」「うちの情報も外で話さない人」と信頼されます。エラベルでは、担当者が他の依頼側の事例を持ち込まない形を前提にしていて、依頼側にもそれを伝えています。事例の多さではなく、依頼側の状況を見る力が、担当者の価値です。

## 公開情報の使い方

公開されている情報は、他社事例として使えますが、使い方に注意があります。

| 注意 | 内容 |
|---|---|
| 出典を確認する | 企業の公式の発表、媒体の公式の情報、公的な統計のように、誰が出した情報かが分かるものだけ。「〜と聞いた」「〜らしい」は使わない |
| 数値は出典と一緒に | 返信率や採用の人数のような数値を出すなら、出典を示す。出典が確認できない数値は出さない |
| 前提を添える | 公開されている事例には、その企業の規模、業界、時期、体制という前提がある。「この事例は〇〇の前提なので、御社にそのまま当てはまるとは限りません」と添える |
| 依頼側の状況と比べる | 事例を出すだけでなく、「御社の記録と比べると、ここが違う」と、依頼側の状況に引き戻す |
| 古い情報を使わない | 媒体の仕様や採用の傾向は変わる。時期の分からない情報は使わない |
| 事例を答えにしない | 「他社はこうしているので、御社もこうすべき」ではなく、「他社にはこういう形がある。御社の状況ではどれが合うか」 |

使い方の要点は、「前提を添えて、依頼側の状況に引き戻す」ことです。公開されている事例は、その企業の前提の上で成り立っていて、前提が違えば結果も違います。「この事例の企業は数百名の規模で、専任の人事が複数いる。御社は数十名で専任がいないので、同じ形は取れないが、考え方は取り入れられる」のように、前提の違いを示してから、取り入れられる部分を出します。事実の扱いの線は[発信で書いてはいけないこと](/media/fukugyo-hasshin-nglines/)にも書いています。

## 他社事例を提案の根拠にするときの注意

提案の根拠として他社事例を使うと、通りやすくなることがありますが、注意があります。

| 注意 | 内容 |
|---|---|
| 根拠の中心は依頼側の事実にする | 「他社もやっている」は補助で、中心は「御社の記録でここが止まっている」。他社事例だけを根拠にすると、依頼側の状況を見ていない提案になる |
| 他社事例が効かなかったときの責任を考える | 「他社で効いたから」で通した提案が効かないと、「他社の話を持ってきただけ」になる。依頼側の状況で効く見込みを、自分の言葉で示す |
| 依頼側の社内で一人歩きさせない | 担当者が「外部の人が他社もやっていると言った」と社内で使うと、他社事例が判断の根拠になる。「他社の形は参考で、判断は御社の状況で」と添える |
| 自分の他の依頼側の事例は、提案の根拠にしない | 「前の案件でこれで返信が上がった」は、前の依頼側の結果。根拠にすれば守秘の線を越える |
| 事例が無くても提案できる形にする | 依頼側の記録と、自分の判断の仕方だけで提案できるなら、他社事例は要らない。無くても通る提案が、依頼側にとって最も価値がある |

注意の要点は、「根拠の中心は依頼側の事実」だということです。提案の根拠が他社事例だけだと、依頼側は「他社のことは分かったが、うちで効くのか」と感じます。依頼側の記録で「ここが止まっている」を示し、その打ち手として「他社にもこういう形がある」と補助で添える。この順番なら、他社事例は提案を補強し、判断の代わりにはなりません。提案の四段の型は[改善提案の伝え方](/media/fukugyo-kaizen-teian/)に、事実の出し方は[現状把握のしかた](/media/fukugyo-genjou-haaku/)に整理しています。

## 依頼側が他社の真似をしたがるとき

依頼側の担当者や経営者が、「〇〇社と同じやり方にしてほしい」と、特定の他社の真似を求めることがあります。

| 求め方 | 対応 |
|---|---|
| 「〇〇社の文面と同じにしてほしい」 | 「〇〇社の文面は、〇〇社の状況と候補者に向けたものです。構造は取り入れられますが、中身は御社の状況で作ります」と、構造と中身を分ける |
| 「〇〇社は年収を高く出しているから、うちも」 | 条件の話は依頼側の判断。「条件は御社でご判断ください。条件を変えずにできることとして、〇〇があります」と、自分の範囲に引き戻す。[年収提示に関わるとき](/media/fukugyo-nensyu-teiji/) |
| 「〇〇社は採用を全部外部に任せている」 | 「〇〇社の体制と御社の体制は違います。御社の範囲は、契約の通り〇〇で進めます」と、範囲の線を保つ |
| 「〇〇社の事例を調べて、同じ施策を全部やってほしい」 | 「公開されている範囲で調べます。ただし、御社の記録でどこが止まっているかを見て、効く見込みのある施策から選びましょう」と、選ぶ形にする |
| 「他社がやっているなら、うちもやらないと遅れる」 | 「他社がやっているかどうかより、御社の採用でどこが止まっているかが先です。止まっている場所に効く施策なら取り入れ、効かないなら他社がやっていても要りません」 |

対応の要点は、「他社の真似を、依頼側の状況の判断に引き戻す」ことです。真似そのものを否定すると、依頼側は「じゃあどうすれば」となります。真似を否定せず、「構造は取り入れられる」「御社の状況で効くかを見る」と、依頼側の状況に引き戻せば、依頼側は自分で判断できます。判断を依頼側に返す形は[提案が通らなかったとき](/media/fukugyo-hantai-sareta/)にも書いています。

## 自分の経験を他社事例にせずに活かす形

自分が他の案件で得た経験は、他社事例として出さなくても、今の依頼側に活かせます。

| 経験 | 他社事例として出す（避ける） | 判断の仕方として活かす（よい） |
|---|---|---|
| 前の案件で、文面の冒頭を変えたら返信が増えた | 「前の案件では、冒頭を会社の状況にしたら返信が上がりました」 | 「返信が少ないとき、私は冒頭を役割の説明から会社の状況の説明に変えることを試します。御社の文面でも試せます」 |
| 前の案件で、面接の枠を固定したら辞退が減った | 「前の依頼側では、枠を固定して辞退が減りました」 | 「日程の理由での辞退が多いとき、面接官の枠を週に固定する形があります。御社の辞退の理由を見て、当てはまるか確認しましょう」 |
| 前の案件で、要件を三つに絞ったら応募の質が上がった | 「〇〇業界の会社で、要件を絞って応募が変わりました」 | 「要件が五つ以上あるとき、私は三つに絞ることを提案します。御社の要件を見ると、〇つあるので、絞れるか一緒に見ましょう」 |
| 前の案件で、依頼側の社内の判断が遅くて止まった | 「前の依頼側は判断が遅くて困りました」 | 「面接の評価の期限を決めておくと、止まりにくくなります。御社でも期限の目安を決めませんか」 |

活かす要点は、「前の案件の話ではなく、自分の判断の仕方として言う」ことです。「前の案件では」で始めると、他社事例になります。「私は〇〇のとき、△△を試します」で始めると、自分の判断の仕方になり、依頼側の情報を含みません。同じ経験でも、言い方で、他社事例にも自分の型にもなります。判断の仕方の取り出し方は[発信のネタの見つけ方](/media/fukugyo-hasshin-neta/)に、型の育て方は[事例を流用しない](/media/fukugyo-jirei-ryuuyou/)に整理しています。

### エラベルの見解

担当する側から見ると、依頼側から「他社では」と聞かれる場面は、担当者の守秘の姿勢が試される場面でもあります。他の依頼側の事例を出した担当者は、その場では喜ばれても、依頼側から「うちのことも次で話される」と見られ、情報を渡されにくくなっています。出さなかった担当者は、その場では物足りなく見えても、「この人は外で話さない」と信頼され、依頼側の社内の情報まで渡されるようになっています。

順番として、「他社では」と聞かれたら、まず依頼側が求めている理由（基準か、根拠か、答えか、安心か）を見て、公開情報と自分の判断の仕方で答え、依頼側の記録と比べて依頼側の状況に引き戻し、他社の真似を求められたら構造と中身を分け、判断は依頼側に返す。自分の経験は「前の案件では」ではなく「私は〇〇のとき△△を試す」の形で出す。この順番で、他社事例は守秘を守りながら、依頼側の判断の材料になります。エラベルでは、担当者が他の依頼側の事例を持ち込まず、依頼側の状況を見て判断の材料を出す形を前提にしています。他社の事例を知っていることより、依頼側の状況を見る力が、担当者の価値です。

## まとめ

- 他社事例として出してよいのは**公開されている情報と自分の判断の仕方**まで。自分が担当した他の依頼側の事例は、会社名を伏せても出さない
- 依頼側が他社事例を求める理由は**基準・根拠・答え・試し・安心・具体**。「答え」と「根拠」が、他社事例を判断の代わりにする入口
- 公開情報は**出典を確認し、数値は出典と一緒に、前提を添えて、依頼側の状況に引き戻す**
- 提案の根拠の中心は**依頼側の事実**。他社事例は補助で、無くても通る提案が最も価値がある
- 他社の真似を求められたら**構造と中身を分け、依頼側の状況の判断に引き戻す**
- 自分の経験は**「前の案件では」ではなく「私は〇〇のとき△△を試す」**の形で、判断の仕方として活かす

## よくある質問

### 依頼側の担当者が、他社の人事と知り合いで、他社の内情を話してきます

依頼側の担当者が持っている他社の情報は、依頼側のもので、自分がそれを聞くことは問題ありません。ただし、聞いた他社の情報を、自分の記録に書いたり、別の依頼側で使ったりはしません。「参考として伺いました」と受け止め、依頼側の状況の判断に使えるなら使い、それ以上は広げない形にします。聞いた情報が他社の守秘に関わりそうなら、深く聞かず、話題を依頼側の状況に戻します。

### 公開されている他社の採用の取り組みを、依頼側に紹介してよいですか

公開されている情報なら紹介できます。企業が自ら発表している取り組み、媒体が公開している傾向、公的な統計のように、出典が明確なものに限り、出典と前提を添えて出します。「〇〇社が公開している取り組みでは、こういう形です。〇〇社は〇〇の規模で〇〇の体制なので、御社にそのまま当てはまるとは限りませんが、考え方は取り入れられます」の形です。数値を出すなら出典を確認し、確認できない数値は出しません。

### 「他社事例を知らないなら、経験が浅いのでは」と言われました

「他の依頼側の事例は、守秘の観点でお伝えしない形にしています。御社の情報も同じように扱います」と、知らないのではなく出さない姿勢であることを伝えます。そのうえで、「御社の記録を見て、ここが止まっているので、こう考えます」と、依頼側の状況での判断を示せば、経験は判断の中身で伝わります。他社事例を出さないことを頼りなさと見る依頼側には、判断の仕方で答えます。それでも他社事例を求め続けるなら、その依頼側は「他社の情報を持ってくる人」を求めていて、自分の姿勢と合っていない可能性があります。合わない案件の見分け方は[合わない案件の見分け方](/media/fukugyo-awanai-anken/)に書いています。

「評価制度を直したい」「給与テーブルを作りたい」と、部分の依頼から人事制度の話が始まります。ただ、評価だけを直すと「評価は変わったが給与に反映されない」となり、給与だけを作ると「何を基準に上がるのか分からない」となります。人事制度は、等級・評価・報酬の三つが一本につながっていて、どこか一つを触ると他の二つに影響します。結論を先に書くと、**人事制度の設計は、等級・評価・報酬を一本のつながりとして扱い、現状の一枚（処遇の実態・社員の困りごと・経営の意図）から始め、制度の型を外から持ち込まずに選択肢を並べて依頼側が選び、法令と処遇の接続は専門家に置き、導入は説明と移行の設計までを担当者が担います。**案件として受ける形は[人事制度の設計の副業の実務](/media/fukugyo-jinji-seido-shigoto/)に、評価と給与の個別の型は[評価制度を設計する](/media/fukugyo-skill-hyouka/)と[給与テーブルの設計の副業案件](/media/fukugyo-kyuyo-seido-fukugyo/)に書いています。ここでは、三つをつなぐ設計の型に絞ります。

## 部分で直すとずれる

| 部分の依頼 | 何が起きるか |
|---|---|
| 評価だけ直す | 評価の結果が処遇に反映されず、「評価しても意味がない」になる |
| 給与テーブルだけ作る | 何を基準に上がるかが無く、テーブルが形だけになる |
| 等級だけ作る | 等級の違いが評価と報酬に現れず、名前だけになる |
| 目標管理だけ入れる | 目標の達成が等級と報酬につながらず、目標が形だけになる |
| 他社の制度を持ち込む | 依頼側の役割の段階と合わず、運用で崩れる |

三つは、一本のつながりです。触るときは、三つ全部を見て、直す順番と範囲を決めます。

## 三つのつながり

| 要素 | 決めること | 他の二つとの関係 |
|---|---|---|
| 等級 | 役割の段階。「この段階の人には、これを期待する」 | 評価の観点の元。報酬の幅の元 |
| 評価 | その段階での期待に対して、どうだったか | 等級の期待を測る。報酬の変動の元 |
| 報酬 | 段階（等級）と評価に対応した処遇 | 等級で幅が決まり、評価で幅の中の位置が決まる |

等級が無い会社では、評価の観点が「良い人」になり、報酬は個別の交渉になります。等級を先に置くと、評価と報酬の骨ができます。ただし、等級を精緻に作りすぎると運用できません。依頼側の規模で、段階の数を最小にします。

### エラベルの見解

担当する側から見ると、人事制度の設計で最も差がつくのは、「現状の一枚を作ってから、選択肢を並べる」順番を守れるかです。受ける側は、依頼側の「評価制度を直したい」を聞いて、すぐに評価の観点を作り始めます。ただ、なぜ直したいのか（社員が納得していない、昇給の基準が無い、経営者が特定の人を上げたい）で、直す場所は変わります。「いま、誰がどう処遇されていて、社員は何に困っていて、経営は何を意図しているか」を一枚にしてから、「等級から作る」「評価の観点だけ直す」「報酬の幅を先に決める」の選択肢を並べる。順番を守ると、依頼側が自分で選べます。エラベルで担当者を選ぶ企業には、「制度を直す前に、いまの処遇の実態を一枚にしていますか」を、私たちから先に聞いています。受ける側がその場で使える判断としては、設計の最初の成果物を「現状の一枚」にし、制度の案を出す前に依頼側と一枚を確認すること。

## 現状の一枚

| 欄 | 中身 | 出どころ |
|---|---|---|
| 処遇の実態 | 役割ごとに、いまどう決まっているか（等級があるか、評価が処遇に反映されているか、昇給の基準） | 依頼側の人事の記録 |
| 社員の困りごと | 「何で評価されているか分からない」「上がる基準が無い」など。個人を特定せず、傾向で | 依頼側が聞いた声、サーベイの結果（あれば） |
| 評価者の困りごと | 「何を見ればよいか分からない」「差を付けられない」 | 評価者への聞き取り |
| 経営の意図 | 何を報いたいか、何を変えたいか | 経営者 |
| 制約 | 原資の考え方、法令上の整理、既存の規程 | 依頼側と専門家 |

一枚には、個人の給与の額や評価の結果を書きません。傾向と構造だけです。聞き取りの中で個人の事情を聞いても、記録に残しません。聞き方は[採用要件を引き出すヒアリングの型](/media/fukugyo-skill-youken-hearing/)の「三者に別々に聞く」と同じです。

## 選択肢を並べて依頼側が選ぶ

| 選択肢 | 向く状況 | 影響の範囲 |
|---|---|---|
| 等級から作る | 等級が無く、役割の段階が曖昧 | 三つ全部。時間がかかる |
| 評価の観点だけ直す | 等級はあるが、評価が印象で決まっている | 評価と、報酬への反映の一部 |
| 報酬の幅を先に決める | 昇給の基準が無く、個別の交渉になっている | 報酬と、等級との対応 |
| 運用だけ直す | 制度はあるが、評価の面談や説明が行われていない | 制度は変えず、運用の型を置く |

選択肢ごとに、「直るもの」「直らないもの」「影響する範囲」「かかる期間の考え方」を並べ、依頼側が選びます。担当者が「等級から作るべきです」と決めません。制度の型を外（他社、一般的な型）から持ち込むことも避け、依頼側の役割の段階から起こします。

## 決めるのは依頼側、法令と処遇の接続は専門家

| 担当者がやること | 依頼側が決めること | 専門家が確認すること |
|---|---|---|
| 現状の一枚、選択肢、設計の材料 | どの選択肢か。等級の段階の数。評価の観点。報酬の幅 | 規程の変更、労働条件の変更に関わる手続き、法令上の整理 |
| 設計の案（等級の定義、評価の観点、報酬の対応の構造） | 案の採否 | 処遇の変更が個別の労働条件に及ぶ場合の扱い |
| 導入の説明の資料と移行の設計 | 説明の実施、移行の判断 | 移行の手続き |

人事制度の変更は、労働条件に関わり、法令上の整理があると一般に整理されています。就業規則や賃金規程の変更、不利益になる変更の扱いは、専門家（社労士等）の確認に従います。担当者は制度の構造を設計し、規程の文言や手続きには踏み込みません。個別の判断は専門家にご確認ください。線の詳細は[副業で法令違反をしないために](/media/fukugyo-ihan-shinai/)に書いています。

### エラベルの見解

相談で最も多い思い込みは、受ける側の「制度は精緻なほど公平になる」というものです。実際には、等級を十段階にし、評価の観点を十個にし、報酬の表を細かくすると、評価者が運用できず、社員は理解できず、結局は印象で決まります。等級は依頼側の役割の段階の数だけ（三〜五段が多い）、評価の観点は三〜五つ、報酬は等級ごとの幅と評価による位置の考え方だけ。運用できる粗さが、公平さを保ちます。受ける側がその場で使える判断としては、設計の案を出す前に、「この制度を、評価者が一枚の説明で運用できるか」を問うこと。一枚で説明できなければ、削ります。

## 導入は説明と移行の設計まで

| 決めること | 中身 |
|---|---|
| 説明 | 社員への説明の資料と順番（経営者から意図、人事から仕組み、評価者から運用）。担当者は資料と順番を作り、説明は依頼側が行う |
| 移行 | いまの処遇から新しい制度へ、誰がどの等級に入るか、報酬はどう移るか。移行の判断は依頼側、手続きは専門家 |
| 最初の評価の期間 | 試行として回し、分布と困りごとを見る。記録の形を置く |
| 見直し | 一年後に、分布・面談の実施・社員の声を材料に。直すかは依頼側 |

移行で「下がる人」が出る場合の扱いは、法令上の整理があると一般に整理されているので、専門家の確認に従います。担当者は「下がる人がいる構造」を依頼側に示すまでです。

## 聞いた事情の扱い

制度の設計で、担当者は社員の給与の額、評価の結果、個人の事情を耳にします。記録には、傾向と構造だけを残し、個人を特定できる情報は書きません。案件の終了時に、手元の聞き取りの記録は依頼側の決まりに従って消します。扱いは[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に書いています。

## よく起きる詰まりと直し方

| 詰まり | 直し方 |
|---|---|
| 依頼側が「評価だけ直したい」 | 三つのつながりを示し、評価だけ直したときに直らないものを添える。選ぶのは依頼側 |
| 他社の制度を持ち込みたがる | 依頼側の役割の段階から起こす。他社の型は参考の構造だけ |
| 制度が精緻になりすぎる | 「評価者が一枚で運用できるか」で削る |
| 経営者が特定の人を上げるための制度にしたい | 現状の一枚の「経営の意図」に書き、制度で個人を扱わない構造を示す。判断は依頼側 |
| 移行で下がる人が出る | 構造を示し、扱いは専門家に |
| 個人の給与の情報が手元に残る | 傾向と構造だけを記録。終了時に消す |

## まとめ

- 部分で直すとずれる。**等級・評価・報酬は一本のつながり**
- 設計は**現状の一枚から**。処遇の実態・社員と評価者の困りごと・経営の意図・制約
- **選択肢を並べて依頼側が選ぶ**。制度の型を外から持ち込まない
- 精緻にしない。**評価者が一枚で運用できる粗さ**
- **決めるのは依頼側、法令と処遇の接続は専門家**。規程と手続きに踏み込まない。個別の判断は専門家にご確認ください
- 導入は**説明の資料と順番、移行の設計、最初の期間の記録の形**まで
- 個人の給与と評価の情報は記録に残さない

## よくある質問

### 依頼側の規模が小さく、制度は要らないのではないかと思います

「制度」を作らない選択肢も並べます。数人の会社なら、等級を作らず、「役割ごとの期待」と「年に一度の面談の型」だけを置く形で足りることがあります。制度が要るかどうかは、社員の困りごと（「何で評価されているか分からない」があるか）と、経営の意図で決まり、規模だけでは決まりません。作らない案を含めて、依頼側が判断できる形にします。

### 経営者が「制度を作って、自分が判断しなくて済むようにしたい」と言います

制度は判断を無くすものではなく、判断の基準と記録を残すものです。等級の期待と評価の観点があっても、最終の判断は評価者と経営者が行います。「制度があれば自動で決まる」と期待して作ると、運用で「制度どおりだと納得できない」となり、崩れます。「判断が説明できるようになる」が制度の効果で、「判断が要らなくなる」ではない、と最初に伝えます。

### 制度の設計を、社労士と一緒に進めてよいですか

法令と処遇の接続、規程の変更、手続きは社労士の領域で、一緒に進める形が自然です。担当者は制度の構造（等級の段階、評価の観点、報酬の対応の考え方）を設計し、社労士は法令上の整理と規程の文言と手続きを担う、と役割を分けます。分担は最初に依頼側と決め、契約の範囲に書きます。範囲の決め方は[業務範囲を書面で固める](/media/fukugyo-scope/)に書いています。

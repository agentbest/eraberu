「採用の業務をマニュアルにしてほしい」と頼まれて、応募から入社までの全工程を数十ページに書くと、完成した日に読まれ、翌月には誰も開かず、半年後には実態と合わなくなります。分厚いマニュアルは、作った人の努力の証拠にはなっても、担当者が替わった翌日に業務を回す道具にはなりません。結論を先に書くと、**マニュアルは、型（一枚の様式）・基準（判断の一行）・手順（順番と担当）・例（実際の記録の匿名化）・更新の決まり（誰がいつ直すか）の五つに分け、いま回っている業務の記録から起こし、一業務一枚で毎日使う画面に置き、会社が決めることを明記し、個人情報と機密を載せず、権利の扱いを契約で先に決め、三か月で使われている部分だけを残す形で作ります。**会社側から見た残し方は[採用マニュアルを残す](/media/rpo-manual-seibi/)に、スカウトの運用に絞った型は[スカウト運用マニュアルの作り方](/media/scout-manual/)に、権利の考え方は[代行が作ったマニュアルの権利は誰のものか](/media/rpo-manual-kizoku/)に書いています。ここでは、作る型に絞ります。

## 分厚いマニュアルが読まれない理由

| 分厚い形 | 何が起きるか |
|---|---|
| 全工程を文章で | 探せない。読む時間が無い |
| 「〜すること」の羅列 | どの様式を使うか、どう判断するかが無い |
| 例が無い | 抽象で終わり、初めての人が動けない |
| 更新の決まりが無い | 実態が変わっても直されず、嘘になる |
| 判断の所在が無い | 「マニュアルどおりにやったのに」と、会社の判断が抜ける |
| 個人情報の例が載っている | 共有できない |

読まれるマニュアルは、「困ったときに、一枚を開けば、次にやることが分かる」ものです。分けて、薄くします。

## 五つの部

| 部 | 中身 | 形 |
|---|---|---|
| 型 | その業務で使う様式。候補者リスト、評価シート、依頼書、報告の一枚 | 空の一枚。そのまま使える |
| 基準 | 判断の一行。「必須の○△×の付け方」「段階を進める条件」「見送りの理由の分類」 | 一行ずつ。長くしない |
| 手順 | 順番と担当。「誰が、いつ、何を、次に誰へ」 | 表。一業務一枚 |
| 例 | 実際に使った記録を、個人が特定できない形にしたもの | 型に記入した見本 |
| 更新の決まり | 誰が、いつ（月次、担当が替わったとき、実態が変わったとき）、どこを直すか | 一行。末尾に版と日付 |

五つは別々の一枚（または別々のページ）にし、手順の一枚から型と基準と例にたどれる形にします。これまでの記事で作ってきた一枚（[候補者リストの作り方](/media/fukugyo-skill-list/)、[評価シートを作る](/media/fukugyo-skill-hyouka-sheet/)、[ATSの運用ルールを作る](/media/fukugyo-skill-ats-unyou/)）は、そのまま「型」と「基準」と「手順」の部になります。

### エラベルの見解

担当する側から見ると、マニュアルで最も差がつくのは、「いま回っている業務の記録から起こす」ができるかです。受ける側は、「あるべき業務の流れ」を頭で組み立てて書きます。あるべき流れは、実態と合わず、現場は「うちはこうじゃない」で閉じます。いま実際に回っている業務の記録（候補者リスト、評価シート、依頼書、週次の報告）を並べ、「この記録を、誰が、いつ、どう更新しているか」を手順に写す。それが実態のマニュアルで、現場は自分の業務として読めます。エラベルで担当者を選ぶ企業には、「マニュアルは、いまの記録から起こしましたか、あるべき流れから書きましたか」を、私たちから先に聞いています。受ける側がその場で使える判断としては、マニュアルを書く前に、いま使われている記録の一覧を作り、記録が無い業務は「マニュアルの前に記録の形を作る」と分けること。

## 書く順番

| 順 | 中身 |
|---|---|
| 一 | いま使われている記録（型）の一覧を作る。無い業務は記録の形から |
| 二 | 記録ごとに、「誰が、いつ、どう更新しているか」を現場に聞き、手順の一枚に |
| 三 | 手順の中の「判断」を拾い、基準の一行にする。判断が現場の頭の中にあるなら、言葉にしてもらう |
| 四 | 実際の記録から、個人が特定できない形の例を一つ |
| 五 | 更新の決まりを一行。版と日付 |
| 六 | 担当者以外の人（依頼側の人事）に、手順の一枚だけを見て業務を一度やってもらう。詰まった箇所を直す |

六が、マニュアルが回るかどうかの確かめです。担当者が「分かりやすく書けた」と思っても、他の人が動けなければ、マニュアルではありません。

## 一業務一枚で、毎日使う画面に置く

| 置き方 | 理由 |
|---|---|
| 一業務一枚 | 探せる。「日程調整」「見送りの連絡」「週次の確認」で一枚ずつ |
| 毎日使う画面に | ATSの固定のメモ、共有の場所の先頭。別の場所にあると開かれない |
| 手順の一枚から型と基準にリンク | 手順を読んで、そのまま型を開ける |
| 全体の目次は一枚 | 業務の一覧と、各一枚への入口 |

置き場所は依頼側の環境で、担当者の手元ではありません。置き場所は[ATSの運用ルールを作る](/media/fukugyo-skill-ats-unyou/)の「担当者が替わっても回る形」と同じです。

## 判断の所在を明記する

| 書くこと | 例 |
|---|---|
| 会社が決めること | 「合否は決める人が決める」「条件は人事が提示する」「見送りの連絡の文面の変更は人事の承認」 |
| 担当者が決めてよいこと | 「候補者リストの優先度」「文面の一段落目」「日程の候補の提示」 |
| 専門家に確認すること | 「表現の可否」「在留の確認」「労働条件に関わる変更」 |

判断の所在が無いマニュアルは、「マニュアルどおりにやった」で会社の判断が抜けます。手順の一枚の各行に「決める人」の列を置きます。法令に関わる判断は、マニュアルの中で「専門家に確認」と書き、内容を断定しません。個別の判断は専門家にご確認ください。

### エラベルの見解

相談で最も多い思い込みは、受ける側の「マニュアルは完成させるもの」というものです。実際には、完成したマニュアルは、完成した日から実態とずれ始めます。「三か月後に、使われている部分と使われていない部分を分け、使われていない部分は消す」を、作るときに決めておく。使われていない部分は、実態と合わないか、要らないかのどちらかで、残しておくとマニュアル全体の信用が落ちます。受ける側がその場で使える判断としては、更新の決まりに「三か月後の見直しの日」と「見直しで消してよい」を書くこと。消せるマニュアルは、生き続けます。

## 個人情報と機密を載せない

| 載せない | 代わりに |
|---|---|
| 候補者の氏名、経歴、連絡先 | 例は番号と、経歴の記述を一般化した形 |
| 社員の評価の結果 | 例は架空か、個人が特定できない形 |
| 依頼側の顧客名、数字、開発中のもの | 「〇〇社」「〇件」の形 |
| 紹介会社との契約の条件 | 「契約に従う」と書き、条件は載せない |
| アカウントとパスワード | 載せない。アカウントの管理の一枚は別に、依頼側の管理者が |

例は、実際の記録から起こすと具体になりますが、個人が特定できない形に直します。直せない例は載せません。扱いは[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に書いています。

## 権利の扱いは契約で先に

| 決めること | 中身 |
|---|---|
| マニュアルは誰のものか | 依頼側の業務のために作ったものは、依頼側のもの。契約に書く |
| 担当者が持ち出せるもの | 「型の考え方」（五つの部の構造）だけ。中身は持ち出さない |
| 他の依頼側で使えるもの | 構造だけ。依頼側の記録から起こした中身は使わない |
| 担当者が作った様式の扱い | 契約で決める。決めていなければ揉める |

権利の考え方は[代行が作ったマニュアルの権利は誰のものか](/media/rpo-manual-kizoku/)に書いています。契約の条項の文言は、依頼側の決まりと専門家の確認に従います。範囲の決め方は[業務範囲を書面で固める](/media/fukugyo-scope/)に書いています。

## よく起きる詰まりと直し方

| 詰まり | 直し方 |
|---|---|
| 依頼側が「全部を網羅して」と言う | 五つの部に分け、一業務一枚。網羅より「翌日に回る」を目的に |
| あるべき流れで書いてしまった | いまの記録から起こし直す |
| 基準が書けない | 現場の頭の中の判断を、「この場合はこうしている」と聞き出して一行に |
| 例が無い | 実際の記録を匿名化して一つ。無ければ架空と明記 |
| 更新されない | 更新の決まりに、日と人と「消してよい」を |
| 個人情報が載っている | 匿名化するか消す |

## まとめ

- 分厚いマニュアルは読まれず更新されない。**型・基準・手順・例・更新の決まり**の五つに分けて薄く
- **いま回っている業務の記録から起こす**。あるべき流れで書かない
- **一業務一枚、毎日使う画面に**。手順から型と基準にたどれる形
- **判断の所在**（会社が決めること・担当者が決めてよいこと・専門家に確認すること）を各行に。個別の判断は専門家にご確認ください
- **他の人が手順の一枚だけで一度回せるか**で確かめる
- **個人情報と機密を載せない**。例は匿名化
- **権利の扱いは契約で先に**。持ち出せるのは構造だけ
- **三か月で使われていない部分を消す**。完成させない

## よくある質問

### マニュアルの作成を、副業の成果物として単価に含めてよいですか

五つの部の構造の設計と、記録から起こす作業は成果物です。ただし、作ったマニュアルは依頼側のもので、担当者が持ち出したり、他の依頼側で使い回したりしません。持ち出せるのは「五つの部に分ける」という構造の考え方だけです。成果物の範囲と権利の扱いを、契約に書きます。見積もりの型は[見積もりの出し方](/media/fukugyo-mitsumori/)に書いています。

### 現場が「マニュアルどおりにやると遅くなる」と言います

手順の一枚が、実態より細かい可能性があります。現場に「実際は、どこを飛ばしていますか」と聞き、飛ばしている部分が「要らない」なら消し、「要るのに飛ばしている」なら基準の一行に理由を足します。マニュアルは現場の実態に合わせて薄くするもので、現場をマニュアルに合わせるものではありません。三か月の見直しで、使われていない部分を消します。

### 動画や画面の録画でマニュアルを作りたいと言われました

操作の説明は動画が向きますが、五つの部（型・基準・手順・例・更新の決まり）は文字の一枚が向きます。動画は探せず、更新しにくく、実態が変わると全部撮り直しになります。「手順の一枚は文字で、操作の部分だけ短い動画を添える」形を提案します。動画に候補者の情報や画面上の個人情報が映らないように、撮る画面を先に確かめます。

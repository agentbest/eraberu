スカウト代行の副業を初めて受けるとき、いちばん不安なのは「実際に何が、どの順番で起きるのか」が見えないことです。募集文には「スカウト業務」とだけ書いてあり、契約してから、聞き取りの会議、アカウントの共有、文面の承認、返信の対応、週次の報告と、次々にやることが出てきます。順番を知っていれば、先回りして決めておけます。結論を先に書くと、**1案件は「契約前→第1週→第2週以降→月次→終了と更新」の五つの段階で進み、契約前に範囲・稼働・アカウント・名義・報告の形を決め、第1週は送らずに聞き取りと検索条件と文面の承認に使い、第2週から送信と返信対応と週次の報告を回し、月次で返信が来た人の共通点から条件と文面を直し、終了時に引き継ぎと次の提案をします。**案件の型と求められる経験は[スカウト代行の副業案件](/media/fukugyo-scout-daikou-fukugyo/)に書いていますので、ここでは「1案件の流れ」に絞ります。

## 契約前：決めておくこと

契約前に決めていないことは、あとで揉めます。とくにスカウト代行は、媒体のアカウントと候補者の情報に触れるので、口約束で始めません。

| 決めること | 確かめる中身 | 決めていないと起きること |
|---|---|---|
| 範囲 | 文面だけか、検索と送信か、運用一式か、立ち上げ支援か。返信対応と日程調整は含むか | 「返信対応もお願い」が後から足される |
| 稼働 | 週の時間の上限、平日の日中に返信を確認できる時間帯 | 候補者の返信が放置され、会社から連絡が来る |
| アカウント | 会社が契約した媒体のアカウントを、どの権限で、どう共有するか。終了時の返却 | 自分の名義で送る形になり、責任の所在があいまいになる |
| 名義 | 誰の名前で送るか。名義の人が返信を読める状態か | 名義の人が返信を知らず、候補者に二重の連絡が行く |
| 最終決定者 | ターゲットと文面を最終的に決めるのは誰か（会社側の誰か） | 職業安定法上の論点に触れる形になる。専門家にご確認ください |
| 報告 | 週次か、形式（表か文か）、誰が読むか | 報告が独り言になり、直す判断が会社で行われない |
| 評価 | 何の数字で評価されるか。その数字を自分で動かせる範囲が任されているか | 動かせない数字で評価される |

止まりやすいのは、「まず始めてみましょう」で契約前の確認を飛ばすときです。範囲と稼働だけは、書面（メールで構いません）に残します。範囲の決め方は[業務範囲の決め方](/media/fukugyo-scope/)に書いています。

## 第1週：送らない週

第1週は、送信しません。聞き取りと、検索条件と文面の準備に使います。ここを急いで送り始めると、返信が来ない理由が分からなくなります。

| やること | 依頼側に持ってもらうこと | 落とし穴 |
|---|---|---|
| 聞き取り（要件、対象の職種、これまでの送信と返信の状況、会社の条件と実態） | 現場の責任者か経営者が出る時間。過去の送信と返信の記録 | 人事だけから聞いて、現場の「良い人」が言葉にならない |
| 返信が来た人の共通点を出す（過去の記録があれば） | 記録の共有 | 記録が無い。無いなら「最初の一か月は数字を見える形にする」と伝える |
| 検索条件の設計（必須と歓迎を分け、経験の言葉で組む） | 条件の案の承認 | 肩書と年数で組んで、対象が少ないか合わない |
| 文面の初稿（件名、本文、転向元ごとの一行目） | 文面の承認。名義の人の確認 | 承認の前に送る。会社の条件と違うことを書く |
| 送る順の付け方を決める | 送る順の基準の合意 | 出てきた順に送る |

止まりやすいのは、聞き取りで「良い人」「即戦力」のまま終わるときです。「その職種で、いま社内で一番うまくやっている人は何が違いますか」と聞くと、言葉になります。聞き方は[質問の仕方](/media/fukugyo-shitsumon-shikata/)に書いています。

### エラベルの見解

担当する側から見ると、この仕事は「第1週に送らない」ことを会社に納得してもらえるかで、その後の難易度が決まります。会社は媒体の契約が始まっていて、一日も早く送りたい。そこで担当者が押されて初日から送り始めると、返信が来ない理由が「文面か、相手か、条件か」のどれか分からず、直す手段を持たないまま一か月が過ぎます。エラベルで担当者を選ぶ企業には、「最初の一週間は聞き取りと設計に使い、その分、二週目からの返信率で判断してください」と、私たちから先に伝えています。受ける側がその場で使える判断としては、契約前に「第1週は送信しない。聞き取りと条件と文面の承認に使う」と、稼働の計画に書いて渡すこと。書いてあれば、会社も「送ってないのか」とは言いません。

## 第2週以降：送信・返信対応・週次の報告

第2週から送信を始めます。ここからは、送る、返信を見る、対応する、記録する、の繰り返しです。

| やること | 頻度の目安 | 落とし穴 |
|---|---|---|
| 送信（送る順に沿って、一行目を相手ごとに変える） | 稼働の枠の中で。一度に大量に送らない | 一行目を変えずに同じ文面を送る。開封が落ちる |
| 返信の確認と一次対応 | 平日の日中、朝と昼など決めた時間帯に | 週末にまとめて返す。候補者は待たない |
| 日程調整（面談の候補日を出し、会社と候補者の間をつなぐ） | 返信が来た当日か翌日 | 会社側の面談の枠を先に確保していない |
| 記録（送信数、開封、返信、面談、辞退の理由） | 送るたび | 媒体の画面だけで済ませ、あとで集計できない |
| 週次の報告（数字と、次に直すこと一つ） | 週に一度、決めた曜日 | 数字だけ並べて、次に何を直すかが無い |

止まりやすいのは、返信対応を「時間があるときに」にするときです。候補者は複数の会社と話しているので、返信が遅い会社から順に候補から外します。対応できる時間帯を決め、その時間帯に見ることを会社と候補者の両方に合わせます。返信の速さの考え方は[連絡の速さ](/media/fukugyo-renraku-sokudo/)に、報告の型は[報告の仕方](/media/fukugyo-houkoku/)に書いています。

## 月次：返信が来た人の共通点から直す

月に一度、会社と見直しの時間を持ちます。見るのは、返信率の高低ではなく、「返信が来た人の共通点」と「来なかった人の共通点」です。

| 見ること | 直すところ |
|---|---|
| 返信が来た人の転向元、経験、いまの会社の規模 | 検索条件と送る順。共通点に寄せる |
| 開封されたが返信が来なかった人 | 本文（とくに条件と実態の段）。件名は通っている |
| 開封されなかった人 | 件名と一行目 |
| 面談に来たが辞退した人の理由 | 文面と実態のずれ。会社に返す |
| 会社の条件そのものへの反応（年収、働き方） | 条件の提案。決めるのは会社 |

止まりやすいのは、月次で「返信率が低いので文面を変えます」で終わるときです。返信率は、会社の条件と実態、送る相手、文面の順に決まります。文面より先に、送る相手と条件を見ます。一度に全部を変えず、一つずつ変えて比べます。

### エラベルの見解

同じ料金・同じ業務範囲でも、結果が分かれるのは、月次の見直しで「会社の条件に踏み込むか」です。返信が来ない案件で、文面と検索条件だけを直し続ける担当者は、三か月目に「成果が出ない」と契約を終えられます。返信が来た人と来なかった人の共通点を並べて、「この年収の幅では、この層には届いていません。幅を上げるか、届く層に変えるか」と会社に判断を返す担当者は、条件が変わらなくても、層を変えて結果を出します。会社が決めることに踏み込むのは越権ではなく、外の担当者にしかできない仕事です。社内の人事は、経営者に「条件が低い」とは言いにくい。エラベルで長く続いている担当者は、月次の報告に「会社に決めてもらうこと」の欄を作っています。受ける側がその場で使える形としては、週次の報告の最後に「次に直すこと」と「会社に決めてもらうこと」を分けて一行ずつ書くことです。

## 終了と更新：引き継ぎと次の提案

契約の期間が来たら、更新か終了かを会社が決めます。どちらでも、引き継げる形にして終えます。

- **残すもの。** 検索条件（名前を付けて保存したもの）、文面の型（件名と本文と転向元ごとの一行目）、送る順の基準、返信が来た人の共通点、月次の見直しの記録
- **返すもの。** 媒体のアカウントの権限、共有された資料、候補者に関する情報（自分の端末に残さない）
- **次の提案。** 更新するなら、次の期間で直すこと。終了するなら、社内で回すための手順書と、最初の一か月で見るべき数字

止まりやすいのは、終了が決まってから引き継ぎの資料を作り始めるときです。週次の報告と月次の記録をそのまま引き継ぎの資料になる形で残しておけば、終了時の負担は小さくなります。引き継ぎの型は[引き継ぎの仕方](/media/fukugyo-hikitsugi/)に書いています。

## 候補者の情報の扱い

スカウト代行は、候補者の経歴という個人情報に触れる仕事です。媒体の中で完結させ、候補者のプロフィールを自分の端末や個人のクラウドに保存しません。返信のやりとりも媒体の中で行い、メールや電話に移すときは会社の連絡先を使います。記録に残すのは、集計に要る項目（送信日、開封、返信、面談、辞退の理由の分類）にとどめ、氏名や連絡先は会社の管理する場所に置きます。扱いの詳細は[候補者の個人情報の扱い](/media/fukugyo-kojin-jouhou/)に書いています。個別の判断は専門家にご確認ください。

## 稼働時間は何で決まるか

週に何時間かかるかは、送信数と返信対応で決まります。送信の時間は「一通あたりにプロフィールを読んで一行目を書く時間×送信数」で、返信対応の時間は「返信数×一件あたりの往復」です。返信率が上がると、送信は減らせて返信対応が増えるので、時間の中身が変わります。受ける前に「週に何通送るか」と「返信対応はどの時間帯に見るか」を決めておけば、稼働の見込みが立ちます。数値は案件ごとに違うので、最初の一か月の実績で見直します。稼働の管理は[稼働時間の管理](/media/fukugyo-kadou-kanri/)に書いています。

## まとめ

- 1案件は**契約前→第1週→第2週以降→月次→終了と更新**の五つの段階
- 契約前に**範囲・稼働・アカウント・名義・最終決定者・報告・評価**を決め、範囲と稼働は書面に残す
- 第1週は**送らない**。聞き取りと検索条件と文面の承認に使い、そのことを稼働の計画に書いておく
- 第2週以降は**送る順に沿って一行目を変えて送り、決めた時間帯に返信を見て、週次で数字と「次に直すこと」を一つ報告する**
- 月次は**返信が来た人の共通点**から、送る相手→条件→文面の順に一つずつ直す。「会社に決めてもらうこと」を分けて書く
- 終了時は**検索条件・文面の型・共通点の記録を残し、アカウントと候補者の情報を返す**
- 候補者の情報は**媒体の中で完結させ、手元に残さない**

## よくある質問

### 第1週に送らないと言ったら、会社に断られませんか

「送らない」ではなく「二週目からの返信率で判断してもらうために、最初の一週間で条件と文面を整える」と伝えます。過去に送って返信が来なかった会社ほど、理由が分からないまま送り続けることの無駄を知っています。契約前の稼働の計画に第1週の中身を書いておけば、始まってから揉めません。それでも初日から送ることを求められる案件は、返信率の責任を持たされる形なら、受けるかどうかを考え直します。

### 返信対応を平日の日中にできません

運用一式ではなく、「文面だけ」「検索条件の設計」「立ち上げ支援」の型を選びます。返信対応は会社の人事に残してもらい、自分は文面と条件の設計と、週次の見直しを担います。あるいは、返信の一次対応だけは会社が行い、日程調整以降を自分が夜に行う分け方もあります。どの分け方でも、候補者を待たせない形になっているかを、会社と一緒に確かめます。

### 週次の報告には何を書けばよいですか

数字（送信、開封、返信、面談、辞退）と、次に直すこと一つ、会社に決めてもらうこと一つ、の三つです。数字だけ並べた報告は読まれず、直す判断が行われません。「次に直すこと」は一つに絞り、直した結果を翌週の数字で見せます。「会社に決めてもらうこと」は、条件や面談の枠など、自分では動かせないことを書きます。この形で報告を残しておけば、月次の見直しと終了時の引き継ぎの資料がそのままできます。

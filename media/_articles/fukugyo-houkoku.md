副業の人の働きは、依頼側からは見えません。同じ場所にいないし、稼働の時間帯も違う。依頼側が知るのは、届いた成果物と、報告だけです。報告が無いか薄いと、どれだけ働いていても「何をしているのか分からない」となり、報告が長いと読まれず、同じ結果になります。結論を先に書くと、**報告は「稼働ごとの一行」「週ごとの一枚」「区切りごとの数」の三層に分け、それぞれの長さと宛先を固定する**と、遠隔でも動いていることが伝わり、区切りの判断も数でできます。三層を混ぜて、毎回の稼働で長い報告を書いたり、区切りで一行しか出さなかったりすると、伝わりません。稼働の記録そのものは[稼働管理の方法](/media/fukugyo-kadou-kanri/)に、定例会での使い方は[定例会の進め方](/media/fukugyo-teirei-shinkou/)にまとめています。

## 報告の三層

三層の目的、長さ、宛先を整理します。

| 層 | いつ | 目的 | 長さ | 宛先 |
|---|---|---|---|---|
| 稼働ごとの一行 | 稼働の終わり（火木の夜、土曜午前など） | 翌朝に動くものと、判断待ちを渡す。動いていることを示す | 数行。一分で読める | 担当 |
| 週ごとの一枚 | 週の終わり（木曜の夜か土曜） | 一週間の数、進んだこと、止まったこと、翌週の予定 | 一枚。五分で読める | 担当と判断する人 |
| 区切りごとの数 | 月末か契約の区切り | 開始時点と現在の数、変わった理由、次の提案 | 一枚＋提案の一枚 | 判断する人と担当 |

三層の要点は、「稼働ごとの一行は担当に、区切りごとの数は判断する人に」という宛先の違いです。担当は日々の動きを知りたく、判断する人は結果を知りたい。宛先を分けると、それぞれが自分に要る情報だけを受け取ります。

## 稼働ごとの一行

稼働の終わりに送る、最も短い報告です。型を示します。

| 項目 | 書くこと | 例 |
|---|---|---|
| やったこと | 業務の種類と数 | 「スカウト文面十五通を作成、予約送信を設定」 |
| 翌朝に動くもの | 依頼側が翌日に確認・送信するもの | 「返信の下書き三件を共有フォルダに。ご確認のうえ送信をお願いします」 |
| 判断待ち | 依頼側の判断が要るもの | 「書類の一次絞りで迷った二件、一覧にしました。ご判断ください」 |
| 次回 | 次の稼働で何をするか | 「木曜は今週分の応募の一次絞りと、返信対応」 |

一行の要点は、「翌朝に動くものを、動かせる形で渡す」ことです。「下書きを作りました」ではなく「共有フォルダのここに置きました。送信をお願いします」。依頼側が翌朝、迷わず動ける形にします。名前は書かず、数と種類で書きます。[情報の取り扱いと端末の分離](/media/fukugyo-security/)を参照してください。

### エラベルの見解

登録の相談で多いのは、「稼働ごとに丁寧な報告を書いていたら、報告に三十分かかって、作業の時間が減った」という話です。報告を見ると、やったことの経緯、考えたこと、迷ったことが長く書かれています。担当は読み切れず、翌朝に何をすればよいかを探すことになります。丁寧さが、担当の手間を増やしています。

見ていて差がつくのは、「稼働ごとの報告を、数行で固定しているか」です。やったこと、翌朝に動くもの、判断待ち、次回。この四つを数行で。経緯や考えは書かない。担当は一分で読み、翌朝に動けます。エラベルの登録でも、稼働ごとの報告が短く固定されている人は、担当から「分かりやすい」と評価され、稼働時間が報告に消えていません。報告の丁寧さは、長さではなく、相手が動ける形になっているかで決まります。

## 週ごとの一枚

週の終わりに送る、一週間のまとめです。担当と判断する人の両方に送ります。型を示します。

| 項目 | 書くこと |
|---|---|
| 今週の数 | 見る数（応募から返信までの日数など）の今週の値。送信数、応募数、返信数、面接設定数 |
| 進んだこと | 本命の課題で、何が進んだか。数で |
| 止まったこと | 判断待ち、依頼側の分担が動いていないこと、自分の側で止まったこと。理由と一緒に |
| 今週直した小さなこと | 一行。数と一緒に。[早い段階で成果を出す](/media/fukugyo-quick-win/) |
| 来週の予定 | 稼働の曜日と、やること。稼働が減る週なら先に |
| 依頼側へのお願い | 来週、依頼側に動いてほしいこと。一つか二つ |

一枚の要点は、「止まったことを、理由と一緒に書く」ことです。止まったことを書かないと、順調に見えて、区切りで急に「変わっていない」となります。止まったことと理由を毎週書けば、依頼側は途中で動けます。

## 区切りごとの数

月末か契約の区切りに送る、結果の報告です。判断する人が「続けるか」を決める材料になります。

| 項目 | 書くこと |
|---|---|
| 見る数の変化 | 開始時点の値と、区切り時点の値を並べる。「平均五日→一日」 |
| 変わった理由 | 何を直したから変わったか。仕組みとして何が残っているか |
| 変わらなかった理由 | 変わらなかった部分と、その理由（仕組みの側か、分担の側か） |
| 残っている課題 | 一覧。次に直す候補 |
| 次の提案 | 一つに絞った次の課題と、見る数と期間。[提案のまとめ方](/media/fukugyo-teian/) |
| 時間と単価 | 見直しがあれば。[契約更新のタイミング](/media/fukugyo-koushin/) |

区切りの要点は、「開始時点の値を書く」ことです。開始時点の値が無いと、区切りの値だけでは変化が示せません。一か月目の四週目に記録した値を、ここで使います。

## 報告の書き方の手順

三層に共通する、書き方の手順を番号付きで整理します。

1. **数から書く。** やったことも、進んだことも、変化も、数で。「頑張りました」は書かない。
2. **相手が次に何をすればよいかを書く。** 稼働ごとなら翌朝に動くもの、週ごとならお願い、区切りなら決めること。
3. **止まったことと理由を書く。** 隠さない。理由を構造で（人の責任にしない）。
4. **経緯と考えは書かない。** 聞かれたら答える。報告には結果だけ。
5. **応募者の名前を書かない。** 数と種類で。
6. **長さを固定する。** 稼働ごとは数行、週ごとは一枚、区切りは一枚＋提案。超えたら削る。
7. **送る時間を固定する。** 稼働の終わり、週の終わり、区切りの日。依頼側が「この時間に届く」と分かる。
8. **同じ型で送り続ける。** 毎回、項目の順番を変えない。依頼側が読み慣れる。

手順の要点は、「一で、数から書く」ことです。数から書くと、経緯や考えを書く余地が減り、自然に短くなります。

## 悪い報告の直し方

よくある悪い報告と、直し方を整理します。

| 悪い報告 | 何が起きるか | 直し方 |
|---|---|---|
| 「今週も頑張りました」 | 何をしたか分からない | 数で。「返信十二件、送信二十通」 |
| 経緯が長い | 読まれない。翌朝に何をすればよいか探す | 結果と、相手が動くことだけ |
| 止まったことを書かない | 順調に見えて、区切りで急に変わっていない | 止まったことと理由を毎週 |
| 全部を担当にだけ送る | 判断する人が結果を知らない | 週ごとと区切りは判断する人にも |
| 区切りに開始時点の値が無い | 変化が示せない | 四週目に記録した値を使う |
| 送る時間がばらばら | 依頼側が待つ | 固定する |
| 応募者の名前が入っている | 情報が自分の報告に残る | 数と種類で |
| 報告に稼働時間の大半を使う | 作業が減る | 長さを固定。数行、一枚 |
| 良いことだけ書く | 信頼されない | 止まったことも書く。止まったことを書く人が信頼される |
| 判断待ちを報告に埋める | 依頼側が気づかない | 判断待ちは項目を分けて、目立つ位置に |

直し方の要点は、「止まったことを書く人が信頼される」という点です。良いことだけの報告は、依頼側にとって判断の材料になりません。止まったことと理由を書く報告は、依頼側が途中で動け、副業の人の見立てを信頼するようになります。

### エラベルの見解

担当する側として登録した人の話を聞くと、依頼側との関係が長い人は、報告の型が固定されていて、内容が単調です。毎回同じ項目、同じ順番、同じ長さ、同じ時間。依頼側は読み慣れ、届くのを待ち、届かなければ気づく。この「届かなければ気づく」状態が、遠隔での存在感です。報告の形が毎回違う人は、依頼側が読むたびに探し、慣れず、届かなくても気づかれません。

依頼側から見ると、副業の人の報告は、その人の働きの全部です。エラベルは、範囲と時間を書いた登録に、条件が合う案件のときだけご連絡する窓口ですが、依頼側から「続けたい」と言われる人は、報告が短く、数があり、止まったことも書いてあり、届く時間が決まっています。報告は、働きを伝える手段であると同時に、自分の見立てを依頼側に信頼してもらう手段です。三層の型を一つ持っていただくことをお勧めしています。

## まとめ

- 報告は**稼働ごとの一行・週ごとの一枚・区切りごとの数**の三層。長さと宛先を固定する
- 稼働ごとは**やったこと・翌朝に動くもの・判断待ち・次回**を数行で、担当に
- 週ごとは**今週の数・進んだこと・止まったこと（理由と）・小さな改善・来週・お願い**を一枚で、担当と判断する人に
- 区切りは**開始時点と現在の値・変わった理由・変わらなかった理由・残る課題・次の提案・時間と単価**
- 書き方は**数から・相手が動くことを・止まったことと理由を・経緯は書かない・名前を書かない・長さと時間を固定・同じ型で**
- **止まったことを書く人が信頼される**。良いことだけの報告は判断の材料にならない

## よくある質問

### 依頼側が報告を読んでいる気配がありません

読まれていないなら、長いか、相手が動くことが書かれていないか、時間がばらばらかのどれかです。まず、稼働ごとの報告を数行にして、翌朝に動くものを目立つ位置に書き、送る時間を固定する。それでも反応が無ければ、週次の確認で「報告のこの項目は要りますか」と聞き、依頼側が要る項目だけに減らす。読まれない報告を送り続けるより、読まれる長さと中身に変えるほうが、遠隔での存在感は上がります。

### 止まったことを書くと、評価が下がりませんか

逆です。止まったことを書かない報告は、区切りで「変わっていない」と急に分かり、そのときに評価が下がります。止まったことと理由を毎週書く報告は、依頼側が途中で動け、副業の人が状況を見ていることが伝わり、評価は上がります。書き方は、人の責任にせず、構造で。「担当の方の返信が遅い」ではなく「日中の定型返信の分担が動いていない週があり、その週は日数が伸びています」。数と構造で書けば、責める報告にはなりません。

### 週ごとの報告を、判断する人（経営者）にも送るべきですか

送る形が基本です。判断する人が週ごとの数を見ていないと、区切りで初めて結果を知ることになり、続けるかの判断が急になります。週ごとに数を見ていれば、区切りの判断は確認だけで済みます。担当が「経営者には自分から伝える」と言う場合は、担当に任せてもよいですが、区切りの数と提案は、判断する人に直接届く形にします。担当経由で意図が変わることを避けるためです。

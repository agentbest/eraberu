「人を採ろう」と決まってから、三か月。誰を採るのかが、まだ決まらない。経営者は「事業を広げられる人」と言い、現場は「今の業務を回せる人」と言う。会議のたびに要件が変わり、求人票は出せないまま。結論を先に書くと、**採用要件が固まらないのは、「理想の人」を描こうとしているからです。理想は、人によって違い、話すほど広がります。代わりに、「この役割で、最初の三か月に何をするか」「そのときに何ができないと困るか」から逆算します。逆算した要件は、事実に基づくので、関係者の間でずれにくく、固まります**。要件が高すぎる場合は[採用要件が高すぎて誰も通らない](/media/rpo-youken-takasugi/)に、必須と歓迎の線引きは[必須要件と歓迎要件の線が引けない](/media/rpo-must-want/)にまとめています。

## 要件が固まらない構造

採用要件が固まらないのは、次の構造で起きます。

| 構造 | 起きていること |
|---|---|
| 「理想の人」から考えている | 「〇〇もできて、△△もできて、人柄も良く」。理想は、話すほど増える |
| 関係者の見ている場面が違う | 経営者は一年後の事業、現場は今日の業務、人事は市場。同じ言葉で違うものを見ている |
| 役割が決まっていない | 「人が足りない」は分かるが、「何をする人か」が無い。役割が無いので要件が作れない |
| 決める人が決まっていない | 経営者と現場のどちらの意見が優先されるかが無く、会議のたびに揺れる |
| 「決めたら変えられない」と思っている | 一度決めた要件を変えるのが怖く、決めきれない |
| 市場を見ずに決めようとしている | 要件を決めてから「そんな人はいない」と分かり、振り出しに戻る |
| 過去の失敗が影を落としている | 「前に採った人が合わなかった」経験から、要件が過剰に慎重になる |

構造が分かれば、「もっと話し合えば固まる」のではなく、「考え方を変えれば固まる」と分かります。

## 固まらない原因の切り分け

固まらない原因を、切り分けます。

**役割が無い。** 「何をする人か」が決まっていないなら、要件の前に役割を決めます。役割が無いまま要件を話しても、固まりません。

**関係者の見ている場面が違う。** 経営者と現場が違うことを言っているなら、「どの時点の、どの場面の話か」を揃えます。「入社して最初の三か月」に揃えれば、大半は近づきます。

**決める人がいない。** 意見が割れたときに、誰が決めるか。決める人を先に決めます。多くの場合、その役割の直属の責任者です。

**理想が膨らんでいる。** 要件が十個以上あるなら、理想が膨らんでいます。「最初の三か月に無いと困るもの」だけに絞ります。

**市場を知らない。** 「この要件の人はいるのか」が分からないなら、紹介会社や媒体の担当者に聞きます。市場に無い要件は、固めても意味がありません。

**過去の失敗への反応。** 「前に採った人が合わなかった」なら、何が合わなかったかを一つ特定し、その一つを要件に足します。全部を慎重にする必要はありません。

切り分けると、「固まらない」の中身が一つか二つに絞れます。絞れれば、対処できます。

## 役割から逆算する手順

「理想の人」ではなく、役割から逆算する手順です。

**最初の三か月に、何をするかを書く。** 「入社して最初の三か月で、この人は何をするか」を、現場の責任者が具体的に書きます。「〇〇の業務を引き継ぐ」「△△の顧客を担当する」「□□の仕組みを作り始める」。理想ではなく、実際にやること。

**その三か月で、何ができないと困るかを書く。** やることの一つひとつについて、「これができないと、三か月で詰まる」ものを挙げます。これが「必須」の候補です。

**「あれば早い」ものを分ける。** 「無くても三か月は回るが、あれば早い」ものは、「歓迎」の候補です。分け方は[必須要件と歓迎要件の線が引けない](/media/rpo-must-want/)に書いています。

**一年後の姿を、別に書く。** 経営者が見ている「一年後にこうなってほしい」は、最初の三か月の要件とは別に書きます。入社後の成長の見通しとして、求人票と面接で伝えます。要件には混ぜません。

**「一緒に働けない人」を書く。** 「こういう人は、この役割では合わない」。過去の失敗から一つ。要件を増やすのではなく、外す条件を一つ持ちます。

**要件を、観察できる言葉にする。** 「コミュニケーション力」ではなく「顧客の要望を聞き取って、社内に文章で伝えられる」。面接で確認できる形に。

**要件の数を、必須三〜四、歓迎二〜三に収める。** それ以上は、理想に戻っています。

逆算した要件は、「最初の三か月に、実際にやること」に基づくので、経営者も現場も「それは確かに要る」と言えます。理想の話より、揃いやすいです。

## 関係者の意見を揃える場

経営者・現場・人事の意見を、一度の場で揃える方法です。

| 項目 | 型 |
|---|---|
| 参加者 | 役割の直属の責任者（決める人）、経営者（または事業の責任者）、人事（または担当者）。多くしない |
| 時間 | 一時間。それ以上は、理想の話になる |
| 事前の準備 | 現場の責任者が「最初の三か月にやること」を書いてくる。人事が「市場でこの要件の人がいるか」を紹介会社に聞いてくる |
| 進め方 | 「最初の三か月にやること」を読み合わせ→「無いと困るもの」を挙げる→「あれば早いもの」を分ける→「一年後の姿」を別に書く→「合わない人」を一つ書く |
| 決め方 | 意見が割れたら、直属の責任者が決める。経営者は「一年後の姿」で意見を出す |
| 出力 | 要件の一枚（役割、必須、歓迎、一年後の姿、合わない人、条件の幅） |
| 有効期限 | 「三か月間はこの要件で進める。三か月後に見直す」と決める |

場の要点は、「理想を話す場」ではなく「最初の三か月から逆算する場」にすることです。進め方が決まっていれば、一時間で固まります。進め方が無いと、三時間話しても固まりません。

### エラベルの見解

相談で最も多い失敗は、「経営者と現場と人事で三か月話し合って、要件が十二個になり、紹介会社に『該当者はいません』と言われて振り出しに戻った」というものです。三か月の間、「どんな人が理想か」を話していました。「最初の三か月にやること」から逆算したら、必須は三つ、歓迎は二つになり、一時間で固まり、紹介会社からも推薦が来ました。理想を話す時間が、固まらない時間でした。

見ていて差がつくのは、担当者が「最初の三か月にやること」を現場から引き出せるかどうかです。「どんな人が欲しいですか」と聞く担当者と、「入社した人が、最初の三か月で実際にやることを教えてください」と聞く担当者がいます。前者の答えは理想で、後者の答えは事実です。事実から作った要件は、固まります。

発注側にできるのは、担当者に「理想の人」を聞かせず、「最初の三か月にやること」を現場に聞かせることです。

## 要件を「仮」で出して直す運用

要件は、一度で完成しません。「仮」で出して、直す運用にします。

**「仮の要件」で求人を出す。** 固まるまで待つと、出せません。逆算した要件を「仮」として出し、応募と面接で確かめます。

**応募と面接で、要件を確かめる。** 「必須にした〇〇は、面接で確認できたか」「必須にしていない△△が、実は要ると分かったか」。応募と面接が、要件の検証になります。

**紹介会社と媒体の反応で、市場との合いを確かめる。** 「この要件で該当者がいるか」。反応が無ければ、要件が市場に合っていません。

**三か月ごとに、要件を見直す。** 「有効期限」を決めておき、期限が来たら、応募と面接の記録を見て直します。

**変えた理由を、記録する。** 「〇〇を必須から歓迎に変えた。理由は面接で△△が確認できれば十分と分かったから」。記録があれば、次の見直しの材料になります。

**「変えられない」と思わない。** 要件は、仮説です。応募と面接で検証し、直すものです。最初から完璧を目指すと、固まりません。

仮で出して直す運用は、「固まらないから出せない」を「出しながら固める」に変えます。

## 要件が変わったときの扱い

要件が途中で変わることは、あります。扱いです。

**変える理由を、明確にする。** 「面接で分かった」「事業の方針が変わった」「市場に該当者がいなかった」。理由が無い変更は、揺れです。

**決める人が、変更を決める。** 会議のたびに誰かの一言で変わる状態を避けます。変更も、直属の責任者が決めます。

**選考中の候補者への影響を、見る。** 要件を変えると、選考中の候補者が「新しい要件では通らない」または「通る」になることがあります。候補者に不利益が出ないよう、扱いを決めます。

**求人票と、紹介会社への説明と、面接官の観点を、同じ日に直す。** 要件を変えたのに求人票が古い、紹介会社が古い要件で探している、面接官が古い観点で見ている、が起きます。全部を同じ日に。

**変更の履歴を残す。** 「いつ、何を、なぜ変えたか」。次の採用で、同じ議論を繰り返さないために。

**頻繁に変わるなら、役割が決まっていない。** 三か月に一度の見直し以外で頻繁に変わるなら、役割そのものが決まっていません。要件ではなく、役割に戻ります。

変わること自体は問題ではありません。理由と決める人と反映の手順が無いことが、問題です。

## 外注する場合の範囲

要件が固まらない問題を、採用代行に出す場合の範囲です。

**出せる工程。** 固まらない原因の切り分け、現場の責任者からの「最初の三か月にやること」の聞き取り、逆算した要件の案（必須、歓迎、一年後の姿、合わない人）、観察できる言葉への書き換え、市場との合いの確認（紹介会社と媒体の担当者への聞き取り）、関係者の場の設計と進行、要件の一枚の作成、仮の要件での求人票、応募と面接の記録による検証、三か月ごとの見直しの材料、変更の反映（求人票、紹介会社、面接官の観点）、変更の履歴。

**社内に残す判断。** 役割の決定、決める人の指名、要件の決定、変更の決定、選考中の候補者への扱い。

**外注の効きどころ。** 要件が固まらない会社は、関係者の間で「理想」を話し続けています。外部の担当者が「最初の三か月にやること」を聞き、逆算した案を持ち込み、場を進行すれば、一時間で固まることが多いです。担当者は関係者の誰の側でもないので、意見が割れたときに「決める人が決める」を促せます。

**外注しても動かない場合。** 役割を決めない、決める人を決めない、経営者が「理想の人」を譲らない。社内の判断で、代行を替えても直りません。

要件は、考え方を変えれば固まります。外注は、考え方を持ち込み、場を進める手段です。

### エラベルの見解

担当する側から見ると、要件が固まらない相談で最も多いのは、「決める人がいない」ことです。経営者と現場が違うことを言い、人事が間で困っている。どちらの意見が優先されるかが無いので、会議のたびに揺れます。

「この役割の直属の責任者が決める。経営者は一年後の姿で意見を出す」と役割を分けるだけで、揺れは止まります。決める人が決まれば、意見が割れても前に進めます。

発注側にできるのは、要件の話を始める前に、「誰が決めるか」を決めることです。

## よくある質問

### 経営者と現場で、求める人がまったく違います

見ている時点が違うことが多いです。経営者は一年後の事業、現場は今日の業務。「入社して最初の三か月にやること」に時点を揃えると、大半は近づきます。経営者の「一年後の姿」は、要件ではなく、入社後の成長の見通しとして別に書きます。それでも割れるなら、直属の責任者が最初の三か月の要件を決め、経営者は一年後の姿で意見を出す、と役割を分けます。

### 要件を決めきれないまま、求人を出してもよいですか

「仮の要件」として出します。逆算した必須三〜四、歓迎二〜三で出し、応募と面接で確かめます。固まるまで待つと、いつまでも出せません。出しながら、応募と面接と市場の反応で直します。「有効期限」を三か月と決め、期限が来たら記録を見て見直します。要件は仮説で、検証して直すものです。

### 前に採った人が合わなかったので、要件を厳しくしたいです

何が合わなかったかを、一つ特定します。「〇〇ができなかった」「△△の考え方が合わなかった」。その一つを、要件（または「合わない人」の条件）に足します。全部を厳しくすると、理想が膨らみ、誰も通らなくなります。失敗から学ぶのは、一つの要件を足すことで、全部を慎重にすることではありません。

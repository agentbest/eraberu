ゲーム業界の会社が採用代行を検討するとき、動機は「開発が動き出したのに、プランナーもデザイナーもエンジニアも足りない」であることが多い。ただ、ゲーム業界の採用は、他の業界と違う難しさがあります。職種が細かく分かれ、作品の実績（ポートフォリオ）で判断する部分が大きく、プロジェクトの段階で要る人と時期が動き、候補者は「どの作品に関わるか」で会社を選び、守秘の制約で発信できる情報が限られる。結論を先に書くと、**ゲーム業界の採用代行は、母集団形成・一次対応・日程調整・記録は外に出せる一方、作品の実績の見極め・プロジェクトとの照合・守秘の範囲の判断・条件の判断は社内に残さないと、採れても作品に合いません。**代行に出す前に、難しさを自社の状況で分解し、工程ごとに「任せる・残す」を決めることが、代行が機能する条件です。職種ごとの切り分けは[デザイナー採用を代行に出す判断基準](/media/rpo-designer-rpo/)や[エンジニア採用を代行に出す判断基準](/media/rpo-engineer-rpo/)に、IT・Web業界との共通点は[IT・Web業界の採用代行](/media/rpo-it-rpo/)に書いています。ここでは、ゲーム業界で共通する切り分けに絞ります。

## ゲーム業界の採用が難しい四つの理由

| 難しさ | 中身 | 代行への影響 |
|---|---|---|
| 作品の実績で判断する | 経歴の言葉より、関わった作品と担った範囲で読む。ポートフォリオの見方が職種ごとに違う | 代行は「関わった作品と範囲」の照合まで。作品の質の判断は社内 |
| プロジェクトの段階で要る人が動く | 企画の段階はプランナー、開発の段階はエンジニアとデザイナー、運営の段階は運営とデータ。時期が読みにくい | 採る数と時期がプロジェクトの計画と紐づいていないと、早すぎるか遅すぎる |
| 候補者が「作品」で選ぶ | どのジャンル、どの規模、どの段階の作品に関わるかで動く | 「ゲーム会社だから」では差にならない。作品と役割の実態で |
| 守秘の制約 | 開発中の作品の情報を出せない。求人票と文面に書ける範囲が限られる | 出せる範囲を社内が決めないと、代行は文面を書けない |

四つのうち、代行で解決できるのは母集団形成と速さで、実績の見極め・照合・守秘の判断は社内の関わりが要ります。

## 工程ごとの「任せられる・残す」

| 工程 | 任せられるか | 理由 |
|---|---|---|
| プロジェクトの計画から採る数と時期を決める | 残す | 開発の責任者が決める |
| 採用要件の言葉への整理 | 一緒に | 「関わった作品の型・担った範囲・使った道具」の言葉に。代行が整え、社内が確認 |
| 守秘の範囲の判断（何を書けるか） | 残す | 社内の判断。代行は範囲の中で文面を書く |
| 母集団形成（媒体・スカウト・イベント） | 任せられる | 職種ごとの型があれば外で回せる |
| 一次対応（返信・日程） | 任せられる | 速さが要る工程 |
| ポートフォリオの一次確認 | 一部任せられる | 「関わった作品と担った範囲」の照合は外で。質の判断は社内 |
| 作品の実績の見極め（面接、課題） | 残す | 社内の同じ職種の人 |
| プロジェクトとの照合（どの作品のどの段階に入るか） | 残す | 開発の責任者 |
| 条件の判断 | 残す | 会社の判断 |
| 記録と報告 | 任せられる | 一覧と週次の一枚 |

「守秘の範囲の判断」は、ゲーム業界に特有の残す工程です。範囲が決まっていないと、代行は動けません。

### エラベルの見解

ゲーム業界で多くの会社が見落とすのは、「守秘の範囲」を先に決めることです。開発中の作品の情報は出せない、という制約の中で、「ジャンル・規模・段階・使う道具・チームの構成」のどこまでを求人票と文面に書いてよいかを、社内で決めていない。代行は「書けること」が分からず、「ゲーム会社です。一緒に作りましょう」の文面になり、返信が来ません。「作品名は書けないが、ジャンルと規模と段階は書ける」「使う道具とチームの構成は書ける」と範囲を一枚にすると、代行は範囲の中で具体の文面を書けます。エラベルで担当者を選ぶ企業には、「求人票と文面に、開発中の作品について何まで書けますか」を、私たちから先に聞いています。答えが「分からない」なら、代行の前に範囲の一枚が要ります。

## 代行に出す前に社内で確認すること

| 確認 | 中身 |
|---|---|
| プロジェクトの計画と採用の一枚 | どの作品の、どの段階で、どの職種が、いつまでに要るか |
| 守秘の範囲 | ジャンル・規模・段階・道具・チームの構成のどこまでを書けるか |
| 作品の実績を見極める人 | 職種ごとに、社内の同じ職種の人が面接と課題を担えるか |
| 面接の枠 | 開発の責任者と同じ職種の人の枠を、週に決まった数出せるか |
| 条件の幅 | 年収の幅と働き方を先に出せるか |
| 記録の形 | 一覧と記録が社内の環境にあるか。ポートフォリオの置き場所と権限 |

「作品の実績を見極める人」の時間は、開発が動いているほど取りにくい。枠を週に一つでも先に預けます。

## 職種ごとに代行の型が違う

| 職種 | 代行に向く工程 | 社内に残す度合い |
|---|---|---|
| プランナー | 母集団形成、一次対応 | 企画の実績の見極めは社内。課題の設計 |
| デザイナー（2D・3D・UI） | 母集団形成、ポートフォリオの一次確認（関わった作品と範囲） | 質の判断は社内。[デザイナーの採用要件の作り方](/media/rpo-designer-youken/) |
| エンジニア（クライアント・サーバー） | 母集団形成（スカウト中心） | 技術の見極めは社内 |
| サウンド・シナリオ | 母集団形成、実績の一次確認 | 質の判断は社内 |
| 運営・データ | 母集団形成、一次対応 | 運営の段階に合う人かを社内で |

「ゲーム業界の採用に強い代行」でも、職種ごとの型（ポートフォリオの一次確認の項目、経路、文面）を持っているかは別です。

## 代行を選ぶときの確認項目

| 確認 | 聞き方 |
|---|---|
| 職種ごとの型があるか | 「プランナーと3Dデザイナーで、経路と文面と一次確認の項目をどう変えますか」 |
| 守秘の範囲の中で文面を書けるか | 「作品名を出せない場合、文面に何を書きますか」 |
| 担当者の経歴 | 「担当する方は、ゲーム業界のどの職種の採用を、どの工程で担った経験がありますか」 |
| ポートフォリオの扱い | 「候補者の作品の情報を、どこに置き、誰が見られる形にしますか」 |
| 返事の速さと記録の置き場所 | 「候補者への返事は何営業日以内か。記録はどこに置くか」 |
| 費用の構造 | 「月額に含まれる工程と職種の数は」 |

費用は、含まれる工程と職種の数で変わり、金額の相場を先に聞くより「同じ工程・同じ職種数で比べる軸」をそろえます。費用の構造は[採用代行の費用の内訳](/media/rpo-hiyou-uchiwake/)に、選び方の軸は[採用代行会社の選び方](/media/rpo-erabikata/)に書いています。

## 代行に出したあとに起きること

| 起きること | 原因 | 対応 |
|---|---|---|
| 文面が「ゲーム会社です」で返信が来ない | 守秘の範囲が決まっておらず、書けることが無い | 範囲の一枚を作り、ジャンル・規模・段階・道具・構成を書く |
| ポートフォリオの一次確認で、質を代行が判断してしまう | 一次確認の項目が「関わった作品と範囲」に絞られていない | 項目を絞り、質は社内 |
| 採れたが、プロジェクトの段階と合わない | 採る時期がプロジェクトの計画と紐づいていない | 計画と採用の一枚を同じ行に |
| 候補者の作品の情報が代行の環境に | 置き場所と権限を決めていない | 社内の環境に、権限を最小に |
| 契約が終わると記録が消える | 記録が代行の環境 | 社内の環境に置く形を契約で |

出したあとの問題は、「守秘の範囲」「一次確認の項目」「計画との紐づけ」「作品の情報の置き場所」に戻ります。

### エラベルの見解

ゲーム業界の候補者は「どの作品に関わるか」で動くので、守秘の範囲の中で「作品の型」をどこまで具体に書けるかが、返信を決めます。作品名を出せなくても、「〇〇のジャンルで、〇〇の規模のチームが、いま〇〇の段階にいて、この役割は〇〇を担う」と書ければ、候補者は自分が関わる姿を想像できます。エラベルは担当者を工程ごとに選べる形にしているので、ゲーム業界の職種ごとの経路と文面の型を持つ担当者を、母集団形成と一次対応に絞って選べます。作品の実績の見極めと守秘の判断は社内に残し、代行はその範囲の中で動く。この分担ができる会社では、代行は機能します。差の出し方は[自社紹介はどこまで書くか](/media/scout-kaisha-shoukai/)に書いています。

## まとめ

- ゲーム業界の難しさは、**作品の実績で判断・段階で動く時期・作品で選ぶ候補者・守秘の制約**の四つ
- **母集団形成・一次対応・日程・記録は任せられ、実績の見極め・プロジェクトとの照合・守秘の判断・条件は残す**
- **守秘の範囲の一枚**（ジャンル・規模・段階・道具・構成のどこまで書けるか）を先に。無いと代行は文面を書けない
- ポートフォリオの一次確認は**「関わった作品と担った範囲」の照合まで**。質は社内
- 採る数と時期は**プロジェクトの計画と同じ行**に
- 候補者の作品の情報は**社内の環境に、権限を最小に**
- 代行を選ぶときは**職種ごとの型と、守秘の範囲の中で書けるか**を確かめる

## よくある質問

### 開発中の作品のことを何も出せず、文面に書けることがありません

作品名と内容は出せなくても、「ジャンル・規模・段階・使う道具・チームの構成・この役割が担うこと・一緒に働く人」は、多くの場合出せます。出せる範囲を社内で決め、一枚にします。それでも出せることが無いなら、「過去の作品」と「会社としての作品の型」で語り、開発中のものは面接で守秘の合意の上で話す形にします。守秘の範囲の判断は会社の領域で、代行は範囲の中で動きます。

### ポートフォリオの一次確認を代行に任せて大丈夫ですか

「関わった作品・担った範囲・使った道具」の照合に絞れば任せられます。「この作品の質は高いか」の判断は、社内の同じ職種の人にしかできません。一次確認の項目を三つに絞った一枚を代行に渡し、質の判断は社内の二次で行う形にします。候補者の作品の情報は、社内の環境に置き、代行の権限を最小にします。

### プロジェクトの計画が変わりやすく、採る時期が読めません

計画が変わることを前提に、採用の一枚を月次で見直します。「確定した段階」だけを採る数の根拠にし、「予定」は一枚に載せるが数えない。募集の開始から入社までの日数を記録から出し、確定の段階から逆算します。計画と採用が同じ行にあれば、計画が変わったときに採用も一緒に動きます。計画のつなぎ方は[要員計画と採用計画がつながっていない](/media/rpo-jinin-keikaku/)に書いています。

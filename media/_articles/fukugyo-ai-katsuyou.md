副業の稼働は限られている。AIを使えば、文面も報告も資料も速くなりそうだが、どこまで使ってよいのか、依頼側に何と言えばよいのか、使いすぎて自分の力が落ちないかが気になる。結論を先に書くと、**人事の副業でAIを使ってよいのは、「依頼側と候補者の情報を含まない作業」に限ります。型の構造の下書き、人事の一般的な知識の整理、自分の文章（依頼側の情報を含まないもの）の整え、自分の判断の言語化には使え、候補者への対応、依頼側への報告、依頼側の記録を扱う作業には使いません。使う前に「これは依頼側か候補者の情報を含むか」を問う一つの癖が、使い方の全部を決めます。**線の根拠は、守秘（情報を外部に渡さない）と責任（送るものの責任は自分にある）の二つです。文面での前提は[AIで文面を作るときの前提](/media/fukugyo-ai-bunmen/)に、情報の扱いの線は[情報の取り扱いと端末の分離](/media/fukugyo-security/)に、ツールの揃え方は[使うツールをそろえる](/media/fukugyo-tool/)にまとめています。AIのサービスの規約と、依頼側の情報管理の決まりの解釈は、依頼側と専門家にご確認ください。

## 使ってよい作業と使わない作業の線

線は一本で、「依頼側と候補者の情報を含むか」です。含まなければ使え、含めば使いません。

| 作業 | 情報を含むか | 使うか |
|---|---|---|
| スカウトの文面の構造の下書き | 含まない（一般的な構造） | 使う |
| 候補者向けの文面の中身 | 含む（候補者の経歴、依頼側の状況） | 使わない |
| 候補者からの返信への返答 | 含む（やり取りの内容） | 使わない |
| 依頼側への稼働報告 | 含む（依頼側の記録の数字、状況） | 使わない |
| 人事の一般的な知識の整理（選考の一般的な流れ、媒体の一般的な機能） | 含まない | 使う |
| 自分の判断のメモの言語化（依頼側の情報を抜いたもの） | 含まない | 使う |
| 自分の発信の下書き（判断の仕方、型の話） | 含まない | 使う。ただし送る前に五つの線で読む。[発信で書いてはいけないこと](/media/fukugyo-hasshin-nglines/) |
| 依頼側の記録の集計や分析 | 含む | 使わない |
| 議事録の作成（依頼側との打ち合わせ） | 含む | 使わない |
| 型の文書の構造の整理（依頼側の情報を抜いた構造） | 含まない | 使う |
| 自分の経歴やプロフィールの整え | 含まない（依頼側の名前を入れなければ） | 使う。実績の書き方は粗くしたもので |
| 契約書の条項の一般的な意味の確認 | 契約書そのものを貼れば含む | 一般的な用語の意味の確認までは使える。契約書は貼らない。判断は専門家に |

線の要点は、「作業の種類ではなく、その作業に情報が要るか」で決めることです。「文面の作成」でも、構造の下書きは情報を含まず、中身は含みます。「資料の作成」でも、四段の骨格の整理は含まず、根拠の数字は含みます。同じ作業の中で、含む部分と含まない部分を分け、含まない部分だけをAIに任せます。情報の種類ごとの線は[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に書いています。

## 線の根拠は守秘と責任

なぜ「情報を含むか」が線になるのか、根拠を二つで押さえます。

| 根拠 | 内容 |
|---|---|
| 守秘 | AIのサービスに情報を入力することは、そのサービスの運営者に情報を渡すことになり得る。依頼側との秘密保持、候補者の個人情報の扱いの観点で、第三者への提供と見られる。サービスの規約で入力した情報の扱いが決まっているが、規約は変わり、依頼側はそれを前提にしていない |
| 責任 | 候補者に送るもの、依頼側に出すものの責任は、AIではなく自分と依頼側にある。中身をAIに任せると、事実と違うこと、約束になる表現、依頼側の言い方と違う表現が混ざり、それに気づかずに送ることになる。責任を取れるのは、自分が中身を把握しているものだけ |

根拠の要点は、「守秘は情報を入力しないことで守れ、責任は中身を自分で作ることで守れる」ことです。情報を含まない作業に限れば、守秘は守れます。中身を自分で作れば、責任は取れます。二つを満たす使い方が、「構造と一般的な整理はAI、中身と判断は自分」です。守秘の線を越える場面は[守秘の線を越える](/media/fukugyo-shippai-8/)に、責任の線は[会社の代表として話す責任](/media/fukugyo-kaisha-daihyou/)に整理しています。

### エラベルの見解

相談で最も多い思い込みは、「AIを使うか使わないかを、まず決めるべきだ」というものです。実際には、使うか使わないかは作業ごとに違い、一つの答えはありません。決めるべきなのは、「この作業は依頼側か候補者の情報を含むか」を、使う前に毎回問うことです。この一つの癖があれば、どのサービスが出てきても、どの作業でも、線は守れます。癖が無いと、便利さに引かれて、情報を含む作業に使い、後で分かって信頼を失います。

見ていて差がつくのは、AIを「速くする道具」と見ているか、「情報を渡す先」と見ているかです。前者だけで見ている人は、速くなる作業なら何でも入力します。後者の視点も持っている人は、入力する前に「これを渡してよいか」を考え、渡してよいものだけを入力します。エラベルでは、担当者が依頼側と候補者の情報を外部のサービスに入力しないことを、情報の扱いの前提にしています。AIを使うかどうかは担当者の判断ですが、情報の線は担当者の判断で動かせるものではありません。

## 使うと効く四つの場面

情報を含まない作業のうち、AIを使うと副業の稼働が減る場面を四つに絞ります。

| 場面 | 使い方 | 効き方 |
|---|---|---|
| 一、型の構造の下書き | 「スカウトの文面の構造」「面接の準備の資料の項目」「稼働報告の骨格」のような、一般的な構造の案を出させる | 一から考える時間が減る。出てきた構造を、自分の判断で削り、案件ごとに中身を埋める |
| 二、一般的な知識の整理 | 「選考の一般的な流れ」「媒体の一般的な機能の違い」「業務委託と雇用の一般的な整理」のような、案件に依らない知識を整理させる | 調べる時間が減る。ただし、数値や仕様や法令の解釈は、出典を確認するか専門家に |
| 三、自分の文章の整え | 依頼側の情報を含まない文（発信の下書き、自分の経歴、型の説明）を、短くする、言い換える | 書く時間が減る。送る前に自分で読む |
| 四、自分の判断の言語化 | 「返信が来ないときに自分がやっていること」のような、頭の中の判断を言葉にする補助。依頼側の情報は抜いて | 判断のメモが溜まりやすくなる。発信と経歴の材料になる。[発信のネタの見つけ方](/media/fukugyo-hasshin-neta/) |

四つの要点は、「一」の構造の下書きが、最も効くことです。文面、資料、報告の構造を一から考える時間は、副業の稼働の中で大きく、構造の下書きをAIに出させれば、その時間はほぼ消えます。中身は自分で埋めるので、情報の線は守れ、責任も取れます。構造と中身の分け方は[AIで文面を作るときの前提](/media/fukugyo-ai-bunmen/)に、型の育て方は[事例を流用しない](/media/fukugyo-jirei-ryuuyou/)に書いています。

## 使ってはいけない四つの場面

情報を含む作業のうち、特に使いたくなるが使ってはいけない場面を四つに絞ります。

| 場面 | なぜ使いたくなるか | なぜ使わないか |
|---|---|---|
| 一、候補者への対応 | 返信の量が多く、速くしたい | 候補者の情報（経歴、やり取り）を入力することになる。候補者は依頼側の外の人で、情報の同意が無い |
| 二、依頼側への報告 | 毎月の報告を速く書きたい | 依頼側の記録の数字と状況を入力することになる。報告の中身は依頼側の情報そのもの |
| 三、依頼側の記録の集計と分析 | 数字を見るのが速くなる | 依頼側の記録を丸ごと入力することになる。集計は表計算で、自分で |
| 四、議事録の作成 | 打ち合わせの録音から起こしたい | 打ち合わせの内容は依頼側の情報。録音そのものも、依頼側の許可が要る |

四つの要点は、「使いたくなる場面ほど、情報を含む」ことです。候補者対応、報告、記録、議事録は、副業の稼働の中で時間がかかる作業で、だからこそAIに任せたくなりますが、どれも依頼側と候補者の情報そのものです。この四つは、型を持ち、記録を整え、手順を固定することで速くします。AIではなく、型で速くする方法は[稼働報告のフォーマット](/media/fukugyo-kadou-houkoku/)、[議事録の残し方](/media/fukugyo-gijiroku/)、[候補者への対応で気をつけること](/media/fukugyo-kouhosha-taiou/)に整理しています。

## 依頼側の決まりとサービスの規約の確認

自分の線を守っていても、依頼側の決まりと、サービスの規約が別にあります。両方を確認します。

| 確認すること | 誰に | 結果ごとの扱い |
|---|---|---|
| 依頼側でAIの利用が認められているか | 依頼側の担当者、情報管理の窓口 | 禁止なら使わない。条件付きなら条件に従う。無ければ自分の線で |
| 依頼側が指定するサービスがあるか | 同上 | 指定があればそれを使う。依頼側が契約しているサービスは、依頼側の管理下にある |
| 依頼側が入力を禁じている情報の範囲 | 同上 | 自分の線（依頼側と候補者の情報を入力しない）より厳しければ、依頼側に従う |
| サービスの規約で、入力した情報がどう扱われるか | サービスの規約。解釈は専門家に | 情報を含まない作業に限っていれば、規約の影響は小さいが、規約は読んでおく |
| サービスの規約が変わったか | 定期的に | 変わることがある。使い続けるなら、たまに見直す |
| 本業の会社のAIの利用の決まり | 本業の規定 | 本業の端末や回線でAIを使わないのは前提。本業の決まりが副業に及ぶかは、規定を確認 |

確認の要点は、「依頼側の決まりが、自分の線より厳しければ、依頼側に従う」ことです。依頼側が「AIの利用は一切不可」なら、構造の下書きにも使いません。依頼側の決まりは、契約の最初に、端末と回線の確認と同じ場で聞きます。確認の項目は[ネットワーク環境の注意](/media/fukugyo-vpn/)に、本業との線は[本業と利益相反になる案件](/media/fukugyo-riekisouhan/)に書いています。規約と決まりの解釈は、専門家にご確認ください。

## AIに頼ると弱る力

AIを使うこと自体は問題ありませんが、頼りすぎると、副業で要る力が育たなくなります。

| 弱る力 | なぜ弱るか | 保つ方法 |
|---|---|---|
| 相手の立場で読む力 | AIが作った文を、そのまま送る癖がつく | 送る前に自分で読むことを省かない。[文章力をどう磨くか](/media/fukugyo-writing/) |
| 自分の判断の型 | 構造も中身もAIに任せると、「この状況でこう判断する」が自分に溜まらない | 中身と判断は自分で。判断のメモを自分で書く |
| 記録を見て考える力 | 記録の分析をAIに任せる（情報の線で本来できないが）と、数字から状態を読む力が育たない | 記録は自分で見る。[数字で語る](/media/fukugyo-suuji/) |
| 依頼側の言い方に合わせる力 | AIの一般的な文体に慣れ、依頼側ごとの言い方を見なくなる | 依頼側の過去の文面を見て合わせる習慣を保つ |
| 聞いたことを構造にする力 | ヒアリングの整理をAIに任せると、自分で工程と範囲に当てはめる力が育たない | 一枚に戻すのは自分で。[ヒアリング力の磨き方](/media/fukugyo-hearing-skill/) |

弱る力の要点は、「AIに任せてよいのは構造で、判断は自分でやり続ける」ことです。判断（この状況でこう書く、この数字をこう読む、この課題をこう構造にする）が自分に溜まることが、副業の担当者の価値で、次の案件で使えるものです。構造はAIに出させても、判断は自分でやれば、力は育ちます。判断の型の育て方は[改善を回す](/media/fukugyo-kaizen/)にも書いています。

## 副業の枠での使い方の型

副業の枠の中で、AIを使う型を決めておきます。毎回迷わずに済みます。

| 手順 | 内容 |
|---|---|
| 一、使う前に「情報を含むか」を問う | 含むなら使わない。含まないなら次へ |
| 二、依頼側の決まりを確認済みか | 契約の最初に確認していれば、その範囲で。未確認なら確認してから |
| 三、構造か一般的な整理に限る | 中身と判断は自分で |
| 四、出てきたものを、自分の判断で削る | AIの出すものは一般的で長い。自分の型と依頼側の状況に合わせて削る |
| 五、中身を自分で埋める | 依頼側の状況、候補者との接点、依頼側の言い方は自分で |
| 六、送る前に相手の立場で読む | 省かない |
| 七、使ったことを、依頼側に聞かれたら答えられる形にしておく | 「構造の下書きに使い、御社と候補者の情報は入力していません」 |

型の要点は、「一」の問いを、毎回省かないことです。慣れてくると、「これくらいなら」と情報を含む作業に使いたくなります。毎回問えば、線は保てます。一つの癖が、使い方の全部を決めます。使うことを依頼側に伝える形は[AIで文面を作るときの前提](/media/fukugyo-ai-bunmen/)に整理しています。

### エラベルの見解

担当する側から見ると、AIを使って副業の稼働を減らせている人は、AIを多く使っている人ではなく、使う場面を「情報を含まない構造と整理」に限っている人です。文面と資料と報告の構造の下書きをAIに出させ、中身と判断は自分でやり、送る前に自分で読む。構造の時間が消えた分、中身と判断に時間を使え、文面と報告の質はむしろ上がっています。AIに中身まで任せた人は、速く見えますが、候補者に「量産された文面」と見られ、依頼側に情報の扱いを疑われ、自分の判断の型が溜まっていません。

順番として、契約の最初に依頼側のAIの決まりを確認し、使う前に「情報を含むか」を毎回問い、含まない構造と整理に限って使い、出てきたものを自分の判断で削り、中身を自分で埋め、送る前に自分で読み、聞かれたら答えられる形にしておく。この順番で、AIは情報の線を守りながら、副業の枠を有効に使う道具になります。エラベルでは、担当者が依頼側と候補者の情報をAIを含む外部のサービスに入力しないことを前提にしています。AIは、その前提の中で使える道具で、前提の外では使えない道具です。

## まとめ

- AIを使ってよいのは**依頼側と候補者の情報を含まない作業**に限る。作業の種類ではなく、情報が要るかで決める
- 根拠は**守秘（情報を渡さない）と責任（中身は自分が把握する）**の二つ
- 効く場面は**型の構造の下書き・一般的な知識の整理・自分の文章の整え・自分の判断の言語化**の四つ
- 使わない場面は**候補者への対応・依頼側への報告・依頼側の記録の集計・議事録**の四つ。使いたくなるほど情報を含む
- **依頼側の決まりとサービスの規約**を確認し、依頼側の決まりが厳しければそれに従う
- 頼りすぎると**相手の立場で読む力・判断の型・記録を読む力・言い方を合わせる力・構造にする力**が弱る。判断は自分で
- 型は**情報を含むかを問う→決まりを確認→構造に限る→削る→中身を埋める→送る前に読む→聞かれたら答えられる形に**

## よくある質問

### 依頼側が自社で契約しているAIのサービスを使ってよいと言っています

依頼側の管理下にあるサービスなら、依頼側の決まりの範囲で、依頼側の情報を扱う作業にも使える場合があります。ただし、候補者の情報の扱いは、依頼側のサービスであっても、候補者への同意や依頼側の個人情報の方針に関わるので、「候補者の情報を入力してよいか」を依頼側の情報管理の窓口に確認します。依頼側のサービスを使う場合も、送るものの責任は自分と依頼側にあるので、中身を自分で読むことは省きません。

### AIで下書きした発信を、そのまま投稿してよいですか

自分の判断の仕方や型の話のように、依頼側と候補者の情報を含まない内容なら、下書きにAIを使うことはできますが、投稿の前に、五つの線（依頼側・候補者・本業・契約の条件・保証に見える表現）で自分で読みます。AIの下書きには、一般的な表現として、保証に見える表現（「誰でも〜できる」のような）や、出典の無い数字が混ざることがあり、そのまま投稿すると線を越えます。下書きは構造まで、中身と確認は自分で、が発信でも同じです。線は[発信で書いてはいけないこと](/media/fukugyo-hasshin-nglines/)に整理しています。

### AIを一切使わないほうが、依頼側からの信頼は高いですか

使わないこと自体が信頼になるわけではなく、情報の線を守っていることが信頼になります。「構造の下書きに使い、御社と候補者の情報は入力していない」と線を示せる担当者と、AIを一切使わない担当者で、依頼側の信頼に差はほとんどありません。差が出るのは、線を越えて使った担当者と、そうでない担当者の間です。使うかどうかより、使うなら線を守り、聞かれたら答えられる形にしておくことが、信頼の条件です。

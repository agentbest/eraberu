採用代行との契約を終える際は、**必要なデータと成果物、保存先と利用条件を整理し、受渡し・受入確認・削除や保管・権限解除を分けて決めます。**自社に残したいものを全て返してもらえるとは限らず、契約や媒体・ツールの条件、利用目的と権限を確認します。

自社ATSに記録していても、外部に複製・添付や作業用データがないとは限りません。権限解除だけで返還・削除の確認が不要になる、という設計上の保証はありません。個別の取扱いは、情報管理や法務等の担当者と整理します。

## 返還・移管と削除・保管を同じ一覧で管理する

データを受け取ること、受取後に利用できること、相手側の複製を処理することは別の確認です。ただし別々に依頼して済ませるのではなく、対象ごとの一覧で関連付けると、何が未確認かを追えます。

| 確認する対象の例 | 照合する内容 |
|---|---|
| 候補者の情報と進行 | 必要な項目と利用目的、状態・最終連絡と次の担当 |
| 選考・スカウトの履歴 | 対象と日時、判断や承認の記録、利用・取得できる範囲 |
| 原稿・文面と手順 | 現行版と過去版、編集・再利用できる条件 |
| 検索条件や報告 | 条件・集計の定義、期間、引渡し対象と形式 |
| 環境と複製 | 保存場所、作業用ファイル、添付、連携・再委託先等 |
| 終了時の処理 | 受入確認、返還削除・保管の根拠と期限、権限解除 |

これは洗い出しの例で、全項目の無条件な取得権を示すものではありません。利用目的に不要な個人データ、媒体上でしか利用できない情報や第三者の権利を含む資料等は、取得・保管・再利用できるかを確認します。議事録や稼働報告も、頼まなければ出ないと決めず、契約の成果物・報告範囲と実際にある記録を照合します。

個人情報保護委員会の通則ガイドラインには、利用する必要がなくなった個人データの消去についての努力義務と、法令上の保存期間等がある場合の扱いが示されています。また、委託先の選定・契約・取扱状況の把握等による監督を説明しています。契約の終了日だけで、全データの保管可否や処理期限が一律に決まると扱いません。

## 保存先と利用条件を環境ごとに確かめる

自社ATS、媒体管理画面、外部の進捗管理ツール、メール、共有ドライブやチャット等を確認します。紙、端末への出力やダウンロード、バックアップ、外部連携・再委託先等があるかも、実際の構成を担当者へ確かめます。五つの場所を順に見れば漏れが防げる、という固定の一覧ではありません。

| 保存環境 | 主な確認事項 |
|---|---|
| 自社ATS等 | 記録がそろっているか、出力・連携先と外部の複製、解除する権限 |
| 求人・スカウト媒体 | 名義だけでなく規約、利用期限、閲覧・書出しと移管の可否 |
| 外部ツール | 引渡し対象と機能、形式・費用、保持期間と終了後の処理 |
| メール・共有環境 | 自社側にある範囲、外部の添付や保存、共有リンクと権限 |
| 複製・別の管理先 | 作業用や保存分の対象・処理、再委託先の確認と報告方法 |

自社名義なら維持する限り残る、外部名義なら終了時に全て失うと名義だけでは判断しません。保存期間、退会・利用停止と出力機能、権限や契約条件を確認します。書き出して別環境へ移すことも、機能と利用条件が認める範囲で検討します。

自社ドメインのメールなら全履歴が残るとも限りません。実際の共有方法と保存先、添付・転送の扱いを確かめます。必要な情報だけを扱い、新たな不要コピーを増やさない受渡し方法を決めます。

## 形式は取り込み先と受入確認から決める

CSVや表計算、文書等は選択肢ですが、全ツールでそのまま取り込めるとは限りません。項目の対応、文字コード、日付・状態の値、候補者や応募の識別、添付との関連等を、受入先の仕様と合わせて確認します。出力できる項目とできない項目、代替の記録方法も照合します。

画像しかないから全て使えない、文書なら編集できると形式名だけで決めません。利用目的に応じて、読めること、確認・検索できること、必要なら編集や取り込みができることを確かめます。検索条件の設計意図も、引渡しに含まれるかと記録の有無を確認します。

受入前に小さなサンプル等で確認する方法を相談し、件数・項目、現行版と更新時点、添付や履歴、進行中候補者の状態を照合します。不足・誤りを差し戻す担当、修正期限と追加費用の扱いを決めます。受け取ったという連絡と、内容が利用可能と確認したことは分けて記録します。

### エラベルの見解

仮に、CSVを受け取れても、応募者の状態や添付との関連が受入先と違っていたら、そのまま運用を再開できないかもしれません。形式を指定するだけでなく、どの項目がどの意味で渡り、何を確認したら受入完了とするかを合わせる必要があります。これは検討のための仮例で、実際の障害や改善実績ではありません。

「全データを返す」という言葉だけより、対象・条件と受入確認を一覧に残すことを勧めます。

## 削除・保管と権限解除を別に確認する

返還が必要な対象は、受入確認と処理の関係を決めます。ただし「受け取るまで全て残す」「終了日の前に全て削除」を共通の規則にはしません。不要なデータや保管が必要な記録等を、利用目的、法令・契約と媒体条件から担当者と分け、処理時期と実行・確認する人を決めます。

削除については対象環境と複製、方法、時期、報告内容と確認できる証跡を相談します。バックアップ等で処理に制約があるなら、対象と保持理由・期限、利用や復元の制限、処理後の報告を確認します。バックアップなら無期限に残せるという扱いにはしません。

報告以上の確認は現実に困難と一律に諦める必要はありません。対象データとリスク、契約や環境に応じ、記録・設定・証跡の確認や監査等、合理的に取扱状況を把握する方法を相談します。一枚の証明書だけで全保存先から完全に消えたことが証明できる、とも保証しません。

権限解除は、媒体ATSや共有環境のアカウント、共有リンク・連携等の実際の構成から対象を洗い出します。解除しても既に出力されたファイル等が消えるわけではなく、逆にファイルを削除してもアカウント権限がなくなるとは限りません。受渡しのため一時的に必要な権限と、その終了確認も決めます。

## 日程・費用と候補者対応を並行して決める

契約終了日、出力機能や閲覧の利用期限、移行先の準備と担当稼働から日程を組みます。依頼、サンプル確認、受渡しと受入・差戻し、削除や保管・権限解除の期限を、対象ごとに決めます。全処理が終了日前に終わると固定せず、終了後に必要な作業がある場合の権限・費用と連絡窓口も合意します。

進行中の候補者については、次の連絡と面接・判断待ち、承認者と不在代替を確認します。切替中に誰が案内し、状態をどこへ記録するかを決め、重複や連絡漏れを点検します。データ移行だけで候補者対応も引き継がれたと判断しません。

契約に定めがなければ、口頭を先にしなければ協力が得られないと考えず、必要な対象・形式・期限と根拠を記録に残して相談します。会話で調整した事項も書面等で確認します。争いがあれば契約と事実を整理して専門家へ相談し、自社環境にあるから無制限に回収・再利用できるとは扱いません。

### エラベルの見解

自社環境へ記録する設計は、確認や引継ぎを考える選択肢になりますが、返還条項や終了時の処理確認に代わるものではありません。置き場所と複製、利用条件、契約と運用を併せて整えます。整理すれば次の支援会社の提案が良くなると保証せず、何が現行で何が未確認かを正確に渡すことを重視します。

## 次の支援先には必要な範囲だけを渡す

移管先へ渡す情報は、委託する作業と利用目的に必要な項目へ絞り、共有権限と方法を決めます。現行・過去の版、項目や集計の意味、進行中の状態を整理しますが、全候補者データを一枚にまとめる必要はありません。管理しやすさだけで情報を増やさないようにします。

入力・管理やATS運用の支援と、返還・削除・保管の法的判断、旧委託先への請求や技術監査は分けて相談します。今回のツールで必要な作業ができるか、出力や移行の対応、受入確認と社内承認を個別に照合します。一般的な情報入力の案内だけで、全ツールの移行や削除証明まで含むとは推定しません。

対象件数・形式、修正や受入照合、稼働と追加費用・期間、成果物の利用、再委託と交代を確認します。次の委託で生じる作業用データも、処理と権限解除を決めます。切替全体は[引き継ぎ項目の記事](/media/rpo-hikitsugi/)も参照してください。

## まとめ

契約終了時は、データと成果物の一覧、保存先と複製、利用条件を確認します。受渡しと受入・差戻し、削除や保管、権限解除を対象ごとに決め、進行中候補者の対応と費用・終了後の窓口も合意します。自社ATSや媒体の名義だけで、処理が不要・利用可能と判断しないようにします。

## よくある質問

### 削除をどう確認しますか

対象と環境・方法を決め、報告と証跡、必要に応じた取扱状況の確認方法を相談します。報告以上の確認は不可能とも、証明書だけで完全削除を証明できるとも一律には言えません。

### 終了後に追加データが必要になったらどうしますか

保存状況と利用条件を担当者へ確認します。削除済みなら復旧できるとは限らず、削除報告だけで全保存先の状態も確定しません。終了前から対象と受入確認、終了後の窓口・作業条件を決めます。

### 媒体の候補者データは自社へ移せますか

媒体の契約・利用条件、出力項目と形式、移行先での利用目的と権限を個別に確認します。自社名義だから全データを移せる、アカウントを維持すれば常に残ると決めないようにします。

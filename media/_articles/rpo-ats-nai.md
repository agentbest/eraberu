応募者の管理は、人事のスプレッドシート。媒体ごとにシートが分かれ、面接官はメールで結果を返し、誰がどの段階かは人事の頭の中。連絡の漏れと重複が起き、責任者に「いま何人が選考中か」と聞かれても、すぐに答えられない。「ATSを入れるべきか」と思うが、費用と手間で決めきれない。結論を先に書くと、**応募者管理の問題は、道具（スプレッドシートかATSか）の問題ではなく、「一つの表」「列」「更新の担当」の三つが無いことの問題です。三つを決めれば、スプレッドシートでも回ります。三つが無ければ、ATSを入れても回りません。まず三つを決めて回し、応募の数と媒体の数が増えたら、ATSへの移行を判断します**。ATSの選び方は[ATSの選び方](/media/rpo-ats-erabikata/)に、入れたが使えていない場合は[ATSを入れたが使いこなせていない](/media/rpo-ats-tsukaikonasenai/)にまとめています。

## スプレッドシート管理で起きていること

スプレッドシートや紙や記憶で応募者を管理している会社では、次のことが起きています。

| 起きていること | 背景 |
|---|---|
| 誰がどの段階か分からない | 表が無い、または更新されていない。人事の記憶が頼り |
| 連絡の漏れ | 「結果を伝えたつもり」「案内したつもり」。記録が無いので確認できない |
| 連絡の重複 | 同じ候補者に、人事と面接官が別々に連絡する |
| 媒体ごとに表が分かれている | 全体が見えない。同じ候補者が複数の媒体から応募していても気づかない |
| 面接官の判定が、メールに埋もれる | 判定がメールで来て、表に転記されず、探す |
| 「いま何人が選考中か」に答えられない | 表が更新されていないか、集計できる形になっていない |
| 人事が休むと、止まる | 表の場所も、更新の仕方も、人事しか知らない |
| 過去の応募者が探せない | 前回の募集の応募者が、どこにあるか分からない。再応募に気づかない |

問題は、「スプレッドシートだから」ではなく、「一つの表が無く、列が決まっておらず、更新する人がいない」ことです。ATSを入れても、三つが無ければ同じことが起きます。

## 道具より先に決める三つ

道具を変える前に、三つを決めます。

**一、一つの表。** 媒体ごと、職種ごとに分けず、全部の応募者を一つの表に入れます。「媒体」「職種」は列で持ちます。一つの表なら、全体が見え、重複に気づけます。

**二、列。** 表の列を決めます（次の章）。列が決まっていれば、誰が更新しても同じ形になります。列が決まっていないと、人によって書く内容が違い、集計できません。

**三、更新の担当。** 表を更新する人を、一人決めます。応募が来たら、判定が出たら、連絡したら、その日に更新する。更新の担当がいなければ、表は古くなり、信用されなくなります。

三つが決まれば、スプレッドシートでも、ATSでも、回ります。三つが決まっていなければ、どちらでも回りません。

「一つの表」は、スプレッドシートで作れます。費用はかかりません。今日、作れます。

## 一つの表の列の型

表の列の型です。最小の列から始め、足りなければ足します。

| 列 | 内容 | 目的 |
|---|---|---|
| 応募日 | 応募が届いた日 | 待たせている日数を見る |
| 経路 | 媒体名、紹介会社名、社員の紹介、直接 | 経路ごとの効きを見る |
| 職種 | 応募した求人 | 求人ごとの進み具合を見る |
| 氏名 | 候補者の名前 | 重複の確認 |
| 段階 | 応募・書類・一次・二次・最終・内定・入社・辞退・不合格 | いま何人がどこにいるか |
| 受付の返信日 | 受付の返信を出した日 | 「待たせない」の確認 |
| 書類の判断日と結果 | 判断した日と、通す・通さない | 判断の速さと結果 |
| 面接の日程 | 各段階の面接日 | 日程の管理 |
| 面接の判定と根拠 | 段階ごとの判定と、根拠の一〜二行（または記録へのリンク） | 判定の記録 |
| 結果の連絡日 | 各段階の結果を伝えた日 | 連絡の漏れの確認（空欄＝未連絡） |
| 次の予定 | 次に何を、いつまでに | 止まっている候補者の発見 |
| 担当 | この候補者の対応の担当者 | 誰が動くか |
| 辞退・不合格の理由 | 辞退なら理由、不合格なら要件に対する理由 | 振り返りの材料 |
| 備考 | 特記事項 | |

列の要点は、「日付の列」です。受付の返信日、判断日、連絡日。日付の列の空欄が、「未対応」の印になり、放置を防ぎます。

個人情報が入る表なので、アクセスできる人を限定し、社内の規程と法令に沿って管理します。扱いは専門家に確認します。

## 運用の型

表を回す運用です。

**応募が来た日に、行を足す。** 応募日・経路・職種・氏名・段階（応募）・受付の返信日。毎朝の応募の確認とセットで。運用は[応募を放置してしまう](/media/rpo-oubo-houchi/)に書いています。

**判定が出た日に、更新する。** 面接官から判定が来たら、その日に段階と判定と根拠を更新します。面接官がメールで返す形なら、担当者が転記します。面接官が直接書く形なら、書く列と書き方を面接官に渡します。

**連絡した日に、連絡日を入れる。** 結果を伝えたら、その日に。空欄が残っていれば、未連絡です。

**週に一度、空欄と「次の予定」を確認する。** 受付の返信日が空欄、判断日が空欄、連絡日が空欄、次の予定が過ぎている。止まっている候補者を見つけて、動かします。

**月に一度、集計する。** 経路ごとの応募・面接・内定の数、段階ごとの人数、応募から返信までの日数、辞退と不合格の理由の内訳。責任者への報告の材料になります。集計の見方は[採用の数字が取れていない](/media/rpo-data-nai/)に書いています。

**募集が終わった求人の行は、別の表（または別のシート）に移す。** 今の表は、動いている候補者だけ。過去の応募者は、再応募の確認と振り返りのために、別に残します。保存の期間は社内の規程と法令に沿います。

**表の場所と更新の手順を、書面にする。** 更新の担当が休んでも、代わりの人が回せるように。

運用の要点は、「その日に更新する」ことです。「後でまとめて」は、表を古くし、信用を失わせます。

### エラベルの見解

相談で最も多い失敗は、「応募者管理がスプレッドシートで回らないので、ATSを入れた。ただ、誰が更新するかを決めておらず、ATSも三か月で古くなり、結局スプレッドシートに戻った」というものです。道具を変えても、更新の担当と列と運用が無ければ、同じことが起きます。逆に、一つの表と列と更新の担当を決めたら、スプレッドシートのまま一年回りました。ATSに移ったのは、応募が月に数十件を超えて、表の更新が追いつかなくなってからでした。

見ていて差がつくのは、担当者が「道具の提案」より先に「表の運用」を作るかどうかです。「ATSを入れましょう」から始める担当者と、「まず一つの表に列を決めて、私が毎日更新します。ATSは応募の数を見てから判断しましょう」と、運用から始める担当者がいます。後者は、道具に頼らず回します。

発注側にできるのは、「ATSを入れるべきか」の前に、「一つの表と更新の担当があるか」を確認することです。

## ATSに移る判断の目安

スプレッドシートからATSに移る判断の目安です。

| 目安 | 中身 |
|---|---|
| 応募の数 | 月に数十件を超え、表の更新に毎日一時間以上かかる |
| 媒体の数 | 三つ以上の媒体から応募が来て、管理画面を回る手間が大きい |
| 関わる人の数 | 面接官が五人以上で、判定の転記が追いつかない。面接官が直接入力する形が要る |
| 求人の数 | 同時に動く求人が五本以上 |
| 連絡の型の数 | 受付、案内、結果、内定、不合格の文面を、候補者ごとに手で送るのが限界 |
| 集計の頻度 | 月に一度の集計を手で行うのが限界。経路や段階の集計を自動で出したい |
| 個人情報の管理 | スプレッドシートのアクセスの管理が不十分。権限の設定が要る |
| 過去の応募者の検索 | 過去の応募者を、条件で探したい |

目安の複数に当てはまれば、ATSを検討します。当てはまらなければ、スプレッドシートで足ります。

ATSは、費用と、導入の手間と、使い方を覚える時間がかかります。「一つの表と列と更新の担当」が回っている状態で移れば、ATSは表の代わりとして機能します。回っていない状態で移れば、使われないATSになります。選び方は[ATSの選び方](/media/rpo-ats-erabikata/)に書いています。

## 移るときの手順

ATSに移ると決めたときの手順です。

**いまの表の列を、ATSの項目に対応させる。** 表の列が、ATSのどの項目に入るかを決めます。対応しない列があれば、ATSの自由項目か、備考に。

**動いている候補者を、移す。** 過去の応募者を全部移す必要はありません。動いている候補者と、直近の募集の応募者。過去の分は、スプレッドシートを保管します。

**更新の担当を、そのまま引き継ぐ。** 表の更新の担当が、ATSの更新の担当に。ATSに変わっても、「その日に更新する」は同じです。

**面接官に、判定の入力の仕方を渡す。** ATSで面接官が直接判定を入力する形なら、入力の画面と、書く内容（観点ごとの判定と根拠）を、一枚で渡します。

**媒体との連携を設定する。** 媒体からの応募がATSに自動で入る設定。設定は各媒体とATSの公式の案内で確認します。

**連絡の文面の型を、ATSに登録する。** 受付、案内、結果、内定、不合格の文面を、ATSのテンプレートに。

**一か月、スプレッドシートと並行する。** ATSの運用が回っているかを確認しながら。回っていれば、スプレッドシートを止めます。

**個人情報の扱いを、ATSの設定で確認する。** アクセスの権限、保存の期間、削除の手順。社内の規程と法令に沿い、専門家に確認します。

移行の要点は、「運用は変えず、道具だけ変える」ことです。運用が変わると、面接官も担当者も混乱します。

## 外注する場合の範囲

応募者管理の問題を、採用代行に出す場合の範囲です。

**出せる工程。** 一つの表の設計（列の型）、表の作成、毎日の更新（応募・判定・連絡）、週に一度の空欄の確認、月に一度の集計と報告、表の場所と手順の書面化、面接官への判定の書き方の共有、ATSに移る判断の材料、ATSの選定の支援、移行の手順の設計と実行、媒体との連携の設定の支援、連絡の文面の型の登録、個人情報の扱いの手順の整理（専門家の確認を経て）。

**社内に残す判断。** 列の決定（何を記録するか）、更新の担当の指名（社内の場合）、ATSに移るかどうかの決定、ATSの選定と費用、個人情報の扱いの方針（専門家との連携）、アクセスできる人の決定。

**外注の効きどころ。** 応募者管理の問題は、「更新する人がいない」ことが根本です。担当者が更新の担当になり、表を毎日更新し、空欄を確認し、集計を出せば、表は信用される表になります。ATSへの移行も、運用が回っている状態で担当者が進めれば、使われるATSになります。

**外注しても動かない場合。** 面接官が判定を出さない、社内がアクセスの権限を決めない、責任者が表を見ない。社内の判断で、代行を替えても直りません。

応募者管理は、道具ではなく運用です。外注は、運用を回す人を置く手段です。

### エラベルの見解

担当する側から見ると、応募者管理の相談で最も多いのは、「表が三つも四つもある」ことです。媒体ごとの表、職種ごとの表、面接官が個人で持っている表。全部を見ないと全体が分からず、誰も全部を見ていません。

一つの表にまとめるだけで、「いま何人が選考中か」に即答でき、重複と漏れが見え、集計ができます。表を作る時間は、一時間です。ATSより先に、一つの表です。

発注側にできるのは、社内にある応募者の表を全部集めて、一つにすることを、今日決めることです。

## まとめ

- 起きているのは**段階が分からない・漏れ・重複・媒体ごとに表が分かれる・判定がメールに埋もれる・即答できない・人事が休むと止まる・過去が探せない**
- 道具より先に**一つの表・列・更新の担当**の三つ。三つが無ければATSでも回らない
- 列は**応募日・経路・職種・氏名・段階・受付の返信日・判断日と結果・面接の日程・判定と根拠・連絡日・次の予定・担当・理由・備考**。日付の列の空欄が未対応の印。個人情報の扱いは専門家に確認
- 運用は**応募の日に行を足す・判定の日に更新・連絡の日に連絡日・週に一度の空欄と次の予定・月に一度の集計・終わった求人は別に・場所と手順を書面に**。その日に更新
- ATSに移る目安は**応募が月に数十件超・媒体三つ以上・面接官五人以上・求人五本以上・連絡の型が手で限界・集計が手で限界・権限の管理・過去の検索**
- 移る手順は**列を項目に対応・動いている候補者だけ移す・担当を引き継ぐ・面接官に入力の仕方・媒体との連携・文面の登録・一か月並行・個人情報の設定**。運用は変えず道具だけ
- 外注できるのは**表の設計と作成・毎日の更新・空欄・集計・書面化・面接官への共有・移行の判断と実行・連携・登録・手順**。社内に残るのは**列の決定・担当の指名・移行の決定・選定と費用・個人情報の方針・権限**

## よくある質問

### スプレッドシートのままで、本当に大丈夫ですか

一つの表に列を決め、更新の担当がその日に更新する運用が回っていれば、応募が月に数十件までなら足ります。問題は道具ではなく、表が複数ある、列が決まっていない、更新する人がいない、の三つです。三つを決めれば、スプレッドシートで回ります。応募の数、媒体の数、面接官の数が増えて、表の更新が追いつかなくなったら、ATSを検討します。

### ATSを入れれば、管理の問題は解決しますか

「一つの表・列・更新の担当」が無いままATSを入れると、更新されないATSになり、三か月で使われなくなります。ATSは表の代わりで、運用の代わりではありません。先にスプレッドシートで運用を回し、回っている状態でATSに移れば、ATSは機能します。ATSの選び方は[ATSの選び方](/media/rpo-ats-erabikata/)に、入れたが使えていない場合は[ATSを入れたが使いこなせていない](/media/rpo-ats-tsukaikonasenai/)に書いています。

### 面接官がメールで判定を返してきて、表に転記するのが大変です

更新の担当が転記する形か、面接官が直接表に書く形か、どちらかに決めます。面接官が直接書くなら、書く列（段階の判定と根拠）と書き方を一枚で渡し、面接の直後に五分で書く型にします。転記する形なら、面接官からのメールの型（観点ごとの判定と根拠を決まった形で）を決め、転記を速くします。面接官が五人以上で転記が追いつかないなら、ATSで面接官が直接入力する形を検討します。

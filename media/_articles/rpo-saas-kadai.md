SaaS業界の会社が「人が採れない」と言うとき、その言葉には五つの違う問題が混ざっています。要件に事業の段階が無く、前の段階の会社で活躍した人が来て合わない。営業もCSもエンジニアも同時に始めて、経営者の面接の枠が奪い合いになる。条件の比較が速い業界で、幅を先に出していない。「SaaSだから」の訴求で他社との差が出ていない。採った後の受け入れの型が無く、早期に離れる。どれが原因かで、直す場所も、外に出せるかも変わります。結論を先に書くと、**SaaS業界の採用課題は、段階・優先順位・条件と速さ・差の出し方・受け入れの五つに分解し、自社の記録（書類と面接の一致、面接の枠の待ち人数、辞退の理由、返信の数、早期離職の時期）で詰まりを一つに特定してから直します。**「人が採れない」を一つの問題として扱うと、媒体と代行を足す施策に費用を使い、面接の枠で詰まって候補者が流れる、という結果になります。代行に出す工程の切り分けは[SaaS業界の採用代行](/media/rpo-saas-rpo/)に、IT・Web業界との違いは[IT・Web業界の採用課題](/media/rpo-it-kadai/)に書いています。ここでは、SaaS業界の課題を分解する順番に絞ります。

## 「採れない」に混ざっている五つ

| 課題 | 現れ方 | 記録で見えること |
|---|---|---|
| 段階 | 面接で「前の会社のやり方と違う」。入社後に「型が無い」か「型で退屈」 | 書類で○の人が面接で通らない。早期離職の理由が「仕事の中身」 |
| 優先順位 | 全職種を同時に始め、どれも遅い。経営者の面接の枠が埋まる | 段階ごとの日数。面接の待ち人数 |
| 条件と速さ | 面談前に離脱。「他社に決まった」 | 辞退の理由が「条件」「速さ」 |
| 差の出し方 | スカウトの返信が来ない。面接で「他社と何が違うのか」 | 返信の数。面接での質問 |
| 受け入れ | 採れたが、三か月で離れる | 早期離職の時期と理由 |

五つは同時に起きることもありますが、直すのは一つずつです。

## 分解の順番

| 順 | 見ること | 判断 |
|---|---|---|
| 一 | 面接の枠の待ち人数と、段階ごとの日数 | 詰まっていれば優先順位。全職種を同時に始めていないか |
| 二 | 書類の○と面接の一致 | ○が面接で通らないなら段階（要件に段階が無い） |
| 三 | 辞退の理由 | 「条件」「速さ」なら条件と速さ |
| 四 | 返信の数と、面接での「他社との違い」の質問 | 少なければ差の出し方 |
| 五 | 早期離職の時期と理由 | 三か月以内が多ければ受け入れ |

一から五を順に見ると、詰まりは一か所に絞れます。SaaSでは一（優先順位）が最初に詰まることが多い。ファネルの並べ方は[採用ファネルのどこが詰まっているか分からない](/media/rpo-funnel/)に書いています。

### エラベルの見解

SaaS業界で最も多い詰まりは「優先順位」です。資金の調達や事業の拡大で「営業を五人、CSを三人、エンジニアを二人」と同時に始め、経営者と数人の責任者が全部の面接に出て、日程が三週間先になり、候補者は他社で決まる。応募が足りないのではなく、面接の枠が足りない。直し方は、採用計画の一枚で職種の優先を決め、優先の一職種の型（要件・文面・日程・記録）を作ってから、次の職種に広げること。一つの型ができれば、次の職種は速い。エラベルで担当者を選ぶ企業には、「いま同時に動かしている職種は何種類で、経営者の面接の枠は週にいくつですか」を、私たちから先に聞いています。職種の数が枠の数を超えていれば、直すのは経路ではなく優先順位です。計画の作り方は[採用計画の設計の進め方](/media/rpo-task-saiyo-keikaku-susumekata/)に書いています。

## 段階の課題：要件に事業の段階が無い

| 段階 | 要る人 | 要件の言葉 |
|---|---|---|
| 立ち上げ | 決まりの無いことを自分で決めて進める人 | 「型が無い環境で、〇〇を自分で設計して回した経験」 |
| 拡大 | 型を回して数を出す人。型を人に渡せる人 | 「決まった型で〇〇を回し、数を出した経験。後から入る人に型を渡した経験」 |
| 安定 | 仕組みを作り、複数のチームを動かす人 | 「〇〇の仕組みを作り、複数のチームに広げた経験」 |

同じ「営業」でも、段階で要件は逆になります。要件に「いまの段階で、最初の三か月に何をしてもらうか」を書くと、検索も文面も面接も揃います。要件の作り方は[採用要件の定義の進め方](/media/rpo-task-youken-teigi-susumekata/)に書いています。

## 優先順位の課題：全職種を同時に始める

| 状態 | 直し方 |
|---|---|
| 全職種を同時に募集 | 採用計画の一枚で優先を決め、一職種から |
| 経営者が全職種の面接に出る | 職種ごとの責任者に見極めを分け、経営者は最終だけ。枠を週に決まった数で預ける |
| 面接の待ち人数が増える | 枠を超える応募を集めない。母集団の目標を枠に合わせる |
| 責任者がいない職種を先に募集 | 責任者を先に採るか、その職種を後に |

優先順位は、費用がかからず、今日から変えられる課題です。枠の預かり方は[面接の日程調整の進め方](/media/rpo-task-nittei-chousei-susumekata/)に書いています。

## 条件と速さの課題：比較が速い業界

| 遅れる場所 | 直し方 |
|---|---|
| 条件の幅を面接まで出さない | スカウトの文面か初回の連絡で幅を。額は面談で |
| 日程の確定が数日 | 枠を先に預かり、候補を三つ以上、確定を即日 |
| 内定の判断が遅い | 決める人を一人に |
| 内定後に静か | 接点を先に設計 |

SaaS業界の候補者は、同時に複数のSaaSの会社を見ています。幅と速さで後回しにされると、他社で決まります。条件の出し方は[スカウト段階で条件を出すか](/media/scout-kyuuyo-teiji/)に書いています。

### エラベルの見解

SaaS業界で見落とされやすいのは「差の出し方」です。「急成長中」「裁量が大きい」「フラットな組織」は、SaaSの会社のほとんどが書いていて、候補者には差に見えません。差になるのは、「いまの段階で、この役割が、最初の三か月に何をするか」「一緒に働く人は誰で、何をしているか」「いまうまくやっている人が、前の会社と違うと感じていること」の実態です。エラベルで担当者を選ぶ企業には、「御社のスカウト文面と求人票から『急成長』『裁量』『フラット』を消したら、何が残りますか」を、私たちから先に聞いています。残るものが差で、残らなければ、いまうまくやっている人に「前の会社と違うこと」を聞くところからです。差の出し方は[自社紹介はどこまで書くか](/media/scout-kaisha-shoukai/)に書いています。

## 差の出し方の課題：「SaaSだから」では差にならない

| 差にならない言葉 | 差になる実態 |
|---|---|
| 「急成長中」 | 「いまの段階で、この役割は〇〇を自分で決めて進める」 |
| 「裁量が大きい」 | 「入社二か月目から〇〇の判断を任せている」（実績があるものだけ） |
| 「フラットな組織」 | 「一緒に働く人は〇〇と〇〇で、週に〇〇の場で判断を合わせている」 |
| 「事業が伸びている」 | 「〇〇の業界の顧客に、〇〇の課題を解いている」 |

実態の言葉は、いまうまくやっている人の「前の会社と違うこと」から起こします。求人票の書き方は[求人原稿の作成の進め方](/media/rpo-task-kyujin-genko-susumekata/)に書いています。

## 受け入れの課題：型が無く早期に離れる

| 状態 | 直し方 |
|---|---|
| 入社した日から「自分で考えて」 | 立ち上げの段階でも、最初の三か月の到達点と、毎日短く話す担当を決める |
| 面接で聞いた役割と入社後の仕事が違う | 面接で渡した「最初の三か月」を、入社後の計画にそのまま |
| 段階が変わって役割が変わった | 変わったことを本人に伝え、役割を決め直す |
| 早期離職の理由を見ていない | 退職面談の記録から、求人票のずれか受け入れの問題かを分ける |

SaaSでは事業の段階が速く変わり、入社時の役割が半年で変わることがあります。変化を伝える接点が無いと、「聞いていた話と違う」で離れます。受け入れの型は[入社後のオンボーディングの進め方](/media/rpo-task-onboarding-susumekata/)に、早期離職の分け方は[早期離職が続くのは採用のどの段階の問題か](/media/rpo-souki-rishoku/)に書いています。

## 外に出せる部分と社内で直す部分

| 課題 | 外に出せる部分 | 社内で直す部分 |
|---|---|---|
| 段階 | 「経歴で読める言葉」に整える作業 | 段階と、最初の三か月の中身を決める |
| 優先順位 | 一覧と日程の運用 | 職種の優先を決める。責任者を置く |
| 条件と速さ | 一次対応、日程の確定 | 条件の幅を出す判断。枠を出す |
| 差の出し方 | 文面と求人票に落とす作業 | 実態を語る（いまうまくやっている人） |
| 受け入れ | 受け入れの型の設計 | 担当と時間 |

どの課題にも社内で直す部分があります。機能する条件と機能しない条件は[SaaS業界で採用代行が機能する条件・機能しない条件](/media/rpo-saas-jirei/)に書いています。

## まとめ

- 「採れない」には**段階・優先順位・条件と速さ・差の出し方・受け入れ**の五つが混ざっている
- **記録で一つに特定してから直す**。面接の枠の待ち→書類と面接の一致→辞退の理由→返信と質問→早期離職の順
- 最も多い詰まりは**優先順位**。全職種を同時に始めない。一職種の型を作ってから広げる
- 要件に**事業の段階**を入れる。同じ職種でも段階で要件は逆になる
- **条件の幅を先に、確定を即日に**。比較が速い業界
- 「急成長」「裁量」「フラット」は差にならない。**実態の言葉**で
- 受け入れは**最初の三か月の到達点と担当**。段階の変化を伝える接点

## よくある質問

### 資金を調達して、半年で二桁の採用が要ります

人数が多いほど、優先順位と型が要ります。全職種を同時に始めず、最初の一職種で型（要件・文面・日程・記録）を一か月で作り、二職種目からは型を写して速く回す。経営者の面接の枠を週に決まった数で預け、責任者ごとに見極めを分ける。それでも枠が足りなければ、採る数の計画そのものを、枠から逆算して依頼側が見直します。急成長の段階の体制は[急成長フェーズの会社の採用体制の作り方](/media/rpo-kyuu-seichou-taisei/)に書いています。

### 候補者が「他社のSaaSからも内定が出ている」と言い、条件で負けます

条件だけで比べられている状態は、差が実態の言葉で出ていないことが多い。迷いの中身（役割、段階、一緒に働く人）に答えられていれば、同じ条件でも決まることがあります。条件を上げるかは会社の判断で、上げる前に「迷いに答え切ったか」を面接の記録で確かめます。条件と迷いの分け方は[内定辞退が続くときに見直す3点](/media/rpo-jitai-ooi/)に書いています。

### 段階が変わって、去年採った人の役割が合わなくなりました

段階の変化は、SaaSでは避けられません。変化を本人に伝え、新しい段階での役割を決め直す接点（月次の1on1、四半期の役割の確認）があれば、離れずに済むことがあります。伝えずに役割だけが変わると、「聞いていた話と違う」になります。段階が変わるたびに、要件の一枚と求人票も更新し、次に採る人には新しい段階を伝えます。

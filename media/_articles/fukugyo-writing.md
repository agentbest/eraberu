スカウトの文面、候補者への返信、依頼側への報告。副業では、書く場面が本業より多い。書くのに時間がかかり、書いても返信が来なかったり、依頼側から「要点が分からない」と言われたりする。文章力を磨きたいが、何をすればよいのか。結論を先に書くと、**人事の副業で要る文章力は、上手な文章を書く力ではなく、「相手が読んだ後に、次に何をすればよいかが分かる文章」を書く力です。スカウト、候補者への返信、依頼側への報告の三つの場面で、相手が次にすることは違い、型も違います。磨き方は、「場面ごとの型を持つ」「一文を短くする」「送る前に相手の立場で読む」「返ってきた反応で直す」の四つで、文章の技術を学ぶより、送った文章の反応を見て直すことが、最も早く効きます。**依頼側への連絡の型は[メールの書き方と運用](/media/fukugyo-mail/)に、報告の書き方は[報告のしかた](/media/fukugyo-houkoku/)に、資料の作り方は[資料の作り方](/media/fukugyo-shiryou/)にまとめています。

## 副業で文章が要る三つの場面

副業で書く文章は、三つの場面に分かれ、それぞれで相手と目的が違います。

| 場面 | 相手 | 相手が次にすること | 文章の目的 |
|---|---|---|---|
| スカウトの文面 | 候補者（初めて接する人） | 返信するか、無視するか | 「自分に関係がある」と数秒で分かり、返信の負担が小さいこと |
| 候補者への返信・連絡 | 候補者（やり取りが始まった人） | 日程を答える、質問に答える、次の選考に進む | 何を答えればよいかが一目で分かり、待たせないこと |
| 依頼側への報告・連絡 | 依頼側の担当者 | 社内に伝える、判断する、返事をする | 担当者が上長に一言で言え、判断が要ることが分かること |

三つの要点は、「相手が次にすることが違うので、同じ書き方では通じない」ことです。スカウトは、読む気の無い相手に数秒で関係を伝える文章で、報告は、忙しい担当者が上長に使える文章です。スカウトの書き方で報告を書けば長く、報告の書き方でスカウトを書けば冷たくなります。場面ごとに型を分けます。スカウトの文面の構造は[事例を流用しない](/media/fukugyo-jirei-ryuuyou/)の「構造だけを持ち込む」に、報告の型は[稼働報告のフォーマット](/media/fukugyo-kadou-houkoku/)に書いています。

## 上手な文章が要らない理由

文章力と聞くと、表現の豊かさや読みやすい文体を思い浮かべますが、副業ではそれは要りません。

| 上手な文章を目指すと | 何が起きるか |
|---|---|
| 表現を工夫する | 書くのに時間がかかり、副業の枠を圧迫する |
| 丁寧にしようと長くなる | 候補者は読まず、担当者は要点を探す |
| 自分らしさを出そうとする | スカウトでは候補者に関係の無い話が増え、報告では担当者が社内で使いにくくなる |
| 文体を整える | 整えても、相手が次に何をすればよいか分からなければ、返信も判断も来ない |
| 一度で完璧にしようとする | 送るのが遅れる。反応を見て直す機会を失う |

要らない理由の要点は、「副業の文章は、読まれて終わりではなく、相手の行動で結果が決まる」ことです。スカウトは返信が来るか、候補者は日程を答えるか、担当者は判断するか。文章の良し悪しは、相手の行動で分かり、表現の良し悪しでは分かりません。上手さより、相手が次にすることが分かるかで、文章を見ます。

### エラベルの見解

相談で最も多い思い込みは、「文章が苦手だから、スカウトの文面や報告は向いていない」というものです。実際には、依頼側から「文面が良い」「報告が分かりやすい」と評価されている担当者の文章を見ると、表現が上手いわけではありません。共通しているのは、一文が短く、相手が次にすることが冒頭で分かり、余計なことが書かれていないことです。文章が苦手だと感じている人は、多くの場合、上手に書こうとして長くなり、結果として伝わっていません。

見ていて差がつくのは、送った文章の反応を見て、直しているかです。スカウトなら返信の割合、候補者への連絡なら返答までの時間と問い合わせの数、報告なら担当者からの聞き返しの回数。これらを見て、冒頭を変える、一文を削る、判断が要ることを先に書く、と直している人の文章は、数か月で見違えます。反応を見ずに、書き方の本を読んで直そうとしている人は、変わりません。エラベルでは、担当者の文面や報告について、依頼側の反応を見て直す形をお願いしています。文章力は、書く前に磨くものではなく、送った後の反応で磨くものです。

## 四つの磨き方

文章力を磨く四つの方法です。どれも、副業の枠の中でできます。

| 磨き方 | 内容 | 要点 |
|---|---|---|
| 一、場面ごとの型を持つ | スカウト、候補者への連絡、報告の三つで、型（構造と順番）を持つ。毎回一から書かず、型に当てはめる | 型は自分の側に構造だけを持ち、中身は案件ごとに埋める |
| 二、一文を短くする | 一文に一つのことだけ。読点で長くつながない。「〜ですが、〜で、〜なので」を切る | 書いた後、読点が二つ以上ある文を切る |
| 三、送る前に相手の立場で読む | 送る前に一度、相手（候補者、担当者）になったつもりで読み、「次に何をすればよいか分かるか」を見る | 分からなければ、冒頭に次にすることを書く |
| 四、返ってきた反応で直す | 返信の割合、返答までの時間、聞き返しの回数を見て、型の一部を一つ変える | 月に一つ。改善の回し方と同じ。[改善を回す](/media/fukugyo-kaizen/) |

四つの要点は、「三」の送る前に相手の立場で読むことです。書いた直後は、自分の意図で読んでしまい、相手がどう受け取るかが見えません。一度、相手になって読み、「これを受け取った自分は、次に何をすればよいか分かるか」を確かめる。分からなければ、冒頭に「〇日までにご返答ください」「ご判断をお願いします」のように、次にすることを置きます。この一手間が、文章の結果を最も変えます。

## 送る前の読み直しの型

「三」の、送る前の読み直しを、型にしておきます。三つの場面で、確かめることが違います。

| 場面 | 確かめること | 直し方 |
|---|---|---|
| スカウト | 冒頭の数行で、候補者が「自分に関係がある」と分かるか。返信の負担が小さいか（「ご興味があれば一言で構いません」のような一文があるか） | 冒頭が会社の説明なら、候補者の経歴との接点を冒頭に。返信の負担を下げる一文を結びに |
| 候補者への連絡 | 何を答えればよいかが一目で分かるか。答える期限があるか。候補者を待たせる部分に「〇日までにご連絡します」があるか | 質問が複数なら箇条書きに。期限が無ければ足す |
| 依頼側への報告 | 冒頭に、担当者が上長に言える一文があるか。判断が要ることが分けて書かれているか。長さは画面をスクロールせずに読めるか | 冒頭に一つの数字を比較で。「確認したいこと」を分ける。[数字で語る](/media/fukugyo-suuji/) |
| 全部 | 一文に読点が二つ以上無いか。同じことを二度言っていないか。相手が知らない言葉（社内の略語、自分の案件の用語）が無いか | 切る、削る、言い換える |

読み直しの要点は、「確かめることを場面ごとに決めておく」ことです。「良い文章か」と漠然と読み直しても、直す場所は見つかりません。「冒頭で関係が分かるか」「次にすることが分かるか」「上長に言える一文があるか」と、確かめることが決まっていれば、直す場所がすぐ見つかります。候補者への連絡の注意は[候補者への対応で気をつけること](/media/fukugyo-kouhosha-taiou/)に整理しています。

## 反応で直す仕組み

「四」の、反応で直す仕組みです。改善を回す形と同じで、月に一つ変えます。

| 場面 | 見る反応 | 直す候補 |
|---|---|---|
| スカウト | 送信に対する返信の割合、返信の内容（断りか、質問か、前向きか） | 冒頭の接点の書き方、結びの返信の負担、長さ、送る時間帯 |
| 候補者への連絡 | 返答までの時間、候補者からの問い合わせ（「どういう意味ですか」「いつまでですか」）の数 | 質問の並べ方、期限の明示、待たせる部分の見込みの伝え方 |
| 依頼側への報告 | 担当者からの聞き返し（「これはどういうことですか」「で、どうなんですか」）の回数、上長に使ったと言われたか | 冒頭の一文、判断が要ることの分け方、長さ |
| 全部 | 「分かりにくい」と言われた回数 | 一文の長さ、言葉の選び方 |

仕組みの要点は、「候補者からの問い合わせと、担当者からの聞き返しを、文章の反応として数える」ことです。「どういう意味ですか」「いつまでですか」と聞かれるのは、文章にその答えが無かったからで、直す場所を教えてくれています。聞かれた内容を、次から文章に入れる。この繰り返しで、聞かれる回数は減り、文章は相手に合っていきます。反応の記録の付け方は[稼働ログの付け方](/media/fukugyo-log/)の判断のメモと同じで足ります。

## 文章が長くなる癖の直し方

文章が伝わらない原因の多くは、長さです。長くなる癖と、直し方です。

| 癖 | なぜ長くなるか | 直し方 |
|---|---|---|
| 前置きが長い | 「お世話になっております。先日は〜」から本題まで数行 | 前置きは一行。本題を二行目に |
| 理由を全部書く | 「〜という理由で、〜という背景があり、〜なので」 | 理由は一つ。詳しい理由は聞かれたら |
| 丁寧にしようと言葉を足す | 「〜させていただければと存じます」 | 「〜します」で足りる場面が多い |
| 同じことを言い換えて繰り返す | 念のため、別の言葉でもう一度 | 一度で足りる。繰り返さない |
| 全部の情報を入れる | 関係あるかもしれないことを全部 | 相手が次にすることに関係ある情報だけ |
| 一文に複数のことを入れる | 「〜ですが、〜で、〜なので、〜です」 | 読点二つで切る |
| 謝罪や断りが長い | 「大変申し訳ございませんが〜」が続く | 謝罪は一言。断りは「できないこと→できること」の形で。[無理なときの伝え方](/media/fukugyo-warukunai-kotowari/) |

直し方の要点は、「相手が次にすることに関係ある情報だけを残す」ことです。書いた文章を読み直し、各文に「これは相手が次にすることに要るか」と問い、要らなければ削る。削った結果、短くなった文章のほうが、相手には親切です。長い文章は丁寧に見えますが、相手の時間を使います。

## 候補者への文章で気をつけること

三つの場面のうち、候補者への文章は、依頼側の印象に直結するので、特に気をつけることがあります。

| 気をつけること | 内容 |
|---|---|
| 依頼側の代表として読まれる | 候補者は、自分の文章を「その会社からの連絡」として読む。自分の言い回しではなく、依頼側の言い方に合わせる。[会社の代表として話す責任](/media/fukugyo-kaisha-daihyou/) |
| 約束にならない書き方 | 「〇〇の条件です」「〇日に結果をお伝えします」は、依頼側の判断が要ることなら、「確認してご連絡します」に。[権限がないと動けない場面](/media/fukugyo-kengen-nai/) |
| 断りの文章は短く丁寧に | 不合格や辞退の受理の連絡は、理由を書かず、短く、丁寧に。長い理由は候補者を傷つけることがある |
| 候補者の情報を文章に書かない | 別の候補者の話、依頼側の社内の事情を、候補者への文章に入れない。[個人情報の扱い](/media/fukugyo-kojin-jouhou/) |
| 待たせるときは見込みを書く | 「確認中です」ではなく「〇日までにご連絡します」。候補者が予定を組める |
| 型は使うが、宛名と接点は毎回変える | 候補者は、型で送られたことに気づく。宛名と、その候補者の経歴との接点だけは、毎回書く |

候補者への要点は、「依頼側の代表として読まれる」ことです。自分の文章の丁寧さや速さが、候補者にとっては「その会社の丁寧さと速さ」です。依頼側の採用の印象を、自分の文章が作っています。だから、候補者への文章は、依頼側の言い方に合わせ、約束にならず、短く丁寧に、待たせるときは見込みを書きます。

### エラベルの見解

担当する側から見ると、文章で評価されている人は、書く時間が短い人です。場面ごとの型を持ち、型に当てはめ、一文を短くし、送る前に相手の立場で確かめ、反応で型を直している。書く時間が短いのに、返信も判断も速く返ってきています。文章に時間がかかっている人は、上手に書こうとして長くなり、送るのが遅れ、返ってくる反応も鈍く、それをさらに丁寧に書き直そうとして、また時間がかかっています。

順番として、三つの場面の型を持ち、書いたら一文を短くし、送る前に相手になって「次にすることが分かるか」を確かめ、送った後の反応（返信の割合、問い合わせの数、聞き返しの回数）を見て、月に一つ型を直す。この順番で、文章力は書く技術ではなく、相手の行動で確かめる習慣として磨かれます。エラベルでは、担当者の文面と報告について、依頼側と候補者の反応を見て直す形をお願いしています。文章力は、上手さではなく、相手が次に動ける文章を書けるかで決まります。

## まとめ

- 副業で要る文章力は**上手な文章ではなく、相手が次に何をすればよいか分かる文章**
- 場面は**スカウト・候補者への連絡・依頼側への報告**の三つで、相手が次にすることが違い、型も違う
- 磨き方は**型を持つ・一文を短く・送る前に相手の立場で読む・反応で直す**の四つ
- 送る前に確かめることは**場面ごとに決めておく**。冒頭で関係が分かるか、次にすることが分かるか、上長に言える一文があるか
- 反応は**返信の割合・返答までの時間・問い合わせの数・聞き返しの回数**で見て、月に一つ直す
- 長くなる癖は**相手が次にすることに関係ある情報だけを残す**ことで直す
- 候補者への文章は**依頼側の代表として読まれる**。約束にならず、短く丁寧に、待たせるときは見込みを

## よくある質問

### スカウトの文面を、AIに書いてもらってもよいですか

型の構造を作る補助や、一文を短くする補助には使えますが、依頼側の情報や候補者の情報を入力することは、情報の扱いの線に関わります。依頼側の会社名、求人の条件、候補者の経歴を入力すれば、依頼側の情報を外部のサービスに渡したことになり得ます。使うなら、依頼側の情報を含まない構造の作成に限り、中身は自分で埋め、送る前に相手の立場で読むことは省きません。情報の扱いの線は[情報の取り扱いと端末の分離](/media/fukugyo-security/)に書いています。

### 依頼側から「もっと丁寧な文章で」と言われました

「丁寧」が何を指すかを確かめます。長さを求めているのか、言い回しを求めているのか、依頼側の言い方に合わせることを求めているのか。多くの場合、依頼側の「丁寧」は、候補者への文章が依頼側の社内の言い方と違うことへの違和感で、依頼側が候補者に送っている過去の文章を見せてもらい、言い方を合わせれば解決します。長さを増やすことが丁寧さになるとは限りません。依頼側の型に合わせる考え方は[クライアントのツールに合わせる](/media/fukugyo-kokyaku-tool/)に整理しています。

### 報告の文章が長くなり、担当者に読まれていない気がします

冒頭に、担当者が上長に言える一文（一つの数字を比較で語った文）を置き、判断が要ることを分けて書き、それ以外は表にします。文章として書く部分を、冒頭の一文と、判断が要ることの数行に絞れば、担当者は読めます。詳しい内容は表に添え、読みたい担当者だけが読む形にします。報告の層の分け方は[報告の頻度をどう決めるか](/media/fukugyo-report-hindo/)に、一つの数字の語り方は[数字で語る](/media/fukugyo-suuji/)に書いています。

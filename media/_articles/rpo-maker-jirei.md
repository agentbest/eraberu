同じ採用代行を使っても、機能するメーカーと機能しないメーカーがあります。差を作るのは代行の腕ではなく、発注側の条件です。職種の型ごとに経路を分けているか、製品と工程の要件が言葉になっているか、勤務地と転居の条件を先に出しているか、働き方の実態を求人票に書いているか、面接の枠を預けられるか、記録が社内にあるか、任せる工程が絞られているか。結論を先に書くと、**メーカー業界で採用代行が機能するのは、型・要件・勤務地・実態・枠・記録・工程の七つで「社内に残すものを残している」会社で、機能しないのは「全職種を一つの媒体で、全部任せたい」会社です。**発注の前に七つで自社を確かめ、機能しない条件があれば、発注の前にそれを変えます。工程の切り分けは[メーカー業界の採用代行](/media/rpo-maker-rpo/)に、課題の分解は[メーカー業界の採用課題](/media/rpo-maker-kadai/)に、IT・Web業界の条件は[IT・Web業界で採用代行が機能する条件・機能しない条件](/media/rpo-it-jirei/)に書いています。ここでは、メーカー業界の七つの対に絞ります。

## 七つの対

| 軸 | 機能する条件 | 機能しない条件 |
|---|---|---|
| 型 | 技術職・現場職・事務職で経路と任せる工程を分けている | 「全職種を一つの媒体で」 |
| 要件 | 製品と工程の要件を技術者が言葉にし、代行と「経歴で読める言葉」に整えている | 「要件は技術者が見れば分かる」 |
| 勤務地 | 勤務地・転居の支援・転勤の有無を、求人票と初回の連絡で出す | 「勤務地は面接で」 |
| 実態 | 交替勤務・残業・環境の実態を求人票に書き、現場の見学を段に置く | 「アットホームな職場」。見学が無い |
| 枠 | 技術者と現場の責任者の面接の枠を週に決まった数預けられる | 「現場が忙しくて面接に出られない」 |
| 記録 | 一覧と面接の記録が社内の環境にあり、兼務の担当でも見られる | 記録が代行の環境 |
| 工程 | 任せる工程が絞られ、残す工程（要件・見極め・勤務地と条件の判断）の担当がいる | 「全部任せたい」 |

七つのうち一つでも機能しない条件にあると、代行はその部分で止まります。

## 型：経路と工程を分けているか

| 機能する | 機能しない |
|---|---|
| 技術職はスカウトと紹介、現場職は地域の経路、事務職は掲載型、と型ごとに経路がある | 一つの媒体で全部 |
| 型ごとに任せる工程が決まっている（技術職はスカウトの母集団形成、現場職は地域の経路の運用、など） | 「採用を全部」 |
| 型ごとに応募の数を記録している | 全部を一つの数で見る |

型の分け方は、社内で決めます。代行は、型ごとの経路の運用を担います。

### エラベルの見解

メーカー業界で最も多い機能しない条件は「要件」です。「設計の要件は、技術者が履歴書を見れば分かる」と言い、代行と紹介会社には「機械設計の経験者」と伝える。代行は経験者を集め、技術者が見ると「製品が違う」「工程が違う」で通らない。技術者は「代行の質が低い」と言い、代行は「要件が無い」と言う。直し方は、最初の一回、いまうまくやっている人に「入った頃にすぐできたことと時間がかかったこと」を三十分聞き、「〇〇の製品の〇〇の工程で、〇〇を担った経験」の形に担当者が整え、技術者が確認すること。技術者が書くのではなく、話してもらって整える。エラベルで担当者を選ぶ企業には、「設計の要件を、製品と工程の言葉で一枚にしていますか」を、私たちから先に聞いています。要件の作り方は[採用要件の定義の進め方](/media/rpo-task-youken-teigi-susumekata/)に書いています。

## 要件：製品と工程が言葉になっているか

| 機能する | 機能しない |
|---|---|
| 「〇〇の製品の〇〇の工程で、〇〇を担った経験」が必須に | 「設計経験〇年」 |
| 技術者が最初の一回話し、担当者が整え、技術者が確認 | 技術者が「見れば分かる」 |
| 製品や工程が変われば要件が更新される | 去年の要件のまま |

## 勤務地：先に出しているか

| 機能する | 機能しない |
|---|---|
| 勤務地を求人票の先頭に。転居の支援と転勤の有無を初回の連絡で | 「勤務地は面接で」 |
| 応募の減少を受け入れ、辞退と離職で見る | 応募の数を成果にして隠す |
| 転居できる人への経路（スカウト）と、通える人への経路（地域）を分ける | 一つの経路で |

勤務地を先に出す判断は会社のもので、代行が決められません。出さない会社では、代行の母集団形成は面接での辞退で消えます。

## 実態：求人票に書き、見学を置いているか

| 機能する | 機能しない |
|---|---|
| 交替勤務・残業・環境・一緒に働く人・最初の三か月を、実態の言葉で | 「アットホーム」「未経験歓迎」だけ |
| 現場の見学を選考の段に置き、候補者が実態を見て判断できる | 見学が無く、入社後に「聞いていない」 |
| 早期離職の理由を求人票に戻す | 離職を「本人の事情」で片付ける |

実態の書き方は[求人原稿の作成の進め方](/media/rpo-task-kyujin-genko-susumekata/)に書いています。

### エラベルの見解

「全部任せたい」というメーカーは、多くの場合、採用の担当が総務や人事の兼務で、採用に使える時間が週に数時間しかありません。その状態で全部を任せると、要件の判断も勤務地の判断も代行に寄り、代行にはできないので止まります。エラベルは担当者を工程ごと・職種の型ごとに選べる形にしているので、兼務の担当が「要件の確認（技術者との橋渡し）・勤務地と条件の判断・面接の設定」だけに時間を使い、「一次対応・日程・記録・型ごとの経路の運用」を担当者が担う、という組み方ができます。兼務の担当の時間は、週に数時間で足ります。最初に外に出すのは、負担が最も大きい「一次対応と日程」です。工程の切り分けは[面接の日程調整は代行に出せるか](/media/rpo-task-nittei-chousei-daikou/)や[求人媒体の運用は代行に出せるか](/media/rpo-task-baitai-unyou-daikou/)に書いています。

## 枠：技術者と現場の責任者の時間を預けられるか

| 機能する | 機能しない |
|---|---|
| 技術者と現場の責任者が週に一枠、決まった曜日と時間を面接の枠として空け、代行が預かる | 候補者の希望を聞いてから現場の予定を調整 |
| 一次（書類の照合と一次対応）を外に出し、その人の時間を面接と見学だけに | 全段にその人が出る |
| 面接と見学を同日に | 段が多く、日程が延びる |

枠の預かり方は[面接の日程調整の進め方](/media/rpo-task-nittei-chousei-susumekata/)に書いています。

## 記録：社内の環境にあるか

| 機能する | 機能しない |
|---|---|
| 一覧と面接の記録が社内のATSか共有の場所にあり、兼務の担当でも更新と閲覧ができる | 記録が代行の環境 |
| 型ごとに応募の数と段階が見える | 全部を一つの数で |
| 契約が終わっても、記録と型（要件の一枚、求人票、経路の一覧）が社内に残る | 契約が終わると消える |

メーカーは同じ職種を繰り返し採るので、型が残るかどうかで、二回目以降の速さが変わります。記録の扱いは[引き継ぎ資料に含める内容](/media/rpo-hikitsugi-shiryou/)に書いています。

## 工程：絞られているか

| 機能する | 機能しない |
|---|---|
| 「技術職のスカウトの母集団形成と一次対応」「現場職の地域の経路の運用と一次対応」のように、型と工程で任せる範囲が明確 | 「採用を全部」 |
| 残す工程（要件・見極め・勤務地と条件・合否）の担当が決まっている | 残す工程の担当がいない |
| 一つの型・一つの工程で三か月回し、記録で効いたかを見てから広げる | 最初から全型・全工程 |

## 機能しない条件を変える順番

| 順 | 変えること | 費用 |
|---|---|---|
| 一 | 型：技術職・現場職・事務職で経路を分ける | かからない |
| 二 | 要件：技術者が最初の一回話し、担当者が整える | 技術者の三十分 |
| 三 | 枠：技術者と現場の責任者の週に一枠 | かからない |
| 四 | 記録：一覧を社内の環境に | かからない |
| 五 | 工程：任せる工程を一つに絞る（最初は一次対応と日程） | 契約の範囲が小さくなる |
| 六 | 勤務地：先に出すかを決める | 会社の判断 |
| 七 | 実態：求人票に書き、見学を段に | 現場の責任者の時間 |

一から五は発注の前に社内で変えられます。六は会社の判断、七は現場の協力が要ります。

## 機能しているかを見る記録

| 見ること | 機能している目印 |
|---|---|
| 型ごとの応募の数 | 偏りが減っていれば型が機能 |
| 書類の○と面接の一致 | 一致していれば要件が機能 |
| 辞退の理由 | 「勤務地」が減っていれば勤務地が機能 |
| 早期離職の理由 | 「働き方」が減っていれば実態が機能 |
| 段階ごとの日数 | 短くなっていれば枠と工程が機能 |

件数のまま並べ、前の募集と比べます。割合や外部の平均で断定しません。見る指標は[採用代行との定例会で見るべき数字](/media/rpo-teirei/)に書いています。

## まとめ

- 代行が機能するかは**代行の腕より発注側の条件**で決まる
- 七つの対は**型・要件・勤務地・実態・枠・記録・工程**
- 最も多い機能しない条件は**要件**。技術者が「見れば分かる」では代行は動けない。話してもらって担当者が整える
- **「全職種を一つの媒体で、全部任せたい」は機能しない**。型で分け、兼務の担当は要件の橋渡しと判断に絞る
- 変える順番は**型→要件→枠→記録→工程→勤務地→実態**。一〜五は発注前に社内で
- メーカーは同じ職種を繰り返し採るので、**型が社内に残るか**で二回目以降が変わる

## よくある質問

### 技術者の人数が少なく、面接の枠も要件の時間も出せません

要件は最初の一回の三十分、面接は週に一枠から。一次の書類の照合と一次対応を外に出せば、技術者の時間は面接だけになります。それでも出せないなら、いまは技術職の採用の時期ではなく、現場職か事務職の採用から始め、技術者の負担が減った時期に技術職を採る、という順番の判断になります。順番は会社が決めます。

### 現場の責任者が「見学で候補者に来られると、現場が止まる」と言います

見学は短く（三十分程度）、見せる場所と説明する人を決めておけば、現場は止まりません。見学で候補者が実態を見て判断すれば、入社後の早期離職が減り、現場の教える負担が減ります。「見学の三十分」と「早期離職で教え直す時間」を比べれば、見学のほうが現場の負担は小さい。見せ方は現場の責任者が決め、日程の調整は代行が担います。

### 紹介会社を使っているが、製品と工程が合わない推薦ばかりです

紹介会社に渡している要件が「設計経験〇年」のままなら、ずれるのは当然です。「〇〇の製品の〇〇の工程で、〇〇を担った経験」の一枚を依頼書として渡し、見送りの理由を要件の言葉で戻すと、推薦が変わります。紹介会社の側の問題にする前に、依頼書と返事の速さを確かめます。紹介会社との付き合い方は[紹介会社の推薦の質が低い](/media/rpo-agent-shitsu/)に書いています。

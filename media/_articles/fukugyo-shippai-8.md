副業の仲間との勉強会で、担当している案件の話を「参考になれば」と少し話した。SNSに「今日の候補者が」と書いた。自分のクラウドに依頼側の候補者の一覧を置いて作業した。どれも、悪いことをしているつもりは無かった。結論を先に書くと、**守秘の線を越えるのは、多くの場合、悪意ではなく善意からです。「相談のつもり」「実績のつもり」「効率のつもり」の三つが、線を越える入口になります。越えた瞬間は本人が気づかず、後で依頼側から分かって、信頼を一度に失います。**線は複雑ではなく、「依頼側と候補者が特定できる情報は、依頼側の仕組みの外に出さない」の一本です。この一本を、相談・発信・作業のすべての場面で守れば、越えることはありません。情報の種類ごとの扱いは[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に、端末と置き場の分け方は[情報の取り扱いと端末の分離](/media/fukugyo-security/)に、発信で書いてはいけないことは[発信で書いてはいけないこと](/media/fukugyo-hasshin-nglines/)にまとめています。契約の秘密保持の解釈は、専門家にご確認ください。

## 線を越える三つの善意

守秘の線を越える人の多くは、越えたつもりがありません。三つの善意が、入口になります。

| 善意 | 頭の中 | 実際に起きていること |
|---|---|---|
| 相談のつもり | 「同じ立場の人に相談すれば、よい判断ができる」 | 相談の中で、依頼側の会社名、状況、候補者の話が出る。聞いた相手は依頼側との秘密保持の外にいる |
| 実績のつもり | 「担当した案件を実績として書けば、次の案件につながる」 | 依頼側の名前や成果の数字を、許可なく発信や経歴に書く。依頼側が読めば、契約の存在が外に出たことになる |
| 効率のつもり | 「自分のツールで管理したほうが早い」「家で見られるように手元に置いておこう」 | 候補者の情報が依頼側の仕組みの外（自分のクラウド、端末、紙）に出る。依頼側の管理の外に情報が散らばる |

三つの要点は、「どれも、その場では正しいことをしている感覚がある」ことです。相談は判断を良くし、実績は次につながり、効率は稼働を減らします。だから、越えたことに気づきません。気づくのは、依頼側の担当者から「この話、外でされましたか」と言われたときか、候補者から「なぜ別の人が知っているのか」と問い合わせが来たときです。

## 越えやすい場面の一覧

線を越えやすい場面を、日常の動きに沿って並べます。自分がどこで越えそうかを見ます。

| 場面 | 越え方 | 線の内側の形 |
|---|---|---|
| 副業の仲間との会話 | 「A社の案件で、こういう候補者がいて」 | 「この規模・業界の会社で、こういう条件のとき、どう判断するか」と、構造だけにする。[同じ立場の仲間を作る](/media/fukugyo-nakama/) |
| 家族との会話 | 「今日の案件の候補者が面白くて」 | 案件の中身は話さない。「今日は副業で疲れた」まで |
| SNSや記事の発信 | 「今日面談した候補者が」「クライアントの人事が一人で」 | 出来事ではなく判断の仕方を書く。[発信で書いてはいけないこと](/media/fukugyo-hasshin-nglines/) |
| 経歴やプロフィール | 依頼側の会社名と成果の数字を、許可なく書く | 業界・規模・担当した工程で書く。名前を出すなら許可を取る。[クライアントに実績公開の許可を取る](/media/fukugyo-kyoka-toru/) |
| 別の依頼側との会話 | 「他社ではこうしていました」 | 一般的な方法として、自分の判断の仕方で答える。[案件ごとの情報の分け方](/media/fukugyo-jouhou-bunri/) |
| 自分のツールでの作業 | 候補者の一覧を自分のクラウドに置く。履歴書を自分の端末に保存する | 依頼側の仕組み（ATS、共有）の中だけで扱う。[クライアントのツールに合わせる](/media/fukugyo-kokyaku-tool/) |
| 稼働ログや判断のメモ | 候補者の名前、依頼側の社内の事情を書く | 工程と時間と、依頼側の情報を抜いた判断だけ。[稼働ログの付け方](/media/fukugyo-log/) |
| 議事録 | 候補者の評価の中身を書く | 人数と工程と方針だけ。[議事録の残し方](/media/fukugyo-gijiroku/) |
| 本業の会話 | 本業の同僚に副業の案件の話をする | 副業の話自体をしない。本業に副業を伝えていても、案件の中身は話さない |
| 案件が終わった後 | 依頼側の資料や候補者の情報が、自分の側に残っている | 終了時に消し、消したことを依頼側に伝える。[引き継ぎの進め方](/media/fukugyo-hikitsugi/) |
| 公共の場での作業 | カフェで候補者の情報を開く。電車で依頼側の資料を読む | 候補者の情報を扱う作業は、自宅で。[ネットワーク環境の注意](/media/fukugyo-vpn/) |

場面の要点は、「相談・発信・作業の三つの場面に、越えやすさが集まっている」ことです。相談では会社名と候補者の話が出やすく、発信では出来事を書きやすく、作業では自分のツールに置きやすい。この三つの場面で線を意識すれば、他の場面はほぼ守れます。

### エラベルの見解

相談で最も多い思い込みは、「会社名を出さなければ、案件の話をしてもよい」というものです。実際には、会社名が無くても、業界・規模・状況・職種・時期の組み合わせで、依頼側の担当者や同業の人には特定できます。仲間との会話で「〇〇業界の数十名規模で、〇〇職を採用していて」と話せば、その業界の人には会社が絞れます。候補者の話は、名前が無くても、経歴の特徴で候補者本人には分かります。

見ていて差がつくのは、「どこで知ったか」を問う癖があるかです。話す前、書く前、置く前に「これは依頼側の仕組みの中で知ったことか」を問い、そうなら外に出さない。この癖がある人は、相談でも発信でも、構造と判断の仕方だけを出していて、依頼側から「この人は外で話さない」と信頼されています。癖が無い人は、善意で話し、善意で書き、善意で置き、後で依頼側から指摘を受けています。エラベルでは、担当者の発信や相談に依頼側や候補者の情報が含まれていると分かった場合、依頼側の信頼に関わるので、登録の前に見直しをお願いすることがあります。守秘の線は、契約の条項である前に、担当者の癖です。

## 越えたときに起きること

線を越えたことが分かると、何が起きるかを知っておくと、線の重さが分かります。

| 起きること | 内容 |
|---|---|
| 依頼側からの信頼が一度に消える | 稼働の質がどれだけ高くても、「外で話す人」と分かった時点で、任せられなくなる |
| 契約の終了 | 秘密保持の条項に反したとして、契約が終わることがある。契約によっては責任の問題も。専門家に |
| 候補者への影響 | 候補者の情報が外に出れば、候補者本人の不利益になり、依頼側は候補者への対応を迫られる |
| 依頼側の社内での問題 | 依頼側の担当者が、外部の担当者の情報の扱いについて社内で説明することになる。担当者の立場が悪くなる |
| 紹介が止まる | 依頼側の担当者は、その担当者を人に紹介しなくなる。同業の間で話が広がることもある |
| 窓口との関係 | 窓口を通していれば、窓口の他の案件にも影響する |
| 自分の評価の回復に時間がかかる | 一度の越境で失った信頼は、数か月の稼働の質では戻らない |

起きることの要点は、「稼働の質で埋め合わせられない」ことです。遅れや誤りは、次の稼働で取り返せますが、守秘の線を越えたことは、その後の稼働の質で戻りません。依頼側の担当者にとって、「外で話す人」は、どれだけ仕事ができても任せられない人です。信頼の積み方は[信頼を積む小さな行動](/media/fukugyo-shinrai/)に、一度で失う行動は同じ記事に書いています。

## 線の引き方

線は一本で、「依頼側と候補者が特定できる情報は、依頼側の仕組みの外に出さない」です。この一本を、三つの場面に当てはめます。

| 場面 | 線の内側 | 線の外側 |
|---|---|---|
| 相談 | 業界と規模を粗くした状況、判断の構造、自分の迷い | 依頼側の会社名、担当者の名前、社内の事情、候補者の話、合意した条件の具体 |
| 発信 | 判断の仕方、型の構造、一般化した教訓、粗くした事例、許可を取った実績 | 出来事、依頼側が特定できる話、候補者の話、契約の条件、本業の話 |
| 作業 | 依頼側の仕組みの中での作業。自分の側には工程と時間と、依頼側の情報を抜いた判断のメモ | 自分のクラウドや端末や紙に、候補者の情報や依頼側の資料を置く |

引き方の要点は、「線の内側にあるものだけで、相談も発信も作業も成り立つ」ことです。相談は構造で足り、発信は判断の仕方で足り、作業は依頼側の仕組みの中で足ります。線の外側のものを使わないと成り立たない相談や発信や作業は、そもそもやらないものです。事例として書くときの粗くし方は[事例の書き方](/media/fukugyo-jirei-kakikata/)に、依頼側の名前を出すときの許可の取り方は[クライアントに実績公開の許可を取る](/media/fukugyo-kyoka-toru/)に整理しています。

## 日常の中で線を守る習慣

線は、決めるだけでは守れません。日常の動きの中に、守る習慣を組み込みます。

| 習慣 | 内容 |
|---|---|
| 「どこで知ったか」を問う | 話す前、書く前、置く前に、一度だけ問う。依頼側の仕組みの中で知ったことなら、出さない |
| 依頼側の仕組みの中で作業する | 候補者の情報を扱う作業は、ATSと依頼側の共有の中だけ。自分の側に写さない。最初に依頼側と決める |
| 自分の記録に依頼側の情報を書かない | 稼働ログ、判断のメモ、自分の側の議事録は、工程と時間と判断だけ。書き始める前に「依頼側の名前を書いていないか」を見る |
| 相談は構造だけにすると決めておく | 仲間に相談するとき、「会社名と候補者は出さない」と自分に言ってから話す |
| 発信は「五人の視点」で読んでから出す | 依頼側の担当者、候補者、本業の上司、他の依頼側、副業を始めたい人が読んだらどう感じるか |
| 案件の終了時に消す | 自分の側に残った依頼側の情報を、終了時に消し、消したことを伝える |
| 月に一度、置き場を点検する | 自分のクラウド、端末、紙に、依頼側の情報が無いかを見る |

習慣の要点は、「どこで知ったか」を問うことに尽きます。この問いを、話す前・書く前・置く前の三つの時点で一度だけ問えば、越えることはほぼ無くなります。問いは数秒で済み、慣れると無意識になります。依頼側の情報を自分の側に置かない形は[案件ごとの情報の分け方](/media/fukugyo-jouhou-bunri/)に書いています。

## 越えてしまったときの対処

気をつけていても、越えることはあります。気づいたときの対処で、その後が変わります。

| 状況 | 対処 |
|---|---|
| 仲間との会話で会社名を出した | その場で「会社名は忘れてほしい」と伝える。以後、その依頼側の話は一切しない |
| 発信に依頼側や候補者の情報を書いた | すぐに消す。依頼側の担当者に、書いた内容と消した日と経緯を伝える。隠さない |
| 自分のクラウドや端末に候補者の情報を置いていた | すぐに消す。依頼側に「作業の都合で一時的に置いていたが、消した」と伝え、以後は依頼側の仕組みの中だけで作業すると約束する |
| 別の依頼側に他社の話をした | 話した直後に「他社のことなので忘れてほしい」と伝える。元の依頼側に伝えるかは、内容の重さで判断する |
| 候補者に別の候補者の話をした | すぐに依頼側に伝え、候補者への対応を依頼側と決める |
| 何を越えたか分からないが、依頼側から指摘された | 事実を確認し、認め、対処を依頼側と決める。言い訳をしない |

対処の要点は、「依頼側に伝える」ことです。越えたことを隠して、後で分かると、越えたこと自体より、隠したことで信頼を失います。気づいた時点で、何を出し、いつ消し、今後どうするかを、依頼側に伝えます。伝えた結果、契約が終わることもありますが、隠して後で分かるより、関係は保たれます。トラブルの整理は[トラブルへの対処](/media/fukugyo-trouble/)に書いています。契約上の責任は、専門家にご確認ください。

## 依頼側との合意で線を明確にする

線は、自分の中だけでなく、依頼側と最初に合意しておくと、迷いが減ります。

| 合意すること | 内容 |
|---|---|
| 候補者の情報を扱う場所 | 「候補者の情報は御社のATSと共有の中だけで扱い、私の側には置きません」 |
| 自分の記録の範囲 | 「稼働の記録には、工程と時間だけを書き、候補者や社内の情報は書きません」 |
| 相談や発信の線 | 「案件の内容は外で話さず、発信には御社や候補者が特定できることを書きません」 |
| 実績としての扱い | 「実績として書くときは、業界と規模と工程だけにし、御社の名前を出す場合は改めて許可をいただきます」 |
| 終了時の扱い | 「契約が終わったら、私の側に残った情報は消し、消したことをお伝えします」 |
| 秘密保持の条項の確認 | 契約書の秘密保持の範囲と期間を読み、分からなければ聞く。[契約はどうなるか](/media/fukugyo-qa-5/) |

合意の要点は、「自分から先に線を示す」ことです。依頼側から「情報の扱いはどうしますか」と聞かれる前に、「このように扱います」と示せば、依頼側は「情報の扱いで安心できる人」と受け取り、最初から信頼が積み上がります。合意は、初回の打ち合わせで口頭で伝え、議事録に残します。初回の打ち合わせの項目は[初回打ち合わせの進め方](/media/fukugyo-shodan/)に整理しています。

### エラベルの見解

担当する側から見ると、守秘の線を越えた人は、悪い人ではなく、線を「契約の条項」としてしか持っていなかった人です。条項は読んでいても、相談・発信・作業の日常の場面に、線が落ちていない。善意で話し、善意で書き、善意で置いて、越えています。線を守れている人は、条項を暗記しているのではなく、「どこで知ったか」を問う癖を、話す前・書く前・置く前に持っています。

順番として、案件の最初に依頼側と線を合意し、依頼側の仕組みの中で作業すると決め、自分の記録に依頼側の情報を書かず、相談は構造だけ、発信は判断の仕方だけと決め、「どこで知ったか」を問う癖を付け、終了時に消して伝える。この順番で、守秘の線は、契約の条項ではなく、日常の習慣になります。エラベルでは、依頼側と担当者の契約の際に情報の扱いを最初に整え、担当者にも自分から線を示す形をお願いしています。線を自分から示せる担当者は、依頼側から最も信頼される担当者です。

## まとめ

- 守秘の線を越えるのは**悪意ではなく、相談・実績・効率の三つの善意**から。越えた瞬間は気づかない
- 越えやすいのは**相談・発信・作業**の三つの場面。会社名を出さなくても、組み合わせで特定される
- 越えると**信頼が一度に消え、契約が終わり、候補者に影響し、紹介が止まり、稼働の質では戻らない**
- 線は一本。**「依頼側と候補者が特定できる情報は、依頼側の仕組みの外に出さない」**
- 習慣は**話す前・書く前・置く前に「どこで知ったか」を問う**。依頼側の仕組みの中で作業し、自分の記録に依頼側の情報を書かない
- 越えたら**すぐ消し、依頼側に伝える**。隠さない
- 最初に**自分から線を示して依頼側と合意する**

## よくある質問

### 副業の仲間に相談したいのですが、どこまで話してよいですか

「業界と規模を粗くした状況」「自分が迷っている判断の構造」「自分の考え」までです。「〇〇業界の数十名規模の会社で、返信が来ない候補者の絞り方で迷っている。自分は〇〇と考えている」は線の内側で、「A社で、〇〇という候補者が」は外側です。相談の前に「会社名と候補者は出さない」と自分に言ってから話すと、越えません。相談の仕方は[同じ立場の仲間を作る](/media/fukugyo-nakama/)に整理しています。

### 依頼側から「候補者の一覧を自分のパソコンで整理してほしい」と言われました

依頼側が求めているなら、依頼側の仕組みの中で整理できないかを先に提案します。「御社の共有の中に表を作って整理する形でよいですか」と聞き、それで済むなら自分の側に置きません。依頼側が「自分の側で」と言う場合は、置く情報の範囲と、終了時に消すことを文面で確認し、副業用の端末とアカウントで、他の案件と混ぜずに扱います。自分の側に置くことは、依頼側の指示があっても、扱いの責任が自分に来ることを知っておきます。端末の扱いは[私物端末で作業してよいか](/media/fukugyo-tanmatsu/)に書いています。

### 案件が終わって時間が経ちましたが、当時の話を発信に書いてよいですか

時間が経っても、依頼側と候補者が特定できる情報は書けません。秘密保持の条項は、契約の終了後も一定の期間続くことが多く、期間は契約書で確認します。書くなら、業界と規模と状況を粗くし、判断と進め方だけを残す形で、依頼側の担当者に「特定されない形で進め方を書く」と一言伝えておくと安全です。粗くし方は[事例の書き方](/media/fukugyo-jirei-kakikata/)に、条項の期間の読み方は専門家にご確認ください。

エンジニアの採用がうまくいかず、代行に出すことを考える会社は多い。ただ、エンジニア採用は他の職種と違い、「全部任せる」が最も失敗しやすい職種です。母集団を作る工程は外に出せても、技術を見極める工程と、どんなエンジニアが要るかを決める工程は、社内に残さないと採れません。結論を先に書くと、**エンジニア採用で代行に出せるのは「探す・届ける・一次対応する・進捗を回す」の工程で、「要件を決める・技術を評価する・条件を決める」は社内に残す**のが線です。この線を引かずに任せると、応募は増えても、面接で合わない人ばかりになります。エンジニアが採れない構造の全体は[エンジニアが採れない理由と打ち手](/media/rpo-engineer-torenai/)に、採用代行そのものの整理は[採用代行（RPO）とは](/media/rpo-toha/)にまとめています。

## エンジニア採用が他の職種と違う点

代行に出す前に、エンジニア採用の構造を押さえておきます。他の職種と同じ感覚で出すと、ずれます。

一つ目は、候補者の側が選ぶ職種だということです。エンジニアは、求人の数に対して人が少なく、経験のある人には複数の選択肢があります。会社が選ぶというより、候補者に選ばれる構造です。求人票やスカウトは、「募集しています」ではなく「あなたにとって何があるか」を書かないと読まれません。

二つ目は、経歴の読み方に技術の知識が要ることです。職務経歴書に並ぶ技術の名前、関わった範囲、担当した工程。これを読んで「自社に合うか」を判断するには、技術が分かる人が要ります。人事だけで書類を読むと、名前の一致で通し、実態のずれが面接で出ます。

三つ目は、要件が現場でしか決められないことです。どんな技術で、どこまでを任せるか、何年目くらいの人か。これは経営者でも人事でもなく、一緒に働く現場が決めることです。現場が要件に関わらないまま募集すると、要件が高すぎるか、逆に曖昧になります。

この三つから、代行に出せる工程と出せない工程が決まります。

## 工程ごとの「任せられる・残す」

採用の工程を並べ、それぞれ外に出せるかを整理します。

| 工程 | 任せられるか | 理由 |
|---|---|---|
| 要件の決定 | 残す | 現場が決めるもの。外部は整理を手伝えるが、決められない |
| 求人票の作成 | 任せられる（要件が決まっていれば） | 要件を文章にする工程。技術の言葉を正しく使える代行なら |
| 媒体の選定と運用 | 任せられる | エンジニア向けの媒体と一般の媒体の使い分けは、経験のある代行が詳しい |
| スカウトの検索と送信 | 任せられる | 検索の条件を要件から作り、文面を候補者ごとに変える工程 |
| 応募者への一次対応 | 任せられる | 連絡、日程調整、選考の流れの案内 |
| 書類の一次絞り込み | 条件付き | 要件に沿った機械的な絞り込みは任せられる。技術の妥当性の判断は残す |
| 技術の評価 | 残す | 現場のエンジニアが行う。外部は評価の型作りと記録を手伝える |
| 面接の日程調整と記録 | 任せられる | 進行と記録 |
| 合否の判断 | 残す | 会社の判断 |
| 条件の決定と提示 | 残す | 会社の判断。外部は候補者の希望の整理まで |
| 内定後の連絡と入社までの対応 | 任せられる | 辞退を防ぐ連絡の設計と実行 |

線の要点は、「技術が関わる判断は全部残す」ことです。要件、技術の評価、合否。ここを外に出すと、外部の人が自社に合う技術者を決めることになり、入社後にずれます。

### エラベルの見解

相談で最も多いのは、「エンジニアが全然採れないので、全部任せたい」というご相談です。話を聞くと、社内に技術の分かる人が採用に関わっていない、要件が「経験三年以上のエンジニア」で止まっている、応募が来ても面接で何を聞けばよいか分からない、という状態です。この状態で代行に全部を出しても、代行は要件を作れず、技術を評価できず、応募を増やすことしかできません。応募が増えて、面接で合わない人が増えて、現場が疲れて終わります。

見ていて差がつくのは、「現場のエンジニアを、要件と評価に巻き込めているか」です。要件を現場と一緒に決め、評価の型を現場と作り、面接に現場が出る。この三つがあれば、代行は探す・届ける・回す工程で力を出せます。エラベルでは、担当者を紹介する前に、この三つが社内にあるかを確認しています。無ければ、代行を入れる前に、現場を巻き込む形を先に作ることをお伝えしています。

## 代行に出す前に社内で確認すること

工程の線が分かったら、代行に出す前に、社内の状態を確認します。次の五つが揃っていないと、代行を入れても動きません。

- **要件を決める人がいるか。** 現場のエンジニアか、技術の分かる責任者。「経営者が決める」では、技術の要件が曖昧になる
- **技術を評価する人がいるか。** 面接で技術の話ができる人。いなければ、外部の技術顧問や、業務委託で技術面接だけを担う人を別に用意する
- **要件が「必須」と「歓迎」に分かれているか。** 必須が五つ以上あるなら、まだ整理されていない。[必須と歓迎の分け方](/media/rpo-must-want/)で整理する
- **候補者に伝えられる技術の情報があるか。** 使っている技術、開発の進め方、チームの構成。これが求人票とスカウトの中身になる。無ければ、代行は書けない
- **面接の日程を現場が出せるか。** 現場が忙しくて面接の日程が出ないと、代行が母集団を作っても止まる

五つのうち、一つ目と二つ目が無い会社は、代行の前に、技術の分かる人を採用の側に置くことが先です。[技術の分かる人がいない場合](/media/rpo-engineer-torenai/)に、その組み方があります。

## 技術の分かる人がいない会社の組み方

社内にエンジニアがいない、いても採用に時間を割けない会社は多い。その場合の組み方を三つ示します。

一つ目は、現場のエンジニアの時間を、要件と技術面接だけに絞ることです。要件を決める打ち合わせを一回、技術面接を候補者ごとに一回。それ以外の工程（探す、届ける、一次対応、日程、記録）は代行が担い、現場は判断の場面だけに出る。現場の負担は、候補者一人あたり一時間程度に収まります。

二つ目は、外部の技術の分かる人を、評価の工程だけに入れることです。技術顧問、業務委託のエンジニア、元社員。技術面接と、書類の技術的な妥当性の確認だけを担ってもらう。代行とは別の役割なので、代行に「技術評価もできますか」と聞くのではなく、技術評価の担い手を別に用意します。

三つ目は、最初の採用で、技術の評価ができる人を採ることです。一人目のエンジニアや、技術責任者。この採用は代行に出しにくく、経営者が自ら動く採用になります。一人採れれば、二人目からは代行に出せる工程が増えます。

どの組み方でも、「技術の評価を代行に任せない」ことは同じです。代行の担当者に元エンジニアがいても、自社の技術の要件と評価は、自社の側で持ちます。

## 代行を選ぶときの確認項目

エンジニア採用を代行に出すとき、見積もりや面談で確認する項目です。

| 確認項目 | 聞き方 | 見るポイント |
|---|---|---|
| エンジニア採用の経験 | 「エンジニア採用で、どの工程を担当した経験がありますか」 | 母集団形成だけか、要件の整理まで関わったか |
| 技術の言葉の理解 | 「この求人の技術要件を、候補者向けの言葉にするとどうなりますか」 | 技術の名前を正しく使えるか、関わった範囲を読めるか |
| 媒体の使い分け | 「エンジニア向けの媒体と一般の媒体を、どう使い分けますか」 | エンジニアがいる場所を知っているか |
| スカウトの文面 | 「エンジニアに送る文面で、最初に書くことは何ですか」 | 技術環境と裁量を先に書くか、会社の紹介から始めるか |
| 技術評価の扱い | 「技術の評価はどう進めますか」 | 「自社で」と答えるか、「こちらで」と答えるか。後者は注意 |
| 現場との関わり方 | 「現場のエンジニアとは、どう連携しますか」 | 担当を通す設計があるか |
| 担当者 | 「担当する方の経歴を教えてください」 | 誰が付くかで結果が変わる。[担当者の経歴を確認する](/media/rpo-tantousha-keireki/) |

確認の要点は、「技術評価をどう進めるか」の答え方です。「こちらで一次の技術評価まで行います」と答える代行は、自社の技術の要件と違う基準で絞る可能性があります。「技術の評価は御社で。こちらは評価の型作りと記録を手伝います」と答える代行のほうが、線を分かっています。

## 代行に出したあとに起きること

線を引いて代行に出しても、運用の中で線が動くことがあります。起きやすいことと、戻し方を整理します。

| 起きること | 戻し方 |
|---|---|
| 代行が「良い人がいた」と技術の判断を始める | 「技術の判断は現場で」と戻す。代行は要件との対応を整理するまで |
| 現場が面接の日程を出さず、母集団が溜まる | 現場の面接の枠を先に固定する。代行が候補者を溜めても、面接が無ければ辞退が出る |
| 要件が途中で変わる | 現場と代行と人事で、要件の変更を書面で共有する。代行に口頭で伝えると、スカウトの対象がずれる |
| 応募は増えたが合わない人ばかり | 要件の書き方か、代行の検索の条件か、どちらがずれているかを見る。[エンジニアの母集団形成](/media/rpo-engineer-boshuudan/) |
| 代行の担当が技術を分かっていない | 担当者の変更を相談する。エンジニア採用は担当者の差が大きい |

戻し方の要点は、「現場の面接の枠を先に固定する」ことです。エンジニア採用で最も多い止まり方は、代行が候補者を作ったのに、現場が面接に出られず、候補者が他社で決まることです。

### エラベルの見解

担当する側から見ると、エンジニア採用で最も難しいのは、探すことではなく、現場を動かすことです。要件を出してもらう、面接の日程を出してもらう、評価を返してもらう。これは代行の担当者が現場に直接頼めることではなく、依頼側の人事か経営者が現場を動かす必要があります。代行に出しても、現場を動かす役は社内に残ります。

エラベルでは、エンジニア採用の案件をお受けするとき、依頼側に「現場のエンジニアが要件と評価に関わる時間を、週にどのくらい確保できるか」を先に伺っています。この時間が無い会社では、代行を入れても止まるので、先に現場の時間を確保することをお勧めしています。代行に出すかどうかの判断は、代行の質より、社内の現場の時間で決まることが多い。

## まとめ

- エンジニア採用で代行に出せるのは**探す・届ける・一次対応する・進捗を回す**工程。**要件を決める・技術を評価する・条件を決める**は社内に残す
- 他の職種と違うのは**候補者が選ぶ職種・経歴の読み方に技術の知識が要る・要件は現場でしか決められない**の三点
- 代行に出す前に**要件を決める人・技術を評価する人・必須と歓迎の分離・候補者に伝える技術の情報・現場の面接の枠**の五つを確認
- 技術の分かる人がいなければ**現場の時間を判断の場面だけに絞る・外部の技術の分かる人を評価だけに入れる・最初に技術の評価ができる人を採る**
- 代行を選ぶときは**技術評価をどう進めるかの答え方**を見る。「こちらで」と答える代行は注意
- 出したあとは**現場の面接の枠を先に固定する**。止まり方の大半はここ

## よくある質問

### 社内にエンジニアが一人もいません。それでも代行に出せますか

出せますが、技術の評価をする人を、代行とは別に用意する必要があります。外部の技術顧問、業務委託のエンジニア、知人の技術者。技術面接と書類の技術的な妥当性の確認だけを担ってもらいます。代行に「技術評価も」と頼むと、代行の担当者の技術の感覚で絞られ、自社に合うかどうかが分からなくなります。技術の評価をする人が用意できない場合は、最初の一人を経営者が自ら採る採用になり、代行はその補助（探す、届ける）にとどまります。

### 代行の担当者が元エンジニアなら、技術評価も任せてよいですか

担当者が元エンジニアであることは、求人票やスカウトの質を上げますが、技術評価を任せる理由にはなりません。自社の技術の要件は、自社の現場でしか決められず、評価も自社の基準で行うものです。担当者が元エンジニアなら、「評価の型を一緒に作ってもらう」「現場の面接官が聞く質問の案を出してもらう」という形で、評価の準備に関わってもらうのが良い使い方です。評価そのものは、現場が行います。

### 代行に出したのに、応募が増えただけで採用が決まりません

応募が増えて決まらないのは、要件のずれか、現場の面接が回っていないかのどちらかです。要件のずれなら、応募者の経歴と要件を並べて、どこがずれているかを現場と代行で確認します。面接が回っていないなら、現場の面接の枠を固定し、候補者を待たせない形にします。代行の側の問題（検索の条件、文面）であることもありますが、多くは社内の側にあります。代行の担当者と週に一度、数（応募、書類通過、面接、内定）を並べて見ると、どこで止まっているかが分かります。

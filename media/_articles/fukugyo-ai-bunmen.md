スカウトの文面を作るのに時間がかかるので、AIに作らせたい。候補者の経歴を貼って「この人向けの文面を」と頼めば、数秒で出てくる。速くなりそうだが、依頼側や候補者の情報を入力してよいのか、出てきた文面をそのまま送ってよいのかが分からない。結論を先に書くと、**AIで文面を作るなら、「依頼側と候補者の情報を入力しない」「構造の下書きまでにして、中身は自分で埋める」「依頼側の情報管理の決まりで、AIの利用が認められているかを確認する」「送る前に自分が相手の立場で読む」の四つが前提です。この前提を欠いてAIを使うと、速さを得る前に、守秘の線を越えます。**候補者の経歴を貼った時点で、候補者の個人情報を外部のサービスに渡したことになり得て、依頼側の求人の条件を貼った時点で、依頼側の情報を渡したことになり得ます。AIは、依頼側と候補者の情報を含まない作業に限って使います。AIの使い方の全体は[AIをどう使うか](/media/fukugyo-ai-katsuyou/)に、情報の扱いの線は[情報の取り扱いと端末の分離](/media/fukugyo-security/)に、文章の磨き方は[文章力をどう磨くか](/media/fukugyo-writing/)にまとめています。AIのサービスの規約と、依頼側の情報管理の決まりの解釈は、依頼側と専門家にご確認ください。

## AIが向く作業と向かない作業

文面に関わる作業を、AIが向くものと向かないものに分けます。線は「依頼側と候補者の情報が要るか」です。

| 作業 | 向くか | 理由 |
|---|---|---|
| 文面の構造（冒頭・中盤・結びに何を置くか）の下書き | 向く | 依頼側と候補者の情報が要らない。一般的な構造の案を出させる |
| 一文を短くする、言い回しを変える | 向く。ただし依頼側の情報を含まない文に限る | 自分が書いた一般的な文の整え |
| 候補者向けの文面を、候補者の経歴から作る | 向かない | 候補者の経歴（個人情報）を入力することになる |
| 依頼側の求人の条件を入れた文面を作る | 向かない | 依頼側の求人の情報を入力することになる |
| 候補者からの返信への返答を作る | 向かない | 候補者のやり取りの内容を入力することになる |
| 依頼側への報告の文章を作る | 向かない | 依頼側の記録と状況を入力することになる |
| 一般的な人事の知識の整理 | 向く | 案件の情報を含まない |
| 型の文書の構造を整える | 向く。依頼側の情報を抜いた型に限る | 自分の側の構造の型の整理 |

分け方の要点は、「向く作業は、案件の情報が無くてもできる作業だけ」ということです。文面の構造の下書き、一般的な言い回しの整え、人事の一般的な知識の整理は、案件の情報が無くてもできます。候補者向けの文面、返信、報告は、案件の情報が無いと作れず、作るには情報を入力することになります。情報の種類ごとの線は[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に書いています。

## 入力してはいけない情報の線

AIに入力してはいけない情報を、明確にしておきます。悪気なく貼ることが、最も起きやすい越え方です。

| 入力しないもの | なぜ |
|---|---|
| 候補者の名前、経歴、連絡先、やり取りの内容 | 個人情報。外部のサービスに渡すことになり得る。候補者の同意も依頼側の許可も無い |
| 依頼側の会社名、求人の内容、条件、社内の事情 | 依頼側の情報。秘密保持の対象。依頼側の許可が無い限り、外部に渡せない |
| 依頼側の記録の数字 | 依頼側の情報 |
| 依頼側の担当者や面接官の名前、評価 | 個人情報と、依頼側の社内の情報 |
| 自分が作った文面のうち、依頼側の情報を含む部分 | 文面に依頼側の会社の状況や条件が入っていれば、それは依頼側の情報 |
| 本業の会社の情報 | 本業の情報の持ち出し |
| 他の依頼側の情報 | 守秘の線を越える |

線の要点は、「自分が作った文面でも、依頼側の情報を含んでいれば入力しない」ことです。「自分が書いたものだから」と、依頼側向けの文面をAIに整えさせると、その文面に含まれる依頼側の会社の状況や求人の条件が、外部に渡ります。整えさせるなら、依頼側の情報を抜いた構造だけの文にしてからです。AIのサービスの規約（入力した情報の扱い）は、サービスごとに違い、変わることもあるので、使う前に確認します。規約の解釈は専門家にご確認ください。

### エラベルの見解

相談で最も多い思い込みは、「AIに入力した情報は、自分しか見ていないので、外に出したことにならない」というものです。実際には、AIのサービスに情報を入力することは、そのサービスの運営者に情報を渡すことで、依頼側や候補者から見れば、第三者に渡したことになり得ます。サービスによって、入力した情報の扱いは違いますが、依頼側の秘密保持の条項や、候補者の個人情報の扱いの観点では、「自分しか見ていない」は成り立ちません。

見ていて差がつくのは、AIを使う前に「これは依頼側か候補者の情報を含むか」を問う癖があるかです。問う癖がある人は、AIを構造の下書きと一般的な整えに限って使い、案件の情報を含む作業は自分でやっています。速さは、構造の下書きだけでも十分に得られています。問う癖が無い人は、候補者の経歴を貼り、依頼側の条件を貼り、それが依頼側に分かった時点で、信頼を失っています。エラベルでは、担当者が依頼側と候補者の情報をAIを含む外部のサービスに入力しない形を、情報の扱いの前提にしています。AIは、情報の線を守れる範囲で使う道具です。

## 構造の下書きまでに留める理由

AIを使ってよい範囲を、「構造の下書きまで」に留める理由は、情報の線だけではありません。

| 理由 | 内容 |
|---|---|
| 情報を入力せずに済む | 構造（冒頭に何を置き、中盤で何を伝え、結びをどうするか）は、案件の情報が無くても作れる |
| 中身は依頼側ごとに違う | 依頼側の状況、候補者との接点、依頼側の言い方は、案件ごとに違い、AIには分からない。自分で埋める必要がある |
| 候補者は型に気づく | AIが作った文面は、どこかで見た形になりやすく、候補者は「量産された文面」と感じる。宛名と接点は自分で書く |
| 依頼側の言い方に合わせる必要がある | 候補者は文面を「その会社からの連絡」として読む。依頼側の社内の言い方に合わせるのは、自分の仕事。[会社の代表として話す責任](/media/fukugyo-kaisha-daihyou/) |
| 自分の型が育たない | 中身までAIに任せると、「この状況でこう書くと返信が変わる」という自分の判断が溜まらない。[事例を流用しない](/media/fukugyo-jirei-ryuuyou/) |
| 責任は自分にある | 送った文面の責任は、AIではなく自分と依頼側にある。中身を自分で埋めていないと、責任が取れない |

留める要点は、「構造は道具、中身は自分の仕事」という分け方です。構造の下書きをAIに出させ、そこに依頼側の状況と候補者との接点を自分で埋め、依頼側の言い方に合わせ、送る前に相手の立場で読む。この形なら、速さと情報の線と文面の質の三つが保てます。文面の構造と中身の分け方は[事例を流用しない](/media/fukugyo-jirei-ryuuyou/)の「持ち込んでよいもの」と同じです。

## 依頼側の情報管理の決まりの確認

自分が線を守っていても、依頼側の側でAIの利用そのものに決まりがあることがあります。

| 確認すること | 聞き方 | 結果ごとの扱い |
|---|---|---|
| AIの利用が認められているか | 「業務でAIのサービスを使うことに、御社の決まりはありますか」 | 禁止なら使わない。条件付きなら条件に従う。決まりが無ければ、自分の線で使う |
| 使ってよいサービスの指定があるか | 「使ってよいサービスや、使ってはいけないサービスの指定はありますか」 | 指定があれば従う。依頼側が契約しているサービスがあれば、それを使う |
| 入力してよい情報の範囲 | 「AIに入力してよい情報の範囲に、決まりはありますか」 | 決まりがあれば従う。無くても、依頼側と候補者の情報は入力しない |
| AIで作った文面を候補者に送ることの可否 | 「AIで下書きした文面を、候補者に送ることに問題はありますか」 | 依頼側によっては、候補者向けの文面はAIを使わない方針のことがある |
| 情報管理の担当者の窓口 | 「AIの利用で迷ったとき、どなたに確認すればよいですか」 | 採用の担当者では答えられないことがある |

確認の要点は、「決まりが無いことと、使ってよいことは別」だということです。依頼側に決まりが無くても、依頼側と候補者の情報を入力しない線は、自分の側で守ります。決まりがある場合は、決まりのほうが優先で、自分の線より厳しければそれに従います。依頼側の情報管理の確認は[ネットワーク環境の注意](/media/fukugyo-vpn/)と[私物端末で作業してよいか](/media/fukugyo-tanmatsu/)で聞く項目と同じ場で聞きます。

## 送る前に自分が読む必要

AIが作った構造に中身を埋めた後も、送る前に自分が読むことは省けません。

| 読んで確かめること | なぜAIでは足りないか |
|---|---|
| 候補者との接点が、その候補者に合っているか | AIは候補者の経歴を知らない（入力しないので）。接点は自分が書き、自分が確かめる |
| 依頼側の言い方と合っているか | AIは依頼側の社内の言い方を知らない |
| 約束にならない書き方か | 「条件は〇〇です」のような、依頼側の判断が要ることを断定していないか。[権限がないと動けない場面](/media/fukugyo-kengen-nai/) |
| 事実と違うことが入っていないか | AIの出す文には、一般的な表現として、事実と合わないことが混ざることがある |
| 候補者が読んで、次に何をすればよいか分かるか | 相手の立場で読むのは自分の仕事。[文章力をどう磨くか](/media/fukugyo-writing/) |
| 依頼側の情報が意図せず入っていないか | 構造に中身を埋める過程で、入れすぎていないか |

読む要点は、「AIが作った部分と、自分が埋めた部分の両方を、相手の立場で読む」ことです。AIが作った構造は一般的で、そのままだと候補者に「誰にでも送っている」と伝わります。自分が埋めた中身は、依頼側の言い方と接点が合っているかを確かめます。送る前の読み直しの型は[文章力をどう磨くか](/media/fukugyo-writing/)に整理しています。

## AIの文面で起きやすい失敗

AIを使った文面で、実際に起きやすい失敗です。前提を欠くと起きます。

| 失敗 | 何が起きるか | 防ぎ方 |
|---|---|---|
| 候補者の経歴を貼って文面を作った | 候補者の個人情報を外部に渡した。依頼側に分かれば信頼を失う | 経歴は貼らない。接点は自分で書く |
| 依頼側の求人票を貼って文面を作った | 依頼側の情報を外部に渡した | 求人の条件は貼らない。構造の下書きだけ |
| AIの文面をそのまま送った | 候補者が「量産された文面」と感じ、返信が来ない。事実と違うことが混ざる | 中身は自分で埋め、送る前に読む |
| 依頼側の言い方と違う文面になった | 候補者が「この会社らしくない」と感じる。依頼側の担当者が違和感を持つ | 依頼側の過去の文面を見て、言い方を合わせる |
| 約束になる表現が入った | 「〇〇の条件でお迎えします」のような、依頼側の判断が要ることを断定した | 送る前に、約束になる表現を消す |
| 依頼側の決まりで禁止されていた | 後で分かり、契約に関わる | 最初に確認する |
| 速さに頼って、自分の型が育たなかった | 案件が変わったとき、判断の仕方が溜まっていない | 構造の下書きまでに留め、中身と判断は自分で |

失敗の要点は、「最初の二つ（経歴と求人票を貼る）が、最も起きやすく、最も重い」ことです。他の失敗は、文面の質や候補者の印象の問題ですが、最初の二つは情報の線を越える問題で、依頼側に分かった時点で、稼働の質に関わらず信頼を失います。速さを求めて貼る前に、「これは候補者か依頼側の情報か」を問います。守秘の線を越えたときの対処は[守秘の線を越える](/media/fukugyo-shippai-8/)に書いています。

## 依頼側にどう伝えるか

AIを使うことを、依頼側に隠す必要はありませんが、伝え方に線があります。

| 場面 | 伝え方 |
|---|---|
| 契約の最初 | 「文面の構造の下書きにAIを使うことがありますが、御社と候補者の情報は入力しません。御社の決まりがあれば教えてください」と、線と一緒に伝える |
| 依頼側から「AIを使っているか」と聞かれた | 事実を答える。「構造の下書きに使い、中身は自分で書き、御社と候補者の情報は入力していません」 |
| 依頼側から「AIで速くしてほしい」と言われた | 「情報を入力しない範囲で使います。候補者向けの中身は、御社の言い方に合わせて自分で書きます」と、線を保つ |
| 依頼側がAIの利用を禁止している | 使わない。「御社の決まりに沿って、使いません」 |
| 依頼側が自社のAIのサービスを提供した | 依頼側の管理の下にあるサービスなら、依頼側の決まりの範囲で使う。それでも候補者の情報の扱いは依頼側に確認 |

伝える要点は、「使っていることではなく、情報を入力していないことを伝える」ことです。依頼側が気にするのは、AIを使ったかどうかより、自社と候補者の情報がどう扱われたかです。「構造の下書きに使い、情報は入力していない」と線を示せば、依頼側は安心します。隠して後で分かるほうが、信頼を失います。

### エラベルの見解

担当する側から見ると、AIを文面に使って問題が起きていない人は、AIを構造の下書きに限って使い、依頼側と候補者の情報を入力せず、中身は自分で埋め、送る前に自分で読んでいる人です。速さは構造の下書きで十分に得られていて、文面の質は自分の型で保たれています。問題が起きた人は、候補者の経歴や依頼側の求人票を貼って文面を作り、そのまま送り、依頼側に分かって信頼を失った人です。

順番として、依頼側の情報管理の決まりを最初に確認し、AIを構造の下書きと一般的な整えに限ると決め、使う前に「依頼側か候補者の情報を含むか」を問い、含むなら入力せず自分でやり、構造に中身を自分で埋め、依頼側の言い方に合わせ、送る前に相手の立場で読む。この順番で、AIは情報の線を守りながら、文面の作成を速くする道具になります。エラベルでは、担当者が依頼側と候補者の情報を外部のサービスに入力しないことを、情報の扱いの前提にしています。AIをどう使うかは、担当者の判断ですが、情報の線は、担当者の判断で動かせるものではありません。

## まとめ

- AIで文面を作る前提は**依頼側と候補者の情報を入力しない・構造の下書きまでにして中身は自分で埋める・依頼側の決まりを確認する・送る前に自分が読む**の四つ
- 向くのは**案件の情報が無くてもできる作業**（構造の下書き、一般的な整え、一般的な知識）。向かないのは**情報が要る作業**（候補者向けの文面、返信、報告）
- 入力しないのは**候補者の情報・依頼側の情報・記録の数字・人の名前と評価・依頼側の情報を含む自分の文面・本業と他の依頼側の情報**
- 構造に留める理由は**情報の線・中身は依頼側ごとに違う・候補者は型に気づく・依頼側の言い方に合わせる・自分の型が育つ・責任は自分にある**
- 依頼側の決まりは**利用の可否・サービスの指定・入力の範囲・候補者向けの可否・窓口**を確認。決まりが無いことと使ってよいことは別
- 失敗で最も重いのは**候補者の経歴と依頼側の求人票を貼ること**。貼る前に情報の線を問う
- 依頼側には**使っていることではなく、情報を入力していないこと**を伝える

## よくある質問

### 候補者の経歴を貼らずに、その候補者向けの文面をどう作ればよいですか

AIには、候補者の情報を含まない構造の下書きだけを出させます。「エンジニア向けのスカウトの文面の構造を、冒頭・中盤・結びで」のような、一般的な依頼です。出てきた構造に、その候補者の経歴との接点（自分が媒体で見た経歴から、自分で書く）と、依頼側の状況（依頼側の言い方に合わせて自分で書く）を埋めます。接点と状況は、AIに書かせるものではなく、自分の仕事です。構造と中身の分け方は[事例を流用しない](/media/fukugyo-jirei-ryuuyou/)に整理しています。

### 依頼側がAIの利用について何も決めていません。自分の判断で使ってよいですか

決まりが無ければ、自分の線（依頼側と候補者の情報を入力しない、構造の下書きまで）で使えますが、使うことと線を、契約の最初に依頼側に伝えておきます。「構造の下書きに使うことがあり、御社と候補者の情報は入力しません」と伝えれば、依頼側が後から決まりを作ったときも、自分の使い方がその決まりに沿っているかを確認できます。伝えずに使い、後で決まりができて禁止されていたことが分かると、遡って問題になることがあります。

### AIで文面を作ることを、候補者に伝える必要はありますか

候補者向けの文面の中身を自分で書いているなら、構造の下書きにAIを使ったことを候補者に伝える必要は、通常はありません。ただし、依頼側の方針として「AIで作った文面は候補者に送らない」「送る場合は明示する」と決めている場合は、それに従います。候補者から「AIで書いたか」と聞かれた場合は、事実を答えます。候補者との接し方は[候補者への対応で気をつけること](/media/fukugyo-kouhosha-taiou/)に書いています。

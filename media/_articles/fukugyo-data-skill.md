「データを見て採用を改善してほしい」と依頼側に言われた。データの分析は専門ではなく、統計の手法も知らない。何をどう見ればよいのか、自分にできることなのかが分からない。結論を先に書くと、**人事の副業で要るデータの力は、分析の手法や統計の知識ではなく、「依頼側の記録から工程ごとの数字を取る」「以前と比べる」「止まっている場所を見つける」「一つの数字で依頼側に語る」までの一連です。表計算の集計と絞り込みで足り、専門の手法は要りません。前提は、データを依頼側の仕組みの外に出さないことで、依頼側の記録を自分のツールやAIのサービスに写して分析することは、情報の線を越えます。**依頼側のATSや媒体の管理画面の中で数字を取り、自分の側には集計の結果（依頼側が特定できない形）だけを持ちます。数字の語り方は[数字で語る](/media/fukugyo-suuji/)に、課題の構造化は[課題を構造化する](/media/fukugyo-kouzou-ka/)に、KPIの設計は[KPIを設計する](/media/fukugyo-kpi-sekkei-skill/)にまとめています。

## 副業で要るデータの力の範囲

「データを扱う」と聞くと広く感じますが、副業の担当者に要る範囲は限られています。

| 要るもの | 要らないもの |
|---|---|
| 依頼側の記録（ATS、媒体の管理画面）から、工程ごとの出口の数を取る | 統計の手法、回帰や検定のような分析 |
| 月ごとに同じ項目を並べ、以前と比べる | 大量のデータを扱う専用のツールの操作 |
| 工程の間の落ち幅を見て、止まっている場所を見つける | 予測のモデルを作ること |
| 数字を、比較と工程と範囲で、一文にして依頼側に語る | 見栄えの良いグラフを作ること |
| 変えた一つと、変えた後の数字を並べて、効いたかを見る | 複数の要因を同時に分析すること |
| 数字の出どころを示し、断定を避ける | 数字から因果を断定すること |

範囲の要点は、「要るのは、記録を見て、比べて、語る力で、分析の専門性ではない」ことです。依頼側の担当者が求めているのは、「うちの採用はどこで止まっていて、何が変わったか」を数字で示すことで、統計の手法で導いた結論ではありません。表計算の集計と絞り込みで、工程ごとの数を月ごとに並べられれば、その問いには答えられます。分析の専門性が要る場面は、副業の範囲では、ほぼ来ません。

## 扱うデータの種類と出どころ

副業の担当者が扱うデータは、種類が限られ、出どころは依頼側の記録です。

| データ | 出どころ | 何が分かるか | 誰の範囲か |
|---|---|---|---|
| スカウトの送信数、返信数 | 媒体の管理画面 | 文面と相手の絞り方が効いているか | 自分（スカウトを担当していれば） |
| 応募数、応募の経路 | ATS、媒体 | 母集団の形成が足りているか | 自分か依頼側（求人票の担当による） |
| 書類の通過数 | ATS | 選考の基準と応募の質 | 依頼側 |
| 日程の提示から確定までの日数 | ATS、自分の記録 | 日程調整が速いか | 自分と依頼側 |
| 辞退の数と理由 | ATS、自分の記録 | どの工程で、なぜ離れているか | 工程による |
| 面接の実施数、通過数 | ATS | 面接の判断 | 依頼側 |
| 内定数、承諾数 | ATS | 条件と候補者の判断 | 依頼側 |
| 自分の稼働の時間 | 稼働ログ | 工程ごとの稼働 | 自分 |

種類の要点は、「出どころが依頼側の記録であるデータは、依頼側の仕組みの中で見る」ことです。ATSと媒体の管理画面の集計の機能で、工程ごとの数は出せます。それを自分の側に写す場合は、集計の結果（月ごとの数字の表）だけにし、候補者ごとの一覧は写しません。工程ごとの出口の考え方は[KPIを設計する](/media/fukugyo-kpi-sekkei-skill/)に、記録が無い場合の整え方は[稼働ログの付け方](/media/fukugyo-log/)に書いています。

### エラベルの見解

相談で最も多い思い込みは、「データを扱えるようになるには、分析の勉強が要る」というものです。実際には、依頼側から「数字で示してくれて助かる」と評価されている担当者の多くは、分析の手法を知りません。やっているのは、毎月、ATSと媒体の管理画面から工程ごとの数を取り、表計算に月ごとに並べ、先月と比べ、落ち幅が大きい工程を見つけ、一つの数字を比較で語ることです。統計の知識は使っていません。

見ていて差がつくのは、「毎月、同じ項目を取っているか」です。同じ項目を毎月取っていれば、数か月で比較ができ、変化が見え、止まっている場所が分かります。取る項目が月ごとに違ったり、取ったり取らなかったりする人は、データがあっても比べられず、「数字はあるが何も分からない」状態になります。エラベルでは、担当者の稼働報告に、依頼側の記録から取った同じ項目の数字を毎月書く形をお願いしていますが、それはデータを扱う力の最も簡単な形です。データの力は、手法ではなく、同じものを毎月見る習慣です。

## 四つの手順

データを扱う一連を、四つの手順にします。月に一度、稼働報告と同じ日に回します。

| 手順 | 内容 | 使う機能 |
|---|---|---|
| 一、取る | 依頼側の記録から、工程ごとの出口の数を、同じ項目で取る。表計算に、行が月、列が項目の形で並べる | ATSと媒体の集計の機能。表計算への転記 |
| 二、比べる | 先月、先々月、入る前（起点）と比べる。増えたか、減ったか、変わらないか | 表計算の並び。差の列 |
| 三、見つける | 工程の間の落ち幅（前の工程の出口から次の工程の出口への減り方）を見て、最も大きい工程を見つける | 表計算の割り算。一つの列を足す |
| 四、語る | 落ち幅が大きい工程と、そこで起きていることを、一つの数字を比較と工程と範囲で、一文にする | 文章。[数字で語る](/media/fukugyo-suuji/) |

四つの要点は、「一」で同じ項目を取り続けることが、他の三つの土台になることです。項目が揃っていれば、比べる、見つける、語るは、表計算の簡単な操作と一文で済みます。項目が揃っていないと、比べられず、見つけられず、語れません。起点の作り方は[現状把握のしかた](/media/fukugyo-genjou-haaku/)に、止まっている場所の見つけ方は[課題を構造化する](/media/fukugyo-kouzou-ka/)に整理しています。

## データを依頼側の外に出さない線

データを扱うとき、情報の線があります。分析のために、線を越えやすい場面があります。

| 場面 | 線 | 代わりに |
|---|---|---|
| ATSの候補者の一覧を、自分の表計算に丸ごと写して分析する | 候補者の情報が依頼側の外に出る | ATSの集計の機能で、工程ごとの数だけを出し、その数だけを自分の表に |
| 依頼側の記録を、AIのサービスに貼って分析させる | 依頼側の情報を外部に渡す。[AIをどう使うか](/media/fukugyo-ai-katsuyou/) | 集計は表計算で、自分で |
| 分析の結果を、自分の発信に書く | 依頼側の数字は依頼側の情報 | 判断の仕方（「落ち幅を見る」）だけを書く。数字は書かない |
| 他の依頼側の数字と比べる | 守秘の線 | 比べない。その依頼側の過去との比較だけ |
| 集計の結果を、依頼側の名前と一緒に自分の側に残す | 案件の終了後に残ると問題になり得る | 自分の側に残すなら、依頼側が特定できない形（案件のタグだけ） |
| 依頼側の記録に、自分の推定を混ぜて集計する | 依頼側が確認できない数字になる | 記録から取れる数字だけ。推定は書かない |

線の要点は、「候補者の一覧を写さず、集計の結果だけを持つ」ことです。分析のために候補者の一覧を自分の表に写したくなりますが、それは候補者の情報を依頼側の外に出すことです。ATSの集計の機能で工程ごとの数を出し、その数だけを自分の表に並べれば、分析はでき、情報は出ません。情報の分け方は[案件ごとの情報の分け方](/media/fukugyo-jouhou-bunri/)に、守秘の線は[守秘の線を越える](/media/fukugyo-shippai-8/)に書いています。

## 小さい数字の扱い

副業の案件の数字は、小さいことが多いです。小さい数字の扱いを間違えると、偶然を効果と取り違えます。

| 状況 | 起きること | 扱い |
|---|---|---|
| 送信が月に数十件、返信が数件 | 一か月の変化が偶然の幅に入る | 二か月か三か月で見る。「傾向として」と添える |
| 割合で見ると大きく動く | 母数が小さいと、一件の差で割合が大きく変わる | 割合と実数を一緒に出す。実数の差で見る |
| 一件の辞退で数字が変わった | 一件の出来事が、全体の傾向に見える | その一件の理由を記録で見る。傾向とは分けて語る |
| 変えた月に、他の要因もあった | 自分の変更の効果か、他の要因か分からない | 他の要因を記録に書き、判断を保留する。翌月も見る |
| 効いたように見えるが、数字が小さい | 断定すると、翌月に戻って信用を失う | 「効いていると見ているが、数か月見て判断する」 |

小さい数字の要点は、「断定しない」ことです。小さい数字で「効いた」と断定し、翌月に戻ると、依頼側は「前の報告は何だったのか」となります。「傾向として」「数か月見て判断する」と添えれば、翌月に戻っても、報告の信頼は保てます。断定を避ける書き方は[数字で語る](/media/fukugyo-suuji/)に、改善の効果の見方は[改善を回す](/media/fukugyo-kaizen/)に整理しています。

## データで失敗する場面

データを扱う中で、副業の担当者が起こしやすい失敗です。

| 失敗 | 何が起きるか | 防ぎ方 |
|---|---|---|
| 項目が月ごとに違う | 比べられない | 最初に項目を決め、変えない |
| 候補者の一覧を自分の表に写す | 情報の線を越える | 集計の結果だけ |
| 数字を並べるだけで、語らない | 依頼側は「で、どうなのか」 | 一つの数字を比較と工程で一文に |
| 因果を断定する | 「文面を変えたから増えた」と言い切り、他の要因があると信用を失う | 「〇〇と見ている。他の要因もあるかもしれない」 |
| 依頼側の範囲の数字を自分の成果にする | 内定数を自分の成果と言う | 自分の範囲の出口と、依頼側の範囲を分ける |
| 見栄えのグラフに時間をかける | 副業の枠を圧迫する。判断に関係ない | 表で足りる |
| 悪い数字を出さない | 記録で分かったときに報告全体が疑われる | 減った数字も、理由の見立てと一緒に |
| 数字を見て、何もしない | 見るだけで、弱い場所に手を打たない | 見た月に一つ変える |

失敗の要点は、「項目が月ごとに違う」が最初に起きやすく、他の全部の土台を崩すことです。項目が揃っていなければ、比べられず、見つけられず、語れず、改善もできません。最初に項目を決めて、変えない。それだけで、データを扱う力の半分はできます。

## 身につける順番

データを扱う力を、副業の中で身につける順番です。勉強からではなく、案件の中で身につけます。

| 順 | やること | 身につくもの |
|---|---|---|
| 一、自分の稼働ログを付ける | 日付、工程、時間を表計算に。月末に工程ごとに集計する | 同じ項目を毎日取り、月末に集計する習慣。表計算の集計の機能 |
| 二、依頼側の記録から、自分の範囲の出口の数を毎月取る | 送信数、返信数、面接の設定数のように、自分の範囲の出口を月ごとに並べる | 依頼側の記録の集計の機能。同じ項目を毎月取る習慣 |
| 三、先月と比べて、稼働報告の「状態の変化」に一文書く | 増えたか減ったかを、一つの数字で | 比べる力。語る力 |
| 四、工程の間の落ち幅を見て、止まっている場所を見つける | 前の工程の出口から次の出口への減り方を、割り算で | 見つける力。課題の構造化 |
| 五、一つ変えて、翌月に同じ数字で比べる | 改善を回す | 効果の見方。因果を断定しない習慣 |
| 六、依頼側の採用全体の工程の出口を並べ、KPIの一枚にする | 自分の範囲と依頼側の範囲を分けて | 全体を見る力。範囲で分ける力 |

順番の要点は、「一」の自分の稼働ログから始めることです。稼働ログは、同じ項目を毎日取り、月末に集計する、というデータを扱う力の基本の形で、依頼側の情報を含まないので、練習に最も適しています。稼働ログが習慣になれば、依頼側の記録を取ることも、比べることも、同じ形でできます。ログの付け方は[稼働ログの付け方](/media/fukugyo-log/)に、KPIの一枚は[KPIを設計する](/media/fukugyo-kpi-sekkei-skill/)に書いています。

### エラベルの見解

担当する側から見ると、「データで示してくれる」と依頼側に評価されている人は、分析の勉強をした人ではなく、自分の稼働ログを毎日付け、依頼側の記録から同じ項目を毎月取り、先月と比べて一文で語り、落ち幅を見て一つ変えている人です。全部が表計算の集計と絞り込みでできていて、統計の手法は使っていません。分析の勉強から入った人は、手法は知っていても、毎月同じ項目を取る習慣が無く、比べられるデータを持っていません。

順番として、自分の稼働ログから始めて同じ項目を毎日取る習慣を作り、依頼側の記録から自分の範囲の出口を毎月取り、先月と比べて一文で語り、落ち幅で止まっている場所を見つけ、一つ変えて翌月に比べ、全体の工程をKPIの一枚にする。この順番で、データを扱う力は、勉強ではなく案件の中で身につきます。エラベルでは、担当者の稼働報告に依頼側の記録から取った同じ項目の数字を毎月書く形をお願いしていますが、それはデータを扱う力を、報告の副産物として身につける仕組みでもあります。データの力は、手法ではなく、同じものを毎月見て語る習慣です。

## まとめ

- 副業で要るデータの力は**記録から取る・以前と比べる・止まっている場所を見つける・一つの数字で語る**の一連。分析の手法は要らない
- 扱うデータの出どころは**依頼側の記録（ATS・媒体の管理画面）と自分の稼働ログ**。依頼側の仕組みの中で見る
- 四つの手順の土台は**同じ項目を毎月取ること**。項目を変えない
- **候補者の一覧を自分の表に写さず、集計の結果だけを持つ**。AIに記録を貼らない。他の依頼側と比べない
- 小さい数字は**断定しない**。数か月で見て、割合と実数を一緒に、他の要因を記録する
- 失敗は**項目が違う・一覧を写す・語らない・因果を断定・依頼側の範囲を自分の成果に・グラフに時間・悪い数字を隠す・見て何もしない**
- 身につける順番は**稼働ログ→自分の範囲の出口→比べて一文→落ち幅→一つ変えて比べる→KPIの一枚**

## よくある質問

### 依頼側から「もっと高度な分析をしてほしい」と言われました

「高度な分析」が何を指すかを確かめます。多くの場合、依頼側が求めているのは、統計の手法ではなく、「工程ごとの数字を、職種ごと・媒体ごとに分けて見たい」「どこで止まっているかを知りたい」のような、集計の切り口の追加です。それは表計算の絞り込みでできます。本当に統計の手法が要る分析を求められたら、自分の範囲の外であることを伝え、依頼側の社内の分析の担当者か、専門の外部に頼む形を提案します。範囲の外の依頼の伝え方は[無理なときの伝え方](/media/fukugyo-warukunai-kotowari/)に整理しています。

### 依頼側のATSの集計の機能が弱く、工程ごとの数字が出せません

ATSの集計で出ないなら、ATSの一覧を画面で見ながら、工程ごとの数を手で数えて、自分の表に数だけを書きます。一覧を自分の表に写すのではなく、数えた結果の数だけを書く形です。数える手間はかかりますが、月に一度、数十件から数百件なら、副業の枠に入ります。数える項目を最初から絞れば、時間は短くて済みます。記録が無い工程は、記録を始めることから。整え方は[KPIを設計する](/media/fukugyo-kpi-sekkei-skill/)に書いています。

### 数字に強くないので、データの報告に自信がありません

数字に強い必要はなく、同じ項目を毎月取って、先月と比べて、増えたか減ったかを一文で言えれば足ります。「先月の〇件から今月は△件で、増えています」は、数字に強くなくても言えます。落ち幅も、前の工程の出口の数と次の出口の数を並べれば、どこで大きく減っているかは見れば分かります。自信が無いなら、自分の稼働ログから始めて、集計と比較の習慣を作れば、依頼側の記録でも同じことができるようになります。語り方の型は[数字で語る](/media/fukugyo-suuji/)に整理しています。

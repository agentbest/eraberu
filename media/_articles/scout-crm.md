スカウトで返信が来た候補者、面談した候補者、「今は動けない」と言った候補者。一人ひとりを追いかけたい。今どの段階にいて、次に誰が何をするか、いつまでに、を見たい。しかし、送信ログには「送った」「返信が来た」はあっても、候補者ごとの今の状態が無い。CRMのツールを入れてみたが、担当者が使わず、表とツールに情報が分かれた。結論を先に書くと、**候補者CRMは、「ツールを入れる」ことではなく、「一人一行」「段階」「次の行動と期日」「担当」「履歴」の五つを持つ一つの表を作り、毎日見る運用を回すことです。表で回ってから、道具に移すかを判断します。表で回らない運用は、道具に移しても回りません**。送信ログの列と場所は[送信ログの残し方](/media/scout-log/)に、追客の段階ごとの型は[追客（フォローアップ）の設計](/media/scout-tsuiokuri/)にまとめています。

## 候補者管理が回らない構造

候補者を一人ひとり追いかける運用が回らないのは、次の構造で起きます。

| 構造 | 起きていること |
|---|---|
| 送信ログしか無い | 「送った」「返信が来た」の記録はあるが、候補者ごとの「今」が無い |
| 一人が複数行に散っている | 送信のたびに行が増え、同じ候補者の行が離れ、今の状態が分からない |
| 段階が定義されていない | 「返信あり」「面談済み」が、担当者ごとに違う意味 |
| 次の行動が無い | 「面談した」で止まり、「次に誰が何を、いつまでに」が無い |
| 担当が無い | 候補者ごとに誰が追うかが決まっておらず、全員が誰も追わない |
| 履歴が無い | 前回何を話したかが無く、次の連絡で同じことを聞く |
| ツールを先に入れた | 表で回っていない運用をツールに載せ、入力されず、表と二重になる |
| 毎日見ていない | 表はあるが、週に一度しか開かず、期日を過ぎた行動が溜まる |

構造の大半は、「候補者ごとの今と次が無い」ことです。送信ログは「送った記録」で、CRMは「候補者の状態」です。役割が違います。

## CRMの目的

何のために候補者CRMを持つかで、列と運用が決まります。目的は三つです。

| 目的 | 内容 | 必要な情報 |
|---|---|---|
| 止まっている候補者を拾う | 段階が進まないまま期日を過ぎた候補者を、毎日見つけて動かす | 段階、次の行動と期日、担当 |
| 候補者ごとの文脈を引き継ぐ | 前回のやり取り、相手の希望、時期、懸念を、次の連絡で使う | 履歴、備考 |
| 状態を集計する | 段階ごとに何人いるか、どの段階で止まっているか | 段階、日付 |

三つの要点は、「止まっている候補者を拾う」が最初にあることです。CRMは分析の道具である前に、「今日、誰に何をするか」を出す道具です。毎日開いて、期日を過ぎた行動を拾う。それができない表は、CRMではありません。

## 最低限の五つの列

候補者CRMに、最低限必要な列です。五つあれば回ります。

| 列 | 内容 | 無いと起きること |
|---|---|---|
| 一人一行（識別） | 候補者ごとに一行。媒体のID、表示名、現職。送信ログの識別と同じ | 同じ候補者が散り、今の状態が分からない |
| 段階 | 今どの段階か。定義した段階の一覧から選ぶ | 担当者ごとに意味が違い、集計できない |
| 次の行動と期日 | 次に何をするか（返答、日程の提示、追客、条件の確認）と、いつまでに | 「面談した」で止まり、放置される |
| 担当 | その候補者を誰が追うか。名前で | 全員が誰も追わない |
| 履歴 | 日付と要点。「〇月〇日、面談。〇〇に関心。時期は△月以降」。長く書かない | 前回の内容が引き継がれない |

五つの列に、あれば良い列として、役割、媒体、最初の送信日、相手の希望（時期、条件）、懸念、辞退の理由、を足します。ただし、最初は五つで始めます。列が多いと、入力されません。

## 段階の定義

「段階」の列に入れる値を、先に定義します。担当者ごとに意味が違わないように、一覧にします。

| 段階 | 状態 | 次の行動の例 | 目安の期日 |
|---|---|---|---|
| 送信済み | スカウトを送り、返信待ち | 二通目の判断 | 一〜二週間後 |
| 返信あり | 返信が来て、返答前 | 返答と日程の提示 | 当日か翌営業日 |
| 日程調整中 | 返答済み、日程の確定前 | 候補の再提示、追客 | 三日後 |
| 面談予定 | 日程が確定 | 前日の確認、当日の面談 | 前日 |
| 面談済み | 面談が終わり、次の連絡前 | 感謝と次の流れの連絡 | 翌営業日 |
| 応募検討中 | 面談の後、応募の意思の確認前 | 追客（材料の追加） | 一週間後 |
| 選考中 | 応募し、選考の途中 | 選考の進行、書類の確認 | 選考の各段 |
| 内定 | 内定を出し、返事待ち | 迷いの確認、期限の連絡 | 期限の三日前 |
| 今は動けない | 相手が時期を言った | 時期の少し前に再送 | 相手の時期の一か月前 |
| 辞退・見送り | 終了。理由を記録 | 三か月後に再送の対象へ | 三か月後 |
| 連絡不要 | 意思の表明。送らない | 無し | — |

定義の要点は、「段階ごとに次の行動と期日の目安が決まる」ことです。段階を入れれば、次の行動と期日が自動で決まる形にしておくと、入力の手間が減り、抜けも減ります。段階の動きの速さは[スカウトはスピードでどれだけ変わるか](/media/scout-sokudo/)に書いています。

## 運用の型

表を持った後、回すための運用です。表があっても、運用が無ければ回りません。

| タイミング | 誰が | 何を |
|---|---|---|
| 送信のたび | 送った人 | 一行を作る（または既存の行の段階を更新） |
| 返信が来たとき | 受けた人 | 段階を「返信あり」に、次の行動と期日を入れる。当日 |
| 毎営業日の決めた時間 | 担当者 | 期日が今日までの行動を全部見て、実施するか、期日を更新する。十五分 |
| 面談の後 | 面談した人か人事 | 段階と履歴を当日に。面談以降は社内が書く |
| 週に一度 | 担当者と発注側 | 段階ごとの人数と、期日を過ぎた行動の数を見る。止まっている候補者を拾う |
| 月に一度 | 発注側 | 段階ごとの人数の推移。辞退の理由の内訳。表の抜けと誤り |
| 段階が「辞退・見送り」「連絡不要」になったとき | 担当者 | 理由を記録し、再送の対象か送ってはいけない一覧かに振り分ける |

運用の要点は、「毎営業日の決めた時間に、期日が今日までの行動を全部見る」ことです。これが、CRMの中心の動きです。この十五分が無ければ、表は記録の置き場になり、候補者は放置されます。

### エラベルの見解

相談で最も多い失敗は、「候補者管理のツールを入れたが、担当者は送信ログの表を使い続け、ツールには面談の予定だけが入り、三か月後にツールと表のどちらが正しいか誰も分からなくなった」というものです。表で回る運用が無いまま、ツールを入れていました。ツールを止め、送信ログとは別に五つの列の表を作り、毎営業日に期日が今日までの行動を見る十五分を担当者の予定に入れたら、放置される候補者が無くなりました。半年後、表で回っていたので、道具に移すときも迷いませんでした。

見ていて差がつくのは、担当者が「次の行動と期日」を空欄にしないかです。段階だけ更新して、次の行動を空欄にする担当者と、「段階を変えたら、必ずしも同じ日ではなくても、次の行動と期日を同時に入れます」と言う担当者がいます。後者の表は、毎日見ると「今日やること」が出ます。前者の表は、見ても何をすればよいか分かりません。

発注側にできるのは、週に一度、「次の行動が空欄の行」と「期日を過ぎた行」の数を担当者と見ることです。

## 送信ログとの関係

送信ログと候補者CRMは、別の表です。役割と関係を整理します。

| 項目 | 送信ログ | 候補者CRM |
|---|---|---|
| 一行の単位 | 一通の送信 | 一人の候補者 |
| 目的 | 送った記録。再送の判断、効果の検証、重複の防止 | 候補者の今と次。止まっている候補者を拾う |
| 主に書く人 | 送った人（担当者） | 担当者と、面談以降は社内 |
| 見る頻度 | 送信のたびに書き、月次で集計 | 毎営業日に見る |
| つなぎ | 候補者の識別（媒体のIDなど）で紐づける。送信ログの返信の記録と、CRMの「返信あり」の段階は同じ事実 | |
| 一つにする場合 | 候補者ごとの行に、送信の履歴を持たせる形。行が長くなるが、表が一つで済む | |

関係の要点は、「識別を同じにする」ことです。送信ログの候補者の識別と、CRMの識別が同じなら、二つの表は紐づきます。違うと、「送信ログのこの人は、CRMのどの人か」が分からなくなります。最初から、同じ識別を使います。小さい運用なら、一つの表に「送信の履歴」の列を持たせて、一つにしても構いません。

## 道具に移す判断

表で回った後、CRMのツールに移すかを判断する観点です。

| 観点 | 移す目安 | 移さない目安 |
|---|---|---|
| 候補者の数 | 表で見きれない数になった（毎営業日の十五分で回らない） | 表で回っている |
| 担当者の数 | 複数の担当者が同時に書き、衝突や重複が起きている | 一人か二人で、衝突が無い |
| 通知と自動の予定 | 期日の通知や、段階を変えたときの次の行動の自動の設定が要る | 手で見て回っている |
| 媒体との接続 | 媒体の返信や面談の予定を、自動で取り込みたい | 手の入力で間に合う |
| 記録の持ち出し | 移した後も、表に出せるツールがある | 出せないツールしか無い |
| 運用の型 | 表で回っている運用の型が、ツールに載る | ツールの型に運用を合わせることになる |

判断の要点は、「表で回っている運用の型を、ツールに載せる」ことです。ツールの型に運用を合わせると、担当者は使いません。表で回った型を持ち込み、その型が載るツールを選びます。ツールの選び方は[スカウト支援ツールの選び方](/media/scout-tool/)に、応募者管理の表の回し方は[応募者管理がスプレッドシートのまま](/media/rpo-ats-nai/)に書いています。

## 外注する場合の範囲

候補者CRMの構築と運用を、スカウト代行に出す場合の範囲です。

**出せる工程。** 段階の定義の下書き、五つの列の表の設計、送信ログとの識別の統一、送信と返信の記録の当日の記入、毎営業日の期日の確認と行動の実施（担当者が行う行動）、社内が行う行動の依頼と確認、週次の止まっている候補者の抽出、辞退と見送りの理由の記録と振り分け、月次の段階の推移の報告、道具に移す判断の材料の整理と試用の実施。

**社内に残す判断。** 段階の定義の承認、面談以降の段階と履歴の記入（社内で起きること）、社内の人が行う行動（面談後の連絡、条件の提示など）の実施、担当の割り当て（社内の人が追う候補者）、表の所在（自社の管理下）、道具に移す決定と費用、個人情報の扱い（履歴の書き方、閲覧の権限、保管の期間。法令は専門家に）。

**外注の効きどころ。** 候補者CRMは、「一人一行で、段階と次の行動と期日と担当を持ち、毎営業日に見る」運用で、社内では「送信ログしか無い」か「ツールを入れて使わない」になりやすい工程です。担当者が段階を定義し、表を作り、毎営業日の十五分を回し、止まっている候補者を拾えば、候補者は放置されません。担当者は複数の会社の候補者管理を見ているので、「この段階の期日はこの目安」「この列は要らない」を持ち込めます。ただし、面談以降の記入と、社内の人が行う行動は、社内からしか出ません。

**外注しても動かない場合。** 面談以降を社内が書かない、社内の人が行う行動の期日を守らない、段階の定義を承認しない、表を代行の手元に置く、運用が回る前にツールを入れる。社内の判断で、代行を替えても直りません。

候補者CRMは、五つの列の一つの表と、毎営業日の十五分から始め、回ってから道具に移せば、候補者は放置されず、道具も使われます。外注は、表の設計と当日の記入と毎営業日の確認と止まっている候補者の抽出を担う手段です。

### エラベルの見解

担当する側から見ると、候補者CRMの相談で最も多いのは、「面談以降の段階が更新されない」ことです。担当者は「面談予定」までは書ける。面談が終わった後、応募したのか、選考のどこにいるのか、内定が出たのか、辞退したのかは、社内で起きるので、社内の人が書かないと更新されません。結果、CRMの半分が「面談予定」で止まり、面談以降の候補者が見えなくなります。

面談以降の段階を書く人を、名前で決める。「面談した人が、当日に、段階と一行の履歴を書く」。それだけで、CRMは最後まで動きます。書く量は、一人につき一行です。

発注側にできるのは、面談の担当者に、「面談の当日に、表の段階を一つ動かして、一行書いてください」を頼み、その時間を面談の枠に含めることです。

## まとめ

- 回らないのは**送信ログしか無い・一人が複数行・段階が無い・次の行動が無い・担当が無い・履歴が無い・ツールを先に・毎日見ない**構造
- 目的は**止まっている候補者を拾う・文脈を引き継ぐ・状態を集計する**。最初は「今日、誰に何をするか」
- 列は**一人一行・段階・次の行動と期日・担当・履歴**の五つ。最初は五つで始める
- 段階は**送信済み・返信あり・日程調整中・面談予定・面談済み・応募検討中・選考中・内定・今は動けない・辞退・連絡不要**。段階ごとに次の行動と期日の目安
- 運用は**送信のたび・返信の当日・毎営業日の十五分（期日が今日までの行動）・面談の当日・週次・月次・終了時の振り分け**
- 送信ログとは**別の表で、識別を同じに**。小さい運用なら一つでも
- 道具に移すのは**表で見きれない・担当者が複数で衝突・通知と自動が要る・接続が要る・持ち出せる・運用の型が載る**とき
- 外注できるのは**段階の下書き・表の設計・識別の統一・当日の記入・毎営業日の確認と実施・依頼と確認・抽出・理由の記録・報告・道具の材料と試用**。社内に残るのは**定義の承認・面談以降の記入・社内の行動・担当の割り当て・所在・道具の決定・個人情報**

## よくある質問

### 送信ログとCRMを別にすると、二重に入力することになりませんか

「送った」という事実は、送信ログに一行、CRMでは段階を「送信済み」にする、の二か所に入りますが、CRMの側は行を作るときの一回だけです。返信以降は、送信ログには返信の有無だけ、CRMには段階と次の行動と履歴、と役割が分かれるので、二重にはなりません。それでも手間なら、一つの表に「送信の履歴」の列を持たせて一つにします。候補者が数十人までなら一つで回ります。

### 「今は動けない」と言った候補者は、CRMに残しておくべきですか

残します。段階を「今は動けない」にし、次の行動を「時期の少し前に再送」、期日を相手が言った時期の一か月前にします。毎営業日の確認で、期日が来たときに拾えます。相手が時期を言わなかった場合は、三か月後を期日にします。「動けない」の候補者は、時期が来れば最も近い候補者です。時間を空けた再送の書き方は[時間を空けて再送するときの書き方](/media/scout-kikan-aketa/)に、溜めた候補者の動かし方は[タレントプールの育て方](/media/scout-talent-pool/)に書いています。

### 履歴には、どこまで書いてよいですか

次の連絡で使う要点だけです。「〇月〇日、面談。〇〇に関心。時期は△月以降。年収の希望は□□」のように、一行。面談の詳細な評価や、候補者の私的な事情は書きません。履歴は個人情報で、閲覧できる人が読むものです。評価は別の場所に、権限を絞って置きます。書く範囲と保管の期間は、社内の方針と法令に沿って、専門家に確認してください。個人情報の扱いは[スカウトで得た個人情報の扱い](/media/scout-kojin-jouhou-toriatsukai/)に書いています。

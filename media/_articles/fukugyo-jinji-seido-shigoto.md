人事制度（等級・評価・報酬）の設計を副業で受けるとき、見えにくいのは「誰が何を決め、誰が何を確かめ、自分は何をするか」の役割の線です。募集文には「人事制度の構築」とだけあり、実際には、経営者が決めること、専門家（社会保険労務士など）が確かめること、副業の人が材料と進行を担うこと、の三つが混ざったまま始まりやすく、混ざったまま進むと、責任だけが副業の人に残ります。結論を先に書くと、**1案件は「契約前→現状の整理→設計の材料と選択肢→会社の決定と専門家の確認→導入の進行と説明の支援→運用の定着と見直し」の六つの段階で進み、契約前に三つの条件（設計から運用まで見た経験・専門家の関与・決めるのは会社）を確かめて範囲を工程で分け、現状の整理で処遇の実態と声と困りごとを課題の一覧にし、絞った課題について等級・評価・報酬のつながりを構造で示して選択肢と全体の影響を出し、会社が決めて理由を書面にし、専門家が就業規則と労務を確かめ、導入の計画と説明の資料と進行を支え、最初の評価の期間の運用を伴走して一年後の見直しの材料を残して終えます。**案件の型と受けてよいかの条件は[人事制度の設計の副業案件](/media/fukugyo-jinji-seido-fukugyo/)に書いていますので、ここでは「1案件の流れ」に絞ります。

## 契約前：決めておくこと

この仕事は、契約前に決めていないことが、社員の処遇の事故になって返ってきます。他の案件より時間をかけて決めます。

| 決めること | 確かめる中身 | 決めていないと起きること |
|---|---|---|
| 三つの条件 | 自分に設計から運用まで見た経験があるか。専門家が関与し費用は会社が持つか。決めるのは会社と理解しているか | 揃わないなら受けない。手前の範囲（現状の整理）を提案 |
| 範囲を工程で分ける | 現状の整理、材料と選択肢、導入の進行、運用の定着、を別々の範囲と見積もりに。一括で受けない | 「全部作って」の丸投げになる |
| 決める人 | 等級の定義、評価の基準、報酬の水準を決めるのは誰か（経営者）。決めるまでの期限 | 決まらず、副業の人が決めた形になる |
| 専門家の関与と費用 | 誰（社会保険労務士など）が、どの段階で（選択肢の前か、決定の後か）、何を確かめるか。費用は会社 | 就業規則と労務の判断が抜ける |
| 聞いたことの扱い | 現状の整理で聞く管理職と社員の声を、誰にどう共有するか（個人が特定されない形で）。個人の処遇の情報の扱い | 声を話した社員が特定され、話す人がいなくなる |
| 個人の処遇に入らないこと | 誰を何等級に、誰の報酬をいくらに、は会社。副業の人は構造と全体の分布まで | 個人の判断に巻き込まれる |
| 終わりの定義 | 導入の日か、最初の評価の期間の終わりか。評価の基準 | 導入で終わり、運用で歪む |
| 説明の場の役割 | 社員への説明で話すのは経営者と管理職。副業の人は資料と進行の補助 | 外の人が説明して、社員に「外から押しつけられた」と受け取られる |

止まりやすいのは、「まず制度の案を見せてほしい」で始めるときです。現状の整理の前に案を出すと、他社の制度を写した案になり、その会社に合いません。範囲の決め方は[業務範囲の決め方](/media/fukugyo-scope/)に、丸投げの見分け方は[丸投げ案件をどう扱うか](/media/fukugyo-marunage/)に書いています。

## 現状の整理：処遇の実態、声、困りごと、課題の一覧

設計の前に、いまの処遇がどう決まっているかを見ます。制度が無い会社にも、実態としての「決まり方」はあります。

| やること | 依頼側に持ってもらうこと | 落とし穴 |
|---|---|---|
| 処遇の実態（いま、誰が、何を基準に、昇給と昇格と評価を決めているか。書かれていない決まり） | 経営者と人事の時間。過去の昇給と昇格の記録（個人が特定されない形で） | 「制度が無い」で止まる。実態を見ない |
| 管理職の声（評価で困ること、部下に説明できないこと、他の管理職との差） | 管理職の時間（別々に） | 一緒に聞いて本音が出ない |
| 社員の声（何が評価されていると感じるか、納得していないこと、知りたいこと） | 社員の時間（別々に、または匿名の形で） | 聞いた人が特定される形で共有する |
| 困りごとの整理（評価の基準が無い、等級が無く滞留、報酬の説明ができない、逆転がある、など） | 困りごとの確認 | 全部を直そうとする |
| 課題の一覧と優先の案（最初に直す一つを提案。決めるのは会社） | 優先の決定 | 自分で優先を決める |

止まりやすいのは、社員の声を経営者にそのまま渡すときです。誰が言ったかが分かる形で渡すと、その社員が不利になり、次から誰も話しません。声は「構造」（何が起きているか）として渡し、人の評価として渡しません。聞き方は[ヒアリングの技能](/media/fukugyo-hearing-skill/)に、課題の絞り方は[課題の言語化](/media/fukugyo-kadai-teigi/)に書いています。

### エラベルの見解

担当する側から見ると、この仕事は「現状の整理で、いまの『書かれていない決まり』を言葉にできるか」で、設計の質が決まります。制度が無い会社でも、昇給と昇格は実際に起きていて、そこには経営者の頭の中の基準があります。「去年昇格した人と、しなかった人の違いは何でしたか」と聞くと、その基準が言葉になります。それを無視して他社の制度を持ち込むと、経営者は「うちはそうじゃない」と運用で例外を作り、制度は形だけになります。エラベルで担当者を選ぶ企業には、「最初に、いまの昇給と昇格がどう決まってきたかを一緒に言葉にします。制度は、その言葉を土台に作ります」と、私たちから先に伝えています。受ける側がその場で使える判断としては、現状の整理の記録に「書かれていない決まり」の欄を作り、経営者の言葉のまま残すこと。設計の材料は、その欄から作ります。

## 設計の材料と選択肢：つながりの構造、選択肢、全体の影響

絞った課題について、材料と選択肢を出します。数字（報酬の水準）は会社が入れ、自分は構造までです。

| 作るもの | 中身 | 落とし穴 |
|---|---|---|
| つながりの構造 | 等級（何で段階を分けるか）→評価（何を見るか、誰が、いつ）→報酬（等級と評価がどう報酬に結びつくか）を、一枚で | 一つだけを設計して、他とのつながりを見ない |
| 選択肢（二〜三） | 例：等級を役割で分けるか能力で分けるか。評価を目標で見るか行動で見るか。報酬を等級で決めるか評価で動かすか。それぞれの向く会社の段階 | 一つの「正解」を出す |
| 全体の影響 | 選択肢ごとに、いまの社員を当てたとき、何等級に何人になるか、報酬が上がる人と下がる人がどのくらい出るか（個人名は出さない） | 個人の名前で影響を出す |
| 運用で歪みやすい箇所 | 評価者の甘辛、等級の滞留、経営者の例外、報酬の逆転、が起きやすい箇所と、避ける設計 | 運用を見ずに設計する |
| 専門家に確認する論点の一覧 | 就業規則の変更、不利益になる人の扱い、手当や賞与の扱い、など。判断は専門家 | 自分で判断して書く |

止まりやすいのは、選択肢を出さずに「この制度がよいです」と一つを出すときです。会社が自分で選ばなかった制度は、運用で経営者が守りません。選択肢の出し方は[提案のまとめ方](/media/fukugyo-teian/)に書いています。

## 会社の決定と専門家の確認

会社が選び、理由を書面にし、専門家が確かめます。この順を飛ばしません。

| 順 | やること | 落とし穴 |
|---|---|---|
| 一 | 経営者が選択肢から選び、理由を、経営者の名前で書面に残す | 経営者が「任せる」と言い、副業の人が決める |
| 二 | 報酬の水準など数字を会社が入れる | 副業の人が数字を入れる |
| 三 | 専門家（社会保険労務士など）が、就業規則の変更、不利益になる人の扱い、法令の論点を確かめる | 専門家の確認を飛ばす、または後回しにする |
| 四 | 専門家の指摘を設計に反映し、再度、会社が確認する | 指摘を副業の人の判断で処理する |
| 五 | 決まった制度の全体（構造、数字、移行の扱い）を、会社の文書として確定する | 副業の人の資料のまま導入する |

止まりやすいのは、専門家の確認を「導入の直前に」と後回しにするときです。確認で構造が変わることがあり、直前だと導入が崩れます。選択肢の段階で論点の一覧を渡し、決定の直後に確認してもらいます。個別の判断は専門家にご確認ください。

### エラベルの見解

同じ料金・同じ範囲でも、結果が分かれるのは、「専門家をどの段階で入れるか」です。導入の直前に専門家に見せる担当者の案件は、就業規則や不利益になる人の扱いで構造の変更が入り、説明の直前に作り直しになり、経営者の信頼を失います。選択肢を出す段階で「専門家に確認する論点」の一覧を作り、決定の直後に専門家に渡す担当者の案件は、確認で大きく変わることが無く、導入の計画が守れます。副業の人が労務の判断をしないことは、責任を逃れるためではなく、会社と社員を守るためです。エラベルで長く続いている担当者は、設計の資料の最後に「専門家に確認する論点」の一枚を付け、それを会社と専門家の三者で共有しています。受ける側がその場で使える形としては、設計の各項目の横に「労務の確認が要るか」の印を付け、印の付いた項目は「専門家の確認後に確定」と書いておくことです。

## 導入の進行と説明の支援

決まった制度を、社員に届けます。説明の場で話すのは経営者と管理職で、副業の人は資料と進行の補助です。

| やること | 依頼側に持ってもらうこと | 落とし穴 |
|---|---|---|
| 導入の計画（説明の順：管理職→社員。移行期間。最初の評価の期間の始まり） | 計画の承認 | 社員に先に伝わる |
| 管理職への説明の資料と進行（なぜ変えるか、何が変わるか、管理職が何をするか、質問への答え） | 経営者が話す | 副業の人が説明する |
| 管理職の目線合わせの初回（評価の基準を、同じ人物の例で話し合う） | 管理職の時間 | 目線合わせをせずに評価を始める |
| 社員への説明の支援（資料、質問の想定と答え、個別の疑問の受け皿） | 経営者と管理職が話す。個人への通知は会社 | 個人の処遇の説明を副業の人がする |
| 移行期間の設計の補助（不利益になる人の扱いは専門家の確認に沿って） | 会社の決定と専門家の確認 | 移行期間を置かずに切り替える |
| 質問と不安の記録（説明の場で出た質問、個別に来た不安を、個人が特定されない形で） | 記録の共有先 | 記録せずに進む |

止まりやすいのは、社員への説明を副業の人がするときです。「外の人が作った制度を押しつけられた」と受け取られ、制度の信頼が最初から損なわれます。説明は会社の人が話し、副業の人は資料と進行と記録です。説明の資料の作り方は[資料の作り方](/media/fukugyo-shiryou/)に書いています。

## 運用の定着と見直し：最初の評価の期間、記録、一年後の材料、引き継ぎ

制度は、最初の評価の期間の運用で決まります。範囲に含めているなら、伴走します。

| 見ること | やること |
|---|---|
| 評価者の甘辛 | 評価の前に管理職の目線合わせの場を回す。評価の後に分布を並べて、差の理由を管理職に話してもらう（個人名は出さない形で） |
| 等級の滞留と逆転 | 当てた結果の分布を見て、基準の言葉が曖昧な箇所を直す材料を出す |
| 経営者の例外 | 例外が出たら記録し、「例外を制度に入れるか、例外のままにするか」を会社に決めてもらう |
| 社員の疑問 | 説明の場と個別の疑問の記録から、次の説明で足す項目を出す |
| 一年後の見直しの材料 | 分布、滞留、例外、疑問、管理職の困りごとを並べ、直す箇所の案を出す。決めるのは会社 |

終了時は、制度の文書（会社のもの）、つながりの構造の一枚、選択肢と決定の書面、専門家に確認した論点の一覧、説明の資料、目線合わせの進行の型、記録（個人が特定されない形）、一年後の見直しの材料を残し、社員の声と個人の処遇の情報を自分の手元に一切残しません。引き継ぎの型は[引き継ぎの仕方](/media/fukugyo-hikitsugi/)に書いています。

## 聞いた事情の扱い

制度の設計では、管理職と社員の声、個人の処遇（誰がいくらか、誰が昇格しなかったか）、経営者の人に対する評価を聞きます。他の副業案件より重い情報です。声は個人が特定されない「構造」として共有し、個人の処遇は会社の管理する場所でだけ扱い、自分の端末に残さず、影響の資料でも個人名を出しません。経営者が話した個人の評価は、記録にも書面にも残しません。会社の外で話さず、他の依頼側や本業に持ち込みません。本業や他の依頼側の制度や報酬の水準を、この会社に持ち込みません。個別の判断は専門家にご確認ください。利益相反の見分け方は[本業と利益相反になる案件](/media/fukugyo-riekisouhan/)に書いています。

## 稼働時間は何で決まるか

全体の時間は、「現状の整理（聞き取りの人数）」「材料と選択肢（課題の数と、会社の決定を待つ期間）」「専門家との調整」「導入の進行（説明の場の回数、管理職の人数）」「運用の定着（最初の評価の期間の月数）」の合計で決まり、会社の決定を待つ期間と専門家の確認の期間は自分では縮められません。工程ごとに範囲と見積もりを分け、「決定待ちの期間は稼働に含めない」と決めておけば、見込みが立ちます。数値は案件ごとに違うので、現状の整理が終わった時点で、以後の工程を見直します。稼働の管理は[稼働時間の管理](/media/fukugyo-kadou-kanri/)に書いています。

## まとめ

- 1案件は**契約前→現状の整理→設計の材料と選択肢→会社の決定と専門家の確認→導入の進行と説明の支援→運用の定着と見直し**の六つの段階
- 契約前に**三つの条件・工程で分けた範囲・決める人・専門家の関与と費用・聞いたことの扱い・個人の処遇に入らないこと・終わりの定義・説明の場の役割**を決める。揃わないなら受けない
- 現状の整理は**書かれていない決まりを経営者の言葉で残し、管理職と社員の声を別々に聞き、構造として共有する**。他社の制度を持ち込まない
- 設計は**等級・評価・報酬のつながりを一枚に、二〜三の選択肢と全体の影響（個人名なし）、運用で歪む箇所、専門家に確認する論点**。数字は会社が入れる
- 決定は**経営者の名前で理由を書面に**、専門家の確認は**決定の直後に**。導入の直前に回さない
- 導入は**説明の順・管理職の目線合わせ・社員への説明は会社の人が話す・移行期間は専門家の確認に沿う**
- 定着は**評価者の甘辛・滞留と逆転・経営者の例外・社員の疑問**を記録し、一年後の見直しの材料を出す。決めるのは会社
- 声と個人の処遇は**構造として扱い、個人名を出さず、手元に残さず、外に持ち出さない**

## よくある質問

### 経営者が「案を三つも見せられても選べない。一つに絞ってほしい」と言います

理由付きの見立てを添えるのは構いません。「御社の段階と、現状の整理で出た『書かれていない決まり』に近いのはこちらです。理由はこの三点です。ただ、選ぶのは経営者ご自身でお願いします」と、見立てと決定を分けます。選択肢を一つにして出すと、経営者が自分で選んでいないので、運用で例外を作ります。三つが多いなら二つにし、それぞれの「向く会社」と「歪みやすい箇所」を並べて、経営者が比べられる形にします。

### 管理職が「新しい評価の基準では部下を評価できない」と言います

基準の言葉が曖昧か、目線合わせが足りないかのどちらかです。同じ人物の例（架空でよい）で、管理職が集まって「この人なら何点か」を話し合う場を回し、差が出た項目の言葉を直す材料を出します。管理職の困りごとは、制度を直す最も良い材料です。「評価できない」を管理職の能力の問題にせず、基準の言葉と目線合わせの問題として扱います。それでも埋まらない差は、会社に「基準を直すか、評価者を絞るか」を決めてもらいます。

### 導入の直前に、専門家から「この変更は手続きが要る」と指摘されました

設計を止め、専門家の指摘に沿って会社が対応を決めるのを待ちます。指摘を副業の人の判断で処理したり、導入の日を守るために指摘を先送りしたりしません。導入の日は延び、経営者は困りますが、手続きを飛ばした制度は、あとで社員との間で大きな問題になります。次の案件からは、選択肢の段階で「専門家に確認する論点」の一覧を渡し、決定の直後に確認してもらう順にします。個別の判断は専門家にご確認ください。

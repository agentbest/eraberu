人事のマネージャーとして、数人のチームを持ち、採用の計画を立て、経営と現場の間に立ってきた。副業で活かしたい。ただ、マネージャーの経験は「管理」で、副業で頼まれる「スカウトを送る」「求人票を書く」とはずれる気がする。作業を受けるには経験が重すぎ、管理を売るには副業の枠が小さい。結論を先に書くと、**マネージャー経験は、「管理していた」のままでは売れません。「仕組みを作った」「人を回した」「経営と現場をつないだ」の三つに分解し、それぞれを「手が動く形」にして、最初は一つに絞って出します。マネージャー経験で最も売れるのは、「作業をする」ことではなく、「作業が回る仕組みを作って渡す」ことです。ただし、副業の枠は小さいので、仕組みを作る範囲を絞り、判断は依頼側に残します**。三年目からの範囲の広げ方は[人事3年目からできること](/media/fukugyo-3nenme/)に、責任者・CHROの経験は[人事責任者・CHRO経験を活かす](/media/fukugyo-cho/)にまとめています。

## マネージャー経験が売りにくい構造

マネージャーの経験が、副業で売りにくく見えるのは、次の構造で起きます。

| 構造 | 起きていること |
|---|---|
| 「管理」を売ろうとしている | 「チームを管理していました」は、依頼側には「何をしてくれるか」が読めない |
| 作業から離れている | 自分で送信や求人票の作成をしなくなって数年。作業の案件を受けると、感覚が古い |
| 副業の枠が小さい | 週数時間で「管理」はできない。管理は常駐と継続を前提にしている |
| 全部できると書いてしまう | 採用、制度、評価、労務、育成。マネージャーは全部に関わったので、全部書き、一つも具体的でない |
| 判断に踏み込みたくなる | マネージャーは判断してきたので、副業でも合否や条件を「決めたく」なる。外部の立場では決めない |
| 単価が作業と合わない | 作業の単価では低すぎると感じ、管理の単価では副業の枠に合わない |
| 相手を選んでいない | 大手の人事部と、人事が一人の会社では、マネージャー経験の売れ方が違う |

構造の大半は、「管理をそのまま売ろうとしている」ことです。分解して、手が動く形にすれば、売れます。

## 経験の三つの分解

マネージャー経験を、三つに分解します。分解ごとに、売れるものが違います。

| 分解 | 内容 | 売れるもの |
|---|---|---|
| 仕組みを作った | 採用の型、手順、記録、指標、報告の形を作り、チームが回るようにした | 型と仕組みの設計と引き渡し。「自分がいなくても回る形」を作る力 |
| 人を回した | 担当者に業務を割り、育て、詰まりを解き、稼働を配った | 担当者の育成の補助、体制の設計、詰まりの特定。「回らない理由」を見つける力 |
| 経営と現場をつないだ | 経営の目標を採用の計画に落とし、現場の要件を言葉にし、両者の間で調整した | 要件の言葉化、計画の逆算、経営への報告の形。「通訳」の力 |

分解の要点は、「三つとも、作業ではなく、作業の周りの力」ということです。マネージャーは、作業を自分でやるより、作業が回る仕組みと人と関係を作ってきました。それが売れるものです。作業の案件を受けて「感覚が古い」と感じるのは、売るものを間違えているからです。

## 分解ごとに売れる業務と相手

三つの分解それぞれで、売れる業務と、売れる相手です。

| 分解 | 売れる業務 | 売れる相手 | 売れにくい相手 |
|---|---|---|---|
| 仕組みを作った | スカウト運用の立ち上げ、採用の記録と指標の設計、運用マニュアルの作成、型の作成と引き渡し | 人事が一人か少数で、仕組みが無い会社。「回る形を作ってほしい」 | 大手の人事部（仕組みは既にある） |
| 人を回した | 採用担当者の育成の補助、体制の設計、詰まりの特定と解消の提案、代行と社内の分担の設計 | 担当者はいるが回っていない会社。「なぜ回らないか分からない」 | 担当者がいない会社（回す人がいない） |
| 経営と現場をつないだ | 役割の要件の言葉化、採用の計画の逆算、経営向けの報告の形、現場との要件のすり合わせ | 経営が採用を理解していない会社、現場と人事がずれている会社 | 経営が自ら採用を回している小さい会社 |

相手の要点は、「人事が一人か少数で、仕組みが無い会社」です。マネージャー経験は、仕組みが無いところで最も効きます。仕組みがある大手では、マネージャーは社内にいます。売れる相手を選ぶと、案件は決まりやすくなります。

## 手が動く形にする方法

分解した経験を、依頼側が「何を頼めるか」分かる形にする方法です。「仕組みを作れます」では頼めません。

| 分解 | 手が動く形 | 見せ方の例 |
|---|---|---|
| 仕組みを作った | 成果物と期間で書く | 「スカウト運用の型・基準・手順・記録の表を二か月で作り、三か月目に御社の担当者に渡します」 |
| 人を回した | 何を見て、何を提案するかで書く | 「送信ログと担当者の稼働を見て、回っていない箇所を特定し、体制と分担の案を一枚で出します。月に二回の確認を三か月」 |
| 経営と現場をつないだ | 成果物で書く | 「役割の要件を現場から聞き取り、一枚の要件書にします。採用の目標から必要な送信数を逆算した計画を作ります」 |

形の要点は、「成果物と期間」です。マネージャーの経験は、成果物が見えにくい。「型の表」「体制の案の一枚」「要件書」「計画の一枚」と、出すものを決めると、依頼側は頼めます。範囲の書き方は[業務範囲を書面で固める](/media/fukugyo-scope/)に書いています。

### エラベルの見解

登録の相談で、マネージャー経験の方から「作業の案件しか無いのですか」という声を聞きます。作業の案件を受けて、「送信の感覚が古い」「単価が合わない」と止まる方もいます。売るものを、「作業」から「作業が回る仕組みを作って渡す」に変えた方は、人事が一人の会社の立ち上げの案件で、二か月で型と記録の表を作り、三か月目に渡して終え、次の案件に進みました。マネージャー経験は、作業ではなく仕組みで売れます。

見ていて差がつくのは、「判断を渡せるか」です。マネージャーは判断してきたので、副業でも「この候補者は進めるべき」「条件はこうすべき」と言いたくなります。素案として出す分にはよいのですが、決定に踏み込むと、依頼側の意思決定への介入になります。「素案は出します。決定は御社で」と線を引ける方は、続きます。

エラベルでは、マネージャー経験の方には、「仕組みを作って渡す」範囲で登録していただくことをお勧めしています。合う案件の相手は、人事が少数の会社が多くなります。

## マネージャーが陥りやすいこと

マネージャー経験の人が、副業で陥りやすいことです。

| 陥りやすいこと | 何が起きるか | 避け方 |
|---|---|---|
| 全部を見ようとする | 採用の全体を見て、範囲が広がり、時間が足りなくなる | 三つの分解のうち一つに絞る。一件目は一つ |
| 判断に踏み込む | 合否、条件、優先順位を決めようとする | 「素案は出す、決定は依頼側」を受ける前に決める |
| 作業を軽く見る | 「送信くらい」と思い、作業の案件で雑になる | 作業の案件は受けないか、受けるなら型に沿って丁寧に |
| 相手の規模を選ばない | 大手の人事部に「仕組みを作る」を提案し、既にあると言われる | 仕組みが無い会社を選ぶ |
| 常駐の感覚で受ける | 「毎日見ないと分からない」と、週数時間で回らない範囲を受ける | 成果物と期間で区切り、渡して終わる形に |
| 本業の仕組みを持ち出す | 本業で作った型、資料、指標の表をそのまま使う | 考え方は自分のもの、作ったものは本業のもの。依頼側の要件から新しく作る。線は専門家に |
| 単価を「役職」で決める | 「マネージャーだから」で高く出し、根拠が無い | 成果物と、それが依頼側にもたらす変化を根拠に |

陥りやすいことの要点は、「全部を見ようとする」と「判断に踏み込む」の二つです。マネージャーの強みが、副業では範囲の広がりと責任の逸脱になります。強みを、一つに絞り、素案に留めることで、副業の形に収めます。

## 範囲と単価の考え方

マネージャー経験で受けるときの、範囲と単価の考え方です。金額は案件によるので書きませんが、根拠の作り方を示します。

| 項目 | 考え方 |
|---|---|
| 範囲 | 三つの分解の一つ。成果物と期間で区切る。「渡して終わる」形。判断は含まない |
| 期間 | 二〜三か月。立ち上げなら、作る一〜二か月と、渡す一か月 |
| 時間 | 週数時間で収まる範囲。常駐の感覚で受けない。[週何時間から受けられるか](/media/fukugyo-kadou-jikan/) |
| 単価の根拠 | 作業の時間ではなく、成果物（型、表、計画、体制の案）と、それが依頼側にもたらす変化（担当者が回る、採用が進む）。「自分がいなくても回る形」の価値 |
| 単価の出し方 | 「時間×時給」を土台に、成果物の価値で上乗せ。役職を根拠にしない。[最初の1件の価格の決め方](/media/fukugyo-shoninka/) |
| 見積もり | 金額の前に、工程・時間・成果物・含まない業務を一枚に。[見積もりの出し方](/media/fukugyo-mitsumori/) |
| 二件目以降 | 一件目の成果物と依頼側の変化を根拠に、単価を見直す。[値上げを申し出るタイミング](/media/fukugyo-neage-timing/) |

考え方の要点は、「渡して終わる形」です。マネージャー経験の価値は、「自分がいなくても回る形を作る」ことにあります。自分が回し続ける形だと、案件が自分に依存し、時間が固定できず、マネージャー経験の価値も出ません。

## 最初の一件の選び方

マネージャー経験で、最初の一件に向く案件です。

| 向く案件 | 理由 |
|---|---|
| 人事が一人か少数で、スカウトや採用の仕組みが無い会社の立ち上げ | 仕組みを作って渡す、が最も効く |
| 担当者はいるが回っていない会社の、詰まりの特定と体制の案 | 人を回した経験が効く。成果物が一枚で済む |
| 役割の要件が曖昧で、現場と人事がずれている会社の、要件書の作成 | つないだ経験が効く。期間が短い |
| 代行を使っているが成果が出ない会社の、社内と代行の分担の設計 | 体制の設計。[社内のスカウト体制の作り方](/media/scout-taisei/)の考え方 |

向かない案件は、作業の代行（送信、一次対応）、大手の人事部の一部の作業、判断を含む案件（合否、条件）、期間の無い伴走です。最初の一件は、成果物が明確で、二〜三か月で渡して終わるものを選びます。

### エラベルの見解

担当する側として登録したマネージャー経験の方で、続いている方は、「仕組みを作って渡す」形で、人事が少数の会社の案件を受けています。二〜三か月で型と表と手順を作り、社内の担当者に渡して終える。それを繰り返しています。作業の案件を受けた方は、感覚の古さと単価の低さで止まることが多い。

マネージャー経験は、副業の市場では「仕組みが無い会社に、仕組みを作って渡す」ところで最も価値が出ます。大手で管理していた経験を、小さい会社で「回る形」に翻訳する。それが、マネージャー経験の売り方です。

エラベルでは、依頼側の規模と人事の体制を登録の時点でお伝えできるので、仕組みが無い会社の案件を選んでいただけます。

## まとめ

- 売りにくいのは**管理を売る・作業から離れた・枠が小さい・全部できると書く・判断に踏み込む・単価が合わない・相手を選ばない**構造
- 分解は**仕組みを作った（型と仕組みの設計と引き渡し）・人を回した（育成の補助、体制、詰まりの特定）・経営と現場をつないだ（要件の言葉化、計画、報告）**の三つ
- 売れる相手は**人事が少数で仕組みが無い会社・担当者はいるが回っていない会社・経営と現場がずれている会社**。大手の人事部には売れにくい
- 手が動く形は**成果物と期間で書く**。「型の表」「体制の案の一枚」「要件書」「計画の一枚」
- 陥りやすいのは**全部を見る・判断に踏み込む・作業を軽く見る・規模を選ばない・常駐の感覚・本業の仕組みの持ち出し・役職で単価**
- 範囲と単価は**一つに絞る・二〜三か月・週数時間・成果物と変化を根拠・渡して終わる形**
- 最初の一件は**仕組みが無い会社の立ち上げ・詰まりの特定と体制の案・要件書・分担の設計**。作業と判断と期間の無い伴走は避ける

## よくある質問

### マネージャー経験があっても、作業の案件から始めるべきですか

始める必要はありません。作業の案件は、作業から離れて数年経った人には感覚が古く、単価も合いません。「仕組みを作って渡す」範囲で、成果物と期間を区切った案件から始めるほうが、マネージャー経験が活きます。ただし、副業の感覚（週数時間、外部の立場、判断は依頼側）を掴むために、最初の一件を短い期間（一〜二か月）にするのは勧めます。

### 「管理職の経験を活かした伴走支援」のような案件は受けてよいですか

「伴走」は、範囲と期間と成果物が曖昧になりやすい言葉です。受ける前に、「何を、いつまでに、どの形で出すか」と「判断は誰か」を面談で確認します。成果物と期間が決まり、判断が依頼側に残るなら受けられます。「毎週会議に出て助言する」だけで成果物が無い形は、時間が固定できず、判断に踏み込みやすいので、避けるか、成果物を足してもらいます。[副業案件の面談で聞かれること](/media/fukugyo-mensetsu/)に、確認の仕方を書いています。

### 部下の育成の経験は、副業で売れますか

「人を回した」の分解で売れます。ただし、副業で部下を持つことはできないので、売り方は「担当者の育成の補助」です。依頼側の担当者に、型と段階を渡し、週次で決めた箇所を見て、三か月で段を上げる、という形です。自分が直接育てるのではなく、依頼側の人事や責任者が育てられる仕組み（段階、渡すもの、見るもの）を作って渡します。[スカウト担当者の育て方](/media/scout-tantousha-ikusei/)に、育成の段階の考え方を書いています。

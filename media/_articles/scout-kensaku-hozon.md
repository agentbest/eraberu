スカウトの検索条件は、担当者の頭の中にある。毎回、少しずつ違う条件で検索し、少しずつ違う母集団に送っている。担当者が替わると検索が変わり、母集団も返信も変わる。先月、返信が多かった検索を、今月は再現できない。逆に、返信が来なかった検索を、気づかずに繰り返している。結論を先に書くと、**検索条件は、役割ごとに「条件」「言葉」「除外」「並び」の四つの要素を、名前を付けて保存します。保存した検索を送信ログの「層」と紐づけ、結果と一緒に更新すれば、良かった検索を再現でき、悪かった検索を繰り返さず、担当者が替わっても同じ検索ができます**。母集団の広げ方は[母集団が小さすぎるときの広げ方](/media/scout-boshuudan-semasugi/)に、絞り方は[母集団が広すぎるときの絞り方](/media/scout-boshuudan-hirosugi/)にまとめています。

## 検索条件が残らない構造

検索条件が担当者の頭の中に留まり、再現できないのは、次の構造で起きます。

| 構造 | 起きていること |
|---|---|
| 検索を「その場の作業」と考えている | 検索は送る前の手段で、記録するものだと思っていない |
| 媒体の保存機能に頼っている | 媒体に保存した条件は、媒体の中、そのアカウントの中にしか無く、言葉や除外の理由は残らない |
| 条件と結果が紐づいていない | 「先月の返信が多かった」が、どの検索の結果かが分からない |
| 担当者ごとに検索が違う | 同じ役割で、担当者Aと担当者Bの検索が違い、母集団が違う |
| 除外の理由が残らない | 「この会社は除く」「この言葉は合わない」が、頭の中にしか無い |
| 言葉の一覧が無い | 検索に使った言葉と、使わなかった言葉と、試して合わなかった言葉が残らない |
| 引き継ぎで消える | 担当者の交代で、検索の蓄積がゼロになる |

構造の大半は、「検索を記録の対象にしていない」ことです。対象にすれば、保存の型は難しくありません。

## 保存する四つの要素

検索条件として保存するのは、四つの要素です。媒体の画面で設定する項目だけでなく、その理由と周辺も保存します。

| 要素 | 内容 | 保存する理由 |
|---|---|---|
| 条件 | 媒体の画面で設定する項目。職種、経験、スキル、勤務地、年収の幅、活動の状態など。属性は使わない | 同じ母集団を再現するため |
| 言葉 | 検索に使う言葉の一覧。使って合った言葉、試して合わなかった言葉、これから試す言葉 | 言葉の蓄積を引き継ぐため。[母集団が小さすぎるときの広げ方](/media/scout-boshuudan-semasugi/) |
| 除外 | 除く会社、除く経歴の特徴、送ってはいけない相手の区分。理由を添えて | 除外の判断を再現し、理由を失わないため。[送ってはいけない候補者の管理](/media/scout-blacklist/) |
| 並び | 順番をつける基準。経歴の特徴、転職の動きの見え方、順位ごとの扱い | 母集団の中で誰から送るかを再現するため。[母集団が広すぎるときの絞り方](/media/scout-boshuudan-hirosugi/) |

四つの要点は、「条件だけでは足りない」ことです。媒体の画面の設定は条件だけで、言葉と除外と並びは担当者の頭の中にあります。四つを揃えて保存して、初めて同じ検索が再現できます。

## 保存の型

四つの要素を、どう保存するかです。役割ごとに、一つの文書か、表の一行にします。

| 項目 | 内容 |
|---|---|
| 検索の名前 | 「役割名＋媒体＋版」。「〇〇職・媒体A・第三版」のように |
| 役割 | 対象の役割 |
| 媒体 | 使う媒体。媒体ごとに条件の項目が違うので、媒体ごとに保存 |
| 条件 | 媒体の画面の項目と値を、そのまま書き写す |
| 言葉 | 使う言葉の一覧（合った・合わなかった・未試行の三つに分けて） |
| 除外 | 除く会社と経歴の特徴、理由 |
| 並び | 順番の基準と、順位ごとの扱い |
| 作った日と作った人 | 版の管理のため |
| 対応する層の名前 | 送信ログの「層」の区分名。この検索で出た候補者を、どの層として記録するか |
| 結果の要約 | この検索で出た母集団の数、送った通数、返信率、面談率（後から追記） |
| 次に試すこと | この検索で足りなかった点と、次の版で変えること |

型の要点は、「対応する層の名前」です。検索と送信ログの層が紐づいていれば、「この検索の結果はこうだった」が分かります。紐づいていないと、検索を保存しても結果と結びつかず、良し悪しが判断できません。送信ログの層は[送信ログの残し方](/media/scout-log/)に書いています。

## 使い回しの型

保存した検索を、どう使い回すかです。「同じ役割で再び」「似た役割で」「別の媒体で」の三つの場面があります。

| 場面 | 使い回し方 | 注意 |
|---|---|---|
| 同じ役割で、再び募集する | 最新の版をそのまま使う。時間が経っていれば、言葉と除外を見直す | 前回送った人への再送の扱い。[時間を空けて再送するときの書き方](/media/scout-kikan-aketa/) |
| 似た役割で募集する | 最も近い役割の検索を複製し、条件と言葉を役割に合わせて直す。並びの基準は役割ごとに違うので作り直す | 「似ている」と決めつけて条件をそのまま使うと、母集団がずれる |
| 別の媒体で同じ役割を募集する | 言葉と除外と並びは引き継ぎ、条件は媒体の項目に合わせて作り直す | 媒体ごとに項目が違う。仕様は公式の案内で確認 |
| 担当者が替わる | 最新の版と、過去の版の「次に試すこと」を渡す | 版の履歴が無いと、前の担当者が試して合わなかったことを繰り返す |
| 検索の結果を見直す | 結果の要約を見て、返信率と面談率が良かった版を「基準の版」にする | 一度の結果で決めず、二〜三回の募集で判断 |

使い回しの要点は、「複製して直す」ことです。似た役割で、前の検索をそのまま使うと、母集団がずれます。複製し、役割に合わせて直し、新しい名前を付けます。元の検索はそのまま残します。

### エラベルの見解

相談で最も多い失敗は、「前の担当者の検索が良く、返信も面談も出ていたが、担当者が替わった途端に母集団が変わり、返信が落ちた。前の担当者の検索は、媒体に保存された条件だけが残っていて、言葉と除外と並びは頭の中だった」というものです。条件だけを引き継いだ新しい担当者は、同じ条件で検索しても、言葉が違い、除外が違い、順番が違った。四つの要素を役割ごとに文書にし、結果の要約と「次に試すこと」を版ごとに残す形にしたら、次の交代では母集団が変わりませんでした。検索は、条件だけでは再現できません。

見ていて差がつくのは、担当者が「試して合わなかった言葉」を残しているかです。合った言葉だけを残す担当者と、「この言葉は試したが、出てくる人の経歴が違った」と合わなかった言葉と理由を残す担当者がいます。後者の記録は、次の担当者が同じ遠回りをせずに済みます。

発注側にできるのは、契約の最初に、「検索の四つの要素を、役割ごとに、当社の文書として残してください」を条件にすることです。

## 更新の運用

保存した検索を、結果に合わせて更新する運用です。

| タイミング | 更新すること |
|---|---|
| 送信のたび | 対応する層の名前で、送信ログに記録する（検索の側は変えない） |
| 週に一度 | 返信者の経歴から、言葉を拾って「言葉」に追記。「次に試すこと」を書き足す |
| 月に一度 | 結果の要約（母集団の数、送った通数、返信率、面談率）を追記。基準の版を見直す |
| 版を変えるとき | 複製して新しい名前を付け、変えた点を書く。元の版は残す |
| 募集が終わったとき | 最終の結果の要約と、「次に募集するときの注意」を書く |
| 担当者が替わるとき | 最新の版と、過去の版の「次に試すこと」を、引き継ぎの資料として渡す |

更新の要点は、「版を上書きしない」ことです。上書きすると、送信ログの層が指す検索が変わり、結果と検索の対応が崩れます。変えるときは複製し、新しい名前で、変えた点を残します。文面の型と同じ考え方です。

## 媒体の機能との関係

媒体には、検索条件を保存する機能があることが多い。それと、自社の保存の関係です。

| 項目 | 媒体の保存機能 | 自社の保存 |
|---|---|---|
| 保存されるもの | 条件（画面の項目） | 条件・言葉・除外・並びの四つと、理由と結果 |
| 置き場所 | 媒体の中、そのアカウントの中 | 自社の管理下 |
| 引き継ぎ | アカウントの権限を引き継げば見られる。ただし理由は無い | 文書として渡せる |
| 媒体を替えたとき | 消える | 言葉と除外と並びは残る |
| 使い方 | 日々の検索の手間を減らす道具として使う | 再現と引き継ぎと検証のための記録として持つ |
| 新着の通知 | 保存した条件に合う新着を通知する機能がある媒体もある。仕様は公式の案内で確認 | 通知を受けた後の動きを決める。[新着候補者への即時アプローチ](/media/scout-shinchaku-tsuuchi/) |

関係の要点は、「媒体の保存は道具、自社の保存は記録」です。両方使います。媒体の保存機能の有無や仕様は媒体ごとに違うので、公式の案内で確認してください。媒体のアカウントの権限と引き継ぎは[媒体アカウントの権限設定](/media/scout-daikou-kengen/)に書いています。

## 外注する場合の範囲

検索条件の保存と使い回しを、スカウト代行に出す場合の範囲です。

**出せる工程。** 役割ごとの検索の四つの要素の文書化、検索の名前と版の管理、送信ログの層との紐づけ、週次の言葉の追記、月次の結果の要約の追記、版の複製と変更点の記録、似た役割や別の媒体への使い回しの案、担当者の交代時の引き継ぎの資料の作成、媒体の保存機能の設定。

**社内に残す判断。** 検索の文書を自社の管理下に置くこと、役割の要件の定義（条件の元になる）、除外の理由の提供（取引先、競合、社内の判断）、基準の版の承認、担当者の交代時に文書の引き渡しを確認すること。

**外注の効きどころ。** 検索の保存は、「四つを揃えて、名前を付けて、結果と紐づけて、版で更新する」運用で、社内では「担当者の頭の中」になりやすい工程です。担当者が四つを文書にし、送信ログと紐づけ、週次と月次で更新し、版を上書きしなければ、検索は再現でき、引き継げます。担当者は複数の会社で同じ役割の検索を見ているので、「この役割はこの言葉で」「この媒体はこの項目が効く」を持ち込めます。ただし、文書の置き場所を自社の管理下にすることと、除外の理由は、社内でしか決められません。

**外注しても動かない場合。** 検索の文書を代行の手元にだけ置く、役割の要件が曖昧で条件が作れない、除外の理由を担当者に渡さない、担当者の交代時に文書の引き渡しを確認しない。社内の判断で、代行を替えても直りません。

検索条件は、四つの要素を役割ごとに名前付きで保存し、送信ログの層と紐づけ、版で更新すれば、再現でき、引き継げます。外注は、文書化と紐づけと更新を担う手段です。

### エラベルの見解

担当する側から見ると、検索の保存の相談で最も多いのは、「保存はあるが、結果と紐づいていない」ことです。役割ごとに検索の条件は文書になっている。ただ、その検索で出た人に送って、どうだったかが、文書には無い。送信ログにも、どの検索から出た人かが無い。結果、「第二版と第三版のどちらが良かったか」が分からず、担当者の記憶で「たぶん三版」になります。

紐づけは、送信ログの「層」の列に、検索の名前を書くだけです。それだけで、月次の集計で「検索ごとの返信率と面談率」が出ます。

発注側にできるのは、送信ログの「層」の列を、担当者と一緒に見て、検索の名前が入っているかを確認することです。

## まとめ

- 残らないのは**その場の作業と考える・媒体の保存に頼る・条件と結果が紐づかない・担当者ごとに違う・除外の理由が無い・言葉の一覧が無い・引き継ぎで消える**構造
- 保存するのは**条件・言葉・除外・並び**の四つ。条件だけでは再現できない
- 型は**名前（役割＋媒体＋版）・役割・媒体・条件・言葉（合った・合わなかった・未試行）・除外と理由・並び・作った日と人・対応する層・結果の要約・次に試すこと**
- 使い回しは**同じ役割は最新の版・似た役割は複製して直す・別の媒体は言葉と除外と並びを引き継ぎ条件を作り直す・交代は最新の版と過去の次に試すこと・結果で基準の版を決める**
- 更新は**送信のたびに層で記録・週次で言葉・月次で結果の要約・版は複製して上書きしない・募集の終了時に注意を書く・交代時に渡す**
- 媒体の保存は**道具**、自社の保存は**記録**。両方使い、媒体の仕様は公式の案内で確認
- 外注できるのは**文書化・版の管理・紐づけ・言葉の追記・要約の追記・複製と記録・使い回しの案・引き継ぎの資料・媒体の設定**。社内に残るのは**置き場所・要件の定義・除外の理由・基準の版の承認・引き渡しの確認**

## よくある質問

### 検索条件の文書は、どこに置けばよいですか

送信ログと同じ、自社の管理下の場所です。送信ログの「層」の列が検索の名前を指すので、同じ場所にあると照合しやすい。代行の手元だけに置くと、契約が終わったときに残りません。文面の型の一覧、送ってはいけない一覧、送信ログ、検索の文書の四つを、同じ場所に置くのが型です。契約終了時のデータの扱いは[送信データの引き渡し](/media/scout-daikou-data/)に書いています。

### 役割が多く、全部の検索を文書にする手間が大きいです

優先順位をつけます。今、募集している役割と、繰り返し募集する役割から文書にします。一度きりの役割は、募集が終わったときに「結果の要約」と「次に募集するときの注意」だけを残します。四つの要素のうち、最初は「条件」と「言葉」だけでも、無いよりはるかに良い。「除外」と「並び」は、二回目の募集で足します。複数の役割の優先順位は[複数職種があるときの優先順位](/media/scout-shokushu-yuusen/)に書いています。

### 媒体の保存機能があれば、自社の文書は要らないのではないですか

媒体の保存は、条件だけで、そのアカウントの中にだけあります。言葉の蓄積、除外の理由、並びの基準、結果との紐づけは、媒体には残りません。媒体を替えたとき、担当者が替わったとき、代行を替えたときに、媒体の保存だけでは再現できません。媒体の保存は日々の手間を減らす道具として使い、自社の文書は再現と引き継ぎと検証のために持ちます。媒体の保存機能の仕様は、公式の案内で確認してください。

自動車業界の会社が採用代行を検討するとき、動機は「機械の設計は採れていたが、電気とソフトの人が採れない」「取引先の増産で現場の人が急に要る」であることが多い。ただ、自動車の採用は、メーカー全般の難しさに加えて、業界に特有の難しさがあります。完成車・部品・販売・整備で会社の型が違い、技術の領域が機械から電気とソフトへ広がり、部品の会社は取引先の計画で人数と時期が動き、拠点が地方にあり、現場職は交替勤務の実態が定着を左右する。結論を先に書くと、**自動車業界の採用代行は、母集団形成・一次対応・日程調整・記録は外に出せる一方、技術の領域の要件の決定・技術の見極め・取引先の計画との照合・勤務地と条件の判断は社内に残さないと、採れても領域と現場に合いません。**代行に出す前に、難しさを自社の型で分解し、工程ごとに「任せる・残す」を決めることが、代行が機能する条件です。メーカー全般の切り分けは[メーカー業界の採用代行](/media/rpo-maker-rpo/)に、職種ごとの切り分けは[機械設計採用を代行に出す判断基準](/media/rpo-kikai-sekkei-rpo/)や[電気設計採用を代行に出す判断基準](/media/rpo-denki-sekkei-rpo/)に書いています。ここでは、自動車業界で共通する切り分けに絞ります。

## 自動車業界の採用が難しい五つの理由

| 難しさ | 中身 | 代行への影響 |
|---|---|---|
| 会社の型が違う | 完成車・部品（一次・二次）・販売・整備で、職種も経路も要件も違う | 「自動車業界の採用に強い」だけでは、自社の型に合うか分からない |
| 技術の領域が広がる | 機械の設計に加え、電気・電子・ソフト・制御の人が要る。従来の経路（機械系の学校、機械系の紹介）では届かない | 領域ごとに経路と要件と文面が要る。IT・Web業界の候補者と競合する |
| 取引先の計画で人数と時期が動く | 部品の会社は、取引先の生産の計画で必要な人数が変わる | 計画と採用の一枚が要る。急ぐと要件が曖昧になる |
| 勤務地で絞られる | 工場が地方にあり、通える人か転居できる人に限られる | 転居の条件と地域の経路が要る |
| 現場職の交替勤務 | 交替勤務・繁忙期の残業の実態が、応募と定着を左右する | 実態を先に出すかで、応募の数と離職が変わる |

五つのうち、代行で解決できるのは母集団形成と速さで、要件・見極め・計画・勤務地・実態の判断は社内の関わりが要ります。

## 工程ごとの「任せられる・残す」

| 工程 | 任せられるか | 理由 |
|---|---|---|
| 取引先の計画から採る数と時期を決める | 残す | 営業と生産の責任者が決める |
| 技術の領域の要件の決定 | 残す | 機械・電気・ソフトの各領域の技術者が決める |
| 要件を「経歴で読める言葉」に整える | 一緒に | 「〇〇の部品（システム）の〇〇を、〇〇の領域で担った経験」に。代行が整え、技術者が確認 |
| 母集団形成（領域ごとの経路） | 任せられる | 機械は従来の経路、電気とソフトはIT・Web寄りの経路。型があれば外で回せる |
| 一次対応（返信・日程） | 任せられる | 速さが要る工程 |
| 書類の一次確認 | 一部任せられる | 「領域・部品の型・担った範囲」の照合は外で。深さは社内 |
| 技術の見極め（面接） | 残す | 各領域の技術者 |
| 現場職の見学と働き方の実態の説明 | 残す | 現場の責任者 |
| 勤務地と転居の条件の判断 | 残す | 会社の判断 |
| 条件の判断 | 残す | 会社の判断 |
| 記録と報告 | 任せられる | 一覧と週次の一枚 |

「技術の領域の要件」は、機械の技術者だけでは決められません。電気とソフトの要件は、その領域の人が決めるか、いなければ最初の一人を採ることから始めます。

### エラベルの見解

自動車業界で多くの会社が見落とすのは、「電気とソフトの人は、IT・Web業界の候補者と競合している」ことです。機械の設計と同じ経路（機械系の学校、機械系の紹介会社、掲載型の媒体）で募集し、機械の要件の型（「設計経験〇年」）で探し、来ない。電気とソフトの候補者は、スカウト型の媒体にいて、「どの領域の、どの部分を、どこまで担うか」で動き、返事の速さで会社を選びます。IT・Web業界の採用の型（要件の言葉、経路、速さ）を、自動車の会社が持てるかが、分かれ目です。エラベルで担当者を選ぶ企業には、「電気とソフトの採用で、機械と同じ経路と要件の型を使っていませんか」を、私たちから先に聞いています。領域ごとに型を分けることが、代行に出す前の準備です。IT・Web業界の型は[IT・Web業界の採用代行](/media/rpo-it-rpo/)に書いています。

## 代行に出す前に社内で確認すること

| 確認 | 中身 |
|---|---|
| 会社の型 | 完成車・部品・販売・整備のどれか。採る職種の型（技術職・現場職・営業・整備） |
| 技術の領域ごとに要件を決める人 | 機械・電気・ソフトのそれぞれに、要件を言葉にできる技術者がいるか。いない領域は最初の一人から |
| 取引先の計画と採用の一枚 | 部品の会社は、取引先の生産の計画と採る数と時期が同じ行にあるか |
| 勤務地と転居の条件 | 転居の支援、転勤の有無を先に出すか |
| 現場職の働き方の実態 | 交替勤務・残業・環境を求人票に書き、見学を段に置くか |
| 面接の枠 | 各領域の技術者と現場の責任者の枠を、週に決まった数出せるか |
| 記録の形 | 一覧と記録が社内の環境にあるか |

「技術の領域ごとに要件を決める人」がいない領域（多くは電気かソフト）では、代行に出しても、面接に来る人がずれます。

## 会社の型と技術の領域ごとに代行の型が違う

| 型・領域 | 代行に向く工程 | 社内に残す度合い |
|---|---|---|
| 完成車・部品の機械設計 | 従来の経路の運用（学校、紹介、掲載型） | 製品と工程の要件、見極め |
| 完成車・部品の電気・ソフト | スカウト型の母集団形成（IT・Web寄りの経路）、一次対応 | 領域の要件、技術の見極め。IT・Web業界の型で |
| 部品の現場職（製造・保全） | 地域の経路の運用、一次対応 | 見学と働き方の実態 |
| 販売・整備 | 地域の掲載型と学校の経路、一次対応 | 店舗の責任者の見極め。整備は資格の扱いを依頼側の決まりで |

「自動車業界の採用に強い代行」でも、会社の型と技術の領域の両方の型を持っているかは別です。

## 代行を選ぶときの確認項目

| 確認 | 聞き方 |
|---|---|
| 会社の型ごとの経験 | 「完成車と部品の一次で、採用の型をどう変えますか」 |
| 技術の領域ごとの型 | 「機械の設計と、電気・ソフトで、経路と文面をどう変えますか」 |
| 取引先の計画との照合 | 「取引先の計画で採る数が変わる場合、採用の一枚をどう組みますか」 |
| 担当者の経歴 | 「担当する方は、自動車業界のどの型の会社の、どの領域の採用を、どの工程で担った経験がありますか」 |
| 返事の速さと記録の置き場所 | 「候補者への返事は何営業日以内か。記録はどこに置くか」 |
| 費用の構造 | 「月額に含まれる工程と、領域の数は」 |

費用は、含まれる工程と領域の数で変わり、金額の相場を先に聞くより「同じ工程・同じ領域で比べる軸」をそろえます。費用の構造は[採用代行の費用の内訳](/media/rpo-hiyou-uchiwake/)に、選び方の軸は[採用代行会社の選び方](/media/rpo-erabikata/)に書いています。

## 代行に出したあとに起きること

| 起きること | 原因 | 対応 |
|---|---|---|
| 機械の応募は来るが、電気とソフトが来ない | 領域ごとに経路と要件を分けていない | 電気とソフトはIT・Web寄りの経路と型で |
| 電気とソフトの候補者が、返事の遅さで他社に決まる | IT・Web業界の速さに合っていない | 一次対応と日程を外に出し、確定を即日に |
| 取引先の計画が変わり、採った人の役割が無い | 計画と採用の一枚が無い | 一枚を同じ行に。確定だけを数える |
| 現場職が面接で「交替勤務は聞いていない」と辞退 | 実態を先に出していない | 求人票と初回の連絡に。見学を段に |
| 面接で「勤務地が遠い」と辞退 | 転居の条件を先に出していない | 先に出す。経路を転居できる人と地域で分ける |
| 契約が終わると記録が消える | 記録が代行の環境 | 社内の環境に置く形を契約で |

出したあとの問題は、「領域ごとの型」「速さ」「計画との照合」「実態と勤務地」に戻ります。

### エラベルの見解

部品の会社で多いのは、「取引先の増産が決まったので、現場の人を急いで採りたい」という相談です。急ぐほど、要件が「工場で働ける人」になり、交替勤務の実態を書かずに募集し、面接で辞退され、採れても早期に離れて、また募集する。取引先の計画は、増産の決定の前に「見込み」の段階があり、その段階で採用の一枚に「予定」として置き、実態を書いた求人票と地域の経路と見学の段を準備しておけば、決定と同時に募集を始められます。エラベルは担当者を工程ごとに選べる形にしているので、「現場職の地域の経路の運用と一次対応と見学の日程」を担当者が担い、営業と生産の責任者は計画の一枚と実態の説明に絞る、という組み方ができます。計画のつなぎ方は[要員計画と採用計画がつながっていない](/media/rpo-jinin-keikaku/)に書いています。

## まとめ

- 自動車業界の難しさは、**会社の型・技術の領域の広がり・取引先の計画・勤務地・現場職の交替勤務**の五つ
- **母集団形成・一次対応・日程・記録は任せられ、領域の要件・技術の見極め・計画との照合・勤務地と条件は残す**
- **電気とソフトはIT・Web業界の候補者と競合**。機械と同じ経路と要件の型では届かない
- 領域ごとに要件を決める技術者がいない領域は、**最初の一人から**
- 部品の会社は**取引先の計画と採用の一枚を同じ行に**。見込みの段階で準備
- 現場職は**交替勤務の実態を先に出し、見学を段に**
- 代行を選ぶときは**会社の型と技術の領域の両方の型**を確かめる

## よくある質問

### 電気とソフトの技術者が社内に一人もいません。要件を誰が決めますか

最初の一人は、経営者と機械の技術者が「この領域で、最初の三か月に何をしてもらうか」を仕事の中身で決め、外部の助言（取引先、専門家）で要件の言葉を確かめる形で採ります。一人目が入れば、二人目からはその人が要件を決められます。代行に「要件も決めて」と頼むと、代行の推測になります。一人目の採用は、要件の言葉より「最初の三か月の仕事」と「一緒に働く人」を具体にし、面接で「決まりの無いことを自分で決めて進めた場面」を聞く形にします。

### 販売の会社ですが、整備士が採れません

整備は、資格の扱い（法令上の整理があると一般に整理されている）と、地域の経路（学校、地域の掲載型、紹介）と、働き方の実態（休日、繁忙期）で決まります。資格の扱いは依頼側の決まりと専門家の確認に従い、担当者が断定しません。経路は地域の経路を全部使い、求人票に働き方の実態と「一緒に働く人」を書きます。整備の採用も、他の現場職と同じで、実態を先に出すと応募は減り、定着が上がります。個別の判断は専門家にご確認ください。

### 取引先から「増産に合わせて人を増やしてほしい」と言われましたが、計画が確定しません

「見込み」と「確定」を分け、確定した分だけを採る数の根拠にし、見込みは一枚に載せて準備（求人票、経路、見学の段、記録の形）を進めます。確定した瞬間に募集を始められる状態にしておけば、遅れません。見込みの段階で採ると、取引先の計画が変わったときに待機か離職になります。取引先との計画の共有の仕方は、営業の領域で、採用の側は「確定と見込みを分けた一枚」を求めるまでです。

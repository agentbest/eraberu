「過去の応募者を活かしたい」「タレントプールを作りたい」という依頼で、過去の応募者の一覧を一つのシートにまとめると、それは「名簿」であって、プールではありません。誰に、何のために、いつ連絡し、いつ消すかが決まっていない名簿は、使われないまま個人情報だけが溜まり、扱いの問題になります。結論を先に書くと、**タレントプールは、入れてよい人を同意と依頼側の決まりで決め、四つの層に分け、一人一行で「入れた理由・要件との照合・同意の範囲・次の接点の時期・出す条件」を持ち、動かす接点は求人の変化があるときだけにし、出す条件を先に決め、個人情報の保管と使用は専門家の確認に従い、担当者はプールを手元に持たない形で作ります。**会社側から見た考え方は[過去の応募者を活かせていない](/media/rpo-talent-pool-katsuyou/)と[タレントプールの育て方](/media/scout-talent-pool/)に、代行に持たせるときの線は[タレントプールを代行に持たせるリスク](/media/rpo-talent-pool/)に書いています。ここでは、副業の担当者が作る型に絞ります。

## 「溜めておく」だけで使われない理由

| 名簿の形 | 何が起きるか |
|---|---|
| 過去の応募者を全部入れる | 誰が要件に近いかが分からず、開かれない |
| 入れた理由が無い | 「なぜこの人が入っているか」を後で誰も説明できない |
| 同意の範囲が無い | 連絡してよいのか分からず、連絡できない。または同意の無い連絡をしてしまう |
| 次の接点の時期が無い | 「いつか連絡する」は来ない |
| 出す条件が無い | 消えず、個人情報が溜まり続ける |

プールは「動かす」ためのもので、動かす設計が無ければ、名簿のほうがまだ害が少ない。設計が無いなら、作らないほうがよい、というのが出発点です。

## 入れてよい人は同意と依頼側の決まりで

| 前提 | 中身 |
|---|---|
| 本人の同意 | 応募や面談の際に、「今後の求人の案内のために情報を保管し連絡することがある」への同意。取り方と文言は依頼側の決まりと専門家に |
| 依頼側の決まり | 保管の期限、保管の場所、使用の目的、見られる人。無ければ先に作る（依頼側と専門家で） |
| 同意が無い人 | 入れない。過去の応募者で同意の記録が無い人は入れない |
| 紹介会社経由の人 | 紹介会社との契約に関わる。入れてよいかは契約と依頼側の判断 |

応募者の情報を選考の後も保管し、別の求人の案内に使うことは、個人情報の扱いに関わり、法令上の整理があると一般に整理されています。担当者が「同意はあるだろう」と判断しません。個別の判断は専門家にご確認ください。扱いは[個人情報の扱い](/media/fukugyo-kojin-jouhou/)と[副業で法令違反をしないために](/media/fukugyo-ihan-shinai/)に書いています。

### エラベルの見解

担当する側から見ると、タレントプールで最も差がつくのは、「出す条件を先に決めているか」です。受ける側は、入れる基準を丁寧に作りますが、出す基準を作りません。すると、プールは増える一方で、保管の期限を過ぎた人、本人が「もう連絡不要」と言った人、要件が変わって合わなくなった人が残り、いつか同意の無い連絡が発生します。「保管の期限が来たら出す」「本人の申し出があれば即日出す」「要件の変化で照合が×になったら出す」の三つを、入れる前に一枚に書く。それで、プールは増え続けず、動かせる状態が保てます。エラベルで担当者を選ぶ企業には、「タレントプールから人を出す条件は決まっていますか」を、私たちから先に聞いています。受ける側がその場で使える判断としては、一人一行の項目に「出す条件と時期」の列を作り、空欄の行は入れないこと。

## 四つの層

| 層 | 誰か | 動かす接点 |
|---|---|---|
| 見送りだが要件に近い | 選考で見送ったが、必須の一つが△で、他は○だった人 | その必須が歓迎に変わった求人が出たとき |
| 辞退した | 内定や選考の途中で辞退。理由が「速さ」「迷い」で、会社への評価は低くなかった人 | 辞退の理由に対応した変化（役割、体制）があったとき |
| カジュアル面談で今は動かない | 「今は考えていない」と言い、時期を示した人 | 本人が示した時期 |
| 退職者で意向のある人 | 退職時に「連絡を続けてよい」と示した人 | [アルムナイ採用を設計する](/media/fukugyo-skill-alumni/)の型で |

層ごとに、動かす接点が違います。全員に同じ案内を送るのは、プールではなく一斉配信で、返信は来ず、同意の範囲を超えることもあります。

## 一人一行の項目

| 列 | 中身 |
|---|---|
| 番号 | 一覧の番号と同じ。氏名は個人情報のシートで |
| 層 | 四つのどれか |
| 入れた理由 | 「必須〇〇が△、他は○」「辞退の理由は速さ」など、要件の言葉で一行 |
| 要件との照合 | 入れた時点の○△× |
| 同意の範囲 | 何に同意しているか（求人の案内、近況の連絡）。同意の日 |
| 次の接点の時期 | 本人が示した時期か、求人の変化があったとき |
| 出す条件と時期 | 保管の期限、本人の申し出、要件の変化 |
| 接点の記録 | いつ、誰が、何を送り、返事はどうだったか |

候補者リストと同じく、一人一行、氏名は別のシートで番号で紐づけます。構造は[候補者リストの作り方](/media/fukugyo-skill-list/)と[スプレッドシートで採用管理を作る](/media/fukugyo-skill-spreadsheet/)に書いています。

## 動かす接点は「求人の変化」があるときだけ

| 送ってよいとき | 送らないとき |
|---|---|
| その人の「入れた理由」に対応する求人の変化があった（必須が変わった、役割ができた） | 定期的な「近況のお知らせ」だけを目的に（同意の範囲による） |
| 本人が示した時期が来た | 求人が無いのに関係を保つために |
| 辞退の理由に対応した変化があった | 一斉に同じ文面で |

接点の文面は、スカウト文面と同じ型（その人の経歴に触れる一段落・変化の中身・返信しやすい結び）で、「以前ご応募いただいた際に〇〇でしたが、〇〇が変わりました」と、入れた理由に対応する変化を書きます。文面の型は[スカウト文面を書く](/media/fukugyo-skill-scout-bunmen/)に書いています。送る前に、同意の範囲と出す条件を確かめます。

### エラベルの見解

相談で最も多い思い込みは、受ける側の「プールは大きいほど価値がある」というものです。実際には、プールの価値は、大きさではなく「動かせる行の数」で決まります。動かせる行とは、入れた理由が要件の言葉で書かれ、同意の範囲が明確で、次の接点の時期が決まっている行です。百行の名簿より、十行の動かせるプールのほうが、次の求人で役に立ちます。受ける側がその場で使える判断としては、月に一度、「次の接点の時期」が過ぎている行を見て、動かすか出すかを依頼側に判断してもらうこと。放置された行が増えるプールは、名簿に戻ります。

## 出す条件を先に決める

| 条件 | 扱い |
|---|---|
| 保管の期限 | 依頼側の決まりで定めた期限が来たら出す。期限の管理は依頼側 |
| 本人の申し出 | 「連絡不要」「情報を消してほしい」があれば、依頼側の決まりに従って即日 |
| 要件の変化 | 照合が×になった行は出す |
| 接点で返事が無い | 一定の回数で出す。回数は依頼側の決まり |
| 入社した | 出す。プールは候補者のためのもの |

「出す」の実務（消す、返す、匿名にする）は依頼側の個人情報の扱いの決まりに従い、担当者は「出す条件に該当した行」を依頼側に知らせるまでです。

## 担当者はプールを手元に持たない

| 線 | 理由 |
|---|---|
| プールは依頼側の環境（ATSか共有の場所）に | 担当者の端末やアカウントに置くと、案件の終了後に個人情報が残る |
| 担当者の他の案件で使わない | 依頼側の候補者の情報は、その依頼側のもの |
| 案件の終了時に、手元の写しを消す | 引き継ぎで「消した」ことを伝える |
| 担当者が独自にプールを作らない | 「自分の候補者データベース」は、複数の依頼側の情報が混ざり、扱いの問題になる |

代行や外部の担当者がプールを持つことの問題は[タレントプールを代行に持たせるリスク](/media/rpo-talent-pool/)に書いています。担当者の側から、依頼側の環境に置く形を提案します。

## よく起きる詰まりと直し方

| 詰まり | 直し方 |
|---|---|
| 過去の応募者に同意の記録が無い | 入れない。今後の応募者から同意の取り方を依頼側と専門家で決める |
| 「とりあえず全員入れたい」と言われる | 動かせる行だけに絞る理由を説明。入れた理由が書けない人は入れない |
| 出す条件が決まらない | 保管の期限は依頼側の決まりから。無ければ先に作る |
| 接点の文面が一斉配信になる | 層ごと、入れた理由ごとに。求人の変化に対応する一段落 |
| 担当者の端末にプールがある | 依頼側の環境に移し、手元を消す |
| 接点を送ったが返事が無い行が溜まる | 回数で出す条件に従って出す |

## まとめ

- 「溜めておく」名簿はプールではない。**動かす設計が無ければ作らない**
- 入れてよい人は**同意と依頼側の決まり**で。同意の記録が無い人は入れない。個別の判断は専門家にご確認ください
- 層は**見送りだが近い・辞退した・今は動かない・退職者で意向のある人**。層ごとに動かす接点が違う
- 一人一行で**入れた理由・照合・同意の範囲・次の接点の時期・出す条件**。氏名は別に
- 動かすのは**求人の変化があるとき**だけ。一斉配信にしない
- **出す条件を先に決める**。期限・本人の申し出・要件の変化・返事なし・入社
- **担当者はプールを手元に持たない**。依頼側の環境で、案件の終了時に手元を消す

## よくある質問

### 依頼側から「プールの人に、定期的に会社の近況を送りたい」と言われました

同意の範囲によります。「求人の案内」への同意しか無い人に、近況の配信を送ることは、同意の範囲を超える可能性があります。近況の配信を行いたいなら、その目的への同意を改めて取る形を、依頼側と専門家で決めます。担当者は「同意の範囲を確かめてから」と伝え、範囲の判断はしません。同意の範囲の中で送る場合も、層ごとに文面を分けます。

### プールの人に接点を送ったら、「なぜ私の情報を持っているのか」と返されました

同意の記録を依頼側が確かめ、本人に「いつ、どの場面で同意をいただいたか」を依頼側の人事から説明します。記録が無ければ、依頼側の決まりに従って情報を出し、本人にその旨を伝えます。担当者が本人に直接説明することはせず、依頼側の人事に渡します。この事態を防ぐために、入れる前の同意の確認と、接点の文面に「以前〇〇の際にご同意いただいた」を入れる形にします。

### 副業の案件が終わった後、自分が作ったプールの型を次の依頼側で使ってよいですか

型（層の分け方、一人一行の項目、出す条件の考え方）は使えます。中身（依頼側の候補者の情報）は一切持ち出しません。「型は自分のもの、中身は依頼側のもの」の線を、案件の最初に契約で書いておきます。引き継ぎのときに、手元の写しを消したことを依頼側に伝えます。引き継ぎの形は[引き継ぎ資料の残し方](/media/fukugyo-hikitsugi/)に書いています。

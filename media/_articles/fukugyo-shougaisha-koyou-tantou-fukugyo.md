本業で障害者雇用の担当をしてきた。業務の切り出し、受け入れの体制、支援機関との連携、定着の面談。この経験は、人事の副業で売れるのか。障害者雇用は制度が絡み、副業で扱ってよいのか迷う。結論を先に書くと、**障害者雇用の担当の経験は、「これから始める、または詰まっている依頼側の、受け入れの設計と運用」で売れます。売れるのは、「業務の切り出し」「受け入れの体制と面談の設計」「支援機関との連携の型」「定着の仕組み」の四つです。障害者雇用を始めたいが何から手をつければよいか分からない依頼側、始めたが定着しない依頼側は多く、実際に運用してきた人が求められています。ただし、制度の数値や要件、法的な判断は、副業の範囲で扱わず、依頼側が公的な窓口と専門家に確認する形で示します。自分が担うのは、運用の設計と型です。**候補者の個人情報の扱いは[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に、定着の面談は[キャリアコンサルタントが副業でできること](/media/fukugyo-kyaria-consultant-fukugyo/)に、法改正の追い方は[法改正の追い方](/media/fukugyo-houkaisei/)にまとめています。

## この経歴の何が売れるか

障害者雇用の担当の経験を、副業の工程に置き換えた棚卸しです。制度の判断は含まず、運用の設計と型に絞ります。

| 担当の経験 | 副業の工程への置き換え | 依頼側にとっての価値 |
|---|---|---|
| 業務の切り出しをしてきた | 依頼側の業務を分解し、切り出せる業務と、切り出し方（手順の明文化、判断の少ない形）を設計する | 「任せられる仕事が無い」と思い込んでいる依頼側が多い |
| 受け入れの体制を作ってきた | 受け入れる部署、担当する社員、相談の窓口、最初の期間の流れを設計する | 体制が無いまま受け入れ、現場が困る依頼側が多い |
| 面談を設計し、実施してきた | 採用の面談で、配慮の希望と業務の適性を、本人の言葉で聞き取る面談の型を作る | 面談で何を聞いてよいか分からず、聞くべきことを聞けていない依頼側が多い |
| 支援機関と連携してきた | 支援機関との連携の流れ（誰が、いつ、何を共有するか）の型を作る | 支援機関との連携の仕方を知らない依頼側が多い |
| 定着の面談と仕組みを回してきた | 入社後の面談の頻度、聞くこと、現場との共有の仕組みを設計する | 採用して終わり、定着しない依頼側が多い |
| 現場の理解を作ってきた | 受け入れる現場の社員向けの説明の型を作る | 現場の不安が受け入れの壁になっている依頼側が多い |
| 制度の変化を追い、確認先を知っている | 制度に関わることは「確認が要る」と示し、公的な窓口と専門家への確認先を整理する（内容の判断はしない） | 確認先を知らない依頼側が多い |

売れるものの要点は、「制度の知識ではなく、運用の設計と型が売れる」ことです。依頼側が困っているのは、制度の内容より、「実際にどう業務を切り出し、どう受け入れ、どう定着させるか」で、それは運用してきた人にしか設計できません。制度の数値と要件と法的な判断は、変わるものであり、副業の範囲で扱うと事故になるので、「確認が要る」と示し、公的な窓口と専門家に委ねます。自分の範囲は、運用の設計と型です。範囲の決め方は[業務範囲を書面で固める](/media/fukugyo-scope/)に、現場との関係は[現場との関係の作り方](/media/fukugyo-genba-chousei/)に書いています。

## 売りにくい点とその扱い

障害者雇用の担当の転身で売りにくい点は三つあり、扱い方があります。

| 売りにくい点 | 依頼側の懸念 | 扱い方 |
|---|---|---|
| 制度の判断との線 | 「制度のことも全部教えてくれるのか」「要件を満たすかどうか判断してくれるのか」 | 制度の内容と要件の判断は範囲に入れない。「制度に関わることは、公的な窓口と専門家に確認する形で進めます。私は運用の設計と型を担います」と契約の前に示す |
| 個人情報と配慮の線 | 「候補者の障害や配慮の情報を、どう扱うのか」「本人の同意なく現場に伝えるのでは」 | 本人の同意と、伝える範囲と、伝える相手を、最初に決める型を持つ。本人の言葉で聞き、本人が同意した範囲で共有する。個人情報の扱いの線を契約に書く |
| 依頼側の理解の差 | 「うちの現場は受け入れに消極的で、設計しても動かないのでは」 | 現場の理解を作る説明の型を、範囲に入れる。設計だけでなく、最初の受け入れの一巡を一緒に回す |

扱い方の要点は、「個人情報と配慮の線」を、最初に型として示すことです。障害者雇用では、本人の障害と配慮の情報が、採用と受け入れの中で扱われます。その情報を、誰が、誰に、どの範囲で、本人のどの同意のもとで共有するかが曖昧だと、本人の信頼と依頼側の信用の両方を失います。「本人の言葉で聞き、本人が同意した範囲で、受け入れに要る人にだけ共有する」型を持ち、契約に書きます。個人情報の線は[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に、守秘の線は[守秘の線を越える](/media/fukugyo-shippai-8/)に、面談の型は[ヒアリング力の磨き方](/media/fukugyo-hearing-skill/)に整理しています。

### エラベルの見解

担当する側から見ると、障害者雇用の担当の経験で副業を続けている人と、一件で終わる人の差は、制度の知識の量ではなく、「制度の判断を範囲に入れていないか」と「現場の一巡を一緒に回しているか」です。一件で終わる人は、依頼側から制度の要件や数値の判断を求められ、それに答える形になり、制度が変わったときや個別の状況で違ったときに、責任の所在が曖昧になって続けられなくなっています。続いている人は、「制度は公的な窓口と専門家に。私は運用を」と線を引き、業務の切り出しと受け入れの設計を、現場と一緒に最初の一巡まで回し、依頼側から「実際に受け入れが動いた」と評価されています。

見ていて差がつくのは、業務の切り出しで、「任せられる仕事が無い」という依頼側の思い込みを、業務の分解で崩しているかです。依頼側の多くは、業務を「一人の社員が全部やる」単位で見ていて、切り出せる部分が見えていません。担当の経験がある人は、業務を工程に分解し、手順を明文化できる部分、判断が少ない部分を抜き出し、「この部分なら」と具体的に示せます。この分解の型を持っている人は、依頼側の受け入れが始まる最初の壁を崩しています。エラベルでは、依頼側が担当者を選ぶ仕組みなので、運用の設計と型を明確にし、制度の判断との線を示している担当者に、受け入れで詰まっている依頼側がついています。障害者雇用の担当の転身は、制度ではなく、運用で始まります。

## 案件の探し方

障害者雇用の担当から入りやすい案件と、探し方です。

| 入りやすい案件 | 理由 | 探し方 |
|---|---|---|
| 業務の切り出しの設計 | 分解の型で入れる | 「任せられる仕事が無いと思っている依頼側の、業務の分解と切り出し」を範囲の一言に |
| 受け入れの体制と最初の期間の流れの設計 | 体制を作ってきた経験で入れる | 「受け入れる部署、担当、窓口、最初の期間の流れ」を示す |
| 採用の面談の型 | 面談を設計してきた経験で入れる | 「配慮の希望と業務の適性を、本人の言葉で聞く面談の型」を示す |
| 支援機関との連携の型 | 連携してきた経験で入れる | 「誰が、いつ、何を共有するかの流れ」を示す |
| 定着の面談と仕組み | 定着を回してきた経験で入れる | 「定着しない依頼側」を範囲の一言に |
| 現場向けの説明の型 | 現場の理解を作ってきた経験で入れる | 「現場の不安を減らす説明」を提案の形で |

探し方の要点は、「これから始める依頼側」と「始めたが定着しない依頼側」の二つに絞ることです。前者は業務の切り出しと受け入れの設計、後者は定着の面談と仕組みが入口になります。どちらも、制度の判断ではなく、運用の設計で価値が出ます。制度の相談から入ると、範囲が制度の判断に寄るので、運用の詰まりから入ります。案件の探し方は[案件の探し方](/media/fukugyo-anken-sagashi/)に、面談で聞くことは[こちらから聞くべき質問](/media/fukugyo-mensetsu-shitsumon/)に書いています。

## 単価の目安

単価は、具体的な額ではなく、決まり方の構造で考えます。障害者雇用の担当の転身で、単価に影響する要素です。

| 要素 | 単価への影響 | 考え方 |
|---|---|---|
| 運用の設計の経験の希少さ | 実際に受け入れと定着を回してきた人は少なく、依頼側にとって価値が高い | 経験の希少さを、運用の型で示す |
| 成果物で受けやすい工程 | 業務の切り出しの一覧、受け入れの流れ、面談の型、連携の型は、成果物で受けやすい | 成果物で受けると、制度の判断との線も明確になる |
| 最初の一巡の実行 | 設計だけでなく、最初の受け入れを一緒に回す部分は、工程で受ける | 設計の成果物と、一巡の実行を分けて見積もる |
| 定着の面談の継続 | 入社後の面談は、回数で受けやすい | 一回あたりと、月の回数の上限を決める |
| 制度の判断を含まないこと | 制度の判断を含まない範囲は、含む範囲より単価は下がるように見えるが、責任の線が明確な分、続く | 制度の判断は範囲に入れず、その分を運用の型で示す |
| 本業との利益相反 | 本業の会社と競合する依頼側、本業の候補者や支援機関の関係を持ち込む形は避ける | 本業の関係と情報を副業に持ち込まない |

単価の要点は、「設計の成果物と、一巡の実行と、定着の面談の回数を分けて示す」ことです。障害者雇用の受け入れは、設計して終わりではなく、最初の一巡を回し、定着の面談を続ける工程で、一つの単価にまとめると、依頼側にも自分にも分かりにくくなります。三つに分けて示せば、依頼側は必要な部分だけを頼め、自分は範囲を守れます。単価の構造は[人事の副業単価の相場](/media/fukugyo-tanka-souba/)に、本業との線は[本業と利益相反になる案件](/media/fukugyo-riekisouhan/)に整理しています。

## 始める順番

障害者雇用の担当から副業を始める順番です。

| 順番 | 内容 |
|---|---|
| 一、本業で回してきた運用（業務の切り出し、受け入れ、面談、連携、定着）を、本業の会社と本人の情報を含まない型で書き出す | 守秘の線を守った型 |
| 二、制度の判断を範囲に入れない、と決める | 「確認が要る」と示し、公的な窓口と専門家への確認先を整理する形に |
| 三、個人情報と配慮の情報の扱いの型を、自分の言葉で書く | 本人の同意、伝える範囲、伝える相手 |
| 四、本業の会社との利益相反の線を引く | 競合、本業の候補者、本業で関わった支援機関の関係を持ち込まない |
| 五、範囲を、業務の切り出し、受け入れの設計、面談の型、連携の型、定着の仕組みに絞る | 制度の判断と法的な判断は範囲外 |
| 六、「受け入れの設計と運用を、実際に回してきた型で」の一言を作る | 「制度に詳しいです」とは言わない |
| 七、登録先に、範囲と、制度の判断との線を登録する | これから始める依頼側と、定着しない依頼側 |
| 八、業務の切り出しか定着の面談を一件、成果物で受け、型を残す | 次の工程に広げる材料に |

順番の要点は、「二」と「三」を、案件を探す前に決めることです。制度の判断を範囲に入れないこと、個人情報と配慮の情報の扱いの型を持つことは、障害者雇用の副業で最も重要な線で、この二つが曖昧なまま始めると、依頼側にも本人にも不利益が出ます。線を決め、契約に書き、その上で運用の設計を売ります。自己紹介の型は[自己紹介文のテンプレート](/media/fukugyo-jiko-shoukai/)に、プロフィールは[プロフィールの書き方](/media/fukugyo-profile/)に書いています。

### エラベルの見解

相談で最も多い思い込みは、「障害者雇用は制度が絡むので、副業で扱うのは難しい」というものです。実際には、依頼側が困っているのは制度の内容より運用で、業務の切り出し、受け入れの体制、面談、連携、定着を実際に回してきた人の型は、制度の判断を含めなくても価値が高いです。難しいのは、制度の判断を範囲に入れてしまう場合で、入れなければ、運用の設計として受けられます。

順番として、本業で回してきた運用を型で書き出し、制度の判断を範囲に入れないと決め、個人情報と配慮の情報の扱いの型を書き、本業との利益相反の線を引き、範囲を運用の設計に絞り、実際に回してきた型の一言を作り、登録先に範囲と線を登録し、業務の切り出しか定着の面談を一件成果物で受ける。この順番で、障害者雇用の担当の転身は、「制度が絡むから難しいもの」から「運用の型で価値を出すもの」になります。エラベルでは、依頼側が担当者を選ぶ仕組みなので、運用の設計と型を明確にし、制度の判断との線を示している担当者に、受け入れで詰まっている依頼側がついています。障害者雇用の担当の転身は、制度ではなく、運用で始まります。

## まとめ

- 障害者雇用の担当の経験は**「これから始める、または詰まっている依頼側の、受け入れの設計と運用」**で売れる。**業務の切り出し・受け入れの設計・支援機関との連携の型・定着の仕組み**の四つ
- **制度の数値と要件と法的な判断は範囲に入れない**。「確認が要る」と示し、公的な窓口と専門家に委ねる
- **個人情報と配慮の情報の扱いの型**（本人の同意・伝える範囲・伝える相手）を最初に示し、契約に書く
- 業務の切り出しで**「任せられる仕事が無い」という思い込みを、業務の分解で崩す**
- 案件は**これから始める依頼側と、定着しない依頼側**から。制度の相談ではなく運用の詰まりから入る
- 単価は**設計の成果物・一巡の実行・定着の面談の回数を分けて示す**。本業の関係と情報は持ち込まない

## よくある質問

### 依頼側から「制度の要件を満たすには何人必要か」と聞かれました。答えてよいですか

制度の数値と要件は、変わるものであり、個別の状況で結果が違うため、副業の範囲では答えず、「制度の要件は、公的な窓口と専門家に確認してください。確認先を整理してお渡しします」と、確認先を示す形にします。答えてしまうと、制度が変わったときや、依頼側の状況が違ったときに、責任の所在が曖昧になります。自分が担うのは、要件が確認された後の、受け入れの設計と運用です。線の引き方は[業務範囲を書面で固める](/media/fukugyo-scope/)に、制度の変化の追い方は[法改正の追い方](/media/fukugyo-houkaisei/)に整理しています。

### 面談で聞いた本人の配慮の希望を、現場にどこまで伝えてよいですか

本人の同意の範囲で、受け入れに要る人にだけ、受け入れに要る内容だけを伝えます。面談の前に、「聞いたことのうち、受け入れに要ることは、本人の同意を得たうえで、受け入れる部署の担当に伝えます。それ以外は伝えません」と本人に示し、面談の後に「これを、この人に、この範囲で伝えてよいですか」と確認します。本人の同意なく伝えると、本人の信頼と依頼側の信用の両方を失います。個人情報の線は[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に、候補者対応は[候補者対応で気をつけること](/media/fukugyo-kouhosha-taiou/)に書いています。

### 本業で連携している支援機関を、副業の依頼側に紹介してよいですか

本業で作った支援機関との関係を、副業に持ち込むことは避けます。本業の会社の関係を副業に使う形になり、本業との利益相反と、支援機関との信頼の両方に関わります。副業の依頼側には、「支援機関との連携の流れの型」を渡し、連携先は依頼側が地域の公的な窓口を通して探す形にします。本業で得た「連携の型」は使えますが、「本業で作った関係そのもの」は使いません。線の引き方は[本業と利益相反になる案件](/media/fukugyo-riekisouhan/)に整理しています。

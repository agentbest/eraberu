依頼側から「これもお願いできますか」と言われるたびに、「はい」と答えてきた。気づけば、契約の範囲を大きく超える量を抱え、期限に遅れ始め、依頼側からは「最近、動きが鈍い」と言われている。断ればよかったのに、断れなかった。結論を先に書くと、**「断れずに抱え込む」は、人事の副業で最も多い失敗で、性格の問題ではなく、範囲と稼働の線を先に決めていないことから起きます。線が無いと、依頼のたびに「できるか」を自分の気持ちで判断することになり、気持ちは「断りたくない」に傾きます。線があれば、依頼を線に当てて「入るか入らないか」で判断でき、断ることは気持ちの問題ではなく事実の確認になります。**抱え込んだ後に遅れて信頼を失うより、その場で線を引いて断るほうが、依頼側との関係は続きます。無理な依頼の伝え方は[無理なときの伝え方](/media/fukugyo-warukunai-kotowari/)に、範囲の広がりの扱いは[範囲が広がっていくとき](/media/fukugyo-scope-creep/)に、安請け合いを避ける考え方は[安請け合いを避ける](/media/fukugyo-yasuuke/)にまとめています。

## 抱え込みが起きる場面

抱え込みは、一度の大きな依頼で起きるのではなく、小さな依頼の積み重ねで起きます。

| 場面 | 依頼の形 | なぜ断れないか |
|---|---|---|
| 定例の終わりの一言 | 「ついでに、これも見てもらえますか」 | 「ついで」に聞こえ、断るほどのことではないと感じる |
| 候補者の対応の延長 | 「その候補者の条件の相談にも乗ってあげてください」 | 候補者を待たせたくない。範囲外だと気づく前に動いてしまう |
| 依頼側の担当者が困っているとき | 「面接官が急に来られなくなったので、代わりに」 | 担当者を助けたい。断ると冷たいと感じる |
| 成果が出た直後 | 「こんなにうまくいったので、次はこれも」 | 評価されている嬉しさで、範囲を考えずに受ける |
| 更新の直前 | 「次の期も続けてほしい。それで、これも追加で」 | 更新を断られたくない。追加を条件のように感じる |
| 「他の人はやってくれた」と言われたとき | 「前の担当者はやってくれていた」 | 比べられて、自分もやらないといけないと感じる |
| 感謝された直後 | 「いつも助かっています。それで、お願いが」 | 感謝の後で断ると、感謝を裏切るように感じる |

場面の要点は、「小さく、断りにくい形で来る」ことです。一つ一つは小さく、断るほどではないと感じますが、積み重なると範囲の外の稼働が範囲の中を超えます。小さいからと受け続けると、どこで線を引けばよいか分からなくなります。

## 抱え込んだ後に起きること

抱え込んだ結果は、抱え込んだ本人だけでなく、依頼側にも及びます。

| 起きること | 本人の側 | 依頼側の側 |
|---|---|---|
| 範囲内の工程が遅れる | 抱えた分で稼働が足りず、本来の工程が後回しになる | 頼んだ範囲の仕事が遅れる。「追加を頼んだせいで」とは思わず、「遅い人」と思う |
| 品質が下がる | 全部を薄くやることになり、どれも中途半端になる | 「前はもっと丁寧だった」 |
| 本業に影響する | 副業の枠を超えて本業の時間を削る | 見えないが、担当者の稼働が不安定になる |
| 稼働報告と請求が合わなくなる | 範囲外の稼働を報告に書けず、実態より少ない請求になる | 実態が見えないまま、範囲が広がったと認識しない |
| 更新のときに根拠が無い | 範囲が広がったことを記録していないので、条件の見直しができない | 「今の条件で続けてほしい」となる |
| 突然、続けられなくなる | 限界が来て、稼働が落ちるか、辞めると言うことになる | 「急に」と感じる。引き継ぎも整わない |
| 断れない人として固定される | 依頼側の中で「頼めば何でもやる人」になり、依頼が増え続ける | 悪気なく、頼み続ける |

起きることの要点は、「依頼側は、追加を頼んだことと、遅れたことを結びつけない」ことです。依頼側の担当者は、追加の依頼を小さなものと思っていて、それが原因で本来の工程が遅れているとは思いません。遅れは「この人が遅い」として見られ、追加を受けた善意は評価に残りません。抱え込みは、善意で受けて、悪い評価で終わる失敗です。

### エラベルの見解

相談で最も多い思い込みは、「断ると、依頼側との関係が悪くなる」というものです。実際には、依頼側との関係が悪くなるのは、断った人ではなく、引き受けて遅れた人です。担当者は、断られたことより、頼んだものが出てこないことで困ります。その場で「それは範囲の外なので、代わりに〇〇なら」と言われた担当者は、社内に「〇〇の形で進める」と伝えられ、困りません。引き受けて遅れた場合、担当者は社内に説明できず、担当者自身の立場が悪くなります。

見ていて差がつくのは、依頼が来たときに「線に当てる」習慣があるかです。線がある人は、依頼を聞いた瞬間に「範囲の中か外か」「今の枠に入るか」を見て、外なら理由を添えて断り、代わりの案を出しています。線が無い人は、依頼を聞いた瞬間に「断りたくない」が先に来て、受けてから考えます。エラベルでは、依頼側と担当者の契約の範囲を工程の単位で明確にし、範囲外の依頼が来たときは担当者が個別に判断するのではなく、窓口を通して範囲の見直しとして扱う形も取っています。断る負担を担当者一人に置かない仕組みが、抱え込みを防ぎます。

## 断れない構造

断れないのは、性格ではなく構造です。構造が分かれば、直せます。

| 構造 | 内容 | 直し方 |
|---|---|---|
| 線が無い | 範囲と稼働の上限が決まっていないので、依頼のたびに気持ちで判断する | 範囲を工程で、稼働を週の枠で、先に決める。[受ける範囲の決め方](/media/fukugyo-scope/)、[稼働時間の上限](/media/fukugyo-kadou-jikan/) |
| 断る言葉を持っていない | 「できません」の後に何を言えばよいか分からず、言えない | 「できないこと→できること→判断を返す」の三段を型として持つ。[無理なときの伝え方](/media/fukugyo-warukunai-kotowari/) |
| 依頼側の担当者を助けたい | 担当者の困りごとを見ると、自分の枠を忘れる | 助ける形を「範囲の中でできること」に限る。範囲の外を引き受けることは、結果として担当者を助けない |
| 評価を失うことを恐れる | 断ると「使えない」と思われる、と感じる | 評価は、引き受けた量ではなく、引き受けたものを出したかで決まる。[評価される副業人材の共通点](/media/fukugyo-hyouka-sareru/) |
| 「今回だけ」を信じる | 一度受ければ終わると思う | 「今回だけ」は次も来る。受けるなら条件を付けて文面に残す |
| 稼働の実態を見ていない | 枠を超えていることに気づいていない | 稼働ログで工程ごとの時間を見る。[稼働ログの付け方](/media/fukugyo-log/) |

構造の要点は、「線が無い」が根にあることです。線があれば、断る言葉も「範囲の外なので」で足り、担当者を助けたい気持ちも範囲の中で発揮でき、評価の心配も「範囲の中を出している」で消えます。線を先に決めることが、断れない構造を直す最初の手です。

## 兆しの見つけ方

抱え込みは、限界が来る前に兆しが出ます。兆しの段階で気づけば、直せます。

| 兆し | 何が起きているか |
|---|---|
| 稼働ログに「契約外」の工程が増えている | 範囲の外の稼働が積み上がっている |
| 「はい」と答えた後に、後悔することが増えた | 気持ちで受けて、線に当てていない |
| 範囲内の工程の期限が、少しずつ遅れ始めた | 範囲外が範囲内を圧迫している |
| 稼働報告に書けない稼働がある | 範囲外の稼働を、報告に載せる根拠が無い |
| 依頼側からの依頼の頻度が上がっている | 「頼めばやる人」として認識され始めている |
| 副業のことを考えると気が重い | 枠を超えているか、範囲が合っていない |
| 「あの依頼、断ればよかった」と思う依頼が三つ以上ある | 線が無いまま受け続けている |

兆しの要点は、「稼働ログの契約外の工程」が最初に見える兆しだということです。ログに契約外の行が増え始めたら、それが抱え込みの始まりです。ログを付けていなければ、兆しは見えず、限界が来て初めて気づきます。稼働報告に「契約外」の行を分けて書く形は[稼働報告のフォーマット](/media/fukugyo-kadou-houkoku/)に整理しています。

## 防ぐための線の引き方

抱え込みを防ぐには、依頼が来る前に線を引いておきます。

| 線 | 引き方 | 使い方 |
|---|---|---|
| 範囲の線 | 契約の範囲を工程で書き、受けない工程も書く | 依頼が来たら「範囲の中か外か」を見る。外なら「範囲の外なので」と言える |
| 稼働の線 | 週の枠を、本業の繁忙期でも守れる量で固定する | 依頼が来たら「今の枠に入るか」を見る。入らなければ「今の稼働では」と言える |
| 立場の線 | 候補者への約束、依頼側の代表としての交渉、合否の判断は受けない | 依頼が来たら「立場の外か」を見る。外なら、稼働があっても受けない。[権限がないと動けない場面](/media/fukugyo-kengen-nai/) |
| 「今回だけ」の線 | 一度だけ受けるなら、条件（期間、範囲）を付けて文面に残す | 「今回だけ」と言われたら「今回は〇〇の形で、次回以降は範囲の見直しとして」 |
| 返事の線 | その場で「はい」と言わず、「確認して返事します」と一度持ち帰る | 気持ちで判断せず、線に当ててから返事をする。ただし、返事は当日中に |
| 記録の線 | 範囲外の依頼を受けた場合も、稼働ログと報告に「契約外」として書く | 更新のときの根拠になる。書けない稼働は受けない |

線の要点は、「返事の線」です。その場で「はい」と言わなければ、抱え込みの多くは防げます。「確認して、今日中に返事します」と持ち帰り、範囲と稼働の線に当てて、入るなら受け、入らないなら三段の型で断る。持ち帰る時間は数時間で足り、その数時間が、抱え込みと線引きの分かれ目になります。持ち帰った後の返事の仕方は[無理なときの伝え方](/media/fukugyo-warukunai-kotowari/)に書いています。

## 抱え込んでしまった後の立て直し

すでに抱え込んでいる場合、限界が来る前に立て直します。順番があります。

| 手順 | 内容 |
|---|---|
| 一、稼働ログで実態を出す | 範囲内と範囲外の工程を分けて、週の時間を出す。記憶ではなくログで |
| 二、範囲外の工程を一覧にする | いつから、どの依頼で、どれだけの稼働かを並べる |
| 三、依頼側に事実として伝える | 「契約の範囲は〇〇でしたが、現在は△△と□□も担当しており、稼働が週に〇時間超えています」と、責めずに事実で |
| 四、選択肢を出す | 「範囲外の工程を範囲に入れて条件を見直す」「範囲外の工程を御社の社内に戻す」「範囲外の工程を止める」の三つを並べ、依頼側に選んでもらう。[改善提案の伝え方](/media/fukugyo-kaizen-teian/) |
| 五、決まったら文面に残す | 議事録か覚書で、新しい範囲と稼働を記録する |
| 六、線を引き直す | 範囲と稼働の線を、今回の経験を踏まえて決め直す。次の依頼から線に当てる |

立て直しの要点は、「三」で依頼側を責めないことです。「追加ばかり頼まれて困っている」と言うと、依頼側は責められたと感じます。「契約の範囲と、現在の実態がずれている」と事実で伝えれば、依頼側は実態を知り、選択肢から選べます。依頼側は、範囲が広がっていることを認識していないことが多く、事実を見せれば「そんなに増えていたのか」となります。条件の見直しの進め方は[更新時の条件見直し](/media/fukugyo-keiyaku-koushin-koushou/)に整理しています。

## 関係を保ちながら手放す形

抱え込んだものを手放すとき、依頼側との関係を保つ形があります。

| 手放し方 | 内容 | 関係への影響 |
|---|---|---|
| 範囲に入れて条件を見直す | 範囲外だったものを正式に範囲に入れ、稼働と単価を合わせる | 依頼側は「実態に合わせた」と受け取る。最も関係が保てる |
| 依頼側の社内に戻す | 範囲外の工程を、依頼側の担当者か社内の人に戻す。戻すための型と手順を渡す | 「投げ返した」ではなく「型を渡して戻した」なら、関係は保てる |
| 期限を切って止める | 「〇月まではやるが、以降は範囲から外す」と、移行の期間を置く | 急に止めるより、依頼側が準備できる |
| 別の担当者を足してもらう | 範囲外の工程を、依頼側が別の外部の担当者に頼む。窓口を通していれば窓口に相談 | 自分の範囲は保たれ、依頼側の困りごとも解消する |
| 全部を急に止める | 限界が来て、範囲外も範囲内も止まる | 避ける。関係が切れる |

手放す要点は、「型を渡して戻す」ことです。範囲外の工程を依頼側に戻すとき、自分がやっていた手順と型を文書にして渡せば、依頼側は「投げ返された」ではなく「引き継がれた」と受け取ります。自分の稼働は減り、依頼側の困りごとは型で解消し、関係は保てます。引き継ぎの整え方は[引き継ぎの進め方](/media/fukugyo-hikitsugi/)に、依頼側の社内の人との分担は[社内の人事担当との役割分担](/media/fukugyo-shanai-jinji/)に書いています。

### エラベルの見解

担当する側から見ると、抱え込みで止まった人と、線を引いて続いている人の差は、人事の能力ではなく、「その場で『はい』と言わない」習慣の有無です。線を引いて続いている人は、依頼を持ち帰り、線に当て、当日中に返事をしています。断るときは三段の型で、代わりの案を添えています。依頼側の担当者は、その人を「範囲が明確で、頼みやすい」と評価しています。抱え込んで止まった人は、その場で「はい」と言い、後で遅れ、依頼側から「遅い」と評価されています。

順番として、案件の最初に範囲・稼働・立場の線を引き、依頼が来たら持ち帰って線に当て、入るなら受け、入らないなら三段で断り、範囲外を受けるなら条件を付けて文面に残し、稼働ログで契約外の工程を見て、兆しが出たら事実で依頼側に伝えて選択肢を出す。この順番で、抱え込みは起きません。エラベルでは、依頼側と担当者の範囲を契約で明確にし、範囲外の依頼は窓口を通して範囲の見直しとして扱う形を取っています。断る負担を仕組みで支えることが、担当者を抱え込みから守ります。

## まとめ

- 「断れずに抱え込む」は**性格ではなく、範囲と稼働の線が無い構造**から起きる
- 抱え込みは**小さく、断りにくい形で**来て、積み重なる。依頼側は追加と遅れを結びつけない
- 抱え込んだ後は**範囲内が遅れ・品質が下がり・本業に影響し・報告に書けず・更新の根拠が無く・突然止まる**
- 兆しは**稼働ログの契約外の工程**が最初。ログが無ければ気づけない
- 防ぐには**範囲・稼働・立場・「今回だけ」・返事・記録**の六つの線。特に**その場で「はい」と言わず、持ち帰って当日中に返事**
- 立て直しは**ログで実態→範囲外の一覧→事実で伝える→選択肢を出す→文面に残す→線を引き直す**
- 手放すときは**型を渡して戻す**。全部を急に止めない

## よくある質問

### 依頼側の担当者が本当に困っていて、断るのが心苦しいです

担当者の困りごとを助ける形は、範囲の中でもあります。「その工程は範囲の外ですが、〇〇の形なら私の範囲で助けられます」と、範囲の中の手段を出せば、担当者を助けつつ線は守れます。範囲の外を引き受けて遅れれば、結果として担当者を助けることにならず、担当者の立場を悪くします。心苦しさは、断ることではなく、引き受けて出せないことから来るほうが大きいです。担当者を守る伝え方は[無理なときの伝え方](/media/fukugyo-warukunai-kotowari/)に整理しています。

### すでに「何でもやる人」として見られています。今から線を引けますか

引けます。更新の節目が最も自然で、「次の期から範囲を明確にしたい」と、契約の範囲の見直しとして出します。節目まで遠いなら、稼働ログの実態を事実として伝え、「現在の稼働が契約の範囲を超えているので、範囲を整理させてください」と切り出します。急に全部を断るのではなく、範囲外の工程を一覧にして、範囲に入れるか戻すかを依頼側と決めれば、「急に態度が変わった」とは受け取られません。

### 断ったら、依頼側から「じゃあ他の人に頼む」と言われました

依頼側の判断として受け入れます。範囲外の工程を別の人に頼むのは、依頼側にとって正しい選択で、自分の範囲は保たれます。「範囲の外については、そのほうが御社にとってもよいと思います」と返し、自分の範囲の工程は変わらず続けます。もし範囲内の工程まで「他の人に」と言われたなら、それは契約の終了の話で、契約の条項に沿って進めます。線を引いたことで契約が終わるなら、その依頼側は「何でもやる人」を求めていて、自分の範囲と合っていなかったということです。合わない案件の見分け方は[合わない案件の見分け方](/media/fukugyo-awanai-anken/)に書いています。

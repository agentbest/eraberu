新卒のスカウトを外注するとき、最初に決めるのは「何を任せるか」ではなく「**どの権限を渡すか**」です。権限が決まると、任せられる範囲が自動的に決まるからです。結論を先に書くと、**Wantedlyの採用サービスの権限は「管理者」「担当」「メンバー」「なし」の四つで、ヘルプセンターによれば、管理画面（採用機能）へのアクセス・募集の作成・スカウトの送信ができるのは「管理者」と「担当」だけです。そして「担当」は、候補者のプロフィール確認が「未対応」と「担当者に設定された候補者」のみに限られます**。仕様は変わるので、契約する前に公式の案内で確認してください。以下は、2026年9月23日時点でWantedlyのヘルプセンターに記載されている内容に基づいて整理しています。選定の型は[Wantedly（新卒）のプロフィール選定基準の作り方](/media/scout-shinsotsu-wantedly-shinsotsu-screening/)にまとめています。

## 権限の四段階

ヘルプセンターの「権限について」は、会社アカウントについて「**全体の権限**」「**採用サービスの権限**」「**エンゲージメントサービスの権限**」をそれぞれ設定できるとしたうえで、「権限によって閲覧可能ページや操作内容が異なるため、管理者は利用範囲に応じて社員に合う権限を設定してください」と説明しています。

**採用サービスの権限（同ページの記載）。**

| できること | 管理者 | 担当 | メンバー | なし |
|---|---|---|---|---|
| 管理画面（採用機能）へのアクセス | ◯ | ◯ | ✕ | ✕ |
| 募集の作成 | ◯ | ◯ | ✕ | ✕ |
| 募集条件の作成 | ◯ | ◯ | ✕ | ✕ |
| ストーリーの作成 | ◯ | ◯ | ◯ | ✕ |
| **候補者のプロフィール確認** | ◯（**全ての候補者**の確認可能） | ◯（**「未対応」と「担当者に設定された候補者」のみ**確認可能） | ✕ | ✕ |
| スカウトの送信 | ◯ | ◯ | ✕ | ✕ |
| メッセージの送付（本選考案内含む） | ◯ | ◯ | ✕ | ✕ |
| 会社ページへのメンバー表示 | ◯ | ◯ | ◯ | ✕ |

**外注先に渡すのは「担当」が基本です。**スカウトの送信、募集の作成、メッセージの送付ができて、候補者のプロフィール確認は「未対応」と「担当者に設定された候補者」に限られます。**自社の選考が進んでいる候補者の情報までは見えない**、という線を引けます。

**全体の権限は別です。**同ページは、全体の権限について「メンバー追加やプラン変更など、メンバー管理や請求/会社情報に関する画面のアクセスに必要な権限です」とし、「会社アカウントには、**最低1名の全体の『管理者』の登録が必要**です」としています。全体の「管理者」は、メンバーの追加・削除、契約・支払い方法の確認・変更、ベースプランやオプションの申し込み、会社情報・基本情報の確認・変更ができる、とされています。

**外注先に全体の「管理者」は渡しません。**契約や支払いに触れる権限なので、社内に残します。外注先には**全体は「メンバー」、採用サービスは「担当」**という組み合わせが、条文上の線としては素直です。

**アクセス人数に上限があります。**同ページは「契約プランによって管理画面にアクセスできる上限人数が異なります。※採用の『管理者』『担当』権限を付与されたアカウントの合計がカウントされます」としたうえで、次を示しています。

| 契約プラン | 管理画面にアクセスできる人数 |
|---|---|
| ライトプラン | 15人 |
| スタンダードプラン | 30人 |
| プレミアムプラン | 無制限 |

**外注先の人数が枠を食います。**代行会社から三人入れば、三人ぶんの枠が減ります。ライトプランで社内に十三人いるなら、渡せるのは二人までです。**契約前に、誰が何人入るかを数えます。**

## 外に出す範囲を決める

新卒スカウトの作業を分解すると、次のようになります。それぞれについて、外に出すか社内に残すかを決めます。

| 作業 | 外に出しやすさ | 判断の材料 |
|---|---|---|
| 募集の作成・更新 | △ | 事業の言葉が要る。社内で原案を作り、外で整える形が現実的 |
| 抽出条件の設計 | ◯ | 新卒フィルター・職種・地域・フリーワードの組み合わせ |
| 候補者の選定 | ◯ | 基準を文章にして渡せば任せられる |
| 文面の作成 | △ | 共通部分は外、冒頭の固有部分は素材を渡して外 |
| **送信予約** | ◯ | 営業日9:00〜18:00の配信になる仕様を理解していれば回る |
| 再送の管理 | ◯ | 前回送信後1週間（3通目以降は1年）の条件で絞り込む |
| **返信対応** | ✕ | 選考の入口。社内で持つほうが速い |
| 日程調整 | △ | 面接官の予定に触れる。ツール次第 |
| 週次の集計 | ◯ | 送信数・開封数・返信数・面談設定数 |

**返信対応を社内に残すと、権限の設計が楽になります。**外注先が「担当」権限なら、候補者のプロフィール確認は「未対応」と「担当者に設定された候補者」のみです。返信が来た候補者を社内の担当者に割り当てれば、外注先の視界から外れます。**権限の仕様が、そのまま業務分担の線になります。**

**送信予約の仕様を共有します。**ヘルプセンターの「スカウトの送信予約を利用したい」は、送信タイミングについて「**土日祝を除く営業日の朝9：00より順次配信**されます」とし、営業日9:00〜18:00外の予約は直近営業日、内の予約は翌営業日の9:00〜18:00に送信されると例示しています。**外注先の稼働日と、この配信タイミングを合わせて週次の締めを決めます。**

**エラーの責任分界を決めます。**同ページは、送信エラーの要因として、候補者がスカウト受け取り設定を変更した場合、**送信予定日がスカウトチケットの有効期限を超過している場合**、**送信予約数がスカウトチケットの残数を超過している場合**、**送信予約に紐づいた募集が募集停止ステータスに変更された場合**などを挙げています。チケットの購入は全体の「管理者」の領域、募集の公開停止は社内の判断であることが多いので、**どちらが何を見るか**を決めておきます。

**記録の置き場所を決めます。**ヘルプセンターの「スカウトの『気になる』について」は、気になるリストのメモが「候補者一覧のプロフィール下に表示されます」としています。外注先が書いたメモは、社内からも読めます。**判断の理由をメモに残す**ことを契約の条件にしておくと、引き継ぎが楽になります。

### エラベルの見解

依頼側から見ると、スカウト代行の失敗は「範囲が曖昧なまま始める」ことから起きます。送信は頼んだが、返信が来たときに誰が答えるか決めていない。学生から質問が来て、外注先が答えられず、社内に回って三日かかる。新卒は複数社を並行して見ているので、三日は致命的です。

だから、**範囲より先に「返信が来たらどうするか」を決める**ことを勧めています。ここが決まると、権限の設計も、連絡の経路も、自動的に決まります。Wantedlyの「担当」権限が、候補者のプロフィール確認を「未対応」と「担当者に設定された候補者」に限っているのは、この分担を想定した作りです。仕様に沿って分けると、余計なルールを作らずに済みます。

もう一つ、**アクセス人数の上限を先に数える**こと。ライトプランは15人、スタンダードプランは30人、プレミアムプランは無制限とされていて、採用の「管理者」「担当」の合計でカウントされます。代行会社は複数名でシフトを組むことがあるので、何人ぶんの枠が必要かを見積もりの段階で聞きます。ここを確かめずに契約して、後から枠が足りずにプランを上げる、という流れは避けられます。

エラベルでは、依頼側が担当者の経歴を見て選ぶ仕組みにしています。新卒のスカウト代行は、媒体の操作よりも**学生の動く時期と、返信の速さ**で結果が変わるので、新卒採用を自分で回した経験がある担当者を選ぶと、初月から週次の設計ができます。

## 契約の前に決めること

外注する前に、次を一枚にします。

| 決めること | 中身 |
|---|---|
| 権限 | 外注先は全体「メンバー」＋採用「担当」。全体「管理者」は社内に残す |
| アカウント数 | 外注先が何人入るか。プランの上限に収まるか |
| 作業の範囲 | 抽出／選定／文面／送信予約／再送／集計のどこまで |
| 返信対応 | 社内の誰が、いつまでに返すか。担当者への割り当ての手順 |
| 募集の管理 | 誰が作り、誰が公開・停止するか。停止時の予約の扱い |
| チケット | 購入は誰が。残数と有効期限を誰が見るか |
| 記録 | 気になるリストのラベル・メモ・評価の書き方。週次の集計の様式 |
| 報告 | 週次で何を報告するか。送信数・開封数・返信数・面談設定数 |
| 引き継ぎ | 契約終了時に何を残すか。抽出条件、文面、判断基準、記録 |
| 終了の手順 | アカウントの削除、権限の変更、データの扱い |

**引き継ぎを最初に決めます。**代行は、いつか終わります。終わったときに何が残るかを、始める前に決めておく。抽出条件、文面のテンプレート、選定の基準、気になるリストのラベル体系。これらが残っていれば、内製に戻すこともできますし、次の代行会社にも渡せます。

**募集単位で集計できます。**ヘルプセンターの「スカウト送信済みのユーザーの絞り込みについて」は、送信済みユーザーを**募集**（特定の募集または募集作成時に設定している職種）、**送信者名**、最終送信期間、開封有無、返信有無、再送で絞り込めるとしています。送信者名で絞れるので、**外注先が送った分だけを抜き出して集計できます**。報告の様式を決めるときに、この仕様を使います。

**重複送信を防ぐ担当を決めます。**同ページの仕様で、送信済みは確認できます。新卒は職種別・コース別に募集を複数立てることが多く、別の募集から同じ学生に送ってしまう事故が起きます。週次で送信済みを確認する担当を、社内か外注先のどちらかに明記します。媒体を複数使う場合の整理は[媒体の組み合わせ方](/media/scout-baitai-kumiawase/)にまとめています。

### エラベルの見解

依頼側から見ると、代行会社を選ぶときの判断材料は「実績」と言われがちですが、実際に効くのは**最初の三十分で何を聞かれるか**です。プランは何か、チケットは何通残っているか、有効期限はいつか、募集は誰が作っているか、返信は誰が返すか。ここを先に聞く担当者は、月の途中で止まりません。

逆に、いきなり「文面を見せてください」から入る担当者は、仕様の確認を後回しにしている可能性があります。Wantedlyは、プランによって使える絞り込みが変わり、アクセス人数に上限があり、送信予約の配信タイミングが決まっています。この三つを知らずに設計すると、途中で作り直しになります。

そして、**引き継ぎの話を自分から持ち出す担当者**は信用できます。契約が終わったときに何を残すかを最初に言う人は、自分がいなくなった後のことを考えています。これは、外部の人に仕事を任せるときの、分かりやすい判断材料です。

エラベルは、依頼側が担当者を選び、担当者も条件が合うときだけ受ける形にしています。新卒のスカウト代行は、期間が限られていて、途中で止まると取り返しがつきません。**最初の面談で仕様の確認から入る人**を選ぶと、そのあとが楽になります。

## まとめ

- 採用サービスの権限は**管理者／担当／メンバー／なし**の四つ。**管理画面へのアクセス・募集の作成・スカウトの送信ができるのは管理者と担当**
- **担当**は、候補者のプロフィール確認が「**未対応**」と「**担当者に設定された候補者**」のみ。管理者は全ての候補者を確認できる
- 全体の権限は別枠で、**最低1名の全体の「管理者」の登録が必要**。メンバー管理・契約・支払い・会社情報は全体の管理者の領域
- 管理画面にアクセスできる人数は、**ライト15人／スタンダード30人／プレミアム無制限**。採用の「管理者」「担当」の**合計でカウント**される
- 送信予約は**土日祝を除く営業日の朝9:00より順次配信**。エラー要因に**チケットの有効期限超過・残数超過・募集の停止**がある
- 送信済みは**送信者名**でも絞り込めるため、外注先が送った分だけを集計できる。仕様は変わるので、公式の案内でご確認ください

## よくある質問

### 代行会社にはどの権限を渡せばよいですか

Wantedlyのヘルプセンター「権限について」によれば、採用サービスの権限は管理者・担当・メンバー・なしの四つで、管理画面（採用機能）へのアクセス、募集の作成、スカウトの送信、メッセージの送付ができるのは「管理者」と「担当」です。「担当」は候補者のプロフィール確認が「未対応」と「担当者に設定された候補者」のみに限られるとされています。また、全体の権限は別に設定するもので、メンバー追加やプラン変更、契約・支払い方法の確認・変更には全体の「管理者」が必要とされています。自社の運用に合う組み合わせは、公式の案内を確認したうえで決めてください。

### 外注先を増やすと、社内の人が使えなくなりますか

同ページは「契約プランによって管理画面にアクセスできる上限人数が異なります。※採用の『管理者』『担当』権限を付与されたアカウントの合計がカウントされます」としたうえで、ライトプラン15人、スタンダードプラン30人、プレミアムプラン無制限と示しています。したがって、外注先のアカウントも同じ枠を使います。契約の前に、社内で何人が採用の「管理者」「担当」を持っているかと、外注先が何人入るかを数えておきます。

### 代行会社が送った分だけを集計できますか

「スカウト送信済みのユーザーの絞り込みについて」は、送信済みユーザーを募集、**送信者名**、最終送信期間、開封有無、返信有無、再送などで絞り込めるとしています。送信者名で絞れる仕様なので、誰が送った分かを分けて確認できます。あわせて、スカウトを送信する際には募集を選択して送信することとされているため、募集単位での集計も取れます。報告の様式を決めるときは、この二つを軸にすると、社内でも同じ数字を確認できます。

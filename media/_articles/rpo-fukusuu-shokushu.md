営業を二人、エンジニアを一人、事務を一人。四つの求人を同時に出している。人事は一人で、全職種の応募を見て、返信し、日程を組み、面接に同席し、結果を連絡する。どの職種も、返信が遅れ、面接が組めず、候補者が流れる。三か月経って、一人も決まっていない。結論を先に書くと、**複数職種を同時に採れないのは、「全部を同時に、同じ人が、同じ形で」回そうとしているからです。職種ごとに違う工程（要件、経路、面接官、観点）は分け、共通の工程（受付、返信、日程、連絡、記録）は一つにまとめます。分けるものと、まとめるものを整理すれば、同時に回ります。回らないなら、並行の数を減らします**。優先順位の付け方は[どの職種から採用すべきか決められない](/media/rpo-yuusen-jyuni/)に、スカウトでの職種の優先は[複数職種があるときの優先順位](/media/scout-shokushu-yuusen/)にまとめています。

## 同時に採れない構造

複数職種を同時に採れないのは、次の構造で起きます。

| 構造 | 起きていること |
|---|---|
| 一人が全職種の全工程を回している | 応募の確認、返信、日程、面接の同席、連絡を、四職種分。回らない |
| 職種ごとの違いを、同じ形で扱っている | 営業とエンジニアで、経路も観点も面接官も違うのに、同じ求人票の型、同じ面接の進め方 |
| 共通の工程を、職種ごとに別々にやっている | 受付の返信、日程の調整、記録を、職種ごとに別の表、別の文面で |
| 面接官が、職種ごとに違い、日程が組めない | 四職種の面接官の予定を、それぞれ調整。枠が取れない |
| 優先順位が無い | 四つを同じ重さで扱い、全部が薄くなる |
| 進み具合が、職種ごとに見えない | まとめて「採れていない」。どの職種がどこで止まっているかが分からない |
| 応募が多い職種に、時間が取られる | 事務の応募が多く、その対応で営業とエンジニアが後回し |

同時に採れない問題は、「人が足りない」より「分け方とまとめ方が無い」ことのほうが大きいです。

## 職種ごとに違う工程と共通の工程

工程を、職種ごとに違うものと、共通のものに分けます。

| 職種ごとに違う工程 | 理由 |
|---|---|
| 役割の記述と要件 | 職種で役割が違う。要件も違う |
| 求人票の中身 | 役割と働く理由が違う。型は共通でよい |
| 経路 | 営業は媒体と紹介、エンジニアはスカウトと特化型、事務は媒体と社員の紹介、のように違う |
| 面接官 | 職種の現場の責任者と一緒に働く人。職種ごとに違う |
| 面接の観点と質問 | 職種で見るものが違う |
| 書類の判断の基準 | 必須の要件が違う |
| 条件の幅 | 職種で違う |

| 共通の工程 | まとめ方 |
|---|---|
| 応募の受付と返信 | 一つの窓口、一つの文面の型（職種名を差し替え） |
| 候補者の表 | 一つの表、「職種」は列で |
| 日程調整 | 一つの仕組み（予約制の枠、または担当者）。面接官の枠は職種ごとに先に押さえる |
| 面接の案内の文面 | 一つの型（職種名と面接官を差し替え） |
| 結果の連絡 | 一つの型 |
| 記録の型 | 観点は職種ごと、記録の形は共通 |
| 月次の集計 | 一枚に、職種ごとの行 |
| 責任者への報告 | 一枚 |

分ける要点は、「中身は職種ごと、型と窓口は共通」です。中身まで共通にすると職種に合わず、型まで職種ごとにすると手間が四倍になります。

## 同時に回す設計

分けたものと、まとめたものを、同時に回す設計です。

**共通の工程を、一人（または担当者）が回す。** 受付、返信、日程、連絡、記録、集計。四職種分でも、型と窓口が一つなら、一人で回ります。毎朝の応募の確認は、四職種を一つの表で。

**職種ごとの工程を、職種の現場が担う。** 書類の判断（基準に沿って、観点一つで）、面接、判定。人事や担当者は、進行と記録。

**面接官の枠を、職種ごとに先に押さえる。** 「営業の面接官は火曜の午前に二枠、エンジニアの面接官は木曜の午後に一枠」。枠が先にあれば、日程調整は「枠に入れる」だけ。

**求人票と面接の観点を、職種ごとに一枚ずつ用意する。** 中身は違うが、型は同じ。作る手間は、二回目から減ります。

**経路を、職種ごとに分けて、運用は共通の担当者が回す。** 営業の媒体、エンジニアのスカウト、事務の社員の紹介。出す先は違うが、応募の受付は一つの窓口に。

**候補者の表を一つにして、職種の列で絞る。** 「いま営業は何人が選考中か」を、表を絞れば見える。

**週に一度、職種ごとの進み具合を確認する。** 一つの表を職種で絞って、止まっている候補者と、空欄を見る。

**月に一度、職種ごとの一枚を責任者に。** 応募・面接・内定・辞退と日数を、職種の行で。

設計の要点は、「共通の工程を一人が、職種ごとの工程を現場が」です。人事が職種ごとの工程（面接の同席、判定）まで抱えると、回りません。

## 並行の数の目安

同時に回せる職種の数には、限りがあります。目安です。

| 体制 | 同時に回せる目安 |
|---|---|
| 人事が一人、兼務 | 一〜二職種。それ以上は、共通の工程が回らない |
| 人事が一人、専任 | 二〜三職種 |
| 人事が一人＋採用代行の担当者 | 三〜五職種。共通の工程を担当者が回す前提 |
| 人事が二人以上 | 四職種以上。ただし、面接官の枠が取れるかで決まる |

目安を超える場合は、並行の数を減らします。減らす判断は、優先順位です。[どの職種から採用すべきか決められない](/media/rpo-yuusen-jyuni/)に書いています。

並行の数を減らすと、「後回しにした職種が採れない」と現場は言います。ただ、全部を薄く回して全部が採れないより、絞って順に採るほうが、結果として全部が早く採れます。

目安は、体制だけでなく、「面接官の枠」でも決まります。面接官が一人で四職種を見る形なら、枠が取れず、四職種は回りません。

### エラベルの見解

相談で最も多い失敗は、「四職種を同時に出し、人事が一人で全工程を回し、三か月で一人も採れず、『人事が足りない』で人事をもう一人採ろうとした」というものです。人事の問題ではなく、分け方の問題でした。共通の工程（受付、返信、日程、連絡、記録）を一つの窓口と型にまとめ、職種ごとの工程（判断、面接、判定）を現場に渡し、面接官の枠を職種ごとに先に押さえたら、同じ人事一人で、四職種が回り始めました。二か月で二職種が決まりました。

見ていて差がつくのは、担当者が「共通の工程を引き受ける」かどうかです。「四職種は多いので、優先順位を付けましょう」だけ言う担当者と、「受付・返信・日程・連絡・記録は、四職種分を私が一つの窓口で回します。人事の方は、職種ごとの判断と面接の進行に集中してください」と、共通の工程を引き受ける担当者がいます。後者がいれば、並行の数は増やせます。

発注側にできるのは、担当者に「共通の工程」を渡し、社内は「職種ごとの工程」に集中することです。

## 職種ごとの担当と面接官

職種ごとに、担当と面接官を決めます。

| 職種 | 現場の担当（書類の判断・面接・判定） | 面接官の枠 | 経路 | 観点の一枚 |
|---|---|---|---|---|
| 営業 | 営業の責任者と、一緒に働く人 | 火曜の午前、二枠 | 媒体A、紹介会社B | 営業用 |
| エンジニア | 開発の責任者と、一緒に働く人 | 木曜の午後、一枠 | スカウト、特化型媒体C | エンジニア用 |
| 事務 | 管理部の責任者 | 水曜の午前、一枠 | 媒体A、社員の紹介 | 事務用 |

表にすれば、「誰が、いつ、どの経路で、何を見るか」が職種ごとに見え、人事や担当者は進行に集中できます。

現場の担当が「忙しくて判断できない」場合は、[現場が採用に協力してくれない](/media/rpo-genba-kyouryoku/)の負担の減らし方で。「観点一つで、五分で」の形にします。

面接官の枠は、職種ごとに先に押さえます。「候補者が来たら調整」では、四職種分の調整が同時に発生し、回りません。

## 月次で見る一枚

複数職種の進み具合を、一枚で見ます。

| 職種 | 応募 | 書類通過 | 面接 | 内定 | 辞退 | 応募から内定までの日数 | 止まっている段階 | 来月の打ち手 |
|---|---|---|---|---|---|---|---|---|
| 営業 | | | | | | | | |
| エンジニア | | | | | | | | |
| 事務 | | | | | | | | |

一枚で、「どの職種が、どこで止まっているか」が見えます。営業は応募が少ない、エンジニアは面接に進まない、事務は応募は多いが要件に合わない、のように、職種ごとに詰まりが違います。

詰まりが違えば、打ち手も違います。営業は経路、エンジニアは要件、事務は求人票の絞り込み。全部に同じ打ち手をしません。詰まりの読み方は[採用ファネルのどこが詰まっているか分からない](/media/rpo-funnel/)に書いています。

一枚を、月に一度、責任者と現場の責任者で見ます。「来月の打ち手」を職種ごとに一つ決めます。

## 外注する場合の範囲

複数職種の同時採用を、採用代行に出す場合の範囲です。

**出せる工程。** 職種ごとに違う工程と共通の工程の整理、共通の工程の運用（受付、返信、日程、連絡、記録、集計）を全職種分、職種ごとの求人票（型は共通、中身は職種ごと）、職種ごとの経路の設計と運用、職種ごとの観点の一枚、面接官の枠の調整（職種ごとに先に押さえる）、候補者の表の一本化と職種の列、週に一度の職種ごとの確認、月次の一枚、並行の数の目安の提示と優先順位の案。

**社内に残す判断。** 職種ごとの要件と条件、面接官の指名と枠の決定、書類の判断と面接と判定（職種の現場）、並行の数の決定、優先順位の決定、来月の打ち手の決定。

**外注の効きどころ。** 複数職種の採用は、「共通の工程の量」が回らない原因です。担当者が共通の工程を全職種分引き受ければ、社内は職種ごとの工程だけになり、並行の数を増やせます。担当者は複数の会社で複数職種を回しているので、「この職種はこの経路」「型は共通で中身は職種ごと」の設計を持ち込めます。

**外注しても動かない場合。** 現場が職種ごとの判断と面接を担わない、面接官の枠が取れない、責任者が並行の数を減らす判断をしない。社内の判断で、代行を替えても直りません。

複数職種は、分けるものとまとめるものを整理すれば、同時に回ります。外注は、共通の工程を引き受ける人を置く手段です。

### エラベルの見解

担当する側から見ると、複数職種の相談で最も多いのは、「応募の多い職種に時間を取られて、応募の少ない重要な職種が放置されている」ことです。事務の応募が五十件、エンジニアの応募が三件。人事は事務の五十件の対応に追われ、エンジニアの三件への返信が一週間後になり、三件とも他社に決まる。

応募の多い職種は、書類の判断の基準を厳しくして絞るか、共通の工程を担当者に出して人事の手を空けるか。応募の少ない重要な職種は、来た応募を当日に返す。「応募の数」と「重要さ」は別で、時間の配分は重要さで決めます。

発注側にできるのは、応募の多い職種の共通の工程を担当者に出し、社内の時間を重要な職種に回すことです。

## まとめ

- 同時に採れないのは**一人が全職種の全工程・違いを同じ形で・共通を別々に・面接官の日程が組めない・優先順位が無い・進み具合が見えない・応募の多い職種に取られる**構造
- 職種ごとに違うのは**役割と要件・求人票の中身・経路・面接官・観点・判断の基準・条件**。共通は**受付と返信・表・日程・案内と結果の文面・記録の型・集計・報告**。中身は職種ごと、型と窓口は共通
- 設計は**共通を一人が・職種ごとを現場が・枠を職種ごとに先に・一枚ずつ用意・経路は分けて運用は共通・表を一つに職種の列・週に一度・月に一度**
- 並行の数は**兼務で一〜二・専任で二〜三・代行と組んで三〜五・二人以上で四以上**が目安。超えたら優先順位で減らす。面接官の枠でも決まる
- 職種ごとに**現場の担当・面接官の枠・経路・観点の一枚**を表に
- 月次の一枚で**職種ごとの応募・通過・面接・内定・辞退・日数・止まっている段階・来月の打ち手**。詰まりは職種で違う
- 外注できるのは**整理・共通の工程の全職種分・求人票・経路・観点・枠の調整・表・確認・一枚・目安と優先順位**。社内に残るのは**要件と条件・面接官・判断と面接と判定・並行の数・優先順位・打ち手**

## よくある質問

### 人事が一人で、四職種を同時に採るのは無理ですか

全工程を一人で回すなら、無理です。共通の工程（受付、返信、日程、連絡、記録）を一つの窓口と型にまとめ、職種ごとの工程（判断、面接、判定）を職種の現場に渡し、面接官の枠を職種ごとに先に押さえれば、人事一人で三職種ほどは回ります。共通の工程を採用代行の担当者に出せば、さらに増やせます。それでも回らないなら、並行の数を優先順位で減らし、順に採ります。

### 現場が「自分の職種を後回しにしないでほしい」と言います

全部を同時に薄く回して全部が採れないより、絞って順に採るほうが、結果として全部が早く採れます。優先順位を「採れないと最も困る順」で責任者が決め、現場には「〇月から動かす」と時期を伝えます。後回しになる職種も、求人票と観点の一枚は先に用意しておき、動かす時期が来たらすぐ出せる形にします。並行の数を増やしたいなら、共通の工程を担当者に出すか、現場が職種ごとの工程を担うかです。

### 応募が多い職種に時間を取られて、他の職種が回りません

応募の数と重要さは別です。応募の多い職種は、書類の判断の基準を厳しくして絞る（必須の要件を観察できる言葉で）か、共通の工程を担当者に出して社内の手を空けます。応募の少ない重要な職種は、来た応募を当日に返します。時間の配分は、応募の数ではなく、「採れないと最も困る順」で決めます。月次の一枚で職種ごとの詰まりを見て、打ち手を職種ごとに一つ決めます。

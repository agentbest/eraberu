依頼側から「採用のKPIを作ってほしい」と頼まれた。本業では会社の型があり、自分で設計したことは無い。何を指標にし、どんな数字を目標にすればよいのか。結論を先に書くと、**採用のKPIの設計は、「採用の工程を分ける」「各工程の出口を数える」「依頼側の記録で測れる指標だけを置く」「自分の範囲と依頼側の範囲を分ける」の四つで進めます。数字の目標を最初から置くのではなく、まず数か月測り、実績が見えてから目標の水準を置きます。**測れない指標、目標だけが先にある指標、誰の範囲か分からない指標は、形だけのKPIになり、使われません。副業の担当者が設計するKPIは、依頼側の担当者が毎月見て、社内で説明でき、外部の担当者の範囲の出口が分かる形にします。成果の定義の考え方は[成果をどう定義しておくか](/media/fukugyo-seika-teigi/)に、成果の見せ方は[成果が数字に出ない業務の見せ方](/media/fukugyo-seika-mienai/)に、改善を回す形は[改善を回す](/media/fukugyo-kaizen/)にまとめています。

## KPI設計が求められる場面

副業の担当者にKPIの設計が求められるのは、依頼側に型が無いか、型が使われていないときです。

| 場面 | 依頼側の状態 | 求められること |
|---|---|---|
| 人事の専任がいない | 採用の進捗を「何となく」で見ている。数字が無い | 何を数えればよいかを、一から決める |
| 数字はあるが、見ていない | ATSに記録はあるが、誰も集計せず、月ごとの変化を見ていない | 記録から指標を取り出し、見る形にする |
| 目標だけがある | 「今期〇名採用」という目標はあるが、途中の工程の指標が無く、遅れに気づけない | 工程ごとの指標を置き、途中で分かる形にする |
| 外部の担当者の成果を見たい | 依頼側が、自分（外部の担当者）の成果を何で見ればよいか分からない | 自分の範囲の出口を指標にする |
| 上長への報告の材料が要る | 担当者が上長に採用の状況を説明するのに、数字が無い | 上長が見て分かる指標に絞る |
| 採用を改善したい | 何を直せばよいか分からない | 工程ごとの指標で、弱い場所を見つける |

場面の要点は、「上長への報告の材料が要る」ことが、依頼側の担当者にとって最も切実だということです。担当者は、上長に「採用はどうか」と聞かれ、数字で答えたいのに答えられません。KPIは、採用を良くする道具である前に、担当者が社内で説明する道具です。担当者が使える形にすることが、設計の第一の条件です。依頼側の型の有無は[どんな会社から依頼が来るのか](/media/fukugyo-qa-11/)に書いています。

## 工程で分けて出口を数える

採用のKPIは、採用を工程に分け、各工程の出口を数えるところから始めます。

| 工程 | 出口（数えるもの） | 記録の場所 |
|---|---|---|
| 母集団の形成 | スカウトの送信数、応募数、媒体ごとの応募数 | 媒体の管理画面、ATS |
| スカウトの反応 | 送信に対する返信の数と割合 | 媒体の管理画面 |
| 書類の選考 | 応募に対する通過の数と割合 | ATS |
| 日程の調整 | 通過から面接の確定までの日数、日程の理由での辞退の数 | ATS、自分の記録 |
| 一次面接 | 面接の実施数、通過の数と割合 | ATS、面接の記録 |
| 二次以降 | 同じ | 同じ |
| 内定 | 内定の数、承諾の数と割合、承諾までの日数 | ATS |
| 入社 | 入社の数、入社後の定着 | 依頼側の人事の記録 |

工程の要点は、「各工程の出口を数えると、どこで止まっているかが見える」ことです。「今期〇名採用」だけでは、遅れているときに、母集団が足りないのか、面接で落ちているのか、内定を辞退されているのかが分かりません。工程ごとの出口があれば、弱い場所が一目で分かり、そこに手を打てます。工程の分け方は、依頼側の実際の選考の流れに合わせ、依頼側に無い工程は置きません。現状の把握は[現状把握のしかた](/media/fukugyo-genjou-haaku/)に整理しています。

### エラベルの見解

相談で最も多い思い込みは、「KPIは、目標の数字を決めることだ」というものです。実際には、目標の数字を先に決めたKPIは、ほとんど使われていません。「返信率〇割」「面接設定〇件」と最初に置いても、依頼側の実績が分からない状態で置いた数字は根拠が無く、達しても達しなくても、誰も動きません。使われているKPIは、まず数か月、工程ごとの出口を測り、実績の平均が見えてから、「ここから上げる」と目標を置いたものです。

見ていて差がつくのは、KPIを「依頼側の記録で毎月測れるか」で選んでいるかです。「候補者の満足度」「文面の質」のように、測れない指標を置くと、毎月の数字が出ず、KPIは形だけになります。「送信に対する返信の割合」「日程の確定までの日数」のように、ATSと媒体の管理画面から毎月出せる指標だけを置けば、担当者は毎月見られ、上長に出せます。エラベルでは、担当者が依頼側のKPIを設計するとき、測れる指標だけを、自分の範囲と依頼側の範囲に分けて置く形をお願いしています。KPIは、置くものではなく、毎月見るものです。

## 測れる指標だけを置く理由

指標の候補は多くありますが、置くのは「依頼側の記録で毎月測れるもの」だけです。

| 指標の候補 | 測れるか | 扱い |
|---|---|---|
| 送信に対する返信の割合 | 測れる。媒体の管理画面 | 置く |
| 日程の提示から確定までの日数 | 測れる。ATSか自分の記録 | 置く |
| 日程の理由での辞退の数 | 測れる。辞退の理由を記録していれば | 置く。記録していなければ、記録を始めてから |
| 面接の通過の割合 | 測れる。ATS | 置く |
| 内定の承諾の割合 | 測れる。ATS | 置く |
| 候補者の満足度 | 測れない。アンケートを取れば測れるが、副業の範囲では難しい | 置かない |
| 文面の質 | 測れない | 置かない。返信の割合で代替 |
| 面接官の評価の質 | 測れない | 置かない。通過の割合と、内定後の辞退で間接的に |
| 採用のコスト | 測れるが、依頼側の経理の情報 | 依頼側の範囲。自分は置かない |
| 入社後の定着 | 測れるが、時間がかかり、副業の範囲の外 | 依頼側の範囲 |

理由の要点は、「測れない指標を置くと、KPI全体が使われなくなる」ことです。一つでも毎月の数字が出ない指標があると、担当者は「今月は数字が揃わない」と感じ、KPIを見なくなります。測れるものだけを置き、測れないものは置かない。測りたいが記録が無いものは、記録を始めることを先にし、記録が数か月溜まってから指標にします。記録の整え方は[議事録の残し方](/media/fukugyo-gijiroku/)と[稼働ログの付け方](/media/fukugyo-log/)に書いています。

## 自分の範囲と依頼側の範囲を分ける

KPIを設計するとき、各指標が誰の範囲かを明示します。これが無いと、依頼側の範囲の停滞が自分の評価になります。

| 指標 | 誰の範囲 | 理由 |
|---|---|---|
| 送信数、返信の割合 | 自分（スカウトを担当している場合） | 自分の稼働と判断で動かせる |
| 日程の確定までの日数 | 自分と依頼側 | 提示は自分、面接官の予定は依頼側 |
| 日程の理由での辞退 | 自分と依頼側 | 同上 |
| 書類の通過の割合 | 依頼側 | 選考の判断は依頼側 |
| 面接の通過の割合 | 依頼側 | 面接官の判断 |
| 内定の承諾の割合 | 依頼側 | 条件と候補者の判断 |
| 入社、定着 | 依頼側 | 入社後は依頼側 |

分ける要点は、「依頼側の範囲の指標も置くが、自分の評価には使わない」ことです。面接の通過や内定の承諾は、採用の全体を見るために置きますが、それは依頼側の範囲で、自分の成果ではありません。「自分の範囲の指標は動いている。依頼側の範囲の指標で止まっている」が、一枚で分かる形にすれば、成果の話が正確になります。成果の定義は[成果をどう定義しておくか](/media/fukugyo-seika-teigi/)に、依頼側の範囲で止まっているときの示し方は[成果が見えない](/media/fukugyo-shippai-4/)に整理しています。

## 目標の水準を後で置く理由

指標を置いても、目標の数字は最初から置きません。数か月測ってから置きます。

| 最初から目標を置くと | 数か月測ってから置くと |
|---|---|
| 根拠が無い。依頼側の実績を知らずに置いた数字 | 実績の平均が起点になり、根拠がある |
| 達しても「たまたま」、達しなくても「目標が高すぎた」で、誰も動かない | 「実績からここまで上げる」で、動く理由がある |
| 依頼側の担当者が上長に「なぜこの数字か」を説明できない | 「先月までの実績がこれで、今期はここを目指す」と説明できる |
| 自分の評価が、根拠の無い数字で決まる | 実績を踏まえた水準で決まる |
| 目標が業界の目安から来ていることが多く、依頼側の状況と合わない | 依頼側の状況から来ている |

後で置く要点は、「最初の数か月は測るだけ」と、依頼側と合意しておくことです。「まず三か月、工程ごとの数字を測ります。その実績を見て、四か月目から目標を置きます」と最初に伝えれば、依頼側は「目標が無い」とは感じず、「測っている段階」と理解します。測る段階で、すでに弱い場所は見え、改善は始められます。改善の回し方は[改善を回す](/media/fukugyo-kaizen/)に書いています。

## KPIが形だけになる失敗

設計しても、使われなくなるKPIには共通点があります。

| 失敗 | 何が起きるか | 防ぎ方 |
|---|---|---|
| 指標が多すぎる | 毎月集計するのに時間がかかり、見なくなる | 工程ごとに一つか二つ。全体で十以内 |
| 測れない指標が混ざる | 数字が揃わない月が出て、見なくなる | 測れるものだけ |
| 誰の範囲か分からない | 止まったときに、誰が動けばよいか分からない | 指標ごとに範囲を書く |
| 目標が先にある | 根拠が無く、達しても達しなくても動かない | 数か月測ってから |
| 見る場が無い | 集計しても、誰も見る場が無い | 月次の定例と稼働報告で見る。[報告の頻度をどう決めるか](/media/fukugyo-report-hindo/) |
| 数字を見て、何もしない | 見るだけで、弱い場所に手を打たない | 見た月に一つ変える。改善と一体にする |
| 集計が担当者の負担になる | 依頼側の担当者が集計を抱え、続かない | 自分の範囲の指標は自分が集計し、報告に載せる |

失敗の要点は、「見る場と、見た後の動きを決めておく」ことです。KPIは、集計して終わりではなく、月に一度見て、弱い場所に一つ手を打つところまでが一連です。見る場（定例と稼働報告）と、見た後の動き（一つ変える）を、設計の時点で決めておけば、形だけになりません。

## 依頼側と一枚で合意する形

設計したKPIは、一枚にして依頼側と合意します。一枚の形です。

| 項目 | 内容 |
|---|---|
| 工程 | 依頼側の選考の流れに沿った工程の一覧 |
| 指標 | 工程ごとの出口の指標。測れるものだけ |
| 記録の場所 | 各指標を、どの記録（媒体の管理画面、ATS、自分の記録）から取るか |
| 範囲 | 各指標が、自分の範囲か、依頼側の範囲か、両方か |
| 集計する人と時期 | 誰が、毎月いつ集計するか |
| 見る場 | 月次の定例と稼働報告 |
| 目標 | 最初の数か月は空欄。「〇か月目に実績を見て置く」と書く |
| 見た後の動き | 弱い場所に、月に一つ手を打つ |

一枚の要点は、「記録の場所」と「集計する人」を書くことです。指標を決めても、どこから数字を取り、誰が集計するかが決まっていないと、翌月に数字が出ません。自分の範囲の指標は自分が集計し、依頼側の範囲の指標は依頼側の担当者が集計するか、自分がATSから取れるなら取る、と最初に決めます。一枚の共有の仕方は[プロジェクトとして進める](/media/fukugyo-project/)の五つの要素と同じで、議事録に添えます。

### エラベルの見解

担当する側から見ると、KPIの設計を任されて、それが依頼側で使われ続けている人は、指標を少なく、測れるものだけに絞り、範囲を分け、目標を後で置いています。依頼側の担当者は、毎月の定例で一枚を見て、弱い場所を見つけ、上長に「ここが弱いので、ここに手を打っている」と説明しています。使われなくなったKPIは、指標が多く、測れないものが混ざり、目標が先にあり、見る場が無いものです。

順番として、依頼側の選考の流れを工程に分け、各工程の出口で測れる指標を一つか二つ置き、記録の場所と集計する人を決め、自分の範囲と依頼側の範囲を分け、目標は数か月測ってから置くと合意し、月次の定例と稼働報告で見て、見た月に一つ変える。この順番で、KPIは設計して終わりではなく、依頼側の採用を動かす道具になります。エラベルでは、担当者が依頼側のKPIを設計するとき、測れる指標だけを範囲で分けて置き、目標は実績を見てから置く形をお願いしています。KPIの設計は、数字を決める仕事ではなく、依頼側が毎月見て動ける形を作る仕事です。

## まとめ

- KPIの設計は**工程を分ける→各工程の出口を数える→測れる指標だけを置く→自分の範囲と依頼側の範囲を分ける**の四つ
- 依頼側の担当者にとって、KPIは**上長に説明する道具**。担当者が使える形が第一の条件
- **測れない指標を一つでも置くと、KPI全体が見られなくなる**。測りたいが記録が無いものは、記録から始める
- 依頼側の範囲の指標も置くが、**自分の評価には使わない**。止まっている場所が一枚で分かる形に
- **目標は数か月測ってから置く**。最初の数か月は測るだけと合意する
- 形だけになる失敗は**多すぎる・測れない・範囲が不明・目標が先・見る場が無い・見て何もしない・集計が負担**
- 一枚には**工程・指標・記録の場所・範囲・集計する人と時期・見る場・目標（後で）・見た後の動き**を書く

## よくある質問

### 依頼側が「業界の平均と比べたい」と言います

業界の平均は、出典が明確な公開情報があれば参考として示せますが、依頼側の状況（規模、職種、地域、媒体）と前提が違うことが多く、そのまま目標にはできません。「公開されている数字はこれですが、前提が違うので、まず御社の実績を数か月測り、御社の起点から上げる形にしましょう」と、依頼側の実績を起点にする形を提案します。出典が確認できない平均は出しません。他社の数字の扱いは[他社事例をどう扱うか](/media/fukugyo-benchmark/)に整理しています。

### 依頼側のATSに、工程ごとの記録が無く、数字が取れません

取れない工程は、まず記録を始めます。ATSの状態の項目を工程に合わせて整えるか、自分の記録の表に、候補者ごとの工程の日付を残す形を作ります。数か月記録すれば、工程ごとの数字が出ます。記録を整えること自体が、KPI設計の最初の工程で、依頼側には「記録が無いので、まず記録から整えます」と伝えます。記録の整備は[記録の整備](/media/fukugyo-gijiroku/)と[稼働ログの付け方](/media/fukugyo-log/)に書いています。

### 自分の範囲がスカウトの運用だけなのに、採用全体のKPIの設計を頼まれました

設計そのものは、自分の範囲を超えて採用全体を見る作業なので、範囲として受けるかを先に決めます。受けるなら、「設計は全体を、集計と改善は自分の範囲を」と分け、依頼側の範囲の指標は依頼側が集計し動く形にします。全体の設計を無償で引き受け、集計も改善も自分が抱えると、範囲が膨らみます。設計を範囲に入れるなら、稼働と条件を見直します。範囲の扱いは[範囲の膨張](/media/fukugyo-shippai-2/)に、条件の見直しは[更新時の条件見直し](/media/fukugyo-keiyaku-koushin-koushou/)に整理しています。

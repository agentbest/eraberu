スカウトを送った記録は、媒体の画面に残っている。代行の担当者の手元にも何かあるらしい。ただ、自社で「この人に、いつ、何を送ったか」を引こうとすると、引けない。半年前の候補者に再送してよいか分からず、文面を変えた効果も比べられず、代行を切り替えるときに記録ごと消える。結論を先に書くと、**送信ログは、「媒体に残っているから」で済ませず、一通ごとに「誰に・いつ・何を（文面の型）・誰が・どうなったか」を、自社が持つ一つの表に残します。媒体の画面は媒体を解約すれば見られなくなり、代行の手元の記録は契約が終われば戻ってきません。ログは、自社の資産として自社の場所に置きます**。ログを何の単位で見るかは[どの単位で効果を検証するか](/media/scout-kensho-tan-i/)に、代行から引き渡してもらうデータは[送信データの引き渡し](/media/scout-daikou-data/)にまとめています。

## ログが残らない構造

送信ログが自社に残らないのは、次の構造で起きます。

| 構造 | 起きていること |
|---|---|
| 媒体に残っていると思っている | 媒体の画面で見られるのは、その媒体の、契約中の、限られた項目だけ。複数の媒体をまたいで引けない |
| 代行の手元にある | 担当者が自分の表で管理し、自社には月次の集計だけが来る。一通ごとの記録は無い |
| 何を送ったかが残っていない | 送信日と相手は残るが、どの文面の型か、どの材料を出したかが無い |
| どうなったかが残っていない | 送信の記録と、返信・面談・応募の記録が別の場所にあり、つながらない |
| 表が複数ある | 媒体ごと、担当者ごと、月ごとに別の表。同じ人に別の媒体から送ったことに気づかない |
| 更新の担当が無い | 「誰かが書く」で、誰も書かない。送信のたびに書く決まりが無い |
| 契約が終わると消える | 代行の切り替え時に、記録の引き渡しを取り決めておらず、ゼロから始まる |

構造の大半は、「ログを自社の資産として設計していない」ことです。設計すれば、残ります。

## ログの目的

何のために残すかで、残す列が決まります。目的は四つです。

| 目的 | 必要な情報 |
|---|---|
| 再送の判断 | 誰に、いつ、何回、どの役割で送ったか。返信の有無と内容。「連絡不要」の意思の表明 |
| 効果の検証 | どの文面の型か、どの層か、どの媒体か、誰が送ったか。開封・返信・面談・応募の結果 |
| 候補者への対応 | いま、どの段階で、誰が対応していて、次に何をするか。止まっている人の把握 |
| 代行の切り替えと引き継ぎ | 上の全部。次の担当者が、過去の送信を前提に動けること |

四つの目的のうち、「再送の判断」と「候補者への対応」は、ログが無いと毎日の運用で事故が起きます。同じ人に二重に送る、「連絡不要」と言われた人に送る、返信が来た人を放置する。「効果の検証」と「引き継ぎ」は、ログが無いと積み上がりません。再送の判断の考え方は[同じ候補者に何回送ってよいか](/media/scout-soushin-hindo/)に書いています。

## 最低限の列

一通ごとに残す、最低限の列です。

| 列 | 内容 | 目的 |
|---|---|---|
| 候補者の識別 | 媒体上のIDや、媒体名＋表示名。自社で一意に引ける形 | 全部 |
| 媒体 | 送った媒体 | 検証、再送 |
| 役割 | 募集の役割 | 全部 |
| 候補者の層 | 自社で決めた区分（経験の深さ、現職の業種など） | 検証 |
| 送信日 | 日付。曜日と時間帯は別の列でも | 全部 |
| 何通目か | 一通目、二通目、時間を空けた再送 | 再送、検証 |
| 文面の型 | 件名の型の名前、本文の型の名前 | 検証 |
| 送り主 | 送った人の名前 | 検証、引き継ぎ |
| 開封 | 有無（媒体で見られる場合） | 検証 |
| 返信 | 有無、日付、内容の区分（前向き・質問・断り・連絡不要） | 全部 |
| 面談 | 日付、担当者 | 対応、検証 |
| その後 | 応募、選考、内定、入社、辞退。日付 | 検証 |
| 現在の段階と次の対応 | どこで止まっていて、誰が、いつ、何をするか | 対応 |
| 備考 | 相手が言った時期、条件の希望など | 再送、対応 |

列の要点は、「候補者の識別が一意」であることと、「文面の型に名前がある」ことです。識別が一意でないと、媒体をまたいだ二重送信に気づけません。型に名前が無いと、効果を比べられません。

## 文面の残し方

ログの表に、文面の全文は入れません。表が読めなくなります。型に名前を付けて、文面は別に保管します。

| 項目 | 内容 |
|---|---|
| 型の名前 | 件名の型と本文の型に、「件名A-1」「本文B-3」のように名前を付ける |
| 型の一覧 | 型の名前、実際の文面、作った日、使い始めた日、使い終えた日、対象の役割と層。一つの文書に |
| 個別の部分 | 一段落目など、候補者ごとに変えた部分は、ログの備考か、媒体の送信履歴で見る。全文を残すなら媒体の履歴を使う |
| 版の管理 | 型を直したら、新しい名前を付ける。「本文B-3」を直して「本文B-4」に。上書きしない |
| 保管の場所 | 自社が持つ場所。代行の手元だけに置かない |

残し方の要点は、「型を上書きしない」ことです。上書きすると、過去のログの「本文B-3」が、どの文面を指すか分からなくなります。直したら、新しい名前です。文面の型の考え方は[文面の標準化と属人化の間](/media/scout-hyoujun-ka/)に書いています。

## 更新の担当と頻度

ログは、書く決まりが無いと残りません。

| 項目 | 決めること |
|---|---|
| 送信の記録 | 送った人が、送った日に書く。「週末にまとめて」は漏れる |
| 返信の記録 | 返信を受けた人が、受けた日に。内容の区分も |
| 面談以降の記録 | 面談の担当者、または人事が、起きた日に。代行が面談に同席しないなら、社内の担当を決める |
| 現在の段階の更新 | 週に一度、担当者が全員分を見直し、止まっている人を拾う |
| 型の一覧の更新 | 型を作った・直した人が、その日に |
| 表の確認 | 月に一度、発注側が表を開いて、漏れと二重を見る |

担当の要点は、「面談以降の記録は社内からしか出ない」ことです。代行は送信と返信までは書けますが、面談の結果、選考の結果、辞退の理由は、社内で起きます。ここの担当を決めないと、ログは返信で止まり、効果の検証も引き継ぎもできません。応募者管理の表の回し方は[応募者管理がスプレッドシートのまま](/media/rpo-ats-nai/)にも書いています。

### エラベルの見解

相談で最も多い失敗は、「代行を切り替えたら、二年分の送信の記録が前の代行の手元にあって戻らず、新しい担当者が過去に送った人に一通目から送り直し、『前にも来た』と何人かから返信が来た」というものです。ログが自社に無く、引き渡しの取り決めも無かった。表を自社の場所に作り、代行には「送信のたびに自社の表に書く」を契約の条件にし、面談以降は社内の人事が書く担当を決めたら、次の切り替えでは新しい担当者が初日から過去の送信を前提に動けました。ログは、代行のものではなく、自社のものです。

見ていて差がつくのは、担当者が「自社の表に書く」ことを嫌がらないかです。自分の表で管理したい担当者と、「発注側の表に書きます。私が替わっても残るように」と言う担当者がいます。後者は、引き継ぎで困りません。

発注側にできるのは、契約の前に、「送信の記録は、当社の表に、送信のたびに書いてください」を条件として伝えることです。

## 個人情報の扱い

送信ログは、候補者の個人情報を含みます。残し方と同時に、扱い方を決めます。

| 項目 | 内容 |
|---|---|
| 何を残すか | 目的に必要な項目だけ。履歴書の全文や連絡先を、必要が無いのに表に入れない |
| 誰が見られるか | 採用に関わる人だけ。閲覧の権限を分ける |
| どこに置くか | 自社の管理下。個人の端末や、代行の私用の場所に置かない |
| いつまで残すか | 保管の期間を決める。「連絡不要」の意思の表明は、再送を防ぐために、期間内は残す |
| 媒体の規約 | 媒体上の候補者の情報を、媒体の外に持ち出してよい範囲は、媒体ごとの規約で決まる。公式の案内で確認 |
| 代行との取り決め | 代行が持つ記録の扱い、契約終了時の引き渡しと削除 |
| 法令 | 個人情報の扱いは法令に沿う。個別の判断は専門家に確認 |

扱いの要点は、「媒体の規約」です。媒体によっては、候補者の情報を媒体の外に保存することに制限があります。ログの列を決める前に、媒体ごとの規約を公式の案内で確認し、必要なら専門家に確認します。契約終了時の削除は[候補者データの削除](/media/scout-daikou-kadai-data-kesu/)に書いています。

## 代行との取り決め

ログについて、代行と決めておくことです。

| 項目 | 取り決め |
|---|---|
| 表の所在 | 自社の表に書く。代行の表は補助 |
| 書くタイミング | 送信の当日。返信の当日 |
| 書く項目 | 上の最低限の列。特に文面の型の名前と送り主 |
| 型の一覧 | 型を作った・直したら、自社の型の一覧に追加する。上書きしない |
| 面談以降 | 社内が書く。代行が同席する場合は代行が書いてもよいが、担当を決める |
| 月次の確認 | 発注側が表を開き、漏れと二重を見る。漏れが続けば改善を求める |
| 契約終了時 | 代行の手元にある記録を引き渡し、代行側では削除する。引き渡しの形式と削除の確認の方法 |

取り決めの要点は、「表の所在」を契約の前に決めることです。始まってから「自社の表に書いてほしい」と言うと、担当者の運用を変えることになり、抵抗が出ます。最初から自社の表なら、それが当たり前になります。代行に求めるデータの全体は[送信データの引き渡し](/media/scout-daikou-data/)に書いています。

## 外注する場合の範囲

送信ログの整備を、スカウト代行に出す場合の範囲です。

**出せる工程。** ログの表の設計（列の提案）、既存の媒体の履歴と代行の手元の記録からの移し替え、送信と返信の記録の当日の記入、文面の型の名前付けと型の一覧の維持、週次の段階の見直しと止まっている人の抽出、二重送信と「連絡不要」の相手のチェック、月次の集計、契約終了時の引き渡しの準備。

**社内に残す判断。** 表の所在（自社の管理下）、閲覧の権限、保管の期間、媒体の規約と法令の確認（専門家との連携）、面談以降の記録の担当と実施、月次の表の確認。

**外注の効きどころ。** ログは、「送信のたびに、決めた列で、一つの表に書く」運用で、社内では「媒体に残っているから」で済ませて残らない工程です。担当者が表の型を持ち込み、当日に書き、型の一覧を維持し、週次で止まっている人を拾えば、再送の事故が減り、検証が積み上がり、切り替えでも消えません。担当者は複数の会社のログを見ているので、「この列が無いと後で困る」を最初から入れられます。ただし、表の所在と面談以降の記録は、社内からしか出ません。

**外注しても動かない場合。** 表を自社の管理下に置かない、面談以降を社内が書かない、媒体の規約を確認せずに何でも残すことを求める、契約終了時の引き渡しを取り決めない。社内の判断で、代行を替えても直りません。

送信ログは、一通ごとに「誰に・いつ・何を・誰が・どうなったか」を自社の一つの表に残せば、再送の事故が減り、検証が積み上がり、代行を替えても消えません。外注は、表の型と当日の記入と型の一覧を担う手段です。

### エラベルの見解

担当する側から見ると、ログの相談で最も多いのは、「送信の記録はあるが、『どうなったか』が無い」ことです。送信日と相手と返信の有無までは、代行が書いている。面談に至ったか、応募したか、内定が出たか、辞退したかは、社内で起きるので、誰も表に書かない。結果、「返信率は分かるが、どの文面から入社した人が出たか」が分からず、検証は返信率で止まります。

面談以降の列を、人事が起きた日に書く。それだけで、ログは「送信の記録」から「採用の記録」になります。書く量は、月に数行です。

発注側にできるのは、面談以降の記録を書く人を、名前で決めることです。「人事が書く」ではなく、「〇〇さんが、面談の当日に書く」まで決めます。

## まとめ

- 残らないのは**媒体に残っていると思う・代行の手元・何を送ったかが無い・どうなったかが無い・表が複数・担当が無い・契約が終わると消える**構造
- 目的は**再送の判断・効果の検証・候補者への対応・切り替えと引き継ぎ**の四つ。前の二つは無いと毎日の事故、後の二つは無いと積み上がらない
- 列は**識別・媒体・役割・層・送信日・何通目・文面の型・送り主・開封・返信・面談・その後・現在の段階・備考**。識別は一意、型に名前
- 文面は**型に名前を付けて別に保管し、上書きせず新しい名前**。個別の部分は備考か媒体の履歴
- 更新は**送った人が当日・返信を受けた人が当日・面談以降は社内・週次の見直し・月次の確認**。面談以降の担当を名前で決める
- 個人情報は**必要な項目だけ・閲覧の権限・自社の管理下・保管の期間・媒体の規約・代行との取り決め・法令は専門家に**
- 代行とは**表の所在・タイミング・項目・型の一覧・面談以降・月次の確認・契約終了時**を契約の前に決める
- 外注できるのは**表の設計・移し替え・当日の記入・型の一覧・週次の見直し・チェック・集計・引き渡しの準備**。社内に残るのは**所在・権限・期間・規約と法令・面談以降の記録・月次の確認**

## よくある質問

### 媒体の管理画面で送信履歴が見られるので、それで足りませんか

その媒体の、契約中の、その画面で見られる項目だけです。複数の媒体をまたいで同じ人に送ったかは引けず、文面の型や送り主の情報も無く、面談以降の結果もつながりません。媒体を解約すれば見られなくなります。媒体の画面は「個別の文面の全文を見る場所」として使い、一通ごとの記録は自社の表に持ちます。媒体の履歴の保存期間や書き出しの可否は、公式の案内で確認してください。

### 過去の分を、今から表に移すべきですか

「連絡不要」の意思の表明と、直近の送信の相手だけは、先に移します。再送の事故を防ぐためです。それ以外の過去の分は、効果の検証には使いにくい（文面の型の名前が無い）ので、無理に全部を移さず、今日から新しい表で始めます。過去の分は、媒体の履歴と代行の手元の記録を、引き渡しの形で受け取っておき、必要なときに引けるようにします。

### 代行が「自社の表に書くのは工数が増える」と言います

送信のたびに一行書く工数は、送信の工数に比べて小さいものです。それでも増えると言われたら、「代行の表を、自社の管理下の場所に置き、自社が閲覧と書き出しをできる形にする」を提案します。表が代行のものでも、置き場所と権限が自社にあれば、消えません。それも断られる場合、契約終了時の引き渡しの取り決めだけは、書面で残します。担当者に求める範囲の考え方は[改善提案をどこまで求めるか](/media/scout-daikou-kaizen/)に書いています。

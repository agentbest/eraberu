社内SEの採用で相談が多いのは、「応募は来るが、欲しい人が来ない」「入っても一年以内に辞める」「一人目の社内SEを採りたいが、何を要件にすればよいか分からない」の三つです。社内SEは、エンジニアの中では応募者の多い職種です。SIerやSESで客先常駐や長い残業に疲れた人が「社内SEなら落ち着ける」と考えて応募するからです。ただ、「社内SE」の名前で募集される中身は、ヘルプデスクと機器の管理、基幹システムの保守とベンダー管理、社内の開発、DX推進の四つに分かれ、会社ごとに割合が違います。中身と割合を書かずに募集すると、開発をしたい人がヘルプデスクの会社に来て、ヘルプデスクをしたい人が開発の会社に来て、どちらも「聞いていたのと違う」と辞めます。結論を先に書くと、**代行に出す判断基準は、中身と割合が決まっているか、一人目か二人目以降か、経営者が社内SEに何を期待しているか、応募の多さを捌けるか、の四つ**です。四つのうち決まっているものが多ければ、代行は「中身を文面に落とし、応募を絞り、面接の段取りを回す」役として効き、決まっていなければ、代行の最初の仕事は募集ではなく整理です。エンジニア採用の全体は[エンジニア採用を代行に出す判断基準](/media/rpo-engineer-rpo/)に、インフラエンジニアは[インフラエンジニア採用を代行に出す判断基準](/media/rpo-infra-engineer-rpo/)に書いていますので、違いは後半で触れます。

## 社内SE採用で起きていること

社内SEは、他のエンジニア職と違う事情が三つあります。

一つ目は、応募者の動機が「離れたい」であることです。SIerやSESで客先常駐、長い残業、案件ごとに変わる環境に疲れた人が、「社内SEなら自社で落ち着いて働ける」と考えて応募します。動機が「離れたい」なので、応募先の中身を細かく見ずに応募し、入ってから中身を知ります。応募が多いのに欲しい人が来ないのは、この構造です。

二つ目は、中身が会社ごとに違うことです。社員数十名の会社の一人目の社内SEは、PCの設定、アカウントの管理、ネットワークの不調、業務ソフトの問い合わせ、ベンダーとのやり取り、セキュリティの対応まで一人で持つ「ひとり情シス」です。数百名の会社の情報システム部の一人は、基幹システムの保守とベンダー管理が中心で、ヘルプデスクは別の人が持つ。事業会社の開発部門の社内SEは、社内向けのシステムを自分で作る。同じ「社内SE」で、日々の仕事はまったく違います。

三つ目は、経営者の期待と実態がずれやすいことです。経営者は「DXを進めてほしい」「業務を効率化してほしい」と期待して募集し、実態は「PCが動かない」「メールが届かない」への対応で一日が終わる。応募者は「DX推進」の文面で来て、実態を知って辞めます。逆に、ヘルプデスクを期待して募集したのに、開発をしたい人が来て「作らせてもらえない」と辞めることもあります。

三つを合わせると、「離れたい動機の応募者に、中身の違う仕事を、期待と実態のずれた文面で募集する」のが、起きていることです。

## 代行に出す判断基準

判断基準は四つです。

**一つ目：中身と割合が決まっているか。** ヘルプデスクと機器の管理、基幹システムの保守とベンダー管理、社内の開発、DX推進の四つのうち、日々の割合がどうか。「DX推進」と書いて実態がヘルプデスク八割なら、八割と書きます。割合が決まっていれば、代行は文面に落とし、応募を絞れます。決まっていなければ、代行の最初の仕事は、いまの社内SE（いなければ総務や経営者）に日々の中身を聞いて整理することです。

**二つ目：一人目か二人目以降か。** 一人目の社内SEは、上司にITの分かる人がいない、聞く相手が社外のベンダーだけ、範囲が広くて決まりが無い、という条件で働きます。この条件で続く人は、SIerで若手を指導していた人や、小さな会社で一人で情シスをしていた人で、大きな情報システム部の一員だった人は、聞く相手がいないことに戸惑います。二人目以降は、いる人との分担で中身が決まります。一人目か二人目以降かで、要件と文面が変わります。

**三つ目：経営者が社内SEに何を期待しているか。** 「PCとネットワークが止まらないこと」「基幹システムの更新を回すこと」「業務を効率化する仕組みを作ること」「セキュリティを整えること」のどれを、どの順で期待しているか。経営者の期待が言葉になっていれば、文面に書け、面接で応募者と擦り合わせられます。言葉になっていなければ、代行は経営者に聞き取るところから始めます。

**四つ目：応募の多さを捌けるか。** 社内SEは応募が多い職種で、中身に合わない応募も多く来ます。書類で中身との合致を見て絞り、合う人には速く連絡し、合わない人には丁寧に断る、という応募対応を社内で回せるか。回せないと、合う人への連絡が遅れて他社に決まります。社内で回せないなら、代行に出す最も効く工程はここです。

四つの基準の使い方は、「決まっているものが多いほど代行が効き、決まっていないものは代行の最初の仕事になる」と考えることです。

### エラベルの見解

相談で多いのは、「社内SEを募集したら応募は多いのに、面接で『思っていたのと違う』と言われて決まらない」というご相談です。求人を見ると、「DX推進担当」「社内システムの企画・開発」「業務効率化」の文面で、実態を聞くと、社員数十名の会社の一人目の社内SEで、日々はPCとアカウントとネットワークとベンダー対応が八割、残りの二割でようやく業務ソフトの改善、とのことでした。文面が「開発をしたい人」を呼び、実態が「ひとり情シス」なので、面接で決まりません。文面を実態に合わせ、「ひとり情シスとして会社のITを一から整える。開発は二割で、整えた後に増やす」と書き直したところ、応募は減りましたが、小さな会社で一人情シスをしていた人と、SIerで幅広く見ていた人が来て、決まりました。

見ていて差がつくのは、「実態を隠さずに文面にしているか」です。エラベルでは、社内SEの担当者に、募集を出す前にいまの社内SEか総務か経営者に日々の中身を聞き取り、割合を文面に落とすところから始めてもらっています。

## 中身の整理の仕方

代行に出す前でも後でも、最初にやるのは中身の整理です。

| 項目 | 決めること | 決まっていないと起きること |
|---|---|---|
| 四つの割合 | ヘルプデスクと機器の管理・基幹システムの保守とベンダー管理・社内の開発・DX推進の日々の割合 | 開発をしたい人がヘルプデスクの会社に来て辞める、またはその逆 |
| 一人目か二人目以降か | 一人目なら聞く相手がいないこと、範囲が広いこと。二人目以降なら分担 | 大きな情報システム部の出身者が一人目で戸惑う |
| 経営者の期待と順番 | 止まらないこと・更新を回すこと・仕組みを作ること・セキュリティのどれをどの順で | 「DX推進」の文面で来て実態を知って辞める |
| 使っているもの | 基幹システムの種類、クラウドか自社サーバーか、業務ソフト、ベンダーの数 | 応募者が自分の経験と合うか判断できない |
| ベンダーとの関係 | 保守をベンダーに出している範囲、社内SEが持つ範囲 | 「自分で作りたい」人と「ベンダー管理が中心」の実態がずれる |
| 決裁と予算 | 社内SEが自分で決められる範囲、ツールの導入に要る手続き | 「提案しても通らない」で辞める |
| 上司と評価 | 誰の下か（総務、経営者、開発部門）、何で評価するか | ITの分からない上司に評価されることへの不安 |

整理の要点は、「DX推進」「業務効率化」を実態より大きく書かないことです。経営者の期待としては本当でも、日々の割合がヘルプデスク八割なら、文面には八割と書き、「整えた後に増やす」と順番を書きます。実態を書くと応募は減りますが、続く人だけが来ます。

もう一つの要点は、決裁と予算を書くことです。社内SEの辞める理由で多いのは、「提案しても通らない」「ツール一つ入れるのに何か月もかかる」です。自分で決められる範囲と手続きを文面と面接で伝えると、入ってからのずれが減ります。セキュリティや個人情報に関わる決まりは、書く前に専門家にご確認ください。情報の扱いは[情報漏えいと採用代行](/media/rpo-jouhou-rouei/)にも書いています。

## 代行に出せる工程と社内に残す工程

| 工程 | 社内に残す | 代行に出せる |
|---|---|---|
| 中身と割合と経営者の期待の決定 | いまの社内SE・総務・経営者が決める | 聞き取り、整理、他社の決め方の例 |
| 一人目か二人目以降かの整理と要件 | 経営者が決める | 一人目に向く経歴の読み方、要件の案 |
| 求人票・文面 | 確認 | 割合と一人目の条件と決裁の範囲を文面に落とす |
| 経路の運用 | 予算の承認 | 媒体とスカウトの運用、反応を見て文面を直す |
| 応募対応・書類の絞り込み | ― | 中身との合致で絞る、合う人に速く連絡、合わない人に丁寧に断る |
| 面接 | 経営者と、いる場合はいまの社内SEか総務 | 段取り、質問の設計、技術の確認を外部の人に頼む段取り |
| 内定後・入社前 | 経営者からの連絡 | 入社前の連絡、辞退の防止 |
| 入社後の初期 | 上司が受け入れる | 最初の数か月の様子を聞き、文面と受け入れに戻す |

分け方の要点は、「中身と期待と面接は社内が持ち、文面と経路と応募対応と段取りは外に出せる」ことです。社内SEの面接で難しいのは、社内にITの分かる人がいない一人目の採用で、技術を確かめられないことです。代行に出す場合は、技術の確認を外部のエンジニアに頼む段取りも含めて任せられます。現場との協力の作り方は[現場の協力を得る方法](/media/rpo-genba-kyouryoku/)に書いています。

## 担当者の選び方

社内SEの採用を任せる担当者は、次の点で選びます。

一つ目は、社内SEか情報システム部門の採用か業務を経験しているかです。経験があると、「ひとり情シス」と「情報システム部の一員」と「社内開発」の違いを知っていて、経歴から向き不向きを読めます。

二つ目は、SIerやSESからの転向者の動機を読めるかです。「離れたい」動機の応募者に、中身を確かめてから進める段取りができるか。動機を否定するのではなく、「離れた先で何をしたいか」を聞いて合致を見る人を選びます。

三つ目は、経営者にITの話を通訳できるかです。一人目の社内SEの採用では、経営者がITの言葉を持たないことが多く、経営者の「DXを進めてほしい」を「まずPCとネットワークを止めない体制、次に基幹システムの更新、その後に効率化」のように翻訳して文面にする役が要ります。

四つ目は、技術の確認の段取りを持っているかです。社内にITの分かる人がいない場合に、外部のエンジニアに技術の確認を頼む段取りを持っているか。担当者の経歴の見方は[担当者の経歴の見方](/media/rpo-tantousha-keireki/)に書いています。

## インフラエンジニアとの違い

社内SEとインフラエンジニアは、機器やネットワークを扱う点で近く、混ぜて募集されることがあります。

インフラエンジニアは、サーバーやネットワークやクラウドを設計し構築し運用する専門職です。SIerやクラウドの事業者や事業会社の開発部門にいて、扱う技術の深さで評価されます。応募者は「扱う技術と規模と設計に関われるか」で選びます。

社内SEは、会社のITを止めずに回し、業務に合わせて整える役です。技術の深さより、範囲の広さと、社内の人とベンダーと経営者の間に立つ動きで評価されます。応募者は「中身の割合と、落ち着いて働けるか、決裁の範囲」で選びます。

混ぜて募集すると、インフラの専門職を求める文面に「ヘルプデスクも」と書いて専門職が離れ、社内SEを求める文面に「クラウドの設計」と書いて社内SE志望者が「自分には無理」と離れます。会社のITを整える一人目なら社内SEとして、サーバーやネットワークを設計する専門職ならインフラエンジニアとして募集します。インフラエンジニアの採用は[インフラエンジニア採用を代行に出す判断基準](/media/rpo-infra-engineer-rpo/)に書いています。

### エラベルの見解

担当する側から見ると、社内SEの採用で最も効くのは、「実態の割合を隠さないこと」と「一人目か二人目以降かを文面に書くこと」の二つです。前者で「DX推進」に来て辞める人が減り、後者で一人目に向く人（小さな会社で一人情シスをしていた人、SIerで幅広く見ていた人）が来ます。応募の数は減りますが、面接で決まる率と続く率が上がります。

エラベルでは、社内SEの案件で担当者を紹介するとき、最初の一週間でいまの社内SEか総務か経営者に日々の中身を聞き取り、割合と一人目の条件と決裁の範囲を文面に落とし、応募を絞る基準を決めるところまでをお願いしています。セキュリティと個人情報に関わる決まりは、専門家にご確認いただくようお伝えしています。

## まとめ

- 社内SE採用で起きているのは**「離れたい」動機の応募者に、中身の違う仕事を、期待と実態のずれた文面で募集している**こと
- 判断基準は**中身と割合が決まっているか・一人目か二人目以降か・経営者が何を期待しているか・応募の多さを捌けるか**の四つ。決まっていないものは代行の最初の仕事になる
- 整理は**四つの割合・一人目か二人目以降か・経営者の期待と順番・使っているもの・ベンダーとの関係・決裁と予算・上司と評価**。**「DX推進」を実態より大きく書かない**
- **中身と期待と面接は社内が持ち、文面と経路と応募対応と段取りは外に出せる**。一人目なら技術の確認を外部に頼む段取りも
- 担当者は**社内SEか情シスの経験・転向者の動機を読めるか・経営者に通訳できるか・技術確認の段取り**で選ぶ
- **インフラエンジニアとは役が違う**。混ぜて募集しない

## よくある質問

### 一人目の社内SEに、どんな人が向きますか

聞く相手が社内にいない、範囲が広い、決まりが無い、という条件で続く人です。小さな会社で一人で情シスをしていた人、SIerで幅広い範囲を見ながら若手を指導していた人、SESで客先の情シスに常駐して社内の人とベンダーの間に立っていた人が向くことが多く、大きな情報システム部で一つの領域を深く持っていた人は、聞く相手がいないことに戸惑うことがあります。経歴だけでなく、面接で「分からないことをどう解決してきたか」「決まりが無い環境で何から手を付けるか」を聞いて確かめます。

### 「DX推進」と書かないと、良い人が来ないのでは

実態がヘルプデスク八割なら、「DX推進」で来た人は入ってから辞めます。書くなら「まず会社のITを一から整え、整えた後に業務の仕組みを作る。最初の一年はPCとネットワークとベンダー対応が中心」のように、順番と割合を書きます。整える段階から入って仕組みを作りたい人は、この書き方のほうに来ます。

### 社内にITの分かる人がいないので、技術を確かめられません

一人目の社内SEの採用で最も多い悩みです。経営者が確かめられるのは「経営者の言葉を理解して翻訳できるか」「分からないことをどう解決するか」「決まりの無い環境で何から手を付けるか」で、技術の深さは外部のエンジニアに一時間ほど面接に入ってもらって確かめます。代行に出す場合は、この段取りも含めて任せられます。技術の確認を省いて採ると、ベンダーに言われるままになる人を採ることがあります。

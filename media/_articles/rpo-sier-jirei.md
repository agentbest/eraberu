同じ採用代行を使っても、機能するSIerと機能しないSIerがあります。差を作るのは代行の腕ではなく、発注側の条件です。役割を工程と案件で切っているか、採った人をどの案件に入れるかを社内で決めているか、常駐と働き方の実態を先に出しているか、案件の見込みの段階で採用が動いているか、記録が社内にあるか、任せる工程が絞られているか。結論を先に書くと、**SIer業界で採用代行が機能するのは、役割・照合・働き方・時期・記録・工程の六つで「社内に残すものを残している」会社で、機能しないのは「SEを何人でも、全部任せたい」会社です。**発注の前に六つで自社を確かめ、機能しない条件があれば、発注の前にそれを変えます。工程の切り分けは[SIer業界の採用代行](/media/rpo-sier-rpo/)に、課題の分解は[SIer業界の採用課題](/media/rpo-sier-kadai/)に、IT・Web業界の条件は[IT・Web業界で採用代行が機能する条件・機能しない条件](/media/rpo-it-jirei/)に書いています。ここでは、SIer業界の六つの対に絞ります。

## 六つの対

| 軸 | 機能する条件 | 機能しない条件 |
|---|---|---|
| 役割 | 「どの工程を、どの案件で、常駐か持ち帰りか」で要件を切っている | 「SE経験〇年」「幅広くできる人」 |
| 照合 | 採った人をどの案件に入れるかを、社内の責任者が決めている | 「採ってから考える」。稼働しない期間が出る |
| 働き方 | 常駐先の型と持ち帰りの比率を、求人票と初回の連絡で出している | 「常駐のことは面接で」 |
| 時期 | 案件の見込みの段階で、要る役割・人数・時期が採用の一枚にある | 受注が決まってから「急いで」 |
| 記録 | 一覧と面接の記録が社内の環境にあり、代行がそこに書く | 記録が代行の環境。契約が終わると消える |
| 工程 | 任せる工程が一つか二つに絞られ、残す工程の担当がいる | 「全部任せたい」 |

六つのうち一つでも機能しない条件にあると、代行はその部分で止まります。全部が揃っている必要は無く、発注前に一つずつ変えます。

## 役割：工程と案件で切っているか

| 機能する | 機能しない |
|---|---|
| 社内の責任者が、案件と体制から「上流のPM」「設計・実装」「運用・常駐」を分けて要件にしている | 「SE」の一本で募集。代行が広く集め、面接で「案件に合わない」 |
| 代行が「担った工程の言葉」に整え、責任者が確認する | 代行が要件を推測 |
| 案件が変われば要件が変わる、と代行に伝わる | 要件が変わっても伝わらず、ずれた推薦が続く |

役割の切り分けは、社内の責任者にしかできません。切り分けに時間を出せない会社では、代行は機能しません。時間は、案件ごとに三十分で足ります。

### エラベルの見解

SIer業界で最も多い機能しない条件は、「照合」が無いことです。代行が採用を進め、内定が出た段階で「この人はどの案件に入れるか」を考え始め、合う案件が無く、稼働しない期間が出るか、合わない案件に入れて早期に離れる。直し方は、募集を始める前に、「この募集は、この案件（または、この型の案件）のため」と決め、採用の一枚に案件の列を置くことです。案件が決まっていない募集は、「この型の案件に入れる人」として、型（業界、工程、常駐か持ち帰りか）を決めておきます。エラベルで担当者を選ぶ企業には、「いまの募集は、どの案件のためですか」を、私たちから先に聞いています。答えが無い募集は、代行に出す前に案件との紐づけをします。紐づけ方は[要員計画と採用計画がつながっていない](/media/rpo-jinin-keikaku/)に書いています。

## 照合：案件に入れる人を社内で決めているか

| 機能する | 機能しない |
|---|---|
| 募集ごとに「どの案件（型）のため」が決まっている | 「採ってから考える」 |
| 採った人の最初の案件と、入社から案件の開始までの役割が決まっている | 入社後に稼働しない期間が出る |
| 案件の責任者が面接に出る | 人事だけが面接し、案件の責任者が入社後に「合わない」と言う |

照合は、代行に任せられない工程です。案件の責任者が、要件の切り分けと面接の一段に出る形が、機能する条件です。

## 働き方：常駐の実態を先に出しているか

| 機能する | 機能しない |
|---|---|
| 常駐先の型（業界、場所の範囲）、持ち帰りの比率、常駐先が変わる頻度を、求人票と初回の連絡で出す | 「常駐のことは面接で」。面接や内定後に辞退 |
| リモートの可否を「常駐先の条件による」と正直に | 「リモート可」と書き、実態は常駐先次第 |
| 応募の減少を受け入れ、面接の通過と定着で見る | 応募の数を成果にして、実態を隠す |

働き方を先に出す判断は会社のもので、代行が決められません。出さない会社では、代行の母集団形成は面接での辞退で消えます。

## 時期：案件の見込みの段階で動いているか

| 機能する | 機能しない |
|---|---|
| 営業と採用が月次で案件の見込みを共有し、採用の一枚に「要る役割・人数・時期」が先に置かれている | 受注が決まってから募集。間に合わず、要件を緩める |
| 募集の開始を、過去の記録の日数から逆算している | 「来月には欲しい」で始める |
| 採る時期と案件の開始を合わせ、間の期間の役割を決めている | 採れたが稼働しない |

時期の条件は、営業と採用の間の仕組みで、代行が触れない領域です。仕組みが無い会社では、代行は「急いで」の依頼を受け続け、ずれた採用を繰り返します。

### エラベルの見解

「全部任せたい」というSIerの会社は、多くの場合、社内に採用の担当がおらず、営業と現場の責任者が兼務で採用を見ています。その状態で全部を任せると、役割の切り分けも照合も働き方の判断も代行に寄り、代行にはできないので止まります。エラベルは担当者を工程ごとに選べる形にしているので、兼務の責任者が「役割の切り分けと案件との照合」だけに時間を使い、「母集団形成・一次対応・日程・記録」を担当者が担う、という組み方ができます。責任者の時間は、案件ごとに三十分の切り分けと、面接の一段だけで足ります。全部を任せる契約より、残す工程を最小にして残りを任せるほうが、機能します。工程の切り分けは[母集団形成は代行に出せるか](/media/rpo-task-boshuudan-daikou/)や[面接の日程調整は代行に出せるか](/media/rpo-task-nittei-chousei-daikou/)に書いています。

## 記録：社内の環境にあるか

| 機能する | 機能しない |
|---|---|
| 一覧と面接の記録が社内のATSか共有の場所にあり、代行がそこに書く | 記録が代行の環境。社内から見えない |
| 週次の一枚で、段階ごとの数と止まりが届く | 月末の報告だけ |
| 契約が終わっても、記録と型（要件の一枚、依頼書、文面）が社内に残る | 契約が終わると全部消え、次の案件でゼロから |

SIerは案件ごとに募集を繰り返すので、型が社内に残るかどうかで、二回目以降の速さが変わります。記録の扱いは[引き継ぎ資料に含める内容](/media/rpo-hikitsugi-shiryou/)に書いています。

## 工程：絞られているか

| 機能する | 機能しない |
|---|---|
| 「スカウトの母集団形成と一次対応」「紹介会社への依頼書と返事の速さ」のように、任せる工程が明確 | 「採用を全部」 |
| 残す工程（役割・照合・技術の見極め・条件・合否）の担当が決まっている | 残す工程の担当がいない |
| 一つの案件の募集で三か月回し、記録で効いたかを見てから広げる | 最初から全工程・全募集 |

## 機能しない条件を変える順番

| 順 | 変えること | 費用 |
|---|---|---|
| 一 | 役割：いまの募集を「どの工程を、どの案件で、常駐か持ち帰りか」で切る | かからない（責任者の三十分） |
| 二 | 照合：募集ごとに案件（型）を決める | かからない |
| 三 | 記録：一覧と記録の形を社内の環境に | かからない |
| 四 | 工程：任せる工程を一つに絞る | 契約の範囲が小さくなる |
| 五 | 働き方：常駐の実態を先に出すかを決める | 会社の判断 |
| 六 | 時期：営業と採用の月次の共有を置く | 仕組み。時間がかかる |

一から四は発注の前に社内で変えられます。五は会社の判断、六は仕組みなので、代行を使いながら整えます。

## 機能しているかを見る記録

| 見ること | 機能している目印 |
|---|---|
| 書類の○と面接の一致 | 一致していれば役割が機能 |
| 入社から最初の案件の開始までの日数 | 短ければ照合が機能 |
| 面接と内定後の辞退の理由 | 「働き方」が減っていれば働き方が機能 |
| 募集の開始と案件の開始の差 | 間に合っていれば時期が機能 |
| 週次の一枚と、型の残り | 届き、残っていれば記録が機能 |

件数のまま並べ、前の募集と比べます。割合や外部の平均で断定しません。三か月で動かない工程は、六つの対で「代行の問題か、社内の残す部分の問題か」を分けます。見る指標は[採用代行との定例会で見るべき数字](/media/rpo-teirei/)に書いています。

## まとめ

- 代行が機能するかは**代行の腕より発注側の条件**で決まる
- 六つの対は**役割・照合・働き方・時期・記録・工程**
- 最も多い機能しない条件は**照合**。募集ごとに「どの案件のため」を決める
- **「SEを何人でも、全部任せたい」は機能しない**。残す工程を最小にして残りを任せる
- 変える順番は**役割→照合→記録→工程→働き方→時期**。一〜四は発注前に社内で
- SIerは募集を繰り返すので、**型が社内に残るか**で二回目以降が変わる
- 機能しているかは**記録で件数のまま**見る

## よくある質問

### 案件が常に複数動いていて、募集ごとに案件を決められません

「案件の型」で決めます。「金融の上流」「製造の運用常駐」「公共の設計・実装」のように、業界と工程と働き方の型を三つ程度作り、募集を型に紐づけます。採った人は、その型の案件のどれかに入る、という形なら、照合の判断は入社の前にできます。型が決まらない募集は、対象が絞れず、代行は機能しません。

### 常駐の実態を先に出すと、競合のSIerに負けるのではないですか

先に出さない競合は、面接と入社後に辞退と離職を出しています。先に出す会社は、応募は減っても、面接の通過と定着が上がり、募集を繰り返す回数が減ります。どちらが「負け」かは、応募の数で見るか、入社と定着で見るかで変わります。記録で「辞退の理由」と「早期離職の理由」を見れば、自社がどちらで損をしているかが分かります。

### 営業と採用の共有の仕組みが無く、時期の条件を変えられません

仕組みが無い間は、代行を使いながら、「案件の見込みが立ったら、責任者から代行の担当者に一言」の形から始めます。月次の会議でなくても、一言が採用の一枚に入れば、募集の開始を逆算できます。仕組みは後から整えればよく、最初は「見込みの段階で一言」の習慣で足ります。採用計画とのつなぎは[採用計画の設計の進め方](/media/rpo-task-saiyo-keikaku-susumekata/)に書いています。

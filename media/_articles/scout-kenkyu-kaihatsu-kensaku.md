研究開発にスカウトを送る前の検索で、「博士、研究経験〇年以上」で条件を組むと、二つの問題が起きます。一つは、分野も対象も手法も違う人が同じ一覧に出ること。もう一つは、博士を必須にすると少ない市場がさらに狭くなり、いても自社のテーマと合わないこと。学位と論文の数は、「自分で問いを立てて、進め方を決めて、成果まで持っていったか」を教えません。研究開発の検索で最初にやるべきは、自社のテーマと任せる段階を決め、学位や年数ではなく「何を対象に、どの手法で、何を示し、どの段階か」で探し、数ではなく一通ずつ論文を確認することです。結論を先に書くと、**検索条件は、先に自社のテーマ（分野・対象・手法）と任せる段階（基礎・応用・事業化前）を決め、学位や年数ではなく経験（研究の対象と手法・担った段階・自分で進めて成果を出したか）で組み、要件の必須だけにし、論文と経歴を「何を対象に、どの手法で、何を示し、どの段階か」で読み、数ではなく一通ずつ論文を確認し、隣の対象や手法と、学位や任期の区切りが近い層を含めて送る順を決めます**。文面の型は[研究開発へのスカウト文面](/media/scout-kenkyu-kaihatsu-bunmen/)に、要件の作り方は[研究開発の採用要件の作り方](/media/rpo-kenkyu-kaihatsu-youken/)に書いていますので、ここでは「検索条件とターゲティング」に絞ります。媒体ごとの検索の仕様には触れません。仕様は各媒体の公式情報でご確認ください。

## 先に「テーマ（分野・対象・手法）」と「任せる段階」を決める

自社のテーマを、分野（材料、化学、生物、情報など）、対象（何を研究するか）、手法（どんな方法で）に分けて決め、任せる段階（基礎の探索か、応用か、事業化の前の実証か）を決めます。二つで探す人が変わります。

| 決めること | 探す人が変わる点 |
|---|---|
| 分野・対象 | 対象が違う人は自分の研究と近いかを判断できない。隣の対象は手法が共通なら対象 |
| 手法 | 手法が共通なら、対象が違っても活きることがある |
| 任せる段階 | 基礎なら問いを立てた経験。応用や事業化前なら成果を製品や工程に近づけた経験 |

止まりやすいのは、「研究開発経験者」でテーマを決めないときと、守秘を理由にテーマを担当者にも伝えないときです。担当者がテーマの分野と対象を知らないと、論文の要点を整理できません。決め方は[研究開発の採用要件の作り方](/media/rpo-kenkyu-kaihatsu-youken/)に書いています。

## 学位や年数ではなく経験で組む

条件に入れるのは、学位や年数ではなく、要件の必須に当たる経験です。学位は、博士に何を期待するか（独立して研究を進める力、専門の深さ）が明確な場合だけ必須にし、それ以外は歓迎にします。肩書は「または」で複数（研究員、研究開発、ポストドクター、助教、開発技術者）を入れるか、入れずに論文と経歴の言葉で読みます。

| 要件 | 検索条件に | 理由 |
|---|---|---|
| 必須：〇〇（分野・対象）の研究経験 | 分野と対象の言葉で | テーマの中核 |
| 必須：〇〇（手法）の経験 | 手法の言葉で | 手法が共通なら対象を広げられる |
| 必須：自分で研究を進めて成果を出した経験 | 論文と経歴で読む | 検索の言葉にしにくい |
| 学位 | 博士に期待することが明確なら入れる。それ以外は入れない | 期待で変わる |
| 歓迎：論文や特許の数 | 入れない | 数と中身は一致しない |
| 歓迎：年数 | 入れない | 年数より対象と手法と段階 |

止まりやすいのは、博士と年数と論文の数を「かつ」で組んで、数人しか出ないときです。博士に期待することが明確でないなら外し、対象と手法で読みます。

## 論文と経歴を「何を対象に、どの手法で、何を示し、どの段階か」で読む

研究開発の経験の中身は、四つで読めます。何を対象に、どの手法で、何を示したか（論文や特許の結果）、どの段階か（基礎の探索か、応用か、事業化に近いか）。加えて、自分で問いを立てて進めたかは、論文の著者の位置や、経歴の記述（主担当か、テーマを提案したか）で読みます。数ではなく、一通ずつ論文を確認します。

| 論文と経歴の記述 | 読み方 |
|---|---|
| 「〇〇の研究に従事」 | 対象も手法も結果も無い。中身が読めない |
| 「〇〇（対象）を〇〇（手法）で解析し、〇〇（結果）を示した（主著）」 | 対象、手法、結果、主担当。四つが揃う |
| 「〇〇プロジェクトに参加。〇〇の実験を担当」 | 一部を担当。問いを立てた経験は不明 |
| 「〇〇（手法）を〇〇（隣の対象）に応用」 | 手法が共通。自社の対象と違っても、手法で近い |
| 「企業で〇〇の実用化に向けた研究。〇〇の試作」 | 応用や事業化前の段階の経験 |
| 「任期〇年の研究員。〇年〇月まで」 | 区切りが近い。動く時期が読める |

止まりやすいのは、学位と論文の数だけで判断するときです。「〇〇の研究に従事」の人に「〇〇のテーマを自分で進めてほしい」と送っても、経歴と合うかが分かりません。

### エラベルの見解

相談で最も多い思い込みは、「研究者は博士で論文が多い人を選べば間違いない」というものです。実際には、博士で論文が多くても、対象と手法が自社のテーマと遠ければ活きず、大きな研究室で一部の実験を担当してきた人は、自分で問いを立てて進めた経験が無いことがあります。ある会社では、博士と論文の数で検索して出てきた人に送っていましたが、対象が遠く、面談で「このテーマには関心が無い」と辞退が続いていました。担当者が入って、自社のテーマを「〇〇（分野）の〇〇（対象）を〇〇（手法）で。応用の段階」と研究所長と整理し、博士を歓迎に落とし、対象と手法の言葉でプロフィールを読み、出てきた人の論文を一通ずつ確認して研究所長に要点を渡す形にしたところ、対象は少し違うが手法が共通で、自分で問いを立てて成果を出してきた人が見つかり、研究所長の一言を添えて送ると返信が来ました。研究開発の検索は、学位と数で機械的に絞るより、対象と手法と段階で人が論文を読むほうが合います。

## 隣の対象や手法と、区切りが近い層を含める

自社のテーマにぴったりの研究者は少ないので、二つの方向で広げます。一つは、隣の対象や手法。対象が違っても手法が共通なら、手法で近い人。手法が違っても対象が同じなら、対象で近い人。もう一つは、学位や任期の区切りが近い層。博士の取得が近い人、任期付きの研究員で任期の終わりが近い人、研究室の移動を考えている人は、動く時期が読めます。

| 広げる方向 | 見どころ | 文面 |
|---|---|---|
| 隣の対象（手法が共通） | 手法で自社のテーマに応用できる記述 | 一行目で手法に触れ、対象の違いは「この手法を当社の対象に」と書く |
| 隣の手法（対象が共通） | 対象が同じで、別の手法で示した結果 | 一行目で対象に触れ、手法の違いは「別の角度から」と書く |
| 区切りが近い層 | 任期の終わり、学位の取得の時期 | 区切りに合わせた日程を書く |
| 企業の研究者から | 応用や事業化前の経験。「基礎に戻りたい」か「事業化に近づきたい」の記述 | 自社の段階と合う方向を書く |

止まりやすいのは、対象が少ないからと、分野も対象も手法も違う人に送るときです。「読んでいない」と受け取られます。

## 送る順の付け方

| 順 | 条件 |
|---|---|
| 一 | 分野と対象と手法が自社のテーマと合い、段階が合い、自分で進めて成果を出した記述があり、研究所長が論文を確認して一言添えられる |
| 二 | 対象か手法のどちらかが合い、もう一方は隣。自分で進めた記述がある。違いに先に触れる文面で送る |
| 三 | 区切りが近く、テーマが近い。区切りに合わせた日程で送る |
| 送らない | 分野が遠い。四つが読めず学位と論文の数だけ。一部の実験の担当のみで、自分で進めた記述も意欲も無い。研究所長が論文を確認する時間が無い（送る数を減らす） |

止まりやすいのは、「博士だから」「論文が多いから」で送るときです。対象と手法と段階と、自分で進めたかで順を付けます。

## 条件の保存と見直し

組んだ条件は、「〇〇（対象）用」「〇〇（手法）用」「区切りが近い層用」のようにテーマの軸ごとに名前を付けて保存し、送った結果と一緒に記録します。月に一度、返信が来た人の共通点（対象、手法、段階、自分で進めたか、区切り）を見て、条件と読み方を直します。保存の仕方は[検索条件の保存と使い回し](/media/scout-kensaku-hozon/)に書いています。

### エラベルの見解

担当する側から見ると、研究開発の検索で会社ごとに差がつくのは、「研究所長がテーマの分野と対象と手法を、守秘の範囲で担当者に伝えているか」です。守秘を理由に担当者に何も伝えない会社では、担当者は「博士、研究経験」で機械的に絞るしかなく、論文の要点も整理できません。分野と対象と手法を伝えている会社では、担当者が対象と手法の言葉でプロフィールを読み、論文の要点を整理して研究所長に渡せ、研究所長は一通に数分で一言添えられます。エラベルでスカウトの検索を担当する人には、条件を組む前に、研究所長に「分野と対象と手法は何か、段階はどこか、博士に何を期待するか、守秘でどこまで担当者に伝えられるか」を聞いてもらっています。文面の型は[研究開発へのスカウト文面](/media/scout-kenkyu-kaihatsu-bunmen/)に書いています。

## 代行に出す場合の範囲

担当者が持つのは、要件から必須の経験を取り出して条件を組むこと、出てきた人の論文と経歴を「何を対象に、どの手法で、何を示し、どの段階か」で読んで絞ること、論文の要点を整理して研究所長に渡すこと、隣の対象と区切りが近い層を分けて送る順を付けること、条件と結果を記録して月に一度見直すこと、です。会社が持つのは、テーマの分野と対象と手法と段階の決定、守秘の範囲で担当者に伝えること、博士に期待することの決定、要件の必須と歓迎の区別、研究所長が論文を確認して一言添える時間、です。担当者が研究の分野を理解して論文の要点を整理できる経験があるかは、担当者を選ぶときに確かめます。担当者の経歴の見方は[担当者の経歴の見方](/media/rpo-tantousha-keireki/)に書いています。

## まとめ

- 先に**テーマ（分野・対象・手法）と任せる段階**を決め、守秘の範囲で担当者に伝える。伝えないと担当者は学位で機械的に絞るしかない
- 検索条件は**学位や年数ではなく経験（対象・手法・段階・自分で進めて成果を出したか）**で組む。博士は期待することが明確な場合だけ必須に
- 論文と経歴は**「何を対象に、どの手法で、何を示し、どの段階か」**で読む。数ではなく一通ずつ論文を確認する
- **隣の対象や手法（どちらかが共通）と、学位や任期の区切りが近い層を含める**
- **一部の実験の担当のみで、自分で進めた記述も意欲も無い人には送らない**
- 条件は**テーマの軸ごとに分けて保存し、返信が来た人の共通点で月に一度直す**

## よくある質問

### 博士を必須にすべきですか

博士に何を期待するか（独立して研究を進める力、専門の深さ、論文を書く力）が明確なら必須にし、明確でないなら歓迎にとどめます。博士でも一部の実験の担当のみで自分で進めた経験が薄い人はいて、修士でも企業で自分でテーマを進めて成果を出してきた人はいます。読むのは学位ではなく、「自分で問いを立てて、進め方を決めて、成果まで持っていったか」です。博士の取得を支援する会社は、その支援を文面に書くと、取得を考えている人に響きます。

### 大学の研究者に送るとき、何に気をつければよいですか

任期と学位の区切りに合わせます。任期付きの研究員は任期の終わりの時期、博士課程の人は学位の取得の時期に動きます。区切りの前に「区切りに合わせて」と書いて送り、区切りの数か月前から接点を持ちます。大学の研究者は「研究者として扱われるか」（発表できるか、自由度はあるか、評価は論文か事業か）を確かめるので、文面で実態を正直に書き、研究所長が論文を読んで面談に出ます。

### 出てくる人が少なすぎます

博士か年数か論文の数で絞っているかを見ます。外して、対象と手法の言葉で読む形にすると増えます。それでも少ないなら、隣の対象（手法が共通）か隣の手法（対象が共通）に広げ、区切りが近い層と企業の研究者を含めます。研究開発は市場に少ないので、送る相手の数より、テーマが近い人に研究所長の一言を添えて送るほうが、返信の数は増えます。研究所長が確認できる数だけ送ります。

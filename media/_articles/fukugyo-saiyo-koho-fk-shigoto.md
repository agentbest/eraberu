採用広報の記事執筆を初めて受けるとき、見えにくいのは「取材の前に何を決め、原稿の後に何があるか」です。募集文には「社員インタビューの執筆」「月〇本」とだけあり、実際には、伝えない情報の一覧、承認する人と期限、顔出しと実名の方針、取材の日程の確保、本人と会社の確認の往復、公開の作業、閲覧と応募の記録と、書く前後に工程が並びます。順番を知っていれば、契約前に決めておけます。結論を先に書くと、**1案件は「契約前→第1週→企画から公開まで（一本ごと）→月次→終了と更新」の五つの段階で進み、契約前に範囲と本数・伝えない情報の一覧・承認する人と期限・顔出しと実名の方針・取材に応じる社員と時間・出す場所・記録の有無・直しの回数を決め、第1週は取材せずに一覧と方針の確認と企画の型と質問表と原稿の型と記録の表を整え、一本ごとに企画→取材→原稿化→本人と会社の確認→公開→記録を回し、月次で読まれた場面の型を次の企画に活かして止まっている工程を直し、型と記録を引き継いで終えます。**案件の型と求められる経験は[採用広報の記事執筆の副業案件](/media/fukugyo-saiyo-koho-fk-fukugyo/)に書いていますので、ここでは「1案件の流れ」に絞ります。

## 契約前：決めておくこと

採用広報は、「月〇本」の本数だけで契約されやすく、承認の往復と取材の日程の変更で稼働が読めなくなります。契約前に決めます。

| 決めること | 確かめる中身 | 決めていないと起きること |
|---|---|---|
| 範囲と本数 | 原稿だけか、企画からか、運用と記録までか、型作りか。月に何本 | 「ついでにSNSの投稿も」が足される |
| 伝えない情報の一覧 | 取引先、未公開の数字、開発中のもの、他の社員のこと、退職者のこと、など会社が決めた一覧があるか。無ければ作るか | 原稿の段階で削る往復が増える。事故 |
| 承認する人と期限 | 本人の確認、会社の承認、それぞれ誰が何日以内か | 原稿が経営者の机で一か月止まる |
| 顔出しと実名の方針 | 顔写真、実名、所属を載せるか。同意の取り方と記録。退職時の扱い | 公開後に本人から取り下げを求められる |
| 取材に応じる社員と時間 | 誰が、いつ、どのくらいの時間、取材に応じられるか。日程の確保は会社 | 取材の日程が取れず、本数が出ない |
| 出す場所 | 採用サイト、ブログ、SNS、外部の媒体。公開の作業は誰か。写真は誰が撮るか | 原稿ができても公開されない |
| 記録の有無 | 閲覧、採用サイトへの流入、応募時に読まれた記事、を誰が記録するか | 「効いているか分からない」で終わる |
| 直しの回数 | 本人の確認と会社の承認で、何回まで直すか。超えたときの扱い | 直しが際限なく続く |

止まりやすいのは、「まず一本書いてみてください」で始めるときです。伝えない情報の一覧と承認する人と期限だけは、取材の前に決めます。範囲の決め方は[業務範囲の決め方](/media/fukugyo-scope/)に、見積もりの出し方は[見積もりの出し方](/media/fukugyo-mitsumori/)に書いています。

## 第1週：取材しない週

第1週は、取材を始めません。一覧と方針を確認し、企画の型、場面を聞く質問表、原稿の型、記録の表を整えます。準備の無いまま取材すると、会社の説明を聞いて帰ることになります。

| やること | 依頼側に持ってもらうこと | 落とし穴 |
|---|---|---|
| 伝えない情報の一覧と、顔出しと実名の方針の確認 | 一覧と方針の共有か作成 | 「常識で分かる」と確認しない |
| 承認の流れの確認（本人→会社の順、期限、直しの回数） | 承認する人の確定 | 期限の無い承認 |
| 企画の型（候補者のどんな疑問に答えるか、誰に、何の場面を聞くか） | 候補者が面接で聞くことの一覧の共有 | 「会社の紹介」「事業の説明」の企画 |
| 場面を聞く質問表（「最近時間がかかった仕事」「入った頃に誰に聞いたか」「昨日の午後」など） | 質問表の確認 | 「やりがい」「魅力」を聞く質問表 |
| 原稿の型（見出しの数、長さ、社員の言葉の割合、写真の位置、末尾の導線） | 原稿の型の承認 | 型が無く、一本ごとに形が違う |
| 記録の表（記事、公開日、取材した社員、場面の型、閲覧、採用サイトへの流入、応募時に読まれたか） | 記録を出す人の確定 | 記録の表が無い |
| 過去の記事の確認（何が読まれ、何が読まれなかったか） | 過去の記録の共有 | 過去を見ずに同じ企画を出す |

止まりやすいのは、「取材の日程が取れたから」と第1週を飛ばすときです。質問表の無い取材は、社員が会社の説明を話し、場面が出ません。聞き方は[ヒアリングの技能](/media/fukugyo-hearing-skill/)に書いています。

### エラベルの見解

担当する側から見ると、この仕事は「第1週に、候補者が面接で聞くことの一覧をもらえるか」で、企画の質が決まります。候補者が面接で聞くことは、「残業は」「入ってすぐ何をするか」「上司はどんな人か」「失敗したらどうなるか」のように具体で、その疑問に答える場面を社員に聞けば、読まれる記事になります。面接で聞かれていることの一覧が無い会社では、企画が「会社の紹介」になり、読まれません。エラベルで担当者を選ぶ企業には、「最初の一週間で、面接で候補者からよく聞かれることを十個ください。それが企画の一覧になります」と、私たちから先に伝えています。受ける側がその場で使える判断としては、企画の型を「候補者の疑問→答える場面→聞く社員」の三つの欄で作ること。疑問の欄が埋まらない企画は、まだ出しません。

## 企画から公開まで：一本ごとの流れ

第2週から、一本ごとに同じ流れを回します。

| 順 | やること | 落とし穴 |
|---|---|---|
| 企画 | 候補者の疑問→答える場面→聞く社員、を決め、会社に取材の日程を確保してもらう | 社員に直接日程を頼む（会社を通す） |
| 取材の前 | 質問表を社員に先に渡す（場面を思い出してもらう）。伝えない情報の一覧を自分で再確認 | 質問表を渡さず、その場で考えてもらう |
| 取材 | 場面を聞く。会社の説明に流れたら「そのとき、具体的には」と戻す。録音は本人の同意で。時間を守る | 「魅力は」と聞く。時間を超える |
| 原稿化 | 社員の言葉のまま。順番と重複だけ整える。伝えない情報を書かない。原稿の型に沿う | 書き言葉に直し切る。面白い話（伝えない情報）を書く |
| 本人の確認 | 「自分の言葉だと思えるか」「載せたくない箇所はあるか」を聞く。直しは本人の意思を優先 | 本人の確認を飛ばして会社に出す |
| 会社の承認 | 伝えない情報が混じっていないか、表現の判断。期限内に | 期限を過ぎても催促しない |
| 公開 | 出す場所に、写真と一緒に。公開日を記録 | 公開の作業を誰がやるか決まっていない |
| 記録 | 公開日、社員、場面の型、閲覧、採用サイトへの流入、応募時に読まれたか | 記録せずに次へ |

止まりやすいのは、本人の確認を飛ばして会社の承認に出すときです。本人が「言っていない」と感じた記事は、公開後に取り下げになり、社員との信頼を失います。本人の確認を先にします。記録の型は[報告の仕方](/media/fukugyo-houkoku/)に書いています。

## 月次：読まれた場面の型を次の企画に

月に一度、記録を見て、次の企画を決めます。見るのは、閲覧の多さより、「どの疑問に答えた記事が、採用サイトへの流入と応募につながったか」です。

| 見ること | 読み方 | 次の企画 |
|---|---|---|
| 読まれた記事の場面の型 | 「困った日」「入ってすぐ」「上司との場面」など、どの型が読まれたか | 同じ型で別の社員に |
| 採用サイトへの流入が多い記事 | 候補者が「もっと知りたい」と思った疑問 | その疑問の周りを深く |
| 応募時に「読んだ」と言われた記事 | 応募に効いた記事 | その記事の型を優先 |
| 読まれなかった記事 | 会社の説明になっていないか。場面が無いか | 型を直す。社員のせいにしない |
| 止まっている工程 | 取材の日程、承認、公開のどこで止まっているか | 会社に決めてもらう |

止まりやすいのは、月次で「閲覧が少ないので、もっと面白く書く」と、文章の側だけを直すときです。読まれないのは、場面が無いか、候補者の疑問に答えていないかで、文章の面白さではありません。

### エラベルの見解

同じ料金・同じ本数でも、結果が分かれるのは、月次で「応募時に読まれた記事」を追えるかです。閲覧だけを見ている担当者は、閲覧の多い「会社の紹介」を増やし、応募は変わらず、三か月で「効いていない」と契約を終えられます。面接や応募のときに「どの記事を読みましたか」と会社に聞いてもらい、記録の表に残している担当者は、閲覧は少なくても応募に効いた記事の型を見つけ、次の企画をそこに寄せて、応募の質を変えます。閲覧は媒体の数字で、応募は会社の数字です。応募の数字を取るには、会社が面接で一言聞く協力が要ります。エラベルで長く続いている担当者は、第1週に「面接で『読んだ記事はありますか』と聞いてください」と会社に頼み、月次でその答えを並べています。受ける側がその場で使える形としては、記録の表に「応募時に読まれた」の欄を作り、埋まらない月は「面接で聞いてもらえていない」ことを報告することです。

## 終了と更新：型と記録の引き継ぎ

契約の期間が来たら、更新か終了かを会社が決めます。どちらでも、引き継げる形にして終えます。

- **残すもの。** 企画の型（候補者の疑問→場面→社員）、場面を聞く質問表、原稿の型、承認の流れ、記録の表（公開日、場面の型、閲覧、流入、応募時に読まれたか）、読まれた型の一覧、伝えない情報の一覧（会社のもの）
- **返すもの。** 取材の録音（会社の管理のもとで削除か保管）、公開前の原稿、写真、共有された資料。社員の話を自分の手元に残さない
- **次の提案。** 更新するなら、次の三か月で寄せる場面の型と本数。終了するなら、社内で回す手順（誰が企画し、誰が取材し、誰が承認するか）

止まりやすいのは、公開済みの記事を自分の実績として、会社の許可を取らずに載せることです。会社の名前で出た記事は会社のもので、実績に使うなら許可を取り、社員の名前と顔は自分の実績には載せません。引き継ぎの型は[引き継ぎの仕方](/media/fukugyo-hikitsugi/)に、実績の書き方は[事例の書き方](/media/fukugyo-jirei-kakikata/)に書いています。

## 取材で聞いた情報の扱い

取材では、社員が、伝えない情報（取引先、未公開の数字、他の社員のこと）や、個人の事情（家族、健康、転職の経緯）を話します。原稿に書かないのはもちろん、会社の外で話さず、他の依頼側や本業に持ち込みません。録音は本人の同意で行い、会社の管理する場所に置き、終了時に会社の方針に従って削除か保管します。公開前の原稿を自分のSNSや実績に出しません。顔写真と実名の同意は会社が取り、記録を会社が残します。退職した社員の記事の扱いは、会社の方針に従います。個別の判断は専門家にご確認ください。扱いの詳細は[発信で書いてはいけないこと](/media/fukugyo-hasshin-nglines/)と[候補者の個人情報の扱い](/media/fukugyo-kojin-jouhou/)に書いています。

## 稼働時間は何で決まるか

一本にかかる時間は、「企画」「取材（移動や待ち時間、日程の変更を含む）」「原稿化」「本人と会社の確認の往復」「公開の作業（含む場合）」「記録」の合計で決まり、書く時間そのものは全体の一部です。承認の往復が多い会社と、取材の日程が動く会社では、一本の稼働が倍以上になります。契約前に「承認の期限と直しの回数」「取材の日程の確保は会社」「公開の作業は誰か」を決めておけば、見込みが立ちます。数値は案件ごとに違うので、最初の三本の実績で見直します。稼働の管理は[稼働時間の管理](/media/fukugyo-kadou-kanri/)に書いています。

## まとめ

- 1案件は**契約前→第1週→企画から公開まで（一本ごと）→月次→終了と更新**の五つの段階
- 契約前に**範囲と本数・伝えない情報の一覧・承認する人と期限・顔出しと実名の方針・取材に応じる社員と時間・出す場所・記録の有無・直しの回数**を決める。一覧と承認は取材の前に
- 第1週は**取材しない**。候補者が面接で聞くことの一覧をもらい、企画の型（疑問→場面→社員）、質問表、原稿の型、記録の表を整える
- 一本ごとに**企画→質問表を先に渡す→場面を聞く取材→社員の言葉のまま原稿化→本人の確認→会社の承認→公開→記録**。本人の確認を先に
- 月次は**応募時に読まれた記事**を追い、読まれた場面の型に次の企画を寄せる。文章の面白さの側だけを直さない
- 終了時は**企画の型・質問表・原稿の型・記録の表・読まれた型**を残し、録音と公開前の原稿を会社の方針で処理する
- 取材で聞いた伝えない情報と個人の事情は**原稿に書かず、外で話さず、持ち込まない**

## よくある質問

### 取材の日程が、社員の都合で直前に何度も動きます

取材の日程の確保は会社の役割にし、契約前に決めておきます。「取材の日程は御社が社員の方と確保してください。前日までの変更は振り替え、当日の変更は稼働として数えます」と、変更の扱いを書面に残します。動くことが続くなら、月次で「取材の日程で止まっている」と報告し、会社に社員の時間の確保を決めてもらいます。自分が社員に直接日程を頼む形にすると、社員の業務との調整を外の人が背負うことになります。

### 本人の確認で、話したことをほとんど削られました

本人の意思を優先します。公開されるのは本人の名前と言葉で、載せたくない箇所を残す権利はありません。削られた原稿が場面の無いものになったら、その記事は出さず、別の社員か別の場面で企画を組み直します。削られやすいのは、取材で本人が「これは載せないで」と言わなかった個人の事情や、他の社員に関わる話です。取材の最初に「載せたくないことは、話の途中でも言ってください」と伝えておくと、削る往復が減ります。

### 社内の人が「もっと会社の事業を書いてほしい」と言います

事業の説明は、採用サイトの会社紹介の欄に書くもので、社員インタビューの記事に混ぜると、場面が薄まり、読まれなくなります。「事業の説明は別の記事（会社紹介）で、インタビューは場面に絞ります。両方を並べて、どちらから応募に流れたかを記録で比べさせてください」と、判断は会社に置いたまま、比べる提案をします。記録を見て会社が判断すれば、事業の説明を混ぜる要望は自然に減ります。

案件の稼働は続いているが、請求をいつ出せばよいかが分からず、月末に慌てて出したり、出し忘れて翌月にまとめたりしている。依頼側から「請求書はまだですか」と聞かれて、初めて遅れていたことに気づく。結論を先に書くと、**副業の請求は、「依頼側の締め日の前に」「その月の稼働の報告と一緒に」「毎月同じ日に」出します。締め日を過ぎると支払いが一か月ずれ、稼働の報告と別に出すと依頼側の経理が突き合わせに困り、日が毎月ずれると自分が忘れます。**案件が終わってからまとめて請求する形は、依頼側の経理の処理に合わず、支払いが遅れる原因になります。請求書そのものの書き方は[請求書の書き方](/media/fukugyo-seikyuusho/)に、締め日と支払日の確認は[支払いサイトの確認](/media/fukugyo-shiharai-site/)に、口座の準備は[決済・振込先の準備](/media/fukugyo-kessai/)にまとめています。税や請求書の記載事項は、税理士などの専門家にご確認ください。

## 請求が遅れると起きること

請求のタイミングを軽く見ていると、報酬が遅れるだけでなく、依頼側との関係にも影響します。

| 遅れ方 | 起きること |
|---|---|
| 締め日を過ぎて出した | 依頼側の経理は次の締めで処理する。支払いが一か月遅れる |
| 数か月分をまとめて出した | 依頼側の予算が月ごとに組まれていると、まとめた額が一度に出て、経理が確認に入る。承認に時間がかかる |
| 稼働の報告と別々に出した | 経理は請求の額と稼働の記録を突き合わせられず、担当者に確認が入る。担当者の手間が増える |
| 毎月出す日がばらばら | 依頼側の担当者が「今月は来るのか」と気にする。自分も出したかどうか分からなくなる |
| 依頼側から催促されてから出した | 「請求の管理ができない人」という印象が残る。次の更新や紹介に響く |
| 案件が終わってから全部まとめて出した | 依頼側の担当者が異動していたり、予算の期が変わっていたりして、処理が難しくなる |

遅れの要点は、「依頼側の経理は月ごとに動いている」ことです。副業の報酬は、自分にとっては数か月に一度まとめて受け取っても構わない感覚でも、依頼側の経理にとっては毎月の処理の一つで、月をまたぐと処理が止まります。報酬が遅れたときの対処は[報酬が支払われないときの対処](/media/fukugyo-mibarai/)に書いていますが、その多くは請求の遅れから始まっています。

## 依頼側の締め日から逆算する

請求の日は、自分の都合ではなく、依頼側の締め日から逆算して決めます。契約の最初に締め日を聞いていなければ、最初の請求の前に聞きます。

| 手順 | 内容 |
|---|---|
| 一、締め日と支払日を確認する | 「月末締め・翌月末払い」「二十日締め・翌月十五日払い」のように会社ごとに違う。契約書か担当者に確認する |
| 二、請求書が経理に届く必要がある日を聞く | 締め日当日でよいのか、締め日の数日前までなのか。会社によって「締め日の三営業日前まで」のような決まりがある |
| 三、担当者の確認の時間を引く | 請求書は担当者が確認してから経理に回ることが多い。担当者の確認に数日かかると見て、その分早く出す |
| 四、自分が出す日を固定する | 逆算した日より少し前の、毎月同じ日にする。「毎月二十五日」「月末の三営業日前」のように |
| 五、稼働の記録を締める日を決める | 請求の日に合わせて、稼働の記録を締める。月末稼働分を月末に請求するなら、稼働の見込みで出すか、翌月頭に出すかを依頼側と決める |

逆算の要点は、「担当者の確認の時間を引く」ことです。締め日の当日に担当者に送ると、担当者が確認して経理に回す前に締め日が過ぎることがあります。担当者が確認する数日を引いた日に出せば、締めに間に合います。稼働の記録の締め方は[稼働時間の管理と申告](/media/fukugyo-kadou-kanri/)に整理しています。

### エラベルの見解

相談で最も多い思い込みは、「請求は稼働が終わってからまとめて出すほうが、依頼側の手間が少ない」というものです。実際には、依頼側の経理は月ごとに処理していて、まとめて出された請求は、月ごとに分けて処理し直すか、一度に大きな額として承認を取り直すかのどちらかになり、手間が増えます。担当者も、まとめた請求の額が正しいかを、数か月分の稼働と突き合わせることになります。

依頼側の経理から見て最も楽なのは、毎月同じ日に、同じ形式で、その月の稼働の報告と一緒に請求書が届くことです。同じ日に来るので待たず、同じ形式なので読まず、報告と一緒なので突き合わせが要らない。この三つが揃っていると、経理は「処理しやすい取引先」として扱い、支払いが止まりません。エラベルでは、担当者の請求の時期と形を、依頼側の締め日に合わせて最初に決めるようにしています。請求の時期が整っている担当者は、それだけで依頼側の経理からの評価が変わります。

## 稼働の報告と請求を一緒に出す理由

請求書は、単独で出すより、その月の稼働の報告に添えて出すほうが、依頼側の処理が早くなります。

| 一緒に出す理由 | 内容 |
|---|---|
| 額の根拠が同時に届く | 時間で請求するなら、稼働の記録が請求の根拠。別々に届くと、経理は根拠を探す |
| 担当者が一度で確認できる | 報告を読んで「今月はこう動いた」と分かった直後に、請求の額を見る。確認が一度で済む |
| 報告を出す日が請求の日になる | 報告の日を固定していれば、請求の日も固定される。忘れにくい |
| 稼働の差が説明済みになる | 想定より稼働が多い月も、報告に理由が書かれていれば、請求の額に驚かれない |
| 依頼側の予算の管理に合う | 担当者は月ごとの報告で予算の消化を見ている。請求が同時なら、予算とのずれをその場で確認できる |

一緒に出す要点は、「稼働の差が説明済みになる」ことです。想定より稼働が多かった月に、請求書だけが届くと、担当者は「なぜ多いのか」を聞きます。報告に「今月は〇〇の工程が加わり、稼働が増えた」と書かれていれば、請求の額はその結果として読まれます。報告の書き方は[報告のしかた](/media/fukugyo-houkoku/)に書いています。固定の月額で請求する場合も、報告に添えて出す形は同じで、依頼側は「今月も動いていた」ことを確認した上で処理できます。

## 契約の形ごとの請求の時期

契約の形によって、請求を出す時期の考え方が変わります。

| 契約の形 | 請求の時期 | 注意 |
|---|---|---|
| 月額固定 | 毎月同じ日。稼働の月の締め日の前に、その月の分を出す | 稼働が月の途中で始まった初回は、日割りにするかを最初に決める |
| 時間単価 | 稼働の月が終わってから、記録を締めて出す。締め日が月末なら翌月頭になることが多い | 月末の稼働分が翌月の請求になるか、見込みで出すかを依頼側と決める |
| 成果報酬 | 成果の定義を満たした時点で出す。「内定承諾時」「入社時」のように契約で決まった時点 | 成果の確認を誰がいつするかを決めておく。[成果報酬型は受けるべきか](/media/fukugyo-seika/) |
| 固定と成果の組み合わせ | 固定分は毎月、成果分は成果の時点で。別々の請求書にするか一枚にするかを依頼側と決める | 成果分が固定分の請求の月とずれると、経理が混乱する。分けて出すほうが安全 |
| 仲介サービス経由 | サービスの画面で稼働を報告する期限に合わせる。サービスが請求をまとめる | 自分で請求書を出さない代わりに、報告の期限を過ぎると翌月扱いになる |

契約の形の要点は、「時間単価の月末の扱い」です。月末締めで時間単価の場合、月末の稼働が確定してから請求書を作ると、締め日に間に合いません。「前月の稼働分を当月に請求する」形にするか、「月末の数日分は見込みで出し、翌月に調整する」形にするかを、最初の請求の前に依頼側と決めておきます。契約の形そのものの違いは[条件のすり合わせ](/media/fukugyo-jouken-suriawase/)に整理しています。

## 初回・最終回・途中終了で変わること

毎月同じ日に出す形が回り始めても、初回と最終回、途中で終わる場合は、扱いが変わります。

| 場面 | 変わること | 決めておくこと |
|---|---|---|
| 初回の請求 | 稼働が月の途中から始まっている。依頼側の取引先の登録がまだ済んでいないことがある | 日割りにするか。取引先の登録に必要な情報（口座、登録番号の有無など）を先に出しておく。登録番号の要否は専門家に |
| 最終回の請求 | 契約の終了日が月の途中。引き継ぎの稼働をどう扱うか | 終了日までの稼働で締める。引き継ぎの稼働が契約の範囲かを確認する。[引き継ぎの進め方](/media/fukugyo-hikitsugi/) |
| 途中で終了した | 依頼側の都合で急に終わった場合、その月の稼働分の請求を出す時期が曖昧になる | 終了が決まった時点で、「終了日までの稼働分を〇日に請求する」と文面で確認する。[契約を切られたとき](/media/fukugyo-kaiyaku-sareta/) |
| 更新で条件が変わった | 新しい単価や範囲が、いつの稼働分から適用されるか | 更新日をまたぐ月の請求は、旧条件と新条件の日数で分けるか、更新日以降の月から新条件かを決める。[更新時の条件見直し](/media/fukugyo-keiyaku-koushin-koushou/) |
| 依頼側の担当者が替わった | 請求書の送り先や確認者が変わる | 替わった時点で、新しい担当者に請求の時期と形を改めて伝える |

場面の要点は、「途中で終了したときの請求の時期を文面で確認する」ことです。終了が決まると、双方とも終了の手続きに気を取られ、最後の請求の時期が曖昧になります。終了が決まった日に、「終了日までの稼働分を、〇日に、いつもの形で請求します」と一文送っておけば、最後の請求が宙に浮きません。

## 請求を忘れないための仕組み

請求の遅れの多くは、忘れることから起きます。忘れない仕組みを、案件の最初に作ります。

| 仕組み | 内容 |
|---|---|
| 請求の日を稼働の記録の締め日にする | 記録を締める作業と請求を作る作業を、同じ日の同じ流れにする |
| 請求書の型を案件ごとに作っておく | 宛名、口座、項目が入った型を用意し、月ごとに日付と額だけ変える。[請求書の書き方](/media/fukugyo-seikyuusho/) |
| 入金の記録表に「請求予定日」の列を作る | 案件ごとに請求予定日を書き、月に一度、その列を見る。[決済・振込先の準備](/media/fukugyo-kessai/) |
| 定例の日に合わせる | 依頼側との定例が月に一度あるなら、定例の直後を請求の日にする。定例の準備と請求の準備が一緒になる |
| 依頼側の担当者に「毎月〇日に出す」と伝えておく | 担当者が「今月はまだか」と気づける。自分が忘れたときに催促が早く来る |
| 複数の案件で請求の日を揃えない | 依頼側の締め日が違えば請求の日も違う。無理に揃えると、どれかが締め日を過ぎる |

仕組みの要点は、「請求の日を稼働の記録の締め日にする」ことです。記録を締めれば額が決まり、額が決まれば請求書が作れます。この流れを一つにしておけば、記録を締めた日に請求を出さない理由が無くなります。複数の案件を持つ場合の記録の分け方は[複数案件を掛け持ちできるか](/media/fukugyo-fukusuu-anken/)に書いています。

### エラベルの見解

担当する側から見ると、請求の時期が整っている人は、依頼側の経理から「取引しやすい相手」として扱われ、支払いの遅れがほとんど起きていません。逆に、請求の時期がばらばらな人は、稼働の質が良くても、依頼側の担当者に「請求の管理ができない」という印象が残り、それが更新や紹介の場面で効いてきます。担当者は、自分が経理から確認を求められる手間を覚えています。

順番として、案件の最初の打ち合わせで締め日と支払日と請求書の届く必要がある日を聞き、自分が出す日を固定し、担当者に「毎月〇日に、稼働の報告と一緒に出します」と伝える。この三つを最初に済ませておけば、あとは毎月同じ流れを回すだけです。エラベルでは、依頼側との契約の際に、請求の時期と形を依頼側の締め日に合わせて最初に決めており、担当者が個別に聞く手間を減らしています。請求は、稼働の質と同じくらい、依頼側からの評価に関わります。最初の打ち合わせで触れる項目は[初回打ち合わせの進め方](/media/fukugyo-shodan/)に整理しています。

## よくある質問

### 稼働が少なかった月も、請求を出してよいですか

月額固定なら、稼働の多少に関わらず契約の額を出します。時間単価なら、少なかった分の額で出します。少ないからと翌月にまとめると、依頼側の経理の月ごとの処理に合わず、翌月の額が大きくなって確認が入ります。少ない月も、いつもの日に、いつもの形で出すのが、依頼側にとって最も処理しやすい形です。少なかった理由は、稼働の報告に一行添えます。

### 依頼側から「請求書は四半期ごとでよい」と言われました

依頼側がそう決めているなら、それに合わせます。ただし、四半期ごとにまとめる場合も、稼働の報告は毎月出しておきます。報告が毎月あれば、四半期の請求の額は報告の合計として読まれ、確認が入りません。四半期ごとの請求は、入金までの期間が長くなるので、自分の収入の見立てにその間隔を入れておきます。[年間の副業収入の見立て](/media/fukugyo-nenkan-shuunyuu/)に、入金の間隔を含めた見立ての考え方を書いています。

### 請求書を出し忘れて、締め日を過ぎてしまいました

気づいた時点で、担当者に「今月分の請求が遅れました。次の締めでの処理で構いませんので、本日お送りします」と伝え、すぐ出します。依頼側の経理によっては、締め日を過ぎても当月で処理してくれることがあるので、担当者に聞いてみる価値はありますが、無理は頼みません。翌月分と一緒にせず、遅れた分は遅れた分として単独で出すと、経理の処理が分かりやすくなります。次からは、請求の日を記録の締め日に合わせる仕組みを入れます。

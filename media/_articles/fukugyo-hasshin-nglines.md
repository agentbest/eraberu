副業の案件につなげるために発信を始めたが、何を書いてよくて何を書いてはいけないのかが、書くたびに気になる。案件の話を書けば具体になるが、依頼側に見られたらと思うと手が止まる。結論を先に書くと、**人事の副業の発信で書いてはいけないのは、「依頼側が特定される情報」「候補者に関わる情報」「本業の会社の情報」「契約の条件の具体」「成果や収入を保証するように見える表現」の五つです。この五つを避けたうえで残るのは、自分の判断の仕方と型の話で、発信が案件につながるのは、そこが書かれているときです。**迷ったら、案件の話を消して判断の仕方だけに戻すと、五つの線を越えません。事例として書く場合の粗くし方は[事例の書き方](/media/fukugyo-jirei-kakikata/)に、依頼側の名前を出す場合の許可の取り方は[クライアントに実績公開の許可を取る](/media/fukugyo-kyoka-toru/)に、発信の進め方は[SNS発信から案件につなげる](/media/fukugyo-sns-hasshin/)にまとめています。

## 書いてはいけない五つの領域

五つの領域は、それぞれ理由が違います。理由が分かると、境目の判断ができます。

| 領域 | 書いてはいけないもの | 理由 |
|---|---|---|
| 依頼側 | 会社名、担当者の名前、社内の事情、採用の内情、業界・規模・状況の組み合わせで特定される話 | 秘密保持の約束。契約の存在自体を開示しない約束のことも多い |
| 候補者 | 名前、経歴、選考の状況、やり取りの内容、「こんな候補者がいた」という話 | 個人情報。特定されなくても、候補者本人が読めば分かる |
| 本業 | 本業の会社名、本業の採用の内情、本業で作った成果物、同僚や上司の話 | 本業に対する情報の持ち出し。副業の許可とは別の問題になる |
| 契約の条件 | 合意した単価、稼働時間、契約の期間、依頼側と交わした条件の具体 | 依頼側との契約の情報。他の依頼側との条件の比較に使われる |
| 保証に見える表現 | 「採用を約束します」「〇か月で決まる」「月〇万円稼げる」など | 成果と収入は依頼側の条件と自分の稼働で変わり、保証できない。読む人に誤った期待を持たせる |

五つの要点は、「依頼側と候補者」が守秘、「本業」が持ち出し、「契約の条件」が信頼、「保証」が誤解、と理由が違うことです。理由が違うので、一つの線で判断しようとすると漏れます。投稿を書いたら、五つそれぞれで見直します。情報の種類ごとの線は[個人情報の扱い](/media/fukugyo-kojin-jouhou/)と[情報の取り扱いと端末の分離](/media/fukugyo-security/)にも書いています。

## 見落としやすい書き方

会社名や候補者の名前を書かないことは分かっていても、書き方によって五つの線を越えていることがあります。

| 領域 | 見落としやすい書き方 | なぜ越えているか |
|---|---|---|
| 依頼側 | 「今日は〇〇業界のクライアントと打ち合わせ」 | 業界と時期で、依頼側の担当者や同業の人には絞れる |
| 依頼側 | 「クライアントの人事が一人で、経営者が面接に出る会社」 | 体制の特徴は、業界と規模と組み合わさると特定される |
| 候補者 | 「今日面談した候補者が、こういう理由で辞退した」 | 候補者本人が読めば自分のことだと分かる。依頼側も分かる |
| 候補者 | 「スカウトの返信で、こんな面白い経歴の人がいた」 | 経歴が珍しいほど特定される |
| 本業 | 「本業でやっている採用の進め方を、副業でも使っている」と具体に書く | 本業の採用の進め方は本業の情報 |
| 契約の条件 | 「今の案件は時給〇〇円で週〇時間」 | 依頼側との合意した条件。他の依頼側が見れば比較の材料になる |
| 契約の条件 | 「〇〇さん（依頼側の担当者）と契約更新の話をした」 | 担当者の名前と契約の状況 |
| 保証 | 「私が入った案件は、全部〇か月以内に決まっています」 | 過去の事実でも、読む人には保証に見える。次の依頼側の期待を固定する |
| 保証 | 「人事の副業は、月〇万円は堅い」 | 収入の保証。読む人の条件で変わる |

見落としの要点は、「その日の出来事」を書くと越えやすいことです。「今日は〇〇と打ち合わせ」「今日の候補者が」という書き方は、時期と状況が具体になり、依頼側と候補者に近づきます。出来事ではなく、そこから取り出した判断の仕方を書くと、時期と状況が消え、線の内側に戻ります。

### エラベルの見解

相談で最も多い思い込みは、「依頼側の名前を出していないから、案件の話を書いても問題ない」というものです。実際には、依頼側の担当者は、名前が無くても自分たちの話だと分かります。分かったときに担当者が感じるのは、「この人は、うちのことを外で書く人だ」という警戒です。契約の違反かどうかより先に、その警戒が信頼を下げ、次の紹介や更新に響きます。

依頼側から見て安心できる発信は、案件の話が出てこない発信です。判断の仕方や型の話だけが書かれていて、「この人は依頼側の話を外に出さない」と読めることが、依頼側が発信を見て「頼みたい」と思う条件になります。エラベルでは、担当者の発信に依頼側や候補者の情報が含まれていると分かった場合、依頼側の信頼に関わるので、登録の前に見直しをお願いすることがあります。逆に、判断の仕方だけを書いている担当者の発信は、依頼側に提示するときの材料になっています。

## 書いてよいものとの線

五つを避けると、書けるものが無くなるように感じますが、残るものが発信の中心です。

| 書いてよいもの | 書き方 | 五つとの線 |
|---|---|---|
| 判断の仕方 | 「この条件のとき、自分はこう考える」 | 案件の出来事ではなく、そこから取り出した型 |
| 進め方の型 | 「スカウトの文面は、冒頭・中盤・結びをこう組む」 | 依頼側の情報を抜いた自分の成果物。帰属は契約書で確認 |
| 一般化した失敗 | 「面接官の時間を先に押さえないと、母集団があっても進まない」 | 特定の案件ではなく、複数の経験から取り出した教訓 |
| 単価や条件の「決め方」 | 「単価は時間×自分の稼働の上限で決めている」 | 合意した単価ではなく、決め方。[最初の1件の価格の決め方](/media/fukugyo-shoninka/) |
| 副業の続け方 | 稼働の管理、本業との切り分け、断り方 | 自分の運用の話で、依頼側と候補者は出てこない |
| 粗くした事例 | 業界・規模・状況を粗くし、判断と進め方を残したもの | [事例の書き方](/media/fukugyo-jirei-kakikata/)の手順で確かめたもの |
| 許可を取った実績 | 依頼側の書面の許可がある範囲 | 許可の範囲を超えない。[クライアントに実績公開の許可を取る](/media/fukugyo-kyoka-toru/) |

線の要点は、「出来事」と「そこから取り出した型」の違いです。出来事は依頼側と候補者に結びついていますが、型は自分のものです。出来事を書きたくなったら、「この出来事から、自分は何を決めるようになったか」に置き換えると、型になります。型の見せ方は[noteで実績を見せる](/media/fukugyo-note/)と[Xでの発信のしかた](/media/fukugyo-x-unyou/)に書いています。

## 投稿する前に確かめる手順

書いた投稿を出す前に、五つの領域ごとに確かめます。慣れるまでは、手順を紙に書いて横に置きます。

| 手順 | 確かめること |
|---|---|
| 一、依頼側の担当者が読んだら | 「うちのことだ」と分かるか。分かるなら、依頼側の情報が入っている。粗くするか消す |
| 二、候補者が読んだら | 「自分のことだ」と分かる人がいるか。一人でもいれば消す |
| 三、本業の上司が読んだら | 本業の情報が入っていると感じるか。感じるなら消す |
| 四、他の依頼側が読んだら | 条件の比較に使える情報が入っているか。入っていれば消す |
| 五、副業を始めたい人が読んだら | 成果や収入が保証されているように読めるか。読めるなら「場合による」と書き直すか消す |
| 六、出来事になっていないか | 「今日」「先日」「この案件で」が入っていれば、型に置き換える |

手順の要点は、「一つの投稿を五人の視点で読む」ことです。自分の視点だけでは、越えているかどうかが分かりません。依頼側の担当者、候補者、本業の上司、他の依頼側、副業を始めたい人の五人が読んだらどう感じるかを、順に考えます。慣れると、書く前にその視点で書けるようになります。

## 書いてしまった後の対処

線を越えた投稿を出してしまったことに、後で気づくことがあります。気づいたときの対処を決めておきます。

| 状況 | 対処 |
|---|---|
| 依頼側の情報を書いた | すぐに消す。依頼側の担当者に、消したことと経緯を伝える。伝えずに消すと、後で知られたときの信頼の損失が大きい |
| 候補者の情報を書いた | すぐに消す。依頼側に伝え、依頼側の判断に従う。候補者への連絡が要るかは依頼側と決める |
| 本業の情報を書いた | すぐに消す。本業の規定で報告が要るかを確認する。規定の解釈は専門家に |
| 契約の条件を書いた | すぐに消す。依頼側に伝えるかは、内容の重さで判断する。単価の具体を書いた場合は伝える |
| 保証に見える表現を書いた | 直すか消す。すでに読まれていれば、「場合による」と補足の投稿を出す |
| 保存や引用で残っている | 消しても残ることは受け入れ、以後の投稿で線を守る。残った分の対処は依頼側と相談する |

対処の要点は、「依頼側に伝える」ことです。消しただけで済ませたくなりますが、依頼側が後で知ると、書いたことより隠したことのほうが信頼を損ねます。伝えるときは、何を書き、いつ消し、今後どうするかを短く伝えます。依頼側との関係が続くかどうかは、伝え方で変わります。依頼側とのトラブルの整理は[トラブルへの対処](/media/fukugyo-trouble/)に書いています。

## 実名でも仮名でも変わらない理由

仮名で発信していれば、案件の話を書いても大丈夫だと思われがちですが、五つの線は名前に関係なく同じです。

| 領域 | 仮名でも越える理由 |
|---|---|
| 依頼側 | 依頼側の担当者は、内容で自分たちの話だと分かる。書き手が誰かは関係ない |
| 候補者 | 候補者は、内容で自分のことだと分かる。書き手が誰かは関係ない |
| 本業 | 本業の情報は、誰が書いても持ち出し。仮名でも、本業の関係者が内容で気づくことがある |
| 契約の条件 | 条件の具体は、仮名でも依頼側が読めば分かる |
| 保証 | 読む人が誤った期待を持つのは、書き手が誰でも同じ |

変わらない要点は、「特定されるのは書き手ではなく、書かれた側」だということです。仮名は書き手を隠しますが、依頼側と候補者を隠しません。仮名で発信する意味は、本業の関係者に書き手が見つかりにくいことであって、書ける内容が広がることではありません。名前の判断は[実名で発信するか](/media/fukugyo-honmyou-hasshin/)に整理しています。

### エラベルの見解

担当する側から見ると、発信で線を越える人の多くは、悪気があるのではなく、「書くことが無い」と感じて出来事に手を伸ばしています。判断の仕方や型は、自分にとっては当たり前で、書くほどのことではないと思い、代わりに「今日こんなことがあった」を書きます。ところが、依頼側が読みたいのは、その当たり前の判断のほうです。

順番として、発信を始める前に、自分の判断の仕方を十個ほど書き出しておくと、出来事に手を伸ばさずに済みます。「求人票は要件を三つに絞る」「面接の枠を先に固定する」「スカウトの文面の冒頭は会社の状況から」のような、自分が案件で繰り返している判断です。それを一つずつ発信にすれば、五つの線を越えずに、依頼側が読みたいものになります。エラベルでは、担当者の経歴を整えるときに、この「繰り返している判断」を聞き出して書いています。発信の種と、経歴の中身は同じものです。

## まとめ

- 書いてはいけないのは**依頼側が特定される情報・候補者に関わる情報・本業の会社の情報・契約の条件の具体・保証に見える表現**の五つ
- 理由は**守秘・個人情報・持ち出し・信頼・誤解**と違うので、一つの線で判断せず、五つそれぞれで見直す
- 見落とすのは**「今日」「先日」の出来事**。時期と状況が具体になり、依頼側と候補者に近づく
- 書いてよいのは**判断の仕方・進め方の型・一般化した失敗・決め方・続け方・粗くした事例・許可を取った実績**
- 出す前に**依頼側の担当者・候補者・本業の上司・他の依頼側・副業を始めたい人**の五人の視点で読む
- 書いてしまったら**すぐ消し、依頼側に伝える**。仮名でも線は同じで、特定されるのは書き手ではなく書かれた側

## よくある質問

### 依頼側の担当者から「うちのことを書いてくれてよい」と言われました

口頭の了承だけで書くことは避け、何を・どこに・いつまで書くかを文面にして、返事を書面で残してから書きます。担当者が了承しても、会社の広報や法務が別の判断をすることがあります。手順は[クライアントに実績公開の許可を取る](/media/fukugyo-kyoka-toru/)に書いています。許可があっても、候補者に関わる情報は対象外で、書きません。

### 「採用がうまくいった」という事実だけなら、書いてもよいですか

依頼側が特定されない形で、数字を出さず、状態の変化として書くなら、多くの場合は線の内側です。「日程の理由での辞退が減った」のように、自分の進め方の結果として書きます。「〇か月で〇名採用」は依頼側の情報で、許可が要ります。「うまくいった」を強調しすぎると、保証に見える表現に近づくので、「この状況では」と条件を添えます。

### 法令に関わる話（労働法、職業安定法など）は書いてよいですか

一般的な整理として書くことはできますが、解釈を断定することは避けます。「一般に〜と整理されています」「個別の判断は専門家に確認してください」を添え、自分の案件で起きた法令に関わる出来事は、依頼側の情報になるので書きません。法令に関わる部分は、書く前に社会保険労務士や弁護士などの専門家に確認するほうが安全です。

一件目の案件を終えたとき、次の案件のために「依頼側からの評価」を残しておきたいと考える人は多い。ただ、依頼側に「レビューを書いてください」と頼むと、「良い方でした」「助かりました」といった、次の依頼側が判断に使えない言葉が返ってきます。逆に具体的に書いてもらうと、依頼側の社名や採用の内情が入り、外に出せません。結論を先に書くと、**レビューは「何を頼んで」「何が変わって」「どう働く人か」の三点が入った形でもらい、依頼側の社名と数値を一般化して、登録先・発信・面談で使う**と、次の依頼側の判断材料になります。もらい方と使い方の線を先に決めておけば、依頼側にも負担をかけずに済みます。実績の示し方全般は[実績の示し方](/media/fukugyo-jisseki-shimeshikata/)に、実績を積む考え方は[実績の積み上げ方](/media/fukugyo-jisseki-tsumu/)にまとめています。

## 使えるレビューと、使えないレビュー

次の依頼側が読んで判断に使えるかどうかで、レビューは分かれます。

| 使えない | 使える | 違い |
|---|---|---|
| 「良い方でした」 | 「スカウトの文面と一次返信を任せて、返信までの日数が短くなった」 | 何を頼んで、何が変わったかがある |
| 「丁寧に対応してくれました」 | 「決めた曜日に稼働し、翌朝には下書きが届いていた」 | どう働く人かが、行動で書かれている |
| 「また頼みたいです」 | 「範囲外の相談は区切りで整理してくれて、こちらも判断しやすかった」 | 範囲の守り方が書かれている |
| 「〇〇社の採用で、応募が月に五十件から百件に」 | 「中小の事業会社で、応募数が二倍近くに」 | 社名と数値が一般化されている |
| 「〇〇さん（担当者名）が言うには」 | 「人事担当の方から」 | 個人名が無い |

違いの要点は、「三点（何を・何が変わった・どう働く）と、一般化」の両方が要ることです。三点が無いと判断に使えず、一般化が無いと外に出せません。

## 頼む時期と頼み方

レビューは、依頼側が良く思っている瞬間の直後に、負担の少ない形で頼みます。番号付きで整理します。

1. **時期は、数で示した区切りの直後か、引き継ぎを終えた直後。** [紹介につなげる](/media/fukugyo-shoukai-renkei/)と同じ時期。途中や数が動いていないときは頼まない。
2. **三点を、質問の形で渡す。** 「お手数ですが、三つだけ教えてください。何をお任せいただいたか、何が変わったか、働き方で良かった点」。白紙で「レビューを」と頼まない。
3. **短くてよいと伝える。** 「各一〜二行で構いません」。長く書かせない。
4. **使い方を先に伝える。** 「次の案件で、登録先のプロフィールや面談で、社名を伏せて使わせていただきます」。使い方が分かれば、依頼側は安心して書ける。
5. **書面（メールかチャット）でもらう。** 口頭のレビューは、あとで使えない。
6. **もらったら、一般化した文案を作り、依頼側に見せる。** 「この形で使います」。依頼側が了解した形だけ使う。
7. **一度だけ頼む。** 返事が無ければ、催促しない。
8. **お礼を伝える。** 金銭ではなく、言葉で。

頼み方の要点は、「二で、質問の形で渡す」ことです。白紙で頼むと、依頼側は何を書けばよいか分からず、「良い方でした」になります。三つの質問なら、答えるだけで使える形になります。

### エラベルの見解

登録の相談で多いのは、「レビューをもらったが、登録先に載せてよいか分からず、使っていない」という話です。もらったレビューを見ると、依頼側の社名と、応募数の具体的な数値が入っています。そのまま載せると、依頼側の採用の内情が出ます。載せられないまま、レビューが手元にあるだけ。もらい方の時点で、使い方と一般化の線を決めていなかったことが原因です。

見ていて差がつくのは、「一般化した文案を、依頼側に見せて了解を取っているか」です。「中小の事業会社で、スカウトの文面と一次返信を担当。応募から返信までの日数が大きく短縮」という形にして、「この形で使います」と見せる。依頼側は、社名も数値も出ないので了解し、自分は安心して使えます。エラベルの登録でも、レビューを一般化して載せている人は、依頼側から「実際に頼んだ会社の声がある」と受け取られ、二件目の面談が早く進んでいます。

## 一般化の線

レビューを外で使うときに、消すものと残すものを整理します。

| 消す | 残す | 例 |
|---|---|---|
| 依頼側の社名 | 業種と規模 | 「中小の事業会社」「従業員数十名のIT企業」 |
| 具体的な数値 | 変化の方向と程度 | 「五日から一日」→「大きく短縮」「応募が二倍近くに」 |
| 個人名（担当、判断する人） | 役割名 | 「人事担当の方」「経営者の方」 |
| 採用していた職種（特定につながる場合） | 職種の種類 | 「営業職」「技術職」 |
| 時期（特定につながる場合） | 期間の長さ | 「三か月間」 |
| 依頼側の内情（予算、社内の事情） | 業務の範囲 | 「スカウトの文面と一次返信」 |
| 候補者の情報 | — | 一切残さない |

線の要点は、「業種と規模と数値がそろうと、特定できる」ことです。「東京の従業員数十名の医療機器商社で、応募が月五十件から百件」は、業界の人が読めば特定できることがあります。数値を程度に変え、業種を広くすれば、特定できなくなります。迷ったら、より広く一般化します。[情報の取り扱いと端末の分離](/media/fukugyo-security/)を参照してください。

## 使い方

一般化したレビューを、どこでどう使うかを整理します。

| 場所 | 使い方 | 注意 |
|---|---|---|
| 登録先のプロフィール | 経験の欄の下に、一件分を三行で | 登録先の規約で、第三者の声の掲載が制限されていないか確認 |
| 面談 | 「前の案件では、こういう評価をいただきました」と口頭で。求められれば一般化した文面を見せる | 依頼側の社名を聞かれても答えない |
| 発信のプロフィール | 一行で。「中小の事業会社で、返信の日数を大きく短縮」 | 具体的な数値は出さない |
| 型と手順を書いた記事 | 記事の末尾に、「この型を使った案件で、依頼側からこういう評価」と一行 | 事例ではなく、型の効果として。[noteで実績を見せる](/media/fukugyo-note/) |
| 職務経歴書 | 案件の項目に、一般化したレビューの要点を一行 | [副業用の職務経歴書](/media/fukugyo-shokumu-keirekisho/) |

使い方の要点は、「面談で社名を聞かれても答えない」ことです。次の依頼側が「どこの会社ですか」と聞くことはありますが、答えると前の依頼側の情報を出すことになります。「守秘のため社名は伏せていますが、業種と規模はこうです」と答えれば、次の依頼側は「この人は自社の情報も守る」と受け取ります。

## レビューにまつわる失敗

レビューで起きやすい失敗を整理します。

| 失敗 | 起きる構造 | 直し方 |
|---|---|---|
| 白紙で「レビューを」と頼む | 何を書いてほしいか決めていない | 三つの質問の形で |
| 早すぎる時期に頼む | 案件の途中で | 数で示した直後か、引き継ぎ後 |
| 社名と数値をそのまま載せる | 具体的なほうが効くと思う | 一般化。業種と規模と程度に |
| 依頼側に文案を見せずに使う | 了解を取っていない | 一般化した文案を見せ、了解した形だけ |
| 口頭でもらって終わる | 書面で頼みにくい | メールかチャットで |
| 面談で社名を答える | 聞かれたので | 守秘を理由に答えない。答えないことが信用になる |
| 長いレビューを求める | 丁寧なほうが良いと思う | 各一〜二行 |
| 何度も催促する | 返事が来ない | 一度だけ。来なければ諦める |
| レビューが無いと次に進めないと思う | 実績はレビューだけと思う | 型と数と手順で示せる。レビューは補助 |
| 候補者の情報が混ざる | 依頼側が具体的に書く | 候補者の話は一切消す |

失敗の要点は、「レビューは補助」ということです。レビューが無くても、型と数と手順で実績は示せます。レビューに頼りすぎると、依頼側への頼み方が重くなります。

### エラベルの見解

担当する側として登録した人の話を聞くと、レビューを効果的に使っている人は、レビューを「依頼側の言葉で書かれた、自分の働き方の説明」として扱っています。自分で「範囲を守ります」と書くより、依頼側が「範囲外の相談は区切りで整理してくれた」と書いたほうが、次の依頼側には伝わる。自分の主張ではなく、第三者の観察として使うのが、レビューの価値です。

依頼側から見ると、レビューを頼まれること自体は負担ですが、三つの質問に一〜二行で答えるだけなら応じやすく、一般化した文案を見せてもらえれば安心です。エラベルは、範囲と時間を書いた登録に、条件が合う案件のときだけご連絡する窓口ですが、登録に一般化したレビューが添えられていると、依頼側が判断しやすく、面談が短くなります。レビューは、頼み方と一般化の線を先に決めて、依頼側に負担をかけずにもらう。その型を持っていただくことをお勧めしています。

## まとめ

- 使えるレビューは**何を頼んで・何が変わって・どう働く人か**の三点が入り、**社名と数値が一般化**されているもの
- 頼む時期は**数で示した直後か、引き継ぎを終えた直後**。頼み方は**三つの質問の形で、短くてよいと伝え、使い方を先に伝え、書面で、一度だけ**
- 一般化は**社名→業種と規模、数値→程度、個人名→役割名、内情→業務の範囲、候補者→消す**。業種と規模と数値がそろうと特定できる
- 使う場所は**登録先・面談・発信・型の記事・職務経歴書**。面談で社名を聞かれても答えない
- **一般化した文案を依頼側に見せて、了解した形だけ使う**
- レビューは**補助**。型と数と手順で実績は示せる

## よくある質問

### 依頼側が「レビューは会社の規程で出せない」と言います

無理に頼みません。代わりに、自分の側で「何を担当し、何が変わったか」を一般化して書き、「この形で、社名を伏せて実績として書いてよいか」だけを確認します。依頼側の言葉ではなく自分の言葉になりますが、依頼側の了解を得た実績として使えます。それも難しい場合は、型と手順（一般化したもの）と、稼働の記録の数（業務の種類と数）で実績を示します。レビューが無くても、実績は示せます。

### 具体的な数値が無いと、説得力が無い気がします

「五日から一日」より「大きく短縮」のほうが弱く見えますが、次の依頼側が知りたいのは、数値の正確さではなく、「この人に頼むと、こういう種類の変化が起きるか」です。「応募から返信までの日数が大きく短縮し、面接の設定が増えた」で、種類は伝わります。具体的な数値は、面談で「前の案件では、程度としてはこのくらい」と口頭で補えば足り、書面に残す必要はありません。数値を残すと、前の依頼側の特定につながるので、程度で書くほうが、守秘の面でも次の依頼側の信用の面でも良い結果になります。

### レビューをもらったあと、依頼側との関係が気まずくなりました

頼み方が重かったか、時期が悪かったか、催促したかのどれかです。まず、レビューの話をそれ以上しないこと。もらったものを使うかどうかより、関係を戻すことが先です。区切りで数を示し、型を残し、引き継ぎを丁寧にする、という通常の動きに戻れば、関係は戻ります。レビューは、関係が良いときに軽く頼むもので、関係を悪くしてまで取るものではありません。次の案件では、頼む時期と頼み方の型を守ってください。

依頼側から「もう少しこまめに報告してほしい」と言われた。一方で、別の案件では「そんなに細かく送ってくれなくていい」と言われたことがある。どのくらいの頻度が適切なのかが、案件ごとに違って分からない。結論を先に書くと、**報告の頻度は、一つに決めるのではなく、「候補者の動きは即時」「進捗は週に一度」「稼働と成果は月に一度」の三層に分けて決めます。頻度が合わないと感じるのは、この三層が混ざって、候補者の動きを週まで溜めたり、稼働の話を毎日送ったりしているからです。**三層の周期は、自分の都合ではなく、依頼側の担当者が社内で説明する周期（面接官への連絡、上長への報告、経理の締め）に合わせます。報告の中身は[報告のしかた](/media/fukugyo-houkoku/)に、月次の報告の形は[稼働報告のフォーマット](/media/fukugyo-kadou-houkoku/)に、定例の進め方は[定例会の進め方](/media/fukugyo-teirei-shinkou/)にまとめています。

## 頻度が合わないと起きること

報告の頻度は、多くても少なくても、依頼側の担当者に負担をかけます。

| 頻度のずれ | 依頼側の担当者に起きること |
|---|---|
| 候補者の動きを週次まで溜める | 候補者からの返信や辞退を、担当者が数日後に知る。面接官への連絡が遅れ、候補者を待たせる |
| 稼働の話を毎日送る | 担当者は毎日読むことになり、読まなくなる。本当に要る報告も埋もれる |
| 進捗の報告が無い | 担当者は「動いているのか」が分からず、自分から聞きに来る。聞きに来る時点で、信頼が下がっている |
| 月次の報告が無い | 担当者が上長に説明する材料が無く、経理は請求の根拠を求める |
| 頻度が毎回違う | 担当者は「今週は来るのか」と気にする。予定に組み込めない |
| 依頼側の周期と合っていない | 担当者が上長に報告する前日に報告が来ない。担当者は自分でまとめ直す |

起きることの要点は、「担当者が自分から聞きに来る状態を作らない」ことです。担当者が「あの候補者はどうなった」「今月は動いているか」と聞きに来るのは、報告の頻度が担当者の必要に合っていない合図です。聞かれる前に届く頻度が、その案件の適切な頻度です。担当者の側の周期は[外部の立場だからできること](/media/fukugyo-gaibu-tachiba/)に書いた社内の構造から見えます。

## 三層に分ける

報告を一つの頻度で出そうとすると、どこかが合いません。三層に分けると、それぞれに合った頻度が決まります。

| 層 | 内容 | 頻度 | 形 | 読む人 |
|---|---|---|---|---|
| 候補者の動き | 返信、辞退、日程の確定、面接の結果待ち、内定者からの連絡 | 起きたら即時（副業の枠の中で、その日のうちに） | チャットかATSの記録。一行 | 担当者、面接官 |
| 進捗 | 今週やったこと、来週やること、止まっていること、確認したいこと | 週に一度、決まった曜日 | 定例か、短い文面 | 担当者 |
| 稼働と成果 | 工程別の時間、状態の変化、次の月の見込み、請求 | 月に一度、締め日に合わせて | 稼働報告の一枚 | 担当者、上長、経理 |

三層の要点は、「候補者の動きは溜めない」ことです。候補者の返信や辞退は、担当者が面接官や社内に伝える必要があり、数日溜まると候補者を待たせます。ただし、副業は本業の合間なので、「即時」は本業の時間中ではなく、副業の枠の中でその日のうちに、が現実的な線です。この線は最初に依頼側と決めておきます。候補者への対応の速さの期待は[候補者への対応で気をつけること](/media/fukugyo-kouhosha-taiou/)に、稼働の枠の置き方は[複数案件のスケジュール管理](/media/fukugyo-fukusuu-kanri/)に整理しています。

### エラベルの見解

相談で最も多い思い込みは、「報告は多いほど安心してもらえる」というものです。実際には、依頼側の担当者は、報告を読む時間が限られていて、毎日届く報告は読まなくなります。読まなくなった後に、候補者の辞退のような本当に要る報告が同じ経路で届くと、埋もれます。報告の量ではなく、「要るものが要るときに届く」ことが、担当者の安心につながります。

見ていて差がつくのは、三層を分けて、それぞれの経路と頻度を担当者に伝えているかです。「候補者の動きはチャットで当日中、進捗は毎週〇曜に短く、稼働と成果は月末に一枚」と最初に伝えている担当者は、依頼側から「報告の形が分かりやすい」と言われ、担当者が聞きに来ることがほとんどありません。伝えていない担当者は、同じ量の報告をしていても、「こまめに」と「細かすぎる」の両方を言われています。エラベルでは、担当者が依頼側と最初に報告の三層と頻度を合意する形をお願いしています。頻度は、合意して初めて「適切」になります。

## 依頼側の担当者の周期に合わせる

三層の周期は、自分の副業の枠だけで決めず、依頼側の担当者が社内で動く周期に合わせます。

| 担当者の周期 | 合わせる層 | 合わせ方 |
|---|---|---|
| 面接官への連絡（随時） | 候補者の動き | 面接官が次に動く前に届くように。面接の前日までに候補者の状況を |
| 社内の採用の定例（週に一度が多い） | 進捗 | 担当者の社内の定例の前日か当日の朝に、進捗を出す。担当者はそれを社内で使える |
| 上長への月次の報告 | 稼働と成果 | 上長への報告の数日前に、稼働報告を出す。担当者が上長向けにまとめ直す時間を残す |
| 経理の締め日 | 稼働と請求 | 締め日の数日前に、請求と一緒に。[請求のタイミング](/media/fukugyo-seikyuu-timing/) |
| 依頼側の採用の山 | 候補者の動き | 山の時期は、候補者の動きの報告を密にし、進捗の報告は短くする |

合わせる要点は、「担当者の社内の定例の前日に、進捗を出す」ことです。担当者は社内の定例で採用の進捗を説明していて、その直前に外部の担当者から進捗が届けば、そのまま使えます。定例の翌日に届くと、担当者は一週間古い情報で説明したことになります。担当者の社内の周期は、最初の打ち合わせで「社内で採用の話をする定例はいつですか」「上長に報告する時期はいつですか」と聞いておきます。聞く項目は[初回打ち合わせの進め方](/media/fukugyo-shodan/)に書いています。

## 契約の形と案件の段階で変わる頻度

三層の基本は同じでも、契約の形と案件の段階で、重みが変わります。

| 状況 | 変わること |
|---|---|
| 時間単価の契約 | 稼働の層が重い。週の進捗にも、その週の稼働の目安を一行入れると、月末に驚かれない |
| 月額固定の契約 | 進捗の層が重い。「今月も動いている」ことが、週の進捗で伝わる |
| 成果報酬の契約 | 候補者の動きの層が重い。成果の定義に近づく候補者の動きを、密に共有する |
| 案件の最初の数週間 | 進捗を週に二回にするか、毎日短く。担当者がまだ外部の担当者の動き方を知らない時期 |
| 型が整った後 | 進捗を隔週にできることがある。担当者に「頻度を落としてよいか」を確認してから |
| 依頼側の採用の山 | 候補者の動きを密に。進捗と稼働の報告は短く |
| 依頼側の担当者が替わった直後 | 最初の数週間と同じ。新任が動き方を知るまで、進捗を密に |
| 自分の稼働が下がる時期 | 進捗の頻度は落とさない。「今週は稼働が少なかった」も進捗として出す。止まっていると思われない |

変わる要点は、「案件の最初と、担当者の交代の直後は密に」です。この時期は、担当者が外部の担当者の動き方を知らず、報告が無いと不安になります。数週間、密に出して「この人はこう動く」と分かってもらった後、通常の頻度に戻します。案件の最初の進め方は[案件の最初の時期の進め方](/media/fukugyo-shoki-90nichi/)に、担当者の交代への備えは[いつ辞めても困らない状態を作る](/media/fukugyo-hikitsugi-junbi/)に整理しています。

## 頻度を最初に合意する項目

報告の頻度は、契約の最初に依頼側と合意しておくと、途中で「こまめに」「細かすぎる」と言われることが減ります。

| 合意する項目 | 内容 |
|---|---|
| 候補者の動きの経路と時間 | チャットかATSか。「副業の枠の中で当日中」の線。本業の時間中は反応できないことを伝える |
| 進捗の曜日と形 | 「毎週〇曜に、定例かメールで」。担当者の社内の定例に合わせる |
| 稼働と成果の日と形 | 「毎月〇日に、一枚の稼働報告と請求書を」。締め日と上長への報告の時期に合わせる |
| 緊急の連絡の経路 | 候補者の辞退や依頼側の急な依頼のように、通常の層に収まらないものの経路 |
| 返信を求めるかどうか | 進捗の報告に返信は要らない、確認したいことがあるときだけ返してほしい、など |
| 頻度を見直す時期 | 「最初の一か月は密に、その後は通常に。三か月目の定例で見直す」 |

合意の要点は、「返信を求めるかどうか」を決めることです。進捗の報告に毎回「確認しました」の返信を求めると、担当者の負担になり、返信が来なくなったときに「読まれていない」と不安になります。「返信は不要。確認したいことがあるときだけ、その旨を書くので返してほしい」と決めておけば、担当者は読むだけで済み、自分も返信の有無で不安になりません。合意の仕方は[期待値のすり合わせ](/media/fukugyo-kitai-chousei/)に書いています。

## 多すぎる・少なすぎるの見分け方

合意した頻度でも、途中で合わなくなることがあります。合図で見分けます。

| 合図 | 意味 | 直し方 |
|---|---|---|
| 担当者が「あの候補者は」と聞きに来る | 候補者の動きの層が遅い | 候補者の動きを当日中に。ATSの記録を担当者が見られる形に |
| 担当者が「今どうなっていますか」と聞きに来る | 進捗の層が無いか遅い | 週の進捗を、担当者の定例の前日に |
| 担当者の返信が無くなった | 進捗の報告が多すぎるか、長すぎる | 短くする。頻度を落とすか、担当者に「読む負担になっていないか」を聞く |
| 担当者から「まとめて教えてください」と言われた | 候補者の動きの報告が細かすぎる | 候補者の動きのうち、面接官に関わるものだけ即時にし、他は週の進捗に |
| 上長への報告の前に担当者から催促が来る | 稼働と成果の層が、上長への報告の周期と合っていない | 上長への報告の数日前に出す形に変える |
| 経理から請求の根拠を聞かれる | 稼働の報告が請求と別に届いている | 稼働報告と請求を同じ日に |

見分けの要点は、「担当者が聞きに来たら、その層が遅い」「担当者の返信が無くなったら、その層が多い」ということです。担当者の行動が、頻度のずれを示します。担当者に直接「頻度はこれでよいですか」と聞くこともできますが、担当者は「大丈夫です」と答えがちなので、行動で見るほうが正確です。

## 途中で頻度を直す節目

頻度は固定ではなく、節目で見直します。

| 節目 | 見直すこと |
|---|---|
| 最初の一か月が過ぎたとき | 密にしていた進捗を、通常の頻度に戻すか。担当者に「頻度を通常に戻してよいか」を確認 |
| 型が整ったとき | 進捗を隔週にできるか。候補者の動きは変えない |
| 依頼側の採用の山に入るとき | 候補者の動きを密に、進捗と稼働を短く。山が過ぎたら戻す |
| 契約の更新のとき | 一期分の報告の頻度を振り返り、次の期の頻度を決める。[更新時の条件見直し](/media/fukugyo-keiyaku-koushin-koushou/) |
| 担当者が替わったとき | 新任に三層と頻度を改めて伝え、最初の数週間は密に |
| 自分の稼働が変わるとき | 稼働が下がっても、進捗の頻度は落とさない。稼働が上がったら、候補者の動きの報告が増えるので、経路を確認 |

節目の要点は、「頻度を落とすときは、担当者に確認してから」です。自分の判断で進捗を隔週にすると、担当者は「報告が減った」と感じます。「型が整ったので、進捗は隔週でもよいでしょうか」と聞き、担当者が「はい」と言ってから落とせば、担当者は減ったのではなく、合意して変えたと受け取ります。

### エラベルの見解

担当する側から見ると、報告の頻度で困っていない人は、頻度を自分で決めていません。依頼側の担当者の社内の周期を最初に聞き、それに三層を合わせ、合意して始め、担当者の行動（聞きに来る、返信が無くなる）で調整しています。困っている人は、自分の副業の枠だけで頻度を決め、担当者の周期と合わず、「こまめに」「細かすぎる」の両方を言われています。頻度は、自分の側ではなく、担当者の側にあります。

順番として、最初の打ち合わせで担当者の社内の周期を聞き、三層の経路と頻度を合意し、最初の一か月は密に、通常の頻度に戻すときは確認し、担当者の行動で調整し、節目で見直す。この順番で、報告の頻度は「適切」になります。エラベルでは、依頼側と担当者の契約の際に、報告の三層と頻度を最初に整える形を取っていて、頻度をめぐる行き違いは、整えている案件ではほとんど起きていません。報告の頻度は、担当者の安心の頻度です。

## まとめ

- 報告は**候補者の動きは即時・進捗は週に一度・稼働と成果は月に一度**の三層で決める。一つの頻度にしない
- 頻度が合わないと**担当者が聞きに来るか、読まなくなる**。聞かれる前に届く頻度が適切
- **候補者の動きは溜めない**。ただし「即時」は副業の枠の中で当日中、と線を決める
- 周期は**担当者の社内の定例・上長への報告・経理の締め**に合わせる。進捗は担当者の定例の前日に
- **案件の最初と担当者の交代直後は密に**。型が整ったら、確認してから落とす
- 最初に**経路と時間・曜日と形・日と形・緊急の経路・返信の要否・見直す時期**を合意する
- **聞きに来たら遅い、返信が無くなったら多い**。担当者の行動で見分け、節目で直す

## よくある質問

### 本業の時間中に候補者から返信が来ました。「即時」に報告できません

「即時」は、副業の枠の中で当日中、が線です。本業の時間中に副業の対応をすることは避けるべきなので、その日の副業の枠で対応し、報告します。この線は最初に依頼側と合意しておき、「本業の時間中は反応できません。当日の夜までに対応します」と伝えておけば、依頼側は数時間の遅れを想定しています。候補者にも、最初の連絡で「返信は当日中か翌日になります」と伝えておけば、待たせている感覚になりません。

### 担当者が「報告は要らない、結果だけ教えて」と言います

担当者がそう言っても、進捗の層は短く出し続けます。「結果だけ」と言う担当者は、結果が出るまでの間に「動いているのか」と不安になり、そのときに聞きに来ます。週に一度、数行の進捗を「返信不要」で送っておけば、担当者は読むだけで済み、不安にもなりません。担当者の「要らない」は、長い報告が要らないという意味であることが多く、短い報告まで要らないという意味ではないことがほとんどです。

### 複数の案件で、報告の曜日や日が重なります

案件ごとに担当者の周期が違うので、報告の日も案件ごとに違って構いません。重なる場合は、自分の側で前倒しして分けます。「A社は月曜、B社は水曜」のように、担当者の社内の定例に合わせつつ、自分のまとまった枠に入る形にします。締め日と定例と報告の日を一枚に並べると、重なりが見えます。並べ方は[複数案件のスケジュール管理](/media/fukugyo-fukusuu-kanri/)に整理しています。

SIer業界の会社が採用代行を検討するとき、動機は「案件が取れているのに人が足りない」であることが多い。ただ、SIerの採用は、IT・Web業界の自社開発の会社とも、他の業界とも違う難しさがあります。同じ「SE」でも、上流の要件定義から下流のテストまで役割の幅が広く、常駐か持ち帰りかで働き方が違い、候補者の側は「SIerから自社開発へ」を考えている層と重なり、案件の受注に合わせて必要な人数と時期が動く。結論を先に書くと、**SIer業界の採用代行は、母集団形成・一次対応・日程調整・記録は外に出せる一方、役割の決定（どの工程を担う人か）・案件との照合・条件の判断は社内に残さないと、採れても案件に合いません。**代行に出す前に、三つの難しさを自社の状況で分解し、工程ごとに「任せる・残す」を決めることが、代行が機能する条件です。IT・Web業界との違いは[IT・Web業界の採用代行](/media/rpo-it-rpo/)に、職種ごとの切り分けは[プロジェクトマネージャー採用を代行に出す判断基準](/media/rpo-pjm-rpo/)や[インフラエンジニア採用を代行に出す判断基準](/media/rpo-infra-engineer-rpo/)に書いています。ここでは、SIer業界で共通する切り分けに絞ります。

## SIer業界の採用が難しい三つの理由

| 難しさ | 中身 | 代行への影響 |
|---|---|---|
| 役割の幅が広い | 同じ「SE」でも、要件定義・設計・実装・テスト・運用のどこを担うか、常駐か持ち帰りか、で仕事が違う | 「SE」の要件では対象が絞れない。担う工程で要件を切る必要がある |
| 候補者の層が「SIerからの転職」と重なる | SIerで働く人の一部は、自社開発やコンサルへの転職を考えている。同業のSIerに転職する動機を、文面で示す必要がある | 「SIerだから」の訴求では返信が来ない。役割と案件の実態で動く理由を作る |
| 人数と時期が案件で動く | 受注が決まってから急いで採る。要る人数と時期が事業の都合で変わる | 急ぐほど、要件が曖昧なまま募集が始まる。計画と紐づかない採用になる |

三つのうち、代行で解決できるのは母集団形成と速さで、役割の切り分けと案件との照合は社内の関わりが要ります。

## 工程ごとの「任せられる・残す」

| 工程 | 任せられるか | 理由 |
|---|---|---|
| 役割の決定（どの工程を担う人か、常駐か持ち帰りか） | 残す | 案件と体制で決まる。社内の責任者が決める |
| 採用要件の言葉への整理 | 一緒に | 役割から「担った工程の言葉」に整える。代行が整え、社内が確認 |
| 母集団形成（媒体・スカウト） | 任せられる | 役割ごとの検索と文面の型があれば外で回せる |
| 一次対応（返信・日程） | 任せられる | 速さが要る工程 |
| 書類の一次確認 | 一部任せられる | 「担った工程」の照合は外で。案件との適合は社内 |
| 案件との照合（この人はどの案件に入れるか） | 残す | 社内の責任者にしか判断できない |
| 技術と経験の見極め（面接） | 残す | 社内の技術者かPM |
| 条件の判断 | 残す | 会社の判断 |
| 記録と報告 | 任せられる | 一覧と週次の一枚 |

「案件との照合」は、SIer業界に特有の残す工程です。採れても案件に入れなければ、稼働しない期間が出ます。

### エラベルの見解

SIer業界で多くの会社が見落とすのは、「SEを採る」を「どの工程を担うSEを、どの案件のために採るか」に分けることです。「SE経験三年以上」で募集し、代行がそのまま検索すると、テストと運用が中心だった人と、要件定義を担ってきた人が同じ一覧に並び、面接で「案件に合わない」となります。「〇〇の案件で、要件定義から基本設計までを担う人」「〇〇の常駐先で、運用と改修を担う人」と、役割と案件で要件を切ると、検索も文面も面接も揃います。エラベルで担当者を選ぶ企業には、「いま採りたいSEは、どの工程を、どの案件で担う人ですか」を、私たちから先に聞いています。答えが「いろいろできる人」なら、代行の前に役割の切り分けが要ります。要件の整理の型は[採用要件の定義の進め方](/media/rpo-task-youken-teigi-susumekata/)に書いています。

## 代行に出す前に社内で確認すること

| 確認 | 中身 |
|---|---|
| 役割を決める人がいるか | 「どの工程を担う人か」「常駐か持ち帰りか」を、案件と体制から決められる責任者 |
| 案件との照合を誰がするか | 採った人をどの案件に入れるかを決める人。稼働しない期間を作らない |
| 「SIerに転職する理由」を語れるか | 候補者の「動く理由」に対応する実態（上流に関われる、持ち帰りの比率、扱う規模）を、いまうまくやっている人の言葉で |
| 面接の枠 | 技術者かPMの面接の枠を、週に決まった数出せるか |
| 条件の幅 | 年収の幅と働き方（常駐先、リモートの可否）を、先に伝えてよいか |
| 記録の形 | 一覧と記録が社内の環境にあるか |

「SIerに転職する理由」は、SIer業界の会社が最も答えにくい問いです。答えが無いまま代行にスカウトを任せると、返信が来ません。動く理由の作り方は[自社紹介はどこまで書くか](/media/scout-kaisha-shoukai/)に書いています。

## 役割ごとに代行の型が違う

| 役割 | 代行に向く工程 | 社内に残す度合い |
|---|---|---|
| 上流（要件定義・PM） | 母集団形成（スカウト中心。対象が少ない） | 要件の言葉が特に具体である必要。案件との照合が重い |
| 設計・実装 | 母集団形成、一次対応 | 技術の見極めは社内 |
| 運用・保守・常駐 | 掲載型の母集団形成、一次対応 | 常駐先の条件を先に。働き方の実態を求人票に |
| インフラ | 母集団形成（スカウト中心） | 要件の言葉が具体である必要 |
| 若手・未経験 | 掲載型と学校経由の母集団形成 | 育てる体制が先 |

「SIerの採用に強い代行」でも、役割ごとの型を持っているかは別です。上流と運用では、経路も文面も違います。

## 代行を選ぶときの確認項目

| 確認 | 聞き方 |
|---|---|
| 役割ごとの型があるか | 「上流のPMと、運用の常駐SEで、検索条件と文面をどう変えますか」 |
| 担当者の経歴 | 「担当する方は、SIer業界のどの役割の採用を、どの工程で担った経験がありますか」 |
| 「SIerに転職する理由」の作り方 | 「候補者がSIerからSIerに動く理由を、御社の実態からどう作りますか」 |
| 案件との照合の分担 | 「採った人をどの案件に入れるかは、社内で決めます。その前提で、どこまで任せられますか」 |
| 返事の速さと記録の置き場所 | 「候補者への返事は何営業日以内か。記録はどこに置くか」 |
| 費用の構造 | 「月額に含まれる工程と含まれない工程は」 |

費用は、含まれる工程で変わり、金額の相場を先に聞くより「同じ工程で比べる軸」をそろえます。費用の構造は[採用代行の費用の内訳](/media/rpo-hiyou-uchiwake/)に、選び方の軸は[採用代行会社の選び方](/media/rpo-erabikata/)に書いています。

## 代行に出したあとに起きること

| 起きること | 原因 | 対応 |
|---|---|---|
| 応募は増えたが、案件に合わない | 役割が「SE」のまま。案件との照合が無い | 役割と案件で要件を切る |
| スカウトの返信が来ない | 「SIerに転職する理由」が文面に無い | 実態の言葉で動く理由を作る |
| 面接で「常駐は聞いていない」と辞退 | 働き方の実態を先に出していない | 常駐先と働き方を求人票と初回の連絡に |
| 採れたが、案件が始まるまで稼働しない | 採る時期と案件の時期がずれている | 採用計画を案件の計画と同じ行に |
| 契約が終わると記録が消える | 記録が代行の環境 | 社内の環境に置く形を契約で |

出したあとの問題は、「役割の切り分け」「動く理由」「働き方の実態」「時期」に戻ります。契約の前に、工程の切り分けと記録の置き場所を書面にします。

### エラベルの見解

相談で多いのは、「案件が決まってから急いで採る」が繰り返され、毎回、要件が曖昧なまま募集が始まる会社です。急ぐほど、代行に「とにかく人を」と頼み、代行は広く集め、面接で合わず、時間だけが過ぎます。急ぐときこそ、「どの工程を担う人か」「いつまでに要るか」「常駐か持ち帰りか」の三つを一枚にしてから動くほうが、結果は速い。エラベルは、担当者を工程ごとに選べる形にしているので、急ぐ案件では「一次対応と日程」だけを先に任せ、社内は役割の切り分けと案件との照合に集中する、という組み方ができます。案件の時期と採用の時期をつなぐ考え方は[要員計画と採用計画がつながっていない](/media/rpo-jinin-keikaku/)に書いています。

## まとめ

- SIer業界の難しさは、**役割の幅・候補者の層の重なり・案件で動く人数と時期**の三つ
- **母集団形成・一次対応・日程・記録は任せられ、役割の決定・案件との照合・技術の見極め・条件は残す**
- 「SEを採る」を**「どの工程を、どの案件で担う人か」**に分ける。「いろいろできる人」では代行は機能しない
- **「SIerに転職する理由」を実態の言葉で**作れるかが、スカウトの返信を決める
- 常駐と働き方の実態は**先に出す**。出さないと面接で辞退
- 代行を選ぶときは**役割ごとの型と、担当者の経歴を役割と工程で**確かめる
- 急ぐときこそ、**役割・時期・働き方の一枚**を先に

## よくある質問

### 案件が決まってから採るので、要件を先に決める余裕がありません

役割の切り分けは、案件が決まってからでも三十分で作れます。「この案件で、どの工程を、常駐か持ち帰りか、いつまでに」の四つを一枚に書けば、要件の骨になります。それが無いまま募集を始めると、面接で合わない人に時間を使い、結果として遅くなります。急ぐ案件では、一次対応と日程を外に出し、社内は四つの一枚と案件との照合に集中する形が速い。

### 候補者が「SIerから自社開発に行きたい」と言って辞退します

その層は、SIerに転職する動機を持っていないので、対象から外して構いません。対象にするのは、「上流に関わりたい」「扱う規模を大きくしたい」「特定の業界の案件を担いたい」など、SIerの中で動く理由がある層です。自社の実態（上流の比率、持ち帰りの比率、扱う業界と規模）が、その理由に対応していれば、文面と求人票でそれを示します。対応していなければ、実態を変えるか、対象を変えるかで、盛った文面で採ることではありません。

### 若手や未経験の採用も代行に出せますか

母集団形成（掲載型、学校経由）と一次対応は出せますが、育てる体制（誰が、どのくらいの期間、何を教えるか）が社内に無ければ、採っても案件に入れず、離れます。育てる体制を先に決め、その体制で受け入れられる人数を採る数にします。未経験の採用は、案件との照合ではなく、育成の計画と紐づけます。育てる体制の考え方は[新卒採用の実務の進め方](/media/rpo-task-shinsotsu-unyou-susumekata/)に書いています。

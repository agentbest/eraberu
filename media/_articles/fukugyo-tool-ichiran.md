副業を始めるとき、どんなツールを使うことになるのかが分からない。ATSと聞いても触ったことがなく、依頼側のチャットも初めてで、自分で何を用意すればよいのかも分からない。結論を先に書くと、**人事の副業で使うツールは、「依頼側が提供するもの」と「自分で持つもの」の二つに分かれます。依頼側が提供するのは、ATS、媒体の管理画面、チャット、共有フォルダのように、依頼側と候補者の情報を扱うツールです。自分で持つのは、表計算、メール、パスワード管理、カレンダーのように、自分の管理の情報を扱うツールです。製品名で選ぶより、「どちらが提供し、何の情報を置くか」で整理すると、案件が変わっても迷いません。**製品の仕様や料金は変わるので、この記事では製品名を挙げず、種類と用途で整理します。ツールの揃え方の考え方は[使うツールをそろえる](/media/fukugyo-tool/)に、依頼側のツールに合わせる進め方は[クライアントのツールに合わせる](/media/fukugyo-kokyaku-tool/)に、統一と合わせるの線は[ツールを統一するか合わせるか](/media/fukugyo-tool-toitsu/)にまとめています。

## 二つに分ける理由

ツールを「依頼側が提供するもの」と「自分で持つもの」に分けるのは、置く情報が違うからです。

| 区分 | 誰が提供するか | 置く情報 | 案件が終わったら |
|---|---|---|---|
| 依頼側が提供するもの | 依頼側 | 依頼側と候補者の情報 | アカウントを依頼側が停止する。自分の側には残らない |
| 自分で持つもの | 自分 | 自分の管理の情報（稼働、請求、判断、アカウントの一覧） | 残す。依頼側の情報が入っていれば消す |

分ける要点は、「依頼側と候補者の情報は、依頼側が提供するツールの中だけで扱う」ことです。自分で持つツールに依頼側の情報を置くと、案件の終了時に消す作業が要り、置き忘れると守秘の問題になります。依頼側の情報は依頼側のツール、自分の管理は自分のツール、と分ければ、終了時はアカウントの停止だけで済みます。情報の分け方は[案件ごとの情報の分け方](/media/fukugyo-jouhou-bunri/)に書いています。

## 依頼側が提供するツールの種類

依頼側から提供されるツールを、種類ごとに用途と置く情報で整理します。案件によって、有るものと無いものがあります。

| 種類 | 用途 | 置く情報 | 最初に確認すること |
|---|---|---|---|
| ATS（採用管理の仕組み） | 候補者の状態の管理、選考の記録、面接の日程、社内の連絡 | 候補者の情報の中心 | 触ってよい範囲（見る、編集する、状態を変える、削除する）。自分専用のアカウントか |
| 媒体の管理画面 | スカウトの検索と送信、応募の確認、返信のやり取り | 候補者のプロフィール、送信と返信の記録 | 自分専用のIDか、共有か。送信の上限や規約は公式の情報で確認 |
| チャット | 依頼側の担当者との連絡、社内の人との連絡 | 依頼側の社内の情報、進捗 | 使い分け（どのチャンネルに何を書くか）、返信の期待の速さ、候補者の情報を書いてよいか |
| 共有フォルダ | 求人票、面接の準備の資料、型の文書、議事録 | 依頼側の資料 | フォルダの構造、自分が作ってよい場所、外部に共有されていないか |
| ビデオ会議 | 定例、面接の同席、面接官との打ち合わせ | 会話の内容 | 依頼側の指定のサービスか、自分のでよいか。録画の可否 |
| 日程調整の仕組み | 候補者と面接官の日程の調整 | 候補者の連絡先、面接官の予定 | 依頼側が使っているか。無ければ自分の記録で管理 |
| 依頼側のメール | 候補者への連絡を依頼側のアドレスで送る場合 | 候補者とのやり取り | 発行されるか。発行されない場合、候補者への連絡は媒体の中か、依頼側の担当者経由か |
| 電子契約 | 契約書の署名 | 契約の内容 | 依頼側の仕組みで署名し、控えを自分の側に保存 |

種類の要点は、「ATSと媒体の管理画面が、候補者の情報の置き場である」ことです。この二つの中で候補者の情報を扱い、外に出さない。他の種類は、依頼側との連絡と資料の置き場で、候補者の情報を書き込んでよいかは、依頼側に確認します。チャットに候補者の名前を書くことを、依頼側が嫌う場合があります。依頼側の仕組みに合わせる進め方は[クライアントのツールに合わせる](/media/fukugyo-kokyaku-tool/)に整理しています。

### エラベルの見解

相談で最も多い思い込みは、「副業を始める前に、ATSや媒体の管理画面を使えるようになっておかないといけない」というものです。実際には、ATSも媒体も依頼側が提供するもので、依頼側ごとに種類が違い、事前に一つを覚えても、次の案件では別のものです。依頼側の担当者は、外部の担当者がそのツールを使ったことがあるかより、候補者の対応やスカウトの進め方の経験を見ています。ツールは、案件の最初の数日で、自分の範囲の操作だけを覚えれば足ります。

見ていて差がつくのは、事前にツールを覚えているかではなく、依頼側から提供されたツールで「触ってよい範囲」と「自分専用のアカウントか」を最初に確認しているかです。確認している人は、慣れないツールでも自分の範囲だけを触るので、依頼側の社内の作業を壊さず、共有アカウントの問題にも巻き込まれません。エラベルでは、依頼側との契約の際に、担当者に提供されるツールと、触る範囲と、専用のアカウントの発行を確認しています。ツールの経験の有無は、登録の条件にしていません。

## 依頼側から提供されるツールで最初に確認すること

提供されたツールを使い始める前に、確認することを一覧にします。確認しないと、後で指摘を受けます。

| 確認すること | なぜ |
|---|---|
| 自分専用のアカウントか、共有か | 共有だと、誰の操作か分からず、規約に触れることがある。[パスワードの受け渡し](/media/fukugyo-password/) |
| 触ってよい範囲（見る、編集する、状態を変える、削除する、送信する） | 範囲外の操作で、依頼側の社内の作業を壊す |
| 依頼側の使い方の癖（状態の名前、記録の書き方、チャンネルの使い分け） | ツールの機能より、依頼側の運用が大切 |
| 候補者の情報を、どのツールに書いてよいか | チャットや共有フォルダに候補者の情報を書くことを、依頼側が嫌う場合がある |
| 通知の設定 | 本業の時間中に通知が来ない設定にできるか。[本業に支障が出る](/media/fukugyo-shippai-9/) |
| 外部からの接続の条件 | 私物の端末、自宅の回線から入ってよいか。指定があるか。[ネットワーク環境の注意](/media/fukugyo-vpn/) |
| 終了時の扱い | アカウントの停止を誰がするか。自分が置いた資料はどうするか。[アカウント管理のしかた](/media/fukugyo-account-kanri/) |
| 分からないときの窓口 | ツールの設定で迷ったとき、誰に聞くか。採用の担当者では答えられないことがある |

確認の要点は、「触ってよい範囲を、項目の単位で聞く」ことです。「ATSを使ってください」だけでは、候補者の状態を変えてよいのか、評価の欄に書いてよいのか、削除してよいのかが分かりません。項目ごとに聞いておけば、依頼側の社内の人の作業と重なりません。確認の全体は[初回打ち合わせの進め方](/media/fukugyo-shodan/)に書いています。

## 自分で持つツールの最小の一組

自分で持つツールは、一組で足ります。案件ごとに増やしません。

| 種類 | 用途 | 置く情報 | 要点 |
|---|---|---|---|
| 表計算 | 稼働ログ、請求と入金の記録、アカウントの一覧、判断のメモ | 自分の管理の情報。依頼側の情報は抜く | 一枚ずつで足りる。案件の列で分ける。[稼働ログの付け方](/media/fukugyo-log/) |
| 副業用のメール | 依頼側との連絡、媒体の登録、請求の送付、議事録の控え | 依頼側とのやり取り | 一つ。案件ごとにラベルで分ける。本業のメールは使わない |
| パスワード管理 | 依頼側から発行されたアカウント、自分のアカウント | ログイン情報 | 副業用の利用者で。本業の会社のツールに入れない。[パスワードの受け渡し](/media/fukugyo-password/) |
| カレンダー | 副業の枠、依頼側の定例、締め日と請求の日 | 予定 | 副業用の一つ。案件ごとに色で分ける。[複数案件のスケジュール管理](/media/fukugyo-fukusuu-kanri/) |
| 副業用のクラウド | 型の構造（依頼側の情報を抜いたもの）、自分の記録 | 自分の型と記録 | 依頼側の資料は置かない。置くなら案件のフォルダで、終了時に消す |
| 請求書の型 | 請求書の作成 | 自分の情報と振込先 | 一つの型を案件ごとに複製。[請求書の書き方](/media/fukugyo-seikyuusho/) |
| ビデオ会議（依頼側の指定が無い場合） | 定例 | 会話の内容 | 依頼側の指定があればそれを使う |

一組の要点は、「表計算が中心で、他は最小」だということです。稼働ログ、請求、アカウントの一覧、判断のメモは、表計算の一枚ずつで足り、案件ごとに列やタグで分ければ、一組のまま増えません。専用のツールは、案件が増えて表計算では回らなくなってから考えれば足ります。一組の整え方は[使うツールをそろえる](/media/fukugyo-tool/)に、端末とアカウントの分離は[情報の取り扱いと端末の分離](/media/fukugyo-security/)に整理しています。

## 使わないほうがよいツールの使い方

ツールそのものではなく、使い方に、避けるべきものがあります。

| 使い方 | なぜ避けるか | 代わりに |
|---|---|---|
| 本業の端末、回線、メール、チャットで副業の作業をする | 本業の記録に残り、依頼側の情報が本業の管理下に入る。規定に触れる | 私物の端末、自宅の回線、副業用のアカウント。[私物端末で作業してよいか](/media/fukugyo-tanmatsu/) |
| 自分のクラウドに候補者の情報を置く | 依頼側の管理の外に情報が出る | 依頼側のATSと共有の中だけで扱う |
| 共有アカウントを、そのまま使い続ける | 誰の操作か分からず、規約に触れる | 専用の発行を頼む。共有なら期間と範囲を限る |
| チャットに候補者の名前や評価を書く | チャットは流れて残り、検索で誰でも見られる | 候補者の情報はATSに。チャットは人数と工程で |
| AIのサービスに依頼側や候補者の情報を入力する | 外部に情報を渡すことになり得る | 情報を含まない作業に限る。[AIをどう使うか](/media/fukugyo-ai-katsuyou/) |
| 自分のチャットに依頼側を招待する | 依頼側の情報が自分のツールに残る | 依頼側のチャットに合わせる。無ければメール |
| 案件ごとにメールやクラウドを作る | 一覧が増え、終了時の整理が増える | 一組の中で、案件ごとにラベルやフォルダで分ける |
| 依頼側のツールの設定を勝手に変える | 依頼側の社内の運用を壊す | 通知など自分の範囲の設定だけ。権限や共有に関わる設定は依頼側に |

避ける要点は、「本業のもので副業をしない」と「候補者の情報を依頼側のツールの外に出さない」の二つに集約されます。この二つを守れば、ツールの使い方で問題になることは、ほぼ無くなります。

## 案件が増えたときの整理

案件が増えると、依頼側から提供されるツールが増えます。自分で持つツールは増やさず、依頼側のツールを整理します。

| 整理 | 内容 |
|---|---|
| アカウントの一覧を一枚に | 案件×ツールの行で、種類（自分・発行・共有）、ID、権限、停止の予定と確認を書く。[アカウント管理のしかた](/media/fukugyo-account-kanri/) |
| ブラウザのプロファイルを案件ごとに分ける | 別の依頼側のATSやチャットを取り違えない。[ツールを統一するか合わせるか](/media/fukugyo-tool-toitsu/) |
| 通知の確認の時間を決める | 全案件の通知の場所を、決めた時間に順に見る。随時の確認をやめる |
| 依頼側ごとの操作の手順を一枚に | 自分の範囲の操作と、依頼側の癖を、依頼側ごとに一枚のメモに。依頼側の情報は書かない |
| 自分の表計算は一組のまま | 稼働ログ、請求、判断のメモは、案件の列で分けて一枚ずつ |
| 終了した案件のアカウントを月に一度点検する | 停止の確認が取れていないものが無いか |

整理の要点は、「増えるのは依頼側のツールで、自分のツールは増やさない」ことです。依頼側のツールは、案件ごとに合わせるしかありませんが、一覧と手順の一枚と、案件ごとのプロファイルで、混同は防げます。自分のツールが一組のままなら、管理は一か所で済みます。複数の案件の回し方は[複数案件のスケジュール管理](/media/fukugyo-fukusuu-kanri/)に書いています。

### エラベルの見解

担当する側から見ると、ツールで困っていない人は、たくさんのツールを使いこなしている人ではなく、「依頼側のものと自分のもの」を分けて、自分のものを一組に留めている人です。依頼側のツールには合わせ、触る範囲を最初に聞き、候補者の情報をそこから出さない。自分のツールは表計算を中心に一組で、依頼側の情報を置かない。この形なので、案件が変わっても、依頼側のツールの操作を数日で覚えるだけで動けています。

順番として、始める前に自分の一組（表計算、副業用のメール、パスワード管理、カレンダー）を整え、案件が決まったら依頼側から提供されるツールと触る範囲と専用のアカウントを確認し、候補者の情報は依頼側のツールの中だけで扱い、自分のツールには自分の管理の情報だけを置き、案件が増えたらアカウントの一覧と手順の一枚で整理する。この順番で、ツールは副業の障害にはなりません。エラベルでは、依頼側から担当者に提供されるツールと、触る範囲と、専用のアカウントを契約の際に確認しています。ツールの経験ではなく、分ける習慣が、担当者を支えます。

## まとめ

- ツールは**依頼側が提供するもの（ATS・媒体・チャット・共有・ビデオ会議・日程調整・依頼側のメール・電子契約）**と**自分で持つもの（表計算・メール・パスワード管理・カレンダー・クラウド・請求書の型）**の二つ
- 分ける理由は**置く情報が違う**から。依頼側と候補者の情報は依頼側のツールの中だけ、自分の管理は自分のツール
- 依頼側のツールでは**専用のアカウントか・触ってよい範囲・使い方の癖・候補者の情報を書いてよい場所・通知・接続の条件・終了時の扱い・窓口**を最初に確認
- 自分のツールは**表計算を中心に一組**。案件ごとに増やさない
- 避けるのは**本業のもので副業をする・候補者の情報を依頼側のツールの外に出す・共有アカウントを続ける・AIに情報を入力する・設定を勝手に変える**
- 案件が増えたら**アカウントの一覧・プロファイルの分離・通知の時間・手順の一枚**で整理し、自分のツールは一組のまま
- 製品の仕様と料金は変わるので、**公式の情報で確認する**

## よくある質問

### ATSを使ったことがありません。事前に覚えておくべきですか

事前に覚える必要はありません。ATSは依頼側ごとに種類が違い、事前に一つを覚えても、次の案件では別のものです。案件が決まってから、依頼側の担当者に自分の範囲の操作を一度見せてもらい、依頼側の使い方の癖を聞き、最初の数件を確認してもらえば、数日で動けます。ATSの種類に共通する骨格（候補者の状態を進める、記録を残す、連絡を送る）は同じなので、一つを覚えれば次は早くなります。覚え方は[クライアントのツールに合わせる](/media/fukugyo-kokyaku-tool/)に整理しています。

### 依頼側がチャットも共有フォルダも持っておらず、メールだけです

依頼側の運用に合わせ、メールで回します。自分のチャットや共有に依頼側を招待する形は、依頼側の情報が自分のツールに残るので、依頼側が求めない限りしません。メールでのやり取りは、件名の型を決め、案件ごとにラベルで分け、議事録と資料はメールに添えれば回ります。候補者の情報の管理の仕組みが依頼側に無い場合は、依頼側の共有の中に表を作ることを提案し、自分の側には置きません。メールの運用は[メールの書き方と運用](/media/fukugyo-mail/)に書いています。

### 有料のツールを自分で契約するべきですか

最初の一件では、無料で使える表計算、メール、カレンダーで足ります。有料のツールを検討するのは、案件が増えて表計算では回らなくなったときか、依頼側が特定のツールを指定して自分で用意する必要があるときです。契約する場合は、副業用のアカウントで、本業の会社の契約とは分け、費用が経費になるかは専門家に確認します。ツールに先に投資するより、案件で必要が出てから揃えるほうが、無駄がありません。経費の考え方は[経費にできるもの](/media/fukugyo-keihi/)に整理しています。

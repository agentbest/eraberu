担当した案件を、プロフィールや発信で事例として書きたい。依頼側の名前は出さないつもりだが、どこまで書けば特定されないのか、逆にどこまで削ると実績として意味が無くなるのかが分からない。結論を先に書くと、**特定されない事例は、「会社を粗くする」「候補者を消す」「判断と進め方を残す」の三つで作ります。会社は業界と規模と状況の粒度を粗くし、候補者に関わる情報は一切書かず、自分が何を決め、どういう順番で進めたかを残す。**この形にすると、依頼側と候補者は特定されず、依頼側が読んでも「自分たちのことだ」と分かる程度で済み、依頼側が見ているのは「この人はどう判断する人か」なので、実績としての意味は残ります。書く前に、読む側の視点で特定できるかを確かめる手順を踏みます。許可を取って名前を出す場合は[クライアントに実績公開の許可を取る](/media/fukugyo-kyoka-toru/)に、書いてはいけない内容の一覧は[発信で書いてはいけないこと](/media/fukugyo-hasshin-nglines/)にまとめています。

## 事例が特定される仕組み

会社名を出さなくても特定されるのは、情報の組み合わせで絞り込めるからです。どの情報が組み合わさると特定されるかを知っておくと、粗くする場所が分かります。

| 組み合わせ | 特定される理由 |
|---|---|
| 業界＋地域＋規模 | 狭い業界で、地域と規模が分かれば、候補は数社になる |
| 職種＋時期＋採用の人数 | その時期にその職種を募集していた会社は、媒体を見れば分かる |
| 珍しい状況 | 「上場直後」「拠点の新設」「事業の撤退」のような状況は、それだけで絞られる |
| 依頼側の担当者の特徴 | 「人事が一人」「経営者が直接」のような社内の体制は、業界と規模と組み合わさると絞られる |
| 自分の経歴との組み合わせ | 自分が本業でどの業界にいたかと、副業の事例の業界が同じだと、つながりで推測される |
| 発信の時期 | 案件の直後に事例を書くと、その時期に自分が動いていた案件と結びつく |

仕組みの要点は、「一つ一つは特定されない情報でも、組み合わせると特定される」ことです。会社名を消しただけでは足りず、組み合わせで絞り込める情報を、一つずつ粗くしていきます。候補者の情報は、組み合わせ以前に、そもそも書きません。候補者の情報の線は[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に整理しています。

## 粗くする三つの軸

会社が特定されないように、業界・規模・状況の三つの軸で、粒度を粗くします。

| 軸 | 細かい（特定される） | 粗い（特定されにくい） |
|---|---|---|
| 業界 | 「医療機器の販売代理店」「地方の食品スーパー」 | 「メーカー系」「小売」「サービス業」 |
| 規模 | 「従業員〇〇名」「拠点数〇」 | 「数十名規模」「数百名規模」「一人人事の会社」 |
| 状況 | 「上場直後で急拡大」「〇〇県に拠点を新設」 | 「採用を増やす局面」「人事の体制が整う前」 |
| 職種 | 「〇〇という製品の営業」 | 「法人営業」「エンジニア」 |
| 時期 | 「今年の春」 | 書かない。または「過去の案件で」 |
| 体制 | 「人事担当が一人で、経営者が面接に出る」 | 「人事の専任がいない体制」 |

粗くする要点は、「業界と規模と状況のうち、少なくとも二つを粗くする」ことです。三つ全部が細かいと特定され、一つだけ細かくても、他の二つが粗ければ特定されにくくなります。自分の事例で、どれを残したいかを決め、残す一つ以外を粗くします。「業界が特徴的な案件」なら業界を粗くし、「体制が特徴的な案件」なら体制を粗くします。

### エラベルの見解

相談で最も多い思い込みは、「粗くすると、実績として何も伝わらなくなる」というものです。実際には、依頼側が事例を読んで知りたいのは、その案件がどの会社だったかではなく、「この人は、その状況で何を決め、どう進めたか」です。会社を粗くしても、判断と進め方が書かれていれば、依頼側は「自分たちの状況でも同じように進めてくれそうか」を読み取れます。逆に、会社の特徴が細かく書かれていても、判断と進め方が無ければ、依頼側には「その会社で何かやった人」としか伝わりません。

粗くして薄くなるのは、会社の情報であって、自分の判断の情報ではありません。書く前に、「この事例で伝えたいのは、自分のどの判断か」を一つに決めておくと、粗くしても薄くならない書き方になります。エラベルでは、担当者の経歴を依頼側に提示するとき、会社名ではなく「どの状況で、何を決めていたか」を中心に整えています。依頼側の反応も、会社名より判断の中身に対して返ってきます。

## 残してよいもの

粗くする一方で、残すものを決めておかないと、削りすぎて実績になりません。残すのは、自分の判断と進め方です。

| 残すもの | 書き方の例 |
|---|---|
| 依頼を受けたときの状況（粗く） | 「人事の専任がいない、数十名規模の会社で、法人営業の採用が進んでいなかった」 |
| 自分が最初に確認したこと | 「求人票と、これまでの応募の経路と、面接に出る人の時間を確認した」 |
| 自分が決めたこと | 「媒体を増やす前に、求人票の要件を三つに絞ることを提案した」 |
| 進めた順番 | 「要件を絞り、求人票を直し、その後にスカウトの文面を型にした」 |
| 途中で直したこと | 「返信率を見て、文面の冒頭を役割の説明から会社の状況の説明に変えた」 |
| 依頼側と分けた判断 | 「合否と条件は依頼側が決め、自分は候補者の対応と進捗の整理を担った」 |
| 自分が学んだこと | 「一人人事の会社では、面接官の時間を先に押さえないと、母集団があっても進まない」 |

残すものの要点は、「決めたこと」と「順番」です。この二つがあれば、依頼側は「この人に頼むと、こう進む」を想像できます。数字が無くても、進め方が具体なら実績として伝わります。数字を出さない実績の示し方は[実績の示し方](/media/fukugyo-jisseki-shimeshikata/)に、型として見せる形は[noteで実績を見せる](/media/fukugyo-note/)と[ポートフォリオの作り方](/media/fukugyo-portfolio/)に書いています。

## 書く前に確かめる手順

書いた事例を出す前に、読む側の視点で特定できるかを確かめます。自分では特定されないと思っていても、読む側は別の情報を持っています。

| 手順 | 内容 |
|---|---|
| 一、依頼側の担当者が読んだらどう思うか | 「自分たちのことだ」と分かるのは構わない。「社外の人にも分かる」と感じる書き方なら、粗くする |
| 二、依頼側の同業の人が読んだら絞れるか | 同じ業界の人は、業界の中の会社を知っている。業界を細かく書くと、同業の人には絞れる |
| 三、候補者が読んだら自分のことだと分かるか | 候補者に関わる情報が少しでも入っていれば、その候補者には分かる。全部消す |
| 四、自分の本業の経歴と組み合わせると推測されるか | 本業の業界と、事例の業界が同じなら、本業の関係者は「あの会社では」と推測する |
| 五、時期が近すぎないか | 案件の直後は書かない。終了から時間を置くか、時期を書かない |
| 六、他の事例と組み合わせると絞れるか | 複数の事例を並べたとき、共通点から「同じ会社」「この時期」と絞られないか |

確かめる要点は、「二」の同業の人の視点です。自分から見て粗くても、その業界にいる人から見ると、業界の中の会社は限られています。業界は、自分が思うより一段粗くします。確かめた結果、特定される可能性が残るなら、その事例は出さず、そこで作った型だけをポートフォリオにします。

## 書き方の型と例

事例は、状況・決めたこと・順番・結果の四つの段落で書くと、粗くしても伝わります。

| 段落 | 書くこと | 例 |
|---|---|---|
| 状況 | 粗くした業界・規模・体制と、困っていたこと | 「人事の専任がいない、数十名規模のサービス業の会社で、法人営業の採用が半年ほど進んでいなかった」 |
| 決めたこと | 最初に確認したことと、決めたこと | 「応募が来ていないのではなく、面接の日程が組めずに辞退が出ていることを確認し、媒体を増やす前に面接官の時間を週に固定することを提案した」 |
| 順番 | 進めた順番と、途中で直したこと | 「面接の枠を固定し、求人票の要件を絞り、その後にスカウトの文面を型にした。途中で返信率を見て文面の冒頭を直した」 |
| 結果 | 数字を出さず、状態の変化で書く | 「日程の理由での辞退が減り、面接まで進む候補者が増えた。合否と条件は依頼側が決めた」 |

型の要点は、「結果を数字ではなく状態で書く」ことです。「〇か月で〇名採用」は依頼側の情報で、許可が要り、組み合わせで特定されます。「日程の理由での辞退が減り、面接まで進む候補者が増えた」なら、依頼側の情報ではなく、自分の進め方の結果として書けます。数字を出したい場合は、[クライアントに実績公開の許可を取る](/media/fukugyo-kyoka-toru/)の手順で許可を取ってからにします。

## それでも書けない案件の扱い

粗くしても特定される案件は、事例としては書けません。書けない案件でも、実績が空になるわけではありません。

| 書けない理由 | 代わりの形 |
|---|---|
| 業界が狭く、粗くしても絞れる | 業界を書かず、「専門職の採用」のように職種の性質だけにする。それでも絞れるなら書かない |
| 状況が珍しく、それ自体で特定される | 状況を書かず、決めたことと順番だけを一般化して書く |
| 候補者との接点が中心の案件 | 候補者の話が抜けると実績にならない場合は、書かない。候補者対応の型だけをポートフォリオにする |
| 秘密保持で契約の存在自体を開示できない | 書かない。そこで作った型を、依頼側の情報を抜いてポートフォリオにする。契約書の解釈は専門家に |
| 依頼側との関係が良くない形で終わった | 特定されなくても書かない。読まれたときの関係の悪化を避ける。[契約を切られたとき](/media/fukugyo-kaiyaku-sareta/) |

書けない案件の要点は、「型だけを残す」ことです。案件で作ったスカウトの文面の型、求人票の要件の絞り方、面接の日程の組み方は、依頼側の情報を抜けば自分の成果物として残せます。事例として書けなくても、型があれば「こういう進め方をする人」と伝わります。

### エラベルの見解

担当する側から見ると、事例を書くのが上手な人は、案件の途中から「この案件で自分が決めたことは何か」を記録しています。案件が終わってから思い出して書くと、依頼側の情報と自分の判断が混ざったまま出てきて、粗くする作業が難しくなります。途中から「自分が決めたこと」だけを別に書き留めておくと、終わった後に、その記録から事例を組めます。依頼側の情報は最初から入っていないので、粗くする手間も小さくなります。

順番として、案件の初回の打ち合わせの後に「最初に確認したことと決めたこと」を書き留め、途中で直したことがあれば足し、終了時に「状態がどう変わったか」を足す。この記録は、事例だけでなく、依頼側への報告や、次の案件の型にも使えます。エラベルでは、担当者の経歴を整えるとき、この「決めたことの記録」があるかどうかで、提示できる内容の濃さが変わっています。案件の記録の付け方は[稼働時間の管理と申告](/media/fukugyo-kadou-kanri/)の型に、「決めたこと」の列を足す形で足ります。

## まとめ

- 特定されない事例は**会社を粗くし、候補者を消し、判断と進め方を残す**
- 特定は**組み合わせ**で起きる。業界・地域・規模・職種・時期・状況・体制・自分の経歴・発信の時期
- 粗くするのは**業界・規模・状況のうち少なくとも二つ**。残したい一つ以外を粗くする
- 残すのは**状況（粗く）・最初に確認したこと・決めたこと・順番・途中で直したこと・依頼側と分けた判断・学んだこと**
- 出す前に**依頼側の担当者・同業の人・候補者・本業の関係者・時期・他の事例との組み合わせ**の視点で確かめる。業界は一段粗く
- 型は**状況・決めたこと・順番・結果**の四段落。結果は数字ではなく状態で書く。書けない案件は型だけを残す

## よくある質問

### 依頼側が事例を読んで「自分たちのことだ」と分かるのは、問題ですか

依頼側の担当者が自分たちのことだと分かること自体は、多くの場合は問題になりません。問題になるのは、依頼側以外の人が読んで、その会社だと分かることです。ただし、依頼側が「自分たちのことが書かれている」と感じて不快に思う可能性はあるので、粗くした事例でも、依頼側の担当者に一言「特定されない形で、進め方を事例として書いています」と伝えておくと、関係が保てます。

### 複数の案件をまとめて、一つの事例として書いてもよいですか

複数の案件の共通点をまとめて「こういう状況では、こう進めている」と書く形は、特定されにくく、自分の判断の型として伝わります。ただし、実際には無かった案件を作ることや、複数の案件の成果を一つの案件の成果のように書くことは、実績を大きく見せることになるので避けます。「複数の案件で共通して」と書き、一つの案件の話として書かないようにします。

### 本業で担当した採用を、副業の事例として書いてもよいですか

本業の採用の内情は、本業の会社の情報で、副業の事例として書くことは本業に対する情報の持ち出しになります。本業の経験を経歴として「法人営業の採用を担当した」と書くことはできますが、本業の案件の状況・決めたこと・結果を事例として書くことは避けます。本業の経験の活かし方は[本業と利益相反になる案件](/media/fukugyo-riekisouhan/)を見たうえで、規定の解釈は専門家にご確認ください。

依頼側との定例で決まったはずのことが、次の週に「そんな話だったか」と食い違う。自分のメモはあるが、依頼側には送っていないので、どちらの記憶が正しいか確かめようがない。結論を先に書くと、**議事録は、話した内容の記録ではなく、「決まったこと」「決まらなかったこと（保留と理由）」「誰がいつまでに何をするか」の三つを書き、打ち合わせの当日に依頼側へ送ります。**当日に送れば、依頼側の記憶が新しいうちに食い違いを直せ、翌週の「そんな話だったか」が起きません。依頼側が議事録を書く場合も、自分の側で三つを確認し、違いがあればその日のうちに伝えます。定例の進め方は[定例会の進め方](/media/fukugyo-teirei-shinkou/)に、月次の報告の形は[稼働報告のフォーマット](/media/fukugyo-kadou-houkoku/)に、依頼側への連絡の型は[メールの書き方と運用](/media/fukugyo-mail/)にまとめています。

## 議事録が要る理由

副業の案件で議事録を残す理由は、社内の会議の議事録とは少し違います。外部の立場で、週に数時間しか稼働しないからこそ要ります。

| 理由 | 内容 |
|---|---|
| 記憶の差を埋める | 依頼側は毎日採用のことを考えていて、自分は週に数時間。同じ打ち合わせでも、記憶の残り方が違う |
| 判断の所在を残す | 「合否は依頼側が決める」「文面の変更は自分の判断でよい」のように、誰が決めたかを残す。[権限がないと動けない場面](/media/fukugyo-kengen-nai/) |
| 範囲の変化を記録する | 打ち合わせで頼まれた範囲外の依頼が、いつから始まったかが残る。[範囲が広がっていくとき](/media/fukugyo-scope-creep/) |
| 担当者が替わっても続けられる | 依頼側の担当者が異動したとき、新任が議事録を読めば経緯が分かる |
| 「聞いていない」を防ぐ | 依頼側に伝えたことが、伝わっていなかったときの根拠になる |

理由の要点は、「判断の所在を残す」ことです。外部の立場では、自分で決めてよいことと依頼側に決めてもらうことの線が、案件の途中で動きます。議事録に「〇〇は自分の判断で進める、と確認」と残しておけば、後で「勝手に進めた」と言われることが減ります。

## 話した内容ではなく決まったことを書く

議事録が長くて読まれないのは、話した内容を順番に書いているからです。三つに絞ると、短くなり、読まれます。

| 項目 | 書くこと | 書かないこと |
|---|---|---|
| 決まったこと | 「来月から日程調整の枠を週二回に増やす」「文面の冒頭を会社の状況の説明に変える」 | 決まるまでの議論の経緯 |
| 決まらなかったこと | 「媒体の追加は保留。理由は予算の確認待ち。次回までに担当者が確認」 | 保留になった話の詳細 |
| 誰がいつまでに | 「自分：文面の修正案を〇日までに送る」「担当者：面接官の予定を〇日までに確認」 | 期限の無いもの |

三つの要点は、「決まらなかったこと」も書くことです。決まったことだけを書くと、保留になった話が消え、次の定例で「あれはどうなった」と最初から話すことになります。保留と理由と、誰が次に動くかを書いておけば、次の定例はそこから始められます。経緯や議論の内容は、書かなくても構いません。読む側が知りたいのは、結論と次の動きです。

### エラベルの見解

相談で最も多い思い込みは、「議事録は依頼側が書くもので、外部の自分が書くと出しゃばりに見える」というものです。実際には、依頼側の担当者は忙しく、議事録を書かないことが多いです。書かれないまま次の週になり、記憶の差で食い違いが起き、その修正に双方の時間が使われます。外部の側が三つに絞った短い議事録を当日に送ると、担当者はそれを読んで確認するだけで済み、「助かる」と受け取られます。

見ていて差がつくのは、「誰がいつまでに」の欄に依頼側の動きも書いているかです。自分の動きだけを書くと、依頼側の担当者が確認すべきことが消え、次の定例で「まだ確認していない」となります。担当者の動きも書き、期限を入れておくと、担当者はそれを社内の自分の作業として扱えます。エラベルでは、担当者と依頼側の定例で決まったことの記録を残すことを勧めており、記録がある案件では、範囲や判断をめぐる行き違いがほとんど起きていません。

## 当日に送る理由と送り方

議事録は、当日に送ることに意味があります。翌日以降になると、役割の半分を失います。

| 当日に送る理由 | 内容 |
|---|---|
| 記憶が新しいうちに直せる | 食い違いがあれば、依頼側はその日のうちに「そこは違う」と返せる。翌週だと、どちらも曖昧 |
| 期限が動き出す | 「〇日までに」が当日に共有されれば、依頼側の担当者はその日から動ける |
| 短く書ける | 当日なら、決まったことを思い出す必要が無く、三つを書くだけで済む |
| 信頼の積み重ねになる | 毎回当日に届くと、依頼側は「この人は決まったことを流さない」と受け取る |

| 送り方 | 内容 |
|---|---|
| 形 | メールの本文で足りる。添付にしない。三つの項目を見出しにし、箇条書きで |
| 長さ | 画面をスクロールせずに読める範囲 |
| 件名 | 「〇月〇日 定例の記録」のように、日付と定例と分かる形。毎回同じ形式に |
| 送る先 | 打ち合わせに出た依頼側の全員。出ていない上長には、担当者が回すかを担当者に任せる |
| 一文添える | 「認識が違う点があればお知らせください」。返事が無ければ合意とみなす、と最初の定例で決めておく |

送り方の要点は、「返事が無ければ合意とみなす」を最初に決めておくことです。毎回「確認しました」の返事を求めると、担当者の負担になり、返事が来なくなります。「違いがあれば連絡、無ければそのまま」と決めておけば、担当者は違うときだけ返せばよく、議事録は返事が無くても記録として成り立ちます。

## 依頼側が議事録を書く場合

依頼側が議事録を書く案件では、自分が書かない代わりに、確認する役割が要ります。

| 場面 | やること |
|---|---|
| 依頼側の議事録が届いた | 三つの項目（決まったこと・決まらなかったこと・誰がいつまでに）が入っているかを見る。自分の動きと期限が自分の理解と合っているか |
| 違いがある | その日のうちに、「〇〇の点は、私の理解では△△でした」と返す。翌週に持ち越さない |
| 三つのどれかが抜けている | 「保留になった媒体の追加の件は、次回までに確認いただく認識でよいでしょうか」のように、抜けた項目を質問の形で足す |
| 依頼側の議事録が届かない | 数日待って届かなければ、自分の側の三つを短く送る。「議事録の代わりに、私の理解を共有します」 |
| 依頼側の議事録に候補者の情報が入っている | 自分の側の保管は、依頼側の情報の扱いに従う。自分のメモには写さない |

依頼側が書く場合の要点は、「違いをその日のうちに返す」ことです。依頼側の議事録に自分の理解と違うことが書かれていて、それを放置すると、依頼側の記録が正になります。後から「違っていた」と言っても、記録に残っているほうが強い。届いた日に読んで、違いがあればその日に返します。

## 候補者の情報を入れない線

定例では候補者の話が出ますが、議事録には候補者を特定する情報を入れません。

| 定例で話したこと | 議事録の書き方 |
|---|---|
| 特定の候補者の選考の状況 | 「一次面接に進んだ候補者の日程を今週中に調整」のように、人数と工程だけ |
| 候補者の評価や合否の判断 | 「合否は依頼側が判断し、結果を自分に共有」のように、判断の所在だけ。評価の内容は書かない |
| 候補者から聞いた事情 | 書かない。必要なら依頼側の候補者管理の記録に、依頼側が書く |
| 候補者への対応の方針 | 「辞退の理由が日程のときは、別の枠を提案する」のように、方針として一般化 |

線の要点は、「議事録は候補者管理の記録ではない」ことです。候補者の情報は、依頼側の候補者管理の仕組み（ATSや依頼側の表）に置くもので、議事録に書くと、議事録が個人情報の記録になり、保管と処分の扱いが変わります。議事録には人数と工程と方針だけを書き、候補者の個別の情報は依頼側の仕組みに置きます。候補者の情報の扱いは[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に整理しています。

## 議事録を後から使う場面

当日に送った議事録は、その後、いくつかの場面で根拠として使えます。

| 場面 | 使い方 |
|---|---|
| 範囲が広がったとき | 「〇月〇日の定例で、〇〇の工程を追加すると確認」が残っていれば、更新のときに範囲の変化の根拠になる。[更新時の条件見直し](/media/fukugyo-keiyaku-koushin-koushou/) |
| 「聞いていない」と言われたとき | 「〇月〇日の記録でお伝えしています」と示せる。争うためではなく、認識を揃えるため |
| 依頼側の担当者が替わったとき | 新任に、直近数回分の議事録を渡せば、経緯の説明が短く済む |
| 月次の稼働報告を書くとき | 「決まったこと」を並べれば、その月の「やったこと」と「次の月の見込み」の材料になる |
| 案件が終わるとき | 引き継ぎの資料の一部になる。決まったことと保留のことの一覧が、次の担当者の出発点。[引き継ぎの進め方](/media/fukugyo-hikitsugi/) |
| 自分の判断の記録として | 「自分の判断で進めてよい」と確認したことの一覧は、次の案件で範囲を決めるときの参考になる |

使う場面の要点は、「争うためではなく、認識を揃えるため」だということです。「記録にあります」を相手を責める形で使うと、関係が壊れます。「記録ではこうなっていますが、今はどう進めましょうか」と、次の動きを決めるために使えば、記録は双方の道具になります。依頼側とのトラブルの整理は[トラブルへの対処](/media/fukugyo-trouble/)に書いています。

## 残す場所と期間

議事録は送ったメールがそのまま記録になりますが、探せる形で残しておきます。

| 決めること | 内容 |
|---|---|
| 残す場所 | 副業用のメールの送信済みに残す。案件ごとにラベルかフォルダを分ける。本業のアカウントには置かない。[情報の取り扱いと端末の分離](/media/fukugyo-security/) |
| 依頼側の側の場所 | 依頼側が社内の共有の場所に置くなら、そこに置くかを担当者に任せる。自分から依頼側の共有の場所に書き込むのは、頼まれたときだけ |
| 期間 | 契約中と、終了後は契約書の記録の保管の定めに従う。定めが無ければ、更新の根拠として一期分は残し、その後は処分の時期を決める |
| 案件の終了時 | 依頼側の情報が含まれる部分の扱いを、契約の終了の条項で確認する。候補者の情報が入っていなければ、扱いは軽くて済む |
| 自分の記録として残す部分 | 自分の判断の記録（「自分の判断で進めてよいと確認」など）は、依頼側の情報を抜いて、自分の記録に写しておく |

残し方の要点は、「候補者の情報が入っていなければ、扱いは軽くて済む」ことです。議事録に候補者の情報を入れない線を守っていれば、議事録は依頼側との合意の記録で、保管も処分も難しくありません。入っていると、個人情報の記録として、依頼側の定めに従った処分が要ります。線を守ることが、後の手間を減らします。契約の終了時の記録の扱いは、契約書の条項を確認し、迷えば専門家にご確認ください。

### エラベルの見解

担当する側から見ると、議事録を当日に送る習慣がある人は、依頼側との行き違いが少ないだけでなく、依頼側の担当者が替わったときに案件が続いています。新任の担当者は、前任から引き継ぎを受けても、外部の担当者との経緯までは分かりません。議事録が残っていれば、新任はそれを読んで「この人とは、こういう線で進めてきた」と分かり、最初からやり直さずに済みます。

順番として、最初の定例で「毎回、決まったこと・保留・誰がいつまでにの三つを当日に送ります。違いがあればお知らせください、無ければそのままで」と伝え、その日から始める。二回目以降は、型に沿って書くだけになります。エラベルでは、依頼側の担当者の交代が案件の終了につながる場面を見てきましたが、記録が残っている案件は、交代の後も続いていることが多いです。議事録は、その日の合意のためだけでなく、案件を長く続けるための記録です。担当者の交代への備えは[契約を切られたとき](/media/fukugyo-kaiyaku-sareta/)にも書いています。

## まとめ

- 議事録は**決まったこと・決まらなかったこと（保留と理由）・誰がいつまでに**の三つ。話した内容は書かない
- 要る理由は**記憶の差を埋める・判断の所在を残す・範囲の変化を記録する・担当者が替わっても続けられる・「聞いていない」を防ぐ**
- **当日にメールの本文で**送る。返事が無ければ合意とみなす、と最初に決めておく
- 依頼側が書く場合は**三つが入っているか確認し、違いはその日のうちに返す**
- **候補者を特定する情報を入れない**。人数と工程と方針だけ。候補者の情報は依頼側の仕組みに
- 後から**範囲の変化・認識のずれ・担当者の交代・稼働報告・引き継ぎ**で使う。争うためではなく認識を揃えるため
- 残す場所は**副業用のアカウントに案件ごと**。期間は契約の定めに従い、自分の判断の記録は依頼側の情報を抜いて写す

## よくある質問

### 定例が短く、決まったことがほとんど無い週も送りますか

送ります。「決まったこと：なし。保留：〇〇（前回から継続）。誰がいつまでに：自分が〇〇を継続」のように、短くて構いません。毎回届くことで、依頼側は「今週は決まったことが無かった」と分かり、届かない週があると「送り忘れか、定例が無かったか」と迷わずに済みます。形を毎回同じにしておけば、書く時間はほとんどかかりません。

### 依頼側から「議事録は要らない」と言われました

依頼側が要らないと言っても、自分の側の記録としては残します。送らない代わりに、三つの項目を自分の記録に書いておき、範囲や判断で食い違いが起きたときに、「〇月〇日の定例では、私の理解ではこうでした」と示せる形にします。依頼側に送らないので相手の確認は取れませんが、自分の理解の記録は残ります。範囲の変化や判断の所在に関わることが決まったときだけ、「念のため、この点は文面で共有させてください」と一文送る形もあります。

### チャットで決まったことも、議事録にしますか

チャットで決まったことは、チャットの記録が残るので、改めて議事録にしなくても構いません。ただし、チャットは流れて探しにくいので、範囲や判断の所在に関わることがチャットで決まった場合は、次の定例の議事録に「〇日のチャットで〇〇と確認」と一行入れておくと、後から探せます。チャットでのやり取りの扱いは[メールの書き方と運用](/media/fukugyo-mail/)に整理しています。

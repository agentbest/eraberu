依頼側の採用計画を見せてもらうと、「今期〇人」と役職名が並んだ一覧であることが多い。それは計画ではなく、目標の数です。いつまでに、どの役割を、どの経路で、誰が動いて採るかが無いと、期の途中で「まだ募集を始めていない」「経路が決まっていない」「面接官が足りない」で止まります。結論を先に書くと、**採用計画は、役割ごとに「要る時期・要る理由・経路・段階の数と面接官・想定の日数・担当・見直しの日」を一枚に置き、要る時期から逆算して募集の開始を出し、経路は型で主と従に分け、日数は過去の記録から置いて外部の数値を使わず、優先順位は要る時期と理由で依頼側が決め、予算とファネルの一枚と同じ行でつなぎ、月次で見直します。**会社側から見た手順は[採用計画の設計の進め方](/media/rpo-task-saiyo-keikaku-susumekata/)に、要員計画とのつなぎは[要員計画と採用計画がつながっていない](/media/rpo-jinin-keikaku/)に、予算は[採用予算を組む](/media/fukugyo-skill-yosan/)に書いています。ここでは、計画の一枚の型に絞ります。

## 「今期〇人」だけで崩れる理由

| 計画の形 | 何が起きるか |
|---|---|
| 人数と役職名だけ | いつまでに要るかが無く、募集の開始が遅れる |
| 経路が無い | 期の途中で媒体を選び始める。予算と合わない |
| 段階と面接官が無い | 応募が来てから面接官を探す。日程が詰まる |
| 日数の想定が無い | 「来月入社」が、実際には三か月かかることに気づかない |
| 担当が無い | 人事と現場が互いに相手がやると思う |
| 見直しの日が無い | 期末に「未達」と分かるだけ |

計画は、「何人」ではなく、「いつまでに要る役割を、どう採るか」の一枚です。人数は、その結果として出ます。

## 一枚に置く項目

| 列 | 中身 | 出どころ |
|---|---|---|
| 役割 | 職種名ではなく、任せる仕事で。要件の一枚の「なぜ採るか」 | [採用要件を引き出すヒアリングの型](/media/fukugyo-skill-youken-hearing/) |
| 要る時期 | いつまでに入社していてほしいか。「なるべく早く」は不可 | 依頼側の事業の予定 |
| 要る理由 | 欠員、増員、新しい仕事。理由で優先順位が変わる | 依頼側 |
| 経路 | 主と従。型で（掲載型・スカウト型・紹介・リファラル・自社） | [媒体を提案する根拠の作り方](/media/fukugyo-skill-baitai-sentei/) |
| 段階の数と面接官 | 何段で、誰が出るか | [面接の設計](/media/fukugyo-skill-mensetsu-sekkei/) |
| 想定の日数 | 募集開始から入社まで。段階ごとの日数の合計 | 依頼側の過去の記録 |
| 募集の開始 | 要る時期から想定の日数を引いた日 | 逆算 |
| 担当 | 各工程を誰が動かすか。人事、現場、外部の担当者 | 依頼側 |
| 見直しの日 | 月次。誰が見るか | 依頼側 |

一行が一つの役割です。役割が十を超えるなら、優先順位で上から並べ、下は「今期は着手しない」と明記します。

### エラベルの見解

担当する側から見ると、採用計画で最も差がつくのは、「要る時期から逆算して募集の開始を出す」ができるかどうかです。受ける側は、依頼側が「来月には欲しい」と言えば、来月を要る時期に置きます。ただ、依頼側の過去の記録で、募集の開始から入社まで三か月かかっているなら、来月は無理で、それを計画の段階で言わなければ、期の途中で「まだか」と責められます。「この役割は、過去の記録では開始から入社までこの日数です。要る時期がこの日なら、募集の開始はこの日で、いまから始めても間に合いません」と、逆算で示す。依頼側は要る時期を動かすか、経路を変えるか、判断できます。エラベルで担当者を選ぶ企業には、「要る時期から逆算して、募集をいつ始めるかを計画に書いていますか」を、私たちから先に聞いています。受ける側がその場で使える判断としては、計画の一枚に「募集の開始」の列を作り、要る時期と想定の日数から機械的に出すこと。開始の日が過去なら、その行は「間に合わない」と書きます。

## 想定の日数は過去の記録から

| 出し方 | 中身 |
|---|---|
| 依頼側の過去の記録がある | 同じ役割か近い役割の、段階ごとの日数の合計。一件ずつ並べ、長いものと短いものを見る |
| 記録が少ない | 一件でもあれば、その一件を仮に置き、「一件の実績」と明記 |
| 記録が無い | 段階ごとに、日程の枠と確定の速さから仮の日数を置き、「仮」と明記。今期の記録で来期に直す |
| やらないこと | 「一般に採用には〇か月」と外部の数値を置く。依頼側の段階と経路に合わない |

日数は、ファネルの一枚の「段階ごとの日数」と同じ元から出ます。ファネルがあれば、そこから写します。ファネルの作り方は[採用ファネルを可視化する](/media/fukugyo-skill-funnel/)に書いています。

## 経路は型で主と従

| 要る理由と時期 | 主の経路の候補 | 従 |
|---|---|---|
| 欠員で急ぐ | 紹介（体制が薄くても動く）、スカウト型（要件が具体なら） | 掲載型 |
| 増員で時期に余裕 | 掲載型、リファラル | スカウト型 |
| 新しい仕事で市場に少ない | スカウト型、リファラル | 紹介 |
| 認知がある | 自社の採用ページ、リファラル | 掲載型 |

経路の型と根拠の作り方は[媒体を提案する根拠の作り方](/media/fukugyo-skill-baitai-sentei/)に書いています。経路ごとの費用は、予算の一枚の同じ行につなぎます。料金や上限は断定せず、確認してから置きます。

## 優先順位は依頼側に残す

| 優先を決める軸 | 考え方 |
|---|---|
| 要る時期 | 早いものが上 |
| 要る理由 | 欠員（いまの仕事が止まる）が増員より上。ただし事業の判断で逆もある |
| 面接官の稼働 | 同じ面接官が複数の役割を持つと、日程が詰まる。並行できる数に上限 |
| 経路の重なり | 同じ媒体で複数の役割を同時に出すと、埋もれる |

担当者は、四つの軸で並べた案を出し、優先順位は依頼側が決めます。「全部を同時に」は、面接官の稼働と経路の重なりで止まる、という構造を添えます。

### エラベルの見解

相談で最も多い思い込みは、受ける側の「計画は年度の初めに作って、期末に振り返るもの」というものです。実際には、要る時期は事業の都合で動き、経路は詰まりで変わり、面接官は異動します。月次で一枚を開き、「要る時期が動いた行」「募集の開始が過ぎた行」「面接官が変わった行」だけを直す。それで計画は生きたままになります。年度の初めに作って放置した計画は、期の途中で誰も見なくなり、期末に「未達」の説明に使われるだけです。受ける側がその場で使える判断としては、計画の一枚に「見直しの日」を月次で書き、見直しでは「変わった行だけを直す」と決めること。全部を作り直すと、見直しが重くなって続きません。

## 計画・予算・ファネルを同じ行でつなぐ

| 一枚 | 行 | つながる列 |
|---|---|---|
| 採用計画 | 役割ごと | 経路、想定の日数、担当 |
| 予算 | 費目ごと（経路に対応） | 対応する役割と人数 |
| ファネル | 段階ごと（役割別に分けられる） | 数、日数、理由 |

三つの一枚が別々にあると、計画で経路を変えても予算が動かず、ファネルで詰まりが見えても計画に戻りません。役割の名前を三つで揃え、同じ行で参照できる形にします。要員計画（何人要るか）とのつなぎは[要員計画と採用計画がつながっていない](/media/rpo-jinin-keikaku/)に書いています。

## 踏み込まない線

| 線 | 理由 |
|---|---|
| 何人採るかを担当者が決めない | 事業の判断。依頼側が決める |
| 優先順位を担当者が決めない | 案を出すまで |
| 費用と相場を断定しない | 予算の一枚と同じ |
| 「〇か月で採れます」と約束しない | 日数は過去の記録の範囲で、仮として置く |
| 要員計画（組織の人数）に踏み込まない | 経営の判断。採用計画は要員計画を受けて作る |

計画に関わる判断は依頼側です。担当者は一枚の構造と、逆算と、案を出すまでです。範囲は契約に書きます。範囲の決め方は[業務範囲を書面で固める](/media/fukugyo-scope/)に書いています。

## よく起きる詰まりと直し方

| 詰まり | 直し方 |
|---|---|
| 要る時期が「なるべく早く」 | 「いつまでに入社していないと、何が止まりますか」で日を出す |
| 過去の記録が無く日数が置けない | 仮の日数を「仮」と明記して置き、今期の記録で直す |
| 役割が多すぎて並行できない | 面接官の稼働と経路の重なりで上限を示し、優先順位を依頼側に |
| 経路が去年のまま | 去年の経路のファネル（どの段で落ちたか）を並べ、主と従を見直す案を出す |
| 計画が期の途中で見られない | 見直しの日を月次で。変わった行だけを直す |
| 計画と予算が別の人が作っている | 役割の名前を揃え、同じ行で参照する形を提案する |

## まとめ

- 「今期〇人」は目標の数で、**計画ではない**
- 一枚は**役割・要る時期・要る理由・経路・段階と面接官・想定の日数・募集の開始・担当・見直しの日**
- **要る時期から逆算**して募集の開始を出す。過去なら「間に合わない」と書く
- 日数は**依頼側の過去の記録**から。無ければ「仮」と明記。外部の数値を使わない
- 経路は**型で主と従**。費用は予算の一枚の同じ行に
- 優先順位は**要る時期・要る理由・面接官の稼働・経路の重なり**で案を出し、**依頼側が決める**
- **計画・予算・ファネルを同じ行でつなぐ**。月次で変わった行だけを直す
- 人数・優先順位・費用・約束に踏み込まない。要員計画は経営の判断

## よくある質問

### 依頼側の要員計画（何人要るか）が無く、採用計画だけを頼まれました

採用計画は、要員計画（いまの人数、辞める見込み、事業に要る人数）を受けて作るものなので、要員計画が無いと「なぜこの役割が要るか」が置けません。「要る理由」の列を埋めるために、役割ごとに「欠員か、増員か、新しい仕事か」と「いつまでに要るか」を依頼側に聞き、それを仮の要員計画として一枚の先頭に置きます。要員計画そのものを作るのは経営の判断で、担当者は「この役割は、なぜいつまでに要るか」を聞き取るまでです。

### 計画を作った後、依頼側が「もっと早く採れないか」と言います

想定の日数は過去の記録から置いているので、「早くする」には段階ごとの日数を縮めるしかない、と構造で答えます。日程の枠を預かる、段を減らす、確定を即日にする、で縮む日数を、ファネルの記録から示します。それでも足りなければ、要る時期を動かすか、経路を紹介に寄せるかの判断で、依頼側が決めます。「頑張ります」と答えると、根拠の無い約束になります。速さの手当ては[日程調整を速くする](/media/fukugyo-skill-nittei/)に書いています。

### 副業の稼働で、計画の全部の役割を担当できません

担当の列で、自分が動く工程と、依頼側が動く工程を分けます。担当者が動くのは、契約の範囲の役割と工程だけで、残りの行は「依頼側」と書きます。計画の一枚は全体を見せるためのもので、担当者が全部を担うためのものではありません。担当の列が埋まっていれば、依頼側は「誰が動いていないか」を自分で見られます。稼働の設計は[稼働時間の管理と申告](/media/fukugyo-kadou-kanri/)に書いています。

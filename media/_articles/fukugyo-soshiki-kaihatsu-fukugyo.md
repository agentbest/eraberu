組織開発の担当として、組織の調査を回し、対話の場を作り、管理職の研修を設計し、部門の間の詰まりをほぐしてきた。この経験は、人事の副業、とくに採用の副業で売れるのか。組織開発は成果が見えにくく、言葉も抽象的になりがちで、採用の実務とは離れているように見えます。結論を先に書くと、**組織開発の経験は、「組織の状態を観察し、対話の場を設計し、人が動く仕組みに変えてきた」型で売れます。売れるのは、「採用の要件を組織の状態から決めること」「受け入れと定着の設計」「面接官の目線合わせ」「辞める理由の構造化」の四つです。採用が決まっても早く辞める、面接官によって判断がばらつく、要件が「今いる人と同じ人」になっている。こうした詰まりは、採用の技術ではなく組織の状態から来ていて、組織開発の経験がそのまま効きます。「組織開発をしていました」ではなく、「採用した人が組織で機能する形を作る」と売ります。**HRBPの経験の売り方は[HRBPが副業でできること](/media/fukugyo-hrbp-fukugyo/)に、人事コンサルタントの経験は[人事コンサルタントが副業でできること](/media/fukugyo-consultant-jinji-fukugyo/)に、人事責任者の経験は[人事責任者・CHROが副業でできること](/media/fukugyo-chro-fukugyo/)にまとめています。

## この経歴の何が売れるか

組織開発の経験を、依頼側の採用の工程に置き換えた棚卸しです。関わった組織の内情は含めず、「型」として抜き出します。

| 組織開発の経験 | 採用の工程への置き換え | 依頼側にとっての価値 |
|---|---|---|
| 組織の調査と観察で、状態を言葉にしてきた | 「どんな人が来たら組織が良くなるか」を、今の組織の状態から要件に落とす | 要件が「今いる人と同じ人」か「スーパーマン」になっている依頼側が多い |
| 対話の場を設計し、進行してきた | 面接官の目線合わせの場、要件を決める場、受け入れの場を設計し、進行する | 面接官によって判断がばらつく依頼側が多い |
| 新しい人が組織に入る過程を見てきた | 受け入れの設計（最初の一か月に誰が何をするか、期待の伝え方、つまずきの拾い方） | 採用は決まるが、早く辞める依頼側が多い |
| 辞める理由を、個人ではなく構造で見てきた | 離職の理由を、要件・面接・受け入れ・配属先の管理職のどこに戻すかを整理する | 辞める理由が「本人の問題」で終わる依頼側が多い |
| 管理職の研修や一対一の面談の設計をしてきた | 面接官としての管理職の見方を揃え、受け入れ側の管理職の関わり方を設計する | 管理職が採用と受け入れで何をすればよいか分からない依頼側が多い |
| 部門の間の詰まりをほぐしてきた | 採用をめぐる人事と現場の噛み合わなさを、対話の形で整理する | 人事と現場が責任を押し付け合う依頼側が多い |
| 変化への抵抗を扱ってきた | 採用の方針の変更や新しい人の受け入れに対する、既存の社員の抵抗を見越して設計する | 新しい人が「浮く」依頼側が多い |

売れるものの要点は、「採用を、組織に人が入る過程として設計できる」ことです。採用の担当者は、募集から内定までを設計しますが、内定の後、その人が組織で機能するまでを設計することは少なく、そこで辞めるとやり直しになります。組織開発の経験は、入る前の要件と、入った後の受け入れを、組織の状態からつなげて設計できます。この型は、採用は決まるのに定着しない会社で、最も効きます。聞き取りの型は[ヒアリングで押さえる項目](/media/fukugyo-hearing/)に、聞き取りの磨き方は[ヒアリング力の磨き方](/media/fukugyo-hearing-skill/)に書いています。

## 売りにくい点とその扱い

組織開発の転身で売りにくい点は三つあり、扱い方があります。

| 売りにくい点 | 依頼側の懸念と自分の懸念 | 扱い方 |
|---|---|---|
| 成果が見えにくい | 「組織が良くなった、と言われても分からない」。自分でも成果を数字で言いにくい | 採用の工程に置き換えると、成果が「辞めた人数」「面接の判断のばらつき」「受け入れの担当が決まったか」で見える。組織開発の言葉で売らず、採用の詰まりの言葉で売る |
| 言葉が抽象的 | 「対話」「心理的安全性」「エンゲージメント」が、経営者に通じない | 抽象語を使わず、「新しく入った人が最初の一か月で何につまずくか」「面接官が何を見ているか」と、場面で語る |
| 採用の実務が薄い | 「媒体の運用やスカウトはできるのか」 | 募集から内定までの実務は範囲に入れないか、別の担当者と組む。売るのは要件と面接官の目線と受け入れ、と最初に分ける |

扱い方の要点は、「組織開発の言葉を捨て、採用の詰まりの言葉で売る」ことです。組織開発の担当者は、自分の仕事を組織開発の言葉で語る癖があり、それが依頼側の経営者には抽象的に聞こえます。「採用は決まるのに早く辞める」「面接官によって合否が変わる」「要件が今いる人のコピーになっている」と、依頼側が困っている場面の言葉に置き換えれば、同じ経験が具体的に伝わります。範囲の決め方は[業務範囲を書面で固める](/media/fukugyo-scope/)に、自己紹介の型は[自己紹介文のテンプレート](/media/fukugyo-jiko-shoukai/)に整理しています。

### エラベルの見解

担当する側から見ると、組織開発から転身して続いている人と、面談で止まる人の差は、最初の面談で「組織」の話をするか「辞めた人」の話をするかです。止まる人は、組織の状態や文化の話から入り、経営者は「うちはそこまで大きくない」「まず人が欲しい」と感じて終わります。続いている人は、「最近辞めた人は、入って何か月で、何につまずいて辞めましたか」と聞き、辞めた人の話から要件と受け入れの詰まりを見つけて、「次に採る人は、この一点を要件に入れ、最初の一か月にこれをします」と返します。組織の話は、辞めた人の話の中で自然に出てきます。

見ていて差がつくのは、面接官の目線合わせを、研修ではなく短い場で済ませているかです。組織開発の経験がある人は、目線合わせを研修の形で設計しがちで、依頼側は「面接官を集めて研修する時間はない」と引きます。過去の候補者を一人取り上げ、面接官が何を見て合否を判断したかを言葉にしてもらう短い場を作った人は、面接官の見ている点のずれがその場で見え、依頼側から「初めて面接官の基準が揃った」と評価されています。エラベルでは、依頼側が担当者の経歴を見て選ぶ仕組みなので、「採用した人が組織で機能する形を作る」と採用の言葉で書いている担当者に、定着に困っている依頼側がついています。組織開発の転身は、組織の理論ではなく、辞めた人の話から始まります。

## 案件の探し方

組織開発から入りやすい案件と、探し方です。

| 入りやすい案件 | 理由 | 探し方 |
|---|---|---|
| 受け入れと定着の設計 | 新しい人が組織に入る過程を見てきた経験でそのまま入れる | 「採用は決まるが早く辞める依頼側」を探す |
| 面接官の目線合わせ | 対話の場の設計と進行の経験で入れる | 「面接官によって合否が変わる依頼側」を探す |
| 組織の状態から要件を決める | 組織の観察の経験で入れる | 「要件が今いる人のコピーになっている依頼側」を探す |
| 辞める理由の構造化 | 離職を構造で見てきた経験で入れる | 「辞める理由が『本人の問題』で終わる依頼側」を探す |
| 受け入れ側の管理職の関わり方の設計 | 管理職の研修と面談の設計の経験で入れる | 「配属先の管理職が新しい人に関われない依頼側」を探す |
| 人事と現場の対話の設計 | 部門の間の詰まりをほぐしてきた経験で入れる | 「人事と現場が押し付け合う依頼側」を探す |

探し方の要点は、「採用は決まるのに辞める会社」から入ることです。募集がうまくいかない会社では、組織開発の経験は募集の技術に負けます。募集はできていて、内定も出て、入った後に辞める会社では、募集の技術では解決できず、組織開発の経験が唯一の打ち手になります。案件の相談で「せっかく採ったのに」という言葉が出たら、それが入り口です。案件の探し方は[副業案件の探し方](/media/fukugyo-anken-sagashi/)に、合わない案件の見分け方は[合わない案件の見分け方](/media/fukugyo-awanai-anken/)に書いています。

## 単価の目安

単価は、具体的な額ではなく、決まり方の構造で考えます。組織開発の転身で、単価に影響する要素です。

| 要素 | 単価への影響 | 考え方 |
|---|---|---|
| 定着の設計の価値 | 一人辞めるごとのやり直しの損失は依頼側に分かりやすく、価値は見えやすい | 「辞めなかった」を成果として残せる形に |
| 成果が出るまでの期間 | 定着は入って数か月経たないと分からず、時間単価で見せると評価が遅れる | 中期の契約で受け、途中の成果（受け入れの担当が決まった、面接官の基準が揃った）を報告で見せる |
| 場の設計と進行 | 回数で受けやすい | 目線合わせの場、受け入れの場を回数で |
| 要件と受け入れの設計 | 成果物で受けやすい | 「組織の状態から書いた要件」「最初の一か月の受け入れの手順」を成果物に |
| 募集の実務を含まないこと | 含まない範囲は月額が下がるが、責任の線が明確 | 得意な工程で単価を出す |
| 抽象的な言葉での見積もり | 「組織開発」で見積もると根拠が伝わらない | 採用の詰まりの言葉と成果物で示す |
| 成果報酬の扱い | 定着は配属先の管理職の動きに左右され、責任の線が引きにくい | 時間か回数か成果物で。可否は専門家に確認 |

単価の要点は、「場は回数で、設計は成果物で受け、定着は途中の成果を報告で見せる」ことです。組織開発の工程は、成果が出るまでに時間がかかり、時間単価だけで見せると、依頼側は「何をしてくれたのか」が分からなくなります。面接官の目線合わせの場は回数で、要件と受け入れの手順は成果物で受け、定着は「受け入れの担当が決まった」「一か月の面談が回った」と途中の成果を報告で見せれば、更新の根拠になります。単価の構造は[人事の副業単価の相場](/media/fukugyo-tanka-souba/)に、数字に出ない成果の見せ方は[成果が数字に出ない業務の見せ方](/media/fukugyo-seika-mienai/)に、成果の定義は[成果をどう定義しておくか](/media/fukugyo-seika-teigi/)に整理しています。

## 始める順番

組織開発から副業を始める順番です。

| 順番 | 内容 |
|---|---|
| 一、本業の会社の副業の規定と、関わった組織の調査の情報の守秘の条件を確認する | 個別の判断は専門家に |
| 二、関わった組織で「新しい人がどこでつまずき、なぜ辞めたか」を、組織の情報を含まない型として書き出す | 受け入れの詰まりの型、辞める理由の構造 |
| 三、組織開発の言葉を、採用の詰まりの言葉に置き換える | 「対話の場」→「面接官の目線合わせ」、「オンボーディング」→「最初の一か月に誰が何をするか」 |
| 四、得意な工程（要件・目線合わせ・受け入れ・辞める理由）と、薄い工程（募集・スカウト・日程）を分ける | 正直に示す準備 |
| 五、範囲を、組織の状態からの要件、面接官の目線合わせ、受け入れの設計、辞める理由の構造化に絞る | 募集の実務は最初は範囲外か、別の担当者と組む |
| 六、「採用した人が組織で機能する形を作る」の一言を作る | 「組織開発をしていました」で終わらせない |
| 七、登録先に、範囲と、形と、募集の実務を含まないことを登録する | 採用は決まるのに辞める依頼側 |
| 八、受け入れの設計か面接官の目線合わせを一件受け、「最初の一か月の手順」を残す | 次の案件に広げる材料に |

順番の要点は、「三」の言葉の置き換えです。組織開発の担当者は、自分の経験を組織開発の言葉で持っていて、その言葉のまま売ると、依頼側の経営者には届きません。「対話の場の設計」は「面接官が何を見ているかを揃える短い場」に、「オンボーディング」は「最初の一か月に、誰が、いつ、何を伝えるか」に、「エンゲージメント」は「辞めそうな人を早く見つける仕組み」に、と一つずつ置き換えておくと、面談でも登録先でもそのまま使えます。プロフィールは[プロフィールの書き方](/media/fukugyo-profile/)に、初案件の備えは[初案件で不安になりやすい点と備え方](/media/fukugyo-hatsu-anken-fuan/)に書いています。

### エラベルの見解

相談で最も多い思い込みは、「組織開発の経験は、採用の副業とは別のものだ」というものです。実際には、採用の詰まりの多くは、募集の技術ではなく組織の側にあります。要件が今いる人のコピーになるのは組織の自己像の問題で、面接官の判断がばらつくのは基準を揃える場がないからで、早く辞めるのは受け入れの設計がないからです。組織開発の経験は、この三つに直接効き、募集の技術しか持たない担当者には打てない手です。別のものに見えるのは、組織開発の言葉で語っているからで、採用の詰まりの言葉に置き換えれば、同じものです。

順番として、本業の規定と守秘の条件を専門家に確認し、新しい人がつまずいた型を組織の情報を含まずに書き出し、組織開発の言葉を採用の詰まりの言葉に置き換え、得意な工程と薄い工程を分け、範囲を要件と目線合わせと受け入れと辞める理由に絞り、採用した人が組織で機能する形を作る一言を作り、登録先に範囲と形を登録し、一件受けて最初の一か月の手順を残す。この順番で、組織開発の経験は「採用とは別のもの」から「定着まで含めた採用の設計」になります。エラベルでは、依頼側が担当者を選ぶ仕組みなので、受け入れと定着の工程を明確にし、募集の実務を含まないことを示している担当者に、採ったのに辞めて困っている依頼側がついています。組織開発の転身は、理論ではなく、言葉の置き換えから始まります。

## まとめ

- 組織開発の経験は**「組織の状態を観察し、対話の場を設計し、人が動く仕組みに変えてきた」型**で売れる。**組織の状態からの要件・受け入れと定着の設計・面接官の目線合わせ・辞める理由の構造化**の四つ
- **「組織開発をしていました」ではなく「採用した人が組織で機能する形を作る」**と売る
- 売りにくい点は**成果が見えにくい・言葉が抽象的・採用の実務が薄い**。採用の詰まりの言葉に置き換え、場面で語り、募集の実務は範囲外と示す
- 案件は**採用は決まるのに辞める会社**から。「せっかく採ったのに」という言葉が入り口
- 単価は**場は回数、設計は成果物**で。定着は途中の成果を報告で見せる。成果報酬は最初は避け、可否は専門家に確認
- 最初の面談では組織の話ではなく、**辞めた人の話**から入る

## よくある質問

### 依頼側の経営者に「まず人を採るのが先で、定着の話は後」と言われました。どう返せばよいですか

順番としてはその通りで、否定しません。「募集は御社の担当者か別の担当者が進め、私は次に入る人が辞めない形を、募集と並行して用意します」と、募集を止めない形で範囲を示します。前に辞めた人が何につまずいたかを一つ聞き取り、「次の人の要件に、その一点を入れておきます」と、募集にすぐ効く形で返すと、定着の話が後回しになりません。範囲の伝え方は[業務範囲を書面で固める](/media/fukugyo-scope/)に、改善の伝え方は[改善提案の伝え方](/media/fukugyo-kaizen-teian/)に整理しています。

### 組織の調査（サーベイ）を提案してよいですか

最初は提案しません。人事の部門が小さい会社では、調査の設計と回収と分析に時間がかかり、結果が出る前に依頼側の期待が切れます。調査の代わりに、辞めた人と最近入った人の話を数人から聞き取り、つまずきの型を見つける形で始めます。聞き取りで見えた詰まりが、社員全員の傾向として確かめる必要があるものなら、そのときに調査を提案します。順番を逆にすると、組織開発の経験が「大きい会社のやり方」に見えます。聞き取りの型は[ヒアリングで押さえる項目](/media/fukugyo-hearing/)に、情報の扱いは[案件ごとの情報の分け方](/media/fukugyo-jouhou-bunri/)に書いています。

### 募集やスカウトの実務ができないと、案件が取れないのではないですか

募集の実務が薄いことは隠さず、「募集は御社の担当者か別の担当者が、私は要件と面接官の目線と受け入れを担います」と分担を示します。募集の実務が得意な担当者と組む形も、エラベルのような登録先では可能なことがあります。募集ができないことを補おうと実務を受けると、稼働が読めなくなり、得意な工程の成果も薄れます。採用は決まるのに辞める依頼側には、募集の実務より受け入れの設計が求められており、そこでは実務の薄さは弱みになりません。分担の型は[複数人で案件を受ける](/media/fukugyo-kyoudou-anken/)に、利益相反の見方は[本業と利益相反になる案件](/media/fukugyo-riekisouhan/)に整理しています。

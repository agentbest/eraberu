デザイナーにスカウトを送る前の検索で、「デザイナー経験〇年以上、〇〇（ツール）」で条件を組むと、プロダクトの画面を作ってきた人、サービスの体験を設計してきた人、ブランドを作ってきた人、広告や販促物を作ってきた人が、同じ一覧に出てきます。どれも「デザイナー」ですが、自社が作ってほしいものに合う人は一部です。もう一つ、ツールの一致は「そのツールを使える」以上を教えず、作品の質も進め方も分かりません。デザイナーの検索で最初にやるべきは、領域と位置づけを決め、ツールや年数ではなく「領域・担当した範囲・進め方・作品」で探し、作品を見て自社の課題と重なる一点があるかで読むことです。結論を先に書くと、**検索条件は、先に領域（何を作るか）と位置づけ（誰が決めるか）を決め、ツール名や年数ではなく経験（領域・担当した範囲・進め方・作品）で組み、要件の必須だけにし、作品を見て「自社の課題と重なる一点があるか」で読み、隣の領域からの転向層を含めて送る順を決めます**。文面の型は[デザイナーへのスカウト文面](/media/scout-designer-bunmen/)に、要件の作り方は[デザイナーの採用要件の作り方](/media/rpo-designer-youken/)に書いていますので、ここでは「検索条件とターゲティング」に絞ります。媒体ごとの検索の仕様には触れません。仕様は各媒体の公式情報でご確認ください。

## 先に「領域」と「位置づけ」を決める

自社が作ってほしいもの（領域）と、デザインを誰が決めるか（位置づけ）を決めます。領域で探す人が変わり、位置づけで合う人が変わります。

| 領域 | 作るもの | 探す経験 |
|---|---|---|
| プロダクトの画面 | アプリやWebの画面、導線 | 画面と導線を設計し、開発と一緒に出した経験 |
| サービスの体験 | 利用者の調査から体験全体の設計 | 調査から設計した経験。画面の前の段階 |
| ブランド | ロゴ、世界観、一貫した表現 | ブランドを作り、展開した経験 |
| 広告・販促物 | バナー、LP、印刷物 | 目的に合わせて作り、結果を見た経験 |

| 位置づけ | 合う人 |
|---|---|
| デザイナーが決める | 自分で決めて作ってきた人。要件の段階から入った人 |
| 要望を形にする | 要件を受けて形にしてきた人。決めたい人は合わない |
| 経営者の判断が大きい | 提案と修正を繰り返せる人。決めたい人は合わない |

止まりやすいのは、領域を決めずに「デザイン全般」で探すときです。一覧が混ざり、文面も混ざります。決め方は[デザイナーの採用要件の作り方](/media/rpo-designer-youken/)に書いています。

## ツール名や年数ではなく経験で組む

条件に入れるのは、ツール名や年数ではなく、要件の必須に当たる経験です。肩書は「または」で複数（UIデザイナー、UXデザイナー、プロダクトデザイナー、Webデザイナー、グラフィックデザイナー、アートディレクター）を入れるか、入れずにプロフィールの言葉で読みます。

| 要件 | 検索条件に | 理由 |
|---|---|---|
| 必須：〇〇（領域）の設計の経験 | 領域の言葉で（「画面」「導線」「体験」「調査」など） | 領域で経験が違う |
| 必須：開発と一緒に出した経験 | プロフィールで読む | 検索の言葉にしにくい |
| 歓迎：特定のツール | 入れない | 入社後に覚えられる。作品の質と関係ない |
| 歓迎：年数 | 入れない | 年数より領域と作品 |
| 歓迎：特定の業界 | 入れない | 文面で触れる |

止まりやすいのは、ツール名を「かつ」で複数入れて数人しか出ないときです。ツールを外し、領域と作品で読みます。

## 作品を見て「自社の課題と重なる一点があるか」で読む

デザイナーの検索で最も重要なのは、プロフィールの文章より作品です。公開されている作品（ポートフォリオ、担当したサービス）を開き、自社の課題と重なる一点があるかを見ます。重なる一点が、文面の一行目になります。

| 作品の見どころ | 読み方 |
|---|---|
| 領域 | 自社の領域と同じか、隣か |
| 担当した範囲 | 画面だけか、導線や体験からか、調査からか |
| 進め方 | 利用者の調査から入っているか。なぜそう設計したかが書いてあるか |
| 自社の課題との重なり | 自社が困っている点（迷わせる導線、伝わらない画面など）を、解いている作品があるか |
| 結果 | 作った後にどうなったか（利用者の反応、数字）が書いてあれば、結果を見る人 |

止まりやすいのは、作品を見ずにプロフィールの文章だけで判断するときです。文章が上手い人と、作品が良い人は一致しません。作品を見る時間を確保します。作品が公開されていない候補者は、経歴の領域と担当範囲と進め方で読みます。

### エラベルの見解

相談で最も多い思い込みは、「ツールが使える人を集めれば、あとは面接で見ればよい」というものです。実際には、ツールの一致で集めた一覧は領域が混ざり、作品を見ていないので一行目が書けず、送っても返信が来ません。ある会社では、ツール名と年数で検索し、出てきた人に同じ文面を送っていましたが、返信はほぼ無い状態でした。担当者が入って、自社の領域を「プロダクトの画面と導線」と決め、ツールを外し、「画面」「導線」「ユーザー」の言葉でプロフィールを読み、出てきた人の作品を開いて「自社の迷わせる導線と同じ課題を解いている一点」を探す形にしたところ、送る相手は減りましたが、一行目にその一点を書いて送ると返信が来ました。デザイナーの検索は、ツールで機械的に絞るより、領域で出して作品を人が見るほうが合います。

## 隣の領域からの転向層を含める

自社の領域の経験者が少ないなら、隣の領域から転向の素養がある人を含めます。転向元は領域で違います。

| 自社の領域 | 転向元 | 素養の見どころ |
|---|---|---|
| プロダクトの画面 | Webサイト、LPのデザイナー | 導線を意識して作っている。利用者の行動を書いている |
| サービスの体験 | プロダクトの画面のデザイナー | 画面の前の段階（調査、要件）に関わった記述 |
| ブランド | 広告・販促物のデザイナー | 一貫した表現を複数の媒体で作った経験 |
| 広告・販促物 | Webデザイナー | 目的に合わせて作り、結果を見た記述 |

転向層には、文面の一行目で「〇〇のご経歴から、〇〇に軸足を移したい方へ」と、転向であることに先に触れます。

止まりやすいのは、転向層に「同じ領域の経験者向け」の文面を送るときです。経歴と合わず、返信が来ません。

## 送る順の付け方

| 順 | 条件 |
|---|---|
| 一 | 領域と位置づけが自社と合い、作品に自社の課題と重なる一点があり、進め方が書いてある |
| 二 | 領域が合い、作品はあるが、重なる一点が探しにくい。担当範囲か進め方の一点で一行目を書く |
| 三 | 転向層。隣の領域で、導線や利用者の行動を意識した作品がある。転向の文面で送る |
| 送らない | 領域が遠い。位置づけが合わない（決めたい人に「要望を形にする」役割）。作品も経歴も一行目に書ける一点が無い |

止まりやすいのは、「ツールが合うから」で送るときです。領域と作品で順を付けます。

## 条件の保存と見直し

組んだ条件は、「画面用」「体験用」「転向層用」のように領域ごとに名前を付けて保存し、送った結果と一緒に記録します。月に一度、返信が来た人の共通点（領域、担当範囲、進め方、作品の傾向、転向元）を見て、条件と読み方を直します。保存の仕方は[検索条件の保存と使い回し](/media/scout-kensaku-hozon/)に書いています。

### エラベルの見解

担当する側から見ると、デザイナーの検索で会社ごとに差がつくのは、「自社の課題が具体に言葉になっているか」です。領域と位置づけは比較的決まりやすいのですが、「自社のデザインで何に困っているか」（迷わせる導線、伝わらない画面、ばらばらな表現）が言葉になっていない会社では、作品を見ても「重なる一点」が探せず、一行目が「作品を拝見しました」だけになります。課題が言葉になっている会社では、作品を見るときに探すものが決まり、一点が見つかり、文面も面談も一本につながります。エラベルでスカウトの検索を担当する人には、条件を組む前に、作るものを決める人に「いまのデザインで何に困っているか」を具体に聞いてもらっています。文面の型は[デザイナーへのスカウト文面](/media/scout-designer-bunmen/)に書いています。

## 代行に出す場合の範囲

担当者が持つのは、要件から必須の経験を取り出して条件を組むこと、出てきた人の作品を見て自社の課題と重なる一点を探すこと、転向層を分けて送る順を付けること、条件と結果を記録して月に一度見直すこと、です。会社が持つのは、領域と位置づけの決定、自社の課題を具体に伝えること、要件の必須と歓迎の区別、転向層をどこまで含めるかの判断、です。担当者が作品を見て判断できる経験があるか（デザインの領域の理解があるか）は、担当者を選ぶときに確かめます。担当者の経歴の見方は[担当者の経歴の見方](/media/rpo-tantousha-keireki/)に書いています。

## まとめ

- 先に**領域（何を作るか）と位置づけ（誰が決めるか）**を決める。領域で探す人が、位置づけで合う人が変わる
- 検索条件は**ツール名や年数ではなく経験（領域・担当範囲・進め方・作品）**で組む。ツールの一致は作品の質を教えない
- **作品を見て、自社の課題と重なる一点があるか**で読む。文章が上手い人と作品が良い人は一致しない
- **隣の領域からの転向層を含める**。転向の文面を分ける
- **領域が遠い人、位置づけが合わない人、一行目に書ける一点が無い人には送らない**
- 条件は**領域ごと・転向層用で分けて保存し、返信が来た人の共通点で月に一度直す**

## よくある質問

### 作品を一人ひとり見る時間がありません

見ないと一行目が書けず、送っても返信が来ないので、見る時間を確保するほうが結果として速い。全員を見る必要はなく、領域で絞った一覧の上から、月の送信数だけ見れば足ります。一通あたり、作品を開いて重なる一点を探すのに数分から十分程度を見込みます。その時間が取れないなら、送信数を減らします。

### ツールの経験が無い人でも大丈夫ですか

多くの場合、ツールは入社後に覚えられます。ツールより、領域と担当範囲と進め方と作品の質のほうが、入社後の仕事に効きます。自社が特定のツールでの共同作業を前提にしているなら、文面の環境の欄に書き、面談で確認します。検索条件には入れません。

### 位置づけが「要望を形にする」で、決めたい人が来ないのでは

正直に書いたうえで、要件のどの段階から入れるかを書きます。「要件は事業側が決めるが、要件を作る打ち合わせから入ってもらい、画面の構成はデザイナーが決める」のように。決めたい人は来ないかもしれませんが、要件を受けて質の高い形にすることに関心がある人は一定数います。位置づけを広く見せて面談で狭いと分かるほうが、辞退につながります。

「離職率が高い。分析してほしい」という依頼で、離職率を年度ごとに出し、「業界の平均と比べて高い」と報告しても、依頼側は「で、何を直せば」と止まります。離職率は一つの数字で、辞めた時期も、採用のどの段階のずれかも、理由も含んでいません。分析は、率を出すことではなく、「いつ・どこで・なぜ」を並べて、直す場所を一つに絞ることです。結論を先に書くと、**離職の分析は、辞めた時期・採用のどの段階のずれか・理由の分類の三つで並べ、時期は入社後の節目で分けて早期とそれ以降を別に読み、段階は要件・求人票・面接・内定後・受け入れ・その後の六つに分け、理由は退職面談の記録から傾向として分類して個人を特定せず、件数のまま並べて割合と外部の平均で断定せず、直す場所を一つに絞って依頼側が決める形で行います。**段階の分け方は[定着まで見る](/media/fukugyo-skill-teichaku/)と[早期離職が続くのは採用のどの段階の問題か](/media/rpo-souki-rishoku/)に、退職面談は[退職面談を設計する](/media/fukugyo-skill-exit-interview/)に書いています。ここでは、分析の型に絞ります。

## 離職率の一つの数字では直せない

| 率だけの報告 | 何が起きるか |
|---|---|
| 「今年の離職率は〇%」 | 高いか低いかの印象で終わる |
| 「業界の平均より高い」 | 依頼側の条件と違う比較。根拠を問われる |
| 年度ごとの推移 | 増えた減ったは分かるが、どこを直すかは分からない |
| 部門ごとの率 | 部門の責任者を責める材料になる |
| 「本人の事情」で片付く | 採用と受け入れの側に戻る材料が無い |

率は「結果」で、直す場所は「時期・段階・理由」の中にあります。率を出すなら、三つを並べた後の参考です。

## 並べる三つ

| 軸 | 分け方 | 見えること |
|---|---|---|
| 辞めた時期 | 入社後の節目（三か月以内・半年以内・一年以内・それ以降） | 早期は採用と受け入れ、それ以降は仕事と上司と見通し |
| 採用のどの段階のずれか | 要件・求人票・面接・内定後・受け入れ・その後 | 直す場所 |
| 理由の分類 | 仕事の中身・上司との関係・見通し（役割、処遇）・働き方・私的な事情・その他 | どの箇所か。「その後」の中の内訳 |

一人一行で、三つの軸を並べます。氏名は書かず、番号で。個人の事情の詳細は書かず、分類だけです。

### エラベルの見解

担当する側から見ると、離職の分析で最も差がつくのは、「早期」と「それ以降」を分けて読めるかです。受ける側は、全部の離職を一つに集計し、「上司との関係が多い」と結論します。ただ、入社三か月以内の離職の多くは、要件・求人票・面接・内定後・受け入れのずれで、上司との関係が理由に見えても、原因は「聞いていた仕事と違った」にあります。一年以降の離職は、仕事の中身と見通しが原因のことが多く、直す場所は等級と評価と役割です。二つを混ぜると、直す場所が両方に散り、どちらも動きません。エラベルで担当者を選ぶ企業には、「離職を、入社後の時期で分けて見ていますか」を、私たちから先に聞いています。受ける側がその場で使える判断としては、一行目に「時期」の列を置き、まず「早期」だけで三つの軸を読み、次に「それ以降」を読むこと。

## 早期の離職：段階で読む

| 段階 | 見分ける問い | 直す場所 |
|---|---|---|
| 要件 | 面接では全観点「通す」だったのに、仕事が回らなかった | [採用要件を引き出すヒアリングの型](/media/fukugyo-skill-youken-hearing/) |
| 求人票 | 「聞いていた仕事と違った」。任せる仕事や一緒に働く人の記述と実態の差 | [求人原稿を書き直す手順](/media/fukugyo-skill-kyujin-genkou/) |
| 面接 | 「迷う」が引き継がれずに通った。基準に無い理由で通した | [面接の設計](/media/fukugyo-skill-mensetsu-sekkei/) |
| 内定後 | 入社前に迷いが残っていた。接点が無かった | [内定辞退を減らす](/media/fukugyo-skill-jitai-boushi/) |
| 受け入れ | 到達点と担当が無く放置された | [オンボーディングを設計する](/media/fukugyo-skill-onboarding/) |

早期の離職の記録は、採用の記録（評価シート、オンボーディングの接点）に戻って読みます。記録が無ければ、「今後の採用から記録する」を提案し、推測で段階を決めません。

## それ以降の離職：理由の分類で読む

| 分類 | 中身 | 直す場所 |
|---|---|---|
| 仕事の中身 | 役割が固定、幅が広がらない、期待が不明 | 等級の期待、目標管理 |
| 上司との関係 | 接点が無い、評価に納得していない | 1on1、評価制度 |
| 見通し | 次の役割が見えない、処遇の上がり方が見えない | 等級と給与テーブルの上がり方 |
| 働き方 | 勤務の形、負荷 | 依頼側の制度と労務。専門家の領域を含む |
| 私的な事情 | 家族、転居、健康など | 直す場所は無い。記録は分類だけ |
| その他 | 上に当たらないもの | 分類を見直す材料 |

理由は退職面談の記録から拾い、傾向として分類します。「私的な事情」に片付けるのは、上の分類を確かめた後です。分類の元になる面談の型は[退職面談を設計する](/media/fukugyo-skill-exit-interview/)に書いています。

## 件数のまま並べ、断定しない

| 断定する書き方 | 置き換え |
|---|---|
| 「離職率が〇%で高い」 | 「今年の離職は〇件。うち早期が〇件、それ以降が〇件」 |
| 「業界平均より高い」 | 外部の数値を持ち込まない。依頼側の前年と比べる |
| 「〇部門の離職率が高い」 | 「〇部門で、それ以降の離職が〇件、理由は見通しが多い」。順位にしない |
| 「上司が原因」 | 「上司との関係が理由の分類に〇件。接点の有無を確かめる」 |

件数が少ないほど、割合は揺れます。件数のまま並べ、前年と比べ、傾向として読みます。数字の伝え方は[数字で語る](/media/fukugyo-suuji/)に、分析の問いの立て方は[採用データを分析する](/media/fukugyo-skill-data-bunseki/)に書いています。

### エラベルの見解

相談で最も多い思い込みは、受ける側の「離職の分析は、辞めた人の問題を見つけるもの」というものです。実際には、辞めた人の問題を見つけても、その人はもういません。分析が役に立つのは、「いまいる人が同じ場所で辞めないように、直す場所を一つ決める」ときです。早期の離職が要件のずれなら、要件の一枚を直す。それ以降の離職が見通しなら、等級の上がり方を直す。直す場所は一つに絞り、決めるのは依頼側です。受ける側がその場で使える判断としては、分析の一枚の最後に「直す場所：一つ」と「その根拠：三つの軸のどこか」を書き、二つ以上書きたくなったら、件数の多いほうを先にすること。

## 依頼側に渡す一枚

| 欄 | 中身 |
|---|---|
| 期間と件数 | いつからいつまで、離職が何件。前年の件数 |
| 時期の内訳 | 早期・それ以降の件数 |
| 早期の段階の内訳 | 六つの段階の件数。記録が無く分からない件は「不明」 |
| それ以降の理由の内訳 | 分類ごとの件数 |
| 直す場所 | 一つ。根拠 |
| 次に見ること | 直した後、次の期間の同じ一枚で何が変わるか |
| 記録の欠け | 退職面談の記録、採用の記録が無い件数 |

部門ごとの内訳を出す場合は、順位にせず、件数と理由の分類だけにします。部門の責任者を責める材料にならない形で、依頼側の決まりに従って共有の範囲を決めます。

## 離職の情報の扱い

| 決めること | 中身 |
|---|---|
| 一枚に書かないもの | 氏名、退職の個別の事情、健康や家族の詳細、上司の名前 |
| 退職面談の記録 | 依頼側の人事が扱う。担当者は分類の結果だけを受け取る |
| 共有の範囲 | 経営者と人事。部門の責任者には自部門の傾向だけ、依頼側の決まりで |
| 担当者の手元 | 一枚（件数と分類）だけ。個人の記録を置かない。終了時に消す |

退職者の情報は、個人情報の中でも扱いに注意が要るものです。扱いは[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に書いています。退職や解雇の場面そのものへの関わりの線は[退職や解雇の場面への関わり方](/media/fukugyo-taishoku-kanyo/)に書いています。

## よく起きる詰まりと直し方

| 詰まり | 直し方 |
|---|---|
| 依頼側が離職率だけを求める | 率は参考の一行に。三つの軸の一枚を主に |
| 退職面談の記録が無い | 「今後の退職から記録する」。過去は分類「不明」 |
| 早期とそれ以降が混ざっている | 時期の列を先頭に。別々に読む |
| 「本人の事情」が多い | 上の分類を確かめてから。面談の型を見直す |
| 部門の順位が出て責任者が責められる | 順位にしない。件数と分類だけ |
| 直す場所が複数 | 件数の多いほうを先に一つ。残りは次の期間 |

## まとめ

- 離職率の一つの数字では**直す場所が分からない**
- 並べるのは**時期・段階・理由の分類**の三つ。一人一行、氏名は書かない
- **早期とそれ以降は原因が違う**。別々に読む
- 早期は**要件・求人票・面接・内定後・受け入れ**の段階で、採用の記録に戻って読む
- それ以降は**理由の分類**で。「私的な事情」は最後
- **件数のまま並べ、割合と外部の平均で断定しない**。順位にしない
- **直す場所は一つ**。決めるのは依頼側
- 個人の記録を担当者の手元に置かない

## よくある質問

### 依頼側から「離職率を業界と比べてどうか教えてほしい」と言われました

外部の数値は、依頼側の職種・規模・雇用の形と条件が違い、比較の根拠になりません。「御社の前年と比べ、時期と段階と理由で読むほうが、直す場所が分かります」と、比較の対象を依頼側の中に変えます。外部の数値を担当者が持ち込むと、根拠を問われて答えられず、「高い・低い」の印象で議論が止まります。

### 離職が年に数件しか無く、傾向が読めません

数件でも、一件ずつ「時期・段階・理由」で並べれば、直す場所は見えます。「三件のうち二件が早期で、どちらも求人票と実態の差」なら、求人票を直す根拠になります。傾向を待たず、一件ずつの事実で読みます。件数が少ないことは、割合で語れないことを意味するだけで、分析できないことではありません。

### 分析の結果、特定の上司の部下が多く辞めていると分かりました

上司の名前を一枚に書かず、「〇部門で、それ以降の離職が〇件、理由は上司との関係と見通し」と、部門と分類で示します。直す場所は「その上司」ではなく、「1on1の型」「評価の面談の型」「等級の期待の伝え方」など、上司が回せる仕組みの側に置きます。上司個人への対応（配置、指導）は依頼側の人事の判断で、担当者は仕組みの案を出すまでです。仕組みの型は[1on1を設計する](/media/fukugyo-skill-1on1/)に書いています。

毎週スカウトを送り、返信に対応し、日程を組み、月末に報告する。回ってはいるが、「何のために、いつまでに、どこまで」が無く、依頼側の担当者も「毎月お願いしていること」としか社内で説明できない。更新のたびに「続けますか」と聞かれる。結論を先に書くと、**案件を「毎月同じことを回す」形から一段上げるには、「目的」「期限」「工程」「役割」「節目」の五つを持つプロジェクトとして組み直します。プロジェクトとして組むと、依頼側の担当者が社内で「〇月までに〇〇を整えるプロジェクト」と説明でき、範囲と成果の話が楽になり、更新は「続けるか」ではなく「次のプロジェクトは何か」になります。**副業の枠でも、五つの要素は一枚で書け、大きな仕組みは要りません。成果の定義は[成果をどう定義しておくか](/media/fukugyo-seika-teigi/)に、短期と中長期の配分は[短期成果と中長期施策のバランス](/media/fukugyo-tanki-choki/)に、改善を回す形は[改善を回す](/media/fukugyo-kaizen/)にまとめています。

## プロジェクトとして組む利点

「毎月同じことを回す」形と、プロジェクトとして組む形で、依頼側と自分にとって何が変わるかを見ます。

| 項目 | 毎月同じことを回す | プロジェクトとして組む |
|---|---|---|
| 依頼側の担当者の社内での説明 | 「外部に毎月お願いしている」 | 「〇月までに〇〇を整えるプロジェクトを外部と進めている」 |
| 成果の見え方 | 稼働の量。「今月も送った」 | 目的に対する進み。「〇〇が整った、次は△△」 |
| 更新の判断 | 「続けるか、やめるか」 | 「このプロジェクトが終わったら、次は何をするか」 |
| 範囲の扱い | 曖昧になりやすい。「ついでに」が入る | 工程で決まっているので、工程外は「次のプロジェクトで」と言える |
| 自分の稼働の見通し | 毎月同じだが、いつまで続くか分からない | 期限と節目があり、山と谷が読める |
| 実績の残り方 | 「〇か月担当した」 | 「〇〇を〇か月で整えた」 |
| 終わり方 | なし崩し | 目的を達して終わる。次につながる |

利点の要点は、「依頼側の担当者が社内で説明できる」ことです。担当者は、外部に頼んでいることを上長に説明する立場にあり、「毎月お願いしている」では、上長に「何のために」と聞かれます。「〇月までに〇〇を整える」と言えれば、上長は目的と期限で判断でき、予算も続きます。担当者の社内での立場は[外部の立場だからできること](/media/fukugyo-gaibu-tachiba/)に書いています。

## 五つの要素の決め方

プロジェクトの五つの要素を、副業の案件に合わせて決めます。一枚に収まる大きさにします。

| 要素 | 内容 | 決め方の要点 |
|---|---|---|
| 一、目的 | このプロジェクトで、依頼側の採用の何を、どういう状態にするか | 「採用を良くする」ではなく「スカウトの返信から面接の設定までの流れを、型として回る状態にする」のように、状態で書く。自分の範囲の出口と一致させる |
| 二、期限 | いつまでに、その状態にするか | 契約の期間に合わせる。三か月の契約なら三か月。長い目的は、三か月ごとの段階に分ける |
| 三、工程 | 目的に至るまでの、順番のある作業のまとまり | 三つから五つ。「現状の把握→文面の型→相手の絞り方→返信の対応の型→面接の設定の流れ」のように |
| 四、役割 | 各工程で、自分がやること、依頼側がやること | 依頼側の役割（面接官の時間の確保、要件の決定、承認）を明示する。自分だけのプロジェクトにしない |
| 五、節目 | 途中で進みを確認する時点 | 月に一度の定例か、工程の終わりごと。節目で「進んでいるか、直すか」を依頼側と見る |

五つの要点は、「四」の役割に、依頼側の役割を明示することです。プロジェクトを自分だけのものにすると、依頼側の側で止まったときに、自分の遅れに見えます。「面接官の時間の確保は御社の役割」と最初に書いておけば、止まった場所が明確になり、責めずに事実として示せます。役割の分け方は[権限がないと動けない場面](/media/fukugyo-kengen-nai/)に、依頼側の側で止まる場面の示し方は[成果が見えない](/media/fukugyo-shippai-4/)に整理しています。

### エラベルの見解

相談で最も多い思い込みは、「副業の稼働では、プロジェクトのような大きな進め方はできない」というものです。実際には、プロジェクトとして組むのに要るのは、五つの要素を一枚に書くことだけで、稼働の量は関係ありません。週に数時間の案件でも、「三か月で、候補者への一次対応と日程調整の型を、依頼側の社内で回る状態にする」という目的と期限と工程があれば、それはプロジェクトです。逆に、稼働が多くても、目的と期限が無ければ、毎月の作業の繰り返しです。

見ていて差がつくのは、契約の最初に「この期間で何を整えるか」を依頼側と決めているかです。決めている人は、更新のときに「〇〇が整ったので、次は△△を整えるプロジェクトを」と提案でき、依頼側の担当者も社内で「次のプロジェクト」として説明できます。決めていない人は、更新のときに「続けますか」と聞かれ、稼働の質に関わらず、依頼側の予算の都合で終わることがあります。エラベルでは、依頼側と担当者の契約を、期間と目的を持つ形で整えることを勧めています。プロジェクトとして組むことは、担当者の稼働を「作業」から「成果に向かう工程」に変えます。

## 依頼側との合意の形

五つの要素は、自分の中で決めるだけでなく、依頼側と合意し、一枚にして共有します。

| 合意の項目 | 依頼側に伝える形 |
|---|---|
| 目的 | 「この三か月で、〇〇を△△の状態にすることを目的にしたいです。御社の採用で、まずここが整うと、次に進めます」 |
| 期限 | 「契約の期間に合わせて、〇月末を期限にします。途中の節目で進みを確認します」 |
| 工程 | 「工程はこの順番で進めます。最初の数週間は現状の把握と型づくりで、目に見える結果は〇週目から出る見込みです」 |
| 役割 | 「私の役割は〇〇で、御社には△△をお願いします。特に□□は、御社の判断が要る工程です」 |
| 節目 | 「月に一度の定例で、工程の進みと、直すべき点を確認したいです」 |
| 一枚 | 五つを一枚にまとめ、議事録に添えて共有する。依頼側の担当者が社内に回せる形 |

合意の要点は、「工程の中で、目に見える結果が出る時期を先に伝える」ことです。プロジェクトの最初の工程は、現状の把握や型づくりで、結果が見えません。それを伝えずに始めると、依頼側は「何も動いていない」と感じます。「〇週目から結果が出る見込み」と先に言えば、その前の期間が「準備」として理解されます。期待のすり合わせは[期待値のすり合わせ](/media/fukugyo-kitai-chousei/)に、最初の数週間の進め方は[早い段階で成果を出す](/media/fukugyo-quick-win/)に書いています。

## 工程と節目の置き方

工程は順番があり、節目で進みを見ます。副業の枠に合う置き方があります。

| 工程の例（スカウトの運用の型づくり） | 期間の目安 | 節目で見ること |
|---|---|---|
| 一、現状の把握 | 最初の数週間 | 依頼側の記録から、返信の割合、辞退の理由、日程の確定までの日数が分かったか。[現状把握のしかた](/media/fukugyo-genjou-haaku/) |
| 二、文面と相手の絞り方の型 | 次の数週間 | 型が文書になり、送り始めたか。返信の変化が出始めたか |
| 三、返信の対応と日程調整の型 | 次の数週間 | 候補者への対応の型が回り、日程の確定までの日数が縮んだか |
| 四、面接の設定の流れ | 次の数週間 | 面接官の枠が固定され、設定が増えたか |
| 五、型の文書化と引き継ぎ | 最後の数週間 | 型が依頼側の共有にあり、自分がいなくても回る状態か。[いつ辞めても困らない状態を作る](/media/fukugyo-hikitsugi-junbi/) |

置き方の要点は、「五」の型の文書化と引き継ぎを、最後の工程として最初から入れておくことです。プロジェクトの目的は「型が回る状態にする」ことで、その状態には「自分がいなくても回る」が含まれます。最後の工程で型を依頼側に残せば、プロジェクトは終わり、次のプロジェクト（次の工程の型づくり）に移れます。型を残さないと、プロジェクトは終わらず、毎月の作業に戻ります。節目の定例の進め方は[定例会の進め方](/media/fukugyo-teirei-shinkou/)に整理しています。

## 途中で崩れたときの立て直し

プロジェクトは、途中で崩れます。崩れ方に応じて、立て直します。

| 崩れ方 | 立て直し |
|---|---|
| 工程が遅れている | 節目で事実を伝え、期限を動かすか、工程を減らすか、依頼側と決める。黙って遅らせない。[遅れそうなときの連絡](/media/fukugyo-okure-renraku/) |
| 依頼側の役割の工程で止まっている | 「〇〇の工程は御社の役割で、ここで止まっています」と事実で示し、依頼側の判断を仰ぐ。責めない |
| 候補者の山が来て、工程が止まった | 山の対応を優先し、工程は山が過ぎてから。節目で「山の分、工程が〇週遅れる」と伝える |
| 目的がずれてきた | 依頼側の採用の方針が変わったなら、目的を見直す。節目で「目的をこう変えたい」と提案する |
| 本業の都合で稼働が落ちた | 工程を減らすか、期限を延ばす。「稼働が合わなくなったら」の四つで調整。[稼働が合わなくなったら](/media/fukugyo-qa-12/) |
| 依頼側の担当者が替わった | 新任に一枚を見せ、目的と工程と役割を合意し直す。前任との合意は引き継がれていない |

立て直しの要点は、「節目で直す」ことです。節目が無いと、崩れに気づくのが遅れ、直す時期を失います。月に一度の節目で、工程の進みと崩れを見て、その場で直す。直せない崩れは、期限か工程か目的を変えることで、プロジェクトの形を保ちます。

## プロジェクトの終わり方

プロジェクトは、目的を達したら終わります。終わり方が、次につながります。

| 終わり方 | 内容 |
|---|---|
| 目的を達して終わる | 「〇〇が△△の状態になった」を、記録の事実で示し、依頼側と確認する。一枚に「完了」を書く |
| 次のプロジェクトを提案する | 「〇〇が整ったので、次は△△を整えるプロジェクトを」と、更新の二か月前に提案する。[更新時の条件見直し](/media/fukugyo-keiyaku-koushin-koushou/) |
| 維持に移る | 型が回っているので、稼働を減らして維持する形に。範囲と稼働と単価を見直す |
| 依頼側の社内に渡して終わる | 型が依頼側の社内で回るなら、契約を終える。「自走する状態になった」は、依頼側にとって最も価値のある終わり方。次の紹介につながる |
| 目的を達せずに終わる | 期限が来て達していないなら、「どこまで進み、何が残ったか」を一枚にし、残りを次のプロジェクトにするか、終えるかを依頼側と決める |

終わり方の要点は、「達せずに終わるときも、一枚にする」ことです。達していないことを曖昧にして更新すると、次のプロジェクトも曖昧になります。「工程の三まで進み、四と五が残った。残った理由は〇〇」と事実で示し、残りをどうするかを依頼側と決めれば、次のプロジェクトは明確になります。終了時の整理は[引き継ぎの進め方](/media/fukugyo-hikitsugi/)に、次の案件への広げ方は[次の案件へ広げる](/media/fukugyo-tsugi-e/)に書いています。

## 副業の枠に収める工夫

プロジェクトとして組むことが、副業の枠を超える負担にならないための工夫です。

| 工夫 | 内容 |
|---|---|
| 一枚で済ませる | 五つの要素は、一枚の文書で足りる。管理のツールや詳細な計画は要らない |
| 工程は三つから五つ | 細かく分けない。副業の枠で、一つの工程に数週間 |
| 節目は既存の定例に乗せる | 節目のための会議を増やさない。月に一度の定例の中で、工程の進みを見る |
| 稼働報告と一体にする | 月次の稼働報告に、工程の進みを一行足す。別の報告を作らない。[稼働報告のフォーマット](/media/fukugyo-kadou-houkoku/) |
| 期限は契約の期間に合わせる | 契約と別の期限を作らない。三か月の契約なら三か月のプロジェクト |
| 目的は自分の範囲の出口に一致させる | 範囲を超える目的にしない。目的が範囲を超えると、稼働も超える |

工夫の要点は、「既存のもの（契約の期間、定例、稼働報告）に乗せる」ことです。プロジェクトのために新しい仕組みを作ると、副業の枠を圧迫します。契約の期間を期限に、定例を節目に、稼働報告に工程の進みを一行足す。それだけで、案件はプロジェクトになります。

### エラベルの見解

担当する側から見ると、更新が「次は何をするか」の形で続いている人は、案件をプロジェクトとして組んでいます。契約の最初に「この期間で何を整えるか」を依頼側と決め、工程と役割を一枚にし、節目で進みを見て、目的を達したら型を依頼側に残して次のプロジェクトを提案する。依頼側の担当者は、それを社内で「次のプロジェクト」として説明でき、予算が続いています。毎月同じことを回している人は、稼働の質が同じでも、「続けますか」と聞かれ、依頼側の都合で終わっています。

順番として、契約の最初に目的を自分の範囲の出口で決め、期限を契約の期間に合わせ、工程を三つから五つに分け、依頼側の役割を明示し、節目を定例に乗せ、一枚にして共有し、節目で直し、目的を達したら型を残して次を提案する。この順番で、副業の案件は作業の繰り返しではなく、成果に向かう工程になります。エラベルでは、依頼側と担当者の契約を、期間と目的を持つプロジェクトの形で整えることを勧めています。プロジェクトとして組むことは、担当者の稼働を、依頼側が社内で説明できる価値に変えます。

## まとめ

- 「毎月同じことを回す」から一段上げるには**目的・期限・工程・役割・節目**の五つを持つプロジェクトとして組む
- 利点は**依頼側の担当者が社内で説明でき、成果が目的に対する進みで見え、更新が「次は何か」になる**
- 目的は**自分の範囲の出口と一致する状態**で書き、期限は**契約の期間**に、工程は**三つから五つ**、役割は**依頼側の役割を明示**、節目は**定例に乗せる**
- 合意では**目に見える結果が出る時期を先に伝える**
- 最後の工程に**型の文書化と引き継ぎ**を入れる。型を残せばプロジェクトは終わり、次に移れる
- 崩れたら**節目で直す**。達せずに終わるときも**一枚にして残りを決める**
- **既存の契約・定例・稼働報告に乗せ**、新しい仕組みを作らない

## よくある質問

### 依頼側が「プロジェクト」という言葉を大げさに感じそうです

言葉は使わなくて構いません。「この三か月で〇〇を整える」と、目的と期限を伝えるだけで、中身はプロジェクトです。依頼側の担当者が社内で使いやすい言葉（「取り組み」「整備」など）に合わせます。大切なのは言葉ではなく、目的・期限・工程・役割・節目が一枚にあり、依頼側と合意されていることです。

### 型づくりのようなまとまった目的が無く、日々の対応だけの案件です

日々の対応だけの案件でも、「三か月で、候補者への対応の型を依頼側の社内で回る状態にする」という目的は置けます。対応そのものが目的ではなく、対応の型が残ることを目的にすれば、日々の作業がプロジェクトの工程になります。型が残れば、自分の稼働を減らして維持に移るか、次の工程（面接の設定の流れなど）に広げるかを、依頼側と決められます。数字に出ない業務の見せ方は[成果が数字に出ない業務の見せ方](/media/fukugyo-seika-mienai/)に整理しています。

### 契約の途中からプロジェクトの形にできますか

できます。更新の節目が最も自然で、「次の期は、〇〇を整えることを目的に、この工程で進めたい」と提案します。節目まで遠いなら、定例で「残りの期間で、〇〇を整えることを目的にしたい」と切り出し、一枚にして共有します。途中からでも、目的と期限と工程が決まれば、その時点からプロジェクトになります。提案の出し方は[提案を出すタイミング](/media/fukugyo-teian-timing/)に書いています。

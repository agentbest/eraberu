ATS（採用管理システム）導入の支援を初めて受けるとき、見えにくいのは「設定の前に何を決め、設定の後に何をすれば使われるか」です。募集文には「ATS導入支援」とだけあり、実際には、集めたいものを一つに絞る、比べる材料、個人情報の方針、権限の範囲と期間、設定の承認、移行の時期と並行期間、手順書、面接官への一枚と同席、併用の解消、権限の返却と、設定の前後に工程が並びます。順番を知っていれば、契約前に決めておけます。結論を先に書くと、**1案件は「契約前→第1週→設定と移行→手順書と面接官への展開→最初の一か月の定着→引き継ぎと終了」の六つの段階で進み、契約前に範囲・集めたいもの・製品の決定者と契約・個人情報の方針・権限の範囲と期間・移行の時期・面接官への依頼・終わりの定義を決め、第1週は設定せずに集めたいものを一つに絞って比べる材料と設定の案と移行の計画を作り、承認された設定だけを入れて進行中の候補者を落とさず移し、三つの画面の手順書と面接官への一枚を作って同席し、一か月で併用を解消して書かない面接官に対応し、運用のルールと担当を引き継いで権限を返して終えます。**案件の型と求められる経験は[ATS導入の支援の副業案件](/media/fukugyo-ats-dounyu-fukugyo/)に、ATSの扱い方は[採用管理システムの技能](/media/fukugyo-ats-skill/)に書いていますので、ここでは「1案件の流れ」に絞ります。

## 契約前：決めておくこと

ATSの導入は、契約と個人情報と権限が絡み、「設定が終わったら終わり」と「使われるまで」で範囲が倍違います。契約前に決めます。

| 決めること | 確かめる中身 | 決めていないと起きること |
|---|---|---|
| 範囲 | 選定の材料だけか、設定と移行か、手順書と面接官への展開と定着か、運用の引き継ぎか | 「使われるようにしてほしい」が後から足される |
| 集めたいもの | 最初に無くしたい困りごと（状況が見えない、判定が集まらない、集計に時間、外部への権限）のうち一つ | 「全部できる製品」を探して、全部設定して、誰も使わない |
| 製品の決定者と契約 | 製品を決めるのは誰か。契約と料金の確認は会社。製品の営業との窓口を自分が持つか | 自分が製品を決めた形になる |
| 個人情報の方針 | 応募者の情報をATSに置くことの社内の方針。保存の期間。誰が見られるか。移行のデータを自分の端末に置かないこと | 方針の無いまま個人情報を移す。専門家にご確認ください |
| 権限の範囲と期間 | 設定に管理者権限が要るなら、期間と、終了時に削除すること。ユーザーの追加と削除は会社 | 権限を持ち続ける。自分でユーザーを増やせる |
| 移行の時期 | 落ち着いた時期か。進行中の候補者の扱い。並行期間の長さと終わりの日 | 忙しい時期に移行して候補者を落とす |
| 面接官への依頼 | 面接官に「一つの画面で判定を書く」ことを、会社の責任者から依頼してもらえるか | 外の人が頼んでも面接官が動かない |
| 終わりの定義 | 「設定が終わった日」か「表計算を止めた日」か。評価の基準 | 設定で終わり、使われない |

止まりやすいのは、「まず製品を比べてください」で始めるときです。集めたいものが決まっていない比較は、機能の多さの比較になります。範囲の決め方は[業務範囲の決め方](/media/fukugyo-scope/)に、見積もりの出し方は[見積もりの出し方](/media/fukugyo-mitsumori/)に書いています。

## 第1週：設定しない週

第1週は、設定を始めません。集めたいものを一つに絞り、比べる材料（製品が決まっていない場合）と、設定の案と、移行の計画を作ります。

| やること | 依頼側に持ってもらうこと | 落とし穴 |
|---|---|---|
| 集めたいものを一つに（最初に無くしたい困りごとを、人事と面接官と経営者に聞く） | 決める人 | 「全部」のまま |
| いまの流れを見る（応募からどこに情報が入り、誰が見て、どこで止まるか。表計算とメールとチャットの現状） | いまの表計算と記録の共有 | 現状を見ずに製品の流れに合わせる |
| 比べる材料（製品が未定なら。選考の流れを変えられるか、権限を閲覧と編集と項目で分けられるか、媒体連携、連絡のテンプレート、集計、書き出し。確認した日付） | 製品の決定。料金は公式で確認 | 特定の製品を推す。料金を書く |
| 設定の案（段階の名前と数、候補者の詳細の項目、通知。既定のまま使わない。分析と自動化は後） | 設定の承認 | 全部の機能を設定する案 |
| 移行の計画（移すデータの範囲、進行中の候補者の扱い、並行期間、止める日） | 移行の時期の決定 | 進行中の候補者を移し忘れる |
| 権限の受け取り（専用のアカウント、範囲、期間） | アカウントの発行 | 共有アカウントで入る |

止まりやすいのは、「製品はもう決まっているから、すぐ設定して」と急かされるときです。集めたいものと段階の名前が決まっていない設定は、あとで作り直します。会社側の選び方は[ATSの選び方](/media/rpo-ats-erabikata/)に書いています。

### エラベルの見解

担当する側から見ると、この仕事は「第1週に、いまの表計算を一緒に見られるか」で、その後の設定の質が決まります。表計算には、その会社が実際に何を追っているか（段階の名前、面接官が書いている欄、止まる箇所）が全部残っています。それを見ずに製品の既定の流れで設定したATSは、表計算と合わず、併用が続きます。表計算の列をそのまま段階と項目に写す形で設定したATSは、人事が迷わず移れます。エラベルで担当者を選ぶ企業には、「最初の一週間で、いまの表計算を見せてください。その列がそのまま設定の案になります」と、私たちから先に伝えています。受ける側がその場で使える判断としては、設定の案を「表計算の列→ATSの項目」の対応表の形で作ること。対応表があれば、承認も早く、移行のときの転記の漏れも防げます。

## 設定と移行：承認された設定だけ、候補者を落とさない

承認された設定の案だけを入れます。設定の途中で「便利そうだから」と機能を足しません。移行は、進行中の候補者を一人も落とさないことを最優先にします。

| やること | 決まり | 落とし穴 |
|---|---|---|
| 設定（段階の名前と数、項目、通知、テンプレート、権限の役割） | 承認された案のとおり。既定のまま残さない。分析と自動化は入れない | 承認の無い機能を足す。既定の段階が残る |
| 権限の役割（人事、面接官、外部、閲覧のみ） | 閲覧と編集と項目で分ける。ユーザーの追加は会社が行う | 全員を管理者にする |
| 移行するデータの範囲（進行中の候補者は全員。過去の応募者は方針に従って） | 個人情報の方針と保存の期間に従う。会社の管理する場所でだけ作業 | 過去の全員を移して保存の方針とずれる |
| 進行中の候補者の移行（段階、次の予定、面接官、連絡の履歴） | 一人ずつ確認。移した日を記録 | 段階を間違えて連絡が二重に出る |
| 並行期間（表計算とATSの両方に入れる期間） | 短く。終わりの日を最初に決める。正はATS | 並行が続き、正が分からなくなる |
| 移行後の確認（進行中の全員がATSにいるか。次の予定が入っているか） | 人事と一緒に一覧で確認 | 確認せずに表計算を止める |

止まりやすいのは、並行期間の終わりの日を決めずに始めることです。「念のため」の表計算は、期限が無いと永久に残ります。個人情報の扱いは[候補者の個人情報の扱い](/media/fukugyo-kojin-jouhou/)に、権限の扱いは[アカウントの管理](/media/fukugyo-account-kanri/)に書いています。

## 手順書と面接官への展開：三つの画面、一つの画面

設定が終わったら、使う人ごとに、見る画面を絞って渡します。全部の機能を教えません。

| 使う人 | 渡すもの | 中身 |
|---|---|---|
| 人事（毎日使う人） | 三つの画面の手順書（一枚） | 応募者の一覧（毎朝見る）、候補者の詳細（段階を進め、記録を書く）、連絡の送信（テンプレートから） |
| 面接官 | 一枚（リンクと書く内容） | 判定を書く一つの画面へのリンク、書く項目（絞る）、いつまでに書くか。面接の案内にリンクを入れる |
| 経営者や責任者 | 見る画面（一つ） | 集計か一覧の一画面。設定は触らない |
| 外部の担当者（スカウトや書類選考） | 範囲の画面と権限 | 触ってよい工程と項目。見えるが触らない範囲 |

面接官には、最初の数回、同席します。書く画面を開いて、書く項目を一緒に確認し、その場で書いてもらいます。書かなかった面接官には、責めずに、口頭で聞いて転記し、「次はここに」と一枚を渡し直します。手順書の作り方は[ATSを使いこなせない会社](/media/rpo-ats-tsukaikonasenai/)に書いています。

### エラベルの見解

同じ料金・同じ製品でも、結果が分かれるのは、「面接官への一枚を、面接の案内に組み込めるか」です。面接官に手順書を渡して「使ってください」で終えた担当者のATSは、三か月後、面接官の判定が入っておらず、人事が口頭で聞いて表計算に書いています。面接の案内（日程の確定の連絡）に判定の画面へのリンクを入れ、面接の直後に「こちらに三行で」と一言添え、最初の三回は同席し、書かなかった分は転記して見せた担当者のATSは、面接官が自分で書くようになります。面接官は忙しく、探す手間が一つあると書きません。リンクを目の前に置くことが、定着の最大の工夫です。エラベルで長く続いている担当者は、面接官への一枚を「案内の文面の一部」として作っています。受ける側がその場で使える形としては、面接の日程の確定の連絡の型に、判定の画面へのリンクと「面接後にこの三項目を」の一文を最初から入れておくことです。

## 最初の一か月の定着：併用の解消、書かない面接官、集計の初回

導入後の一か月が、使われるかどうかの分かれ目です。

| 見ること | やること |
|---|---|
| 表計算との併用 | 残っている理由を確認し、列をATSに移し、判定を統一し、止める日を全員に伝えて止める |
| 書かない面接官 | 責めずに口頭で聞いて転記。一枚を渡し直す。項目を減らす。責任者からの依頼を再度 |
| 段階の名前と実態のずれ | 使ってみて合わない段階の名前を、会社の承認を得て直す |
| 通知の多さ | 多すぎる通知を減らす。少なすぎて見ない通知を増やす |
| 集計の初回 | 一か月の応募・面接・内定・辞退を、ATSから出して見せる。表計算を止めた効果を示す |
| 権限の実態 | 増えたユーザー、管理者になっている人を会社と確認 |

止まりやすいのは、一か月の途中で「もう使えているから」と手を離すときです。併用が残っていれば、二か月目に表計算が正に戻ります。止めた日を確認してから手を離します。

## 引き継ぎと終了：運用のルール、担当、権限の返却

終了時に、運用のルールを文書にし、担当を決めてもらい、自分の権限を返します。

- **残すもの。** 三つの画面の手順書、面接官への一枚、入力のルールと状態の定義、設定の一覧（段階、項目、通知、権限の役割）、更新の担当、集計の取り方、ユーザーの追加と削除の手順（会社が行う）
- **返すもの。** 管理者権限、専用アカウント（会社が削除）、移行の作業用のファイル（会社の管理のもとで削除）。応募者の情報を自分の端末に一切残さない
- **次の提案。** 運用を社内で回すか、[ATSの運用代行](/media/rpo-task-ats-unyou-daikou/)として別の範囲で続けるか、会社に決めてもらう

止まりやすいのは、権限を返さずに「何かあったら見ます」と残すときです。終了後にログインできる状態は、個人情報の管理の上で問題になります。終了の日に、会社にアカウントを削除してもらい、削除されたことを確かめます。引き継ぎの型は[引き継ぎの仕方](/media/fukugyo-hikitsugi/)に書いています。

## 個人情報の扱い

ATSの導入では、応募者の情報をまとめて移します。移行のデータは、会社の管理する場所（ATSと会社の共有の仕組み）でだけ扱い、自分の端末やクラウドに保存せず、メールで送らず、作業が終わったら会社の管理のもとで消します。過去の応募者をどこまで移すかは、会社の個人情報の方針と保存の期間に従い、自分で決めません。権限は専用のアカウントで、範囲と期間を決めて受け、終了時に削除してもらいます。面接官の判定や候補者の記録を、会社の外で話しません。個別の判断は専門家にご確認ください。扱いの詳細は[候補者の個人情報の扱い](/media/fukugyo-kojin-jouhou/)と[セキュリティの基本](/media/fukugyo-security/)に書いています。

## 稼働時間は何で決まるか

全体の時間は、「第1週の設計（集めたいもの、比べる材料、設定の案、移行の計画）」「設定（段階と項目と通知の数）」「移行（進行中の候補者の数と、過去のデータの範囲）」「手順書と面接官への展開（面接官の数と同席の回数）」「定着（一か月の確認の頻度）」「引き継ぎ」の合計で決まります。移行と同席は、候補者と面接官の数に比例します。製品が決まっていなければ、比べる材料の工程が足されます。受ける前に「製品は決まっているか」「進行中の候補者の数」「面接官の数」「終わりの定義」を決めておけば、見込みが立ちます。数値は案件ごとに違うので、第1週の終わりに見直します。稼働の管理は[稼働時間の管理](/media/fukugyo-kadou-kanri/)に書いています。

## まとめ

- 1案件は**契約前→第1週→設定と移行→手順書と面接官への展開→最初の一か月の定着→引き継ぎと終了**の六つの段階
- 契約前に**範囲・集めたいもの・製品の決定者と契約・個人情報の方針・権限の範囲と期間・移行の時期・面接官への依頼・終わりの定義**を決める。終わりは「表計算を止めた日」
- 第1週は**設定しない**。集めたいものを一つに、いまの表計算を見て、「表計算の列→ATSの項目」の対応表で設定の案を作り、移行の計画を立てる
- 設定は**承認された案だけ**。移行は**進行中の候補者を一人も落とさず、並行期間の終わりの日を先に決める**
- 手順書は**人事に三つの画面、面接官に一つの画面**。面接官への一枚は面接の案内の文面に組み込み、最初の数回は同席
- 一か月で**併用を解消し、書かない面接官に転記と一枚で対応し、集計の初回を見せる**
- 終了時は**運用のルールと担当を残し、管理者権限とアカウントを削除してもらい、移行のファイルを消す**

## よくある質問

### 会社が「過去の応募者も全部ATSに入れてほしい」と言います

会社の個人情報の方針と保存の期間に従います。方針が無い会社では、「過去の応募者をどこまで保存するかの方針を先に決めてください。決まってから移します」と返し、自分で範囲を決めません。進行中の候補者は全員移し、過去の応募者は方針に沿った範囲だけを移します。方針の決め方は法令の論点に関わるので、専門家にご確認くださいと添えます。移行の作業は会社の管理する場所でだけ行い、自分の端末に置きません。

### 面接官が「ATSに書く時間が無い」と言って書きません

責めずに、三つを試します。書く項目を減らす（判定と理由の二つまで）、判定の画面へのリンクを面接の案内に入れて探す手間を無くす、面接の直後に同席して「今ここに」と一緒に書く。それでも書かない面接官の分は、口頭で聞いて人事か自分が転記し、「書いていただければ転記は要りません」と伝えます。面接官への依頼は会社の責任者から出してもらい、外の人が「書いてください」と繰り返さないことです。

### 設定は終わりましたが、人事が表計算を手放しません

残っている理由を確認します。多くは「ATSに無い列がある」「集計が表計算のほうが楽」「念のため」の三つです。無い列はATSの項目に足し、集計はATSの書き出しで同じものが出ることを見せ、「念のため」には止める日を決めて全員に伝えます。正がATSであることを会社の責任者から宣言してもらい、止めた日に表計算を閉じます。止める日を決めないと、二か月目に表計算が正に戻ります。

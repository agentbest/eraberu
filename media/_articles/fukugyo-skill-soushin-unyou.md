スカウトは、一回の送信で決まりません。検索して、見極めて、文面を書いて、送って、記録して、返信に対応して、また検索する。この往復を、週に数時間の稼働で止めずに回すのが、送信運用です。運用が止まるのは、担当者の意欲の問題ではなく、工程の配分と、依頼側との合意が無いからです。結論を先に書くと、**送信運用は、週の稼働を検索・見極め・文面・送信・記録の五つの工程に先に配分し、送る数は返信への対応が追いつく範囲で決め、再送は間隔と理由で線を引き、確認の範囲・返信の窓口・止める条件を依頼側と先に合意し、週次の一枚で報告して、担当者が替わっても回る形にします。**各工程の型は[検索条件を組む](/media/fukugyo-skill-kensaku/)・[プロフィールの見極め方](/media/fukugyo-skill-screening/)・[スカウト文面を書く](/media/fukugyo-skill-scout-bunmen/)に書いています。ここでは、工程をつないで回す型に絞ります。

## 運用が止まる典型

| 止まり方 | 原因 |
|---|---|
| 最初の週に大量に送り、翌週はゼロ | 送る数を稼働で決めていない。返信対応に追われて送信が止まる |
| 一通ごとに依頼側の確認を待つ | 確認の範囲を合意していない |
| 返信が来ると、送信が止まる | 返信対応と送信の時間を分けていない |
| 検索条件を毎回ゼロから組む | 記録が無い |
| 依頼側から「今週はどうでしたか」と聞かれて答えられない | 週次の報告の形が無い |

止まる原因のほとんどは、最初の合意と配分で防げます。運用の設計は、送り始める前にします。

## 週の稼働を五つの工程に配分する

| 工程 | やること | 配分の目安の考え方 |
|---|---|---|
| 検索 | 記録した条件で結果を出し、件数を記録 | 短く。記録があれば毎回組み直さない |
| 見極め | ○△×を付け、優先度と理由をリストに | 最も時間がかかる。一人の上限を決める |
| 文面 | 上は個別、中は型に一段落 | 見極めの○の根拠を写す形で短く |
| 送信 | 決めた数だけ送り、送信日を記録 | まとめて送る時間を固定する |
| 記録と返信対応 | 返信の有無を記録し、返信に答えるか依頼側に渡す | 送信と別の時間に置く |

配分は、時間の割合ではなく、「どの工程を、週のどこでやるか」を固定することが要点です。曜日と時間を決めて、その時間はその工程だけをやります。返信対応を送信の時間に混ぜると、送信が止まります。稼働の設計は[稼働時間の管理と申告](/media/fukugyo-kadou-kanri/)に書いています。

### エラベルの見解

担当する側から見ると、送信運用で最も差がつくのは、「送る数を、稼働で送れる数ではなく、返信に対応できる数で決めている」かどうかです。受ける側は、送れる数を最大にしようとします。ただ、返信が来たときに、翌営業日中に対応できなければ、候補者は冷め、依頼側からは「返信が放置されている」と見えます。送る数は、返信が来たときの対応の時間を先に確保して、その残りで決めます。エラベルで担当者を選ぶ企業には、「週に何通送るかより、返信に何日以内に答えるかを先に決めていますか」を、私たちから先に聞いています。受ける側がその場で使える判断としては、週の稼働のうち、返信対応の時間を先に固定し、その時間で対応できる返信の数から逆算して送る数を決めること。返信の対応の速さは[連絡の速さをどう担保するか](/media/fukugyo-renraku-sokudo/)に書いています。

## 送る数の決め方

| 決め方 | 問題 |
|---|---|
| 媒体の送信上限まで送る | 返信対応が追いつかない。上限は媒体と契約で変わるので、確認せずに前提にしない |
| 依頼側が言った数を送る | 依頼側は返信対応の負荷を見ていないことが多い |
| 稼働で送れる最大数を送る | 見極めが流し見になり、返信が減る |
| 返信対応の時間から逆算する | 対応が追いつき、返信の質が保てる |

数を決めたら、週ごとに同じ数を送ります。波打たせないのは、検証（[文面を検証する](/media/fukugyo-skill-ab-test/)）の「同じ時期に送る」を保つためでもあります。送信の上限や仕様は媒体で変わるため、契約の内容は依頼側に確認します。

## 同じ相手への再送の線

| 状況 | 扱い |
|---|---|
| 返信が無い相手に、同じ文面をもう一度 | 送らない。受け取る側の印象を落とす |
| 返信が無い相手に、間隔を空けて、内容を変えて | 依頼側と決めた間隔と理由（求人の内容が変わった、新しい役割ができた）があるときだけ |
| 「今は考えていない」と返信があった相手 | 記録に残し、本人が言った時期まで送らない |
| 辞退した相手 | 送らない。理由を記録 |
| 別の求人で同じ相手 | 同時には送らない。片方が終わってから、間隔を空けて |

再送は、回数ではなく「間隔・理由・内容の変化」で決めます。考え方は[同じ候補者に何回送ってよいか](/media/scout-soushin-hindo/)に書いています。再送の可否は依頼側の方針と媒体の規約に従います。

## 送信の時間帯

「一般に良いとされる時間帯」は、相手の層によって違います。自分の記録で決めます。

| 手順 | 中身 |
|---|---|
| 一 | 送信の時間帯を記録に残す |
| 二 | 返信が来た時間帯を記録に残す（媒体で見えるとき） |
| 三 | 数回分たまったら、返信の多い時間帯に送信を寄せる |
| 四 | 文面の検証と同時に時間帯を変えない |

時間帯の考え方は[送信する時間帯と曜日](/media/scout-soushin-jikantai/)に書いています。副業の担当者の場合、送れる時間帯が本業の都合で限られることが多く、その制約の中で、送信を「予約」できる媒体なら予約を使います。予約の機能の有無は媒体で変わるので確認します。

## 依頼側と先に合意しておくこと

| 合意事項 | 決めること |
|---|---|
| 確認の範囲 | 型の文面は事前確認、個別の一段落は確認なし。役割と迷う理由の段落を変えるときは確認 |
| 返信の窓口 | 初回の返信に誰が答えるか。担当者が答えてよい範囲（選考の流れ、面談の形）と、依頼側に渡す範囲（報酬、条件） |
| 返信への対応の期限 | 何営業日以内に答えるか。担当者が動けない日の代わりは誰か |
| 送る数 | 週の数。増減するときの決め方 |
| 止める条件 | 返信がゼロのまま何回続いたら、送信を止めて見直すか |
| 記録の置き場所 | 依頼側が管理する共有の場所 |

止める条件を先に決めるのは、返信が来ないまま送り続けることが、候補者の側にも媒体の側にも良くないからです。止めたら、[返信ゼロが続くときに疑う順番](/media/scout-henshin-nashi-genin/)の順で見直します。返信の分担は[返信が来たあとの対応分担](/media/scout-daikou-henshin-taiou/)に書いています。

### エラベルの見解

相談で最も多い思い込みは、受ける側の「運用は、自分が回し続けるもの」というものです。実際には、副業の担当者は本業の都合で動けない週があり、案件はいつか終わります。そのとき、運用が担当者の頭の中にしか無ければ、止まります。検索条件・候補者リスト・文面の型・検証の記録・週次の報告が、依頼側の共有の場所に名前付きで置いてあれば、担当者が一週間動けなくても、依頼側が最低限を回せますし、担当者が替わっても続きます。エラベルで担当者を選ぶ企業には、「担当者が動けない週に、社内で何ができますか」を、私たちから先に聞いています。受ける側がその場で使える判断としては、運用を始めて最初の月のうちに、依頼側の担当者に「記録を見て、送信だけをやってみる」を一度やってもらうこと。それで回れば、引き継げる形になっています。引き継ぎの形は[引き継ぎ資料の残し方](/media/fukugyo-hikitsugi/)に書いています。

## 週次の報告の一枚

| 項目 | 中身 |
|---|---|
| 送った数 | 週の数。優先度の内訳 |
| 返信の数 | 週の数。返信で最初に聞かれたこと |
| 面談に進んだ数 | 週の数 |
| 検証 | 試した箇所と判断（採用・継続・戻す） |
| 検索条件の変更 | 変えたなら、何をなぜ |
| 止まっていること | 依頼側の確認待ち、判断待ちの項目 |
| 来週やること | 送る数、試す箇所 |

数は自分が送った範囲の数として書き、「返信率が上がった」のような断定は、件数が少ないうちはしません。見る指標の考え方は[スカウト運用で見るべき指標](/media/scout-shihyou/)に、数字の伝え方は[数字で語る](/media/fukugyo-suuji/)に書いています。報告は、依頼側が読む時間を取らずに済む長さ（一枚）にします。

## よく起きる詰まりと直し方

| 詰まり | 直し方 |
|---|---|
| 返信対応で送信の時間が消える | 返信対応の時間を別に固定し、送信の時間に返信を見ない |
| 依頼側の確認待ちで止まる | 確認の範囲を狭める合意を取り直す。確認の期限を添える |
| 送る数が週で波打つ | 週の数を決め、送れない週は依頼側に先に伝える |
| 見極めに時間がかかり、送信に届かない | 一人の上限を決める。上の人数を絞る |
| 返信がゼロのまま続く | 止める条件に従って止め、疑う順番で見直す。文面から直さない |
| 担当者が動けない週がある | 先に伝え、依頼側が記録を見て送信だけを回せる形にしておく |

## まとめ

- 運用が止まるのは意欲ではなく、**工程の配分と依頼側との合意が無い**から
- 週の稼働を**検索・見極め・文面・送信・記録**に配分し、曜日と時間を固定する。返信対応は送信と別の時間に
- 送る数は**返信への対応が追いつく範囲**で決め、週ごとに同じ数を送る。媒体の上限は確認してから
- 再送は**間隔・理由・内容の変化**で線を引く。同じ文面を二度送らない
- 時間帯は**自分の記録で決める**。文面の検証と同時に変えない
- **確認の範囲・返信の窓口・対応の期限・送る数・止める条件・記録の置き場所**を先に合意
- **週次の一枚**で報告。数は自分が送った範囲の数として
- 記録を共有の場所に置き、**担当者が動けなくても回る形**にする

## よくある質問

### 本業が忙しい週は、送る数を減らしてもよいですか

減らして構いませんが、先に依頼側に伝えます。「今週は送信を減らし、返信対応だけ行います」と伝えれば、依頼側は待てます。伝えずに減ると、「止まった」と見えます。減らす週があることを前提に、週の数を無理のない数に決めておくほうが、波打ちません。動けない週の扱いは[平日日中の連絡にどう対応するか](/media/fukugyo-heijitsu-taiou/)の考え方と同じで、「いつ動くかが依頼側に分かる」ことが要点です。

### 依頼側が「もっと数を送ってほしい」と言います

送る数を増やすと、見極めと返信対応の時間が減ることを、稼働の配分で示します。「数を増やすなら、返信対応を御社で持つか、稼働を増やすか、見極めの基準を下げるかのどれかになります」と、選択肢と代償を並べ、判断を依頼側に渡します。見極めの基準を下げて数を増やすと、返信が減り、結果として面談の数は増えないことが多い、という構造も添えます。

### 運用の途中で、要件が変わりました

検索条件・候補者リストの優先度・文面の型の三つを、要件の変更に合わせて書き換えます。書き換えた日と理由を記録に残し、それ以前の検証の結果は「旧要件」として分けます。要件が変わる前後の数字を混ぜて比べないためです。要件の変更が大きいときは、送信を一度止めて、検索から組み直します。要件の整理は[採用要件を引き出すヒアリングの型](/media/fukugyo-skill-youken-hearing/)に書いています。

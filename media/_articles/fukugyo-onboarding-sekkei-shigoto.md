オンボーディング設計を初めて受けるとき、見えにくいのは「入社の前に何を整え、入社の後に何を回し、自分はどこで手を引くか」です。募集文には「オンボーディングの構築」とだけあり、実際には、上司の時間の確保、教える内容の表、初日の準備の段取り、面談の日程、質問の窓口、つまずきと兆しの記録、定着の見直しと、入社の前後に工程が並び、しかも入社ごとに繰り返します。順番を知っていれば、契約前に決めておけます。結論を先に書くと、**1案件は「契約前→設計→入社前→入社後の運用→月次と三か月→終了と引き継ぎ」の六つの段階で進み、契約前に範囲・教える人と上司の時間・入社の人数と時期・窓口の名義と時間帯・記録の置き場と評価を書かないこと・労務の手続きは担当者であること・終わりの定義を決め、過去の退職の理由から三か月までの計画と教える内容の表と初日の一覧と面談の型と記録の型を設計し、入社前に連絡と準備の段取りと面談の日程の確保と上司への共有を行い、入社後は窓口と取り次ぎと面談の実施の確認とつまずきと兆しの記録を回し、月次と三か月で定着の記録から計画を見直し、型と記録を引き継いで情報を残さずに終えます。**案件の型と求められる経験は[オンボーディング設計の副業案件](/media/fukugyo-onboarding-sekkei-fukugyo/)に書いていますので、ここでは「1案件の流れ」に絞ります。

## 契約前：決めておくこと

オンボーディングは、「新しい人のため」という言葉で範囲が広がりやすい仕事です。契約前に、自分がやらないことを決めます。

| 決めること | 確かめる中身 | 決めていないと起きること |
|---|---|---|
| 範囲 | 設計と表だけか、入社ごとの段取りと窓口と記録を含むか、見直しを含むか、型作りか | 「教えるところも」「面談も」が足される |
| 教える人と上司の時間 | 上司と同僚が、最初の三か月に週にどれだけ時間を使うか。面談は上司が行うこと | 担当者が教える側と面談する側に回る |
| 入社の人数と時期 | 何人が、いつ入るか。同時か、ばらばらか | 稼働が読めない |
| 窓口の名義と時間帯 | 新しい人の質問を受ける窓口を、どの名義で、平日のどの時間帯に見るか。回答は会社 | 窓口が自分の私的な連絡先になる。答えてしまう |
| 記録の置き場と評価を書かないこと | 面談と窓口の記録は会社の管理する場所に。事実だけで、新しい人の評価を書かない | 記録が新しい人の評価に使われる |
| 労務の手続きは担当者 | 入社の書面と手続きは会社の担当者と専門家。自分は初日の一覧に「手続き（担当者）」と書くまで | 手続きを持たされる |
| 終わりの定義 | 設計の納品か、最初の入社の三か月の終わりか、担当者が回せる状態か | 納品で終わり、回らない |
| 評価 | 三か月の定着、面談の実施率、質問の取り次ぎの速さ。新しい人の成長ではない | 新しい人の立ち上がりで評価される |

止まりやすいのは、「来月入る人がいるので、まず初日の準備を」で始めるときです。初日の準備は設計の一部で、上司の時間と教える内容の表が無いまま初日を迎えると、初日だけ整って二週目に放置されます。範囲の決め方は[業務範囲の決め方](/media/fukugyo-scope/)に、見積もりの出し方は[見積もりの出し方](/media/fukugyo-mitsumori/)に書いています。

## 設計：過去の退職、三か月までの計画、教える内容の表、初日の一覧、面談の型、記録の型

入社の前に、設計を終えます。設計は「研修の内容」ではなく、「何週目に何ができる状態か」から作ります。

| 作るもの | 中身 | 落とし穴 |
|---|---|---|
| 過去の退職の理由と時期 | 過去に辞めた人が、何か月目に、何を理由に辞めたか（個人が特定されない形で）。辞めた月に何が起きていたか | 理由を「本人の問題」で片付ける |
| 三か月までの計画 | 入社前、初日、一週目、一か月、三か月で、何ができる状態か。それぞれで誰が関わるか | 研修の内容から作る |
| 教える内容と担当と時期の表 | 上司と同僚の頭の中を聞き出し、何を、誰が、いつ教えるか。教える人の合意 | 表が無く、「その場で教える」になる |
| 初日の準備の一覧 | 机、端末、アカウント、書面（手続きは担当者）、挨拶の順、初日の予定、昼の同席。担当と期限 | 初日に端末が無い |
| 面談の型 | 上司との面談の時期（一週目、一か月、三か月など）、話す項目（できたこと、困っていること、聞きたいこと、次の一か月）、時間。面談は上司 | 面談の時期を決めず、後回しになる |
| 質問の窓口の型 | 新しい人がいつ何をどこに聞けるか。窓口は取り次ぎ、回答は上司か会社 | 窓口が答える形 |
| 記録の型 | 面談の記録（事実）、質問の記録（内容、取り次ぎ先、回答の日）、兆しの欄（質問の数の変化、面談での話の量）。評価の欄は無し | 評価の欄がある |

止まりやすいのは、教える内容の表を人事だけで作ることです。教える内容は上司と同僚の頭の中にあり、本人に聞かないと出ません。聞き方は[ヒアリングの技能](/media/fukugyo-hearing-skill/)に、JDとの関係は[ジョブディスクリプションの作成の副業案件](/media/fukugyo-jd-sakusei-fukugyo/)に書いています。

### エラベルの見解

担当する側から見ると、この仕事は「設計の段階で、上司と同僚に『何を教えるか』を聞く時間をもらえるか」で、定着が決まります。人事が作った研修は、仕事の中身と離れ、新しい人は「研修は受けたが、実際の仕事は誰も教えてくれない」と感じます。上司と同僚が「最初の週はこれ、二週目はこれ」と自分の言葉で表を埋めた会社では、教える側に「自分が教える」という意識ができ、新しい人は聞ける相手を持ちます。エラベルで担当者を選ぶ企業には、「教える内容の表は、上司と同僚の方に三十分ずつ聞いて作ります。人事だけでは作りません」と、私たちから先に伝えています。受ける側がその場で使える判断としては、表の「担当」の欄に、上司と同僚の名前が本人の合意で入っているかを確かめること。名前の無い表は、誰も教えない表です。

## 入社前：連絡、準備の段取り、面談の日程の確保、上司への共有

入社が決まったら、初日までに整えます。

| やること | 依頼側に持ってもらうこと | 落とし穴 |
|---|---|---|
| 入社前の連絡（会社の名義で、承認された文面。初日の集合、持ち物、予定。条件や配属の質問は会社に渡す） | 名義と文面の承認 | 条件や約束を自分がする |
| 初日の準備の段取り（一覧に沿って、担当に期限を伝え、前日に確認） | 準備の実行（担当） | 自分が準備をする。手続きを持つ |
| 面談の日程の確保（一週目、一か月、三か月の面談を、上司の予定に先に入れる） | 上司の予定 | 「落ち着いたら」で後回し |
| 上司と同僚への共有（教える内容の表、新しい人の経歴の要点（会社が共有してよい範囲）、初日の予定） | 共有の範囲の決定 | 経歴の詳細を共有する |
| 窓口の案内の準備（新しい人に渡す、いつ何をどこに聞くかの一枚） | 窓口の名義 | 窓口を私的な連絡先にする |

止まりやすいのは、面談の日程を「入ってから決める」にすることです。上司の予定は埋まり、面談は後回しになります。入社前に、三か月分を先に入れます。

## 入社後の運用：初日、窓口と取り次ぎ、面談の確認、記録、週次の報告

入社したら、計画に沿って回します。自分は教えず、面談せず、段取りと窓口と記録です。

| やること | 頻度の目安 | 落とし穴 |
|---|---|---|
| 初日（一覧どおりに整っているか、挨拶の順、昼の同席、初日の終わりに窓口の案内） | 初日 | 初日の終わりに誰も声をかけない |
| 窓口と取り次ぎ（質問を受け、答えず、上司か会社に当日取り次ぎ、回答の日を記録） | 平日、決めた時間帯に | 答える。取り次ぎが翌日以降になる |
| 教える内容の表の進み（表どおりに教えられているか。遅れは上司に事実で返す） | 週に一度 | 遅れを新しい人のせいにする |
| 面談の実施の確認（予定どおり行われたか。行われていなければ上司に日程の再調整を） | 面談の時期ごと | 面談を自分がやる |
| つまずきと兆しの記録（質問の数と内容の変化、面談での話の量、表の遅れ。評価は書かない） | 週に一度 | 所感を書く |
| 兆しが出たら会社に渡す（質問が減った、面談で話さなくなった、を事実で。対応は会社） | 出たとき | 自分が対応する。抱える |
| 週次の報告（表の進み、面談の実施、質問の数と取り次ぎ、兆し、次に直すこと一つ） | 週に一度 | 新しい人の評価を報告する |

止まりやすいのは、窓口で質問に答えてしまうことです。答えると、新しい人は担当者に聞くようになり、上司との関係が作られません。答えずに取り次ぎ、取り次いだ先を記録します。連絡の速さは[連絡の速さ](/media/fukugyo-renraku-sokudo/)に、報告の型は[報告の仕方](/media/fukugyo-houkoku/)に書いています。

### エラベルの見解

同じ料金・同じ範囲でも、結果が分かれるのは、「兆しを、評価ではなく事実で、当日に渡せるか」です。「質問が先週の半分になった」「面談で困っていることを聞いても『特に無いです』だった」は、辞める前の兆しですが、これを「やる気が落ちている」と所感で書いた担当者の記録は、新しい人の評価に使われ、本人が知れば信頼を失います。「質問の数：先週五件、今週二件。面談の記録：困っていることは『特に無い』」と事実だけを書き、当日に上司と会社に渡した担当者の記録は、上司が「何かあった？」と声をかける材料になり、対応が間に合います。兆しは、早く、事実で、渡す。エラベルで長く続いている担当者は、記録の型に「所感」の欄を作らず、「質問の数」「面談での話の量」の欄だけを持っています。受ける側がその場で使える形としては、兆しを渡すときの文面を「事実を二つ並べて、判断を書かない」型に決めておくことです。

## 月次と三か月：定着の記録、計画の見直しの提案

月に一度と、三か月の節目で、会社と見直します。見るのは、新しい人の評価ではなく、計画が回ったかです。

| 見ること | 読み方 | 直すところ |
|---|---|---|
| 教える内容の表の進み | 遅れた項目と担当 | 表の時期か担当の時間 |
| 面談の実施率 | 行われなかった面談と理由 | 日程の押さえ方、上司の時間 |
| 質問の数と内容の推移 | 減り方（自然に減ったか、急に減ったか）、聞く相手（上司に聞けているか） | 窓口の案内、上司の接し方（事実で会社に） |
| 三か月の定着（続いているか、できる状態になったか） | 計画どおりか | 計画の見直し |
| 辞めた場合の時期と理由（分かる範囲で） | 過去の退職の記録と照らす | 計画の直す箇所 |

止まりやすいのは、見直しで「新しい人の問題」に話が向くときです。定着の記録は計画を直すためのもので、個人の評価のためではありません。

## 終了と引き継ぎ：型と記録、情報を残さない

終了時は、社内の担当者が回せる形にして終えます。

- **残すもの。** 三か月までの計画の型、教える内容と担当と時期の表の型、初日の準備の一覧、面談の型、窓口の案内の型、記録の型、定着の記録（個人が特定されない形）、見直しの履歴
- **返すもの。** 面談と窓口の記録（会社の管理する場所に。手元に残さない）、新しい人の経歴と私的な事情に関わる情報。窓口の名義が自分のものなら、会社のものに切り替える
- **次の提案。** 更新するなら、次の入社に向けた計画の直し。終了するなら、社内の担当者が回す手順（誰が段取りし、誰が窓口になり、誰が記録するか）

止まりやすいのは、窓口の名義を自分のまま残すことです。新しい人が終了後も自分に連絡する形になります。引き継ぎの型は[引き継ぎの仕方](/media/fukugyo-hikitsugi/)に書いています。

## 新しい人の情報の扱い

オンボーディングでは、新しい人の経歴、面談で話した困りごと、上司への感じ方、私的な事情に触れます。記録は事実だけで、所感と評価を書かず、会社の管理する場所に置き、自分の端末に残しません。窓口で聞いた上司への不満は、本人の同意を確かめてから、事実を整理して会社に渡します。同意が無いものは、記録に残さず、「上司に聞きやすい形を作る」方向で扱います。労務の手続きの情報（住所、家族、報酬）は見ません。新しい人の経歴を上司と同僚に共有する範囲は、会社が決めます。個別の判断は専門家にご確認ください。扱いの詳細は[候補者の個人情報の扱い](/media/fukugyo-kojin-jouhou/)に書いています。

## 稼働時間は何で決まるか

全体の時間は、「設計（教える人の聞き取りの人数、表の項目の数）」と「入社ごとの運用（入社前の段取り、初日、窓口の確認の頻度×三か月、面談の確認、記録、週次の報告）」と「月次と三か月の見直し」の合計で決まり、運用は入社の人数に比例します。窓口を含むと、平日の決めた時間帯の確認が固定で乗ります。同時に複数が入ると、初日と一週目が重なって集中します。受ける前に「入社の人数と時期」「窓口を含むか」「三か月まで見るか」を決めておけば、見込みが立ちます。数値は案件ごとに違うので、最初の一人の三か月の実績で見直します。稼働の管理は[稼働時間の管理](/media/fukugyo-kadou-kanri/)に書いています。

## まとめ

- 1案件は**契約前→設計→入社前→入社後の運用→月次と三か月→終了と引き継ぎ**の六つの段階
- 契約前に**範囲・教える人と上司の時間・入社の人数と時期・窓口の名義と時間帯・記録の置き場と評価を書かない・労務の手続きは担当者・終わりの定義・評価**を決める。「まず初日の準備を」では始めない
- 設計は**過去の退職の理由と時期→何週目に何ができる状態かの計画→上司と同僚に聞いて作る教える内容と担当と時期の表→初日の一覧→面談の型→窓口の型→記録の型（評価の欄なし）**
- 入社前に**会社の名義で連絡・準備の段取り・三か月分の面談の日程を先に押さえる・上司への共有**
- 入社後は**教えず、面談せず、窓口で答えずに取り次ぎ、表の進みと面談の実施を確認し、兆しを事実で当日に渡す**
- 月次と三か月は**計画が回ったか**を見る。新しい人の評価にしない
- 終了時は**型と記録を残し、窓口の名義を会社に切り替え、情報を残さない**
- 記録は**事実だけ、所感と評価を書かず、上司への不満は本人の同意を確かめてから**

## よくある質問

### 新しい人から、上司への不満を聞きました

その場で判断せず、まず「上司に伝えてよいか、会社に伝えてよいか」を本人に確かめます。同意があれば、事実（何が、いつ、どう起きたか）を整理して会社に渡し、対応は会社が行います。同意が無ければ、記録に残さず、「上司に聞きやすい形」（面談の議題にする、同僚に先に聞く）を一緒に整えます。自分が上司に直接言ったり、上司を評価したりしません。不満を抱えたままにもしません。同意を確かめることと、事実で渡すことの二つが、線です。

### 上司が教える内容の表を埋めてくれません

上司の時間が無いか、教える内容が頭の中で整理されていないかのどちらかです。三十分で、「新しい人が最初の週にできるようになってほしいことは何ですか」「二週目は」と、時期ごとに口頭で聞いて、自分が表にし、上司に確認してもらう形にします。書いてもらうより、聞いて書くほうが埋まります。それでも時間が取れないなら、会社に「上司の時間が無いとオンボーディングは回りません」と事実で返し、上司の時間を決めてもらいます。表を自分の想像で埋めることはしません。

### 三か月を待たずに、新しい人が辞めると言っています

事実（いつ、何を言ったか、その前の兆し）を整理して、当日に上司と会社に渡します。対応（面談、配属の見直し、条件の話）は会社が行い、自分は関わりません。辞める理由が採用時の説明との違いなら、採用の側に戻す材料として記録します。辞めることを自分の失敗として抱えず、計画の見直しの材料にします。過去の退職の記録に、時期と理由（個人が特定されない形）を足し、次の入社の計画を直します。

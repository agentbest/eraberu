IT企業の人事として、エンジニアやデザイナーやプロダクトの職種を、スカウトを送り、現場のエンジニアを面接に巻き込み、他社との競争の中で速く決めて、採ってきた。この経験は、人事の副業で売れるのか。IT企業の採用は他の業界と進め方が違い、自社の技術や知名度があったから成り立っていたと感じる人が多いところです。結論を先に書くと、**IT企業の人事の経験は、「採りにくいエンジニアを、ダイレクトリクルーティングと現場の巻き込みと速い選考で、競争の中で採ってきた」型で売れます。売れるのは、「スカウトを軸にした母集団の設計」「技術職の要件を現場と一緒に決める型」「選考の速さと候補者体験の設計」「採用の数字を回す運用」の四つです。IT以外の業界でも、社内にエンジニアやデータの職種を持ち始めた会社は、その職種の採り方が分からず、媒体に出しても来ず、現場が面接に関わらず、選考が遅くて他社に取られています。「IT企業の人事でした」ではなく、「採りにくい職種を、スカウトと現場と速さで採る形を作る」と売ります。**エンジニアからの転身は[エンジニアからの転身が副業でできること](/media/fukugyo-engineer-kara-fukugyo/)に、スタートアップの経験は[スタートアップ人事の経験は評価されるか](/media/fukugyo-startup-keiken/)に、社内リクルーターの経験は[社内リクルーターが副業でできること](/media/fukugyo-shanai-recruiter-fukugyo/)にまとめています。

## この経歴の何が売れるか

IT企業の人事の経験を、業界の内外の採用の工程に置き換えた棚卸しです。在籍した会社の採用の内情は含めず、「型」として抜き出します。

| IT企業の人事の経験 | 採用の工程への置き換え | 依頼側にとっての価値 |
|---|---|---|
| スカウトを軸に、媒体に頼らず候補者を探して口説いてきた | 応募を待たず、探して声をかける母集団の設計（誰を、どこで、どう探し、何を書くか） | 媒体に出しても応募が来ず、打ち手がない依頼側が多い |
| 技術職の要件を、現場のエンジニアと一緒に決めてきた | 自分に分からない専門職の要件を、現場の言葉を聞き取って「できること」で書く型 | 専門職の要件を人事だけで書いて、現場が「違う」と言う依頼側が多い |
| 現場のエンジニアを面接に巻き込み、技術の評価を任せてきた | 現場の専門家が面接に出て評価する分担と、人事が見る点との切り分け | 現場が面接に出ず、人事が専門性を評価できない依頼側が多い |
| 競争の中で、応募から内定までを速く回してきた | 選考の日数を縮める設計（即日の連絡、面接の一本化、内定の即出し） | 選考が遅くて他社に取られる依頼側が多い |
| 候補者に「この会社を受けてよかった」と思わせる体験を設計してきた | 面接の前後の連絡、面接官の態度、辞退の理由の聞き取りを設計する | 候補者が途中で離れる理由が分からない依頼側が多い |
| 採用の数字（スカウトの返信率、面接の通過率、内定の承諾率）を毎週見て動いてきた | 工程ごとの数字を集め、どこで落ちているかを見て手を打つ運用 | 採用の数字を見ていない依頼側が多い |
| 採用の広報（技術ブログ、イベント、社員の登壇）を回してきた | 会社の魅力を、候補者が読む形で外に出す設計 | 自社の魅力を候補者の言葉で言えない依頼側が多い |

売れるものの要点は、「採りにくい職種を、待たずに探し、現場と一緒に見て、速く決める型」です。多くの会社の採用は、媒体に出して、応募を待ち、人事が一次面接をし、現場に回し、数週間かけて決める形で動いており、採りにくい職種ではこの形が通じません。IT企業の人事は、その形が通じない環境で、スカウトと現場の巻き込みと速さで採ってきています。この型は、IT以外の業界でも、採りにくい職種を持ち始めた会社にそのまま合います。スカウトの案件は[スカウト代行の副業案件](/media/fukugyo-scout-daikou-fukugyo/)に、指標の設計は[KPIを設計する](/media/fukugyo-kpi-sekkei-skill/)に、聞き取りの型は[ヒアリングで押さえる項目](/media/fukugyo-hearing/)に書いています。

## 売りにくい点とその扱い

IT企業の人事の転身で売りにくい点は三つあり、扱い方があります。

| 売りにくい点 | 依頼側の懸念と自分の懸念 | 扱い方 |
|---|---|---|
| 技術を分かっていると思われる | 「エンジニアの採用ができるなら、技術も分かるのだろう」と期待され、実際は分からない | 「技術は分かりませんが、分からない専門職の要件を現場から聞き取って書く型を持っています」と、最初に線を引く。技術の評価は現場に任せる分担を示す |
| IT以外の業界で通じるか | 「IT企業のやり方は、うちの業界には合わない」 | IT企業の言葉（カジュアル面談、テックブログ、リファラル）を、構造の言葉（応募前の面談、会社の魅力を外に出す、社員の紹介）に置き換える。「採りにくい職種」の構造で語る |
| 自社の魅力に頼っていた | 「知名度のある会社だったから、スカウトに返信が来たのでは」。自分にとっても、知らない会社の名前で口説く技術がない不安 | 知らない会社の名前で返信をもらう文面は、本業の型のままでは通じないことを認め、依頼側の会社の魅力を候補者の言葉に置き換えるところから作り直す前提で入る |

扱い方の要点は、「技術が分かるふりをせず、分からない専門職を採る型として売る」ことです。IT企業の人事の経験がある人は、技術が分かると思われることに応えようとして、面談で技術の話に踏み込み、依頼側の現場に見透かされます。「私は技術は分かりません。ただ、分からない専門職の要件を、現場の言葉を聞き取って『できること』で書き、現場に評価を任せる分担を作ってきました」と最初に言えば、依頼側は「うちの現場と一緒にやれる人」と受け取ります。IT以外の業界には、IT企業の言葉を構造の言葉に置き換えて入ります。範囲の決め方は[業務範囲を書面で固める](/media/fukugyo-scope/)に、自己紹介の型は[自己紹介文のテンプレート](/media/fukugyo-jiko-shoukai/)に整理しています。

### エラベルの見解

担当する側から見ると、IT企業の人事から転身して続いている人と、面談で止まる人の差は、依頼側の会社の名前を知らない候補者に、何を書けば読まれるかを最初に考えているかです。止まる人は、本業で返信が来ていたスカウトの型をそのまま使い、返信が来ずに「この会社は知名度がないから」で止まります。続いている人は、依頼側の会社の名前を知らない候補者が、それでも読む理由を探すところから始めます。「あなたの経歴のここを見た」「この会社のこの点が、あなたの次の一歩に合う」を、依頼側の現場に聞き取って文面の最初に置き、返信が戻ったところで依頼側の信頼を得ます。

見ていて差がつくのは、現場の専門家を面接に巻き込む型を、依頼側の現場の負担に合わせているかです。IT企業の人事の経験がある人は、現場のエンジニアが面接に出るのが当たり前の環境にいたので、依頼側の現場にも同じ関わり方を求め、「そんな時間はない」と引かれます。「面接の時間を短くし、現場が見る点を技術の一点に絞り、人事が見る点と分け、判断は一緒に持つ」形にして、現場の負担を減らしたうえで巻き込んだ人は、現場が面接に出るようになり、依頼側から「初めて現場が採用を自分ごとにした」と評価されています。エラベルでは、依頼側が担当者の経歴を見て選ぶ仕組みなので、「採りにくい職種を、スカウトと現場と速さで採る形を作る」と構造の言葉で書いている担当者に、専門職の採り方が分からない依頼側がついています。IT企業の人事の転身は、IT企業のやり方ではなく、知らない会社の名前で口説く文面から始まります。

## 案件の探し方

IT企業の人事から入りやすい案件と、探し方です。

| 入りやすい案件 | 理由 | 探し方 |
|---|---|---|
| IT・Web・SaaSの依頼側の採用 | 業界の言葉と職種が分かり、説明の手間がない | 同じ業界の依頼側を探す |
| IT以外の会社の、エンジニア・データ・デジタルの職種の採用 | 採りにくい職種の型でそのまま入れる。業界の外で最も需要がある | 「社内にエンジニアを持ち始めた依頼側」を探す |
| スカウトを軸にした母集団の設計と文面 | スカウトの経験で入れる | 「媒体に出しても応募が来ない依頼側」を探す |
| 専門職の要件を現場と一緒に決める型 | 現場と要件を決めてきた経験で入れる | 「専門職の要件を人事だけで書いている依頼側」を探す |
| 選考の速さと候補者体験の設計 | 競争の中で速く回してきた経験で入れる | 「選考が遅くて他社に取られる依頼側」を探す |
| 採用の数字の運用 | 毎週数字を見てきた経験で入れる | 「採用の数字を見ていない依頼側」を探す |

探し方の要点は、「IT以外の会社の、IT系の職種」から入ることです。IT企業の依頼側は、同じ型を持つ人事が社内にいることが多く、副業の担当者に求めるのは手を動かす工程になりがちです。IT以外の会社（メーカー、小売、金融、医療、建設）が社内にエンジニアやデータの職種を持ち始めたとき、その職種の採り方を知っている人が社内におらず、IT企業の人事の型が唯一の打ち手になります。案件の相談で「エンジニアを採りたいが、どうすればよいか分からない」という言葉が出たら、それが入り口です。案件の探し方は[副業案件の探し方](/media/fukugyo-anken-sagashi/)に、業界を絞る戦い方は[業界特化という戦い方](/media/fukugyo-gyoukai-tokka/)に書いています。

## 単価の目安

単価は、具体的な額ではなく、決まり方の構造で考えます。IT企業の人事の転身で、単価に影響する要素です。

| 要素 | 単価への影響 | 考え方 |
|---|---|---|
| 採りにくい職種の価値 | 媒体で採れない職種を採れる設計は、依頼側の詰まりに直接効き、紹介の手数料と比べられる | 「返信が来た」「現場が面接に出た」「選考の日数が縮んだ」を成果として残す |
| スカウトの運用 | 送信と追客は時間が読みやすく、月額で受けやすい | 月に何時間で決める |
| 母集団と要件の設計 | 成果物で受けやすい | 一式の成果物で受ける |
| 選考の速さの設計 | 流れの設計は成果物、運用は月額で | 作る工程は成果物、回す工程は月額で |
| 技術の評価を含まないこと | 含まないことで責任の線が明確 | 「技術の評価は現場が」を範囲に明記する |
| 知名度に頼れないこと | 知らない会社の名前で返信をもらうには時間がかかり、最初の月は成果が出にくい | 最初の月は「文面を作り直した」「返信率が動いた」を途中の成果に |
| 成果報酬の扱い | 採用の成否は依頼側の条件と現場の動きに左右され、責任の線が引きにくい | 時間か回数か成果物で。可否は専門家に確認 |

単価の要点は、「設計は成果物で、運用は月額で受け、最初の月は途中の成果を見せる」ことです。IT企業の人事の経験で受ける工程は、採りにくい職種の採用という価値が分かりやすく、紹介の手数料と比べて示せます。ただ、知らない会社の名前で返信をもらうには時間がかかり、最初の月に成果が出にくいので、「文面を作り直した」「返信率が動いた」「現場が面接に出た」と、途中の成果を報告で見せて、更新の根拠にします。単価の構造は[人事の副業単価の相場](/media/fukugyo-tanka-souba/)に、成果の定義は[成果をどう定義しておくか](/media/fukugyo-seika-teigi/)に、成果報酬は[成果報酬型は受けるべきか](/media/fukugyo-seika/)に整理しています。

## 始める順番

IT企業の人事から副業を始める順番です。

| 順番 | 内容 |
|---|---|
| 一、本業の会社の副業の規定と、候補者の情報とスカウトの文面の守秘の条件を確認する | 本業と同じ職種の案件の可否も。個別の判断は専門家に |
| 二、「採りにくい職種をどう採ってきたか」を、会社と候補者の情報を含まない型として書き出す | 探し方、文面の型、現場の巻き込み、速さの設計 |
| 三、本業の会社の名前があったから通じていたこと（返信率、応募の質）を、正直に書き出す | 依頼側の名前で作り直す前提 |
| 四、IT企業の言葉を、構造の言葉に置き換える | 「カジュアル面談」→「応募前の面談」、「テックブログ」→「会社の魅力を外に出す」、「リファラル」→「社員の紹介」 |
| 五、技術が分かるふりをしないと決め、「分からない専門職を現場と一緒に採る型」の一言を作る | 線を最初に引く |
| 六、範囲を、母集団の設計、要件の型、現場の巻き込み、速さの設計、数字の運用に絞る | 技術の評価は範囲外 |
| 七、「採りにくい職種を、スカウトと現場と速さで採る形を作る」の一言を作る | 「IT企業の人事でした」で終わらせない |
| 八、登録先に、範囲と、IT以外の会社のIT系職種に向いていることと、構造の言葉の一言を登録する | 専門職の採り方が分からない依頼側 |
| 九、母集団の設計か文面の作り直しを一件受け、「返信が戻った」形を残す | 次の工程に広げる材料に |

順番の要点は、「三」の正直な書き出しと「五」の線です。IT企業の人事の経験は、会社の知名度と技術の魅力に支えられていた部分があり、それを認めずに副業に入ると、返信が来ない現実で止まります。知名度に頼れない前提で文面を作り直す準備をし、技術が分かるふりをしない線を引いておくと、依頼側との期待がずれません。プロフィールは[プロフィールの書き方](/media/fukugyo-profile/)に、初案件の備えは[初案件で不安になりやすい点と備え方](/media/fukugyo-hatsu-anken-fuan/)に、情報の分け方は[案件ごとの情報の分け方](/media/fukugyo-jouhou-bunri/)に書いています。

### エラベルの見解

相談で最も多い思い込みは、「IT企業の採用のやり方は、IT企業でしか通じない」というものです。実際には、IT以外の会社が社内にエンジニアやデータの職種を持ち始め、その職種の採り方を知っている人が社内におらず、媒体に出しても来ず、現場が面接に関わらず、選考が遅くて他社に取られています。待たずに探す母集団、現場と一緒に決める要件、速さの設計、数字の運用。IT企業の人事が日常として回してきたこの型は、その会社にとって、持っていない打ち手です。通じないのは、IT企業の言葉と知名度に頼ったまま持ち込む場合で、構造の言葉に置き換えて、知らない会社の名前で口説く文面から作り直せば、業界は関係ありません。

順番として、本業の規定と守秘の条件を専門家に確認し、採ってきた型を会社の情報を含まずに書き出し、知名度に頼っていたことを正直に書き、IT企業の言葉を構造の言葉に置き換え、技術が分かるふりをしない線を引き、範囲を母集団と要件と巻き込みと速さと数字に絞り、スカウトと現場と速さで採る形を作る一言を作り、登録先に範囲と向いている依頼側を登録し、一件受けて返信が戻った形を残す。この順番で、IT企業の人事の経験は「IT企業でしか通じないもの」から「採りにくい職種を持ち始めた会社の打ち手」になります。エラベルでは、依頼側が担当者を選ぶ仕組みなので、採りにくい職種の工程を明確にし、技術の評価を含まないことを示している担当者に、専門職の採り方が分からない依頼側がついています。IT企業の人事の転身は、IT企業のやり方ではなく、知らない会社の名前で口説く文面から始まります。

## まとめ

- IT企業の人事の経験は**「採りにくいエンジニアを、ダイレクトリクルーティングと現場の巻き込みと速い選考で、競争の中で採ってきた」型**で売れる。**スカウト軸の母集団・技術職の要件・選考の速さと候補者体験・数字の運用**の四つ
- **「IT企業の人事でした」ではなく「採りにくい職種を、スカウトと現場と速さで採る形を作る」**と売る
- 売りにくい点は**技術を分かっていると思われる・IT以外の業界で通じるか・自社の魅力に頼っていた**。技術が分かるふりをせず線を引き、IT企業の言葉を構造の言葉に置き換え、文面は依頼側の名前で作り直す
- 案件は**IT以外の会社の、IT系の職種**から。「エンジニアを採りたいが、どうすればよいか分からない」が入り口
- 単価は**設計は成果物、運用は月額**で。最初の月は途中の成果を見せる。成果報酬は最初は避け、可否は専門家に確認
- 現場の巻き込みは、**依頼側の現場の負担に合わせて軽くする**。IT企業の当たり前を持ち込まない

## よくある質問

### 本業でもエンジニアの採用をしています。副業でもエンジニアの採用を受けてよいですか

本業の会社と依頼側が同じ職種を同じ媒体で採用している場合、候補者と情報が重なり、本業の会社との守秘と利益相反の線に関わります。本業の会社の副業の規定と、候補者の情報の扱いの条件を確認し、同じ職種で競合する案件は避けるか、本業の会社の許可を得る形にします。本業がIT企業なら、IT以外の会社のIT系職種の案件のほうが、重なりが少なく入りやすいです。個別の判断は、弁護士や社会保険労務士にご確認ください。利益相反の見方は[本業と利益相反になる案件](/media/fukugyo-riekisouhan/)に、情報の分け方は[案件ごとの情報の分け方](/media/fukugyo-jouhou-bunri/)に整理しています。

### 依頼側の現場から「技術のことが分かっていない」と言われました

分かっていないことを認めたうえで、分担を示します。「技術の評価は御社の現場にお任せします。私は、現場が見る点を一点に絞り、面接の時間を短くし、候補者を探して連れてくるところと、選考を速く回すところを担います」と言えば、現場は「自分の領域を侵されない」と感じて協力します。技術が分かるふりをして踏み込むと、現場の信頼を失います。要件を決めるときは、現場の言葉を聞き取り、「できること」で書き直して現場に確認してもらう形にします。聞き取りの磨き方は[ヒアリング力の磨き方](/media/fukugyo-hearing-skill/)に、エンジニア側から見た採用は[エンジニアからの転身が副業でできること](/media/fukugyo-engineer-kara-fukugyo/)に書いています。

### 本業の会社ではスカウトの返信がよく来ていたのに、副業の依頼側では来ません

本業の会社の知名度と技術の魅力があったから返信が来ていた、ということが多いです。依頼側の会社の名前を知らない候補者が、それでも読む理由を、文面の最初に置き直します。「あなたの経歴のここを見ました」「この会社のこの点が、あなたの次の一歩に合うと思いました」を先に書き、会社の説明は後に回します。依頼側の会社の魅力は、依頼側の現場に聞き取り、候補者の言葉に置き換えて使います。本業の型をそのまま使わず、作り直す前提で入ると、落差に驚かずに済みます。文面の型は[スカウト代行の副業案件](/media/fukugyo-scout-daikou-fukugyo/)に、評価される担当者の共通点は[評価される副業人材の共通点](/media/fukugyo-hyouka-sareru/)に整理しています。

「社員の声を聞きたいのでサーベイをやりたい」という依頼で、設問を数十個並べて実施し、結果を経営者に報告して終わると、二回目の回答率が落ちます。社員は「答えても何も変わらない」と学びます。サーベイは、聞くことではなく、「聞いて、返して、一つ直す」までが設計です。結論を先に書くと、**組織サーベイの設計は、目的を一つ・設問は少なく同じものを続ける・匿名の確保と集計の単位・結果を社員に返す・一つ決めて動くの五つで組み、設問は「聞いて何を直すか」が言えるものだけにし、少人数の単位を除いて匿名を確保し、スコアの高低で断定せず前回との変化と自由記述で読み、結果を返して一つ決める場を置き、回答のデータは担当者が持たない形で回します。**案件として受ける形は[組織サーベイの設計の副業の実務](/media/fukugyo-soshiki-survey-shigoto/)に、結果を施策につなぐ型は[エンゲージメント施策を作る](/media/fukugyo-skill-engagement/)に書いています。ここでは、サーベイの設計の型に絞ります。

## 二回目から回答されない理由

| 一回目の形 | 社員に起きること |
|---|---|
| 設問が数十個 | 途中で疲れて、適当に答える |
| 結果が社員に返らない | 「答えても何も変わらない」 |
| 部署ごとの結果が上司に渡る | 「誰が書いたか分かる」と感じて、本音を書かない |
| 自由記述が経営者に読まれるだけ | 書いたことが使われた形跡が無い |
| 毎回設問が変わる | 変化が見えず、答える意味が分からない |

サーベイの信頼は、「返す」と「一つ直す」で作られます。この二つが無いなら、実施しないほうが、信頼を損ねません。

## 設計の五つ

| 決めること | 中身 |
|---|---|
| 目的を一つ | 「何を知って、何を直すためか」。「社員の声を聞く」は目的ではない |
| 設問は少なく、同じものを続ける | 十数問まで。「聞いて何を直すか」が言えるものだけ。回ごとに変えず、変化を見る |
| 匿名の確保と集計の単位 | 少人数の単位を集計から除く。属性の組み合わせで個人が特定されない形 |
| 結果を社員に返す | 全体の傾向と、決めたことを、実施から一定の期間内に全員に |
| 一つ決めて動く | 結果を読んで、経営者と管理職で「直すこと」を一つ決め、三か月動く |

五つを一枚にして、依頼側と合意してから設問を作ります。設問から作り始めると、数十個になります。

### エラベルの見解

担当する側から見ると、サーベイの設計で最も差がつくのは、「設問ごとに『聞いて何を直すか』が言えるか」で設問を削れるかです。受ける側は、「せっかく聞くのだから」と、聞きたいことを全部入れます。ただ、「上司との関係は良好か」と聞いて、結果が低かったときに何を直すかが決まっていなければ、聞いた意味がありません。「この設問が低かったら、〇〇を直す」と、設問ごとに一行書けるものだけを残すと、十数問に収まります。エラベルで担当者を選ぶ企業には、「サーベイの設問は、低かったときに何を直すかが決まっていますか」を、私たちから先に聞いています。受ける側がその場で使える判断としては、設問の一覧に「低かったら直すこと」の列を作り、空欄の設問を消すこと。

## 設問の作り方

| 設問の型 | 例の形 | 低かったら直すこと |
|---|---|---|
| 仕事の明確さ | 「自分に期待されていることが分かっている」 | 等級の期待、目標管理 |
| 上司との接点 | 「上司と、仕事の進め方について話す機会がある」 | 1on1の設計 |
| 判断の余地 | 「自分の判断で進められる範囲が分かっている」 | 役割の定義、権限 |
| 情報の共有 | 「会社や部門の方針が伝わっている」 | 方針の一枚、共有の場 |
| 続ける意向 | 「この会社で、この先も働きたいと思う」 | 結果の指標。直すのは他の設問から |
| 自由記述 | 「会社が直すべきことを一つ挙げるなら」 | 一つ決める場の材料 |

設問の文は、依頼側の言葉で、短く、一つのことだけを聞きます。「上司は公平で、相談しやすい」のように二つを一つに混ぜません。回答の形式（段階の数）は依頼側が決め、回ごとに変えません。外部の指標や標準の設問を持ち込む場合は、「依頼側で直せることに対応しているか」で選び、持ち込んだ指標の解釈を担当者が断定しません。

## 匿名の確保

| 決めること | 中身 |
|---|---|
| 集計の単位 | 部門や職種。単位の人数が少ない場合は、上の単位にまとめる |
| 属性の組み合わせ | 「部門×勤続×役職」のように組み合わせると個人が特定される。組み合わせを制限する |
| 自由記述 | 文面から個人が分かることがある。返すときは要約か、同意の範囲で。原文を上司に渡さない |
| 回答のデータ | 依頼側の環境で、人事の限られた人だけが扱う。担当者は集計の結果だけを受け取る |
| 案内 | 匿名の確保の方法を、実施の案内に書く。社員が確かめられる形で |

匿名が確保されていないと感じた社員は、本音を書かず、次回は答えません。少人数の単位を除く基準（何人未満は集計しない）は依頼側の決まりで決め、案内に書きます。個人情報の扱いに関わる点は、依頼側の決まりと専門家の確認に従います。個別の判断は専門家にご確認ください。扱いは[個人情報の扱い](/media/fukugyo-kojin-jouhou/)に書いています。

## 読み方：高低で断定せず、変化と自由記述で

| やらないこと | やること |
|---|---|
| 「スコアが〇点だから悪い」 | 「前回より下がった設問はどれか」「部門で差が大きい設問はどれか」 |
| 外部の平均と比べる | 依頼側の前回と比べる。外部の数値は条件が違う |
| 一回の結果で断定 | 二回目以降の変化で読む。一回目は基準 |
| 設問ごとにばらばらに読む | 「低い設問」と「自由記述の内容」を突き合わせ、一つの課題に絞る |
| 部門の順位を出す | 上司を責める材料になる。変化と課題の特定だけ |

読み方は[採用データを分析する](/media/fukugyo-skill-data-bunseki/)の「問いを一つ立てて記録で答える」と同じです。数字は件数と変化のまま並べ、割合や平均で断定しません。数字の伝え方は[数字で語る](/media/fukugyo-suuji/)に書いています。

### エラベルの見解

相談で最も多い思い込みは、受ける側の「サーベイの結果は経営者に報告するもの」というものです。実際には、結果を最初に読むのは経営者でよいのですが、社員に返さなければ、社員は「答えても何も変わらない」と学びます。「全体の傾向を全員に返し、決めた一つを伝え、三か月後に『こう動いた』を伝える」までが設計で、返す日を実施の前に決めておきます。受ける側がその場で使える判断としては、実施の案内に「結果は〇月〇日に全員にお返しします」と日付を入れること。日付があれば、返すことが約束になり、経営者も「一つ決める」を後回しにできません。

## 返して一つ決める

| 順 | 中身 | 誰が |
|---|---|---|
| 一 | 集計の結果（傾向、前回との変化、部門の差が大きい設問）を一枚に | 担当者（集計の結果を受けて） |
| 二 | 経営者と管理職で、「直すこと」を一つ決める場 | 依頼側。担当者は進行と一枚 |
| 三 | 全員に、傾向と決めた一つを返す | 依頼側 |
| 四 | 三か月、決めた一つを動く | 依頼側 |
| 五 | 次の回で、変化を見る | 同じ設問で |

「一つ決める」は、[課題を構造化する](/media/fukugyo-kouzou-ka/)と同じで、複数を同時に直すとどれが効いたか分かりません。決めた一つを動かす型は[エンゲージメント施策を作る](/media/fukugyo-skill-engagement/)に書いています。

## 回答のデータを担当者が持たない

| 線 | 理由 |
|---|---|
| 回答の生データを担当者の端末に置かない | 匿名でも、属性の組み合わせで個人が分かることがある |
| 集計は依頼側の環境で | 担当者は集計の結果（単位ごとの傾向）だけを受け取る |
| 自由記述の原文を担当者が読む場合 | 依頼側の決まりの範囲で。要約だけを一枚に。原文を残さない |
| 案件の終了時 | 手元の集計の結果も消す。型だけを残す |

外部のサーベイのツールを使う場合、データの保管と閲覧の権限はツールと依頼側の契約に従い、担当者は権限を最小にします。ツールの選定と費用は依頼側の判断です。

## よく起きる詰まりと直し方

| 詰まり | 直し方 |
|---|---|
| 設問が数十個 | 「低かったら直すこと」が書けない設問を消す |
| 回答率が低い | 匿名の確保と、前回の結果が返されたかを確かめる。設問を減らす |
| 結果が経営者で止まる | 返す日を案内に書く。一つ決める場を実施の前に予定に入れる |
| 部門の順位が出て上司が責められる | 順位を出さない。変化と課題の特定だけ |
| 外部の平均と比べたがる | 依頼側の前回と比べる。外部は条件が違う |
| 回答のデータが担当者の手元に | 依頼側の環境に戻し、手元を消す |

## まとめ

- 二回目から回答されないのは、**返さず、直さない**から
- 五つは**目的を一つ・設問は少なく同じものを・匿名の確保・返す・一つ決めて動く**
- 設問は**「低かったら直すこと」が言えるもの**だけ。十数問。回ごとに変えない
- 匿名は**少人数の単位を除き、属性の組み合わせを制限**。案内に方法を書く。個別の判断は専門家にご確認ください
- 読み方は**高低で断定せず、前回との変化と自由記述で**。外部の平均と比べない。順位を出さない
- **返す日を案内に書き、一つ決める場を先に予定に**
- 回答のデータは**担当者が持たない**。集計の結果だけ。終了時に消す

## よくある質問

### 依頼側が「外部のサーベイのサービスを使いたい」と言います

使って構いませんが、五つの設計は同じです。サービスの設問が多い場合は、「依頼側で直せることに対応する設問」だけを使う形にできるかを確かめます。サービスが出す指標（外部との比較、スコアの解釈）は、依頼側の条件と合わないことがあるので、「前回との変化」を主に読み、外部との比較は参考に留めます。サービスの選定・費用・データの保管の契約は依頼側の判断です。

### 社員数が少なく、匿名が確保できません

部門ごとの集計をやめ、全体だけで読みます。それでも人数が少なければ、サーベイの形ではなく、「一つ決める場」に社員が直接出る形（全員で困りごとを一つ挙げる）のほうが、匿名の問題が無く、直すことにつながります。サーベイが合う規模かどうかも、設計の判断です。

### 自由記述に、特定の上司への不満が書かれていました

原文を上司に渡しません。人事が読み、内容がハラスメントなど深刻な事案に関わる場合は、依頼側の決まりと専門家の確認に従って、サーベイとは別の窓口で扱います。サーベイの結果としては、「上司との接点」の設問の傾向として返し、個別の記述は要約にも入れません。担当者は原文を扱わず、人事の判断に委ねます。

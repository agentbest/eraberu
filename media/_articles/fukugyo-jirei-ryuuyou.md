前の案件で作ったスカウトの文面が、返信率が良かった。次の案件でも同じ職種なので、その文面をそのまま使いたい。前の依頼側で効いた面接の準備の資料も、今の依頼側に渡せば喜ばれそうだ。結論を先に書くと、**前の案件の事例や成果物を、そのまま次の依頼側に持ち込むことは、二つの理由で避けます。一つは、前の依頼側の情報（会社の状況、求人の条件、候補者の反応から得た知見）を、次の依頼側に渡すことになり、守秘の線に触れること。もう一つは、前の依頼側に合っていた形が、今の依頼側には合わず、結果が出ないことです。持ち込んでよいのは、「構造と判断の仕方」までで、事例と成果物は依頼側ごとに作り直します。**構造を持ち込んで作り直せば、稼働は流用より少し増えますが、守秘も守れ、今の依頼側に合った形になります。案件ごとの情報の分け方は[案件ごとの情報の分け方](/media/fukugyo-jouhou-bunri/)に、守秘の線は[守秘の線を越える](/media/fukugyo-shippai-8/)に、他社の事例の扱いは[他社事例をどう扱うか](/media/fukugyo-benchmark/)にまとめています。

## 流用が起きる場面

流用は、悪意なく、効率のつもりで起きます。場面を知っておくと、自分が流用しかけていることに気づけます。

| 場面 | 流用の形 | 頭の中 |
|---|---|---|
| 同じ職種の案件を続けて受けた | 前の案件の文面を、会社名だけ変えて送る | 「同じ職種だから、同じ文面で効くはず」 |
| 依頼側から「前の案件ではどうしていたか」と聞かれた | 前の依頼側の進め方を、そのまま説明する | 「参考になるなら」 |
| 依頼側に型が無い | 前の依頼側で作った型（求人票の形、面接の準備の資料、記録の表）を、そのまま持ち込む | 「型があったほうが早い」 |
| 成果を早く出したい | 前の案件で効いた施策を、今の依頼側の状況を見ずに、最初から適用する | 「前に効いたから」 |
| 提案の根拠にしたい | 「前の案件では、これで返信が上がった」と、前の依頼側の結果を提案の根拠にする | 「実績があると通りやすい」 |
| 自分の経歴や発信に書く | 前の案件の事例を、依頼側や候補者が特定できる形で書く | 「実績として見せたい」 |

場面の要点は、「同じ職種の案件を続けて受けたとき」が最も起きやすいことです。職種が同じだと、文面も要件も面接の準備も、前の案件と重なる部分が多く、「同じでよい」と感じます。しかし、前の文面には前の依頼側の会社の状況と求人の条件が入っていて、それは前の依頼側の情報です。同じ職種でも、依頼側が違えば、情報も合う形も違います。

## 流用の二つの問題

流用には、守秘の問題と、不適合の問題があります。どちらか一方だけでも、避ける理由になります。

| 問題 | 内容 | 起きること |
|---|---|---|
| 守秘 | 前の依頼側の情報（会社の状況、求人の条件、候補者の反応から得た知見、社内の運用の工夫）が、次の依頼側に渡る | 前の依頼側との秘密保持に触れる。次の依頼側も「うちの情報も、次で使われる」と感じる。[守秘の線を越える](/media/fukugyo-shippai-8/) |
| 不適合 | 前の依頼側に合っていた形（文面の訴求、要件の絞り方、面接の準備の粒度）が、今の依頼側の状況・候補者・社内の型に合わない | 結果が出ない。「前は効いたのに」と、今の依頼側の状況を見ずに施策を続け、時間を失う |

二つの要点は、「守秘の問題は、流用した時点で起きる」ことです。結果が出るかどうかに関わらず、前の依頼側の情報が次に渡った時点で、線を越えています。不適合の問題は、結果が出ないことで分かりますが、守秘の問題は、誰にも気づかれなくても起きています。流用を避ける理由は、効率より、守秘が先です。

### エラベルの見解

相談で最も多い思い込みは、「自分が作った文面や資料は、自分の成果物だから、どの案件でも使ってよい」というものです。自分が作ったことは確かですが、その中身には、前の依頼側の会社の状況、求人の条件、候補者の反応から得た知見が入っています。文面の構造（冒頭に何を書き、中盤で何を伝え、結びをどうするか）は自分のもので、構造を埋めている中身は依頼側のものです。中身ごと持ち込めば、前の依頼側の情報を次に渡したことになります。

見ていて差がつくのは、前の案件が終わったときに、成果物から依頼側の情報を抜いて「構造だけの型」にしているかです。構造だけの型を自分の側に持ち、次の案件では今の依頼側の情報で埋め直す。この形なら、稼働は少し増えますが、守秘は守れ、今の依頼側に合った形になり、依頼側からは「うちのために作ってくれた」と受け取られます。エラベルでは、担当者が複数の依頼側を持つとき、依頼側ごとに成果物を作り直す形を前提にしています。流用で速く見せるより、作り直して合う形にするほうが、結果も信頼も残ります。

## 持ち込んでよいものと持ち込めないものの線

前の案件から次の案件に持ち込めるものと、持ち込めないものを分けます。線は「依頼側の情報が入っているか」です。

| 持ち込んでよい（自分の知見） | 持ち込めない（依頼側の情報） |
|---|---|
| 文面の構造。「冒頭は会社の状況、中盤は役割と候補者の接点、結びは返信の負担を下げる一文」 | 前の依頼側向けに書いた実際の文面。会社の状況、事業、役割、条件の言い回し |
| 要件の絞り方の考え方。「必須を三つに、歓迎を分ける」 | 前の依頼側の求人票そのもの。要件の中身 |
| 面接の準備の資料の項目。「経歴の要点、確認したい点、時間の配分」 | 前の依頼側の面接官向けに書いた実際の資料。候補者の情報、面接官の傾向 |
| 記録の表の列の設計 | 前の依頼側の記録そのもの |
| 判断の仕方。「返信が来ないときは、文面より相手の絞り方を疑う」 | 前の依頼側で「〇〇の訴求で返信が上がった」という結果 |
| 進め方の順番。「面接の枠を先に固定し、求人票を直し、文面を型にする」 | 前の依頼側の社内で、誰がどう動いたかの経緯 |
| 自分が繰り返している型と教訓 | 前の依頼側の運用の工夫（検索の条件の組み方、送信の時間帯の決め方） |

線の要点は、「結果は依頼側の情報、判断は自分の知見」ということです。「〇〇の訴求で返信が上がった」は、前の依頼側の求人と候補者で得られた結果で、依頼側の情報です。「返信が来ないときは相手の絞り方を疑う」は、複数の経験から取り出した判断で、自分の知見です。持ち込むのは判断と構造だけにし、結果と中身は前の案件の中に留めます。判断の取り出し方は[発信のネタの見つけ方](/media/fukugyo-hasshin-neta/)に、事例として書くときの粗くし方は[事例の書き方](/media/fukugyo-jirei-kakikata/)に整理しています。

## 構造だけを持ち込む形

構造だけを持ち込み、依頼側ごとに作り直す手順です。稼働は流用より増えますが、大きくは増えません。

| 手順 | 内容 |
|---|---|
| 一、前の案件の終了時に、型を構造だけにする | 成果物から依頼側の情報を抜き、構造（項目、順番、考え方）だけの型にして、自分の側に残す。[案件ごとの情報の分け方](/media/fukugyo-jouhou-bunri/) |
| 二、今の依頼側の状況を把握する | 会社の状況、求人の条件、候補者の市場、社内の型を、今の依頼側から聞く。[現状把握のしかた](/media/fukugyo-genjou-haaku/) |
| 三、構造の型に、今の依頼側の情報を埋める | 文面の構造に、今の依頼側の会社の状況と役割を入れる。要件の絞り方の考え方で、今の依頼側の要件を絞る |
| 四、今の依頼側の型に合わせる | 依頼側に既存の型があれば、自分の構造より依頼側の型を優先する。[クライアントのツールに合わせる](/media/fukugyo-kokyaku-tool/) |
| 五、結果を見て、今の依頼側向けに直す | 前の依頼側で効いた形が今の依頼側で効くとは限らない。結果を見て直す |
| 六、今の案件の終了時に、型を更新する | 今の案件で構造が改良されたら、依頼側の情報を抜いて、型を更新する |

手順の要点は、「三」で、構造は同じでも中身は今の依頼側の情報で埋めることです。構造が同じなので、一から作るより速く、中身が今の依頼側のものなので、守秘も守れ、合う形になります。流用との差は、「二」の今の依頼側の状況を把握する時間で、これは流用しても本来は要る時間です。

## 依頼側から「他社の事例を」と求められたとき

今の依頼側から、「前の案件ではどうしていたか」「他社ではどうか」と聞かれることがあります。答え方に線があります。

| 聞かれ方 | 答え方 |
|---|---|
| 「前の案件ではどうしていましたか」 | 「前の案件の具体はお伝えできませんが、一般的な進め方として〇〇があります」と、構造と判断の仕方で答える。前の依頼側の名前、状況、結果は出さない |
| 「他社ではこういう文面で効いていると聞いた。同じにしてほしい」 | 「他社で効いた形が御社で効くとは限らないので、御社の状況に合わせて作ります。構造として〇〇は取り入れられます」 |
| 「前の担当者は他社の事例を持ってきてくれた」 | 「私は、他の依頼側の情報を持ち込まない形でやっています。御社の情報も、他には持ち込みません」と、守秘の姿勢として伝える |
| 「実績として、前の案件の結果を教えてほしい」 | 「業界と規模と、担当した工程と、進め方はお伝えできます。会社名と具体の数字は、前の依頼側との守秘でお伝えできません」 |
| 「他社の事例を調べて提案してほしい」 | 公開されている一般的な情報の範囲で調べ、自分の判断の仕方と合わせて提案する。自分の前の案件の情報は使わない。[他社事例をどう扱うか](/media/fukugyo-benchmark/) |

答え方の要点は、「前の依頼側の情報を出さないことを、今の依頼側の安心につなげる」ことです。「他の依頼側の情報は持ち込みません。御社の情報も、他には持ち込みません」と伝えれば、今の依頼側は「この人は外で話さない」と受け取り、情報を渡しやすくなります。事例を出さないことは、頼りないのではなく、信頼の材料です。依頼側からの質問への答え方は[本業の会社に競合はいないか](/media/fukugyo-qa-14/)の「他社ではどうしていますか」への答え方と同じです。

## 自分の型を育てる方法

流用しない代わりに、自分の型（構造と判断の仕方）を育てておくと、案件ごとに作り直しても速くなります。

| 育て方 | 内容 |
|---|---|
| 案件の終了時に、構造だけを残す | 成果物から依頼側の情報を抜き、構造の型として自分の側に保存する。案件ごとに一つずつ増える |
| 判断のメモを、案件をまたいで書く | 「返信が来ないときは」「要件が絞れないときは」のような判断を、依頼側の情報を抜いて書き溜める |
| 複数の案件で繰り返した判断だけを型にする | 一件でしか起きていない判断は、その案件の結果。二件以上で繰り返したら、自分の型 |
| 型を発信や経歴に書く | 構造と判断の仕方は、依頼側の情報を含まないので、発信や経歴に書ける。[発信で書いてはいけないこと](/media/fukugyo-hasshin-nglines/) |
| 型を依頼側に渡す | 案件の中で作った型は、依頼側の共有にも置く。自分の側には構造だけ、依頼側の側には中身も。[いつ辞めても困らない状態を作る](/media/fukugyo-hikitsugi-junbi/) |
| 型を更新する | 新しい案件で構造が改良されたら、型を更新する。古い型を使い続けない |

育て方の要点は、「複数の案件で繰り返した判断だけを型にする」ことです。一件で効いた形は、その依頼側の状況で効いたもので、次に効くとは限りません。二件、三件で同じ判断をするようになったら、それは依頼側に依らない自分の型で、次の案件に持ち込めます。型の見せ方は[noteで実績を見せる](/media/fukugyo-note/)と[ポートフォリオの作り方](/media/fukugyo-portfolio/)に書いています。

### エラベルの見解

担当する側から見ると、複数の依頼側から長く信頼されている人は、案件ごとに成果物を作り直しています。前の案件の文面や資料をそのまま持ち込むことをせず、構造の型を自分の側に持ち、今の依頼側の情報で埋め直しています。依頼側は、自分たちのために作られた文面や資料を受け取り、「うちのことを見て作ってくれた」と感じています。流用している人は、速く見えますが、依頼側から「どこかで見た形」「うちに合っていない」と感じられ、前の依頼側の情報が混ざっていることに気づかれた時点で、信頼を失っています。

順番として、案件の終了時に成果物から依頼側の情報を抜いて構造の型にし、次の案件では今の依頼側の状況を把握し、構造の型に今の情報を埋め、依頼側の型があればそれを優先し、結果を見て直し、終了時に型を更新する。この順番で、事例は流用せずに、型は育ちます。エラベルでは、担当者が依頼側ごとに成果物を作り直し、他の依頼側の情報を持ち込まない形を前提にしています。依頼側が担当者を選ぶ仕組みは、依頼側が「自分たちのために動く担当者」を選ぶ仕組みでもあります。

## まとめ

- 前の案件の事例と成果物を**そのまま持ち込まない**。守秘の問題（前の依頼側の情報が渡る）と、不適合の問題（今の依頼側に合わない）の二つ
- 流用は**同じ職種の案件を続けて受けたとき**に最も起きやすい。効率のつもりで、悪意なく
- 持ち込んでよいのは**構造と判断の仕方**。持ち込めないのは**実際の文面・資料・結果・依頼側の運用の工夫**。「結果は依頼側の情報、判断は自分の知見」
- 構造だけを持ち込む手順は**終了時に構造だけにし→今の依頼側の状況を把握し→構造に今の情報を埋め→依頼側の型を優先し→結果を見て直し→型を更新する**
- 「前の案件では」「他社では」と聞かれたら**構造と判断の仕方で答え、依頼側の情報は出さない**。出さないことが今の依頼側の安心になる
- 自分の型は**複数の案件で繰り返した判断**だけを型にし、案件ごとに更新する

## よくある質問

### 同じ職種の案件で、文面の構造まで同じなら、中身もほぼ同じになりませんか

構造が同じでも、会社の状況、事業、役割の中身、候補者に伝える接点は、依頼側ごとに違います。同じ職種でも、依頼側が数十名の会社か数百名の会社か、事業が伸びている局面か安定している局面かで、候補者に伝えるべきことは変わります。中身がほぼ同じになるなら、今の依頼側の状況を把握しきれていない可能性があります。構造の型に今の依頼側の情報を埋める前に、依頼側の状況を聞き直します。把握の仕方は[現状把握のしかた](/media/fukugyo-genjou-haaku/)に整理しています。

### 前の依頼側で作った型を、前の依頼側が「自由に使ってよい」と言ってくれました

前の依頼側が許可していても、型の中身に前の依頼側の情報（会社の状況、条件、候補者の反応）が入っていれば、次の依頼側に渡すことは、前の依頼側の情報を渡すことです。許可の範囲が「構造を使ってよい」なのか「中身ごと使ってよい」なのかを確認し、中身ごとの許可があっても、次の依頼側に合わない問題は残るので、構造だけを持ち込んで埋め直す形にします。許可の取り方と範囲は[クライアントに実績公開の許可を取る](/media/fukugyo-kyoka-toru/)に書いています。

### 依頼側に型が無く、自分の型を持ち込まないと何も始まりません

依頼側に型が無い場合、自分の構造の型を持ち込むことは問題ありません。持ち込むのは構造で、中身は今の依頼側の情報で埋めます。「文面の構造はこの形で、御社の状況に合わせて中身を作ります」と伝え、依頼側の共有の中に、今の依頼側向けの型として作ります。作った型は依頼側の資産として依頼側の側に残し、自分の側には構造だけを残します。依頼側に型が無い案件の進め方は[どんな会社から依頼が来るのか](/media/fukugyo-qa-11/)の「専任がいない会社」の項に整理しています。

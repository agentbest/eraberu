人事副業 / エンジニアからの転身

エンジニアからの転身が副業でできること｜経験の棚卸しと売り方｜エンジニアの経験は「エンジニア採用の橋渡し」でそのまま売れる。求人票とスカウト文面を技術者の目線で直す、面接官と人事の間の言葉を訳す、技術の課題の設計を手伝う、の三つ。「人事に転身」ではなく、「エンジニア採用の〇〇の工程を、現場の目線で」と売る

エンジニアとして働いてきた。採用に関わったのは、面接官として何度か出た程度。それでも、自社のエンジニア採用がうまくいっていない理由は分かる気がする。求人票が技術者に響いていない、面接で聞くことがずれている。この目線は、副業で売れるのか。結論を先に書くと、エンジニアの経験は、「エンジニア採用の橋渡し」という形で、そのまま売れます。売れるのは、「求人票とスカウト文面を技術者の目線で直す」「面接官（現場）と人事の間の言葉を訳す」「技術の課題や見極めの設計を手伝う」の三つです。エンジニア採用は、人事が技術を分からず、現場が採用を分からず、その間で止まっている依頼側が多く、両方が分かる人が求められています。「人事に転身します」ではなく、「エンジニア採用の〇〇の工程を、現場の目線で」と売ります。人事未経験の売り方は人事未経験が副業でできることに、未経験の区分は人事未経験でも受けられる仕事はあるかに、本業との線は本業と利益相反になる案件にまとめています。

この経歴の何が売れるか

エンジニアの経験を、エンジニア採用の工程に置き換えた棚卸しです。

エンジニアの経験採用の工程への置き換え依頼側にとっての価値
技術者として求人票を読んできた目線求人票を「技術者がどこを見て、どこで冷めるか」で直す求人票が人事の言葉で書かれ、技術者に「何をやる会社か分からない」と映っている依頼側が多い
技術者としてスカウトを受けてきた目線スカウト文面を「返信したくなる一言」と「無視される一言」で直すスカウトの返信が来ない依頼側が多い
現場の言葉が分かる面接官（現場のエンジニア）が言っていることを、人事が分かる言葉に訳す。逆も現場と人事の間で、求める人物像がずれている依頼側が多い
技術の課題の設計と評価の経験選考の課題（コードの提出、技術の質問）の設計と、評価の観点の整理を手伝う課題が古い、評価の観点が面接官ごとに違う依頼側が多い
技術の分野の地図を持っている職種と技術の組み合わせで、候補者がどこにいるか、何を求めているかが分かる「エンジニアが採れない」としか見えていない依頼側に、職種と技術で分けた見方を渡せる
仕組みと自動化の発想採用管理の仕組み、応募の経路、データの見方を、仕組みとして整える採用の運用が手作業で、記録が散らばっている依頼側が多い
技術者が辞退する理由を知っている辞退の理由（技術の環境、裁量、評価）を聞き出し、文面と条件に反映する辞退の理由が「条件が合わなかった」で止まっている依頼側が多い

売れるものの要点は、「人事と現場の両方の言葉が分かる」ことが、そのまま価値になることです。エンジニア採用で最も多い詰まりは、人事が「技術が分からないから求人票が書けない」、現場が「採用が分からないから面接で何を聞けばよいか分からない」という、言葉の断絶です。両方が分かる人が間に入ると、断絶が埋まり、採用が動きます。人事の経験が無くても、現場の目線と言葉があれば、この価値は出せます。面接の設計は面接代行を受けるときの注意に、現場との関係は現場との関係の作り方に書いています。

売りにくい点とその扱い

エンジニアの転身で売りにくい点は三つあり、扱い方があります。

売りにくい点依頼側の懸念扱い方
人事の工程を知らない「応募から入社までの流れ、内定の出し方、条件の提示を知らないのでは」範囲を「橋渡し」に絞る。求人票、スカウト文面、面接の設計、言葉の翻訳。工程の運用と条件の提示は依頼側の人事が持つ
候補者の判断を任せられるか「技術は分かっても、人として合うかの判断は」判断を売らない。技術の観点での「確認できたこと、確認が要ること」を材料として渡し、判断は依頼側が持つ
本業との利益相反「本業の会社の競合の採用を手伝うのでは」「本業の候補者を回すのでは」本業の会社と競合する依頼側、同じ候補者の層を取り合う依頼側を避ける。本業の情報と人脈を副業に持ち込まない

扱い方の要点は、「本業との利益相反」を、エンジニアの転身では特に注意することです。エンジニアの本業の会社と、副業の依頼側が、同じ技術の分野で同じ候補者の層を採用していることは珍しくありません。その場合、本業の会社から見れば「自社の候補者を競合に回している」形になり、副業の許可の前提が崩れます。依頼側を選ぶとき、本業の会社の競合か、候補者の層が重なるかを最初に確認し、重なるなら受けません。利益相反の見分け方は本業と利益相反になる案件に、判断の線は業務範囲を書面で固めるに、人事の工程の学び方は学び直しの進め方に整理しています。

エンジニア採用の橋渡しを工程で示し、本業との利益相反の線を守っている担当者は、人事未経験でも依頼側から選ばれています。範囲と条件を登録しておいてください

エラベルの見解

担当する側から見ると、エンジニアから転身して続いている人と、最初の案件が取れない人の差は、「人事に転身したい」と言うか、「エンジニア採用の求人票とスカウト文面を、技術者の目線で直す」と言うかです。前者は依頼側に「人事の経験が無い人」と映り、後者は「うちのエンジニア採用の詰まりを埋められる人」と映ります。エンジニア採用で困っている依頼側は多く、技術と採用の両方の言葉が分かる人は少ないので、工程で示せば、人事の経験が無いことは懸念になりません。

見ていて差がつくのは、現場の面接官と人事の間で、「訳す」役に徹しているかです。現場の言葉をそのまま人事に伝えると「意味が分からない」となり、人事の言葉をそのまま現場に伝えると「ずれている」となります。「現場が言っている〇〇は、人事の言葉では△△です」「人事が求めている□□は、技術で言えば◇◇の経験です」と、両方に訳している担当者は、依頼側の採用の会議で欠かせない存在になっています。エラベルでは、依頼側が担当者を選ぶ仕組みなので、「エンジニア採用の橋渡し」と範囲を明確にしている担当者に、その詰まりを抱えた依頼側がついています。エンジニアの転身は、技術の知識ではなく、翻訳の役で始まります。

案件の探し方

エンジニアから入りやすい案件と、探し方です。

入りやすい案件理由探し方
エンジニア職の求人票の改善技術者の目線で直せる。判断は依頼側「技術者が読んで応募したくなる求人票」を範囲の一言に。自分が読んで冷めた求人票の例を、直す観点で示す
エンジニア職のスカウト文面受けた側の目線で直せる「自分が返信したスカウトと、無視したスカウトの違い」を示す
面接官（現場）向けの準備資料と評価の観点現場の言葉で書ける「面接官として困ったことと、その解決の型」を示す
技術の課題の設計設計と評価の経験で入れる「課題で何を見るか、見ないか」の設計を示す
現場と人事の橋渡し（採用の会議への同席）両方の言葉が分かる「現場と人事の言葉を訳す」を範囲の一言に
採用の運用の仕組み化仕組みと自動化の発想で入れる「手作業の運用を仕組みに」を提案の形で

探し方の要点は、「自分の技術の分野のエンジニア採用から入る」ことです。自分の分野なら、候補者がどこにいて、何を求めて、どこで冷めるかが分かります。分野が違うと、技術者の目線が薄れます。最初は自分の分野で、求人票かスカウト文面を一本受け、型を作ってから、隣の分野に広げます。依頼側を探すときは、本業の会社との利益相反を先に確認します。案件の探し方は案件の探し方に、始め方は人事の副業の始め方に、面談で聞くことはこちらから聞くべき質問に書いています。

単価の目安

単価は、具体的な額ではなく、決まり方の構造で考えます。エンジニアの転身で、単価に影響する要素です。

要素単価への影響考え方
技術と採用の両方が分かること両方が分かる人は少なく、エンジニア採用で困っている依頼側には高く評価される「人事未経験だから安く」ではなく、「橋渡しの工程」の単価で
自分の技術の分野との一致分野が一致する依頼側では、目線の価値が高い一致する依頼側を選ぶ。分野が違う依頼側では単価の根拠が薄れる
判断を含まない範囲判断を含まない範囲は、判断を含む範囲より単価は下がる材料と翻訳に徹し、判断は依頼側に
成果物で受けやすい工程求人票一本、スカウト文面一式、面接官向けの資料、課題の設計、は成果物で受けやすい成果物で受けると、単価の議論が明確になる
本業の技術の単価との比較エンジニアの本業の時間単価と、人事の副業の単価は、決まり方が違う本業の単価を副業に持ち込まない。副業は工程の単価で
最初の案件人事の実績が無いので、範囲を絞って小さく単価を下げるのではなく、範囲と時間を小さくする

単価の要点は、「本業のエンジニアの単価を、副業の人事の単価に持ち込まない」ことです。エンジニアの本業の時間単価は、技術の市場で決まっていて、人事の副業の単価とは決まり方が違います。「本業ではこの単価だから」と副業でも同じ単価を求めると、依頼側と合いません。逆に、「人事未経験だから安く」と下げる必要もありません。エンジニア採用の橋渡しという工程の単価で、範囲を絞って受けます。単価の構造は人事の副業単価の相場に、実績の示し方は実績の示し方に整理しています。

自分の技術の分野のエンジニア採用で、橋渡しの工程を成果物で受けている担当者は、転身でも単価を保てます。範囲と条件を登録しておいてください

始める順番

エンジニアから人事の副業を始める順番です。

順番内容
一、自分が求人票とスカウトを読んで、応募した理由と冷めた理由を書き出す技術者の目線の棚卸し
二、面接官として困ったことと、その解決の型を書き出す現場の目線の棚卸し
三、本業の会社の競合と、候補者の層が重なる依頼側を、避ける対象として書き出す利益相反の線
四、人事の主要な工程と言葉を一通り学ぶ応募から入社までの流れ、内定と条件の提示
五、範囲を「橋渡し」に絞る求人票、スカウト文面、面接の設計、翻訳。運用と条件は依頼側
六、「エンジニア採用の〇〇の工程を、現場の目線で」の一言を作る「人事に転身」とは言わない
七、登録先に、範囲と技術の分野を登録する自分の分野を明記
八、自分の分野の依頼側で、求人票かスカウト文面を一本受け、型を残す次の工程を広げる材料に

順番の要点は、「三」の利益相反の線を、案件を探す前に引くことです。エンジニアの転身では、本業の会社と依頼側の候補者の層が重なることが多く、案件を見てから考えると、「この依頼側は魅力的だが競合かもしれない」と迷います。先に、避ける対象を書き出しておけば、迷わずに済みます。副業の許可を得るときにも、この線を会社に示せば、懸念に答えられます。許可の申請は副業許可の申請の出し方に、自己紹介の型は自己紹介文のテンプレートに書いています。

エラベルの見解

相談で最も多い思い込みは、「エンジニアから人事への転身は、技術を捨てて別の職種に移ることだ」というものです。実際には、エンジニア採用の橋渡しは、技術の知識と現場の目線があって初めてできる工程で、技術を捨てるのではなく、技術を採用に使う形です。人事の経験が無いことは、橋渡しの工程では懸念になりません。懸念になるのは、本業との利益相反と、判断を引き受けることの二つで、どちらも線を引けば防げます。

順番として、技術者の目線と面接官の目線を棚卸しし、利益相反の線を先に引き、人事の工程と言葉を学び、範囲を橋渡しに絞り、工程と目線を結びつけた一言を作り、登録先に範囲と分野を登録し、自分の分野で一本受けて型を残す。この順番で、エンジニアの転身は、「技術を捨てる転身」から「技術を採用に使う形」になります。エラベルでは、依頼側が担当者を選ぶ仕組みなので、エンジニア採用の橋渡しと技術の分野を明確にしている担当者に、その詰まりを抱えた依頼側がついています。エンジニアの転身は、翻訳の役と、線の提示で始まります。

まとめ

  • エンジニアの経験は「エンジニア採用の橋渡し」でそのまま売れる。求人票とスカウト文面を技術者の目線で直す・現場と人事の言葉を訳す・課題と評価の観点を設計するの三つ
  • 「人事に転身」ではなく「エンジニア採用の〇〇の工程を、現場の目線で」と売る
  • 売りにくい点は人事の工程・候補者の判断・本業との利益相反。範囲を橋渡しに絞り、判断は依頼側に、利益相反の線は案件を探す前に引く
  • 案件は自分の技術の分野のエンジニア採用から。求人票かスカウト文面を一本、成果物で
  • 単価は本業のエンジニアの単価を持ち込まず、「未経験だから安く」もせず、橋渡しの工程の単価で
  • 順番は目線の棚卸し → 利益相反の線 → 工程の学習 → 範囲を橋渡しに → 一言 → 登録 → 自分の分野で一本

よくある質問

本業の会社と同じ技術の分野の依頼側から声がかかりました。受けてよいですか

本業の会社の競合か、候補者の層が重なるかを確認します。同じ技術の分野で、同じ経験年数の候補者を取り合う関係なら、本業の会社から見れば「自社の候補者を競合に回している」形になり、副業の許可の前提が崩れます。分野が同じでも、規模や事業が違い、候補者の層が重ならないなら、受けられることがあります。判断に迷うなら、受けない方が安全で、本業の会社の許可の担当に確認する方法もあります。見分け方は本業と利益相反になる案件に整理しています。

面接に同席して、候補者の技術力を判断してほしいと言われました

技術の観点で「確認できたこと」と「確認が要ること」を整理して渡すことはできますが、合否の判断は依頼側が持つと線を引きます。「〇〇の経験は確認できました。△△は実務での深さを確認した方がよいです。判断は御社で」と、材料として返します。判断を引き受けると、外れたときに信用を失い、依頼側の採用を誤らせます。面接への同席の注意は面接代行を受けるときの注意に、判断の線は業務範囲を書面で固めるに書いています。

人事の知識が無いので、依頼側との面談で何を話せばよいか分かりません

人事の知識ではなく、エンジニア採用の詰まりを話します。「求人票を技術者が読むと、〇〇のところで冷めます」「スカウトは、△△が書いてあると返信します」「面接官が困るのは、□□が決まっていないときです」と、自分が技術者として見てきたことを話せば、依頼側は「うちの詰まりが分かる人だ」と感じます。人事の用語は、面談の前に主要なものを一通り学び、分からない用語はその場で聞きます。面談で聞かれることは副業案件の面談で聞かれることに、聞くべきことはこちらから聞くべき質問に整理しています。

あわせて読む

  • 営業からの転身が副業でできること｜経験の棚卸しと売り方｜営業の経験は「候補者との接点を作り、動かす」工程でそのまま売れる。スカウト文面と返信後の面談、辞退の理由の聞き取りと引き止めの設計、紹介や経路の開拓の三つ。「営業から人事へ」ではなく、「採用の接点の工程を、営業の技能で」と売る
  • IT企業の人事が副業でできること｜経験の棚卸しと売り方｜IT企業の人事の経験は「採りにくいエンジニアを、ダイレクトリクルーティングと現場の巻き込みと速い選考で、競争の中で採ってきた」型で売れる。売れるのは、スカウトを軸にした母集団の設計、技術職の要件を現場と一緒に決める型、選考の速さと候補者体験の設計、採用の数字を回す運用の四つ。「IT企業の人事でした」ではなく、「採りにくい職種を、スカウトと現場と速さで採る形を作る」と売る
  • マーケターからの転身が副業でできること｜経験の棚卸しと売り方｜マーケターの経験は「候補者を顧客として見る」形でそのまま採用に転用できる。求人票とスカウト文面の改善、採用の数字の設計と報告、母集団の経路の設計の三つが売れる。「マーケの経験を人事に」ではなく、「採用の〇〇の工程を、マーケの△△の技能で」と工程で売る
